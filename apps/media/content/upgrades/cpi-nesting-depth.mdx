# Deeper CPI Nesting

September 2026 • Solana Foundation

A cross-program invocation, or CPI, lets one Solana program call another during
the same transaction. The called program can make its own CPI, forming a chain.
Today that chain stops at 4 calls. After this change it can reach 8.

Deeper nesting lets developers keep programs small and focused instead of
flattening or duplicating logic to stay under the limit. A smart wallet can call
an application that calls a router that calls one or more liquidity programs,
and each layer stays its own program.

The limit is runtime-wide. It applies to legacy, v0, and v1 transactions alike.
A separate change raises the number of accounts a v1 transaction can name; see
[More Accounts per Transaction](/upgrades/v1-account-limit).

## Does This Affect Me?

<AudienceGroup>
<Audience title="For Users" summary="No action needed.">

Nothing changes about how you use wallets or applications. Transactions, fees,
and confirmation times stay the same.

</Audience>

<Audience title="For Developers" summary="Nothing breaks. Deeper call chains become possible once the feature gate activates.">

Existing programs keep working. A program that asserts
`sol_get_stack_height() == TRANSACTION_LEVEL_STACK_HEIGHT` behaves exactly as
before; the change raises the ceiling, not how stack height is reported.

| If you                                       | Breaking? | What you have to do                                                               |
| -------------------------------------------- | --------- | --------------------------------------------------------------------------------- |
| **Call** other programs from your program    | No        | Nothing. After activation you can nest up to 8 levels deep instead of 4.          |
| **Wrap** other programs, e.g. a smart wallet | No        | Nothing. Programs you call gain back the depth your wrapper consumes.             |
| **Depend** on the fifth nested call failing  | **Yes**   | Rare and not a supported pattern. Replace the depth check with an explicit guard. |

This change also matters for the durable nonce replacement. Offline signer
programs run authorized instructions through CPI at stack height 2 or 3, which
leaves those instructions less room for their own CPIs. Raising the limit to 8
restores that room. See
[Durable Nonce Deprecation](/upgrades/durable-nonce-deprecation).

## Technical Details

### CPI Nesting Depth: 4 to 8

[SIMD-0268](https://github.com/solana-foundation/solana-improvement-documents/blob/main/proposals/0268-raise-cpi-nesting-limit.md)
raises the maximum number of nested CPI calls from 4 to 8. The top-level
instruction is stack height 1, so the maximum total stack height rises from 5
to 9: eight nested program calls instead of four.

Nothing changes for programs that stay within today's limit. Programs that need
the extra depth can use it as soon as the feature gate activates. No migration
or redeployment is required.

### Who Benefits

- **Composable apps.** Wallets, routers, markets, and token programs can be
  combined in one operation without collapsing layers into a single program.
- **Programs that wrap other programs.** Offline signer programs, such as the
  replacements for durable nonces, run authorized instructions through CPI at
  stack height 2 or 3. Deeper nesting leaves those instructions room for their
  own CPIs.
- **Programs that check stack height.** A program that asserts
  `sol_get_stack_height() == TRANSACTION_LEVEL_STACK_HEIGHT` keeps working. The
  change raises the ceiling; it does not alter how stack height is reported.

## About This Upgrade

Solana's application ecosystem is increasingly composable. CPI depth determines
how many program layers one atomic transaction can pass through. Raising it
gives developers more flexibility without changing the behavior of existing
transactions. The atomic execution model stays the same; richer call chains fit
inside it.
