## Ecosystem work

SIMDs

- A discussion was started to [align on a Solana specification](https://github.com/solana-foundation/solana-improvement-documents/discussions/716) and possible changes to the SIMD process as a result WTM - The [draft document](https://bw-solana.github.io/solana-protocol-spec/) details specifically all the specific details that define the Solana protocol. Starting from here would mean it would be much clearer to see how changes impact the protocol, since the differences are easier to reason about.

- Modifying the Solana virtual machine instruction set architecture (ISA) to [include vector intrinsics and additional vector registers](https://github.com/solana-foundation/solana-improvement-documents/pull/714) was proposed. WTM - Vectors could be thought of as a primitive list of elements of one type (integer, character, floating point number, etc). An ISA defines the set of operations you can use in bytecode when running a program. Bytecode is the simplified instruction payload, compiled from a programming language (like Rust), that the runtime can interpret. Right now, the ISA does not allow for vector operations - that is, arithmetic, loading, and storing of vectors. Normally, instructions fetch one element of the vector at a time to do math. Vector operations on the other hand, allow the computer to operate on these vectors all at once. By proposing this in the ISA, this allows for faster math on-chain as well as more use cases that the runtime and Solana programs can support.

Validator clients (Agave, Firedancer, Mithril)

- A [typed ABI](https://github.com/anza-xyz/agave/pull/16706) will be added to the Agave program runtime implementation WTM - The way the runtime was managing alignment when invoking the Solana instruction was not typed well. This implementation specifies what exactly is being parsed in along with handlers to various parts of the instruction so developers can better reason about the instruction payload.

- More use of the agave-worker-pool was implemented this week, specifically for [lattice hashing of account state](https://github.com/anza-xyz/agave/pull/16647) WTM - The agave-worker-pool will replace the Rayon thread pool implementation used throughout the repository. This way, the performance benefits of the custom implementation will be spread throughout the validator stack.

- Firedancer has [reimplemented its leader handover procedure](https://github.com/firedancer-io/firedancer/pull/12618/) WTM - Some causes of latency within the chain include work around the epoch boundary, and work during a leader handover. If the latency is too long, there is a chance that the first slot would be skipped. By improving the performance of the leader handover, you minimize that risk and improve performance across the cluster.

RPC 2.0

- Cloudbreak is [improving its implementation of querying results](https://github.com/solana-rpc/cloudbreak/pull/64) for getAccountInfo and getMultipleAccounts WTM - The main challenge of an RPC is to make operations cheaper to meter. Depending on the pricing scheme, an RPC call can make or lose money if the query is easy or hard. This change makes both RPC methods easier to query.

Solana language clients (Web3.js, Solana Kit, Kit plugins, Solana SDK, Codama, Solana Go)

- Web3 js will [use Rolldown as its Javascript bundler](https://github.com/solana-foundation/solana-web3.js/pull/4029) WTM - Bundling affects both performance in production deployments and in developer experience during hot module reloading. Some bundlers are more performant than others. Rolldown decreases the bundle time of the project from 2 seconds to almost 0 seconds.

Solana Program Library (SPL) and Core BPF

- [Migration infrastructure](https://github.com/solana-program/ed25519-programmatic-signer/stack/88) on the programmatic signer program are continuing including. This week includes work on new \`[migrate scan](https://github.com/solana-program/ed25519-programmatic-signer/pull/91)\` and \`[migrate token-account](https://github.com/solana-program/ed25519-programmatic-signer/pull/118)\` CLI commands. WTM - This change will support developers as they try to migrate their program operations from a System Account-based control to a programmatic signer control. The above changes allow users to perform that migration in a more seamless way.

Solana program frameworks (Anchor, Pinocchio, Steel, Quasar)

- Anchor is reimplementing [its instruction handling](https://github.com/otter-sec/anchor/pull/5227) WTM - Instruction handling used to involve a ton of heap allocations. Now, directing borrowing instruction information allows Anchor to be more lean and performant when building Solana programs.

Testing frameworks (mollusk, litesvm, surfpool)

- Surfpool is [improving its startup times](https://github.com/solana-foundation/surfpool/pull/936) for its TUI WTM - This will allow a faster developer experience and also possibly make it easier for agents to run faster loops.

- Surfpool includes several [performance improvements](https://github.com/solana-foundation/surfpool/pull/907) WTM - There are too many performance improvements in this change, but a few stand out: improvements to the Websocket implementation, faster runs for sending transactions. All improve the developer experience when using Surfpool.
