## Ecosystem work

### SIMDs

- A discussion has started about [aligning on a Solana specification](https://github.com/solana-foundation/solana-improvement-documents/discussions/716) and potential changes to the SIMD process
  - WTM - The [draft specification](https://bw-solana.github.io/solana-protocol-spec/) documents the details that define the Solana protocol. A shared specification would make it easier to identify and reason about how proposed changes affect the protocol.

- A proposal would [add vector intrinsics and additional vector registers](https://github.com/solana-foundation/solana-improvement-documents/pull/714) to the Solana virtual machine instruction set architecture (ISA)
  - WTM - An ISA defines the operations available to bytecode when a program runs. The current ISA processes vector elements one at a time. The proposed instructions would support arithmetic, loading, and storage across multiple vector elements at once, enabling faster onchain math and additional runtime and program use cases.

### Validator clients (Agave, Firedancer, Mithril)

- Agave will add a [typed ABI](https://github.com/anza-xyz/agave/pull/16706) to its program runtime implementation
  - WTM - The runtime previously managed alignment when invoking Solana instructions without a strongly typed representation. The new implementation defines the parsed instruction data and handlers for its components, making instruction payloads easier to reason about.

- Agave expanded its worker pool implementation to support [lattice hashing of account state](https://github.com/anza-xyz/agave/pull/16647)
  - WTM - The custom Agave worker pool is replacing Rayon thread pools across the repository. Extending it to lattice hashing brings its performance improvements to another part of the validator stack.

- Firedancer [reimplemented its leader handover procedure](https://github.com/firedancer-io/firedancer/pull/12618/)
  - WTM - Work at epoch boundaries and during leader handoffs can add latency. If the handoff takes too long, the new leader may skip its first slot. This change reduces that risk by improving handover performance.

### RPC 2.0

- Cloudbreak is [improving result queries](https://github.com/solana-rpc/cloudbreak/pull/64) for `getAccountInfo` and `getMultipleAccounts`
  - WTM - RPC providers need to meter operations accurately because query costs vary with the work required. This change makes both methods less expensive to query.

### Solana language clients (Web3.js, Solana Kit, Kit plugins, Solana SDK, Codama, Solana Go)

- Web3.js will [use Rolldown as its JavaScript bundler](https://github.com/solana-foundation/solana-web3.js/pull/4029)
  - WTM - Bundling affects production builds and hot module reloading during development. In project benchmarks, Rolldown reduced bundle time from two seconds to nearly zero.

### Solana Program Library (SPL) and Core BPF

- Work continues on the programmatic signer program’s [migration infrastructure](https://github.com/solana-program/ed25519-programmatic-signer/stack/88), including new [`migrate scan`](https://github.com/solana-program/ed25519-programmatic-signer/pull/91) and [`migrate token-account`](https://github.com/solana-program/ed25519-programmatic-signer/pull/118) CLI commands
  - WTM - These commands help developers migrate program operations from System Account-based control to programmatic signer control.

### Solana program frameworks (Anchor, Pinocchio, Steel, Quasar)

- Anchor is reimplementing [its instruction handling](https://github.com/otter-sec/anchor/pull/5227)
  - WTM - Instruction handling previously required many heap allocations. Directly borrowing instruction data reduces allocation overhead when Anchor programs process instructions.

### Testing frameworks (Mollusk, LiteSVM, Surfpool)

- Surfpool is [improving startup times](https://github.com/solana-foundation/surfpool/pull/936) for its TUI
  - WTM - Faster startup reduces wait time for developers and coding agents running repeated test loops.

- Surfpool added several [performance improvements](https://github.com/solana-foundation/surfpool/pull/907)
  - WTM - The changes include WebSocket improvements and faster transaction sending, reducing latency in local development workflows.
