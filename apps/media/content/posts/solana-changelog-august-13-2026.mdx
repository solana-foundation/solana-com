**A routing issue at Terraswitch’s Frankfurt location caused 28.83% of stake to become delinquent, or stop voting for several blocks, without causing Solana network downtime.** This week also brought Testnet and Devnet slot-time feature gates, new validator-client releases, and work across developer tooling.

## Frankfurt routing incident

Terraswitch reported a routing issue affecting its Frankfurt location, where several Solana validators are hosted, at 04:01 UTC on August 12, 2026. The affected stake did not exceed the approximately 33.33% consensus threshold required to cause network downtime.

- The [Solana Foundation’s incident details](https://x.com/jacobvcreech/status/2087597654276477298) describe the event and note previous and ongoing work to diversify providers across regions.
- [Marinade Finance shared its perspective](https://x.com/MarinadeFinance/status/2087485897470083337) on the incident.
- Terraswitch published its [incident report](https://www.teraswitchstatus.com/incidents/rb6k5l3qxw9k).

## Protocol and validator client work

A proposed Solana Improvement Document (SIMD) would increase the number of accounts a transaction can reference. Validator-client teams are also working on cache management, parallel processing, resource usage, and data propagation.

- A [proposal to increase transaction account references](https://github.com/solana-foundation/solana-improvement-documents/pull/596) builds on blockspace increasing from 60M compute units (CUs) to a 100M CU limit per block and transaction sizes increasing from 1,232 bytes to 4,096 bytes. It would allow transactions to read and write more accounts for more complex applications.
- Agave is improving its program cache by [increasing its global capacity from 512 to 1,024 programs](https://github.com/anza-xyz/agave/pull/14482), [invalidating cache entries based on the latest deployment slot in the bank](https://github.com/anza-xyz/agave/pull/14484), and [improving built-in program handling](https://github.com/anza-xyz/agave/pull/14518). The work aims to load more programs with fewer cache reloads.
- Agave will [reuse pinnable slices in its RocksDB integration](https://github.com/anza-xyz/agave/pull/14470) rather than repeatedly creating and destroying them during Repair, which reconstructs validator data using error correction.
- Agave will [parallelize BLS vote verification](https://github.com/anza-xyz/agave/pull/14380) to handle multiple verification jobs simultaneously when incoming Alpenglow votes could otherwise overload a validator.
- Agave is [considering transaction-size-aware scheduling](https://github.com/anza-xyz/agave/pull/14361) to prepare for a possible future where transactions exceed the 4KB size constraint.
- Agave is [running banking-stage checks in parallel](https://github.com/anza-xyz/agave/pull/14129), allocating more workers and a job queue for checks such as transaction sanitization, account locks, and blockhash validity.
- Agave is changing its [snapshot interval from 100 slots to 200 slots](https://github.com/anza-xyz/agave/pull/14350). Snapshots let validators restart without replaying every transaction from the beginning, and the change increases snapshot slot coverage as slot times decrease from 400ms to 200ms.
- Firedancer is working to [reduce compute, memory, and memory read/write usage](https://github.com/firedancer-io/firedancer/pull/10702) based on whether services are running or idle. A Firedancer instance has a memory footprint of around 300GB, much of it used to keep services live.
- Mithril is [implementing the Retransmit service](https://github.com/Overclock-Validator/mithril/pull/262), which identifies peers to receive shreds—pieces of ledger data—and sends them onward as part of the Turbine tree.

## Client and program tooling

Language clients, program frameworks, and testing tools are expanding support for application state, transaction signing, encoding, instruction introspection, and future transaction formats.

- Solana Web3.js will support a [Memo program class](https://github.com/solana-foundation/solana-web3.js/pull/3859), allowing applications to invoke an instruction that shows logs in a transaction.
- Anza’s Kit is planning [React hooks for state management of Solana primitives](https://github.com/anza-xyz/kit/pull/1900), including primitives such as airdrops.
- Kit is [decoupling transaction signing from sending](https://github.com/anza-xyz/kit/pull/1899), enabling workflows including partial signing and delayed sending.
- Solana Go received work to [optimize base58 encoding and decoding](https://github.com/solana-foundation/solana-go/pull/477), which is used across instruction data, account addresses, and transaction APIs.
- Anchor [resolved an issue affecting the Instructions Sysvar account](https://github.com/otter-sec/anchor/pull/4890). The account supports instruction introspection, allowing an instruction to read data or results from other instructions in the same transaction.
- LiteSVM is preparing [Transactions V1 support](https://github.com/LiteSVM/litesvm/pull/399), including a new transaction format and larger transaction sizes for program testing.
