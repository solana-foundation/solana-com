## Ecosystem work

SIMDs

- Changes to the [Vote Account state](https://github.com/solana-foundation/solana-improvement-documents/pull/701) were proposed WTM - The proposal makes changes to how commission rewards are calculated on Solana. Commission updates on Solana are pushed for two epochs because of two SIMDs that create a delay when a validator wants to update their commission rate (two epochs from when the update was asked for.

- [Live commission collectors](https://github.com/solana-foundation/solana-improvement-documents/pull/700) were proposed WTM - When calculating commissions, validators use a cached account state on the validator rather than a live account state. This change will put that state in account data and will be used to calculate commissions.

Validator clients (Agave, Firedancer, Mithril)

- Agave is working to improve [its file system I/O](https://github.com/anza-xyz/agave/pull/16137) WTM - File system I/O is very expensive. In this change, Agave is allocating buffers too small that when it performs I/O with the file system, it creates a lot of faults. This change increases the requested size.

- Agave is preparing for SIMD-0500 by [hoisting part of the deployment environment on the Solana CLI](https://github.com/anza-xyz/agave/pull/16233) WTM - SIMD-0500 will reject deployments of sBPFv0, v1, and v2 programs. The runtime does this check, but the user will still pay fees on uploading these programs despite it not being allowed. This change prepares to reject these program versions ahead of time even before you do anything expensive onchain.

- Agave is [stake-weighting its gossip implementation](https://github.com/anza-xyz/agave/pull/16215) WTM - Gossip is a push-pull messaging implementation on Agave. Every valdiator talks to its validator peers. In order to manage congestion, it would be better for validators to prioritize message processing. This change proposes that the validators process higher-staked validators ahead of others.

- Agave is [decoupling snapshot loading from the accounts stake list](https://github.com/anza-xyz/agave/pull/15828) WTM - Snapshot loading relies on the Agave stake delegation list even if you are a client different from Agave. This change allows for better cross-compatibility as well as decreased dependency in order to start up a validator.

- Firedancer is working to [remove its TowerBFT implementation](https://github.com/firedancer-io/firedancer/pull/12460) following a successful support of Alpenglow WTM - Firedancer successfully participated in the new Alpenglow consensus. This is a routine cleanup.

Solana language clients (Web3.js, Solana Kit, Kit plugins, Solana SDK, Codama, Solana Go)

- Solana Web3 js is [adding a ‘mainnet’ moniker](https://github.com/solana-foundation/solana-web3.js/pull/3995) to its list of cluster URLs WTM - There is talk that following Alpenglow, Solana will drop the ‘beta’ tag from the Solana cluster definitions. This change supports the preparation for this.

- Solana Web3 js is working to [add a package for supporting Vercel’s agent-browse](https://github.com/solana-foundation/solana-web3.js/pull/3994)r to interact on a wallet with the wallet standard WTM - This change allows users to build Solana web applications with agents given that they now can have a simulated environment where they can interact with a wallet application onto your main Solana web application.

- Solana Web3 js opened a discussion for [allowing only Transaction V1 on its transaction implementation](https://github.com/solana-foundation/solana-web3.js/discussions/3997) following a possible SIMD restricting Legacy and V0 transactions WTM - Transaction V1 will probably be the first transaction implementation the protocol will iterate and invest heavily on for the foreseeable future. Efforts to drop Legacy and V0 Transactions are happening across the stack and are preparing for the SIMD to be approved and implemented.

Solana program frameworks (Anchor, Pinocchio, Steel, Quasar)

- Pinocchio will [use r2 as the lazy program entrypoint](https://github.com/anza-xyz/pinocchio/pull/460) WTM - r2 is the third reserved register with the Solana Virtual Machine. It is usual unset during program loading which means it is available for use by program frameworks. Pinocchio has gone ahead to use r2 as the default program entrypoint, which means no custom implementation before your program starts running your Solana program for users.
