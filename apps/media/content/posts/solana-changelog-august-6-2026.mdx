This week, Solana engineering teams shipped new Agave, Firedancer, Frankendancer, SDK, and testing-tool releases, while **the feature gate lowering slot times from 400ms to 350ms reached Devnet and Testnet**.

A notable feature gate for lowering slot times from 400ms to 350ms is now active on [Devnet](https://explorer.solana.com/address/iBRL5RuWhw4yqaAZu96RUULHckHTZAoe2b77qaV38JZ?cluster=devnet) and [Testnet](https://explorer.solana.com/address/iBRL5RuWhw4yqaAZu96RUULHckHTZAoe2b77qaV38JZ?cluster=testnet); upcoming feature gates are tracked in the [Agave feature gate tracker schedule](https://github.com/anza-xyz/agave/wiki/Feature-Gate-Tracker-Schedule).

## SIMDs and protocol discussions

Solana Improvement Documents (SIMDs) moved forward on program account sizing and Vote account safety. One proposal was accepted, and one discussion was created for further review.

- A proposal to [set the right account data size when modifying a Solana program](https://github.com/solana-foundation/solana-improvement-documents/pull/433) was accepted. Modifying an existing program currently requires manually extending the program size before loading in the new update; the proposal makes that space extension automatic.
- A discussion on [prohibiting a self-withdrawal from a Vote account](https://github.com/solana-foundation/solana-improvement-documents/discussions/594) was created. The issue describes a footgun in the existing Vote program: A Vote account can withdraw SOL from itself and send it back to itself, which the runtime treats as a close-account operation and erases the Vote account data.

## Validator client work

Agave, Firedancer, Frankendancer, and Mithril each advanced client implementation work this week. The changes focused on conformance, runtime execution, Turbine behavior, snapshots, and Alpenglow message transport.

- Anza continued Agave [conformance](https://github.com/anza-xyz/agave/issues/12378) work for [instructions](https://github.com/anza-xyz/agave/pull/14264), [VM syscalls](https://github.com/anza-xyz/agave/pull/14236), [VM serialization](https://github.com/anza-xyz/agave/pull/14198), and [VM transaction running](https://github.com/anza-xyz/agave/pull/14305). Fuzz testing generates possible inputs to a system to find bugs, and conformance helps test multiple validator client implementations so valid cases and errors match across clients.
- Agave began [deprecating SysvarSerialize](https://github.com/anza-xyz/agave/issues/10672) on the `solana-account` crate. The effort tracks replacing a trait called `SysvarSerialize` with a more generic method for serializing Sysvar accounts across the Agave stack.
- Agave is rethinking its [program reloading methodology](https://github.com/anza-xyz/agave/pull/14296) during transaction processing. Instead of deserializing and loading all programs among instruction accounts before execution, the proposed change uses a more incremental, as-needed loading strategy.
- Agave improved [Leader Turbine broadcasting caching and routing table rebuilds](https://github.com/anza-xyz/agave/pull/14321). Leaders create blocks from transactions, break them into shreds, and distribute them to validators through Turbine; the change helps a leader more efficiently track peers and update that cache.
- Firedancer is [implementing snapshot creation](https://github.com/firedancer-io/firedancer/pull/10609). Validators can use snapshots to rebuild a starting point for participating in consensus and processing transactions; before this change, Firedancer and Frankendancer used the embedded Agave validator to produce snapshots.
- Firedancer will support [QUIC datagrams](https://github.com/firedancer-io/firedancer/pull/10677) for Alpenglow messages. Agave and Firedancer will use QUIC datagrams instead of QUIC streams, reducing the overhead of setting up QUIC stream connections.
- Mithril is [keeping updated on Agave’s conformance suite](https://github.com/Overclock-Validator/mithril/pull/258). Mithril is a new validator implementation written in Go that will soon participate in consensus, and the conformance suite helps it keep up with Agave across multiple client implementations.

## RPC, clients, and program tooling

RPC 2.0 work, language client updates, Solana Program Library work, and testing framework improvements also moved forward. These changes focus on request filtering, React application primitives, token authority support, and local development workflows.

- Superbank is [adding a request filter](https://github.com/solana-rpc/superbank/pull/64) for suspicious requests. For data-streaming services, spam requests can add unnecessary system load, and this change allows Superbank to block those requests at the parameter level.
- Kit will add new React hooks for [useAirdrop](https://github.com/anza-xyz/kit/pull/1879), [usePayer and useIdentity](https://github.com/anza-xyz/kit/pull/1876), and [usePlanTransaction, usePlanTransactions, useSendTransaction, and useSendTransactions](https://github.com/anza-xyz/kit/pull/1869). The hooks let React applications use these primitives and update components based on state changes.
- The under-development `ed25519-programmatic-signer` program added a [nonce program implementation](https://github.com/solana-program/ed25519-programmatic-signer/pull/12) as its replacement for durable nonces. The change is the SPL successor to the durable nonces implementation currently onchain and is similar to [Blueshift’s Vector](https://github.com/blueshift-gg/vector).
- Anchor will [support multisig authorities on its SPL token interface](https://github.com/otter-sec/anchor/pull/4870). It was already possible to assign a multisig address as the authority on an SPL token; this gives SPL tokens created by an Anchor program more flexibility in supporting that functionality.
- Surfpool added a [stop command to its daemon service](https://github.com/solana-foundation/surfpool/pull/700). Instead of typing `Ctrl+C` to stop a running Surfpool instance, users running Surfpool in detached mode can now run an additional command that stops the service.
