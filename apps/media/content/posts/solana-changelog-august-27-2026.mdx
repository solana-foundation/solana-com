**V1 Transactions are coming soon to Solana.** Teams preparing for the release should review the guidance for larger transaction sizes. Meanwhile, a feature gate to reduce slot time to 300ms reached Mainnet.

## Preparing for V1 Transactions

Solana is preparing to introduce V1 Transactions. Builders and teams should follow the guidance on the upgrade page as they prepare for the release.

* Read the [V1 Transactions and larger transaction sizes upgrade guidance](https://solana.com/upgrades/larger-transaction-sizes).

## Network releases and feature gates

This week brought feature-gate activity across Testnet, Devnet, and Mainnet, alongside releases for validator clients, SDKs, programs, and testing tools.

### Feature gates

* The post-execution `min_balance` relaxation reached [Testnet](https://explorer.solana.com/address/BY4JhHLahVzS9ynfDz4exzGPbVXhFmJvEyMWsXbDBqME?cluster=testnet) and [Devnet](https://explorer.solana.com/address/BY4JhHLahVzS9ynfDz4exzGPbVXhFmJvEyMWsXbDBqME?cluster=devnet).
* Testnet set [lamports per byte to 6333](https://explorer.solana.com/address/4a6f7o7iTcA8hRDCrPLkSatnt5Ykxiu36wo5p1Tt12wC?cluster=testnet).
* Devnet upgraded the [BPF Stake Program to v5.1.0](https://explorer.solana.com/address/s51VGwCAgebo2745DSUris72RavoLkXGUmVJosESCXr?cluster=devnet).
* Mainnet activated a feature gate to [reduce slot time to 300ms](https://explorer.solana.com/address/iBRLL3k18HST852F1Mf3Lv83waTNQmmqvKDxvYGwQFL).

## Proposed protocol changes

Contributors opened several Solana Improvement Documents (SIMDs), proposals for changes to Solana’s protocol and network behavior. The proposals address runtime arithmetic, leader scheduling, stake deactivation, account withdrawals, and transaction ordering.

* A proposed [runtime move from floating-point to integer arithmetic](https://github.com/solana-foundation/solana-improvement-documents/pull/607) aims to provide more predictable behavior with fewer edge cases and improve performance.
* A proposed [leader-schedule implementation change](https://github.com/solana-foundation/solana-improvement-documents/pull/612) aims to keep a validator’s leader slots within one four-slot leader window during an epoch.
* A proposed change would [allow stake accounts delegated to nonexistent vote accounts to deactivate](https://github.com/solana-foundation/solana-improvement-documents/pull/608).
* Two proposals would prohibit self-withdrawals from [nonce accounts](https://github.com/solana-foundation/solana-improvement-documents/pull/610) and [vote accounts](https://github.com/solana-foundation/solana-improvement-documents/pull/609).
* Contributors opened a discussion on [enforcing priority ordering for transaction batches](https://github.com/solana-foundation/solana-improvement-documents/discussions/605), with the goal of creating more deterministic ordering within a slot.

## Validator and RPC work

Agave and Firedancer continued work on transaction delivery, bank lifecycle management, program caching, TLS, and Alpenglow-related support. Shipstern also joined the RPC 2.0 initiative.

* Anza plans to deprecate Agave’s original TPU client in favor of [`tpu-client-next`](https://github.com/anza-xyz/agave/pull/14872), its current transaction-sending service for validators.
* Agave implemented [graceful shutdown for an unused bank state in a fork](https://github.com/anza-xyz/agave/pull/14864), decoupled the [global program cache from banking forks](https://github.com/anza-xyz/agave/pull/14839), and improved behavior during a [Core BPF migration](https://github.com/anza-xyz/agave/pull/14629).
* Agave hardened its TPU client API to use [QUIC streams rather than QUIC datagrams](https://github.com/anza-xyz/agave/pull/14810).
* Firedancer is building an [X.509 certificate verifier service](https://github.com/firedancer-io/firedancer/pull/11029) and a [no-dependency TLS implementation](https://github.com/firedancer-io/firedancer/pull/10973).
* Firedancer is adding support for Alpenglow [rewards](https://github.com/firedancer-io/firedancer/pull/10939), [BLS API usage](https://github.com/firedancer-io/firedancer/pull/10982), [Rotor FECs](https://github.com/firedancer-io/firedancer/pull/10990), [Rotor repair responses](https://github.com/firedancer-io/firedancer/pull/11023), and [Alpenglow footers](https://github.com/firedancer-io/firedancer/pull/11025).
* Firedancer [reimplemented its public-key hash function](https://github.com/firedancer-io/firedancer/pull/10959) to speed cryptographic operations involving Solana keypairs.
* The RPC 2.0 initiative added Shipstern, following the project’s [rename from Yellowstone-vixen](https://github.com/solana-rpc/shipstern/pull/279).

## SDKs, programs, and developer tools

Updates this week included a transaction-signature validation fix, confidential-transfer support in Solana Go, program framework improvements, and TLS support for Surfpool.

* The Rust Solana SDK transactions crate fixed a bug by [requiring signature and public-key counts to match before signature verification](https://github.com/anza-xyz/solana-sdk/pull/890).
* Solana Go is adding [confidential transfers](https://github.com/solana-foundation/solana-go/pull/484) and incorporating [Firedancer’s AVX2 implementation](https://github.com/solana-foundation/solana-go/pull/479) for faster cryptographic operations on supported x86\_64 processors.
* The Subscriptions Program is adding [Token-2022 transfer-hook support](https://github.com/solana-foundation/subscriptions/pull/244).
* Anchor is adding a [minimal target binary and logging option](https://github.com/otter-sec/anchor/pull/4963) for building and deploying programs in CI.
* Surfpool is adding [TLS connections to Surfnet](https://github.com/solana-foundation/surfpool/pull/770).
