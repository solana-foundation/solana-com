## PSA

```bash
npm install @solana/web3.js@3
```

The new web3.js package is now ready for general use. To migrate to the new version, add the dependency to your project using the command above.

For now, you will have to call the version explicitly, and there will be moves to have it be the default version you install without the version tag.

See the advisory [here](https://github.com/solana-foundation/solana-web3.js/issues/3947).

## Ecosystem work

### SIMDs

- [Requiring hash validation for Loader v2 to Loader v3 migration](https://github.com/solana-foundation/solana-improvement-documents/pull/690) for programs was proposed
  - WTM - This affects programs deployed by the runtime, not Solana programs deployed by users. This change will ensure that migrations check that the content is the same before adopting the program broadly by the cluster.

- [Simplifying the runtime environments to a single service](https://github.com/solana-foundation/solana-improvement-documents/pull/688) was proposed
  - WTM - Currently there are two runtime environments, one for the current slot and another for the next slot. This change combines both runtimes since previous work would allow program deployments within the same slot without downtime for that slot.

- [Removing the ExtendProgram instruction](https://github.com/solana-foundation/solana-improvement-documents/pull/685) from the Program Loader V3 Program was proposed
  - WTM - The new instruction for upgrading programs has since been updated to automatically extend the program length as needed during an upgrade. This change removes a legacy instruction that preemptively extended the program length via a separate instruction before updating.

- [Allowing prefunding SOL on LoaderV3 Buffer accounts](https://github.com/solana-foundation/solana-improvement-documents/pull/684) was proposed
  - WTM - This change builds on work already done on the CreateAccountAllowPrefund instruction. It allows ProgramData to be written to accounts that already exist and hold SOL.

### Validator clients (Agave, Firedancer, Mithril)

- Agave will [implement a faster random number generator](https://github.com/anza-xyz/agave/pull/15762) for peer sampling in its gossip implementation
  - WTM - Agave plans to use a weighted shuffle for gossip peer selection. Gossip allows nodes to exchange network addresses, stake, credentials, and other information with a subset of the cluster. The faster random number generator improves this selection process and supports future work to select geographically closer peers to reduce latency.

- Agave will increase the default snapshot interval to 200,000 slots
  - WTM - Since slot times have decreased, full snapshots would otherwise be created more often than necessary. Increasing the default interval keeps snapshot production at the same rate as slots become faster.

### RPC 2.0

- Cloudbreak is improving its [queries of token mints and token accounts](https://github.com/solana-rpc/cloudbreak/pull/56)
  - WTM - Cloudbreak is the open-source RPC implementation for account state. This change routes token mint and token account data requests to a separate `getProgramAccounts` request onchain.

### Solana language clients (Web3.js, Solana Kit, Kit plugins, Solana SDK, Codama, Solana Go)

- Solana Rust SDK added [helpers for signing versioned transactions](https://github.com/anza-xyz/solana-sdk/pull/990)
  - WTM - Versioned transactions are increasingly important following the rollout of Transaction V1. These methods support multiple signers on a transaction.

### Solana program frameworks (Anchor, Pinocchio, Steel, Quasar)

- Anchor’s TypeScript provider [created a new type to simplify instruction account resolution](https://github.com/otter-sec/anchor/pull/5154)
  - WTM - Anchor maintains a TypeScript provider that allows web apps to interact with program methods. As the provider moves from legacy web3.js to Kit, this change simplifies a type used to resolve accounts for an instruction.

- Pinocchio will add [instruction helpers for token metadata and token groups](https://github.com/anza-xyz/pinocchio/pull/451) in its crate for interacting with the Token-2022 program
  - WTM - Pinocchio does not yet support instructions for the Token Metadata and Token Group extensions. Adding these helpers allows Pinocchio to interact with both extensions.
