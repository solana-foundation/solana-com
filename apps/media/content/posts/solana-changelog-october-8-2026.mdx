## Ecosystem work

SIMDs

- [Requiring hash validation for Loader v2 to Loader v3 migration](https://github.com/solana-foundation/solana-improvement-documents/pull/690) for programs was proposed WTM - This affects programs deployed by the runtime, not Solana programs deployed by users. This change will ensure that migrations check that the content is the same before adopting the program broadly by the cluster.

- [Simplifying the runtime environments to a single service](https://github.com/solana-foundation/solana-improvement-documents/pull/688) was proposed WTM - Currently there are two runtime environments, one for the current slot, another for the next slot. This change combines both runtimes since previous work would allow program deployments within the same slot without downtime for that slot.

- [Removing the ExtendProgram instruction](https://github.com/solana-foundation/solana-improvement-documents/pull/685) from the Program Loader V3 Program was proposed WTM - The new instruction for upgrading program has since been updated to automatically extend the program length as needed when it is being upgraded. This change removes a legacy instruction that preemptively extended the program length via a separate instruction before updating.

- [Allowing prefunding SOL on LoaderV3 Buffer accounts](https://github.com/solana-foundation/solana-improvement-documents/pull/684) was proposed WTM - This change builds on work already done on the CreateAccountAllowPrefund instruction. By allowing this, accounts that already exist and have SOL (a lamport balance) on them will allow for ProgramData writing.

Validator clients (Agave, Firedancer, Mithril)

- Agave will [implement a faster random number generator](https://github.com/anza-xyz/agave/pull/15762) for its peer sampling in its gossip implementation WTM - Agave is planning to do a weighted shuffle implementation of its peer selection criteria for gossip. Gossip is the service that allows nodes to send and receive crucial information about each other - network addresses, stake, credentials, etc. It does not require nodes to send to everyone but only a subset of all the nodes in the cluster. To select for which nodes to send to, it selects peers based on a random number generation. This change uses a faster version of that. There are obvious performance improvements here, but this is also in line with future plans to make the cluster more geographically aware. Allowing the peers to be selected based on how near they are to the node decreases latency in the gossip implementation.

- Agave will increase the default snapshot interval to 200k slots WTM - Since slot times have reduced, full snapshots will be created more often than is necessary. Increasing the default snapshot size keeps snapshot production at the same rate even as slots become faster.

RPC 2.0

- Cloudbreak is improving is [querying of token mints and token accounts](https://github.com/solana-rpc/cloudbreak/pull/56). WTM - Cloudbreak is the RPC open source implementation of anything related to account state. Token Mint data and token data are staples when it comes to querying information from onchain. This implementation routes these data requests to a separate getProgramAccounts request onchain.

Solana language clients (Web3.js, Solana Kit, Kit plugins, Solana SDK, Codama, Solana Go)

- Solana Rust SDK added [helpers for signing versioned transactions](https://github.com/anza-xyz/solana-sdk/pull/990) WTM - Versioned transactions are becoming especially important, especially since TransactionV1 has been rolled out. This supports multiple signers to a transaction by adding a few more flexible methods.

Solana program frameworks (Anchor, Pinocchio, Steel, Quasar)

- Achor’s Typescript provider [created a new type to simplify instruction accounts resolution](https://github.com/otter-sec/anchor/pull/5154) WTM - Anchor maintains its own Typescript provider that allows web apps to interact with its program methods. They are currently in the process of moving from using a legacy web3.js version to using Kit. This change simplifies a type that was previously used to resolve accounts for an instruction.

- Pinocchio’s will add [instruction helpers for token metadata and token groups](https://github.com/anza-xyz/pinocchio/pull/451) in its crate for interacting with the Token-2022 program WTM - There are two instructions that still don’t have support on Pinocchio for this change, namely the Token Metadata and the Token Group extensions. Adding these allows Pinocchio to interact with these features.
