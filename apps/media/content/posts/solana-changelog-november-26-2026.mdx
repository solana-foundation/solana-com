## Ecosystem work

### Validator clients (Agave, Firedancer, Mithril)

- Agave will support [dynamic networking buffers based on the operating system](https://github.com/anza-xyz/agave/pull/13055)
  - WTM - Operating systems handle networking differently because it happens in kernel space. This change lets the validator adjust based on the operating system and load.

- Agave’s connection cache implementation will be [removed](https://github.com/anza-xyz/agave/pull/17102) in favor of `tpu-client-next`
  - WTM - `tpu-client-next` is the default way to send transactions to the TPU. This change makes it the default in the `solana-client` crate, which transaction senders typically use.

- Agave will [retransmit vote messages three times](https://github.com/anza-xyz/agave/pull/17006) to help ensure delivery
  - WTM - Retransmitting votes reduces the risk that validators lose rewards because vote messages were dropped.

- Agave will [improve snapshot decompression times using its worker pool implementation](https://github.com/anza-xyz/agave/pull/17024)
  - WTM - Snapshots let validators restart from a fixed point and catch up to the rest of the network. This change uses Agave’s worker pool to decompress snapshots faster.

- Agave will [decouple the replay thread from the scheduling thread](https://github.com/anza-xyz/agave/pull/17065)
  - WTM - Replay and scheduling behave differently when a validator is a leader and a non-leader. Separating them prevents the two workflows from getting in each other’s way.

- Firedancer is [advertising its snapshot server to the cluster](https://github.com/firedancer-io/firedancer/pull/12764)
  - WTM - Other validator operators will be able to discover Firedancer’s snapshot server, download snapshots, and restart when needed.

- Mithril is making another [performance optimization to its Replay implementation](https://github.com/Overclock-Validator/mithril/pull/371)
  - WTM - Replay is a bottleneck for faster and larger blocks. This change helps Mithril keep up with the network and more mature validator implementations such as Agave and Firedancer.

### Solana Program Library (SPL) and Core BPF

- The Token ACL Program will allow [optional additional instruction data for the `freeze_permissionless` and `thaw_permissionless` instructions](https://github.com/solana-foundation/token-acl/pull/54)
  - WTM - According to the pull request, this could support inline signature verification or Groth16 proofs without requiring a second instruction and instruction introspection.

### Solana program frameworks (Anchor, Pinocchio, Quasar)

- Anchor is adding an [opt-in constraint to its Accounts struct for duplicate accounts](https://github.com/otter-sec/anchor/pull/5345)
  - WTM - Anchor allows duplicate accounts in its Accounts struct implementation, which can create developer experience and security risks. Rather than break existing behavior, the framework will let developers add a constraint that prevents an account in the struct from being passed again.

- Quasar is [tightening ownership rules at CPI boundaries](https://github.com/blueshift-gg/quasar/pull/528)
  - WTM - Frameworks can decide whether writable ownership rules propagate to cross-program invocation boundaries. Quasar’s stricter rules provide more defined behavior for ownership across CPIs.

### Testing frameworks (Mollusk, LiteSVM, Surfpool)

- LiteSVM will match existing validator behavior by [advancing the SlotHashes sysvar account to the correct state in its `warp_to_slot` implementation](https://github.com/LiteSVM/litesvm/pull/463)
  - WTM - `warp_to_slot` lets a test time-travel to a slot and evaluate state. This change ensures the SlotHashes sysvar also reflects the state at that slot.

- Mollusk will add [`--disable-rent-exempt-checks` and `--no-panic` CLI flags](https://github.com/anza-xyz/mollusk/pull/369)
  - WTM - Rent checks were enabled by default in an earlier change without a way to disable them. These flags add that control to the CLI.

- Surfpool will [serve TPU QUIC](https://github.com/solana-foundation/surfpool/pull/971) from its local test harness so program deployments work
  - WTM - Surfpool could not keep up with `solana program deploy` in a previous release, causing transaction sends to fail repeatedly. This change lets deployments complete as intended.
