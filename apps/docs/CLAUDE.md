# Solana Docs - Developer Documentation

> See root `/CLAUDE.md` for monorepo-wide configuration and shared tooling.

## Overview

The /developers landing, the Solana developer documentation and the cookbook.
General `/learn` content is owned by `apps/web`.

**Package name**: `solana-docs` **Default port**: 3003 **Asset prefix**:
`/docs-assets`

## Tech Stack

- **Framework**: Next.js 15 (App Router) with next-intl
- **Documentation**: Fumadocs (`fumadocs-core`, `fumadocs-mdx`) for content
  loading; the docs chrome is this app's own code
- **Code Highlighting**: Shiki, through Fumadocs' rehype-code
- **Styling**: Tailwind CSS 3, SCSS, and the docs stylesheets in
  `content/styles`
- **Search and Ask AI**: Inkeep

## Content Structure

- Files in `content/` are processed by `fumadocs-mdx` (`source.config.ts`, one
  collection); generated sources are stored in `.source/` (gitignored).
- `src/lib/docs/source.ts` maps `docs/<locale>/x.mdx` to
  `/<locale>/developers/docs/x` and `cookbook/x.mdx` to `/developers/cookbook/x`
  (English is unprefixed). It also reads the English /learn articles from
  `apps/web/content/learn` for `/llms.txt` and `/llms-full.txt` only.
- English is the source language. Translations are generated by Lingo; a page
  without one is served in English at its locale URL.
- `content/navigation/en.json` is the navigation in every locale.

## Routing

- `src/middleware.ts` rewrites `<page>.md` and requests whose Accept header
  prefers `text/markdown` (q-values count, `src/lib/docs/negotiation.ts`) to
  `src/app/api/markdown/[...slug]`, and handles locales. HTML pages get
  `Vary: Accept` and a `Link` header to their `.md` twin and
  `/developers/docs/llms.txt`. The markdown route also answers missing pages (a
  Markdown 404), `/developers` and docs search (`/developers/docs?q=`).
- Missing docs pages: builds inline every page's path (`DOCS_PAGE_PATHS`,
  `src/lib/docs/page-paths.ts`), and the middleware sends unknown docs URLs to
  `app/global-not-found.tsx`, so the 404 is rendered on the server. `next dev`
  has no list, so missing pages render the not-found.tsx boundaries instead.
- `redirects.ts` sends old URLs (`/docs/...`, `/developers/guides/...`,
  `/developers/bootcamp/...`) to their pages; each rule also gets its `.md` and
  locale variants.

## Build Configuration

- Asset prefix: `/docs-assets` for Vercel multi-project deployment
- Memory allocation: 4096MB for builds
- Sentry integration for error tracking (loaded after the page)
- Fumadocs MDX processing runs on postinstall
