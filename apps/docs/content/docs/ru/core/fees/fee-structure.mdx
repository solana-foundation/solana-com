<Callout type="info" title="Краткое резюме">
  Итоговая комиссия = базовая комиссия (5 000 lamport/подпись, 50% сжигается) + комиссия за приоритизацию
  (CU_price * CU_limit / 1M lamport, 100% validator'у). Взимается независимо от того,
  выполнена транзакция успешно или нет.
</Callout>

## Алгоритм расчёта комиссии

Итоговая комиссия за транзакцию вычисляется функцией
[`calculate_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L53-L72):

```text title="Total fee formula"
total_fee = base_fee + prioritization_fee
```

На входе — сообщение транзакции, текущее значение `lamports_per_signature`
(в настоящее время 5 000) и комиссия за приоритизацию, полученная из инструкций вычислительного бюджета. Итоговая комиссия списывается с плательщика комиссии до начала выполнения.
Если транзакция завершается с ошибкой, комиссия всё равно взимается.

## Базовая комиссия

Базовая комиссия покрывает стоимость верификации подписей Ed25519, а также верификации подписей прекомпилированными программами. С каждой подписи в транзакции взимается комиссия, включая подписи, верифицированные прекомпилированными программами Ed25519, Secp256k1 и Secp256r1.

Функция
[`calculate_signature_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L75-L92)
вычисляет:

```text title="Base fee formula"
signature_count = num_transaction_signatures
                + num_ed25519_signatures
                + num_secp256k1_signatures
                + num_secp256r1_signatures   (if feature enabled)

base_fee = signature_count * lamports_per_signature
```

- `num_transaction_signatures`: количество подписей Ed25519 в транзакции
  (как правило, по одной на каждого подписанта).
- `num_ed25519_signatures`, `num_secp256k1_signatures`,
  `num_secp256r1_signatures`: подписи, верифицированные соответствующими
  прекомпилированными программами.
- `lamports_per_signature`: в настоящее время
  [5 000 lamport](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-structure/src/lib.rs#L210).

### Распределение комиссий

Базовая комиссия и комиссия за приоритизацию распределяются по-разному. Функция
[`calculate_reward_and_burn_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L85-L98)
в среде выполнения вычисляет:

```text title="Fee distribution"
burn_amount     = transaction_fee * 50 / 100
validator_share = (transaction_fee - burn_amount) + priority_fee
```

- **Базовая комиссия (transaction_fee)**: 50%
  [сжигается](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L93)
  (изымается из обращения), а 50% направляется validator'у, создающему блок. Процент сжигания задаётся константой
  [`DEFAULT_BURN_PERCENT = 50`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-calculator/src/lib.rs#L70).
- **Комиссия за приоритизацию**: 100% направляется validator'у (ничего не сжигается), согласно
  [SIMD-0096](https://github.com/solana-foundation/solana-improvement-documents/blob/main/proposals/0096-reward-collected-priority-fee-in-entirety.md).

Итоговое вознаграждение validator'а за транзакцию составляет:

```text
validator_reward = (base_fee / 2) + prioritization_fee
```

## Комиссия за приоритизацию

Комиссия за приоритизацию — это необязательная комиссия, повышающая приоритет планирования транзакции. Вычислительная единица (CU) — это единица измерения вычислений, которую среда выполнения отслеживает в ходе выполнения транзакции. Каждая операция (арифметическая, обращение к памяти, системный вызов) стоит фиксированное количество CU. Задать комиссию за приоритизацию можно, включив инструкции вычислительного бюджета в свою транзакцию. (Подробнее см. руководство
[«Как использовать комиссии за приоритет»](/docs/core/fees).)

### Формула комиссии за приоритизацию

Функция
[`get_prioritization_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L61-L69)
вычисляет:

```text title="Prioritization fee formula"
micro_lamport_fee = compute_unit_price * compute_unit_limit
prioritization_fee = ceil(micro_lamport_fee / 1,000,000)
```

| Переменная             | Описание                                                                                                                                                                       | По умолчанию                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `compute_unit_price` | Микро-lamport за CU, задаётся через `SetComputeUnitPrice`                                                                                                                              | 0 микро-lamport                |
| `compute_unit_limit` | Максимальное количество CU, которое может использовать транзакция; задаётся через `SetComputeUnitLimit`                                                                                                            | Сумма значений по умолчанию для каждой инструкции |
| `1 000 000`          | Коэффициент пересчёта микро-lamport в lamport ([`MICRO_LAMPORTS_PER_LAMPORT`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L17)) | --                              |

<Callout type="info" title="Транзакции v1 задают комиссию напрямую">
  Формула цена × лимит применяется к устаревшим транзакциям и транзакциям v0. В
  [формате v1](/docs/core/transactions/versioned-transactions#v1-format)
  комиссия за приоритизацию задаётся как абсолютная итоговая сумма в lamport непосредственно в конфигурации сообщения — без цены за CU, без умножения и без округления.
</Callout>

### Лимит вычислительных единиц

Лимит вычислительных единиц — это максимальное количество CU, которое может использовать транзакция.
Если инструкция
[`SetComputeUnitLimit`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L32)
не включена, значение по умолчанию рассчитывается исходя из количества и типа инструкций (200 000 CU для каждой встроенной инструкции, 3 000 — для каждой нативной). Подробнее о расчёте по умолчанию см. в разделе
[«Вычислительный бюджет»](/docs/core/fees/compute-budget).

<Callout type="warn">
  Комиссия за приоритизацию рассчитывается на основе запрошенного лимита CU, а не фактически использованного. Установка лимита выше необходимого означает оплату неиспользованных вычислительных единиц.
</Callout>

### Цена вычислительной единицы

Цена вычислительной единицы — это необязательная сумма в микро-lamport, уплачиваемая за каждую запрошенную CU. Цена CU напрямую определяет комиссию за приоритизацию. Чтобы задать цену CU, включите инструкцию
[`SetComputeUnitPrice`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L35)
в свою транзакцию.

<Callout>
  Цена CU по умолчанию равна 0, поэтому комиссия за приоритизацию по умолчанию также равна 0.
</Callout>

Актуальные оценки цены CU в реальном времени предоставляют указанные ниже провайдеры API комиссий за приоритет.

### Приоритет планирования транзакций

Планировщик ранжирует транзакции с помощью функции
[`calculate_priority_and_cost`](https://github.com/anza-xyz/agave/blob/v3.1.8/core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs#L526-L546):

```text title="Transaction priority formula"
Priority = reward * 1,000,000 / (cost + 1)
```

- **reward** — доход validator'а от комиссий = комиссия за приоритизацию + не сожжённая
  часть базовой комиссии. Вычисляется функцией
  [`calculate_reward_for_transaction`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L64-L83).
- **cost** — расчётная стоимость CU по оценке планировщика
  ([estimated CU cost](https://github.com/anza-xyz/agave/blob/v3.1.8/cost-model/src/cost_model.rs#L37-L57)):
  стоимость подписей + стоимость блокировок на запись + стоимость instruction data + стоимость
  выполнения программы + стоимость загрузки данных аккаунтов. Подробнее см. в разделе
  [«Вычислительный бюджет»](/docs/core/fees/compute-budget#scheduler-cost-model).
- **1 000 000** — множитель для сохранения точности, поскольку стоимость нередко превышает вознаграждение в абсолютных значениях lamport.
- **+1** — защита от деления на ноль.

Приоритет определяет порядок, в котором транзакции извлекаются из буфера планировщика для выполнения.

```ts !! title="Web3.js v3"
import {
  LAMPORTS_PER_SOL,
  SystemProgram,
  Transaction,
  Keypair,
  Connection,
  ComputeBudgetProgram,
  sendAndConfirmTransaction
} from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");

const sender = await Keypair.generate();
const recipient = await Keypair.generate();

const airdropSignature = await connection.requestAirdrop(
  sender.publicKey,
  LAMPORTS_PER_SOL
);
await connection.confirmTransaction(airdropSignature, "confirmed");

// Create compute budget instructions
const limitInstruction = ComputeBudgetProgram.setComputeUnitLimit({
  units: 300_000
});
const priceInstruction = ComputeBudgetProgram.setComputeUnitPrice({
  microLamports: 1
});

const transferInstruction = SystemProgram.transfer({
  fromPubkey: sender.publicKey,
  toPubkey: recipient.publicKey,
  lamports: 0.01 * LAMPORTS_PER_SOL
});

// Add the compute budget and transfer instructions to a new transaction
const transaction = new Transaction()
  .add(limitInstruction)
  .add(priceInstruction)
  .add(transferInstruction);

const signature = await sendAndConfirmTransaction(connection, transaction, [
  sender
]);

console.log("Transaction Signature:", signature);
```

```rust !! title="Rust"
use solana_client::nonblocking::rpc_client::RpcClient;
use solana_commitment_config::CommitmentConfig;
use solana_compute_budget_interface::ComputeBudgetInstruction;
use solana_sdk::{
    native_token::LAMPORTS_PER_SOL,
    signature::{Keypair, Signer},
    transaction::Transaction,
};
use solana_system_interface::instruction::transfer;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = RpcClient::new_with_commitment(
        String::from("http://localhost:8899"),
        CommitmentConfig::confirmed(),
    );

    let sender = Keypair::new();
    let recipient = Keypair::new();

    let airdrop_signature = client
        .request_airdrop(&sender.pubkey(), LAMPORTS_PER_SOL)
        .await?;

    loop {
        let confirmed = client.confirm_transaction(&airdrop_signature).await?;
        if confirmed {
            break;
        }
    }

    // Create compute budget instructions
    let limit_instruction = ComputeBudgetInstruction::set_compute_unit_limit(300_000);
    let price_instruction = ComputeBudgetInstruction::set_compute_unit_price(1);

    let transfer_amount = LAMPORTS_PER_SOL / 100;
    let transfer_instruction = transfer(&sender.pubkey(), &recipient.pubkey(), transfer_amount);

    let recent_blockhash = client.get_latest_blockhash().await?;

    let mut transaction = Transaction::new_with_payer(
        &[limit_instruction, price_instruction, transfer_instruction],
        Some(&sender.pubkey()),
    );
    transaction.sign(&[&sender], recent_blockhash);

    let signature = client.send_and_confirm_transaction(&transaction).await?;
    println!("Transaction Signature: {}", signature);

    Ok(())
}
```
