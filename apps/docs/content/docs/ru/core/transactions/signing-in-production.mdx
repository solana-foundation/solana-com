Транзакция выполняется, только если она содержит действительную
[подпись](/docs/core/transactions/transaction-structure#signatures) каждого
необходимого подписанта. При локальной разработке этот ключ обычно хранится как
[`Keypair`](/developers/cookbook/wallets/create-keypair), и вы подписываете напрямую. В
продакшене важен другой вопрос: **где хранится приватный ключ
и кто вправе авторизовать подпись с его помощью?**

<Callout type="warn">
  Никогда не встраивайте приватные ключи в клиентский код, не включайте их в сборку фронтенда и не коммитьте в систему контроля версий. Любой, кто получит ключ, получит полный контроль над средствами этого аккаунта.
</Callout>

## Подходы к подписи

| Подход                  | Где хранится ключ                                     | Кто подписывает                                          | Лучше всего подходит для                                                      |
| ------------------------- | ------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **Локальный keypair**         | Файл или переменная окружения на машине           | Ваш код напрямую                                | Локальная разработка, тесты, CI                                  |
| **Браузерный кошелёк**        | Кошелёк конечного пользователя (например, Phantom, Solflare)          | Конечный пользователь, для каждой транзакции                      | Фронтенд-dApps, где пользователи подписывают собственные транзакции        |
| **Облачный KMS / HSM**       | Сервис хранения ключей с аппаратной защитой (AWS KMS, GCP KMS, Vault) | Ваш бэкенд запрашивает подпись у сервиса | Бэкенд-сервисы, операции с казначейством, регулируемые среды |
| **Управляемые / MPC-кошельки** | Разделены или хранятся на стороне провайдера в его инфраструктуре   | Провайдер соподписывает в соответствии с вашей политикой     | Встроенные кошельки, процессы согласования, институциональное кастодиальное хранение   |

Локальный keypair — единственный подход, при котором необработанный ключевой материал находится внутри вашего
приложения. Во всех продакшен-подходах ключ хранится в специализированной инфраструктуре,
и именно она подписывает от вашего имени.

## Подпись на бэкенде

Когда серверу нужно подписывать (оплачивать комиссии, отправлять транзакции программ
или управлять казначейством), используйте специализированный бэкенд управления ключами, а не обычный
keypair. Solana Foundation поддерживает [Keychain](/docs/tools/keychain) —
единую библиотеку подписи (Rust, TypeScript, Python и Go), которая предоставляет один
интерфейс `SolanaSigner` для всех бэкендов из таблицы выше: Memory,
HashiCorp Vault, AWS KMS, GCP KMS, Fireblocks, Privy, Turnkey, CDP, Crossmint,
Dfns, Para, Openfort, Utila и Fordefi.

Поскольку интерфейс един для всех бэкендов, вы можете разрабатывать локально с
ключом в памяти и переходить на продакшен-бэкенд через конфигурацию, не
переписывая код приложения (бэкенды, которые сами рассылают транзакции, например Crossmint,
вызываются через путь «подписать и отправить»). Keychain совместим с
[`@solana/kit`](/docs/clients/official/javascript),
[Rust SDK](/docs/clients/official/rust), `solders` (Python) и `solana-go` v2
(Go).
