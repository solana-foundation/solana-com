<Callout type="info" title="Резюме">
  Программы компилируются в sBPF через LLVM и выполняются в изолированной VM с бюджетом
  1,4 млн CU на транзакцию. Среда выполнения кэширует до 512 скомпилированных программ,
  предоставляет системные вызовы для логирования, CPI, криптографии и работы с памятью,
  а новые развёртывания задерживаются на 1 slot.
</Callout>

## Компиляция

Solana использует [LLVM](https://llvm.org/) для компиляции программ в бинарные файлы
[ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format),
содержащие Solana Bytecode Format (sBPF). ELF-бинарник хранится в сети в
исполняемом аккаунте.

<Callout>
  sBPF — это пользовательский вариант байткода [eBPF](https://en.wikipedia.org/wiki/EBPF) от Solana,
  адаптированный для среды выполнения Solana. Это не стандартный eBPF —
  он содержит модификации, специфичные для Solana.
</Callout>

## Написание программ

Программы Solana преимущественно пишутся на
[Rust](https://rust-book.cs.brown.edu/title-page.html) с использованием одного из трёх
подходов:

<Cards>
  <Card title="Anchor" href="https://www.anchor-lang.com/docs">
    Фреймворк, использующий макросы Rust для сокращения шаблонного кода. Рекомендуется
    большинству разработчиков.
  </Card>
  <Card title="Pinocchio" href="/docs/clients/official/rust#program-crates">
    Лёгкая библиотека Rust с нулевым копированием, оптимизированная для снижения
    потребления вычислительных ресурсов и размера бинарного файла. Включает
    специализированные крейты для распространённых CPI.
  </Card>
  <Card title="Native Rust" href="/docs/programs/rust">
    Чистый Rust без фреймворков. Обеспечивает полный контроль, но требует более
    детальной ручной реализации.
  </Card>
</Cards>

См. [Cross-Program Invocations](/docs/core/cpi) для ознакомления с концепциями и примерами CPI,
применимыми во всех этих подходах.

## Модель выполнения программ

При обработке транзакции среда выполнения последовательно выполняет каждую инструкцию
через
[`process_message()`](https://github.com/anza-xyz/agave/blob/v3.1.8/svm/src/message_processor.rs#L15).
Для каждой инструкции среда выполнения:

1. **Подготавливает контекст инструкции.** Вызывает
   [`prepare_next_top_level_instruction()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L436)
   для сопоставления индексов аккаунтов инструкции, установки флагов подписанта и
   записи, а также настройки
   [`TransactionContext`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L467).

2. **Проверяет прекомпиляции.** Если программа является
   [прекомпиляцией](/docs/core/programs/precompiles), среда выполнения вызывает
   [`process_precompile()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L491),
   которая по-прежнему помещает и извлекает кадр стека (через _rs`push()`_ и _rs`pop()`_),
   но обходит sBPF VM и поиск в кэше программ, выполняя нативный код
   напрямую.

3. **Помещает кадр в стек.** (Шаги 3–6 выполняются внутри
   [`InvokeContext::process_instruction()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L481)
   и
   [`process_executable_chain()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L507),
   вызываемых из _rs`process_message()`_.) Вызывает
   [`push()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L233)
   на
   [`InvokeContext`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L184),
   что увеличивает высоту стека инструкций и применяет правило реентерабельности:
   программа может повторно войти в себя только в том случае, если **непосредственный**
   вызывающий (программа на текущей вершине стека инструкций) является той же программой.
   Глубокая саморекурсия (A -> A -> A) допускается с учётом ограничений глубины стека.
   Другие паттерны реентерабельности (например, A вызывает B, B вызывает A) возвращают
   _rs`InstructionError::ReentrancyNotAllowed`_.

4. **Разрешает программу.** Среда выполнения вызывает
   [`process_executable_chain()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L507),
   которая определяет загрузчик. Если владельцем program account является
   [нативный загрузчик](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L517),
   программа является встроенной, и её точка входа извлекается напрямую из
   [`ProgramCacheForTxBatch`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L706).
   Если владелец — один из BPF-загрузчиков (`bpf_loader_deprecated`,
   `bpf_loader`, `bpf_loader_upgradeable` или `loader_v4`), вместо этого
   вызывается собственная встроенная точка входа загрузчика.

5. **Выполняет BPF-программу.** Для BPF-программ
   [точка входа загрузчика](https://github.com/anza-xyz/agave/blob/v3.1.8/programs/bpf_loader/src/lib.rs#L385)
   извлекает скомпилированный исполняемый файл из кэша программ. Функция
   [`execute()`](https://github.com/anza-xyz/agave/blob/v3.1.8/programs/bpf_loader/src/lib.rs#L1449)
   затем:
   - Сериализует данные аккаунтов в плоский буфер параметров
   - Создаёт sBPF VM со стеком, кучей и регионами памяти
   - Выполняет скомпилированный код, расходуя вычислительные единицы в процессе выполнения.
     Возвращает _rs`ComputationalBudgetExceeded`_, если бюджет превышен.
   - Десериализует данные аккаунтов из буфера обратно в состояние аккаунтов

6. **Извлекает кадр из стека.** Вызывает
   [`pop()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L268),
   которая проверяет, что инструкция не нарушила правила учёта среды выполнения
   (балансы lamport сбалансированы, аккаунты только для чтения не изменялись,
   размеры данных аккаунтов находятся в допустимых пределах).

7. **Накапливает вычислительные единицы.** Вычислительные единицы, потреблённые инструкцией,
   добавляются к итогу транзакции через
   [`saturating_add`](https://github.com/anza-xyz/agave/blob/v3.1.8/svm/src/message_processor.rs#L53).

## Кэш программ

Среда выполнения поддерживает глобальный
[`ProgramCache`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L677),
хранящий верифицированные и скомпилированные программы. Он учитывает граф форков и
обрабатывает правила видимости при развёртывании, вытеснение и перекомпиляцию
на границах epoch.

### Типы записей кэша

Каждая кэшированная программа имеет
[`ProgramCacheEntryType`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L132),
определяющий её поведение в среде выполнения:

| Тип                                                                                                              | Описание                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`Loaded`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L147)             | Верифицированная и скомпилированная программа, готовая к выполнению.                                                                                                                                                                                                                                              |
| [`Builtin`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L149)            | Нативная программа, скомпилированная в бинарник validator (System, Stake, Vote и др.). Не хранится в сети.                                                                                                                                                                                               |
| [`Unloaded`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L145)           | Ранее верифицированная программа, скомпилированный исполняемый файл которой был вытеснен из памяти для освобождения места. По-прежнему отслеживает статистику использования. Может быть перезагружена без повторной верификации.                                                                                                                             |
| [`FailedVerification`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L134) | Метка-захоронение для программ, не прошедших верификатор sBPF при текущем наборе функций. Может стать `Loaded`, если активация функций изменит правила верификации.                                                                                                                              |
| [`Closed`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L139)             | Метка-захоронение для программ, которые были явно закрыты или так и не были развёрнуты. Также используется для аккаунтов (например, буферных аккаунтов), принадлежащих загрузчику, но не содержащих исполняемый код.                                                                                                               |
| [`DelayVisibility`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L141)    | Синтетическая метка-захоронение, возвращаемая [`ProgramCacheForTxBatch::find()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L755), когда запись `Loaded` существует, но ещё не вступила в силу (её `effective_slot` находится в будущем). Никогда не хранится напрямую в кэше. |

### Задержка видимости

Вновь развёрнутые или обновлённые программы не вступают в силу немедленно. Константа
[`DELAY_VISIBILITY_SLOT_OFFSET`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L32)
равна `1`, то есть программа, развёрнутая в slot N, вступает в силу в slot
N+1. В течение slot развёртывания любая попытка вызвать новую версию возвращает
_rs`DelayVisibility`_, и среда выполнения сообщает «Program is not deployed.»

### Политика вытеснения

Кэш содержит не более
[`MAX_LOADED_ENTRY_COUNT`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L31)
(512) записей скомпилированных программ. При достижении лимита наименее используемые
программы вытесняются в состояние _rs`Unloaded`_. Использование отслеживается с помощью
[`tx_usage_counter`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L197)
(увеличивается каждый раз, когда транзакция обращается к программе) и
[`latest_access_slot`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L199).

### Перекомпиляция на границе epoch

Если активация функции изменяет
[`ProgramRuntimeEnvironments`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L529)
на границе epoch, все кэшированные программы
[перекомпилируются](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank.rs#L1494)
под новую среду.

## Возвращаемые данные

Программы могут задавать возвращаемые данные через системный вызов `sol_set_return_data`. Данные
хранятся в структуре уровня транзакции
[`TransactionReturnData`](https://github.com/anza-xyz/agave/blob/v3.1.8/transaction-context/src/lib.rs#L499),
содержащей байты данных и `program_id` программы, чья инструкция вызвала системный вызов.
Максимальный размер составляет 1 024 байта
(_rs`MAX_RETURN_DATA`_).
