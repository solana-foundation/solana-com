Интерфейс командной строки `spl-token` позволяет создавать минты и token accounts,
управлять полномочиями, переводами и расширениями Token-2022.

Этот справочник соответствует
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
версии, входящей в состав Agave v4.2.1. Выполните `spl-token --version` и используйте
`<command> --help`, чтобы узнать точный набор параметров в вашей установленной версии.

<Callout type="warn">
  Создание минтов, переводы, смена полномочий, сжигание, заморозка и закрытие
  аккаунтов отправляют транзакции. Перед выполнением команды проверьте кластер,
  Token Program, подписанта и адреса. Изменения в mainnet затрагивают реальные активы.
</Callout>

## Установка и получение справки

Пакет релиза Agave CLI включает `spl-token`. Если он не установлен, используйте
опубликованный Rust-крейт:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Просмотрите справку на уровне корня или конкретной команды:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Глобальные параметры

Указывайте глобальные параметры перед командой.

| Параметр                                       | Назначение                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Выбор RPC URL или `mainnet-beta`, `testnet`, `devnet` либо `localhost`. |
| `-C, --config <PATH>`                        | Использовать другой файл конфигурации Solana CLI.                            |
| `--fee-payer <KEYPAIR>`                      | Выбор аккаунта, который оплачивает комиссии за транзакции.                            |
| `-p, --program-id <ADDRESS>`                 | Использовать явно указанный ID Token Program.                                         |
| `--program-2022`                             | Использовать Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Возвращать `json` или `json-compact`, где это поддерживается.                          |
| `--with-compute-unit-limit <UNITS>`          | Задать лимит вычислительных единиц транзакции.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Задать приоритетную цену за вычислительную единицу.                                  |
| `-v, --verbose`                              | Показывать дополнительный вывод.                                                   |
| `-V, --version`                              | Вывести установленную версию CLI.                                          |

По умолчанию используется исходный Token Program. Применяйте `--program-2022` для минта
или аккаунта Token-2022, в том числе при его чтении. Команда завершается ошибкой, если
выбранная программа не является владельцем указанного адреса.

## Создание и использование токена

Команды выводят адреса созданных объектов. Сохраните адрес минта, возвращённый командой
`create-token`, для последующих команд.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Суммы указываются в UI-единицах токена с учётом десятичных знаков минта. Команды, такие как
`transfer`, `burn` и `unwrap-sol`, принимают `ALL` там, где это указано в их справке.

## Создание минта Token-2022

Расширения выделяют дополнительное состояние минта или аккаунта и, как правило, должны
выбираться при создании минта. Этот пример создаёт минт с шестью десятичными знаками и
поддержкой встроенных метаданных:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Распространённые параметры расширений `create-token`:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` и `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` или `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` вместе с
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Комбинируйте только те расширения, которые программа Token-2022 допускает совместно.
Прежде чем создавать минт с необратимой конфигурацией, изучите соответствующее
[руководство по расширениям Token-2022](/docs/tokens/extensions).

## Управление полномочиями и делегатами

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` поддерживает типы полномочий mint, freeze, owner, close, а также специфичные для
расширений. Удаление полномочий с помощью `--disable` необратимо, если никакой другой
механизм программы не может их восстановить.

## Заморозка, сжигание и закрытие

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` уменьшает и баланс аккаунта, и общее предложение. `close` возвращает оставшиеся
lamports аккаунта настроенному получателю; он не восстанавливает сожжённые токены.

## Wrap и unwrap SOL

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Используйте `sync-native` после прямого перевода lamports на wrapped SOL token account,
чтобы количество токенов соответствовало базовым lamports.

## Подпись multisig

Создайте multisig Token Program по схеме M-of-N, включающий до 11 участников:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

Для транзакции, контролируемой этим multisig, передайте адрес multisig в качестве
соответствующих полномочий и укажите keypairs участников через повторяющиеся значения
`--multisig-signer`. Сверьтесь со справкой целевой команды, поскольку флаг основных
полномочий зависит от операции.

## Конфиденциальные балансы

Команды конфиденциальных балансов требуют минта Token-2022, настроенного для
конфиденциальных переводов, и настроенного аккаунта получателя.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Для `configure-confidential-transfer-account` и `apply-pending-balance` передайте либо
`--address <TOKEN_ACCOUNT_ADDRESS>`, либо позиционный `<MINT_ADDRESS>`, но не оба сразу.
Позиционная форма использует associated token account владельца. Пополнение и вывод всегда
принимают минт и допускают `--address`, чтобы переопределить этот аккаунт по умолчанию.

Используйте `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits` и `disable-non-confidential-credits`, чтобы
управлять тем, какие зачисления принимает аккаунт. Эти настройки влияют на приватность
аккаунта и совместимость платежей; проверьте аккаунт перед их изменением.

## Структурированная и офлайн-подпись

Используйте структурированный вывод вместо разбора отображаемого текста:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Команды, формирующие транзакции, обычно поддерживают `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce` и `--nonce-authority`. Точные офлайн-параметры
зависят от команды, десятичных знаков минта и схемы полномочий, поэтому сформируйте
неподписанное сообщение по инструкциям `--help` этой команды и проверьте каждый адрес,
прежде чем собирать подписи.
