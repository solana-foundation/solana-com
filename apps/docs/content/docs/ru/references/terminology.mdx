Следующие термины используются в документации Solana и экосистеме разработки.

## аккаунт

Запись в реестре Solana, которая либо хранит данные, либо является исполняемой
программой.

Подобно аккаунту в традиционном банке, аккаунт Solana может хранить средства, называемые
[lamports](#lamport). Каждый аккаунт в [кластере](#cluster) имеет уникальный
[адрес](#address).

## приложение

Клиентское приложение, взаимодействующее с кластером Solana.

## адрес

Местоположение в Solana, которое можно использовать для поиска аккаунта. Каждый адрес
уникален в [кластере](#cluster) Solana.

Адреса в Solana могут быть либо Ed25519 [публичным ключом](#public-key-pubkey), либо
[program derived address](#program-derived-address-pda).

## таблица поиска адресов (ALT)

Структура данных, хранящая список адресов аккаунтов и позволяющая
[версионированным транзакциям](#versioned-transaction) ссылаться на аккаунты с помощью
компактных 1-байтовых индексов вместо полных 32-байтовых публичных ключей. Таблицы поиска адресов
позволяют одной транзакции ссылаться на большее число аккаунтов, чем допускает исходный
формат транзакций. Таблицы поиска адресов поддерживаются только транзакциями версии 0 (`v0`); версия 1 (`v1`) отказывается от них в пользу увеличенного размера транзакции, вмещающего те же адреса напрямую.

## Anchor

Фреймворк для разработки [onchain-программ](#onchain-program) Solana на Rust.
Anchor предоставляет макросы, сокращающие шаблонный код, стандартизированную систему
валидации аккаунтов и генерирует [IDL](#idl), описывающий интерфейс программы.
Это наиболее широко используемый фреймворк для разработки программ Solana.

## associated token account (ATA)

[token account](#token-account), адрес которого детерминированно производится
из адреса кошелька и [token mint](#token-mint). Associated Token Program
гарантирует, что каждый кошелёк имеет один канонический token account для каждого типа токена.

## authority (права управления)

Адрес пользователя, имеющего определённые права доступа к аккаунту.

Например:

- Право выпускать новые токены предоставляется аккаунту, являющемуся 'mint
  authority' для данного token mint.
- Право обновлять программу предоставляется аккаунту, являющемуся 'upgrade
  authority' этой программы.

## автоматический маркет-мейкер (AMM)

Onchain-модель обмена, в которой пользователи торгуют против пула резервов токенов,
управляемого ценовой формулой, а не против лимитных заявок контрагента. Цены меняются
как функция резервов, поэтому сделки несут [проскальзывание](#slippage) пропорционально объёму.

## состояние банка

Результат интерпретации всех программ в реестре на заданной
[высоте тиков](#tick-height). Он включает как минимум набор всех
[аккаунтов](#account), хранящих ненулевые [нативные токены](#native-token).

## блок

Непрерывный набор [записей](#entry) в реестре, охватываемый
[голосованием](#ledger-vote). [Лидер](#leader) производит не более одного блока за
[slot](#slot).

## хеш блока (blockhash)

Уникальное значение ([хеш](#hash)), идентифицирующее запись (блок). Solana вычисляет
хеш блока из последнего [entry id](#entry-id) блока.

## высота блока

Количество [блоков](#block) ниже текущего блока. Первый блок после
[genesis-блока](#genesis-block) имеет высоту один.

## bootstrap-валидатор

[validator](#validator), производящий genesis (первый) [блок](#block)
блокчейна.

## BPF loader

Программа Solana, которая владеет и загружает [BPF](/docs/core/programs)
[onchain-программы](#onchain-program), позволяя программе взаимодействовать со средой исполнения.

## bump

Один байт (0–255), добавляемый к [seeds](#seed) при выводе
[Program Derived Address](#program-derived-address-pda), чтобы гарантировать, что полученный
адрес находится вне кривой ed25519 и является корректным PDA. Канонический
bump — это наибольшее значение, порождающее валидный PDA; он обычно сохраняется в
данных аккаунта, чтобы избежать повторного вычисления.

## книга лимитных заявок (CLOB)

Модель обмена, поддерживающая отсортированный список активных заявок на покупку и продажу;
сделка происходит, когда входящая заявка пересекается с заявкой на противоположной стороне. Противопоставляется
[автоматическому маркет-мейкеру](#automated-market-maker-amm).

## клиент

Компьютерная программа, получающая доступ к серверной сети [кластера](#cluster) Solana.

## подтверждение (commitment)

Мера сетевого подтверждения для [блока](#block).

## формат компактного массива

Компактный массив — это массив, сериализованный в следующем формате:

- Длина массива (закодированная как
  [compact-u16](https://github.com/anza-xyz/agave/blob/v2.1.13/short-vec/src/lib.rs))
- Элементы массива, перечисленные один за другим

![Формат компактного массива](/assets/docs/core/transactions/compact_array_format.png)

Формат компактного массива используется для кодирования как массива
[адресов аккаунтов](/docs/core/transactions/transaction-structure#account-addresses),
так и массива
[инструкций](/docs/core/transactions/transaction-structure#instructions)
в сообщениях транзакций.

## кластер

Набор [validator'ов](#validator), поддерживающих единый [реестр](#ledger).

## вычислительный бюджет

Максимальное количество [вычислительных единиц](#compute-units), потребляемых за транзакцию.

## вычислительные единицы

Наименьшая единица измерения потребления вычислительных ресурсов блокчейна. Вычислительные единицы
используются для измерения вычислительных ресурсов, затраченных на обработку транзакции.

## время подтверждения

Длительность по настенным часам между созданием [лидером](#leader)
[тик-записи](#tick) и созданием [подтверждённого блока](#confirmed-block).

## подтверждённый блок

[Блок](#block), получивший [супербольшинство](#supermajority)
[голосов реестра](#ledger-vote).

## плоскость управления

Gossip-сеть, соединяющая все [узлы](#node) [кластера](#cluster).

## период охлаждения

Определённое количество [epoch'ов](#epoch) после деактивации [стейка](#stake), в течение которых
он постепенно становится доступным для вывода. В этот период стейк
считается «деактивирующимся». Подробнее:
[прогрев и охлаждение](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)

## единицы стоимости

Также называемые `стоимостью транзакции` — это комплексная оценка всех
ресурсов, необходимых для обработки транзакции, измеренная в
[вычислительных единицах](#compute-units). Подробнее
[здесь](https://www.anza.xyz/blog/why-solana-transaction-costs-and-compute-units-matter-for-developers).

## кредит

См. [голосовой кредит](#vote-credit).

## cross-program invocation (CPI)

Вызов одной [onchain-программы](#onchain-program) из другой. Для получения
дополнительной информации см. [вызовы между программами](/docs/core/cpi).

## плоскость данных

Multicast-сеть, используемая для эффективной валидации [записей](#entry) и достижения
консенсуса.

## drone

Offchain-сервис, выступающий хранителем приватного ключа пользователя. Как правило,
служит для валидации и подписи транзакций.

## запись

Запись в [реестре](#ledger) — либо [тик](#tick), либо
[запись транзакции](#transactions-entry).

## идентификатор записи (entry id)

Стойкий к прообразу [хеш](#hash) финального содержимого записи,
служащий глобально уникальным идентификатором [записи](#entry). Хеш служит доказательством:

- Того, что запись была сгенерирована по истечении определённого времени
- Того, что указанные [транзакции](#transaction) включены в данную запись
- Позиции записи относительно других записей в [реестре](#ledger)

См. [доказательство истории](#proof-of-history-poh).

## epoch

Промежуток времени, т.е. количество [slot'ов](#slot), в течение которого
действует [расписание лидеров](#leader-schedule).

## эскроу

Паттерн, при котором [onchain-программа](#onchain-program) удерживает токены в
[хранилище](#vault) от имени двух или более сторон до выполнения условий,
определённых программой, после чего освобождает их. Используется для устранения необходимости
прямого доверия между сторонами.

## комиссионный аккаунт

Комиссионный аккаунт в транзакции — это аккаунт, оплачивающий стоимость
включения транзакции в реестр. Это первый аккаунт в транзакции. Данный аккаунт
должен быть объявлен как доступный для чтения и записи (writable) в
транзакции, поскольку оплата транзакции уменьшает баланс аккаунта.

## финальность

Момент, когда узлы, представляющие 2/3 [стейка](#stake), имеют общий
[корень](#root).

## форк

[Реестр](#ledger), производный от общих записей, но затем разошедшийся.

## genesis-блок

Первый [блок](#block) в цепочке.

## genesis-конфигурация

Файл конфигурации, подготавливающий [реестр](#ledger) для
[genesis-блока](#genesis-block).

## хеш

Цифровой отпечаток последовательности байтов.

## инфляция

Увеличение предложения токенов со временем, используемое для финансирования вознаграждений
за валидацию и продолжения развития Solana.

## внутренняя инструкция

См. [cross-program invocation](#cross-program-invocation-cpi).

## инструкция

Вызов конкретного [обработчика инструкций](#instruction-handler) в
[программе](#program). Инструкция также определяет, какие аккаунты она хочет
читать или изменять, и дополнительные данные, служащие вспомогательным вводом для
[обработчика инструкций](#instruction-handler). [Клиент](#client) должен включить хотя бы
одну инструкцию в [транзакцию](#transaction), и все инструкции должны
выполниться успешно, чтобы транзакция считалась успешной.

## обработчик инструкций

Обработчики инструкций — это функции [программы](#program), обрабатывающие
[инструкции](#instruction) из [транзакций](#transaction). Обработчик инструкций
может содержать один или несколько
[cross-program invocation](#cross-program-invocation-cpi).

## IDL

Interface Definition Language. JSON-файл, генерируемый [Anchor](#anchor) и
описывающий [обработчики инструкций](#instruction-handler), аккаунты
и типы программы. IDL позволяет клиентским библиотекам автоматически генерировать типизированные
интерфейсы для взаимодействия с [onchain-программой](#onchain-program).

## keypair

[Публичный ключ](#public-key-pubkey) и соответствующий [приватный ключ](#private-key)
для доступа к аккаунту.

## lamport

Дробная единица [нативного токена](#native-token) со значением 0.000000001
[SOL](#sol).

> В рамках вычислительного бюджета количество
> _[микро-lamport'ов](https://github.com/solana-labs/solana/blob/ced8f6a512c61e0dd5308095ae8457add4a39e94/program-runtime/src/prioritization_fee.rs#L1-L2)_
> используется при расчёте [комиссий за приоритет](#prioritization-fee).

## лидер

Роль [validator'а](#validator), когда он добавляет [записи](#entry) в
[реестр](#ledger).

## расписание лидеров

Последовательность [публичных ключей](#validator) [validator'ов](#public-key-pubkey), сопоставленных
со [slot'ами](#slot). Кластер использует расписание лидеров для определения того, какой
validator является [лидером](#leader) в любой момент времени.

## реестр

Список [записей](#entry), содержащих [транзакции](#transaction), подписанные
[клиентами](#client). Концептуально его можно проследить вплоть до
[genesis-блока](#genesis-block), однако реестр реального [validator'а](#validator)
может содержать только более новые [блоки](#block), чтобы сократить объём хранилища, поскольку старые блоки не
нужны для валидации будущих блоков по своей конструкции.

## голос реестра

[Хеш](#hash) [состояния validator'а](#bank-state) на заданной
[высоте тиков](#tick-height). Он включает подтверждение [validator'а](#validator)
того, что полученный им [блок](#block) был верифицирован, а также
обязательство не голосовать за конфликтующий [блок](#block) \(т.е. [форк](#fork)\)
в течение определённого времени — периода [блокировки](#lockout).

## лёгкий клиент

Тип [клиента](#client), который может проверить, что он подключён к действующему
[кластеру](#cluster). Он выполняет больше верификации реестра, чем
[тонкий клиент](#thin-client), но меньше, чем [validator](#validator).

## ликвидность

Глубина ордеров или пулов резервов, доступных для торговли по текущей цене или
вблизи неё. Более глубокая ликвидность снижает [проскальзывание](#slippage). В
[CLOB](#central-limit-order-book-clob) ликвидность обеспечивается
[мейкер-ордерами](#maker); в [AMM](#automated-market-maker-amm) она предоставляется
поставщиками ликвидности, которые вносят пары токенов в пул.

## загрузчик

[Программа](#program), способная интерпретировать двоичное кодирование других
[программ на блокчейне](#onchain-program).

## блокировка

Период времени, в течение которого [validator](#validator) не может
[голосовать](#ledger-vote) за другой [форк](#fork).

## мейкер

Трейдер, чей ордер добавляет [ликвидность](#liquidity) в
[CLOB](#central-limit-order-book-clob), ожидая исполнения в книге заявок, а не
немедленно пересекая противоположную сторону. Такой ордер называется мейкер-ордером.
Мейкеры, как правило, не платят комиссию или получают возврат от площадки.

## маркет-мейкер

Участник, обеспечивающий [ликвидность](#liquidity) путём непрерывного выставления
заявок на покупку и продажу. На Solana маркет-мейкерами являются либо программы (например,
[AMM](#automated-market-maker-amm)), либо внешние компании, использующие ботов для размещения
[мейкер-ордеров](#maker) на [CLOB](#central-limit-order-book-clob).

## сообщение

Структурированное содержимое [транзакции](#transaction). Как правило, содержит
заголовок, массив адресов аккаунтов, последний [blockhash](#blockhash) и массив
[инструкций](#instruction).

Подробнее о
[формате сообщений внутри транзакций](/docs/core/transactions/transaction-structure#header)
здесь.

## микро-lamport

1 000 000 микро-lamport = 1 [lamport](#lamport)

## коэффициент Накамото

Мера децентрализации: коэффициент Накамото — это наименьшее количество
независимых субъектов, которые могут совместно действовать для остановки блокчейна. Термин
был введён Баладжи С. Сринивасаном и Лиландом Ли в работе
[Quantifying Decentralization](https://news.earn.com/quantifying-decentralization-e39db233c28e).

## нативный токен

[Токен](#token), используемый для учёта работы, выполненной [узлами](#node) в кластере.

## узел

Компьютер, участвующий в работе [кластера](#cluster).

## количество узлов

Количество [validator'ов](#validator), участвующих в работе [кластера](#cluster).

## вне блокчейна (offchain)

Описывает данные, процессы или сервисы, которые существуют или работают за пределами блокчейна Solana,
например RPC-клиенты, индексаторы, фронтенды и мейкеры книги ордеров вне сети.
Противоположность [onchain](#onchain). Предпочтительное написание — «Offchain» (без дефиса).

## на блокчейне (onchain)

Описывает данные или программы, которые существуют или выполняются на блокчейне. Предпочтительное написание — «Onchain» (без дефиса).

## программа на блокчейне (onchain program)

Исполняемый код на блокчейне Solana, который интерпретирует
[инструкции](#instruction), передаваемые в каждой [транзакции](#transaction), для
чтения и изменения аккаунтов, над которыми у него есть контроль. На других блокчейнах такие программы
часто называют «[_смарт-контрактами_](/docs/core/programs)».

## оракул

[Программа на блокчейне](#onchain-program), публикующая данные из-за пределов
сети — чаще всего цены реальных активов — для использования другими программами.

## владелец

Может относиться либо к [программе-владельцу](#owning-program), либо к
[кошельку-владельцу](#owning-wallet). Например,
[getTokenAccountsByOwner](https://solana.com/docs/rpc/http/gettokenaccountsbyowner)
получает token account'ы, принадлежащие определённому кошельку, однако программой-владельцем
этих token account'ов является [Token Program](#token-program).

Во избежание путаницы предпочтительно использовать термины
[программа-владелец](#owning-program) или [кошелёк-владелец](#owning-wallet), а не
общий термин «владелец».

## программа-владелец

[Адрес](#address) [программы](#onchain-program), которой принадлежит
аккаунт. Только программа-владелец может изменять аккаунт.

См. также [authority](#authority).

## кошелёк-владелец

Кошелёк, связанный с аккаунтом. Например, Token Program используется
для хранения token account'ов, привязанных к определённому кошельку и минту,
по адресу, сформированному из этого [кошелька](#wallet) и [минта](#token-mint).

## PoH

См. [Proof of History](#proof-of-history-poh).

## поинт

Взвешенный [кредит](#credit) в системе вознаграждений. В режиме вознаграждений
[validator'а](#validator)
[rewards regime](https://docs.anza.xyz/consensus/stake-delegation-and-rewards),
количество поинтов, причитающихся [стейку](#stake) при погашении, равно произведению
заработанных [vote credits](#vote-credit) и количества
застейканных [lamport'ов](#lamport).

## приватный ключ

Приватный ключ [keypair'а](#keypair).

## программа

См. [программу на блокчейне (onchain program)](#onchain-program).

## адрес, производный от программы (PDA)

Аккаунт, адрес которого создаётся на основе
[программы на блокчейне](#onchain-program) и одного или нескольких [seed'ов](#seed),
созданных автором программы. Адреса PDA не являются публичными ключами, и у PDA нет приватных ключей.

Полномочия подписи для PDA принадлежат [программе на блокчейне](#onchain-program), которая
является их [программой-владельцем](#owning-program).

## идентификатор программы

Публичный ключ [аккаунта](#account), содержащего
[программу](#onchain-program).

## proof of history (PoH)

Стек доказательств, каждое из которых подтверждает, что некоторые данные существовали до создания
доказательства, и что перед предыдущим доказательством прошёл точный промежуток времени.
Как и [VDF](#verifiable-delay-function-vdf), Proof of History можно верифицировать
быстрее, чем он был создан.

## комиссия за приоритет

Дополнительная комиссия, которую пользователь может указать в [инструкции](#instruction)
бюджета вычислений для приоритизации своих [транзакций](#transaction).

Комиссия за приоритет рассчитывается путём умножения запрошенного максимального количества
вычислительных единиц на цену вычислительной единицы (указывается с шагом 0,000001
[lamport'а](#lamport) за вычислительную единицу) с округлением вверх до ближайшего
[lamport'а](#lamport).

Транзакции должны запрашивать минимальное количество вычислительных единиц, необходимых для
выполнения, чтобы минимизировать комиссии.

## публичный ключ (pubkey)

Публичный ключ [keypair'а](#keypair). Публичный ключ — один из различных
типов [адреса](#address), который аккаунт может использовать в Solana.

## rent

Комиссия, уплачиваемая [аккаунтами](#account) и [программами](#program) за хранение данных на
блокчейне. Если у аккаунтов недостаточно средств для оплаты rent, они могут быть
удалены сборщиком мусора.

См. также [rent exempt](#rent-exempt) ниже. Подробнее о rent:
[Что такое rent?](/docs/core/accounts/account-structure).

## освобождение от rent (rent exempt)

Аккаунты, поддерживающие минимальный баланс в lamport'ах, пропорциональный
объёму данных, хранимых в аккаунте. Все вновь созданные аккаунты хранятся
на блокчейне постоянно до тех пор, пока аккаунт не будет закрыт. Невозможно создать аккаунт,
баланс которого ниже порога освобождения от rent.

## корень (root)

[Блок](#block) или [slot](#slot), достигший максимальной [блокировки](#lockout)
на [validator'е](#validator). Корень — это самый высокий блок, являющийся предком
всех активных форков на validator'е. Все блоки-предки корня также
транзитивно являются корнями. Блоки, не являющиеся предком или потомком корня,
исключаются из рассмотрения при достижении консенсуса и могут быть отброшены.

## среда выполнения (runtime)

Компонент [validator'а](#validator), отвечающий за выполнение
[программ](#program).

## Sealevel

Параллельная среда выполнения Solana для [программ на блокчейне](#onchain-program).

## seed

Байтовое значение или массив байтовых значений, используемых в качестве входных данных при выводе
[адреса, производного от программы](#program-derived-address-pda). Программа может использовать любую
комбинацию статических строк, публичных ключей или других данных в качестве seed'ов. Seed'ы
комбинируются с идентификатором программы и [bump](#bump) для получения уникального адреса PDA.

## shred

Фрагмент [блока](#block); наименьшая единица, передаваемая между
[validator'ами](#validator).

## подпись

64-байтовая подпись ed25519, состоящая из R (32 байта) и S (32 байта). При условии, что R является
упакованной точкой Эдвардса не малого порядка, а S — скаляр в диапазоне `0 <= S < L`.
Это требование исключает пластичность подписи. Каждая транзакция должна содержать
не менее одной подписи для [аккаунта комиссии](#fee-account). Таким образом, первую подпись
в транзакции можно рассматривать как [идентификатор транзакции](#transaction-id).

## подписант

[Аккаунт](#account), авторизовавший [инструкцию](#instruction) или
[транзакцию](#transaction). Для обычного [keypair'а](#keypair) это означает
криптографическую [подпись](#signature) транзакции. Для
[адреса, производного от программы](#program-derived-address-pda), авторизация
подтверждается [программой-владельцем](#owning-program) при выполнении
[cross-program invocation](#cross-program-invocation-cpi), поскольку у PDA нет
приватного ключа.

## процент пропущенных slot'ов

Процент [пропущенных slot'ов](#skipped-slot) от общего числа лидерских slot'ов
в текущей epoch. Этот показатель может быть неточным: он имеет высокую дисперсию
сразу после границы epoch, когда размер выборки мал, а также для
validator'ов с небольшим количеством лидерских slot'ов. Тем не менее он может быть полезен
для выявления неправильных конфигураций узла.

## пропущенный slot

Прошедший [slot](#slot), не породивший [блок](#block), потому что лидер
был офлайн или [форк](#fork), содержащий этот slot, был отвергнут кластерным консенсусом
в пользу лучшей альтернативы. Пропущенный slot не появится в качестве предка
для блоков последующих slot'ов, не увеличит [высоту блока](#block-height)
и не обновит срок действия самого старого `recent_blockhash`.

Определить, был ли slot пропущен, можно только тогда, когда он станет старше
последнего [укоренённого](#root) (то есть непропущенного) slot'а.

## проскальзывание

Разница между ценой, которую ожидал трейдер, и ценой, по которой сделка
фактически исполнилась. На [AMM](#automated-market-maker-amm) оно возникает из-за
смещения кривой цен при изменении резервов; на
[CLOB](#central-limit-order-book-clob) — из-за того, что один ордер последовательно
поглощает несколько рестинг-ордеров по всё менее выгодным ценам.

## slot

Период времени, в течение которого каждый [лидер](#leader) принимает транзакции и
производит [блок](#block).

В совокупности slot'ы формируют логические часы. Slot'ы упорядочены последовательно и
не перекрываются, занимая примерно одинаковые промежутки реального времени согласно
[PoH](#proof-of-history-poh).

## суперквалифицированное большинство

2/3 [кластера](#cluster).

## System Program

Нативная программа Solana (ID программы `11111111111111111111111111111111`),
отвечающая за создание новых [аккаунтов](#account), выделение данных аккаунта,
назначение аккаунтов программам и перевод [SOL](#sol) между аккаунтами.
Все новые аккаунты в Solana принадлежат системной программе до момента переназначения.

## sysvar

Системный [аккаунт](#account). [Sysvars](https://docs.anza.xyz/runtime/sysvars)
предоставляют информацию о состоянии кластера, такую как текущая высота тика, значения
[очков](#point) наград и т.д. Программы могут обращаться к Sysvar через аккаунт Sysvar
(pubkey) или посредством syscall-запроса.

## taker

Трейдер, чья заявка удаляет [ликвидность](#liquidity) из
[CLOB](#central-limit-order-book-clob), пересекая противоположную сторону книги
и совпадая с одной или несколькими ожидающими заявками. Такая заявка называется taker-заявкой,
и taker, как правило, уплачивает торговую комиссию площадки.

## тонкий клиент

Тип [клиента](#client), который доверяет тому, что взаимодействует с действительным
[кластером](#cluster).

## тик

[Запись](#entry) в реестре, оценивающая продолжительность реального времени.

## высота тика

N-й [тик](#tick) в [реестре](#ledger).

## токен

Цифровой актив, допускающий передачу.

## token account

[Аккаунт](#account), хранящий баланс определённого [токена](#token). Token
accounts находятся в собственности [Token Program](#token-program) или
[Token Extensions Program](#token-extensions-program) и содержат баланс токена,
связанный [token mint](#token-mint) и адрес кошелька владельца.

## Token Extensions Program

[Token Extensions Program](https://www.solana-program.com/docs/token-2022)
имеет ID программы `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` и включает
все те же функции, что и [Token Program](#token-program), но дополнена
расширениями, такими как конфиденциальные балансы, пользовательская логика переводов, расширенные
метаданные и многое другое.

## token mint

Аккаунт, способный создавать (или «минтить») токены. Разные токены
различаются по уникальным адресам своего token mint.

## Token Program

[Token Program](https://www.solana-program.com/docs/token) имеет ID
программы `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` и предоставляет базовые
возможности переводов, заморозки и выпуска токенов.

## tps

[Транзакций](#transaction) в секунду.

## tpu

[Блок обработки транзакций](https://docs.anza.xyz/validator/tpu).

## транзакция

Одна или несколько [инструкций](#instruction), подписанных [клиентом](#client) с использованием одной
или нескольких [keypairs](#keypair) и выполняемых атомарно с двумя возможными
исходами: успех или неудача.

## ID транзакции

Первая [подпись](#signature) в [транзакции](#transaction), которая может быть
использована для уникальной идентификации транзакции в полном [реестре](#ledger).

## подтверждения транзакции

Количество [подтверждённых блоков](#confirmed-block) с момента принятия транзакции
в [реестр](#ledger). Транзакция считается окончательной, когда её блок
становится [корневым](#root).

## запись транзакций

Набор [транзакций](#transaction), которые могут выполняться параллельно.

## tvu

[Блок валидации транзакций](https://docs.anza.xyz/validator/tvu).

## validator

Полноправный участник [кластера](#cluster) сети Solana, производящий новые
[блоки](#block). Validator проверяет транзакции, добавляемые в
[реестр](#ledger).

## vault

[Token account](#token-account), принадлежащий
[onchain-программе](#onchain-program) и хранящий объединённые активы от имени пользователей
— например, базовые и котируемые резервы
[AMM](#automated-market-maker-amm), заблокированные токены в [эскроу](#escrow)
или остатки и накопленные комиссии
[CLOB](#central-limit-order-book-clob). Только программа-владелец может выводить токены
из vault, как правило, на собственный [token account](#token-account) пользователя
после выполнения условия сделки или высвобождения.

## VDF

См. [верифицируемая функция задержки](#verifiable-delay-function-vdf).

## верифицируемая функция задержки (VDF)

Функция, выполнение которой занимает фиксированное время и которая создаёт доказательство
своего выполнения, поддающееся проверке за меньшее время, чем потребовалось на его создание.

## версионная транзакция

Формат транзакции, поддерживающий дополнительные возможности по сравнению с исходным
форматом [транзакции](#transaction). Версия 0 (`v0`) — первый версионный
формат, добавляющий поддержку [таблиц поиска адресов](#address-lookup-table-alt),
что позволяет транзакциям ссылаться на большее количество аккаунтов, чем допускает исходный формат.
Версия 1 (`v1`), активная на всех кластерах, увеличивает максимальный размер транзакции
до 4096 байт, хранит лимиты ресурсов в секции конфигурации сообщения
вместо инструкций ComputeBudget и не поддерживает таблицы поиска адресов.
См. [версионные транзакции](/docs/core/transactions/versioned-transactions).

## период прогрева

Некоторое количество [эпох](#epoch) после делегирования [стейка](#stake), в течение которых
он постепенно вступает в силу. В этот период стейк считается
«активирующимся». Подробнее о:
[прогреве и охлаждении](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)
