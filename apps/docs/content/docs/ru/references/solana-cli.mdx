Интерфейс командной строки `solana` настраивает подключение к кластеру, считывает
состояние сети, отправляет SOL, управляет долговечными nonce, развёртывает программы и работает
с аккаунтами стейкинга и голосования.

Этот справочник соответствует
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Выполните
`solana --version`, чтобы узнать установленную версию, и используйте `--help`, чтобы увидеть точные
опции, доступные в этой версии.

<Callout type="warn">
  Команды, которые создают, переводят, авторизуют, выводят средства или развёртывают, отправляют
  транзакции. Перед запуском убедитесь, что выбраны нужный кластер и подписант.
  Токены Devnet и Testnet не имеют ценности; команды в Mainnet используют настоящие SOL.
</Callout>

## Структура команд

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Получение справки на любом уровне:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Глобальные опции

Глобальные опции можно указывать перед командой. Справка по конкретной команде повторяет
опции, которые к ней применимы.

| Опция                          | Назначение                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Выбор URL RPC либо `mainnet-beta`, `testnet`, `devnet` или `localhost`.      |
| `--ws <URL>`                    | Переопределить конечную точку WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Выбор файла keypair, `ASK`, stdin (`-`) или поддерживаемого URL подписанта.          |
| `-C, --config <FILEPATH>`       | Использовать другой файл конфигурации CLI.                                        |
| `--commitment <LEVEL>`          | Чтение с уровнем подтверждения `processed`, `confirmed` или `finalized`.                   |
| `--output <FORMAT>`             | Возвращать `json` или `json-compact`, где это поддерживается.                               |
| `--skip-preflight`              | Отправка без симуляции на RPC. Используйте, только если понимаете компромисс, связанный с возможными сбоями. |
| `--use-tpu-client`              | Отправлять транзакции через клиент TPU.                                      |
| `--no-address-labels`           | Выводить адреса без локальных меток.                                          |
| `--skip-seed-phrase-validation` | Разрешить фразу восстановления вне английского списка BIP39.                       |
| `-v, --verbose`                 | Показывать дополнительный вывод команды.                                                |
| `-V, --version`                 | Вывести установленную версию CLI.                                               |

## Настройка CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

Конфигурация содержит URL RPC, URL WebSocket, подписанта по умолчанию и
уровень подтверждения. Опция командной строки переопределяет сохранённое значение для данного вызова.

## Типичные сценарии работы с аккаунтами и транзакциями

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` по умолчанию принимает SOL. Укажите `ALL` в качестве суммы, чтобы перевести доступный
баланс за вычетом комиссий. Примеры с токенами см. в
[кратком руководстве по токенам](/docs/tokens/quickstart).

## Сценарии работы с программами

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Передайте `--program-id <KEYPAIR_OR_ADDRESS>`, если развёртывание должно использовать известный
ID программы. `--final` делает новое развёртывание неизменяемым; внимательно прочитайте справку,
прежде чем использовать эту опцию, так как полномочия на обновление восстановить невозможно.

## Сценарии работы с долговечным nonce

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Используйте `authorize-nonce-account`, чтобы сменить полномочия над nonce, и `nonce-account`,
чтобы изучить полное состояние аккаунта. Транзакции с nonce также принимают
`--nonce` и `--nonce-authority` в поддерживаемых командах.

## Сценарии стейкинга

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

Деактивация завершается на границе epoch и может занять более одного epoch.
Используйте `stakes`, `validators`, `stake-history` и `stake-minimum-delegation`, чтобы
изучить состояние кластера и делегирования перед отправкой изменений.

## Утилиты для адресов

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

Значения seed для PDA задаются в формате `PREFIX:VALUE`. Поддерживаемые префиксы: `string`, `pubkey`,
`hex`, `u8` и кодировки знаковых или беззнаковых целых чисел фиксированной ширины, например
`u64le`.

## Офчейн-сообщения и автодополнение в оболочке

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Вывод для скриптов

Вместо разбора вывода, предназначенного для человека, используйте `--output json` или `--output json-compact`, где это поддерживается:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Не каждая команда поддерживает структурированный вывод. Проверьте справку по команде, прежде чем
полагаться на него в автоматизации, и считайте ненулевой код завершения признаком сбоя.
