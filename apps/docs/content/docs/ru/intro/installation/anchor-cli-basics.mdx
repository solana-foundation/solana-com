В этом разделе приведены основные команды и примеры, которые помогут вам начать
работу с [Anchor CLI](https://www.anchor-lang.com/docs).

<Steps>
<Step>

### Инициализация проекта

Создайте новый проект Anchor, выполнив команду ниже. Она создаст новую
директорию с именем проекта и инициализирует в ней новый проект Anchor.

```terminal
$ anchor init <project-name>
```

Например, приведённая ниже команда создаст проект `my-project`. Директория
`my-project` будет содержать модульную программу на Rust и шаблон тестов на Rust,
использующий LiteSVM.

```terminal
$ anchor init my-project
```

Чтобы вместо этого сгенерировать шаблон тестов на TypeScript, выберите его
явно. Например, используйте шаблон Mocha:

```terminal
$ anchor init my-project --test-template mocha
```

Шаблоны тестов на TypeScript требуют Node.js и менеджер пакетов JavaScript.

Затем перейдите в директорию проекта:

```terminal
$ cd <project-name>
```

См. [структуру файлов проекта](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) Anchor.

</Step>
<Step>

### Сборка программы

Чтобы собрать ваш проект, выполните следующую команду:

```terminal
$ anchor build
```

Скомпилированная программа будет находиться в директории `/target/deploy`.

<Callout type="warn" title="Не удалось установить platform-tools">
  Если при сборке выводится сообщение о недопустимой директории platform-tools, переустановите инструменты сборки SBF
  и повторите сборку:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Деплой программы

Чтобы задеплоить проект, выполните следующую команду:

```terminal
$ anchor deploy
```

Эта команда деплоит вашу программу в `cluster`, указанный в файле
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml).

</Step>
<Step>

### Тестирование программы

Чтобы протестировать проект, выполните следующую команду:

```terminal
$ anchor test
```

Эта команда собирает, деплоит и запускает тесты для вашего проекта.

<Callout>
  При использовании кластера `localnet` Anchor автоматически запускает локальный
  validator, деплоит программу, выполняет тесты и затем останавливает validator.
</Callout>

<Callout type="warn" title="Ошибки средства запуска тестов JavaScript">

Если вы выбрали шаблон тестов на JavaScript или TypeScript, любая из
следующих ошибок может означать, что Node.js или настроенный менеджер пакетов
не установлен:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
