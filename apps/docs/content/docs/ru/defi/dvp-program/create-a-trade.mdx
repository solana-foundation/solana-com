`CreateDvp` фиксирует условия сделки и создаёт два эскроу-аккаунта, которые стороны будут пополнять. Токены она не перемещает. Отправить её может любой, поэтому запись может прийти от контрагента, оператора расчётного органа или третьей стороны, а каждый другой участник перед тем, как действовать, проверяет сохранённые условия (см.
[внесение средств по плечам](/docs/defi/dvp-program/fund-the-legs)).

В примерах используется сгенерированный клиент напрямую, с адресами-заглушками, чтобы
были видны задействованные аккаунты и подписанты. Они рассчитаны на devnet, где
программа развёрнута по тому же адресу, что и в mainnet-beta.

## Установка

На 2 октября 2026 года для клиентов DvP не опубликовано ни одного пакета. Оба клиента
генерируются из IDL программы в репозитории и используются из исходного кода.

Эти страницы написаны для коммита `df9919e`, с `@solana/kit` 8 в
TypeScript и крейтами `solana-*` 2.x в Rust.

Примеры на каждой странице шагов продолжают друг друга: каждая страница использует клиент, подписантов
и адреса, определённые на предыдущих страницах. `payerSigner`, `userASigner`,
`userBSigner` и `authoritySigner` — это `TransactionSigner` для плательщика rent,
двух сторон и расчётного органа, например из
`createKeyPairSignerFromBytes`. Примеры на Rust собирают инструкции, а подпись
и отправку оставляют вызывающему коду.

## Вычисление адресов

Запись сделки — это Program Derived Address, вычисляемый из расчётного органа,
двух сторон, двух mint-ов и nonce. Каждый эскроу — это associated
token account записи для одного из mint-ов. Для обоих вычислений доступ к сети не нужен.

Используйте случайный 64-битный nonce для каждой сделки. Поскольку создание не требует разрешений,
предсказуемый nonce позволяет третьей стороне занять адрес, который собиралась
использовать сделка. Передавайте nonce и суммы как `bigint` в TypeScript; сгенерированный
клиент отклоняет `number`.

Перед запуском замените каждую заглушку `..._HERE` реальным адресом.
`address()` проверяет base58 и выбрасывает ошибку на заглушке, а `pubkey!` не
компилируется.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## Фиксация условий

`CreateDvp` принимает две суммы в базовых единицах, срок действия, nonce и четыре
необязательных поля: непрозрачную ссылку до 64 байт, адрес назначения расчёта
для каждой стороны и самое раннее время расчёта (см. «Примечания»). Адрес назначения — это
место, куда при расчёте попадают поступления этой стороны, например депозитный кошелёк
кастодиана; по умолчанию это собственный адрес стороны, и после создания
записи он не меняется. Возвраты и обратные списания (reclaim) всегда идут на token account самой стороны
для mint-а этого плеча, а не на адрес назначения, независимо от того, кто пополнил эскроу.

Плательщик вносит rent за запись, tombstone для nonce и оба эскроу.
При закрытии этот rent достаётся тому, кто подписывает инструкцию закрытия, а не возвращается
плательщику. Tombstone никогда не закрывается, поэтому каждая сделка оставляет небольшой постоянный
баланс. При расчёте бюджета плательщика в SOL определяйте суммы rent методом RPC
`getMinimumBalanceForRentExemption`, а не прописывайте их жёстко.

<Tabs items={["TypeScript", "Rust"]}>

    const nowSeconds = BigInt(Math.floor(Date.now() / 1000));

    const createInstruction = getCreateDvpInstruction({
      payer: payerSigner,
      swapDvp,
      nonceTombstone: (
        await getProgramDerivedAddress({
          programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
          seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
        })
      )[0],
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,

      dvpAtaB: escrowB,

      tokenProgramB,
      amountA: 1_000_000_000n, // 1,000 units of a 6-decimal asset
      amountB: 998_500_000n, // 998.50 units of a 6-decimal cash token
      expiryTimestamp: nowSeconds + 60n * 60n * 24n, // one day
      nonce,
      refString: "ORDER-2026-10-02-0001",
      userASettlementDestination: null, // defaults to userA
      userBSettlementDestination: null, // defaults to userB

Для TypeScript-примера в области видимости должны быть `getProgramDerivedAddress` и `getAddressEncoder`
из `@solana/kit`, а также `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` из клиента. Билдер на Rust оставляет System Program и Associated Token Program
со значениями по умолчанию.

## Примечания

- **Срок действия.** Срок проверяет только Settle. Reclaim, Cancel и Reject работают
  и после его истечения, а депозит, поступивший после истечения срока, может вернуть сторона этого плеча.
  Срок действия может быть не более чем через год после создания.
- **Время — это время сети.** Программа читает ончейн-часы, которые могут
  расходиться с реальным временем, порой на десятки секунд, и могут скачком уходить
  вперёд. Оставляйте запас между сроком действия и планируемым временем расчёта,
  избегайте пополнения и расчёта вблизи любой из границ и не полагайтесь на срок действия
  как на дедлайн с точностью до секунды. README программы советует закладывать
  около минуты расхождения.
- **Самый ранний расчёт.** Необязательно. Если задан, Settle до этого момента отклоняется,
  и он не должен быть позже срока действия.
- **Проверки при создании.** Create завершается ошибкой `PartyNotSignerCapable`, если сторона
  не является аккаунтом, принадлежащим System Program (это исключает мультиподпись SPL Token), а также ошибками
  `SettlementDestinationIsSwapDvp`, `SelfDvp`, `SameMint`, `ZeroAmount`,
  `SettlementAuthorityIsParty` или `ExpiryNotInFuture`. Полный список — в
  [таблице ошибок](/docs/defi/dvp-program#errors).
