Фондирование — это обычный `TransferChecked` в эскроу ноги, поэтому профинансировать ногу может любой кошелёк или кастодиальная система, способная отправить перевод токенов. Клиент DvP нужен только для чтения записи сделки перед фондированием. Программа проверяет балансы эскроу только при расчёте; при поступлении перевода никакой проверки не происходит, поэтому каждая сторона читает запись сделки до перевода.

Эта страница продолжает раздел
[создание сделки](/docs/defi/dvp-program/create-a-trade); клиент и подписанты
сохраняются.

## Проверьте условия

Создание записи не требует разрешений, а адреса эскроу выводятся только из записи и минта, но никогда не из условий. Поэтому перевод в эскроу может попасть под условия, с которыми вы не соглашались, в том числе под адреса расчёта, перенаправляющие средства вашего контрагента на третий адрес. Перед фондированием прочитайте аккаунт `SwapDvp` и сверьте его с согласованной сделкой.

`verifySwapDvp` в TypeScript и `verify::decode_swap_dvp_account` в Rust подтверждают, что аккаунт принадлежит программе DvP, имеет ровно 458 байт и находится по адресу, который выводится из его собственных полей (`fetchSwapDvpChecked` выполняет только первые две проверки). Обычные считыватели `fetchSwapDvp` и `decodeSwapDvp` не выполняют ни одной из них. Проверки сторон, сумм, времени и адресов назначения вызывающий код выполняет самостоятельно, сверяясь с согласованной сделкой.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { unwrapOption } from "@solana/kit";
    import { verifySwapDvp } from "./dvp";

    const trade = await verifySwapDvp(client.rpc, swapDvp);
    const t = trade.data;

    const expectedAmountA = 1_000_000_000n;
    const expectedAmountB = 998_500_000n;
    const expectedEarliestSettlement: bigint | null = null; // as agreed
    const expectedExpiry = 1_798_761_600n; // as agreed, unix seconds

    if (
      t.userA !== userA ||
      t.userB !== userB ||
      t.mintA !== mintA ||
      t.mintB !== mintB ||
      t.settlementAuthority !== settlementAuthority ||
      t.tokenProgramA !== tokenProgramA ||
      t.tokenProgramB !== tokenProgramB ||
      t.amountA !== expectedAmountA ||
      t.amountB !== expectedAmountB ||
      unwrapOption(t.earliestSettlementTimestamp) !== expectedEarliestSettlement ||
      t.expiryTimestamp !== expectedExpiry ||
      t.userASettlementDestination !== userA ||
      t.userBSettlementDestination !== userB
    ) {
      throw new Error("Stored terms do not match the agreed trade; do not fund");
    }

    if (t.expiryTimestamp <= BigInt(Math.floor(Date.now() / 1000)) + 60n) {
      throw new Error("Trade expires too soon to fund safely");
    }
    ```

  </Tab>

    }

Если запись создана вашим контрагентом или расчётным органом, сравните каждое поле с условиями, согласованными вне реестра. Если вы создали её сами, это чтение подтверждает, что она записана так, как была отправлена.

## Перевод в эскроу

Фондируйте ногу точно на согласованную сумму. Программа ограничивает расчёт значением `amount_x` и возвращает любой излишек стороне ноги, так что излишек не теряется, но он добавляет второй перевод при расчёте и может завершиться ошибкой для некоторых transfer hooks (см. примечания ниже).

Используйте `TransferChecked`, а не непроверяемый `Transfer`. Минты Token-2022 с расширениями, зависящими от mint account, такими как Pausable, отклоняют перевод, в котором он не передан, а минт с transfer hook требует, чтобы аккаунты хука были определены и добавлены так же, как и для любого другого перевода этого токена.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    Сторона ноги с активом, подписывая как `userASigner`, фондирует эскроу A:

    ```ts
    import {
      findAssociatedTokenPda,
      getTransferCheckedInstruction,
    } from "@solana-program/token-2022";

    const [userAAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: userA,
      tokenProgram: tokenProgramA,
    });
    const [userBAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: userB,
      tokenProgram: tokenProgramB,
    });

    const fundAssetLeg = getTransferCheckedInstruction({
      source: userAAtaA,
      mint: mintA,
      destination: escrowA,
      authority: userASigner,
      amount: t.amountA,
      decimals: 6,
    }, { programAddress: tokenProgramA });

    await client.sendTransaction([fundAssetLeg]);
    ```

    Сторона денежной ноги делает то же самое для эскроу B с `userBAtaB`, `mintB`,
    `userBSigner`, `t.amountB` и `{ programAddress: tokenProgramB }`.

    `user_b` и `trade.amount_b`.

Перевод для фондирования, виденный на уровне [`confirmed`](/docs/rpc#configuring-state-commitment),
всё ещё может быть отменён. Программа читает баланс эскроу ончейн
при расчёте, поэтому Settle, отправленный при отсутствии поступившего перевода для фондирования, завершится
с ошибкой `LegNotFunded`, и ничего не переместится; цена — неудавшийся Settle и повторная попытка.
Считайте ногу профинансированной, когда её перевод имеет статус `finalized`.

## Примечания

- **Ноги с wrapped SOL.** Программа читает баланс нативного эскроу после
  его синхронизации, поэтому lamports, отправленные в эскроу wrapped SOL системным переводом,
  учитываются. Никогда не отправляйте SOL в эскроу для любого другого минта: программа не может
  вернуть его, и он достаётся тому, кто закроет аккаунт.
- **Минты с ограничениями.** Для минта с замороженным Default Account State эскроу
  создаётся замороженным, и перевод завершается ошибкой, пока эмитент не разморозит его или не допустит. В
  [обзоре](/docs/defi/dvp-program#mint-configuration-constraints) описано
  взаимодействие с Token ACL.
- **Transfer hooks.** Фондируйте эскроу с хуками точно на согласованную сумму. Если
  излишек вынуждает сделать возврат при расчёте, возврат повторно использует аккаунты хука ноги
  с другим получателем и суммой, что некоторые хуки отклоняют. Восстановление:
  Reclaim, повторное фондирование на точную сумму и новый расчёт.
- **Фондирование после истечения срока.** Ничто не мешает переводу после `expiry_timestamp`. Он
  поступает, расчёт уже невозможен, и сторона ноги возвращает средства через
  Reclaim, пока сделка открыта, или через Recover после её закрытия. См.
  [отмену сделки](/docs/defi/dvp-program/unwind-a-trade).
- **Кто фондирует первым.** Программа не задаёт очерёдность двух ног. Порядок — это
  вопрос договорённости сторон; любая сторона может вернуть свою ногу в любой момент
  до расчёта, если только mint authority (заморозка, пауза или transfer hook)
  не блокирует эскроу.
