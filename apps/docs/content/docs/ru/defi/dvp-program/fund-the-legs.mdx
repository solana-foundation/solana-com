Финансирование — это обычный `TransferChecked` на эскроу плеча, поэтому профинансировать
плечо может любой кошелёк или кастодиальная система, умеющая отправлять переводы токенов.
Клиент DvP нужен только для чтения записи сделки перед финансированием. Программа
проверяет балансы эскроу только при расчёте; при поступлении перевода ничего не
проверяется, поэтому каждая сторона читает запись сделки до перевода.

Эта страница продолжает раздел
[создание сделки](/docs/defi/dvp-program/create-a-trade); клиент и подписанты
сохраняются.

## Проверьте условия

Создание записи не требует разрешений, а адреса эскроу выводятся только из
записи и mint, но никогда не из условий. Поэтому перевод на эскроу может
поступить по условиям, с которыми вы не соглашались, в том числе с адресами
расчёта, которые перенаправляют поступления вашего контрагента на третий адрес.
Перед финансированием прочитайте аккаунт `SwapDvp` и сверьте его с согласованной
сделкой.

`verifySwapDvp` в TypeScript и `verify::decode_swap_dvp_account` в Rust
подтверждают, что аккаунт принадлежит программе DvP, имеет ровно 458 байт и
находится по адресу, который выводится из его собственных полей (`fetchSwapDvpChecked`
выполняет только первые две проверки). Обычные ридеры `fetchSwapDvp` и `decodeSwapDvp`
не выполняют ни одной из этих проверок. Проверки сторон, сумм, времени и адресов назначения
вызывающий код выполняет самостоятельно, сверяя их с согласованной сделкой.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { unwrapOption } from "@solana/kit";
    import { verifySwapDvp } from "./dvp";

    const trade = await verifySwapDvp(client.rpc, swapDvp);
    const t = trade.data;

    const expectedAmountA = 1_000_000_000n;
    const expectedAmountB = 998_500_000n;
    const expectedEarliestSettlement: bigint | null = null; // as agreed
    const expectedExpiry = 1_798_761_600n; // as agreed, unix seconds

    if (
      t.userA !== userA ||
      t.userB !== userB ||
      t.mintA !== mintA ||
      t.mintB !== mintB ||
      t.settlementAuthority !== settlementAuthority ||
      t.tokenProgramA !== tokenProgramA ||
      t.tokenProgramB !== tokenProgramB ||
      t.amountA !== expectedAmountA ||
      t.amountB !== expectedAmountB ||
      unwrapOption(t.earliestSettlementTimestamp) !== expectedEarliestSettlement ||
      t.expiryTimestamp !== expectedExpiry ||
      t.userASettlementDestination !== userA ||
      t.userBSettlementDestination !== userB
    ) {
      throw new Error("Stored terms do not match the agreed trade; do not fund");
    }

    if (t.expiryTimestamp <= BigInt(Math.floor(Date.now() / 1000)) + 60n) {
      throw new Error("Trade expires too soon to fund safely");
    }
    ```

  </Tab>

  <Tab value="Rust">
    ```rust

    use solana_client::rpc_client::RpcClient;

    let expected_amount_b: u64 = 998_500_000;
    let expected_earliest_settlement: Option<i64> = None; // as agreed
    let expected_expiry: i64 = 1_798_761_600; // as agreed, unix seconds

        || trade.user_b != user_b
        || trade.mint_a != mint_a
        || trade.mint_b != mint_b
        || trade.settlement_authority != settlement_authority
        || trade.token_program_a != token_program_a
        || trade.token_program_b != token_program_b
        || trade.amount_a != expected_amount_a
        || trade.amount_b != expected_amount_b
        || trade.earliest_settlement_timestamp != expected_earliest_settlement
        || trade.expiry_timestamp != expected_expiry
        || trade.user_a_settlement_destination != user_a
        || trade.user_b_settlement_destination != user_b
    {
        return Err("stored terms do not match the agreed trade; do not fund".into());
    }

    let now_seconds: i64 = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)?
        .as_secs() as i64;
    if trade.expiry_timestamp <= now_seconds + 60 {
        return Err("trade expires too soon to fund safely".into());
    }
    ```

Если запись создана вашим контрагентом или расчётным органом, сверьте каждое поле
с условиями, согласованными вне блокчейна. Если вы создали её сами, это чтение
подтверждает, что она поступила в том виде, в каком была отправлена.

## Перевод на эскроу

Финансируйте плечо ровно на согласованную сумму. Программа ограничивает расчёт
значением `amount_x` и возвращает излишек стороне плеча, поэтому излишек не теряется,
но при расчёте добавляется второй перевод, и он может завершиться ошибкой с некоторыми
transfer hooks (см. примечания ниже).

Используйте `TransferChecked`, а не непроверяемый `Transfer`. Mint-ы Token-2022 с
расширениями, зависящими от mint account, такими как Pausable, отклоняют перевод,
в котором он не передан, а mint с transfer hook требует, чтобы аккаунты хука были
определены и добавлены так же, как и для любого другого перевода этого токена.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    Сторона плеча с активом, подписывая как `userASigner`, финансирует эскроу A:

    ```ts
    import {
      findAssociatedTokenPda,
      getTransferCheckedInstruction,
    } from "@solana-program/token-2022";

    const [userAAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: userA,
      tokenProgram: tokenProgramA,
    });
    const [userBAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: userB,
      tokenProgram: tokenProgramB,
    });

    const fundAssetLeg = getTransferCheckedInstruction({
      source: userAAtaA,
      mint: mintA,
      destination: escrowA,
      authority: userASigner,
      amount: t.amountA,
      decimals: 6,
    }, { programAddress: tokenProgramA });

    await client.sendTransaction([fundAssetLeg]);
    ```

    Сторона денежного плеча делает то же самое для эскроу B с `userBAtaB`, `mintB`,
    `userBSigner`, `t.amountB` и `{ programAddress: tokenProgramB }`.

  </Tab>

  <Tab value="Rust">
    ```rust

    use spl_token_2022_interface::instruction::transfer_checked;

    let user_a_ata_a =
        get_associated_token_address_with_program_id(&user_a, &mint_a, &token_program_a);

    let fund_asset_leg = transfer_checked(
        &token_program_a,
        &user_a_ata_a,
        &mint_a,
        &escrow_a,
        &user_a,
        &[],
        trade.amount_a,
        6,
    )?;
    ```

    Сторона денежного плеча формирует ту же инструкцию для эскроу B с `mint_b`,
    `user_b` и `trade.amount_b`.

  </Tab>
</Tabs>

Перевод финансирования, замеченный на уровне [`confirmed`](/docs/rpc#configuring-state-commitment),
всё ещё может быть вытеснен. Программа читает баланс эскроу ончейн при
расчёте, поэтому Settle, отправленный при не поступившем переводе финансирования,
завершится ошибкой `LegNotFunded`, и ничего не сдвинется; цена — неудачный Settle
и повторная попытка. Считайте плечо профинансированным, когда его перевод `finalized`.

## Примечания

- **Плечи с wrapped SOL.** Программа читает баланс нативного эскроу после его
  синхронизации, поэтому lamports, отправленные на эскроу wrapped SOL системным переводом,
  учитываются. Никогда не отправляйте SOL на эскроу для любого другого mint: программа не
  может его вернуть, и он достанется тому, кто закроет аккаунт.
- **Закрытые mint.** У mint с Default Account State frozen эскроу создаётся
  замороженным, и перевод завершается ошибкой, пока эмитент не разморозит его или не допустит.
  [Обзор](/docs/defi/dvp-program#mint-configuration-constraints) описывает
  взаимодействие с Token ACL.
- **Transfer hooks.** Финансируйте эскроу с хуками ровно на согласованную сумму. Если
  излишек вынуждает делать возврат при расчёте, возврат повторно использует аккаунты хука
  плеча с другим адресом назначения и суммой, что некоторые хуки отклоняют. Выход —
  Reclaim, повторное финансирование на точную сумму и повторный расчёт.
- **Финансирование после истечения срока.** Ничто не мешает переводу после `expiry_timestamp`.
  Он поступает, расчёт становится невозможен, и сторона плеча забирает средства через
  Reclaim, пока сделка открыта, или через Recover после её закрытия. См.
  [отмену сделки](/docs/defi/dvp-program/unwind-a-trade).
- **Кто финансирует первым.** Программа не задаёт очерёдность двух плеч. Порядок —
  дело сторон; любая сторона может вернуть своё плечо в любой момент до расчёта,
  если только mint authority (заморозка, пауза или transfer hook) не блокирует эскроу.
