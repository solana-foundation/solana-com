`SettleDvp` подписывает расчётный орган, указанный в записи о сделке. В одной
транзакции инструкция переводит `amount_a` плеча актива на адрес назначения стороны денежного плеча
и `amount_b` денежного плеча на адрес назначения стороны плеча актива,
возвращает любой излишек в каждом эскроу стороне соответствующего плеча и закрывает запись
и оба эскроу. Если хотя бы один из этих переводов не может быть выполнен, инструкция
завершается ошибкой, и ничего не перемещается.

Эта страница продолжает разделы [«Создание сделки»](/docs/defi/dvp-program/create-a-trade)
и [«Финансирование плеч»](/docs/defi/dvp-program/fund-the-legs); клиент, подписанты,
`trade` и token account сторон переходят сюда без изменений.

## Повторная проверка перед подписанием

Расчётный орган подписывает транзакцию, которая перемещает оба плеча, поэтому
перед подписанием он выполняет то же чтение, что и каждая из сторон: владельца, размер, стороны,
mint, суммы, срок действия и оба адреса назначения (см.
[«Финансирование плеч»](/docs/defi/dvp-program/fund-the-legs#verify-the-terms)). Сама
программа при расчёте повторно проверяет, что каждый mint по-прежнему принадлежит token program,
записанной при создании, не содержит запрещённых расширений и имеет тот же
mint authority, что и при создании сделки. Поэтому mint, пересозданный с запрещённым
расширением, другой token program или другим mint authority, не может
участвовать в расчёте.

## Создание аккаунтов получателей

Settle записывает данные в четыре token account, которые программа не создаёт:

| Аккаунт                | Получает                     | Владелец                           |
| ---------------------- | ---------------------------- | ------------------------------- |
| `userADestinationAtaB` | Денежное плечо (`amount_b`)    | `user_a_settlement_destination` |
| `userBDestinationAtaA` | Плечо актива (`amount_a`)   | `user_b_settlement_destination` |
| `userAAtaA`            | Любой излишек на плече актива | `user_a`                        |
| `userBAtaB`            | Любой излишек на денежном плече  | `user_b`                        |

Аккаунты для излишка используются, только если в эскроу лежит больше согласованной
суммы, но любой, у кого есть этот mint, может создать излишек, отправив несколько базовых
единиц в эскроу. Если аккаунт для возврата не существует, вся инструкция Settle
завершится ошибкой, поэтому создайте все четыре идемпотентно в той же транзакции.

  <Tab value="TypeScript">

    ```ts
    import {
      findAssociatedTokenPda,
      getCreateAssociatedTokenIdempotentInstruction,
    } from "@solana-program/token-2022";

    const destinationA = t.userASettlementDestination; // defaults to userA
    const destinationB = t.userBSettlementDestination; // defaults to userB

    const [userADestinationAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: destinationA,
      tokenProgram: tokenProgramB,
    });
    const [userBDestinationAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: destinationB,
      tokenProgram: tokenProgramA,
    });
    // userAAtaA and userBAtaB are from fund the legs.

    const createRecipientAccounts = [
      { ata: userADestinationAtaB, owner: destinationA, mint: mintB, tokenProgram: tokenProgramB },
      { ata: userBDestinationAtaA, owner: destinationB, mint: mintA, tokenProgram: tokenProgramA },
      { ata: userAAtaA, owner: userA, mint: mintA, tokenProgram: tokenProgramA },
      { ata: userBAtaB, owner: userB, mint: mintB, tokenProgram: tokenProgramB },
    ].map(({ ata, owner, mint, tokenProgram }) =>
      getCreateAssociatedTokenIdempotentInstruction({
        payer: authoritySigner,
        ata,
        owner,
        mint,
        tokenProgram,
      }),
    );
    ```

## Расчёт

`legAExtrasCount` сообщает программе, сколько из аккаунтов, добавленных после
фиксированного списка, относится к transfer hook плеча актива; остальные относятся к
денежному плечу. Для mint без transfer hook передайте ноль и ничего не добавляйте. Memo
program account требуется инструкции и используется только для адресов назначения,
которым нужен memo.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getSettleDvpInstruction } from "./dvp";

    const settleInstruction = getSettleDvpInstruction({
      settlementAuthority: authoritySigner,
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userADestinationAtaB,
      userBDestinationAtaA,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    });

    const { context: settleContext } = await client.sendTransaction([
      ...createRecipientAccounts,
      settleInstruction,
    ]);
    const settleSignature = settleContext.signature;
    console.log("Submitted:", settleSignature);

    // sendTransaction returns at the client's commitment (confirmed by default).
    // Wait for finalized before recording the trade as settled.
    let finalized = false;
    for (let attempt = 0; attempt < 30 && !finalized; attempt++) {
      const {
        value: [status],
      } = await client.rpc.getSignatureStatuses([settleSignature]).send();
      if (status?.err) {
        throw new Error("Settle transaction failed");
      }
      finalized = status?.confirmationStatus === "finalized";
      if (!finalized) {
        await new Promise((resolve) => setTimeout(resolve, 2_000));
      }
    }
    if (!finalized) {
      // A closed record means it settled; an open one is safe to settle again.
      throw new Error("Settle not finalized after 60s; read the trade record");
    }
    console.log("Settled:", settleSignature);
    ```

### Transfer hook

Сгенерированный IDL перечисляет только фиксированные аккаунты, поэтому сгенерированные билдеры
ничего не знают об аккаунтах hook. Определите дополнительные account meta для каждого mint с hook
так же, как вы сделали бы это для прямого перевода такого токена, а затем добавьте их в
инструкцию: сначала аккаунты плеча актива, затем денежного плеча, при этом
`legAExtrasCount` равен числу аккаунтов в первой группе. В TypeScript разверните
полученные meta в массив `accounts` инструкции; в Rust используйте
`add_remaining_accounts` в билдере. Лимит — 32 аккаунта на плечо,
включая программу hook и аккаунт валидации; лимит аккаунтов в транзакции
может сработать раньше, если hook есть у обоих плеч. Программа снимает флаг подписанта
со всех передаваемых аккаунтов, поэтому hook не может получить подпись расчётного органа
через этот путь.

## Запись результата

Считайте сделку рассчитанной, когда транзакция Settle достигает статуса `finalized`.
После расчёта запись и оба эскроу больше не существуют, поэтому системе, которой условия нужны
позже, следует сохранить их из чтения до расчёта или из транзакции создания.
rent закрытых аккаунтов перешёл расчётному органу.

## Ошибки Settle

`LegNotFunded` означает, что в эскроу меньше согласованной суммы; `DvpExpired`
и `SettlementTooEarly` означают, что временное окно упущено; `MintAuthorityChanged`
и `BlockedMintExtension` означают, что mint изменился после создания;
`RecipientAtaMismatch` означает, что token account назначения или возврата отсутствует или
больше не принадлежит ожидаемому владельцу и mint, обычно потому что описанный выше
шаг создания аккаунтов был пропущен. Во всех случаях ничего не перемещено, и
стороны могут отменить сделку с учётом полномочий mint (см.
[«Откат сделки»](/docs/defi/dvp-program/unwind-a-trade)).
