Четыре инструкции возвращают средства без расчёта: Reclaim, Cancel и Reject —
пока сделка открыта, и Recover — для депозита, поступившего после её закрытия.
Ни одна из них не проверяет срок действия. Замороженный эскроу или изменённый
минт всё равно могут заблокировать ногу, как описано в примечаниях в конце.

| Инструкция  | Подписант               | Область действия                         | Сделка после |
| ------------ | -------------------- | ----------------------------- | ---------------- |
| `ReclaimDvp` | `user_a` или `user_b` | Собственная нога подписанта          | Остаётся открытой       |
| `CancelDvp`  | Расчётный орган | Обе ноги                     | Закрыта           |
| `RejectDvp`  | `user_a` или `user_b` | Обе ноги                     | Закрыта           |
| `RecoverDvp` | `user_a` или `user_b` | Нога подписанта, после закрытия | Уже закрыта   |

В каждом случае эскроу опустошается: всё, что в нём лежит, возвращается стороне
этой ноги — эскроу A на token account `user_a` для `mint_a`, эскроу B на
token account `user_b` для `mint_b`, независимо от того, кто его пополнил.
Program account программы Memo передаётся для аккаунтов возврата, которым
требуется memo.

Эта страница продолжает предыдущие шаги: клиент и подписанты из
[создания сделки](/docs/defi/dvp-program/create-a-trade), `userAAtaA` и
`userBAtaB` из [пополнения ног](/docs/defi/dvp-program/fund-the-legs), а также
`MEMO_PROGRAM_ID` и `authority` из
[расчёта по сделке](/docs/defi/dvp-program/settle-the-trade) переходят сюда.

## Возврат ноги с помощью Reclaim

Reclaim возвращает ногу подписанта и оставляет сделку открытой, поэтому ногу
можно пополнить снова. Используйте его, когда проблема на ноге контрагента;
Cancel и Reject закрывают всю сделку.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getReclaimDvpInstruction } from "./dvp";

    // The asset-leg party takes its asset back.
    const reclaimInstruction = getReclaimDvpInstruction({
      signer: userASigner,
      swapDvp,
      mint: mintA,
      dvpSourceAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
    });

    await client.sendTransaction([reclaimInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::ReclaimDvpBuilder;

    // The asset-leg party takes its asset back.
    let reclaim_ix = ReclaimDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .mint(mint_a)
        .dvp_source_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .instruction();
    ```

  </Tab>
</Tabs>

## Cancel или Reject

Cancel подписывает расчётный орган, а Reject — любая из сторон. Обе инструкции
возвращают всё, что лежит в каждом эскроу, стороне соответствующей ноги и
закрывают запись и оба эскроу, при этом rent закрытых аккаунтов поступает
подписанту. Обе инструкции принимают одни и те же аккаунты; отличается только
подписант.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCancelDvpInstruction, getRejectDvpInstruction } from "./dvp";

    const unwindAccounts = {
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    };

    // Signed by the settlement authority:
    const cancelInstruction = getCancelDvpInstruction({
      settlementAuthority: authoritySigner,
      ...unwindAccounts,
    });

    // Or signed by either party:
    const rejectInstruction = getRejectDvpInstruction({
      signer: userBSigner,
      ...unwindAccounts,
    });
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::{CancelDvpBuilder, RejectDvpBuilder};

    // Signed by the settlement authority:
    let cancel_ix = CancelDvpBuilder::new()
        .settlement_authority(authority)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();

    // Or signed by either party:
    let reject_ix = RejectDvpBuilder::new()
        .signer(user_b)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();
    ```

  </Tab>
</Tabs>

Аккаунты возврата (`userAAtaA`, `userBAtaB`) должны существовать для любой ноги
с ненулевым балансом; неинициализированный аккаунт возврата приводит к сбою
перевода токенов и откату инструкции. Нога, которая так и не была пополнена, не
требует перевода и допускает отсутствие аккаунта.

## Восстановление позднего депозита

Settle, Cancel и Reject закрывают оба эскроу token account, поэтому обычный
перевод в закрытый эскроу завершится ошибкой. Депозит попадает в эскроу после
закрытия, только если что-то сначала пересоздаёт эскроу — например, транзакция
пополнения, которая включает инструкцию create-idempotent associated token
account перед переводом и находилась в обработке, когда контрагент отправил
Reject. Тогда токены оказываются в эскроу, сделки которого больше не существует:
записи нет, поэтому Reclaim не может её найти, а tombstone nonce не позволяет
создать новую сделку по тому же адресу и перехватить депозит.

Чтобы использовать `RecoverDvp`, сторона ноги передаёт исходные входные данные
seed (расчётный орган, обе стороны, оба минта, nonce). Программа заново
вычисляет адрес записи, требует её tombstone как доказательство того, что
сделка существовала, опустошает эскроу на собственный token account подписанта
и закрывает его, возвращая rent эскроу подписанту. Нога подписанта определяется
тем, какая сторона подписывает: `mint_a` для `user_a`, `mint_b` для `user_b`.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getAddressEncoder, getProgramDerivedAddress } from "@solana/kit";
    import { DVP_SWAP_PROGRAM_PROGRAM_ADDRESS, getRecoverDvpInstruction } from "./dvp";

    const [nonceTombstone] = await getProgramDerivedAddress({
      programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
      seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
    });

    const recoverInstruction = getRecoverDvpInstruction({
      signer: userASigner,
      swapDvp,
      nonceTombstone,
      mint: mintA,
      dvpEscrowAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });

    await client.sendTransaction([recoverInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::RecoverDvpBuilder;

    let recover_ix = RecoverDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .nonce_tombstone(nonce_tombstone)
        .mint(mint_a)
        .dvp_escrow_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .settlement_authority(settlement_authority)
        .user_a(user_a)
        .user_b(user_b)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .nonce(nonce)
        .instruction();
    ```

  </Tab>
</Tabs>

Восстановление зависит от того, сохранила ли сторона параметры создания.
Система, пополняющая сделки, хранит входные данные seed вместе с каждым ордером,
пока сделка не закрыта, а балансы эскроу не подтверждены как пустые.

## Примечания

- **Замороженные ноги.** На минте с ограничениями замороженный эскроу блокирует
  перевод токенов, выполняемый этими инструкциями, пока freeze authority не
  разморозит его. См. [обзор](/docs/defi/dvp-program#mint-configuration-constraints).
- **Изменения минта после создания.** Пути расторжения пропускают проверки
  расширений и mint authority, чтобы собственные проверки программы не
  блокировали восстановление. Правила самой Token Program по-прежнему действуют.
  Минт можно закрыть только при нулевом предложении, поэтому он не может
  измениться, пока в эскроу лежит баланс, но минт, закрытый и пересозданный как
  NonTransferable или с комиссией за перевод до поступления позднего депозита,
  может сделать этот депозит непереносимым или облагаемым комиссией. Это
  зависимость от mint authority, указанная в разделе
  [поддерживаемые токены](/docs/defi/dvp-program#supported-tokens).
