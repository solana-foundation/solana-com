Расширение Transfer Hook и интерфейс Transfer Hook открывают возможность создания Mint Accounts, которые выполняют пользовательскую логику инструкций при каждой передаче токенов.

Это открывает множество новых сценариев использования при передаче токенов, например:

- Принудительное применение роялти для NFT
- Чёрный или белый список кошельков, которые могут получать токены
- Реализация пользовательских комиссий при передаче токенов
- Создание пользовательских событий передачи токенов
- Отслеживание статистики по передачам ваших токенов
- И многое другое

Для достижения этой цели разработчики должны создать программу, реализующую
[интерфейс Transfer Hook](https://github.com/solana-labs/solana-program-library/tree/master/token/transfer-hook/interface)
и инициализировать Mint Account с включённым расширением Transfer Hook.

При каждой передаче токенов из Mint Account программа Token Extensions выполняет Cross Program Invocation (CPI) для запуска инструкции в программе Transfer Hook.

<Callout type="info">

Когда Token Extensions program выполняет CPI к программе Transfer Hook, все аккаунты из исходной передачи преобразуются в аккаунты только для чтения. Это означает, что привилегии подписанта отправителя не распространяются на программу Transfer Hook.

Это архитектурное решение принято для предотвращения злоупотреблений программами Transfer Hook.

</Callout>

В этом руководстве мы создадим программу Transfer Hook с использованием фреймворка Anchor, однако реализовать интерфейс Transfer Hook возможно также с помощью нативной программы. Подробнее о фреймворке Anchor:
[Фреймворк Anchor](https://www.anchor-lang.com/)

## Обзор интерфейса Transfer Hook

Интерфейс Transfer Hook предоставляет разработчикам возможность реализовать пользовательскую логику инструкций, которая выполняется при каждой передаче токенов для конкретного Mint Account.

Интерфейс Transfer Hook определяет следующие
[инструкции](https://github.com/solana-labs/solana-program-library/blob/master/token/transfer-hook/interface/src/instruction.rs):

- `Execute`: Инструкция, которую программа Token Extension вызывает при каждой передаче токенов.
- `InitializeExtraAccountMetaList` (необязательно): Создаёт аккаунт, хранящий список дополнительных аккаунтов, необходимых для пользовательской инструкции `Execute`.
- `UpdateExtraAccountMetaList` (необязательно): Обновляет список дополнительных аккаунтов, перезаписывая существующий список.

Технически реализация инструкции `InitializeExtraAccountMetaList` через интерфейс не является обязательной. Аккаунт может быть создан любой инструкцией программы Transfer Hook.

Однако Program Derived Address (PDA) для этого аккаунта должен быть выведен с использованием следующих seed:

- Жёстко закодированная строка "extra-account-metas"
- Адрес Mint Account
- ID программы Transfer Hook

```js
const [pda] = PublicKey.findProgramAddressSync(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBuffer()],
  program.programId // transfer hook program ID
);
```

Сохраняя дополнительные аккаунты, необходимые инструкции `Execute`, в предопределённом PDA, эти аккаунты могут быть автоматически добавлены к инструкции передачи токенов на стороне клиента.

## Hello-world Transfer Hook

Этот пример является «hello world» для transfer hook. Это простой transfer hook, который выводит сообщение при каждой передаче токенов. Начнём с открытия примера в Solana Playground — онлайн-инструменте для сборки и развёртывания программ Solana:
[ссылка](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/hello_world)

Пример состоит из программы на Anchor, реализующей интерфейс transfer hook, и тестового файла для проверки программы.

Эта программа будет включать только 3 инструкции:

1. `initialize_extra_account_meta_list`: Создаёт аккаунт, который хранит список дополнительных аккаунтов, необходимых для инструкции `transfer_hook`. В примере hello world мы оставляем его пустым.
2. `transfer_hook`: Эта инструкция вызывается через CPI при каждой передаче токенов для выполнения передачи токенов wrapped SOL.
3. `fallback`: Поскольку мы используем Anchor, а token program является нативной программой, нам необходимо добавить запасную инструкцию для ручного сопоставления дискриминатора инструкций и вызова нашей пользовательской инструкции `transfer_hook`. Эту функцию изменять не нужно.

Каждый раз при передаче токена token program будет вызывать функцию `transfer_hook`.

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    Ok(())
}
```

В этой функции вы можете добавить свою дополнительную логику. Например, можно сделать так, чтобы передача завершалась с ошибкой, если передаваемая сумма превышает 50:

```rust
#[error_code]
pub enum MyError {
    #[msg("The amount is too big")]
    AmountTooBig,
}

pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    if amount > 50 {
        return err!(MyError::AmountTooBig);
    }

    Ok(())
}
```

## Transfer Hook со счётчиком

В следующем примере показано, как увеличивать счётчик при каждой передаче токена.
[ссылка](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/counter)

Если вы хотите добавить в transfer hook логику, требующую дополнительных аккаунтов, их необходимо добавить в аккаунт ExtraAccountMetaList. В нашем случае нам нужен PDA, который сохраняет количество передач токена.

Это можно сделать, добавив следующий код в инструкцию `initialize_extra_account_meta_list`:

```rust
let account_metas = vec![
    ExtraAccountMeta::new_with_seeds(
        &[Seed::Literal {
            bytes: "counter".as_bytes().to_vec(),
        }],
        false, // is_signer
        true,  // is_writable
    )?,
];
```

Также нам необходимо создать этот аккаунт при инициализации нового mint account и передавать его каждый раз при передаче токена.

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        init_if_needed,
        seeds = [b"counter"],
        bump,
        payer = payer,
        space = 16
    )]
    pub counter_account: Account<'info, CounterAccount>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(
        token::mint = mint,
        token::authority = owner,
    )]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        token::mint = mint,
    )]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(
        mut,
        seeds = [b"counter"],
        bump
    )]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Этот аккаунт будет хранить переменную-счётчик типа `u64`:

```rust
#[account]
pub struct CounterAccount {
    counter: u64,
}
```

Теперь в функции transfer hook мы можем просто увеличивать этот счётчик на единицу при каждом вызове:

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    ctx.accounts.counter_account.counter.checked_add(1).unwrap();
    msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

    Ok(())
}
```

На стороне клиента эти дополнительные аккаунты добавляются автоматически с помощью вспомогательной функции createTransferCheckedWithTransferHookInstruction:

```js
let transferInstructionWithHelper =
  await createTransferCheckedWithTransferHookInstruction(
    connection,
    sourceTokenAccount,
    mint.publicKey,
    destinationTokenAccount,
    wallet.publicKey,
    amountBigInt,
    decimals,
    [],
    "confirmed",
    TOKEN_2022_PROGRAM_ID
  );
```

<Callout type="warn">

Поскольку здесь мы увеличиваем счётчик при каждой передаче токена, необходимо убедиться, что инструкция transfer hook может быть вызвана только во время передачи, иначе кто-то мог бы вызвать инструкцию transfer hook напрямую и нарушить работу счётчика. Эту проверку следует добавлять в каждый из ваших transfer hook.

</Callout>

Проверку можно добавить следующим образом:

```rust
fn assert_is_transferring(ctx: &Context<TransferHook>) -> Result<()> {
    let source_token_info = ctx.accounts.source_token.to_account_info();
    let mut account_data_ref: RefMut<&mut [u8]> = source_token_info.try_borrow_mut_data()?;
    let mut account = PodStateWithExtensionsMut::<PodAccount>::unpack(*account_data_ref)?;
    let account_extension = account.get_extension_mut::<TransferHookAccount>()?;

    if !bool::from(account_extension.transferring) {
        return err!(TransferError::IsNotCurrentlyTransferring);
    }

    Ok(())
}
```

А затем вызвать её в начале функции `transfer_hook`:

```rust
    #[error_code]
    pub enum TransferError {
        #[msg("The token is not currently transferring")]
        IsNotCurrentlyTransferring,
    }

    #[interface(spl_transfer_hook_interface::execute)]
    pub fn transfer_hook(ctx: Context<TransferHook>, _amount: u64) -> Result<()> {
        // Fail this instruction if it is not called from within a transfer hook
        assert_is_transferring(&ctx)?;

        ctx.accounts.counter_account.counter.checked_add(1).unwrap();
        msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

        Ok(())
    }
```

## Transfer Hook с комиссией wSOL (продвинутый пример)

В следующей части этого руководства мы создадим более продвинутую программу Transfer Hook с использованием фреймворка Anchor. Эта программа будет требовать от отправителя оплаты комиссии в wSOL при каждой передаче токенов.

Передачи wSOL будут выполняться через делегата, который является PDA, выведенным из программы Transfer Hook. Это необходимо, потому что подпись исходного отправителя инструкции передачи токенов недоступна в программе Transfer Hook.

Эта программа будет включать только 3 инструкции:

1. `initialize_extra_account_meta_list`: Создаёт аккаунт, хранящий список дополнительных аккаунтов, необходимых для инструкции `transfer_hook`.
2. `transfer_hook`: Эта инструкция вызывается через CPI при каждой передаче токенов для выполнения передачи wrapped SOL.
3. `fallback`: Инструкции интерфейса transfer hook имеют специфические дискриминаторы (идентификаторы инструкций). В программе Anchor можно использовать запасную инструкцию для ручного сопоставления дискриминатора инструкций и вызова пользовательской инструкции `transfer_hook`.

Эта программа будет требовать от отправителя оплаты комиссии в wrapped SOL (wSOL) при каждой передаче токенов. Вот
[финальная программа](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/main).

### Инструкция инициализации аккаунта ExtraAccountMetas

На этом шаге мы реализуем инструкцию `initialize_extra_account_meta_list` для нашей программы Transfer Hook. Эта инструкция создаёт аккаунт ExtraAccountMetas, который будет хранить дополнительные аккаунты, необходимые для инструкции `transfer_hook`.

В этом примере инструкция `initialize_extra_account_meta_list` требует 7 аккаунтов:

- `payer`: Аккаунт, используемый для оплаты создания аккаунта ExtraAccountMetas.
- `extra_account_meta_list`: Аккаунт ExtraAccountMetas, созданный для хранения списка аккаунтов, необходимых для инструкции `transfer_hook`.
- `mint`: Mint Account, указывающий на эту программу Transfer Hook. Адрес mint является обязательным seed для вывода PDA `extra_account_meta_list`.
- `wsol_mint`: Mint wrapped SOL.
- `token_program`: ID оригинального Token Program
- `associated_token_program`: ID Associated Token Program.
- `system_program`: System Program, который является обязательным аккаунтом при создании новых аккаунтов.

Адреса `mint`, `wsol_mint` и `associated_token_program` будут использоваться для вывода адресов associated token account для wSOL. Эти аккаунты необходимы для инструкции `transfer_hook` и будут сохранены в аккаунте ExtraAccountMetas.

Обновите структуру `InitializeExtraAccountMetaList`, заменив следующий стартовый код:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList {}
```

На приведённый ниже код:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds

    pub wsol_mint: InterfaceAccount<'info, Mint>,

    pub associated_token_program: Program<'info, AssociatedToken>,
```

Затем обновите инструкцию `initialize_extra_account_meta_list`, заменив следующий стартовый код:

```rust

}
```

На приведённый ниже код:

```rust
pub fn initialize_extra_account_meta_list(
        ctx: Context<InitializeExtraAccountMetaList>,
    ) -> Result<()> {
        // index 0-3 are the accounts required for token transfer (source, mint, destination, owner)
        // index 4 is address of ExtraAccountMetaList account
        // The `addExtraAccountsToInstruction` JS helper function resolving incorrectly
        let account_metas = vec![
            // index 5, wrapped SOL mint
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.wsol_mint.key(), false, false)?,
            // index 6, token program
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.token_program.key(), false, false)?,
            // index 7, associated token program
            ExtraAccountMeta::new_with_pubkey(
                &ctx.accounts.associated_token_program.key(),
                false,
                false,
            )?,
```

Далее реализуем пользовательскую инструкцию `transfer_hook`. Это инструкция, которую Token Extensions Program будет вызывать при каждой передаче токенов.

### Резервная инструкция (Fallback)

Наконец, нам нужно добавить резервную инструкцию в программу Anchor для обработки CPI от Token Extensions Program.

Этот шаг необходим из-за различия в способе генерации дискриминаторов инструкций в Anchor по сравнению с теми, что используются в инструкциях интерфейса Transfer Hook. Дискриминатор инструкции `transfer_hook` не будет совпадать с дискриминатором интерфейса Transfer Hook.

Обновите инструкцию `fallback`, заменив следующий стартовый код:

```rust
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    Ok(())
}
```

На обновлённый код ниже:

```rust
// fallback instruction handler as workaround to anchor instruction discriminator check
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    let instruction = TransferHookInstruction::unpack(data)?;

    // match instruction discriminator to transfer hook interface execute instruction
    // token2022 program CPIs this instruction on token transfer
    match instruction {
        TransferHookInstruction::Execute { amount } => {
            let amount_bytes = amount.to_le_bytes();

            // invoke custom transfer hook instruction on our program
            __private::__global::transfer_hook(program_id, accounts, &amount_bytes)
        }
        _ => return Err(ProgramError::InvalidInstructionData.into()),
    }
}
```

Резервная инструкция проверяет, совпадает ли дискриминатор входящей инструкции с инструкцией `Execute` из интерфейса Transfer Hook. При успешном совпадении она вызывает инструкцию `transfer_hook` в нашей программе Anchor.

<Callout type="info">

В настоящее время существует невыпущенная функция Anchor, упрощающая этот процесс. Она устранит необходимость в резервной инструкции.

</Callout>

### Использование данных token account в transfer hook

Иногда вам может потребоваться использовать данные аккаунта для получения дополнительных аккаунтов в extra account metas. Это полезно, например, если вы хотите использовать владельца token account в качестве seed для PDA.

При создании ExtraAccountMeta вы можете использовать данные любого аккаунта в качестве дополнительного seed. В данном случае мы хотим получить аккаунт счётчика из владельца token account и строки 'counter'. Это означает, что мы всегда сможем видеть, как часто данный владелец token account'а переводил токены.

Вот как это настраивается в функции `extra_account_metas()`.

```rust
// Define extra account metas to store on extra_account_meta_list account
impl<'info> InitializeExtraAccountMetaList<'info> {
    pub fn extra_account_metas() -> Result<Vec<ExtraAccountMeta>> {
        Ok(
            vec![
                ExtraAccountMeta::new_with_seeds(
                    &[
                        Seed::Literal {
                            bytes: b"counter".to_vec(),
                        },
                        Seed::AccountData { account_index: 0, data_index: 32, length: 32 },
                    ],
                    false, // is_signer
                    true // is_writable
                )?
            ]
        )
    }
}
```

Рассмотрим структуру token account, чтобы понять, как хранятся данные аккаунта. Ниже приведён пример структуры token account. Таким образом, мы можем взять 32 байта по позиции от 32 до 64 в качестве владельца token account, что соответствует 'account_index: 0'. 'account_index` указывает на индекс аккаунта в массиве аккаунтов. В случае transfer hook владельческий token account является первой записью в массиве аккаунтов. Второй аккаунт — всегда mint, а третий — destination token account. Этот порядок аккаунтов совпадает с порядком в старом Token Program.

```rust
/// Account data.
#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Account {
    /// The mint associated with this account
    pub mint: Pubkey,
    /// The owner of this account.
    pub owner: Pubkey,

    pub amount: u64,
    pub delegate: COption<Pubkey>,
    pub state: AccountState,
    pub is_native: COption<u64>,
    pub delegated_amount: u64,
    pub close_authority: COption<Pubkey>,
}
```

В нашем случае мы хотим получить аккаунт счётчика из владельца sender token account, поэтому при создании аккаунтов ExtraAccountMeta мы инициализируем (`init`) этот PDA-аккаунт счётчика, полученный из владельца sender token account и строки 'counter'. После инициализации PDA-аккаунта счётчика мы сможем использовать его в transfer hook для увеличения значения при каждой передаче.

````rust

```rust

pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,
````

Нам также необходимо определить этот дополнительный аккаунт счётчика в структуре TransferHook. Это аккаунты, которые передаются в нашу программу TransferHook при каждой передаче. Клиент получает эти дополнительные аккаунты из PDA ExtraAccountsMetaList и включает их в инструкцию передачи токенов, однако здесь, в программе, нам всё равно необходимо их определить.

```rust
#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(token::mint = mint, token::authority = owner)]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(token::mint = mint)]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(seeds = [b"extra-account-metas", mint.key().as_ref()], bump)]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(seeds = [b"counter", owner.key().as_ref()], bump)]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Обратите внимание, что аккаунт счётчика получается из владельца token account и должен быть инициализирован перед выполнением передачи. В данном примере мы инициализируем аккаунт счётчика при инициализации extra account metas. Поэтому PDA счётчика будет существовать только для владельца token account, вызвавшего эту функцию. Если вы хотите иметь аккаунт счётчика для каждого token account вашего mint, вам потребуется реализовать функциональность для предварительного создания этих PDA. Например, на вашем dapp может быть кнопка для регистрации счётчика, которая создаёт данный PDA-аккаунт, после чего пользователи смогут использовать этот токен счётчика.
