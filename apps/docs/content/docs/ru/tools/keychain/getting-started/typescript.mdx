## Установка

Установите общий пакет или отдельные подписанты по мере необходимости:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Требуется `@solana/kit` 8.1 или новее. Транзакции v1
(`createTransactionMessage({ version: 1 })`) поддерживаются, за исключением Fireblocks
с `useProgramCall: true`, который принимает только legacy и v0.

## Базовое использование

### Унифицированная фабрика (рекомендуется для приложений, поддерживающих несколько подписантов)

Используйте `createKeychainSigner` с дискриминированной конфигурацией для
создания любого бэкенда:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Или установите отдельный пакет подписанта для уменьшения зависимостей:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Использование с сообщениями транзакций

Каждый бэкенд, кроме Crossmint и нативного режима Fordefi, возвращает
`SolanaTransactionSigner`, который является `TransactionPartialSigner` из Kit и работает
с вспомогательными функциями partial-signer из `@solana/signers`, описанными ниже. Бэкенды с управляемой отправкой в сеть рассмотрены в разделе [Возможности подписантов](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Подпись и отправка с любым подписантом

`signAndSendTransaction` из `@solana/keychain-core` отправляет транзакцию в
блокчейн независимо от типа подписанта. Подписанты с функцией отправки передают её через
своего провайдера; все остальные используют переданную вами функцию `sendTransaction` (в core нет
зависимости от RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Использование с Kit Client (плагин keychainSigner)

`@solana/keychain-kit-plugin` устанавливает подписант keychain непосредственно
на [Kit client](https://github.com/anza-xyz/kit), подключая его в качестве
`payer` и `identity`, что позволяет пропустить ручную настройку `pipe`,
описанную выше:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Плагин принимает ту же конфигурацию с тегом бэкенда, что и `createKeychainSigner`,
за исключением Crossmint и нативного режима Fordefi (когда задан `chain`). Эти бэкенды изменяют
транзакцию на стороне сервера, поэтому не могут выступать в роли клиентского `payer` или
`identity`; плагин отклоняет их как на этапе компиляции, так и во время выполнения. В сборку включается только тот
бэкенд, к которому идёт обращение (пакеты бэкендов загружаются через динамический
`import()`).

Используйте `keychainPayer` или `keychainIdentity`, чтобы назначить только одну
роль, и комбинируйте бэкенды в рамках одного клиента:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Уже есть `SolanaTransactionSigner`? Это корректный `TransactionPartialSigner`
из Kit, поэтому вы можете установить его с помощью
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
(`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Отмена и неподтверждённые отправки

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` и
`signMessages` принимают `{ abortSignal }` вторым аргументом. Прерывание
останавливает ожидание, но не отменяет работу, которую провайдер уже принял.

В нативном авто-режиме Crossmint и Fordefi ошибка не означает, что транзакция
не была отправлена. Если провайдер мог принять транзакцию, код ошибки —
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` задаётся, если создание транзакции было принято, а
`context.idempotencyKey` содержит ключ, полученный из сообщения. Повторная отправка
побайтово идентичной транзакции безопасна; пересобранная транзакция (например, с новым
blockhash) считается новым переводом. Определить тип ошибки помогут `providerMayHaveAccepted(error)` и
`providerStatus(error)` из `@solana/keychain-core`.
Прежде чем повторять попытку, сверьтесь с провайдером.

### Crossmint

```typescript

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmint работает только на отправку. Его API всегда выполняет одобренную транзакцию
на стороне сервера и спонсирует газ, поэтому подписант предоставляет только
`signAndSendTransactions()`: у него нет `signTransactions()` или `signMessages()`,
и его нельзя установить с помощью `@solana/keychain-kit-plugin`. Возвращаемая
подпись идентифицирует транзакцию, которую отправил Crossmint.

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

У Fordefi три режима подписи, которые фиксируются при создании через `chain` и
`pushMode`. Каждый режим предоставляет ровно один метод для транзакций, а все три подписывают
сообщения:

| Режим          | Конфигурация                                      | Тип                        | Метод                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Чёрный ящик     | `chain` не задан                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Нативный авто   | `chain` задан, `pushMode` опущен или `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Нативный ручной | `chain` задан, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

API-запросы аутентифицируются подписью запроса ECDSA P-256: передайте
ключ подписи как `privateKeyPem` или храните его в KMS/HSM, передав
`requestSigner`.

**Нативный авто-режим** (рекомендуется для работы в блокчейне): задайте `chain`, и Fordefi
сам подписывает и отправляет транзакцию. Поскольку Fordefi может заменить
blockhash или комиссии перед подписью, подписант является `TransactionSendingSigner`
из Kit: используйте его с
`signAndSendTransactionMessageWithSigners`, а не с потоком partial-signer, показанным
выше. Нативный авто-режим принимает только неподписанную транзакцию, единственным необходимым
подписантом которой является хранилище (vault), и его нельзя использовать с `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Нативный ручной режим**: задайте `chain` и `pushMode: "manual"`. Fordefi переписывает
сообщение (recent blockhash, инструкции комиссии Compute Budget) и подписывает его,
но не отправляет в сеть. `modifyAndSignTransactions()` возвращает транзакцию,
подписанную Fordefi, которая заменяет отправленную вами: всегда продолжайте работу с
возвращённой транзакцией. Fordefi должен быть плательщиком комиссии и должен подписывать раньше
любого другого необходимого подписанта. Изменения не показываются в виде диффа, поэтому проверьте результат перед
отправкой в сеть.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Режим чёрного ящика**: не указывайте `chain`. Fordefi подписывает сырые байты и не выполняет отправку транзакции — сборку и отправку вы осуществляете самостоятельно. Используйте этот режим с хранилищем Fordefi типа «чёрный ящик».

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Возможности подписантов

`@solana/keychain-core` определяет по одному интерфейсу для каждого типа подписантов Kit. Каждый добавляет
`isAvailable(): Promise<boolean>` к соответствующему интерфейсу `@solana/signers`:

- `SolanaTransactionSigner` (`TransactionPartialSigner` из Kit): возвращает подписи
  для принадлежащей вам транзакции.
- `SolanaModifyingSigner` (`TransactionModifyingSigner` из Kit): переписывает
  транзакцию, подписывает её и возвращает новую транзакцию без отправки в сеть.
- `SolanaSendingSigner` (`TransactionSendingSigner` из Kit): подписывает и отправляет
  через своего провайдера.
- `SolanaMessageSigner` (`MessagePartialSigner` из Kit): подписывает офчейн-сообщения.
  Он существует отдельно от типов для транзакций.

`SolanaSigner` — объединение трёх типов для транзакций. Возвращаемый тип каждой фабрики
указывает точный тип своего бэкенда. Если конфигурация известна только во время
выполнения, сузьте тип с помощью `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` или `isSolanaMessageSigner`. `signerCapabilities(signer)`
сообщает сразу обо всех четырёх.

| Бэкенд                                                                                                     | Тип                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (чёрный ящик) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (без подписи сообщений)  |
| fordefi (нативный ручной)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (нативный авто)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (без подписи сообщений)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Создание пользовательских подписантов

Реализуйте интерфейсы возможностей, которые поддерживает ваш бэкенд:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Реализуйте только то, что поддерживает ваш бэкенд. Kit классифицирует подписантов по тому, какие
методы у них есть, поэтому никогда не добавляйте метод, который просто выбрасывает исключение.

Ознакомьтесь с
[руководством по добавлению подписантов](/docs/tools/keychain/adding-signers),
чтобы интегрировать дополнительные сервисы управления ключами.
