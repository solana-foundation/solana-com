Программа Rewards распределяет токены из принадлежащего программе хранилища между набором
получателей, у каждого из которых свой график вестинга. Authority пополняет хранилище и определяет,
кто и что получает. Получатели забирают разблокированные токены со временем, а
authority может отозвать токены у получателей или вернуть оставшиеся токены, если
распределение это допускает. Программа написана с использованием Pinocchio, поддерживается Solana
Foundation и работает как с минтами SPL Token, так и с минтами Token-2022, за исключением
минтов Token-2022 с расширением transfer hook.

ID программы (mainnet и devnet):

```text

```

## Выберите тип распределения

Программа поддерживает два типа распределения. Оба используют одни и те же графики вестинга
и режимы отзыва.

|                  | Direct                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **Как это работает** | Создаёт ончейн-аккаунт для каждого получателя     | Хранит ончейн единственный merkle root; для получения токенов получатели предоставляют proof  |
| **Первоначальные затраты** | Плательщик оплачивает rent для аккаунта каждого получателя | Аккаунты для каждого получателя не создаются, пока кто-то не заберёт токены                           |
| **Масштаб**        | Практически применимо для нескольких тысяч получателей  | Масштабируется до миллионов получателей; объём хранилища растёт только по мере получения токенов |
| **Изменяемость**   | Получателей можно добавлять после создания       | Набор получателей фиксируется при создании                                       |
| **Когда использовать**   | Небольшие распределения, которые меняются со временем    | Крупные фиксированные распределения, например эирдропы                              |

## Графики вестинга

У каждой аллокации есть один из четырёх графиков. Временные метки указываются в секундах Unix.

| График      | Поведение                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | Все токены доступны для получения сразу                                                                                    |
| `Linear`      | Токены разблокируются пропорционально между `startTs` и `endTs`                                                             |
| `Cliff`       | Ничего не разблокируется до `cliffTs`, затем всё разблокируется сразу                                                       |
| `CliffLinear` | Линейный вестинг от `startTs` до `endTs`, при этом ничего нельзя забрать до `cliffTs`; ранее накопленное разблокируется в момент клиффа |

## Аккаунты

| Аккаунт              | PDA seeds                                        | Хранит                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | Authority, минт и итоговые суммы аллокаций       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | Аллокация и вестинг одного получателя       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | Authority, минт, итоговые суммы и merkle root |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | Сумма, которую один получатель уже забрал        |
| `Revocation`         | `["revocation", distribution, user]`             | Маркер, блокирующий отозванного получателя Merkle-распределения |

`seed` — это адрес дополнительного подписанта, передаваемого при создании, поэтому один
authority может запускать несколько распределений для одного и того же минта. Хранилище
каждого распределения — это associated token account PDA распределения для его минта.

## Инструкции

### Direct-распределение

1. Authority вызывает `CreateDirectDistribution`, чтобы создать PDA распределения
   и его хранилище.
2. Authority вызывает `AddDirectRecipient` по одному разу для каждого получателя, указывая сумму
   и график вестинга. Каждый вызов переводит эту сумму из token account
   authority в хранилище.
3. Получатели вызывают `ClaimDirect`, чтобы вывести разблокированные токены. Передайте `amount: 0`,
   чтобы забрать всё, что на данный момент разблокировано.
4. Когда получатель забрал всё или распределение закрыто,
   `CloseDirectRecipient` закрывает аккаунт получателя и возвращает rent тому
   аккаунту, который за него заплатил.
5. Authority вызывает `CloseDirectDistribution`, чтобы вернуть оставшийся баланс хранилища
   и rent. Если задан `clawbackTs`, закрытие разрешено только после этого
   момента.

### Merkle-распределение

1. Authority строит merkle-дерево офчейн. Каждый лист фиксирует получателя,
   его общую сумму и график вестинга.
2. Authority вызывает `CreateMerkleDistribution`, передавая root, общую сумму,
   доступную для получения, и `clawbackTs`, и пополняет хранилище в той же
   инструкции.
3. Получатели вызывают `ClaimMerkle`, передавая данные своего листа и proof. Первое получение
   создаёт аккаунт `MerkleClaim` получателя. Передайте `amount: 0`, чтобы забрать
   всё, что на данный момент разблокировано.
4. После `clawbackTs` authority вызывает `CloseMerkleDistribution`, чтобы вернуть
   оставшийся баланс хранилища и rent.
5. После закрытия распределения получатели вызывают `CloseMerkleClaim`, чтобы
   вернуть rent за свой аккаунт claim.

Программа хэширует листья с помощью Keccak-256 как
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`, где
`totalAmount` — это little-endian `u64`, а `schedule` использует ту же кодировку, что и
аргумент `VestingSchedule` инструкции. Узлы proof хэшируются как отсортированные
пары, сначала меньший хэш.

### Отзыв

Отзыв необязателен. Битовая маска `revocable`, заданная при создании, определяет, какие
режимы может использовать authority: бит 0 включает `NonVested`, бит 1 включает `Full`,
а `0` отключает отзыв.

| Режим        | Инструкция                                    | Результат                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` или `RevokeMerkleClaim` | Разблокированные, но не полученные токены уходят пользователю; неразблокированные токены возвращаются authority |
| `Full`      | `RevokeDirectRecipient` или `RevokeMerkleClaim` | Все неполученные токены, как разблокированные, так и нет, возвращаются authority               |

Отзыв получателя Merkle-распределения создаёт маркер `Revocation`, который блокирует будущие
получения, даже если получатель ещё ни разу не забирал токены. Отзыв получателя Direct-распределения закрывает
его аккаунт `DirectRecipient` и возвращает его rent.

## Клиенты

Репозиторий включает клиенты [`@solana/kit`](/docs/clients/official/javascript) и
Rust, сгенерированные из IDL программы с помощью Codama, в
[`clients/`](https://github.com/solana-foundation/rewards/tree/main/clients).
Клиент пока не опубликован в npm. Соберите его из исходного кода с помощью
`just generate-clients`.
