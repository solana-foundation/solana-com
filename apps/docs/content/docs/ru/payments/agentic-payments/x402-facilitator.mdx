# Интеграция протокола Solana x402 с Kora RPC

## Что вы создадите

Required) с Kora — инфраструктурой безгазовой подписи Solana. По завершении
у вас будет рабочая система, в которой:

- API может взимать микроплатежи за доступ с использованием протокола x402
- Пользователи платят в USDC, не нуждаясь в SOL для оплаты газа
- Kora берёт на себя все комиссии за транзакции в роли безгазового посредника
- Платежи атомарно исполняются в блокчейне Solana

## Что такое x402?

[x402](https://www.x402.org/) — это открытый платёжный стандарт, обеспечивающий бесшовные
микроплатежи за доступ к API. Вместо традиционных моделей подписки или API-ключей x402 позволяет серверам взимать плату за отдельные вызовы API, создавая настоящую инфраструктуру оплаты по факту использования.

Ключевые преимущества x402:

- **Мгновенные микроплатежи**: Оплата долей цента за каждый вызов API
- **Поддержка платежей для ИИ-агентов**: Оплата вызовов API с помощью ИИ-агентов
- **Без подписок**: Пользователи платят только за то, что используют
- **Web3-платежи**: Прозрачные и верифицируемые платежи в сети
- **Стандартный HTTP**: Работает с существующей веб-инфраструктурой, используя HTTP-статус 402
  при необходимости оплаты

Серверы, использующие x402 для взимания микроплатежей за доступ к API, возвращают HTTP-статус 402, когда требуется оплата. Для доступа к защищённым эндпоинтам клиенты должны передать корректный платёж серверу в заголовке `X-PAYMENT`. x402 опирается на «Фасилитаторов» для верификации и исполнения транзакций, чтобы серверам не приходилось напрямую взаимодействовать с блокчейн-инфраструктурой.

### Понимание фасилитаторов

Фасилитаторы — ключевой компонент экосистемы x402. Они выступают специализированными сервисами, абстрагирующими блокчейн-платежи от имени API-серверов.

**Что делают фасилитаторы:**

- **Верификация платежей**: Проверяют корректность формирования и достаточность платёжных данных клиента
- **Абстракция сложности**: Устраняют необходимость серверам напрямую взаимодействовать с
  блокчейн-инфраструктурой (подписание и оплата сетевых комиссий)
- **Исполнение транзакций**: Отправляют подтверждённые транзакции в Solana (или другие сети)

В нашем демо мы создаём фасилитатор, использующий Kora для верификации и исполнения транзакций (подробнее ниже).

## Что такое Kora?

Kora — это нода-подписант Solana, предоставляющая услуги подписания и безгазового выполнения транзакций. Она позволяет приложениям абстрагироваться от комиссий за газ, давая пользователям возможность оплачивать транзакционные издержки в токенах, отличных от SOL, или полностью за счёт спонсора.

Ключевые возможности Kora:

- **Безгазовые транзакции**: Пользователям не нужен SOL для выполнения транзакций
- **Абстракция комиссий**: Оплата комиссий в USDC или других SPL-токенах
- **JSON-RPC интерфейс**: Простой HTTP API для работы с транзакциями
- **Гибкие подписанты**: Поддержка нескольких бэкендов для подписания (memory, Vault, Turnkey, Privy)
- **Движок политик**: Гранулярный контроль над валидацией транзакций и политиками комиссий

В контексте x402 Kora служит идеальным бэкендом для фасилитаторов: обрабатывает сетевые комиссии, подписывает транзакции и валидирует их.

## Обзор архитектуры

Наша интеграция x402 + Kora состоит из четырёх взаимосвязанных компонентов с полным циклом запроса/ответа:

Полный платёжный поток:

1. Клиент запрашивает защищённый ресурс → API возвращает 402 Payment Required
2. Клиент создаёт платёжную транзакцию с помощью обёртки x402 fetch (которая формирует
   транзакцию Solana с платёжной инструкцией)
3. Клиент отправляет платёж фасилитатору для верификации
4. Фасилитатор выполняет валидацию через Kora, которая подписывает и отправляет транзакцию в Solana
5. Транзакция подтверждена в сети, фасилитатор уведомляет API
6. API возвращает защищённый контент с квитанцией об оплате клиенту

### Разбор компонентов

1. **Kora RPC Server** (Порт 8080)
   - Основной сервис безгазового выполнения транзакций
   - Обрабатывает подписание транзакций в роли плательщика комиссий
   - Валидирует транзакции согласно настроенным политикам

2. **Facilitator Wrapper/Proxy Server** (Порт 3000)
   - Адаптирует Kora к протоколу x402
   - Реализует эндпоинты `/verify`, `/settle` и `/supported`
   - Преобразует данные между форматами x402 и Kora

3. **Protected API** (Порт 4021)
   - Демо-сервер API с эндпоинтами, защищёнными платежами
   - Использует промежуточный слой x402-express для обработки платежей
   - Возвращает данные только после успешной оплаты

4. **Клиентское приложение**
   - Демонстрирует использование обёртки x402 fetch
   - Подписывает транзакции закрытым ключом пользователя

Подход с несколькими компонентами может показаться сложным, но он отражает реальные производственные системы, в которых обработка платежей, обслуживание API и клиентские приложения — это отдельные сущности.

### Шаг 5: Обновление конфигурационных файлов

#### kora.toml

Файл `kora/kora.toml` настраивает Kora RPC Server. Вносить изменения в этот файл не требуется, но вы можете проверить следующие параметры:

1. **Платёжный токен**: Убедитесь, что минт Devnet USDC находится в списке разрешённых:

```toml
allowed_tokens = [
    "4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU", # USDC devnet
]
```

2. **Аутентификация API**: В демо используется API-ключ для доступа к Kora. Он должен
   совпадать с `KORA_API_KEY` в файле `.env`:

```toml
[kora.auth]
api_key = "kora_facilitator_api_key_example"
```

3. **Политика плательщика комиссий**: Настроена для ограничения подписания нежелательных транзакций:

```toml
[validation.fee_payer_policy]
allow_sol_transfers = false
# all other settings are false
```

4. **Разрешённые программы**: Убедитесь, что System Program, Token Program, associated
   token program и compute budget program находятся в списке разрешённых:

```toml
allowed_programs = [
    "11111111111111111111111111111111",             # System Program
    "TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA",  # Token Program
    "ATokenGPvbdGVxr1b2hvZbsiqW5xWH25efTNsLJA8knL", # Associated Token Program
    "ComputeBudget111111111111111111111111111111",  # Compute Budget Program
]
```

#### signers.toml

Файл `kora/signers.toml` настраивает подписанта Kora. Вносить изменения в этот файл не требуется, но вы можете проверить следующие параметры:

1. **Переменная окружения подписанта**: Убедитесь, что переменная окружения подписанта
   `private_key_env` установлена в `KORA_SIGNER_PRIVATE_KEY` (совпадает с именем переменной окружения в файле `.env`).

```toml
[[signers]]
name = "main_signer"
type = "memory"
private_key_env = "KORA_SIGNER_PRIVATE_KEY"
weight = 1
```

## Понимание реализации

Вот что происходит в процессе успешного платёжного потока:

1. **Запрос клиента** → API возвращает 402 с требованиями к оплате
2. **Создание платежа** → Клиент создаёт транзакцию Solana с платежом
3. **Отправка платежа** → Клиент отправляет запрос на сервер с платежом в заголовке
   `X-PAYMENT`
4. **Верификация** → Фасилитатор проверяет через `signTransaction` Kora
5. **Исполнение** → Фасилитатор исполняет через `signAndSendTransaction` Kora
   (отправляя платёжную транзакцию в Solana)
6. **Доступ предоставлен** → Фасилитатор возвращает подпись транзакции, а API
   возвращает защищённый контент с квитанцией об оплате

Давайте подробно рассмотрим, как работает каждый компонент:

- **Kora RPC** (Порт 8080): Обрабатывает безгазовое подписание транзакций
- **Facilitator** (Порт 3000): Связывает протокол x402 с Kora
- **Protected API** (Порт 4021): Ваш монетизированный эндпоинт API
- **Клиент**: Демонстрирует автоматический платёжный поток

### Facilitator Wrapper/Proxy Server

Фасилитатор работает на порту 3000. Это сервер, обрабатывающий взаимодействие
с Solana (в нашем случае через Kora). Он используется для верификации и исполнения x402-платежей.

Фасилитатор (`facilitator/src/facilitator.ts`) является мостом между протоколом x402
и Kora RPC. Он реализует три ключевых эндпоинта:

#### 1. Эндпоинт `/verify`

Этот эндпоинт:

- Получает платёжные данные x402 от сервера защищённого API
- Извлекает транзакцию Solana с помощью вспомогательных инструментов x402
- Использует `signTransaction` Kora для проверки корректности без широковещательной рассылки
- Возвращает статус верификации, `isValid`

#### 2. Эндпоинт `/settle`

Этот эндпоинт:

- Получает платёжные данные x402 после того, как платёж был верифицирован
  эндпоинтом `/verify`
- Использует `signAndSendTransaction` Kora для подписания и широковещательной рассылки транзакции
- Возвращает подпись транзакции как подтверждение исполнения

#### 3. Эндпоинт `/supported`

Этот эндпоинт фактически анонсирует возможности фасилитатора, включая:

- Поддерживаемую версию x402
- Схему платежей (точные платежи)
- Сеть (solana-devnet)
- Адрес плательщика комиссий, который мы получаем из Kora с помощью метода `getPayerSigner`

### Защищённый API

Сервер API (`api/src/api.ts`) использует промежуточный слой x402-express для защиты эндпоинтов:

```typescript
app.use(
  paymentMiddleware(
    KORA_PAYER_ADDRESS, // Where payments should go
    {
      "GET /protected": {
        price: "$0.0001", // Price in USD
        network: NETWORK // solana-devnet
      }
    },
    {
      url: FACILITATOR_URL // Our facilitator wrapper
    }
  )
);
```

Промежуточный слой:

- Перехватывает запросы к защищённым эндпоинтам (в нашем случае эндпоинт `/protected`)
- Возвращает статус 402, если оплата отсутствует
- Валидирует и обрабатывает платежи через фасилитатор
- Предоставляет доступ после успешной оплаты

Хотя мы используем Express, библиотека x402 включает поддержку middleware для
многих популярных фреймворков. Подробнее см. в разделе
[x402 TypeScript Packages](https://github.com/coinbase/x402/tree/main/typescript/packages).

### Клиентское приложение

Клиент (`client/src/index.ts`) демонстрирует, как автоматически работает x402,
отправляя запрос с помощью стандартного вызова `fetch`, а затем повторяя запрос
через обёртку оплаты:

```typescript
// Create a signer from private key
const payer = await createSigner(NETWORK, PAYER_PRIVATE_KEY);

// Wrap fetch with x402 payment capabilities
const fetchWithPayment = wrapFetchWithPayment(fetch, payer);

// First attempt: Regular fetch (will fail with 402)
const expect402Response = await fetch(PROTECTED_API_URL);
console.log(`Status: ${expect402Response.status}`); // 402

// Second attempt: Fetch with payment wrapper (succeeds)
const response = await fetchWithPayment(PROTECTED_API_URL);
console.log(`Status: ${response.status}`); // 200
```

Обёртка x402 для fetch:

- Обнаруживает ответы с кодом 402
- Автоматически создаёт платёжную транзакцию на основе требований
  защищённого API к оплате
- Подписывает с помощью приватного ключа пользователя
- Отправляет платёж фасилитатору для проверки и обработки
- Повторяет запрос с подтверждением оплаты в заголовке `x-payment-response`
- Возвращает успешный ответ

- **Протокол x402** обеспечивает беспрепятственную монетизацию API через микроплатежи
- **Kora RPC** выступает в роли фасилитатора для платежей x402, выполняя
  проверку и расчёт транзакций
- **Пользователи** могут оплачивать доступ к API, не держа SOL и не управляя газовыми комиссиями

Эта архитектура создаёт мощную основу для:

- Маркетплейсов AI-агентов
- API с оплатой за использование
- Контентных платформ с микроплатежами
- Тарификации SaaS на основе потребления
- Любых сервисов, требующих мгновенных и верифицируемых платежей

Сочетание x402 и Kora привносит мощь Solana в традиционную веб-инфраструктуру.

### Продолжайте разработку

- **Настройте ценообразование**: изменяйте API для взимания разных сумм
  на разных эндпоинтах
- **Добавьте несколько токенов**: настройте Kora для приёма различных SPL-токенов
  в качестве оплаты
- **Продакшн-развёртывание**: разверните в основной сети с продакшн-подписантами (Vault,
  Turnkey или Privy)
- **Создайте собственный API**: разработайте реальный сервис с монетизацией через платежи x402
