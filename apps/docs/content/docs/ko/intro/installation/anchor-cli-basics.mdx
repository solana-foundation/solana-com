description:

---

이 섹션에서는 [Anchor CLI](https://www.anchor-lang.com/docs) 사용을 시작하는 데
도움이 되는 일반적인 명령어와 예제를 제공합니다.

<Steps>
<Step>

### 프로젝트 초기화

아래 명령어를 실행하여 새 Anchor 프로젝트를 생성합니다. 프로젝트 이름으로 새 디렉터리가 만들어지고, 이 디렉터리를 사용해 새 Anchor 프로젝트가 초기화됩니다.

```terminal
$ anchor init <project-name>
```

예를 들어, 아래 명령어는 `my-project`라는 프로젝트를 생성합니다. `my-project` 디렉터리에는 모듈식 Rust 프로그램과 LiteSVM을 사용하는 Rust 테스트 템플릿이 포함됩니다.

```terminal
$ anchor init my-project
```

대신 TypeScript 테스트 템플릿을 생성하려면 템플릿을 명시적으로 선택하세요. 예를 들어 Mocha 템플릿을 사용하려면 다음과 같이 합니다.

```terminal
$ anchor init my-project --test-template mocha
```

TypeScript 테스트 템플릿을 사용하려면 Node.js와 JavaScript 패키지 매니저가 필요합니다.

그런 다음 프로젝트 디렉터리로 이동합니다.

```terminal
$ cd <project-name>
```

Anchor의 [프로젝트 파일 구조](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure)를 참고하세요.

</Step>
<Step>

### 프로그램 빌드

프로젝트를 빌드하려면 다음 명령어를 실행하세요:

```terminal
$ anchor build
```

컴파일된 프로그램은 `/target/deploy` 디렉토리에서 찾을 수 있습니다.

<Callout type="warn" title="플랫폼 도구 설치 실패">
  빌드 시 platform-tools 디렉터리가 유효하지 않다는 오류가 표시되면 SBF 빌드 도구를 다시 설치한 후 빌드를 다시 시도하세요.

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### 프로그램 배포

프로젝트를 배포하려면 다음 명령어를 실행하세요:

```terminal
$ anchor deploy
```

이 명령어는
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml) 파일에
지정된 `cluster`에 프로그램을 배포합니다.

</Step>
<Step>

### 프로그램 테스트

프로젝트를 테스트하려면 다음 명령어를 실행하세요:

```terminal
$ anchor test
```

이 명령어는 프로젝트를 빌드하고 배포한 후 테스트를 실행합니다.

<Callout>
  `localnet` 클러스터를 사용할 때 Anchor는 자동으로 로컬 validator를 시작하고
  프로그램을 배포한 후 테스트를 실행하고 validator를 중지합니다.
</Callout>

<Callout type="warn" title="JavaScript 테스트 러너 오류">

JavaScript 또는 TypeScript 테스트 템플릿을 선택한 경우, 다음 오류 중 하나가 표시되면 Node.js 또는 설정된 패키지 매니저가 설치되어 있지 않다는 의미일 수 있습니다.

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
