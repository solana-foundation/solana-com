특정 버전이 필요하거나 [빠른 설치](/docs/intro/installation)가 정상적으로 완료되지 않을 때는
각 종속성을 개별적으로 설치하세요.
새 환경을 구성하는 경우에는 섹션을 순서대로 따라 하고, 특정 도구를 설치하거나
문제를 해결해야 한다면 해당 도구 섹션으로 바로 이동하세요.

## 사전 요구사항

<Accordions>
<Accordion title="Windows">

Windows에서 Solana 프로그램을 개발하려면 **반드시**
[Windows Subsystem for Linux](https://learn.microsoft.com/en-us/windows/wsl/install)(WSL)를
사용해야 합니다. WSL을 설치한 후 다른 모든 종속성은 Linux 터미널을 통해
설치됩니다.

WSL을 설치하려면 Windows PowerShell에서 다음 명령을 실행하세요:

```terminal
$ wsl --install
```

설치 과정에서 기본 사용자 계정을 생성하라는 메시지가 표시됩니다.

![WSL 설치](/assets/docs/intro/installation/wsl-install.png)

기본적으로 WSL은 Ubuntu를 설치합니다. 검색 표시줄에서 "Ubuntu"를 검색하여 Linux
터미널을 열 수 있습니다.

![WSL Ubuntu](/assets/docs/intro/installation/wsl-ubuntu-search.png)

Ubuntu 터미널이 아래 이미지와 같이 보이면 터미널에서 `ctrl + v`(붙여넣기
단축키)가 작동하지 않는 문제가 발생할 수 있습니다.

![Ubuntu 터미널](/assets/docs/intro/installation/wsl-ubuntu-terminal-1.png)

이 문제가 발생하면 검색 표시줄에서 "Terminal"을 검색하여 Windows Terminal을
여세요.

![Windows Terminal](/assets/docs/intro/installation/wsl-windows-terminal.png)

다음으로 Windows Terminal을 닫고 Ubuntu를 다시 검색하여 Linux 터미널을 다시
여세요. 이제 터미널이 아래 이미지와 같이 보이며 `ctrl + v`(붙여넣기 단축키)가
작동합니다.

![Ubuntu 터미널](/assets/docs/intro/installation/wsl-ubuntu-terminal-2.png)

VS Code를 사용하는 경우
[WSL 확장](https://code.visualstudio.com/docs/remote/wsl-tutorial)을 사용하면
WSL과 VS Code를 함께 사용할 수 있습니다.

![VS Code에서 WSL 설정](/assets/docs/intro/installation/wsl-vscode.png)

VS Code 상태 표시줄에 다음과 같이 표시됩니다:

![WSL: Ubuntu](/assets/docs/intro/installation/wsl-vscode-ubuntu.png)

WSL 설정이 완료되면 다음 작업을 수행할 준비가 된 것입니다:

- Ubuntu(Linux) 터미널을 사용하여 [빠른 설치](/docs/intro/installation) 완료하기
- 아래 설명된 대로 [Rust](#install-rust), [Solana CLI](#install-solana-cli) 및
  [Anchor CLI](#install-anchor-cli)를 개별적으로 설치하기

</Accordion>
<Accordion title="Linux">

<Tabs items={[".deb", ".rpm"]}>
<Tab value=".deb" >
Debian 또는 Ubuntu, Mint 같은 Debian 기반 배포판의 경우:

1. 모든 패키지가 최신 상태인지 확인하기 위해 패키지 목록을 업데이트합니다:

```terminal
$ sudo apt-get update
```

2. 다음 종속성을 설치합니다:

```terminal
$ sudo apt-get install -y \
    build-essential \
    pkg-config \
    libudev-dev llvm libclang-dev \
    protobuf-compiler libssl-dev
```

<Callout>
`protobuf-compiler`를 설치할 때 다음 오류가 발생하면, 설치 명령을 다시 실행하기 전에
`sudo apt-get update`를 실행하세요.

```
Package protobuf-compiler is not available, but is referred to by another package.
This may mean that the package is missing, has been obsoleted, or
is only available from another source
```

</Callout>

설치된 패키지를 업데이트합니다:

```terminal
$ sudo dnf upgrade --refresh
```

개발 종속성을 설치합니다:

```terminal
$ sudo dnf group install c-development development-tools \
&& sudo dnf install pkg-config openssl-devel
```

### Rust 설치하기

개발자들은 [Rust](https://www.rust-lang.org/) 프로그래밍 언어를 사용하여 Solana
프로그램을 구축합니다.

1. 터미널에 다음 명령어를 입력하여
   [rustup](https://www.rust-lang.org/tools/install)을 사용해 Rust를 설치하세요:

```terminal
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
```

설치가 성공적으로 완료되면 다음과 같은 메시지가 표시됩니다:

<Accordions>
<Accordion title="Rust 설치 성공 메시지">

```
Rust is installed now. Great!

To get started you may need to restart your current shell.
This would reload your PATH environment variable to include
Cargo's bin directory ($HOME/.cargo/bin).

To configure your current shell, you need to source
the corresponding env file under $HOME/.cargo.

This is usually done by running one of the following (note the leading DOT):
. "$HOME/.cargo/env"            # For sh/bash/zsh/ash/dash/pdksh
source "$HOME/.cargo/env.fish"  # For fish
```

</Accordion>
</Accordions>

2. [Cargo](https://github.com/rust-lang/cargo)의 bin 디렉토리를 포함하도록 PATH
   환경 변수를 다시 로드하세요:

```terminal
$ . "$HOME/.cargo/env"
```

3. 설치가 성공적으로 완료되었는지 확인하세요.

```terminal
$ rustc --version
```

이 명령은 설치된 Rust 버전을 출력합니다. 예:

```
rustc x.y.z (...)
```

</Step>
<Step>

### Solana CLI 설치하기

Solana CLI는 Solana 프로그램을 빌드하고 배포하는 데 필요한 모든 도구를
제공합니다.

1. 공식 설치 명령어를 사용하여 Solana CLI 도구 모음을 설치하세요:

```terminal
$ sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"
```

<Callout>
  `stable`을 특정 Agave 릴리스 태그 또는 `beta`
  나 `edge` 릴리스 채널로 바꿀 수 있습니다.
</Callout>

2. 현재 터미널에서 Solana CLI를 사용할 수 있도록 설정합니다.

설치 프로그램은 셸 설정을 업데이트하고, 현재 세션에 적용하는 데 필요한
명령을 출력합니다. 일반적으로 다음과 같은 명령입니다:

```terminal
$ export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"
```

`solana`를 여전히 사용할 수 없다면 터미널을 다시 시작하세요. 설치 프로그램이 어떤 셸
설정 파일을 업데이트했는지 확인하려면 현재 사용 중인 셸을 확인하세요:

```terminal
$ echo $SHELL
```

- 출력에 `/bash`가 포함되어 있다면 터미널을 다시 시작하거나
  `source ~/.bashrc`를 실행하세요.
- 출력에 `/zsh`가 포함되어 있다면 터미널을 다시 시작하거나 `source ~/.zshrc`를 실행하세요.

3. 설치가 정상적으로 완료되었는지 확인합니다:

```terminal
$ solana --version
```

이 명령은 설치된 Solana CLI 버전을 출력합니다. 예:

```
solana-cli x.y.z (..., client:Agave)
```

<Callout>

사용 가능한 모든 버전은
[Agave GitHub 저장소](https://github.com/anza-xyz/agave/releases)에서 확인할 수 있습니다. Agave는
[Anza](https://www.anza.xyz/)의 validator 클라이언트이며, 이전에는
Solana Labs validator 클라이언트로 알려져 있었습니다.

</Callout>

4. 나중에 Solana CLI를 업데이트하려면 다음을 실행하세요:

```terminal
$ agave-install update
```

</Step>

### Anchor CLI 설치하기

[Anchor](https://www.anchor-lang.com/)는 Solana 프로그램을 개발하기 위한
프레임워크입니다. Anchor 프레임워크는 Rust 매크로를 활용하여 Solana 프로그램
작성 과정을 단순화합니다.

#### 사전 요구사항

Node.js와 JavaScript 패키지 관리자는 Mocha나 Jest 같은 TypeScript 테스트 템플릿을
선택할 때만 필요합니다. 기본 LiteSVM 테스트 템플릿은 Rust에서 실행되며
Node.js 도구가 필요하지 않습니다.

<Accordions>
<Accordion title="Node 설치">

1. 다음 명령을 실행하여
   [Node Version Manager(nvm)](https://github.com/nvm-sh/nvm)로 Node를 설치합니다:

```terminal
$ curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
```

2. 터미널을 다시 시작한 후 `nvm` 명령이 정상적으로 실행되는지 확인합니다:

```terminal
$ command -v nvm
```

3. `nvm`을 사용하여 Node를 설치합니다:

```terminal
$ nvm install --lts
```

4. Node 버전을 확인하여 설치가 정상적으로 완료되었는지 검증합니다:

```terminal
$ node --version
```

이 명령은 설치된 Node.js 버전을 출력합니다. 예:

```
vx.y.z
```

</Accordion>
<Accordion title="Yarn 설치">

1. Yarn을 설치합니다:

```terminal
$ npm install --global yarn
```

2. Yarn 버전을 확인하여 설치가 정상적으로 완료되었는지 검증합니다:

```terminal
$ yarn --version
```

이 명령은 설치된 Yarn 버전을 출력합니다. 예:

```
x.y.z
```

</Accordion>
</Accordions>

#### 설치

Anchor CLI와 도구를 설치하는 두 가지 방법이 있습니다:

- Anchor 버전 관리자(AVM) — 권장 설치 방법
- AVM 없이 — GitHub에서 직접 설치

<Tabs groupId="anchor" items={["AVM", "Without AVM"]}>
<Tab value="AVM">

Anchor 버전 관리자(AVM)를 사용하면 시스템에 다양한 Anchor 버전을 설치하고 관리할
수 있으며, 향후 Anchor 버전을 쉽게 업데이트할 수 있습니다. AVM을 사용하여
Anchor를 설치하려면 아래 단계를 따르세요:

1. 다음 명령어로 AVM을 설치하세요:

```terminal
$ curl -sSfL https://raw.githubusercontent.com/otter-sec/anchor/master/avm/install | sh
```

2.  AVM이 성공적으로 설치되었는지 확인하세요:

```terminal
$ avm --version
```

3. AVM을 사용하여 Anchor CLI를 설치하세요:

최신 버전을 설치하려면:

```terminal
$ avm install latest
$ avm use latest
```

특정 버전을 설치하려면 버전 번호를 지정하세요:

```terminal
$ avm install 1.1.2
$ avm use 1.1.2
```

<Callout type="warn">

Linux 또는 WSL에서 Anchor CLI를 설치할 때 다음 오류가 발생할 수 있습니다:

```
error: could not exec the linker cc = note: Permission denied (os error 13)
```

이 오류 메시지가 표시되면 다음 단계를 따르세요:

1. 이 페이지 상단의
   [Linux](/docs/intro/installation/dependencies) 섹션에 나열된
   종속성을 설치하세요.
2. Anchor CLI 설치를 다시 시도하세요.

</Callout>

4. 다음과 같이 Anchor CLI 버전을 확인하여 설치가 성공했는지 확인하세요:

```terminal
$ anchor --version
```

이 명령은 현재 활성화된 Anchor CLI 버전을 출력합니다. 예:

```
anchor-cli 1.1.2
```

<Callout type="info">

`avm use`를 실행하여 시스템에서 사용할 Anchor CLI 버전을 선택하세요.

- 최신 버전을 설치했다면 `avm use latest`를 실행하세요.
- `1.1.2` 버전을 설치했다면 `avm use 1.1.2`를 실행하세요.

</Callout>

</Tab>

<Tab value="Without AVM">

1. 다음 명령으로 특정 버전의 Anchor CLI를 설치합니다:

```terminal
$ cargo install --git https://github.com/solana-foundation/anchor --tag v1.1.2 anchor-cli --locked
```

2. Anchor CLI 버전을 확인하여 설치가 정상적으로 완료되었는지 검증합니다:

```terminal
$ anchor --version
```

이 명령은 설치된 Anchor CLI 버전을 출력합니다. 예:

```
anchor-cli 1.1.2
```

### Surfpool CLI 설치

[Surfpool](/docs/tools/surfpool)은 로컬 개발을 위한 도구로,
`solana-test-validator`를 개선한 대체 도구입니다.

1. 다음 명령으로 Surfpool을 설치합니다:

```terminal
$ curl --proto '=https' --tlsv1.2 -sSfL https://run.surfpool.run/ | bash
```

2. Surfpool CLI 버전을 확인하여 설치가 정상적으로 완료되었는지
   검증합니다:

```terminal
$ surfpool --version
```

이 명령은 설치된 Surfpool CLI 버전을 출력합니다. 예:

```
surfpool x.y.z
```
