<Callout type="info" title="요약">
  프로그램은 LLVM을 통해 sBPF로 컴파일되며, 트랜잭션당 140만 CU 예산이 주어진 샌드박스 VM에서 실행됩니다. 런타임은 최대 512개의 컴파일된 프로그램을 캐싱하고, 로깅, CPI, 암호화, 메모리를 위한 시스콜을 제공하며, 새 배포를 1 slot 지연시킵니다.
</Callout>

## 컴파일

Solana는 [LLVM](https://llvm.org/)을 사용하여 프로그램을 Solana 바이트코드 형식(sBPF)을 포함한
[ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format) 바이너리로 컴파일합니다. ELF 바이너리는 실행 가능한 계정에 온체인으로 저장됩니다.

<Callout>
  sBPF는 Solana 런타임에 맞게 조정된 [eBPF](https://en.wikipedia.org/wiki/EBPF)
  바이트코드의 Solana 전용 변형입니다. 표준 eBPF가 아니며
  Solana 특화 수정 사항이 포함되어 있습니다.
</Callout>

## 프로그램 작성

Solana 프로그램은 주로 세 가지 접근 방식 중 하나를 사용하여
[Rust](https://rust-book.cs.brown.edu/title-page.html)로 작성됩니다:

<Cards>
  <Card title="Anchor" href="https://www.anchor-lang.com/docs">
    보일러플레이트를 줄이기 위해 Rust 매크로를 사용하는 프레임워크입니다. 대부분의 개발자에게 권장됩니다.
  </Card>
  <Card title="Pinocchio" href="/docs/clients/official/rust#program-crates">
    컴퓨트 소비량과 바이너리 크기에 최적화된 경량 제로 카피 Rust 라이브러리입니다. 일반적인 CPI를 위한 프로그램별 크레이트가 포함되어 있습니다.
  </Card>
  <Card title="Native Rust" href="/docs/programs/rust">
    프레임워크 없이 직접 Rust를 사용합니다. 완전한 제어권을 제공하지만 더 많은 수동 구현이 필요합니다.
  </Card>
</Cards>

이러한 접근 방식 전반에 걸쳐 적용되는 CPI 개념과 예시는 [Cross-Program Invocations](/docs/core/cpi)를 참고하세요.

## 프로그램 실행 모델

트랜잭션이 처리될 때, 런타임은
[`process_message()`](https://github.com/anza-xyz/agave/blob/v3.1.8/svm/src/message_processor.rs#L15)를 통해
각 명령어를 순차적으로 실행합니다.
각 명령어에 대해 런타임은:

1. **명령어 컨텍스트를 준비합니다.** [`prepare_next_top_level_instruction()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L436)을
   호출하여 명령어의 계정 인덱스를 매핑하고, 서명자 및 쓰기 가능 플래그를 설정하며,
   [`TransactionContext`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L467)를 구성합니다.

2. **프리컴파일을 확인합니다.** 프로그램이
   [프리컴파일](/docs/core/programs/precompiles)인 경우, 런타임은
   [`process_precompile()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L491)을 호출합니다.
   이 함수는 여전히 스택 프레임을 푸시 및 팝(_rs`push()`_ 및 _rs`pop()`_ 사용)하지만
   sBPF VM과 프로그램 캐시 조회를 우회하여 네이티브 코드를 직접 실행합니다.

3. **스택 프레임을 푸시합니다.** (3~6단계는
   [`InvokeContext::process_instruction()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L481)과
   [`process_executable_chain()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L507) 내부에서 실행되며,
   _rs`process_message()`_에서 호출됩니다.) [`InvokeContext`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L184)에서
   [`push()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L233)를 호출하면
   명령어 스택 높이가 증가하고 재진입 규칙이 적용됩니다: 프로그램은 **직접적인** 호출자(명령어 스택의 현재 최상위 프로그램)가 동일한 프로그램인 경우에만 자기 자신으로 재진입할 수 있습니다.
   깊은 자기 재귀(A -> A -> A)는 스택 깊이 제한 내에서 허용됩니다.
   다른 재진입 패턴(예: A가 B를 호출하고 B가 A를 호출)은
   _rs`InstructionError::ReentrancyNotAllowed`_를 반환합니다.

4. **프로그램을 해석합니다.** 런타임은
   [`process_executable_chain()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L507)을 호출하여
   로더를 결정합니다. program account의 소유자가
   [네이티브 로더](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L517)인 경우,
   해당 프로그램은 빌트인이며 엔트리포인트 함수가
   [`ProgramCacheForTxBatch`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L706)에서
   직접 조회됩니다.
   소유자가 BPF 로더 중 하나(`bpf_loader_deprecated`,
   `bpf_loader`, `bpf_loader_upgradeable`, 또는 `loader_v4`)인 경우,
   로더 자체의 빌트인 엔트리포인트가 대신 호출됩니다.

5. **BPF 프로그램을 실행합니다.** BPF 프로그램의 경우,
   [로더 엔트리포인트](https://github.com/anza-xyz/agave/blob/v3.1.8/programs/bpf_loader/src/lib.rs#L385)는
   프로그램 캐시에서 컴파일된 실행 파일을 조회합니다.
   [`execute()`](https://github.com/anza-xyz/agave/blob/v3.1.8/programs/bpf_loader/src/lib.rs#L1449) 함수는 다음을 수행합니다:
   - 계정 데이터를 플랫 파라미터 버퍼로 직렬화합니다
   - 스택, 힙, 메모리 영역을 포함한 sBPF VM을 생성합니다
   - 컴파일된 코드를 실행하며 실행 중 컴퓨트 유닛을 소비합니다. 예산이 초과되면
     _rs`ComputationalBudgetExceeded`_를 반환합니다.
   - 버퍼에서 계정 데이터를 역직렬화하여 계정 상태로 복원합니다

6. **스택 프레임을 팝합니다.** [`pop()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L268)을
   호출하여 명령어가 런타임의 회계 규칙을 위반하지 않았는지 검증합니다
   (lamport 잔액이 균형을 이루는지, 읽기 전용 계정이 수정되지 않았는지,
   계정 데이터 크기가 제한 내에 있는지).

7. **컴퓨트 유닛을 누적합니다.** 명령어가 소비한 컴퓨트 유닛이
   [`saturating_add`](https://github.com/anza-xyz/agave/blob/v3.1.8/svm/src/message_processor.rs#L53)를 통해
   트랜잭션 총합에 더해집니다.

## 프로그램 캐시

런타임은 검증 및 컴파일된 프로그램을 저장하는 전역
[`ProgramCache`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L677)를 유지합니다.
포크 그래프를 인식하며 배포 가시성 규칙, 퇴출, epoch 경계 재컴파일을 처리합니다.

### 캐시 항목 유형

캐싱된 모든 프로그램은 런타임 동작을 결정하는
[`ProgramCacheEntryType`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L132)을 가집니다:

| 유형                                                                                                              | 설명                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`Loaded`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L147)             | 검증 및 컴파일이 완료되어 실행 준비가 된 프로그램입니다.                                                                                                                                                                                                                                              |
| [`Builtin`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L149)            | validator 바이너리에 컴파일된 네이티브 프로그램(System, Stake, Vote 등). 온체인에 저장되지 않습니다.                                                                                                                                                                                               |
| [`Unloaded`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L145)           | 이전에 검증되었지만 공간 확보를 위해 컴파일된 실행 파일이 메모리에서 퇴출된 프로그램입니다. 사용 통계는 계속 추적됩니다. 재검증 없이 다시 로드할 수 있습니다.                                                                                                                             |
| [`FailedVerification`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L134) | 현재 기능 세트에서 sBPF 검증기를 통과하지 못한 프로그램의 툼스톤입니다. 기능 활성화로 검증 규칙이 변경되면 `Loaded` 상태가 될 수 있습니다.                                                                                                                              |
| [`Closed`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L139)             | 명시적으로 닫혔거나 한 번도 배포되지 않은 프로그램의 툼스톤입니다. 로더에 속하지만 실행 가능한 코드를 포함하지 않는 계정(예: 버퍼 계정)에도 사용됩니다.                                                                                                               |
| [`DelayVisibility`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L141)    | `Loaded` 항목이 존재하지만 아직 유효하지 않을 때(해당 `effective_slot`이 미래인 경우) [`ProgramCacheForTxBatch::find()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L755)가 반환하는 합성 툼스톤입니다. 캐시에 직접 저장되지 않습니다. |

### 가시성 지연

새로 배포되거나 업그레이드된 프로그램은 즉시 유효해지지 않습니다.
[`DELAY_VISIBILITY_SLOT_OFFSET`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L32)
상수는 `1`로, slot N에 배포된 프로그램은 slot N+1에서 유효해집니다. 배포 slot 동안 새 버전을 호출하려는 시도는
_rs`DelayVisibility`_를 반환하며, 런타임은 "Program is not deployed."를 보고합니다.

### 퇴출 정책

캐시는 최대
[`MAX_LOADED_ENTRY_COUNT`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L31)
(512)개의 컴파일된 프로그램 항목을 보유합니다. 한도에 도달하면 가장 적게 사용된
프로그램이 _rs`Unloaded`_ 상태로 퇴출됩니다. 사용량은
[`tx_usage_counter`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L197)
(트랜잭션이 프로그램을 참조할 때마다 증가)와
[`latest_access_slot`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L199)으로 추적됩니다.

### Epoch 경계 재컴파일

기능 활성화로 epoch 경계에서
[`ProgramRuntimeEnvironments`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L529)가
변경되면, 캐싱된 모든 프로그램이 새 환경에 맞게
[재컴파일](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank.rs#L1494)됩니다.

## 반환 데이터

프로그램은 `sol_set_return_data` 시스콜을 통해 반환 데이터를 설정할 수 있습니다. 데이터는 데이터 바이트와 해당 시스콜을 호출한 명령어의 `program_id`를 보유하는 트랜잭션 수준의
[`TransactionReturnData`](https://github.com/anza-xyz/agave/blob/v3.1.8/transaction-context/src/lib.rs#L499)
구조체에 저장됩니다. 최대 크기는 1,024바이트(_rs`MAX_RETURN_DATA`_)입니다.
