# Solana에서 LLM 및 에이전트 사용하기

특정 도구를 살펴보기 전에, AI
개발 스택의 핵심 구성 요소를 이해해 보겠습니다.

## AI 스택 이해하기

1. **대규모 언어 모델(LLM)**
   - 기반이 되는 AI 모델(예: GPT-4, Claude 또는 Llama)
   - 자연어를 처리하고 생성합니다
   - 원천 지능과 추론 기능을 제공합니다
   - 예: OpenAI의 GPT-4, Anthropic의 Claude, Meta의 Llama

2. **에이전트 프레임워크(예: Eliza)**
   - LLM 위에 구축되어 자율 에이전트를 만듭니다
   - 에이전트의 성격과 동작을 관리합니다
   - 메모리와 컨텍스트를 처리합니다
   - 멀티 플랫폼 통합을 제공합니다
   - 예: Eliza, LangChain, AutoGPT, Vercel AI

3. **도메인 특화 에이전트 키트(예: Solana Agent Kit)**
   - 특정 사용 사례(예: 블록체인 작업)를 위해 구축됩니다
   - 사전 구축된 도구와 통합을 제공합니다
   - 기술적 복잡성을 추상화합니다
   - 바로 사용할 수 있는 블록체인 기능을 제공합니다
   - 예: Solana Agent Kit, GOAT Toolkit

다음과 같이 생각하면 됩니다.

- LLM은 언어를 이해하고 생성할 수 있는 "두뇌"입니다
- 에이전트 프레임워크는 AI의 동작을 관리하는 "운영체제"입니다
- 도메인 특화 키트는 AI에 특정 기능을 제공하는 "앱"입니다

## Solana의 AI 에이전트 소개

Solana의 AI 에이전트는 자연어 처리와 머신러닝을 사용해
블록체인과 상호작용할 수 있는 자율 프로그램입니다. 다음을 수행할 수 있습니다.

- 트랜잭션 실행
- 블록체인 활동 모니터링
- 스마트 계약과 상호작용
- 사용자 지원 제공
- 복잡한 워크플로 자동화

## 사용 가능한 프레임워크

Solana에서 AI 에이전트를 구축하는 데 사용할 수 있는 프레임워크는 여러 가지입니다.

1. **SendAI의 Solana Agent Kit**

- Solana에서 에이전트를 구축하기 위한 도구 모음
- Eliza, Langchain, Vercel AI SDK와 호환
- 내장 Solana 도구 및 유틸리티
- 자연어 처리 기능
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [문서](https://docs.solanaagentkit.xyz/)

2. **Eliza Framework**

- 데이터 레이어, LLM, 에이전트를 결합하며 전용 Solana 플러그인을 제공합니다
- 확장 가능한 에이전트 아키텍처
- 기존 프로젝트와 쉽게 통합할 수 있으며, 예를 들어
  Twitter(X), Telegram 또는 Discord 봇에 사용할 수 있습니다
- [GitHub 저장소](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- 종합 개발 툴킷
- 크로스체인 호환성
- [GitHub 저장소](https://github.com/goat-sdk/goat)

4. **Rig Framework**

- 네이티브 Rust 구현
- 고성능 트레이딩 봇에 적합
- Solana 통합 트랜잭션
  모니터링과 Jito 번들을 사용한 트랜잭션 전송 등을 위해 Listen.rs 툴킷과 결합할 수 있습니다
- [GitHub 저장소](https://github.com/0xPlaygrounds/rig)
- [Listen.rs 저장소](https://github.com/piotrostr/listen)

AI 프레임워크를 구축 중이라면 자유롭게 PR을 열어 목록에 프레임워크를 추가해 주세요

### 에이전트 스크립트 만들기

다음 내용으로 `agent.ts`라는 새 파일을 만드세요.

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## Eliza Framework로 구축하기

[ElizaOS](https://github.com/elizaOS/eliza)(이전 명칭 Ai16z)는
AI 프레임워크입니다. 즉, 여러 애플리케이션을 하나로 결합하고
그 상호작용을 정리합니다. 다음을 결합합니다.

1. 사용자를 이해하기 위한 다양한 LLM
2. 다양한 액션을 가진 블록체인 에이전트(예: NFT 민팅)
3. 예를 들어 Redis, PostgreSQL DB 또는 로컬 스토리지를 사용해 액션 간 캐릭터 상태를 저장하는
   데이터 레이어
4. X, Telegram, Discord 등 다양한 클라이언트

ElizaOS는 이러한 모든 요소를 가져와 함께 조합함으로써 사용자와 상호작용하거나 자율적으로 동작할 수 있는
"Character"를 만들 수 있게 해줍니다. 이러한 Character는 JSON 파일에 정의되며, 여기에는 수행할 수 있는 액션, 사용할 LLM,
그리고 캐릭터의 동작을 정의하는 다양한 프롬프트가 포함됩니다.

### 개인 키 인코딩(필요한 경우)

개인 키가 hex 형식이라면 다음 js 스니펫을 사용해 개인 키를 base58로 인코딩할 수 있습니다.

```ts filename=encode58.ts
const bs58 = require('bs58');
console.log(bs58.encode(new Uint8Array([213,29,143,...])));
```

그리고 다음으로 실행합니다.

```bash
npx tsx encode58.ts
```

### 캐릭터 구성 만들기

새 캐릭터를 만들려면 character.json 파일을 만들어야 합니다. 사전 설정된 캐릭터는 Eliza 프로젝트의 characters 폴더에서 찾을 수 있습니다. 새
캐릭터를 만들려면 기존 캐릭터 중 하나를 복사해 수정하거나,
[Cursor의 composer 기능](https://docs.cursor.com/composer/overview)을 사용해
어떤 종류의 캐릭터를 만들고 싶은지 지시할 수 있습니다.

```json filename=characters/sol.character.json
{
    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },
        ...
```

여기서 중요한 부분은 clients와 modelProvider입니다. 우리의 경우 `.env` 파일에 설정한 비밀 값과 맞추기 위해
클라이언트로 twitter를, 모델 제공자로 openai를 사용하려고 합니다.

```bash
pnpm start --character="characters/sol.character.json"
```

그러면 에이전트가 시작되고 이제 twitter에서 상호작용할 수 있습니다. 캐릭터는 몇 시간마다 자동으로 트윗을 게시하기 시작하며,
우리가 상호작용하면 예를 들어 NFT 민팅 같은 solana 액션을 수행할 수 있습니다.

여기에서
[동작 중인 캐릭터](https://x.com/solanadevhelper/status/1882222232656847143)를 볼 수 있습니다.

다음 명령을 사용해 로컬에서도 캐릭터와 상호작용할 수 있습니다.
포트 3000을 비우고 `--host`
플래그로 캐릭터를 시작해야 할 수도 있습니다.

```bash
pnpm start --character="characters/sol.character.json" --host
pnpm start:client
```

클라이언트가 연결되지 않으면 `--host`
플래그로 에이전트를 실행하고, 클라이언트를 시작할 때 포트 3000이 사용 중이 아닌지 확인하세요.

자세한 내용은
[공식 eliza 문서](https://elizaos.github.io/eliza/docs/quickstart/)를 참고하세요

</Steps>

면책 조항: Solana 통합과 액션은 아직 완벽하지 않지만
지속적으로 개발 중이며 빠르게 발전하고 있습니다. 곧 SendAI agent kit가 Eliza에 직접 통합될 예정입니다.

## 온체인 프로그램 에이전트 통합

Solana 프로그램 내에서 에이전트의 응답을 사용하려면, 응답 데이터를 프로그램이 읽을 수 있는 계정에 기록하는
오라클을 사용해야 합니다. 질문에 올바르게 답한 사용자에게 토큰을 전송하는
LLM 예제는 여기에서 확인할 수 있습니다:

[온체인 프로그램 LLM 상호작용](https://github.com/GabrielePicco/super-smart-contracts)

이것은 LLM(AI) 오라클과 통합하여 "Mar1o"라는 이름의 인터랙티브 토큰 지급 에이전트를 생성하는
온체인 프로그램의 예제입니다.

### 주요 기능

1. **AI 에이전트 상호작용**
   - 사용자는 Mar1o와 채팅하여 토큰을 획득할 수 있습니다
   - 에이전트는 사용자의 Solana 지식을 평가하여 토큰 수량을 결정합니다
   - 응답은 답변 텍스트와 토큰 수량이 포함된 JSON 형식으로 제공됩니다

2. **토큰 관리**
   - 메타데이터와 함께 MAR1O 토큰을 생성합니다
   - AI 응답에 따라 0~10,000개의 토큰을 발행할 수 있습니다
   - 토큰 관리를 위해 PDA를 사용합니다

### 프로그램 흐름 설명

이 프로그램의 작동 방식은 다음과 같습니다:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

이는 AI 기능과 온체인 토큰 메커니즘을 결합하여 인터랙티브한 블록체인 경험을 만드는 방법을 보여줍니다.
에이전트에게 토큰 전송을 요청해볼 수 있는
[라이브 예제](https://mar1o.xyz/)가 여기에 있습니다.

## 알고리즘 트레이딩을 위한 고급 Rust 에이전트

Rust로 에이전트를 작성하려면
[Rig 프레임워크](https://github.com/0xPlaygrounds/rig)와
[Listen.rs](https://github.com/piotrostr/listen) 라이브러리를 사용할 수 있습니다.

이 두 가지는 함께 사용하면 매우 효과적입니다. Rig 프레임워크는 LLM에 손쉽게 연결할 수 있는 방법을 제공하고,
Listen.rs 툴킷은 트랜잭션 모니터링 및 예를 들어 Jito 번들을 사용한 트랜잭션 전송을 포함한
Solana 통합 기능을 제공합니다.

## 모범 사례

- 에이전트는 개인 키를 보유하고 있으므로 지갑의 자금에 접근할 수 있다는 점을 인지하세요.
에이전트가 전송 액션을 갖고 있는 경우, 채팅을 통해 사용자가
자금을 전송하도록 유도할 수 있습니다.
- 유료 [RPC 엔드포인트](https://solana.com/rpc)를 사용하세요. 퍼블릭 엔드포인트는
일반적으로 속도 제한이 적용됩니다
- 에이전트의 활동을 모니터링하고, 악의적인 행동을 하거나
사용자와의 상호작용을 통해 속임을 당하지 않도록 확인하세요
- 네트워크 혼잡 시에도 에이전트 액션이 처리될 수 있도록
우선순위 수수료 및 트랜잭션 재시도 기능을 구현하세요
- 가능하면 메인넷에 배포하기 전에 먼저 devnet에서 테스트하세요. 대부분의 에이전트는
RPC URL을 입력으로 받으므로, 메인넷 준비가 완료될 때까지 devnet URL을 사용할 수 있습니다.
단, 일부 액션은 devnet에서 실행이 불가능할 수 있습니다.
- 직접 액션을 작성할 때는 통합 테스트를 추가하여
프로그램이나 API 변경으로 인해 실패하는 액션을 프레임워크가 모니터링할 수 있도록 하세요

## 결론

Solana의 AI 에이전트는 블록체인과의 자동화 및 상호작용에 새로운 가능성을 열어줍니다.
모든 통합이 아직 완벽하지는 않지만, 빠르게 발전하고 있으며 기여할 수 있는 기회가 많고
자체 통합을 추가하는 데 매우 유연합니다.
