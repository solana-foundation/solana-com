2.0.0은 Go 모듈의 첫 안정 릴리스이므로 마이그레이션할 내용이 없습니다. [2.0 마이그레이션 가이드](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)에서는 Rust와 TypeScript에 대한 동일한 기능 분리를 다룹니다.

## 설치

모든 백엔드는 각자 별개의 Go 모듈이므로, 빌드와 모듈 그래프에는 직접 import한 백엔드만 포함됩니다:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

모듈은 `go/<module>/v2.0.0` 형식으로 태그가 지정됩니다(예: `go/signers/memory/v2.0.0`). 모든 모듈은 Go 1.25.0이 필요하지만, `gcpkms`는 `google.golang.org/api`가 정한 최소 버전 때문에 Go 1.25.8이 필요합니다. Ledger는 Rust 전용이며 Go 모듈이 없습니다.

### solana-go v2와 v1 트랜잭션

이 모듈들은 [`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go) v2.0.0을 기반으로 하며 `*solana.Transaction`을 받습니다. 레거시, v0, v1(`solana.MessageVersionV1`) 트랜잭션을 지원합니다. 단, `UseProgramCall: true`를 사용하는 Fireblocks는 레거시와 v0만 허용합니다.

## 기본 사용법

모든 서명자(signer)는 기본 [`core.SolanaSigner` 인터페이스](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)(`Pubkey`, `SignMessage`, `IsAvailable`)를 구현합니다. 메서드는 `context.Context`를 받으며 블로킹 방식으로 동작합니다. 또한 각 백엔드는 다음 기능 인터페이스 중 정확히 하나를 구현합니다:

- `core.TransactionSigner`: `SignTransaction`은 주어진 트랜잭션을 그대로 서명합니다.
- `core.ModifyingSigner`: `ModifyAndSignTransaction`은 공급자가 트랜잭션을 재작성한 뒤 서명하도록 합니다.
- `core.SendingSigner`: `SignAndSendTransaction`은 공급자가 서명하고 브로드캐스트하도록 합니다.

각 백엔드 패키지는 `Config` 구조체와 `New` 생성자를 제공합니다:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction`과 `ModifyAndSignTransaction`은 `core.SignedTransaction`(`EncodedTransaction`, `Signature`, `Completeness`)을 반환합니다. 원격 HTTP 백엔드는 선택적으로 `HTTPClient`와 `HTTPClientConfig`(타임아웃)를 받습니다. 기본 클라이언트는 HTTPS를 강제하며, 직접 제공한 클라이언트는 이를 우회하므로 해당 클라이언트의 보안 상태는 사용자가 책임져야 합니다.

### 서명자 기능

트랜잭션에 서명할 수 없는 백엔드에는 `SignTransaction` 메서드가 아예 없으므로, 구체 타입의 경우 기능 여부는 컴파일 타임에 확정되고 `core.SolanaSigner`의 경우 타입 단언(type assertion)으로 확인합니다:

| 백엔드                                                                         | 기능          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | 예                            |
| cdp                                                                             | `TransactionSigner` | UTF-8 페이로드만 지원            |
| utila                                                                           | `TransactionSigner` | `CodeSigningFailed`와 함께 실패 |
| fordefi 블랙박스(`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | 예                            |
| fordefi 네이티브 수동(`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | 예                            |
| fordefi 네이티브 자동(`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | 예                            |
| crossmint                                                                       | `SendingSigner`     | `CodeSigningFailed`와 함께 실패 |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### 초기화

별도의 `Init` 단계는 없습니다. Privy, Fireblocks, Dfns, Crossmint, Para, Openfort, Utila는 `New` 내부에서 지갑 주소를 확인하며, 그래서 생성자가 `context.Context`를 받습니다. 서명자는 항상 `New`로 생성하세요. 제로 값 Crossmint, Para 또는 Utila 서명자는 제로 주소로 서명하는 대신 `CodeNotInitialized`와 함께 실패합니다.

### 모든 서명자로 서명 및 전송하기

`core.SignAndSendTransaction`은 서명자의 형태와 관계없이 트랜잭션을 온체인에 반영합니다. `SendingSigner`는 공급자를 통해 브로드캐스트하며 전송 함수는 무시합니다. 그 외의 모든 형태는 서명만 하고, base64 결과를 사용자의 함수가 브로드캐스트합니다. `ModifyingSigner`의 경우 이 결과는 공급자가 재작성한 트랜잭션입니다. Core는 RPC 의존성이 없습니다:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### 일괄 서명

일괄 서명은 독립 헬퍼 함수로 제공되며 동시에 실행됩니다. 속도 제한이 있는 API를 위해 요청별 시차(stagger)를 선택적으로 둘 수 있습니다:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions`는 `core.TransactionSigner`를 받으므로, 브로드캐스트를 자체 관리하는 서명자(Crossmint, Fordefi native auto)와 Fordefi native manual은 이를 통해 일괄 처리할 수 없습니다. 이들은 한 번에 하나의 트랜잭션씩 호출하세요. 호출 시 공급자 측 작업이 생성되는 서명자(`UseProgramCall`을 사용하는 Fireblocks)는 `core.BatchServerSideEffects`를 통해 이를 알리며, 이 경우 일괄 처리는 순차적으로 실행됩니다.

## 백엔드 구성

### Memory

`PrivateKey`(원시 바이트), `PrivateKeyString`(base58 또는 `[1,2,...]` 바이트 배열), `PrivateKeyPath`(Solana CLI keypair 파일) 중 정확히 하나를 제공하세요:

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Go에는 메모리를 확실하게 0으로 지우는 방법이 없습니다. 가비지 컬렉터가 수집 전까지 키 바이트를 복사하고 보관할 수 있습니다(메모리 keypair, 그리고 Crossmint와 Openfort가 로컬에서 파생하는 키). 로컬 키 백엔드를 사용할 때는 프로세스 전체 메모리를 민감한 정보로 취급하세요.

import "github.com/solana-foundation/solana-keychain/go/signers/vault/v2"

signer, err := vault.New(vault.Config{

### Crossmint

Crossmint는 전송 전용입니다. Crossmint API가 승인된 모든 트랜잭션을 서버 측에서 실행하므로 `*crossmint.Signer`에는 `SignAndSendTransaction`만 있고 `SignTransaction`은 없습니다. 트랜잭션은 수정되지 않으며, 반환된 서명은 Crossmint가 실제로 반영한 트랜잭션을 식별합니다. Crossmint가 가스비를 대납하는 경우 사용자의 트랜잭션과 다를 수 있습니다.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Fordefi

Fordefi는 세 가지 서명자 유형으로 제공되며, `Config.Chain`과 `Config.PushMode`에 의해 생성 시점에 결정됩니다. 세 가지 모두 메시지에 서명할 수 있습니다:

| 구성                                          | 유형                          | 진입점                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` 미설정                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` 설정, `PushMode` 미설정 또는 `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` 설정, `PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New`는 구성에 따라 분기하여 `core.SolanaSigner`를 반환하고, `fordefi.NewBlackBox`, `fordefi.NewNativeAuto`, `fordefi.NewNativeManual`은 구체 타입을 반환하며 다른 모드의 구성은 거부합니다. API 요청은 ECDSA P-256 요청 서명으로 인증됩니다. `PrivateKeyPEM` 또는 키를 KMS/HSM에 보관하기 위한 `RequestSigner` 중 정확히 하나를 제공하세요.

**네이티브 자동 모드**: Fordefi가 블록해시와 수수료를 교체한 뒤 서명하고 브로드캐스트할 수 있습니다. 필수 서명자가 볼트뿐인 서명되지 않은 트랜잭션만 허용합니다.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**네이티브 수동 모드**: `PushMode: fordefi.PushModeManual`로 설정합니다. Fordefi가 메시지(최근 블록해시, Compute Budget 수수료 명령)를 재작성하고, 브로드캐스트 없이 서명합니다. `ModifyAndSignTransaction`은 `tx`를 Fordefi가 서명한 트랜잭션으로 교체하므로 항상 그 트랜잭션에서 이어서 진행하세요. 재작성하면 기존 서명이 무효화되므로 Fordefi가 수수료 지불자여야 하며 다른 필수 서명자보다 먼저 서명해야 합니다. 재작성 내용은 diff로 제공되지 않으므로 브로드캐스트 전에 결과를 확인하세요.

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**블랙박스 모드**: `Chain`을 설정하지 않습니다. Fordefi는 사용자가 제공한 메시지 바이트 그대로 서명하며 브로드캐스트하지 않습니다. Fordefi 블랙박스 볼트와 함께 사용하세요.

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## 통합(umbrella) 패키지가 없는 이유

Rust에는 `Signer` enum이, TypeScript에는 `createKeychainSigner`가 있지만 Go에는 의도적으로 둘 다 없습니다. Go는 런타임 디스패치 switch 전반에 걸쳐 죽은 코드를 제거하지 않기 때문에, 통합 패키지를 두면 모든 백엔드의 벤더 SDK(AWS, GCP 등)가 모든 사용자의 빌드에 포함됩니다. 필요한 백엔드 패키지를 import하는 것이 곧 선택 방법입니다. 런타임에 백엔드를 고르려면 지원하는 백엔드만 대상으로 직접 switch를 작성하고, 결과를 `core.SolanaSigner`로 보관하세요.

## 오류 처리

모든 오류는 안정적인 `Code`(`CodeConfigError`, `CodeHTTPError`, `CodeRemoteAPIError`, `CodeSigningFailed`, `CodeNotInitialized`, `CodeBroadcastUnconfirmed` 등)를 가진 `*core.SignerError`입니다. `Error()`는 코드별로 고정된 메시지만 반환하며, 키 자료나 공급자의 원본 응답은 절대 포함하지 않습니다. `errors.As`, `errors.Is(err, &core.SignerError{Code: ...})` 또는 `core.CodeOf(err)`로 매칭하세요.

Crossmint와 Fordefi 네이티브 자동 모드에서는 실패했다고 해서 아무것도 반영되지 않았다는 뜻이 아닙니다. 공급자가 트랜잭션을 수락했을 수 있는 경우 코드는 `core.CodeBroadcastUnconfirmed`(`"SIGNER_BROADCAST_UNCONFIRMED"`)입니다. 생성 요청이 수락되었다면 `ProviderTxID`가 설정되고, `IdempotencyKey`에는 메시지에서 파생된 키가 담깁니다. 바이트가 완전히 동일한 트랜잭션을 다시 보내는 것은 안전하지만, 다시 구성한 트랜잭션(예: 새 블록해시 사용)은 새로운 전송이 됩니다. `core.SignAndSendTransaction`도 전송 함수가 실패하면 수수료 지불자 서명을 `TransactionSignature`에 담아 이 코드를 보고합니다. Fireblocks PROGRAM_CALL은 서명 전용이며 키를 전송하지 않습니다. 폴링 결과 Fireblocks가 어쨌든 브로드캐스트한 것으로 확인된 경우에만 이 코드를 보고합니다.

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

각 서명 형태가 보장하는 내용은 [보안 모델](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md), 전체 모듈 목록은 [Go README](https://github.com/solana-foundation/solana-keychain/blob/main/go/README.md), API 참조는 [pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2)를 확인하세요.

## 커스텀 서명자 추가하기

`core.SolanaSigner`와 기능 인터페이스 정확히 하나를 구현하고, 백엔드가 지원할 수 없는 메서드는 추가하지 마세요. 호출자는 타입 단언으로 기능을 감지합니다. 추가 키 관리 서비스를 통합하려면 [서명자 추가 가이드](/docs/tools/keychain/adding-signers)를 참조하세요.
