다음 용어들은 Solana 문서와 개발
ecosystem 전반에서 사용됩니다.

## 계정

Solana 원장에 있는 레코드로, 데이터를 보관하거나 실행 가능한
프로그램입니다.

전통적인 은행의 계좌처럼 Solana 계정은
[lamports](#lamport)라고 하는 자금을 보유할 수 있습니다. [cluster](#cluster)의 모든 계정에는 고유한
[주소](#address)가 있습니다.

## 앱

Solana 클러스터와 상호 작용하는 프런트엔드 애플리케이션입니다.

## 주소

계정을 찾는 데 사용할 수 있는 Solana 내 위치입니다. 각 주소는 Solana
[cluster](#cluster)에서 고유합니다.

Solana의 주소는 Ed25519 [공개 키](#public-key-pubkey) 또는
[Program Derived Address](#program-derived-address-pda)일 수 있습니다.

## 주소 조회 테이블(ALT)

계정 주소 목록을 저장하는 데이터 구조로,
[버전 지정 트랜잭션](#versioned-transaction)이 전체 32바이트 공개 키 대신
컴팩트한 1바이트 인덱스를 사용해 계정을 참조할 수 있게 합니다. 주소 조회
테이블을 사용하면 단일 트랜잭션이 원래 트랜잭션 형식에서 허용하는 것보다
더 많은 계정을 참조할 수 있습니다. 버전 0(`v0`) 트랜잭션만 주소
조회 테이블을 지원하며, 버전 1(`v1`)은 동일한 주소를 인라인으로 담을 수 있는 더 큰 트랜잭션
크기를 채택하는 대신 이를 제거합니다.

## Anchor

Rust로 Solana [온체인 프로그램](#onchain-program)을 빌드하기 위한 프레임워크입니다.
Anchor는 보일러플레이트를 줄이는 매크로와 표준화된 계정
검증 시스템을 제공하며, 프로그램의 인터페이스를 설명하는 [IDL](#idl)을 생성합니다.
Solana 프로그램 개발에서 가장 널리 사용되는 프레임워크입니다.

## associated token account (ATA)

지갑 주소와 [토큰 민트](#token-mint)로부터 주소가 결정론적으로 파생되는
[token account](#token-account)입니다. Associated Token Program은 각 지갑이 토큰
type별로 하나의 표준 token account를 갖도록 보장합니다.

## 권한

계정에 대해 어떤 종류의 권한을 가진 사용자의 주소입니다.

예:

- 새 토큰을 민트할 수 있는 능력은 해당 토큰 민트의 '민트
  권한'인 계정에 부여됩니다.
- 프로그램을 업그레이드할 수 있는 능력은 프로그램의 '업그레이드
  권한'인 계정에 부여됩니다.

## 자동화된 마켓 메이커(AMM)

사용자가 상대방의 대기 주문이 아니라 가격 책정 공식에 의해 관리되는 토큰 준비금 풀을 상대로 거래하는 온체인 거래소 모델입니다.
가격은 준비금의 함수로 움직이므로, 거래에는 크기에 비례한
[슬리피지](#slippage)가 발생합니다.

## 뱅크 상태

주어진 [틱 높이](#tick-height)에서 원장상의 모든 프로그램을 해석한 결과입니다.
여기에는 최소한 0이 아닌 [네이티브 토큰](#native-token)을 보유한 모든
[계정](#account) 집합이 포함됩니다.

## 블록

[투표](#ledger-vote)가 적용되는 원장상의 연속적인 [엔트리](#entry) 집합입니다.
[리더](#leader)는 [slot](#slot)당 최대 하나의 블록을 생성합니다.

## 블록해시

레코드(블록)를 식별하는 고유한 값([해시](#hash))입니다. Solana는 블록의 마지막
[엔트리 ID](#entry-id)로부터 블록해시를 계산합니다.

## 블록 높이

현재 블록 아래에 있는 [블록](#block)의 수입니다. [제네시스 블록](#genesis-block) 이후 첫 번째 블록의
높이는 1입니다.

## 부트스트랩 validator

블록체인의 제네시스(첫 번째) [블록](#block)을 생성하는
[validator](#validator)입니다.

## BPF 로더

[BPF](/docs/core/programs)
[온체인 프로그램](#onchain-program)을 소유하고 로드하여 프로그램이 런타임과 인터페이스할 수 있게 하는 Solana 프로그램입니다.

## 범프

[Program Derived Address](#program-derived-address-pda)를 파생할 때 결과
주소가 ed25519 곡선에서 벗어나 유효한 PDA가 되도록 [시드](#seed)에 추가되는
단일 바이트(0–255)입니다. 표준
범프는 유효한 PDA를 생성하는 가장 높은 값이며, 일반적으로
재계산을 피하기 위해 계정 데이터에 저장됩니다.

## 중앙 지정가 주문장(CLOB)

대기 중인 매수호가와 매도호가의 정렬된 목록을 유지하는 거래소 모델입니다. 들어오는 주문이 반대편 주문과 교차할 때
거래가 발생합니다. [자동화된 마켓 메이커](#automated-market-maker-amm)와 대비됩니다.

## 클라이언트

Solana 서버 네트워크 [cluster](#cluster)에 접근하는 컴퓨터 프로그램입니다.

## 커밋먼트

[블록](#block)에 대한 네트워크 확인 정도를 나타내는 척도입니다.

## 컴팩트 배열 형식

컴팩트 배열은 다음 형식으로 직렬화된 배열입니다.

- 배열 길이([compact-u16](https://github.com/anza-xyz/agave/blob/v2.1.13/short-vec/src/lib.rs)으로 인코딩됨)
- 배열 항목이 차례로 나열됨

![컴팩트 배열 형식](/assets/docs/core/transactions/compact_array_format.png)

컴팩트 배열 형식은 트랜잭션 메시지에서
[계정 주소](/docs/core/transactions/transaction-structure#account-addresses)
배열과
[명령](/docs/core/transactions/transaction-structure#instructions) 배열을 모두
인코딩하는 데 사용됩니다.

## 클러스터

단일 [원장](#ledger)을 유지하는 [validators](#validator)의 집합입니다.

## 컴퓨트 예산

트랜잭션당 소비되는 [컴퓨트 유닛](#compute-units)의 최대 수입니다.

## 컴퓨트 유닛

블록체인의 계산 리소스 소비를 측정하는 가장 작은 단위입니다.
컴퓨트 유닛은 트랜잭션 처리에 사용된 계산 리소스를 측정하는 데 사용됩니다.

## 확인 시간

[리더](#leader)가 [틱 엔트리](#tick)를 생성한 시점부터 [확인된 블록](#confirmed-block)을 생성할 때까지의
실제 경과 시간입니다.

## 확인된 블록

[원장 투표](#ledger-vote)의 [초다수](#supermajority)를 받은
[블록](#block)입니다.

## 컨트롤 플레인

[cluster](#cluster)의 모든 [노드](#node)를 연결하는 가십 네트워크입니다.

## 쿨다운 기간

[스테이크](#stake)가 비활성화된 후, 출금 가능 상태로 점진적으로 전환되는 동안의 일정 수의 [epochs](#epoch)입니다.
이 기간 동안 스테이크는 "비활성화 중"으로 간주됩니다. 자세한 정보:
[워밍업 및 쿨다운](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)

## 비용 유닛

`트랜잭션 비용`이라고도 하며, 트랜잭션을 처리하는 데 필요한 모든
리소스를 [컴퓨트 유닛](#compute-units)으로 측정한 종합적인 추정치입니다. 자세한 정보는
[여기](https://www.anza.xyz/blog/why-solana-transaction-costs-and-compute-units-matter-for-developers)를 참조하세요.

## Cross Program Invocation (CPI)

## 데이터 플레인

## 드론

사용자의 개인 키에 대한 수탁자 역할을 하는 오프체인 서비스입니다. 일반적으로 트랜잭션을 검증하고 서명하는 데 사용됩니다.

## 엔트리

[원장](#ledger)상의 엔트리는 [틱](#tick) 또는
[트랜잭션의 엔트리](#transactions-entry)입니다.

## 엔트리 ID

엔트리의 최종 내용에 대한 프리이미지 저항성을 가진 [해시](#hash)로,
[엔트리](#entry)의 전역 고유 식별자 역할을 합니다. 이 해시는 다음의 증거로 사용됩니다.

- 해당 엔트리가 일정 시간이 지난 후 생성되었다는 것
- 지정된 [트랜잭션](#transaction)들이 해당 엔트리에 포함된 트랜잭션이라는 것
- [원장](#ledger)의 다른 엔트리와 관련한 해당 엔트리의 위치

[기록 증명](#proof-of-history-poh)을 참조하세요.

## epoch

[리더 스케줄](#leader-schedule)이 유효한 시간, 즉 [slots](#slot)의 수입니다.

## 에스크로

[온체인 프로그램](#onchain-program)이 둘 이상의 당사자를 대신해 토큰을 [볼트](#vault)에 보관하고,
프로그램이 정의한 조건이 충족되면 이를 해제하는 패턴입니다. 당사자들이 서로를 직접 신뢰할 필요를 없애는 데 사용됩니다.

## 수수료 계정

트랜잭션의 수수료 계정은 해당 트랜잭션을 원장에 포함시키는 비용을 지불하는 계정입니다.
이는 트랜잭션의 첫 번째 계정입니다. 트랜잭션 비용을 지불하면 계정 잔액이 줄어들기 때문에,
이 계정은 트랜잭션에서 읽기-쓰기(쓰기 가능)로 선언되어야 합니다.

## 내부 명령

[Cross Program Invocation](#cross-program-invocation-cpi)을 참조하세요.

## 명령

[프로그램](#program)의 특정 [명령 핸들러](#instruction-handler)를 호출하기 위한 요청입니다. 명령은 또한 읽거나 수정하려는 계정과,
[명령 핸들러](#instruction-handler)에 대한 보조 입력으로 사용되는 추가 데이터를 지정합니다. [클라이언트](#client)는
[트랜잭션](#transaction)에 최소 하나의 명령을 포함해야 하며, 트랜잭션이 성공한 것으로 간주되려면 모든 명령이
완료되어야 합니다.

## 명령 핸들러

명령 핸들러는 [트랜잭션](#transaction)의 [명령](#instruction)을 처리하는 [프로그램](#program) 함수입니다.
명령 핸들러는 하나 이상의
[Cross Program Invocation](#cross-program-invocation-cpi)을 포함할 수 있습니다.

## IDL

Interface Definition Language입니다. [Anchor](#anchor)가 생성하는 JSON 파일로,
프로그램의 [명령 핸들러](#instruction-handler), 계정 및 타입을 설명합니다.
IDL을 통해 클라이언트 라이브러리는 [온체인 프로그램](#onchain-program)과 상호 작용하기 위한 타입 지정
인터페이스를 자동으로 생성할 수 있습니다.

## keypair

계정에 접근하기 위한 [공개 키](#public-key-pubkey)와 그에 대응하는 [개인 키](#private-key)입니다.

0.000000001 [SOL](#sol)의 값을 갖는 분수 단위의

> 의 수량은 [우선순위 수수료](#prioritization-fee) 계산에 사용됩니다.

## 리더

[원장](#ledger)에 [엔트리](#entry)를 추가할 때의 [validator](#validator) 역할입니다.

## 리더 스케줄

[slots](#slot)에 매핑된 [validator](#validator) [공개 키](#public-key-pubkey)의 시퀀스입니다.
클러스터는 리더 스케줄을 사용해 특정 시점에 어떤 validator가 [리더](#leader)인지 결정합니다.

## 원장

[클라이언트](#client)가 서명한 [트랜잭션](#transaction)을 포함하는 [엔트리](#entry) 목록입니다.
개념적으로 이는 [제네시스 블록](#genesis-block)까지 거슬러 올라갈 수 있지만, 실제 [validator](#validator)의 원장은
저장 공간을 줄이기 위해 더 최신 [블록](#block)만 가질 수 있습니다. 설계상 이전 블록은
향후 블록 검증에 필요하지 않기 때문입니다.

## 원장 투표

주어진 [틱 높이](#tick-height)에서의 [validator 상태](#bank-state)에 대한 [해시](#hash)입니다.
이는 수신한 [블록](#block)이 검증되었다는 [validator](#validator)의 확인과,
특정 시간인 [락아웃](#lockout) 기간 동안 충돌하는 [블록](#block) \(즉, [포크](#fork)\)에
투표하지 않겠다는 약속으로 구성됩니다.

## 라이트 클라이언트

유효한
[클러스터](#cluster)를 가리키고 있는지 확인할 수 있는 [클라이언트](#client)의 한 유형입니다. [씬 클라이언트](#thin-client)보다는 더 많은 원장 검증을 수행하고, [validator](#validator)보다는 적게 수행합니다.

## 유동성

현재 가격 또는 그 근처에서 거래 상대가 될 수 있는 주문의 깊이 또는 풀링된 준비금입니다. 유동성이 깊을수록 [슬리피지](#slippage)가 줄어듭니다. [CLOB](#central-limit-order-book-clob)에서는 [메이커 주문](#maker)이 유동성을 공급하고, [AMM](#automated-market-maker-amm)에서는 토큰 쌍을 풀에 예치하는 유동성 공급자가 유동성을 공급합니다.

## 로더

다른 [온체인 프로그램](#onchain-program)의 바이너리 인코딩을 해석할 수 있는 [프로그램](#program)입니다.

## 락아웃

[validator](#validator)가 다른 [포크](#fork)에 [투표](#ledger-vote)할 수 없는 시간의 기간입니다.

## 메이커

반대편 주문과 즉시 체결되지 않고 오더북에 대기함으로써 [CLOB](#central-limit-order-book-clob)에 [유동성](#liquidity)을 추가하는 주문을 내는 트레이더입니다. 이러한 주문을 메이커 주문이라고 합니다. 메이커는 일반적으로 수수료를 내지 않거나 거래소로부터 리베이트를 받습니다.

## 마켓 메이커

매수호가와 매도호가를 지속적으로 게시하여 [유동성](#liquidity)을 공급하는 주체입니다. Solana에서 마켓 메이커는 [AMM](#automated-market-maker-amm)과 같은 프로그램이거나, 봇을 운영하여 [CLOB](#central-limit-order-book-clob)에 [메이커 주문](#maker)을 게시하는 오프체인 업체입니다.

## 메시지

여기에서 [트랜잭션 내부의 메시지 형식](/docs/core/transactions/transaction-structure#header)에 대해 자세히 알아보세요.

## Proof of History(PoH)

각각 특정 데이터가 해당 증명이 생성되기 전에 존재했으며 이전 증명 이후 정확한 시간이 경과했음을 증명하는 증명들의 스택입니다. [VDF](#verifiable-delay-function-vdf)와 마찬가지로 Proof of History는 생성에 걸린 시간보다 짧은 시간 안에 검증할 수 있습니다.

## 우선순위 수수료

사용자가 자신의 [트랜잭션](#transaction)에 우선순위를 부여하기 위해 컴퓨트 예산 [명령](#instruction)에서 지정할 수 있는 추가 수수료입니다.

우선순위 수수료는 요청한 최대 컴퓨트 유닛 수에 컴퓨트 유닛 가격(컴퓨트 유닛당 0.000001 [lamport](#lamport) 단위로 지정)을 곱한 뒤 가장 가까운 [lamport](#lamport)로 올림하여 계산합니다.

수수료를 최소화하려면 트랜잭션은 실행에 필요한 최소한의 컴퓨트 유닛만 요청해야 합니다.

## 루트

## seed

[Program Derived Address](#program-derived-address-pda)를 파생할 때 입력으로 사용되는 바이트 값 또는 바이트 값 배열입니다. 프로그램은 정적 문자열, 공개 키 또는 기타 데이터의 임의 조합을 seed로 사용할 수 있습니다. seed는 프로그램의 ID 및 [범프](#bump)와 결합되어 고유한 PDA 주소를 생성합니다.

## 슈레드

[블록](#block)의 일부이며, [validator](#validator) 간에 전송되는 가장 작은 단위입니다.

## 서명

R(32바이트)과 S(32바이트)로 구성된 64바이트 ed25519 서명입니다. R은 작은 차수가 아닌 압축된 Edwards 점이어야 하고, S는 `0 <= S < L` 범위의 스칼라여야 합니다. 이 요구 사항은 서명 가변성을 방지합니다. 각 트랜잭션에는 [수수료 계정](#fee-account)에 대한 서명이 최소 하나 있어야 합니다. 따라서 트랜잭션의 첫 번째 서명은 [트랜잭션 ID](#transaction-id)로 취급할 수 있습니다.

## 서명자

[명령](#instruction) 또는 [트랜잭션](#transaction)을 승인한 [계정](#account)입니다. 일반적인 [keypair](#keypair)의 경우 이는 트랜잭션에 대한 암호학적 [서명](#signature)을 의미합니다. [Program Derived Address](#program-derived-address-pda)의 경우 PDA에는 프라이빗 키가 없으므로, 해당 [소유 프로그램](#owning-program)이 [Cross Program Invocation](#cross-program-invocation-cpi)을 수행할 때 승인이 확인됩니다.

## 스킵률

현재 epoch의 전체 리더 slot 중 [스킵된 slot](#skipped-slot)이 차지하는 비율입니다. 이 지표는 epoch 경계 직후 표본 크기가 작을 때와 리더 slot 수가 적은 validator의 경우 변동성이 커서 오해를 불러일으킬 수 있지만, 때로는 노드 구성 오류를 식별하는 데 유용할 수도 있습니다.

## 스킵된 slot

리더가 오프라인이었거나 해당 slot을 포함한 [포크](#fork)가 클러스터 합의에 의해 더 나은 대안으로 폐기되어 [블록](#block)을 생성하지 못한 과거의 [slot](#slot)입니다. 스킵된 slot은 이후 slot의 블록에 대한 조상으로 나타나지 않으며, [블록 높이](#block-height)를 증가시키지도 않고, 가장 오래된 `recent_blockhash`를 만료시키지도 않습니다.

slot이 스킵되었는지는 최신 [루트 처리된](#root)(따라서 스킵되지 않은) slot보다 더 오래된 후에만 확인할 수 있습니다.

## 슬리피지

트레이더가 예상한 가격과 실제로 거래가 체결된 가격의 차이입니다. [AMM](#automated-market-maker-amm)에서는 준비금이 변하면서 가격 곡선이 이동하기 때문에 발생하고, [CLOB](#central-limit-order-book-clob)에서는 하나의 주문이 점점 더 불리한 가격의 여러 대기 주문을 소비하기 때문에 발생합니다.

## slot

각 [리더](#leader)가 트랜잭션을 수집하고 [블록](#block)을 생성하는 시간 기간입니다.

slot은 집합적으로 논리적 시계를 만듭니다. slot은 순차적으로 정렬되고 서로 겹치지 않으며, [PoH](#proof-of-history-poh)에 따라 실제 세계의 시간으로는 대략 동일한 길이로 구성됩니다.

토큰을 생성(또는 '민팅')할 수 있는 계정입니다. 서로 다른 토큰은
고유한 토큰 민트 주소로 구분됩니다.

## Token Program

ID `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA`를 가지며, 토큰의 전송,
동결, 민팅이라는 기본 기능을 제공합니다.

## tps

초당 [트랜잭션](#transaction) 수입니다.

## tpu

[트랜잭션 처리 유닛](https://docs.anza.xyz/validator/tpu)입니다.

## 트랜잭션

하나 이상의 [keypair](#keypair)를 사용해 [클라이언트](#client)가 서명하고,
성공 또는 실패라는 두 가지 결과 중 하나만 가능하도록 원자적으로 실행되는
하나 이상의 [명령](#instruction)입니다.

## 트랜잭션 ID

[트랜잭션](#transaction)의 첫 번째 [서명](#signature)으로, 전체 [원장](#ledger)에서
해당 트랜잭션을 고유하게 식별하는 데 사용할 수 있습니다.

## 트랜잭션 확인

트랜잭션이 [원장](#ledger)에 수락된 이후의 [확정된 블록](#confirmed-block) 수입니다.
트랜잭션은 해당 블록이 [루트](#root)가 되면 최종 확정됩니다.

## 트랜잭션 엔트리

병렬로 실행될 수 있는 [트랜잭션](#transaction) 집합입니다.

## tvu

[트랜잭션 검증 유닛](https://docs.anza.xyz/validator/tvu)입니다.

## validator

새 [블록](#block)을 생성하는 Solana 네트워크 [클러스터](#cluster)의 완전한 참여자입니다.
validator는 [원장](#ledger)에 추가된 트랜잭션을 검증합니다.

## 볼트

사용자를 대신해 풀링된 자산을 보유하는 [온체인 프로그램](#onchain-program) 소유의
[token account](#token-account)입니다. 예를 들어 [AMM](#automated-market-maker-amm)의 베이스 및 쿼트 준비금,
[에스크로](#escrow)에 잠긴 토큰,
또는 [CLOB](#central-limit-order-book-clob)의 대기 잔액과 누적 수수료가 이에 해당합니다.
소유 프로그램만 볼트에서 토큰을 이동할 수 있으며,
일반적으로 거래 또는 해제 조건이 충족되면 사용자의 자체 [token account](#token-account)로 이동합니다.

## 검증 가능한 지연 함수(VDF)

실행하는 데 고정된 시간이 걸리고, 실행되었다는 증명을 생성하며,
그 증명은 생성에 걸린 시간보다 더 짧은 시간에 검증할 수 있는 함수입니다.

## 버전 지정 트랜잭션

기존 [트랜잭션](#transaction) 형식을 넘어서는 추가 기능을 지원하는 트랜잭션 형식입니다.
버전 0(`v0`)은 최초의 버전 지정 형식으로 [주소 조회 테이블](#address-lookup-table-alt) 지원을 추가하여,
트랜잭션이 기존 형식에서 허용하는 것보다 더 많은 계정을 참조할 수 있게 합니다.
모든 클러스터에서 활성화된 버전 1(`v1`)은 최대 트랜잭션 크기를 4,096바이트로 높이고,
ComputeBudget 명령 대신 메시지의 구성 섹션에 리소스 한도를 담으며,
주소 조회 테이블 지원을 제거합니다.
[버전 지정 트랜잭션](/docs/core/transactions/versioned-transactions)을 참조하세요.
