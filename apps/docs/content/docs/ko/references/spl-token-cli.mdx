`spl-token` 명령줄 인터페이스는 민트, token account, 권한, 전송, Token-2022 확장 기능을
생성하고 관리합니다.

이 문서는
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1)을 기준으로 하며,
이는 Agave v4.2.1에 포함된 버전입니다. 설치된 버전에서 사용할 수 있는 정확한 옵션은 `spl-token --version`을 실행하고
`<command> --help`를 사용해 확인하세요.

<Callout type="warn">
  민트 생성, 전송, 권한 변경, 소각, 동결, 계정 폐쇄는 트랜잭션을 제출합니다.
  명령을 실행하기 전에 클러스터, Token Program, 서명자, 주소를 확인하세요.
  메인넷에서의 변경은 실제 자산을 사용합니다.
</Callout>

## 설치 및 도움말 확인

Agave CLI 릴리스 번들에는 `spl-token`이 포함되어 있습니다. 설치되어 있지 않다면
게시된 Rust crate를 사용하세요:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

루트 또는 명령 수준에서 도움말을 확인하세요:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## 전역 옵션

전역 옵션은 명령 앞에 두세요.

| 옵션                                       | 용도                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | RPC URL 또는 `mainnet-beta`, `testnet`, `devnet`, `localhost` 중 하나를 선택합니다. |
| `-C, --config <PATH>`                        | 다른 Solana CLI 설정 파일을 사용합니다.                            |
| `--fee-payer <KEYPAIR>`                      | 트랜잭션 수수료를 지불할 계정을 선택합니다.                            |
| `-p, --program-id <ADDRESS>`                 | Token Program ID를 명시적으로 지정하여 사용합니다.                                         |
| `--program-2022`                             | Token-2022(`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`)를 사용합니다.           |
| `--output <FORMAT>`                          | 지원되는 경우 `json` 또는 `json-compact`를 반환합니다.                          |
| `--with-compute-unit-limit <UNITS>`          | 트랜잭션의 컴퓨트 유닛 한도를 설정합니다.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | 컴퓨트 유닛당 우선순위 가격을 설정합니다.                                  |
| `-v, --verbose`                              | 추가 출력을 표시합니다.                                                   |
| `-V, --version`                              | 설치된 CLI 버전을 출력합니다.                                          |

기본 프로그램은 기존 Token Program입니다. Token-2022 민트나 계정은 읽을 때를 포함하여
`--program-2022`를 사용하세요. 선택한 프로그램이 제공된 주소를 소유하지 않으면
명령이 실패합니다.

## 토큰 생성 및 사용

명령은 생성된 주소를 출력합니다. `create-token`이 반환한 민트 주소를
저장해 두었다가 이후 명령에 사용하세요.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

금액은 민트의 소수 자릿수(decimals)에 맞게 조정된 UI 토큰 수량입니다. `transfer`, `burn`, `unwrap-sol` 같은 명령은
도움말에 표시된 경우 `ALL`을 허용합니다.

## Token-2022 민트 생성

확장 기능은 민트 또는 계정 상태를 추가로 할당하며, 대개 민트를 생성할 때 선택해야 합니다.
다음 예시는 내장 메타데이터를 지원하는 소수점 6자리 민트를 생성합니다:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

일반적인 `create-token` 확장 옵션은 다음과 같습니다:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` 및 `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` 또는 `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` 및
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Token-2022 프로그램이 함께 사용하도록 허용하는 확장 기능만 조합하세요. 되돌릴 수 없는 민트 구성을 만들기 전에
관련 [Token-2022 확장 기능 가이드](/docs/tokens/extensions)를
검토하세요.

## 권한 및 위임자 관리

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize`는 민트, 동결, 소유자, 폐쇄 및 확장 기능별 권한 유형을 지원합니다.
다른 프로그램 메커니즘으로 복구할 수 없는 경우, `--disable`로 권한을 제거하면 영구적으로 적용됩니다.

## 동결, 소각, 폐쇄

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn`은 계정 잔액과 총 공급량을 모두 줄입니다. `close`는 계정에 남은 lamport를
설정된 수령자에게 반환하며, 소각된 토큰은 복구하지 않습니다.

## SOL 래핑 및 언래핑

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

래핑된 SOL token account에 lamport를 직접 전송한 후에는 `sync-native`를 사용하여
토큰 수량이 기본 lamport와 일치하도록 하세요.

## 멀티시그 서명

최대 11명의 멤버로 구성된 M-of-N Token Program 멀티시그를 생성합니다:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

해당 멀티시그가 제어하는 트랜잭션의 경우, 멀티시그 주소를 해당 권한으로 전달하고
`--multisig-signer` 값을 반복해서 사용하여 멤버 keypair를 제공하세요. 기본 권한 플래그는
작업에 따라 다르므로 대상 명령의 도움말을 확인하세요.

## 기밀 잔액

기밀 잔액 명령에는 기밀 전송이 구성된 Token-2022 민트와
구성이 완료된 수령 계정이 필요합니다.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

`configure-confidential-transfer-account`와 `apply-pending-balance`에는
`--address <TOKEN_ACCOUNT_ADDRESS>` 또는 위치 인자 `<MINT_ADDRESS>` 중 하나만 전달해야 하며,
둘 다 전달해서는 안 됩니다. 위치 인자 형식은 소유자의 associated token account를 사용합니다. 입금과
출금은 항상 민트를 받으며, 해당 기본 계정을 변경하려면 `--address`를 사용할 수 있습니다.

`enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits`, `disable-non-confidential-credits`를 사용하여
계정이 허용하는 입금을 제어하세요. 이 설정은 계정 프라이버시와 결제 호환성에 영향을 주므로,
변경하기 전에 계정을 확인하세요.

## 구조화된 출력 및 오프라인 서명

표시 텍스트를 파싱하지 말고 구조화된 출력을 사용하세요:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

트랜잭션을 생성하는 명령은 대체로 `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce`, `--nonce-authority`를 지원합니다. 정확한
오프라인 입력은 명령, 민트 소수 자릿수, 권한 구성에 따라 다르므로,
해당 명령의 `--help` 안내에 따라 서명되지 않은 메시지를 생성하고 서명을 수집하기 전에 모든 주소를 확인하세요.
