## Anahtar Yönetimi

- **Özel anahtarları asla frontend kodunda açığa çıkarmayın.** Backend imzalama, donanım cüzdanları, çoklu imzalı cüzdanlar veya anahtar yönetim hizmetlerini kullanın.
- **Sıcak ve soğuk cüzdanları ayırın.** İşlemler için sıcak cüzdan, hazine için soğuk cüzdan kullanın.
- **Tüm üretim anahtarlarını yedekleyin.** Şifrelenmiş yedekleri birden fazla güvenli konumda saklayın. Bir anahtarı kaybetmek, erişimi kalıcı olarak kaybetmek demektir.
- **Devnet ve mainnet için farklı anahtarlar kullanın.** Devnet anahtarlarınız mainnet anahtarlarınız olmamalıdır. Her ağ için doğru anahtarların yüklendiğinden emin olmak üzere ortam tabanlı yapılandırma kullanın.

## İmzalama Altyapısı

Üretim ortamında backend imzalama için, birden fazla anahtar yönetimi backend'ini tek bir arayüz üzerinden soyutlayan birleşik bir imzalama kütüphanesi olan [Keychain](/docs/tools/keychain)'i kullanın: Memory, Vault, Privy, Turnkey, AWS KMS, Fireblocks, GCP KMS, CDP, Para, Dfns, Crossmint, Openfort ve Utila. Bu sayede yerelde bellek içi anahtarlarla geliştirme yapabilir, ardından uygulama kodunuzu değiştirmeden üretim seviyesi backend'lere geçebilirsiniz.

Hangi backend'in size uygun olduğundan emin değil misiniz? [Backend seçimi](/docs/tools/keychain/choosing-a-backend) bölümüne bakın. Keychain hem [Rust](https://crates.io/crates/solana-keychain) hem de [TypeScript](https://www.npmjs.com/package/@solana/keychain) için mevcuttur.

## RPC Güvenliği

RPC uç noktalarına API anahtarları gibi davranın; çıkarılıp kötüye kullanılabilecekleri frontend kodunda açığa çıkarmayın. Bir backend proxy'si veya istemci koduna dahil edilmeyen ortam değişkenleri kullanın.

- [QuickNode: Uç Nokta Güvenliği için En İyi Uygulamalar](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: Solana API Anahtarlarınızı Koruyun: Güvenlik İçin En İyi Uygulamalar](https://www.helius.dev/docs/rpc/protect-your-keys)

## İzleme

Üretimde şu metrikleri takip edin:

| Metrik                   | Neden                    |
| ------------------------ | ---------------------- |
| İşlem başarı oranı | Sorunları erken tespit edin    |
| Onay gecikmesi     | Ağ sağlığını izleyin |
| Öncelik ücreti harcaması       | Maliyet yönetimi        |
| RPC hata oranı           | Sağlayıcı sağlığı        |

Şunlar için uyarılar kurun:

- Hazineden eşik değerin üzerindeki transferler
- Başarısız işlem oranındaki ani artışlar
- Olağandışı alıcı kalıpları
- RPC hata oranındaki artışlar

Ölçekli gerçek zamanlı işlem izleme için [Dizinleme Kılavuzu](/docs/payments/accept-payments/indexing)'na bakın.

## Adresleri Doğrulayın

Mainnet'te her token ve programın tam olarak bir doğru adresi vardır. USDC veya diğer stablecoin'leri taklit eden sahte token'lar yaygındır; aynı ada ve sembole sahip olurlar ancak mint'leri farklıdır. Uygulamanız mint adreslerini (gereksinimlerinize göre) koda sabitlemeli veya izin listesine almalı, bunları güvenilmeyen kaynaklardan dinamik olarak asla kabul etmemelidir.

**Ortam tabanlı yapılandırma:** Devnet ve Mainnet çoğunlukla tamamen farklı token mint'leri kullanır. Uygulama yapılandırmanızı, her ortam için doğru adresleri yükleyecek şekilde ayarlayın; mainnet adreslerini koda sabitleyip test sırasında değiştirmeyi unutmak ya da daha kötüsü devnet adreslerini üretime göndermek gibi hatalardan kaçının.

Yaygın stablecoin mint'lerinden bazıları şunlardır:

| Token | İhraççı | Mint Adresi                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

Program adresleri de önemlidir. Talimatları yanlış programa göndermek başarısızlıkla sonuçlanır; hatta daha kötüsü, fonların geri döndürülemez şekilde kaybedilmesine yol açar. Token Program adresleri şunlardır:

| Program            | Adres                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Program | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

Doğru adresleri izin listesine almak sahte token'lara karşı koruma sağlar, ancak yanlış _türde_ bir hesaba gönderim yapılmasına karşı koruma sağlamaz. Alıcı adresi bir cüzdan, bir token account, bir mint veya bir program olabilir ve her biri farklı bir işlem gerektirir. Bir cüzdan dışında herhangi bir yere gönderilen yerel SOL, göndericinin kontrolünden çıkar — mint veya program için tamamen kaybolur, token account için yalnızca hesap sahibi tarafından kurtarılabilir — ve kullanıcıyı uyaracak başarısız bir işlem de olmaz.

<Callout type="warn" title="Göndermeden önce alıcıları doğrulayın">
  Bir transferi imzalamadan önce her alıcı adresini sınıflandırın. Cüzdanları, token account'ları, mint'leri ve programları ayırt eden tam karar ağacı ve referans kodu için [Adres Doğrulama](/docs/payments/send-payments/verify-address) bölümüne bakın.
</Callout>
