## Anahtar Yönetimi

- **Özel anahtarları asla frontend kodunda açığa çıkarmayın.** Backend imzalama, donanım
  cüzdanları, çoklu imza cüzdanları veya anahtar yönetim hizmetlerini kullanın.
- **Sıcak ve soğuk cüzdanları ayırın.** İşlemler için sıcak cüzdan, hazine için
  soğuk cüzdan kullanın.
- **Tüm üretim anahtarlarını yedekleyin.** Şifrelenmiş yedekleri birden fazla güvenli
  konumda saklayın. Bir anahtarı kaybetmek, erişimi kalıcı olarak kaybetmek demektir.
- **Devnet ve mainnet için farklı anahtarlar kullanın.** Devnet anahtarlarınız
  mainnet anahtarlarınız olmamalıdır. Her ağ için doğru anahtarların yüklendiğinden emin olmak
  amacıyla ortam tabanlı yapılandırma kullanın.

## İmzalama Altyapısı

Üretim ortamındaki backend imzalama için [Keychain](/docs/tools/keychain)'i kullanın. Keychain, birden fazla anahtar yönetimi backend'ini tek bir arayüz üzerinden soyutlayan birleşik bir
imzalama kütüphanesidir: Memory, Vault, Privy, Turnkey, AWS KMS, Fireblocks, GCP KMS, CDP,
Para, Dfns, Crossmint, Openfort ve Utila. Bu sayede yerel ortamda bellek içi
anahtarlarla geliştirme yapabilir, ardından uygulama kodunu değiştirmeden
üretim seviyesindeki backend'lere geçebilirsiniz.

Hangi backend'in size uygun olduğundan emin değil misiniz? [Backend seçimi](/docs/tools/keychain/choosing-a-backend) bölümüne bakın. Keychain hem [Rust](https://crates.io/crates/solana-keychain) hem de
[TypeScript](https://www.npmjs.com/package/@solana/keychain) için
mevcuttur.

## RPC Güvenliği

RPC uç noktalarına API anahtarları gibi davranın; çıkarılıp kötüye kullanılabilecekleri frontend kodunda
bunları açığa çıkarmayın. Bir backend proxy'si veya istemci koduna
dahil edilmeyen ortam değişkenleri kullanın.

- [QuickNode: Uç Nokta Güvenliği için En İyi Uygulamalar](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: Solana API Anahtarlarınızı Koruyun: Güvenlik İçin En İyi Uygulamalar](https://www.helius.dev/docs/rpc/protect-your-keys)

## İzleme

Üretim ortamında şu metrikleri takip edin:

| Metrik                   | Neden                    |
| ------------------------ | ---------------------- |
| İşlem başarı oranı | Sorunları erken tespit etmek için    |
| Onay gecikmesi     | Ağ sağlığını izlemek için |
| Öncelik ücreti harcaması       | Maliyet yönetimi        |
| RPC hata oranı           | Sağlayıcı sağlığı        |

Şunlar için uyarılar kurun:

- Hazineden eşik değerin üzerindeki transferler
- Başarısız işlem oranındaki ani artışlar
- Olağan dışı alıcı örüntüleri
- RPC hata oranındaki artışlar

Büyük ölçekte gerçek zamanlı işlem izleme için
[Dizinleme Kılavuzu](/docs/payments/accept-payments/indexing)'na bakın.

## Adresleri Doğrulama

Mainnet üzerinde her token ve programın tam olarak tek bir doğru adresi vardır. USDC veya diğer stablecoin'leri taklit eden sahte
tokenlar yaygındır; aynı ada
ve sembole sahip olurlar ancak mint'leri farklıdır. Uygulamanız mint adreslerini (gereksinimlerinize göre) koda sabitlemeli veya izin listesine almalı,
bunları asla güvenilmeyen kaynaklardan dinamik olarak kabul etmemelidir.

**Ortam tabanlı yapılandırma:** Devnet ve Mainnet çoğu zaman tamamen
farklı token mint'leri kullanır. Uygulama yapılandırmanızı, her ortam için doğru
adresleri yükleyecek şekilde ayarlayın; mainnet adreslerini koda sabitleyip test sırasında
değiştirmeyi unutmayın, daha da kötüsü devnet adreslerini üretime göndermeyin.

Yaygın stablecoin mint'lerinden bazıları şunlardır:

| Token | İhraççı | Mint Adresi                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

Program adresleri de önemlidir. Talimatları yanlış programa göndermek
başarısız olur; daha da kötüsü, fonların geri döndürülemez şekilde kaybedilmesine yol açar. Token Program adresleri
şunlardır:

| Program            | Adres                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Programı | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

Doğru adresleri izin listesine almak sahte tokenlara karşı koruma sağlar, ancak
yanlış _türde_ bir hesaba gönderim yapılmasına karşı korumaz. Bir alıcı adresi
cüzdan, token account, mint veya program olabilir ve her biri farklı
işlem gerektirir. SOL'un bir cüzdan dışındaki herhangi bir şeye gönderilmesi,
gönderenin kontrolünden çıkmasına neden olur: mint veya program için tamamen kaybolur, token account için yalnızca
hesap sahibi kurtarabilir. Üstelik kullanıcıyı uyaracak başarısız bir işlem de olmaz.

<Callout type="warn" title="Göndermeden önce alıcıları doğrulayın">
  Bir transferi imzalamadan önce her alıcı adresini sınıflandırın. Cüzdanları, token account'ları, mint'leri ve
  programları birbirinden ayıran tam karar ağacı ve referans kod için [Adres
  Doğrulama](/docs/payments/send-payments/verify-address) bölümüne bakın.
</Callout>
