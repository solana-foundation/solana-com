Bu kılavuz, `solana-keychain` kütüphanesine yeni anahtar yönetim çözümlerini
entegre etmek isteyen cüzdan hizmet sağlayıcıları ve geliştiriciler içindir.
İmzalayıcı implementasyonunuzu ekleyerek, geliştiricilerin birleşik bir arayüz
üzerinden güvenli Solana işlem imzalama için hizmetinizi kullanmasını
sağlayacaksınız.

Keychain; Rust, TypeScript, Python ve Go implementasyonlarını eşdeğer düzeyde tutar.
Dördünü de içeren PR'lar kesinlikle tercih edilir. Yalnızca birine katkıda bulunabiliyorsanız
sorun değil, ancak imzalayıcı bir sürümde yayınlanmadan önce diğerlerinin de
gerekli olacağını unutmayın.

_Claude Code mu kullanıyorsunuz? Deponun
[`add-signer-ci` skill'i](https://github.com/solana-foundation/solana-keychain/tree/main/.claude/skills/add-signer-ci),
fork PR'ı aracılığıyla katkıda bulunulan yeni bir imzalayıcı için CI iş akışlarını kurar._

## Mimari Genel Bakış

Kütüphane, `src/traits.rs` içinde tanımlanan trait tabanlı bir mimari kullanır. Her
imzalayıcı, `SolanaSigner` temel trait'ini (`pubkey`, `sign_message`,
`is_available`) ve sağlayıcının yapısına uyan tam olarak bir yetenek trait'ini uygular:

- `TransactionSigner` (`sign_transaction`): sağlayıcı, çağıranın baytlarını
  imzalar ve yayını çağıran yapar. Çoğu backend böyledir.
- `ModifyingSigner` (`modify_and_sign_transaction`): sağlayıcı işlemi yeniden
  yazar, ardından yayınlamadan imzalar.
- `SendingSigner` (`sign_and_send_transaction`): sağlayıcı sunucu tarafında
  imzalar ve yayınlar.

Kütüphane ayrıca tüm implementasyonları saran birleşik bir `Signer` enum'u sunar;
bu sayede imzalama backend'i çalışma zamanında seçilebilir. Yalnızca temel trait'i
uygular; yeteneklere `as_transaction_signer()`, `as_modifying_signer()` ve
`as_sending_signer()` üzerinden ulaşılır.

## Hızlı Entegrasyon Kontrol Listesi

- İmplementasyonunuzla birlikte imzalayıcı modülünüzü oluşturun
- `SolanaSigner` temel trait'ini (`pubkey`, `sign_message`,
  `is_available`) ve sağlayıcınızın yapısına uyan yetenek trait'ini uygulayın
  (genellikle `TransactionSigner`)
- `Cargo.toml` içine bir feature flag ekleyin; imzalayıcınız reqwest kullanıyorsa
  dahili `_remote` işaretçisini de ekleyin
- `src/lib.rs` içindeki `Signer` enum'unu güncelleyin (variant, `dispatch_signer!`
  kolu ve yetenek erişimcisinde yapınıza uyan bir kol)
- HTTP istemcilerinde HTTPS'i zorunlu kılın ve zaman aşımlarını yapılandırın
- Mesaj baytlarını imzalayın ve döndürülen imzayı eklemeden önce doğrulayın
- Kapsamlı birim testleri ekleyin (wiremock tabanlı, kendi modülünüzde)
- Bir entegrasyon testi dosyası ekleyin ve `.env.example` dosyasını güncelleyin
- TypeScript, Python ve Go implementasyonlarını ekleyin
- Dokümantasyonu güncelleyin
- CI iş akışı güncellemeleri (bakımcılarla koordinasyon sağlayın, bkz.
  [CI İş Akışı Güncellemeleri](#ci-workflow-updates-fork-prs))
- PR gönderin

## Adım 1: İmzalayıcı Modülünüzü Oluşturun

İmplementasyonunuz için `src/` altında yeni bir dizin oluşturun:

```
src/
├── your_service/
│   ├── mod.rs      # Main implementation with SolanaSigner trait
│   └── types.rs    # API request/response types (if needed)
```

## Adım 2: İmzalayıcı Struct'ınızı Tanımlayın

`src/your_service/mod.rs` içinde imzalayıcı struct'ınızı tanımlayın:

```rust
//! YourService API signer integration

use crate::sdk_adapter::{Pubkey, Signature, VersionedTransaction};
use crate::{error::SignerError, traits::SolanaSigner};
use std::str::FromStr;

/// YourService-based signer using YourService's API
#[derive(Clone)]
pub struct YourServiceSigner {
    api_key: String,
    api_secret: String,
    wallet_id: String,
    api_base_url: String,
    client: reqwest::Client,
    public_key: Pubkey,
}

impl std::fmt::Debug for YourServiceSigner {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.debug_struct("YourServiceSigner")
            .field("public_key", &self.public_key)
            .finish_non_exhaustive()
    }
}
```

## Adım 3: Constructor ve Yardımcı Metodları İmplemente Edin

Uzak imzalayıcılar HTTPS'i zorunlu kılmalı ve HTTP zaman aşımlarını
yapılandırmalıdır. Zaman aşımı ayarları için paylaşılan `HttpClientConfig`
struct'ını kullanın.

```rust
use crate::http_client_config::HttpClientConfig;

impl YourServiceSigner {
    pub fn new(
        api_key: String,
        api_secret: String,
        wallet_id: String,
        public_key: String,
        http_config: Option<HttpClientConfig>,
    ) -> Result<Self, SignerError> {
        let pubkey = Pubkey::from_str(&public_key)
            .map_err(|e| SignerError::InvalidPublicKey(format!("Invalid public key: {e}")))?;

        let http = http_config.unwrap_or_default();
        let builder = reqwest::Client::builder()
            .timeout(http.resolved_request_timeout())
            .connect_timeout(http.resolved_connect_timeout());

        // Enforce HTTPS in production; wiremock uses HTTP in tests
        #[cfg(not(test))]
        let builder = builder.https_only(true);

        let client = builder.build().map_err(|e| {
            SignerError::ConfigError(format!("Failed to build HTTP client: {e}"))
        })?;

        Ok(Self {
            api_key,
            api_secret,
            wallet_id,
            api_base_url: "https://api.yourservice.com/v1".to_string(),
            client,
            public_key: pubkey,
        })
    }

    /// Sign raw bytes using your service's API
    async fn sign(&self, message: &[u8]) -> Result<Signature, SignerError> {
        let encoded_message = base64::engine::general_purpose::STANDARD.encode(message);

        let url = format!("{}/sign", self.api_base_url);
        let response = self
            .client
            .post(&url)
            .header("Authorization", format!("Bearer {}", self.api_key))
            .json(&serde_json::json!({
                "wallet_id": self.wallet_id,
                "message": encoded_message,
            }))
            .send()
            .await?;

        // Use generic error messages: never expose raw API response text
        if !response.status().is_success() {
            let status = response.status().as_u16();
            return Err(SignerError::remote_api(format!(
                "YourService API returned status {status}"
            )));
        }

        // Parse response: always use map_err, never .expect() or .unwrap()
        let response_data: SignResponse = response
            .json()
            .await
            .map_err(|e| SignerError::SerializationError(format!("Failed to parse response: {e}")))?;
        let sig_bytes = base64::engine::general_purpose::STANDARD
            .decode(&response_data.signature)
            .map_err(|e| SignerError::SerializationError(format!("Failed to decode signature: {e}")))?;

        let sig_array: [u8; 64] = sig_bytes
            .try_into()
            .map_err(|_| SignerError::SigningFailed("Invalid signature length".to_string()))?;

        Ok(Signature::from(sig_array))
    }
}
```

## Adım 4: İmzalayıcı Trait'lerini Uygulayın

`SolanaSigner` temel trait'i, `pubkey()` yanında 2 asenkron metot (`sign_message`,
`is_available`) içerir. İşlem imzalama bir yetenek trait'inde yer alır;
çoğu sağlayıcı `TransactionSigner` trait'ini uygular. Bu trait'in `sign_transaction`
metodu, `SignTransactionResult` döndürür (işlemin tamamen veya kısmen imzalandığını
belirten etiketli bir enum).

Tüm wire işlemini değil, mesaj baytlarını imzalayın ve eklemeden önce sağlayıcının
imzasını bu baytlara karşı doğrulayın. İmzalama ve serileştirme için ortak
`TransactionUtil` yardımcılarını kullanın.

```rust
use crate::signature_util::verify_or_reject;
use crate::traits::{SignTransactionResult, TransactionSigner};
use crate::transaction_util::TransactionUtil;

#[async_trait::async_trait]
impl SolanaSigner for YourServiceSigner {
    fn pubkey(&self) -> Pubkey {
        self.public_key
    }

    async fn sign_message(&self, message: &[u8]) -> Result<Signature, SignerError> {
        let signature = self.sign(message).await?;
        verify_or_reject(&signature, &self.public_key, message)?;
        Ok(signature)
    }

    async fn is_available(&self) -> bool {
        let url = format!("{}/health", self.api_base_url);
        self.client
            .get(&url)
            .send()
            .await
            .map(|r| r.status().is_success())
            .unwrap_or(false)
    }
}

#[async_trait::async_trait]
impl TransactionSigner for YourServiceSigner {
    async fn sign_transaction(
        &self,
        tx: &mut VersionedTransaction,
    ) -> Result<SignTransactionResult, SignerError> {
        let message = tx.message.serialize();
        let signature = self.sign(&message).await?;
        verify_or_reject(&signature, &self.public_key, &message)?;

        TransactionUtil::add_signature_to_transaction(tx, &self.public_key, signature)?;
        let serialized = TransactionUtil::serialize_transaction(tx)?;
        Ok(TransactionUtil::classify_signed_transaction(
            tx,
            (serialized, signature),
        ))
    }
}
```

Sağlayıcınız işlemi imzalamadan önce yeniden yazıyorsa bunun yerine
`ModifyingSigner` uygulayın ve çağıranın işlemini sağlayıcının baytlarıyla
tümüyle değiştirin. Sağlayıcı sunucu tarafında yayın yapıyorsa `SendingSigner`
uygulayın ve çağıranın işlemine dokunmayın. Sağlayıcınızın karşılayamayacağı bir
yeteneği asla uygulamayın.

## Adım 6: Özellik Bayrağı Ekleyin

İmzalayıcınızı isteğe bağlı bir feature olarak eklemek için `Cargo.toml` dosyasını
güncelleyin. Uzak backend'ler, `src/error.rs` içindeki `From<reqwest::Error>`
impl'ini kontrol eden dahili `_remote` işaretçisini içerir; bu işaretçi olmadan,
yalnızca feature'ınız etkinken reqwest çağrılarındaki `?` derlenmez.

```toml
[features]
default = ["memory", "sdk-v2"]
memory = []
vault = ["dep:reqwest", "_remote"]
privy = ["dep:reqwest", "dep:p256", "_remote"]
your_service = ["dep:reqwest", "_remote"]  # Add your feature
all = ["memory", "vault", "privy", "...", "your_service"]  # Update all
```

## Adım 7: Signer Enum'unu Güncelleyin

İmzalayıcınızı `src/lib.rs` dosyasına ekleyin. Temel `SolanaSigner` impl'i,
`dispatch_signer!` makrosu üzerinden yönlendirme yapar; bu yüzden oraya bir kol
ekleyin. Yetenek erişimi `as_transaction_signer()`, `as_modifying_signer()` ve
`as_sending_signer()` erişimcilerinde bulunur: yetenek trait'inize uyan erişimciye
bir `Some(s)` kolu ekleyin (ve gönderen ya da değiştiren bir backend için
`as_transaction_signer()` içine bir `None` kolu ekleyin).

```rust
// Add feature-gated module
#[cfg(feature = "your_service")]
pub mod your_service;

// Re-export your signer type
#[cfg(feature = "your_service")]
pub use your_service::YourServiceSigner;

// Add to Signer enum
#[derive(Debug)]
pub enum Signer {
    #[cfg(feature = "memory")]
    Memory(MemorySigner),

    // ... existing variants

    #[cfg(feature = "your_service")]
    YourService(YourServiceSigner),  // Add your variant
}

// Add constructor method
impl Signer {
    #[cfg(feature = "your_service")]
    pub fn from_your_service(
        api_key: String,
        api_secret: String,
        wallet_id: String,
        public_key: String,
    ) -> Result<Self, SignerError> {
        Ok(Self::YourService(YourServiceSigner::new(
            api_key,
            api_secret,
            wallet_id,
            public_key,
            None, // uses default HttpClientConfig
        )?))
    }
}

// Update the dispatch macro: the base SolanaSigner impl uses it for
// pubkey, sign_message and is_available
macro_rules! dispatch_signer {
    ($self:ident, $signer:pat => $body:expr) => {
        match $self {
            // ... existing variants
            #[cfg(feature = "your_service")]
            Signer::YourService($signer) => $body,
        }
    };
}

// Add your arm to the capability accessor matching your shape
impl Signer {
    pub fn as_transaction_signer(&self) -> Option<&dyn TransactionSigner> {
        match self {
            // ... existing variants
            #[cfg(feature = "your_service")]
            Signer::YourService(s) => Some(s),
        }
    }
}
```

## Adım 8: Kapsamlı Testler Ekleyin

Modülünüze testler ekleyin (`src/your_service/mod.rs` dosyasının altında):

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use solana_sdk::{signature::Keypair, signer::Signer};
    use wiremock::{
        matchers::{header, method, path},
        Mock, MockServer, ResponseTemplate,
    };

    #[tokio::test]
    async fn test_new() {
        let keypair = Keypair::new();
        let signer = YourServiceSigner::new(
            "test-key".to_string(),
            "test-secret".to_string(),
            "test-wallet".to_string(),
            keypair.pubkey().to_string(),
            None,
        );
        assert!(signer.is_ok());
    }

    #[tokio::test]
    async fn test_sign_message() {
        let mock_server = MockServer::start().await;
        let keypair = Keypair::new();
        let message = b"test message";
        let signature = keypair.sign_message(message);

        Mock::given(method("POST"))
            .and(path("/sign"))
            .respond_with(ResponseTemplate::new(200).set_body_json(serde_json::json!({
                "signature": base64::engine::general_purpose::STANDARD.encode(signature.as_ref())
            })))
            .expect(1)
            .mount(&mock_server)
            .await;

        let mut signer = YourServiceSigner::new(
            "test-key".to_string(),
            "test-secret".to_string(),
            "test-wallet".to_string(),
            keypair.pubkey().to_string(),
            None,
        ).unwrap();
        signer.api_base_url = mock_server.uri();

        let result = signer.sign_message(message).await;
        assert!(result.is_ok());
    }

    #[tokio::test]
    async fn test_sign_unauthorized() {
        let mock_server = MockServer::start().await;
        let keypair = Keypair::new();

        Mock::given(method("POST"))
            .and(path("/sign"))
            .respond_with(ResponseTemplate::new(401))
            .expect(1)
            .mount(&mock_server)
            .await;

        let mut signer = YourServiceSigner::new(
            "bad-key".to_string(),
            "bad-secret".to_string(),
            "test-wallet".to_string(),
            keypair.pubkey().to_string(),
            None,
        ).unwrap();
        signer.api_base_url = mock_server.uri();

        let result = signer.sign_message(b"test").await;
        assert!(result.is_err());
    }
}
```

İmza doğrulama hatasını da test edin: imzası doğrulanmayan sahte (mock) bir yanıt
hata döndürmelidir.

## Adım 9: Entegrasyon Testleri Ekleyin

`rust/src/tests/test_<name>_integration.rs` dosyasını oluşturun. Entegrasyon
testleri gerçek servis API'sine karşı çalışır (wiremock değil) ve
`integration-tests` feature'ının arkasında yer alır. Her dosyada şunlar bulunmalıdır:

- Ortam değişkeni adları için `pub const` bildirimleri
- Ortam değişkenlerini `dotenvy` ile okuyan bir `get_signer()` yardımcısı
- Üç test fonksiyonu: `test_<name>_sign_message`,
  `test_<name>_sign_transaction` ve `test_<name>_is_available`
- Feature kapıları: modül üzerinde `#[cfg(feature = "your_service")]` ve her test
  üzerinde `#[cfg(feature = "integration-tests")]`

Eksiksiz bir referans için `rust/src/tests/test_para_integration.rs` dosyasına
bakın ve modülünüzü `rust/src/tests/mod.rs` içinde bildirin:

```rust
pub mod test_your_service_integration;
```

Kök dizindeki `.env.example` dosyasını, mevcut düzeni izleyerek imzalayıcınızın

almalıdır; TypeScript, Python ve Go test paketleri de aynı adları kullanır.

## Adım 11: Dokümantasyonu Güncelleyin

README.md içindeki desteklenen arka uçlar tablosuna imzalayıcınızı ekleyin:

| Arka Uç         | Kullanım Durumu                                       | Özellik Bayrağı   |
| --------------- | ---------------------------------------------- | -------------- |
| **Memory**      | Yerel keypair'ler, geliştirme, test           | `memory`       |
| **Vault**       | HashiCorp Vault ile kurumsal anahtar yönetimi | `vault`        |
| **Privy**       | Privy altyapısı ile gömülü cüzdanlar     | `privy`        |
| **Turnkey**     | Turnkey aracılığıyla emanetsiz anahtar yönetimi       | `turnkey`      |
| **YourService** | Hizmetinizin kısa açıklaması              | `your_service` |

Ayrıca backend'inizi her dilin README dosyasındaki imzalayıcı yetenekleri tablosuna
ekleyin. Bir kullanım örneği ekleyin:

```rust
use solana_keychain::{Signer, SolanaSigner};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let signer = Signer::from_your_service(
        "your-api-key".to_string(),
        "your-api-secret".to_string(),
        "your-wallet-id".to_string(),
        "your-public-key".to_string(),
    )?;

    let pubkey = signer.pubkey();
    println!("Public key: {}", pubkey);

    Ok(())
}
```

## CI İş Akışı Güncellemeleri (Fork PR'ları)

CI iki aşamalı bir süreçtir. PR'ınız test edilmeden önce `main` dalını hazırlamak
için bakımcılarla koordinasyon sağlayın: onlar `fork-external-live-manual.yml`
dosyasını günceller, `ci.yml` dosyasına ortam değişkenlerini ekler ve GitHub
Secrets'ı yapılandırır.

PR'ınız, imzalayıcı kodunuzla birlikte şu 2. Aşama değişikliklerini içermelidir:

- **`ci.yml`**: Rust feature'ınızı `backend` matrisine (`all`'dan önce) ve
  entegrasyon test fonksiyonunuzu `test` matrisine ekleyin
- **`typescript-ci.yml`**: paketinizi birim ve entegrasyon test matrislerine ekleyin
  ve ortam değişkenlerini entegrasyon testi adımına ekleyin
- **`typescript-publish.yml`**: paketinizi `PUBLISH_PACKAGES`, GitHub Release
  `packages` dizisi ve özet tablosuna ekleyin
- **`python-ci.yml`**: backend'i `resolve-signers` içindeki `CI_SIGNER_*`
  kapısına ve entegrasyon matrisine ekleyin
- **`go-ci.yml`**: backend'i `CI_SIGNER_*` kapısına ve `moduleBySigner` içine
  ekleyin

## TypeScript İmzalayıcı

Ayrıca bir TypeScript imzalayıcı paketi ekliyorsanız, bunu
`typescript/packages/your-signer/` konumunda oluşturun. Temel desenler:

- `createYourSigner()` fabrika fonksiyonu
  `SolanaTransactionSigner<TAddress> & SolanaMessageSigner<TAddress>` döndürür;
  imzalayıcı sınıfını dahili tutun ve yalnızca fabrikayı ve yapılandırma tipini
  dışa aktarın
- Yapılandırma arayüzünü dışa aktar (`YourSignerConfig`)
- Backend'iniz mesaj imzalayamıyorsa `SolanaMessageSigner` kullanmayın ve hiçbir
  `signMessages` metodu sunmayın: Kit, imzalayıcıları metodun varlığına göre
  sınıflandırır; bu yüzden hata fırlatan bir stub imzalayıcıyı yanlış sınıflandırır
- `apiBaseUrl` yapılandırma alanlarında HTTPS'i `@solana/keychain-core` içindeki
  `assertHttpsUrl()` ile zorunlu kılın
- Uzak çağrıları `@solana/keychain-core` içindeki `fetchSignerJson()` ile yapın;
  hata eşlemesi, yanıt temizleme, yönlendirme reddi ve varsayılan zaman aşımını
  bu fonksiyon yönetir
- Diğer tüm uzak API hata metinlerini `@solana/keychain-core` içindeki
  `sanitizeRemoteErrorResponse()` ile temizleyin
- `@solana/keychain-core` paketinden
  `throwSignerError(SignerErrorCode.*, { cause, message })` kullan
- Her imzalama metodunda `config?.abortSignal` değerine uyun ve bunu
  `fetchSignerJson()` ile `signBatchStaggered()` fonksiyonlarına iletin
- `requestDelayMs` değerini `validateRequestDelayMs()` ile doğrulayın ve toplu
  işlemleri `signBatchStaggered()` ile yapın
- Hata kodlarını listeleyen fabrika fonksiyonlarına `@throws` JSDoc ekle
- `@solana/*` paketlerini `>=8.1.0` sürümüyle peer dependency olarak bildirin
- vitest ve sahte (mock) `fetch` ile birim testleri; `@solana/keychain-test-utils`
  içindeki `runSignerIntegrationTest` ile entegrasyon testleri

### Gönderen İmzalayıcılar

Sağlayıcınız işlemi yeniden yazıyorsa veya sunucu tarafında yayınlıyorsa imzası
çağıranın işlemine uygulanamaz; bu nedenle `SolanaTransactionSigner` yerine
`SolanaSendingSigner` olmalıdır:

- `signAndSendTransactions()` metodunu uygulayın ve `signTransactions` metodunu
  **sunmayın** (backend gerçekten mesaj imzalamıyorsa `signMessages` metodunu da
  sunmayın)
- `config?.abortSignal` değerine uyun. Sağlayıcı oluşturma isteğini kabul ettikten
  sonra, her hatayı (iptal dahil) sağlayıcı işlem kimliğini taşıyan
  `BROADCAST_UNCONFIRMED` olarak bildirin ve iptal nedenini `cause` olarak saklayın
- Gönderen imzalayıcı tipinizi döndüren tipli bir `createKeychainSigner` overload'ı
  ekleyin
- Backend'inizi `typescript/packages/kit-plugin/src/keychain-plugin.ts` içindeki
  `KeychainKitPluginConfig` dışında bırakın; çünkü gönderen bir imzalayıcı, Kit
  istemcisinde `payer` veya `identity` olarak kullanılamaz
- Birim testlerinde, örnekleriniz için `isTransactionPartialSigner()` değerinin
  false, `isTransactionSendingSigner()` değerinin true olduğunu doğrulayın

### Şemsiye Paketini Güncelle

`typescript/packages/keychain/` dizinini güncelleyin (değiştirilecek 7 dosya):

1. `src/types.ts`: `YourSignerConfig` tipini `KeychainSignerConfig`
   ayrımlı birleşim tipine (discriminated union) ekleyin
2. `src/create-keychain-signer.ts`: switch case'i ekleyin (her backend paketi
   dinamik bir `import()` ile yüklenir)
3. `src/resolve-address.ts`: Hızlı yol (fast-path) veya getirme yolu (fetch-path)
   switch case'ine ekleyin
4. `src/index.ts`: Yapılandırma tipini, namespace'i ve fabrika fonksiyonu
   dışa aktarımlarını ekleyin
5. `package.json`: `@solana/keychain-your-signer: "workspace:*"` bağımlılığını ekleyin
6. `tsconfig.json`: `{ "path": "../your-signer" }` referansını ekleyin
7. `typescript/scripts/test-treeshake-umbrella.mjs`: Paketinizi `SIGNER_MARKERS`
   içine ve fabrikanızı `FACTORIES` içine ekleyin

Switch ifadelerinde kapsamlı `never` kontrolleri vardır; bu yüzden birleşim tipine
ekleme yapıp bir case'i atlarsanız TypeScript hata verir. Ardından `just ts-treeshake`
çalıştırın: her paket ve umbrella paketi tree-shake edilebilir kalmalıdır.

## Python İmzalayıcısı

Modülü `python/src/solana_keychain/your_signer/` dizininde oluşturun (`__init__.py`
ve `signer.py`). Temel kalıplar:

- `solana_keychain.core` içinden `SolanaSigner` sınıfını alt sınıflayın (`pubkey`
  özelliği, `async sign_message()`, `async is_available()`) ve tam olarak bir yetenek
  sınıfı ekleyin: `TransactionSigner` (`async sign_transaction()`), `ModifyingSigner`
  (`async modify_and_sign_transaction()`) veya `SendingSigner`
  (`async sign_and_send_transaction()`)
- Backend adresini uzaktan çözümlüyorsa `init()` çağrısını bekleyen (await) bir
  `async create_your_signer()` fabrikası dışa aktarın; init öncesinde imzalama
  `SignerErrorCode.NOT_INITIALIZED` hatası verir
- Gizli bilgileri `field(repr=False)` ile işaretlenmiş bir yapılandırma dataclass'ı
  (`YourSignerConfig`) dışa aktarın
- Temel URL alanlarında HTTPS'i `assert_https_url()` ile zorunlu kılın ve her isteği
  `fetch_signer_json()` üzerinden yönlendirin
- Sağlayıcının imzasını döndürmeden önce doğrulayın; bir imzanın kapsadığı baytlar
  için `signed_message_bytes()` kullanın, elle yazılmış bir sürüm öneki asla
  kullanmayın
- Backend'i `python/src/solana_keychain/keychain.py` içindeki `_BACKENDS` içine
  kaydedin
- Arka uç bir sağlayıcı SDK'sına ihtiyaç duyuyorsa, içe aktarmayı koruma altına alın,
  `pip install 'solana-keychain[your-signer]'` komutunu belirten bir `ImportError`
  fırlatın, ekstrayı `python/pyproject.toml` içinde tanımlayın ve arka ucu paket
  kökünden asla erken (eager) biçimde içe aktarmayın
- pytest ile birim testleri: HTTP arka uçları için `respx`, SDK arka uçları için
  sahte (stub) istemciler ve fırlatılan hataların `str()` veya `repr()` çıktısında
  hiçbir gizli bilginin görünmediğini doğrulayan bir kontrol
- `python/tests/integration/test_live_signers.py` dosyasına bir `make_your_signer()`
  fabrika fonksiyonu ekleyin ve bunu `_MESSAGE_CAPABLE` içine kaydedin
  (`sign_message` desteği olmayan arka uçlar için `_TRANSACTION_ONLY`)

## Go Signer

Her Go arka ucu kendi modülüdür; `go/signers/yoursigner/` dizininde yer alır ve modül yolu
`github.com/solana-foundation/solana-keychain/go/signers/yoursigner/v2` şeklindedir. Referans için
`go/signers/para/` dizinine bakın. Temel kalıplar:

- `core.SolanaSigner` arayüzünü (`Pubkey()`, `SignMessage(ctx, message)`,
  `IsAvailable(ctx)`) ve ek olarak tam olarak bir yetenek arayüzünü uygulayın:
  `core.TransactionSigner`, `core.ModifyingSigner` veya `core.SendingSigner`.
  Yetenek, tür doğrulaması (type assertion) ile tespit edilir; dolayısıyla bir
  işlemi imzalayamayan arka uçta `SignTransaction` metodu hiç bulunmamalıdır
- Bir `Config` struct'ı ve bir `New` yapıcısı dışa aktarın (arka uç adresini uzaktan
  çözümlüyorsa `New(ctx, cfg)`; bu işlemden önce `core.NewNotInitializedError`
  döndürün)
- HTTP istemcilerini `core.NewHTTPClient` veya `core.ResolveHTTPClient` ile oluşturun
  ve temel URL'leri `core.NormalizeHTTPSBaseURL` ile doğrulayın
- İşlemleri, mesaj baytlarını imzalayıp imzayı ekleyen `core.SignTransactionWith` ile
  imzalayın; sağlayıcı imzalarını `core.VerifySignature` ile doğrulayın
- Hataları `core.NewSignerError` / `core.WrapSignerError` ve `core.CodeSigningFailed`
  gibi kararlı kodlarla döndürün
- Birim testleri `httptest` ile; entegrasyon testleri ise `integration_test.go`
  içinde, `//go:build integration` etiketinin arkasında yazılır

## Uygulama İpuçları

### Hata Yönetimi

Her zaman mevcut `SignerError` varyantlarını kullanın. `SignerError` üzerindeki hem
`Display` hem de `Debug` çıktıları gizlenmiştir (redacted); bu nedenle mesajları genel
tutun ve ham API yanıt verilerini asla eklemeyin. Güvenilmeyen API yanıtları üzerinde
hiçbir zaman `.expect()` veya `.unwrap()` kullanmayın:

```rust
// Good: uses the constructor with a generic message
return Err(SignerError::remote_api(format!(
    "YourService API returned status {status}"
)));

// Good: converts from standard errors
let bytes = base64::decode(data)
    .map_err(|e| SignerError::SerializationError(format!("Failed to decode: {e}")))?;
```

### Güvenlik Gereksinimleri

Bunlar öneri değildir: kullanıcılar bir arka ucu bu gereksinimlere güvenerek seçer.
Sağlayıcınız bunlardan birini imkânsız kılıyorsa, bunu PR'da ve deponun
`docs/SECURITY_MODEL.md` dosyasında belirtin.

- **Sağlayıcının neyi imzaladığını doğrulayın.** Mesaj baytlarını yerel olarak hesaplayın
  ve dönen imzayı eklemeden önce, signer'ınızın gerektirdiği konumda bu baytlara karşı
  doğrulayın. Doğrulanmayan bir imza başarısız sayılmalıdır, asla eklenmemelidir.
- **Sağlayıcının yayın (broadcast) yapıp yapmadığını belirtin.** Sağlayıcı işlemi
  sunucu tarafında yürütüyorsa, gönderme (sending) yapısını uygulayın ve gerçekleşen
  işlemi tanımlayan imzayı döndürün. Sağlayıcının yalnızca imzalama yapan bir uç
  noktası yoksa, çağıranın haberi olmadan gönderim yapmak yerine arka ucu yalnızca
  gönderen (sending-only) olarak tasarlayın.
- **Çağıranı, imzanın kapsamadığı bir işlemle asla baş başa bırakmayın.**
  İşlemi yeniden yazan bir sağlayıcı kendi baytlarını imzalar: ya çağıranın işlemine
  dokunmayın (yayının sağlayıcı tarafından yönetildiği durum), ya da değiştiren
  (modifying) yapıyı kullanın ve işlemi tamamen sağlayıcının baytlarıyla değiştirin.
- **Yayın belirsizliğini olduğu gibi bildirin.** Gönderimden sonra oluşan bir hata,
  işlemin yine de zincire ulaşmış olduğu anlamına gelebilir. Genel bir hata yerine
  `BROADCAST_UNCONFIRMED` döndürün, elinizde olduğunda sağlayıcı işlem kimliğini
  (transaction id) ekleyin ve her oluşturma isteğinde mesajdan türetilmiş bir
  idempotency anahtarı gönderin; böylece baytları birebir aynı olan yeniden gönderim
  güvenli olur.
- **Başlatmadan önce asla imzalamayın.** `init()` öncesinde açık anahtar için
  (`Pubkey::default()` yerine) `Option<Pubkey>` kullanın ve önce imzalama
  denenirse bir yapılandırma hatasıyla başarısız olun.
- Hassas verileri (özel anahtarlar, API gizli anahtarları, ham API yanıtları) asla
  loglamayın ve hassas alanları gizleyen bir `Debug` implementasyonu kullanın
- HTTPS kullanımını zorunlu kılın (`https_only(true)`, wiremock için
  `#[cfg(not(test))]` ile koşullandırılmış) ve istek ile bağlantı zaman aşımlarını
  `HttpClientConfig` üzerinden yapılandırın (varsayılanlar: 30sn/5sn)
- Ara anahtar materyalini `zeroize::Zeroizing<Vec<u8>>` ile sıfırlayın

### Mock'larla Test Etme

HTTP API'lerini mocklamak için `wiremock` kullanın. Hata mesajı metnini değil,
yalnızca hata türünü doğrulayın:

```rust
#[cfg(test)]
mod tests {
    use wiremock::{MockServer, Mock, ResponseTemplate};

    #[tokio::test]
    async fn test_api_call() {
        let mock_server = MockServer::start().await;

        Mock::given(method("POST"))
            .respond_with(ResponseTemplate::new(200))
            .mount(&mock_server)
            .await;

        // Use mock_server.uri() as your api_base_url
    }
}
```
