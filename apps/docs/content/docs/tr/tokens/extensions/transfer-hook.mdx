Transfer Hook uzantısı ve Transfer Hook Arayüzü, her token transferinde özel
talimat mantığını çalıştıran Mint Account'lar oluşturma imkânı sunar.

Bu, token transferleri için birçok yeni kullanım senaryosunun kilidini açar. Örneğin:

- NFT telif haklarının zorunlu kılınması
- Token alabilecek cüzdanlar için kara liste veya beyaz liste oluşturma
- Token transferlerine özel ücretler uygulama
- Özel token transfer olayları oluşturma
- Token transferlerinizle ilgili istatistikleri takip etme
- Ve çok daha fazlası

Bunu başarmak için geliştiricilerin
[Transfer Hook Arayüzü](https://github.com/solana-program/token-2022/tree/main/interface/src/extension/transfer_hook)'nü
uygulayan bir program geliştirmesi ve Transfer Hook uzantısı etkinleştirilmiş bir Mint Account başlatması gerekir.

Mint Account'a ait tokenları içeren her token transferinde, Token
Extensions programı Transfer Hook programı üzerinde bir talimat çalıştırmak için
Cross Program Invocation (CPI) yapar.

<Callout type="info">

Token Extensions programı bir Transfer Hook programına CPI yaptığında, ilk transferdeki tüm hesaplar
salt okunur hesaplara dönüştürülür. Bu, gönderenin
imza yetkilerinin Transfer Hook programına geçmediği anlamına gelir.

Bu tasarım kararı, Transfer Hook programlarının kötü amaçlı kullanımını önlemek için alınmıştır.

</Callout>

Bu rehberde Anchor framework'ünü kullanarak bir Transfer Hook programı oluşturacağız;
ancak Transfer Hook Arayüzü'nü yerel (native) bir
programla uygulamak da mümkündür. Anchor framework hakkında daha fazla bilgiyi buradan edinebilirsiniz:
[Anchor Framework](https://www.anchor-lang.com/)

## Transfer Hook Arayüzüne Genel Bakış

Transfer Hook Arayüzü, geliştiricilerin belirli bir Mint
Account için her token transferinde çalıştırılan özel talimat mantığı uygulamasını sağlar.

Transfer Hook Arayüzü aşağıdaki
[talimatları](https://github.com/solana-program/token-2022/blob/main/interface/src/extension/transfer_hook/instruction.rs) tanımlar:

- `Execute`: Token Extensions programının her token
  transferinde çağırdığı bir talimat.
- `InitializeExtraAccountMetaList` (isteğe bağlı): Özel `Execute` talimatının ihtiyaç duyduğu ek hesapların
  listesini saklayan bir hesap oluşturur.
- `UpdateExtraAccountMetaList` (isteğe bağlı): Mevcut listenin üzerine yazarak ek
  hesapların listesini günceller.

`InitializeExtraAccountMetaList` talimatını arayüz üzerinden
uygulamak teknik olarak zorunlu değildir. Hesap, Transfer Hook programındaki herhangi bir talimatla
oluşturulabilir.

Ancak hesabın Program Derived Address (PDA) adresi aşağıdaki
seed'ler kullanılarak türetilmelidir:

- Koda sabit olarak yazılmış "extra-account-metas" dizesi
- Mint Account adresi
- Transfer Hook programının ID'si

<CodeTabs>

```js !! title="Web3.js v3"
const [pda] = await PublicKey.findProgramAddress(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBytes()],
  program.programId // transfer hook program ID
);
```

```js !! title="Web3.js (legacy)"
const [pda] = PublicKey.findProgramAddressSync(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBuffer()],
  program.programId // transfer hook program ID
);
```

</CodeTabs>

`Execute` talimatının ihtiyaç duyduğu ek hesapları
önceden tanımlanmış PDA'da saklayarak, bu hesaplar istemci tarafından bir token transfer
talimatına otomatik olarak eklenebilir.

## Hello-world Transfer Hook

Bu örnek, transfer hook'ların hello world'üdür. Her token transferinde yalnızca bir mesaj yazdıran basit bir transfer hook'tur. Solana programlarını geliştirmek ve dağıtmak için kullanılan çevrimiçi bir araç olan Solana Playground'da örneği açarak başlıyoruz:
[bağlantı](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/hello_world)

Örnek, transfer hook arayüzünü uygulayan bir Anchor programından
ve programı test etmek için bir test dosyasından oluşur.

Bu program yalnızca 3 talimat içerecek:

1. `initialize_extra_account_meta_list`: `transfer_hook` talimatının ihtiyaç duyduğu ek hesapların
   listesini saklayan bir hesap oluşturur. Hello world örneğinde bunu boş bırakıyoruz.
2. `transfer_hook`: Bu talimat, her token transferinde CPI ile çağrılır
   ve sarmalanmış SOL token transferini gerçekleştirir.
3. `fallback`: Anchor kullandığımız ve Token Program yerel (native) bir
   program olduğu için, talimat ayırt edicisini (discriminator) manuel olarak eşleştirmek ve özel `transfer_hook` talimatımızı çağırmak
   üzere bir fallback talimatı eklememiz gerekir.
   Bu fonksiyonu değiştirmeniz gerekmez.

Token her transfer edildiğinde bu `transfer_hook` fonksiyonu
Token Program tarafından çağrılacaktır.

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    Ok(())
}
```

Bu fonksiyona artık ek mantığınızı ekleyebilirsiniz. Örneğin, 50'den büyük bir miktar
transfer edildiğinde transferin başarısız olmasını şöyle
sağlayabilirsiniz:

```rust
#[error_code]
pub enum MyError {
    #[msg("The amount is too big")]
    AmountTooBig,
}

pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    if amount > 50 {
        return err!(MyError::AmountTooBig);
    }

    Ok(())
}
```

## Counter Transfer Hook

Sonraki örnek, tokenınız her transfer edildiğinde bir sayacı nasıl artırabileceğinizi gösterecek.
[bağlantı](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/counter)

Transfer hook'unuza ek hesaplar gerektiren mantık eklemek istiyorsanız,
bu hesapları ExtraAccountMetaList hesabına eklemeniz gerekir. Buradaki örneğimizde,
tokenın kaç kez transfer edildiğini kaydeden bir PDA istiyoruz.

Bu, aşağıdaki kodu
`initialize_extra_account_meta_list` talimatına ekleyerek yapılabilir:

```rust
let account_metas = vec![
    ExtraAccountMeta::new_with_seeds(
        &[Seed::Literal {
            bytes: "counter".as_bytes().to_vec(),
        }],
        false, // is_signer
        true,  // is_writable
    )?,
];
```

Ayrıca yeni mint account'u başlatırken bu hesabı da oluşturmamız
ve token her transfer edildiğinde bu hesabı iletmemiz gerekir.

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        init_if_needed,
        seeds = [b"counter"],
        bump,
        payer = payer,
        space = 16
    )]
    pub counter_account: Account<'info, CounterAccount>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(
        token::mint = mint,
        token::authority = owner,
    )]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        token::mint = mint,
    )]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(
        mut,
        seeds = [b"counter"],
        bump
    )]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Hesap, `u64` türünde bir sayaç değişkeni tutacak:

```rust
#[account]
pub struct CounterAccount {
    counter: u64,
}
```

Artık transfer hook fonksiyonumuzda, fonksiyon her çağrıldığında bu sayacı bir artırabiliriz:

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    ctx.accounts.counter_account.counter.checked_add(1).unwrap();
    msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

    Ok(())
}
```

<Callout type="warn">

Burada token her transfer edildiğinde bir sayacı artırdığımız için, transfer hook talimatının yalnızca
bir transfer sırasında çağrılabildiğinden emin olmamız gerekir; aksi takdirde biri transfer hook talimatını
doğrudan çağırarak sayacımızı bozabilir. Bu, tüm transfer hook'larınıza eklemeniz gereken bir kontroldür.

</Callout>

Kontrolü şöyle ekleyebilirsiniz:

```rust
fn assert_is_transferring(ctx: &Context<TransferHook>) -> Result<()> {
    let source_token_info = ctx.accounts.source_token.to_account_info();
    let mut account_data_ref: RefMut<&mut [u8]> = source_token_info.try_borrow_mut_data()?;
    let mut account = PodStateWithExtensionsMut::<PodAccount>::unpack(*account_data_ref)?;
    let account_extension = account.get_extension_mut::<TransferHookAccount>()?;

    if !bool::from(account_extension.transferring) {
        return err!(TransferError::IsNotCurrentlyTransferring);
    }

    Ok(())
}
```

Ardından `transfer_hook` fonksiyonunuzun başında çağırın:

```rust
    #[error_code]
    pub enum TransferError {
        #[msg("The token is not currently transferring")]
        IsNotCurrentlyTransferring,
    }

    #[interface(spl_transfer_hook_interface::execute)]
    pub fn transfer_hook(ctx: Context<TransferHook>, _amount: u64) -> Result<()> {
        // Fail this instruction if it is not called from within a transfer hook
        assert_is_transferring(&ctx)?;

        ctx.accounts.counter_account.counter.checked_add(1).unwrap();
        msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

        Ok(())
    }
```

## wSOL Transfer Ücreti Olan Transfer Hook (gelişmiş örnek)

Bu rehberin sonraki bölümünde, Anchor framework'ünü kullanarak daha gelişmiş bir Transfer Hook
programı geliştireceğiz. Bu program, göndericiden her token transferi için
wSOL ücreti ödemesini isteyecek.

wSOL transferleri, Transfer Hook programından türetilen bir PDA olan bir delegate kullanılarak gerçekleştirilecek. Bunun nedeni, token transfer talimatının ilk göndericisinin imzasına
Transfer Hook programında erişilememesidir.

Bu program yalnızca 3 talimat içerecek:

1. `initialize_extra_account_meta_list`: `transfer_hook` talimatının ihtiyaç duyduğu ek hesapların
   listesini saklayan bir hesap oluşturur.
2. `transfer_hook`: Bu talimat, her token transferinde CPI ile çağrılır
   ve sarmalanmış SOL token transferini gerçekleştirir.
3. `fallback`: Transfer hook arayüzü talimatlarının belirli
   ayırt edicileri (talimat tanımlayıcıları) vardır. Bir Anchor programında, talimat ayırt edicisini manuel olarak eşleştirmek ve
   özel `transfer_hook` talimatımızı çağırmak için bir
   fallback talimatı kullanabiliriz.

Bu program, göndericiden her token transferinde sarmalanmış SOL (wSOL) cinsinden bir ücret ödemesini isteyecek. İşte
[nihai program](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/main).

### ExtraAccountMetas Hesabı Başlatma Talimatı

Bu adımda, Transfer Hook programımız için `initialize_extra_account_meta_list`
talimatını uygulayacağız. Bu talimat, `transfer_hook` talimatımızın ihtiyaç duyduğu ek hesapları
saklayacak bir ExtraAccountMetas hesabı oluşturur.

Bu örnekte `initialize_extra_account_meta_list` talimatı 7
hesap gerektirir:

- `payer`: ExtraAccountMetas hesabının oluşturulması için ödeme yapan
  hesap.
- `extra_account_meta_list`: `transfer_hook` talimatımızın ihtiyaç duyduğu hesapların listesini saklamak için oluşturulan
  ExtraAccountMetas hesabı.
- `mint`: Bu Transfer Hook programını işaret eden Mint Account. Mint
  adresi, `extra_account_meta_list` PDA'sını türetmek için gerekli bir seed'dir.
- `wsol_mint`: Sarmalanmış SOL mint'i.
- `token_program`: Orijinal Token Program ID'si
- `associated_token_program`: Associated Token Program ID'si.
- `system_program`: Yeni hesaplar oluşturulurken gerekli bir hesap olan
  System Program.

`mint`, `wsol_mint` ve `associated_token_program` adresleri,
wSOL Associated Token Account adreslerini türetmek için kullanılacaktır. Bu
hesaplar `transfer_hook` talimatı için gereklidir ve
ExtraAccountMetas hesabında saklanacaktır.

Aşağıdaki başlangıç kodunu değiştirerek `InitializeExtraAccountMetaList` struct'ını
güncelleyin:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList {}
```

Aşağıda verilen kodla:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    pub wsol_mint: InterfaceAccount<'info, Mint>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}
```

Ardından, aşağıdaki başlangıç kodunu değiştirerek `initialize_extra_account_meta_list` talimatını
güncelleyin:

```rust
pub fn initialize_extra_account_meta_list(
    ctx: Context<InitializeExtraAccountMetaList>,
) -> Result<()> {
    Ok(())
}
```

Aşağıdaki kodla:

```rust
pub fn initialize_extra_account_meta_list(
        ctx: Context<InitializeExtraAccountMetaList>,
    ) -> Result<()> {
        // index 0-3 are the accounts required for token transfer (source, mint, destination, owner)
        // index 4 is address of ExtraAccountMetaList account
        // The `addExtraAccountsToInstruction` JS helper function resolving incorrectly
        let account_metas = vec![
            // index 5, wrapped SOL mint
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.wsol_mint.key(), false, false)?,
            // index 6, token program
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.token_program.key(), false, false)?,
            // index 7, associated token program
            ExtraAccountMeta::new_with_pubkey(
                &ctx.accounts.associated_token_program.key(),
                false,
                false,
            )?,
            // index 8, delegate PDA
```

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {
    msg!("Transfer WSOL using delegate PDA");

    let signer_seeds: &[&[&[u8]]] = &[&[b"delegate", &[ctx.bumps.delegate]]];

    // transfer WSOL from sender to delegate token account using delegate PDA
    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.to_account_info(),
            TransferChecked {

                mint: ctx.accounts.wsol_mint.to_account_info(),
```

### Fallback Talimatı

Son olarak, Token Extensions Program'dan gelen CPI'ı işlemek için Anchor programına bir fallback talimatı eklememiz gerekiyor.

Bu adım, Anchor'ın talimat discriminator'larını oluşturma biçimi ile Transfer Hook arayüzü talimatlarında kullanılanlar arasındaki farktan dolayı gereklidir. `transfer_hook` talimatının discriminator'ı, Transfer Hook arayüzünün discriminator'ıyla eşleşmeyecektir.

Aşağıdaki başlangıç kodunu değiştirerek `fallback` talimatını güncelleyin:

```rust
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    Ok(())
}
```

Aşağıdaki güncellenmiş kodla:

```rust
// fallback instruction handler as workaround to anchor instruction discriminator check
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    let instruction = TransferHookInstruction::unpack(data)?;

    // match instruction discriminator to transfer hook interface execute instruction
    // token2022 program CPIs this instruction on token transfer
    match instruction {
        TransferHookInstruction::Execute { amount } => {
            let amount_bytes = amount.to_le_bytes();

            // invoke custom transfer hook instruction on our program
            __private::__global::transfer_hook(program_id, accounts, &amount_bytes)
        }
        _ => return Err(ProgramError::InvalidInstructionData.into()),
    }
}
```

Fallback talimatı, gelen bir talimatın discriminator'ının Transfer Hook arayüzündeki `Execute` talimatıyla eşleşip eşleşmediğini kontrol eder. Eşleşme başarılı olursa Anchor programımızdaki `transfer_hook` talimatını çağırır.

<Callout type="info">

Şu anda bu süreci basitleştiren, henüz yayınlanmamış bir Anchor özelliği bulunmaktadır. Bu özellik, fallback talimatına duyulan ihtiyacı ortadan kaldıracaktır.

</Callout>

### Transfer hook'ta token account verisini kullanma

Bazen ek hesap meta'larındaki ek hesapları türetmek için hesap verisini kullanmak isteyebilirsiniz. Örneğin, token account'un sahibini bir PDA için seed olarak kullanmak istediğinizde bu yararlıdır.

ExtraAccountMeta oluştururken herhangi bir hesabın verisini ek seed olarak kullanabilirsiniz. Bu durumda, token account sahibinden ve 'counter' dizesinden bir sayaç hesabı türetmek istiyoruz. Bu, o token account sahibinin ne sıklıkla token transfer ettiğini her zaman görebileceğimiz anlamına gelir.

`extra_account_metas()` fonksiyonunda bunu şu şekilde ayarlarsınız.

```rust
// Define extra account metas to store on extra_account_meta_list account
impl<'info> InitializeExtraAccountMetaList<'info> {
    pub fn extra_account_metas() -> Result<Vec<ExtraAccountMeta>> {
        Ok(
            vec![
                ExtraAccountMeta::new_with_seeds(
                    &[
                        Seed::Literal {
                            bytes: b"counter".to_vec(),
                        },
                        Seed::AccountData { account_index: 0, data_index: 32, length: 32 },
                    ],
                    false, // is_signer
                    true // is_writable
                )?
            ]
        )
    }
}
```

Hesap verisinin nasıl saklandığını anlamak için token account struct'ına bakalım. Aşağıda bir token account yapısı örneği verilmiştir. Böylece 32. ile 64. konum arasındaki 32 baytı, 'account_index: 0' olan token account'un sahibi olarak alabiliriz. 'account_index', hesabın accounts dizisindeki indeksini ifade eder. Transfer hook durumunda, sahip token account'u accounts dizisindeki ilk girdidir. İkinci hesap her zaman mint, üçüncü hesap ise hedef token account'tur. Bu hesap sırası eski token programındakiyle aynıdır.

```rust
/// Account data.
#[repr(C)]

pub struct Account {

    pub mint: Pubkey,

```

Bizim durumumuzda, gönderen token account'un sahibinden bir sayaç hesabı türetmek istiyoruz; bu yüzden ExtraAccountMeta hesaplarını oluştururken, gönderen token account sahibinden ve 'counter' dizesinden türetilen bu PDA sayaç hesabını `init` ediyoruz. PDA sayaç hesabı başlatıldığında, her transferde değeri artırmak için bunu transfer hook içinde kullanabileceğiz.


Bu ek sayaç hesabını TransferHook struct'ında da tanımlamamız gerekir. Bunlar, her transfer yapıldığında TransferHook programımıza iletilen hesaplardır. İstemci bu ek hesapları ExtraAccountsMetaList PDA'sından alır ve token transfer talimatına dahil eder, ancak program içinde yine de tanımlamamız gerekir.

```rust
#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(token::mint = mint, token::authority = owner)]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(token::mint = mint)]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(seeds = [b"extra-account-metas", mint.key().as_ref()], bump)]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(seeds = [b"counter", owner.key().as_ref()], bump)]
    pub counter_account: Account<'info, CounterAccount>,
}
```
