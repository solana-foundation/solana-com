Aracı ödemeleri, yazılımın bir fiyatı keşfetmesine, ödemeyi yetkilendirmesine ve
kaynağı aynı HTTP iş akışı içinde almasına olanak tanır. Bir aracı, önce bir faturalama hesabı oluşturmadan
veya bir API anahtarını kopyalamadan bir veri sorgusu, model
çıkarımı ya da araç çağrısı için ödeme yapabilir.

## Ortak ödeme akışı

MPP ve x402 farklı başlıklar ve veri modelleri kullanır, ancak temel HTTP akışları
benzerdir:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP ve x402

Her iki protokol de Solana üzerinde stablecoin ödemelerinin mutabakatını sağlayabilir. Seçiminizi yalnızca ortak `402`
durum koduna göre değil, hizmetinizin ihtiyaç duyduğu
ödeme modeline ve birlikte çalışabilirliğe göre yapın.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Meydan okuma (challenge)               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| İstemci yetkilendirmesi    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Makbuz                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Solana ödeme modelleri   | Tek seferlik `charge` ve üst sınırlı, ölçümlü `session` amaçları (intent)           | `exact` ve `upto` gibi şemalar; destek ağa ve istemciye göre değişir |
| Mutabakat mimarisi | Sunucu doğrulaması veya isteğe bağlı bir röle ya da ağ geçidi                | Yerel doğrulama yapan kaynak sunucusu veya bir facilitator                 |
| İyi bir başlangıç noktası     | HTTP kimlik doğrulama semantiği veya tekrarlı ölçümleme gerektiren API'ler | İstek başına ödemeli kaynaklar ve mevcut x402 istemcileri                      |

MPP, **Machine Payments Protocol** anlamına gelir. Bunu **Model
Context Protocol (MCP)** ile karıştırmayın. MCP, araçları ve kaynakları aracılara sunar; MPP veya x402 ise
bir aracı bu araçlardan birini çağırdığında ödeme talep edebilir.

<Callout type="info">
  Bir hizmet birden fazla protokol sunabilir. İstemci, desteklediği bir ödeme
  seçeneğini seçer, ardından tüm değişim boyunca eşleşen meydan okuma, yetkilendirme ve
  makbuz başlıklarını kullanır.
</Callout>
