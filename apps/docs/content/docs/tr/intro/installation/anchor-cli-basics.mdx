Bu bölüm, [Anchor CLI](https://www.anchor-lang.com/docs) kullanmaya başlamanıza
yardımcı olacak bazı yaygın komutlar ve örnekler sağlar.

<Steps>
<Step>

### Projeyi başlatın

Aşağıda gösterilen komutu çalıştırarak yeni bir Anchor projesi oluşturun. Bu komut, proje adıyla yeni bir dizin oluşturur ve yeni bir Anchor projesini başlatmak için bu dizini kullanır.

```terminal
$ anchor init <project-name>
```

Örneğin, aşağıdaki komut `my-project` adlı bir proje oluşturur. `my-project` dizini, modüler bir Rust programı ve LiteSVM kullanan bir Rust test şablonu içerir.

```terminal
$ anchor init my-project
```

Bunun yerine TypeScript test şablonu oluşturmak için şablonu açıkça seçin. Örneğin, Mocha şablonunu kullanın:

```terminal
$ anchor init my-project --test-template mocha
```

TypeScript test şablonları Node.js ve bir JavaScript paket yöneticisi gerektirir.

Ardından proje dizinine gidin:

```terminal
$ cd <project-name>
```

Anchor'ın [proje dosya yapısına](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) göz atın.

</Step>
<Step>

### Programı derle

Projenizi derlemek için aşağıdaki komutu çalıştırın:

```terminal
$ anchor build
```

Derlenmiş programı `/target/deploy` dizininde bulabilirsiniz.

<Callout type="warn" title="Platform araçları yüklenemedi">
  Derleme işlemi geçersiz bir platform-tools dizini bildirirse SBF derleme araçlarını yeniden yükleyin, ardından derlemeyi tekrar deneyin:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Programı dağıtın

Projenizi dağıtmak için aşağıdaki komutu çalıştırın:

```terminal
$ anchor deploy
```

Bu komut, programınızı
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml)
dosyasında belirtilen `cluster` üzerine dağıtır.

</Step>
<Step>

### Programı test edin

Projenizi test etmek için aşağıdaki komutu çalıştırın:

```terminal
$ anchor test
```

Bu komut, projenizi derler, dağıtır ve testleri çalıştırır.

<Callout>
  `localnet` kümesi kullanılırken, Anchor otomatik olarak yerel bir validator
  başlatır, programı dağıtır, testleri çalıştırır ve ardından validator'ı
  durdurur.
</Callout>

<Callout type="warn" title="JavaScript test çalıştırıcısı hataları">

Bir JavaScript veya TypeScript test şablonu seçtiyseniz, aşağıdaki hatalardan herhangi biri Node.js'in veya yapılandırılmış paket yöneticisinin yüklü olmadığını gösterebilir:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
