七个概念构成了 Solana 开发的基础。从账户和程序开始，然后了解指令如何构成交易。PDA、CPI 和费用在此执行模型之上进一步延伸。

<DocsDiagram
  src="/assets/docs/diagrams/core-concepts.svg"
  alt="Solana core concepts, ordered from accounts and programs through instructions and transactions, with PDAs, CPIs, and fees"
/>

<Cards>
  <Card title="账户" href="/docs/core/accounts">
    Solana 将所有状态存储在账户中，这是一个以 32 字节地址为键的键值存储。每个账户有五个字段：lamport、数据、所有者、可执行标志和 rent_epoch。
  </Card>
  <Card title="程序" href="/docs/core/programs">
    Solana 的智能合约，编译为 sBPF。程序是无状态的，所有可变状态存储在通过指令传入的独立数据账户中。
  </Card>
  <Card title="指令" href="/docs/core/instructions">
    向某个程序发起执行请求，包含程序 ID、账户列表和不透明数据字节。多条指令可组合成一笔交易。
  </Card>
  <Card title="交易" href="/docs/core/transactions">
    Solana 上的原子执行单元。包含签名和消息（账户地址、最近的区块哈希及已编译的指令）。最大 1232 字节，使用 v1 格式时最大 4096 字节。
  </Card>
  <Card title="费用" href="/docs/core/fees">
    每个签名的基础费用为 5,000 lamport，另外还有基于所请求计算单元的可选优先费用。每笔交易最多可使用 140 万个计算单元。
  </Card>
  <Card title="Program Derived Addresses（PDA）" href="/docs/core/pda">
    由程序 ID 和种子确定性派生的地址。只有拥有该 PDA 的程序才能通过 invoke_signed 代表该 PDA 进行签名。
  </Card>
  <Card title="Cross-Program Invocations（CPI）" href="/docs/core/cpi">
    一个程序通过 invoke 或 invoke_signed 调用另一个程序。签名者和可写权限会延伸至被调用方。指令调用栈最大深度为 5（顶层调用加上 CPI）。
  </Card>
</Cards>
