## 密钥管理

- **切勿在前端代码中暴露私钥。** 请使用后端签名、硬件钱包、多签钱包或密钥管理服务。
- **区分热钱包和冷钱包。** 热钱包用于日常操作,冷钱包用于存放资金库资产。
- **备份所有生产环境密钥。** 将加密备份存储在多个安全位置。密钥丢失意味着永久失去访问权限。
- **开发网和主网使用不同的密钥。** 开发网密钥不应与主网密钥相同。请使用基于环境的配置,确保每个网络加载正确的密钥。

## 签名基础设施

对于生产环境的后端签名,请使用 [Keychain](/docs/tools/keychain)——一个统一的签名库,通过单一接口对多种密钥管理后端进行抽象,包括:Memory、Vault、Privy、Turnkey、AWS KMS、Fireblocks、GCP KMS、CDP、Para、Dfns、Crossmint、Openfort 和 Utila。这样您可以使用内存密钥在本地进行开发,然后在不更改应用程序代码的情况下切换到生产级后端。

不确定哪种后端适合您?请参阅[选择后端](/docs/tools/keychain/choosing-a-backend)。Keychain 同时提供 [Rust](https://crates.io/crates/solana-keychain) 和 [TypeScript](https://www.npmjs.com/package/@solana/keychain) 版本。

## RPC 安全

请像对待 API 密钥一样对待 RPC 端点——不要在前端代码中暴露它们,否则可能被提取并滥用。请使用后端代理,或不会被打包进客户端代码的环境变量。

- [QuickNode:端点安全最佳实践](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius:保护您的 Solana API 密钥——安全最佳实践](https://www.helius.dev/docs/rpc/protect-your-keys)

## 监控

在生产环境中跟踪以下指标:

| 指标                   | 原因                    |
| ------------------------ | ---------------------- |
| 交易成功率 | 及早发现问题    |
| 确认延迟     | 监控网络健康状况 |
| 优先费用支出       | 成本管理        |
| RPC 错误率           | 服务提供商健康状况        |

为以下情况设置警报:

- 从资金库发起的转账超过阈值
- 交易失败率激增
- 异常的接收方模式
- RPC 错误率上升

如需大规模实时交易监控,请参阅我们的[索引指南](/docs/payments/accept-payments/indexing)。

## 验证地址

每个代币和程序在主网上都只有一个正确的地址。仿冒 USDC 或其他稳定币的欺诈代币十分常见——它们的名称和符号相同,但 mint 不同。您的应用程序应硬编码或使用白名单(根据您的需求)管理 mint 地址,切勿动态接受来自不受信任来源的地址。

**基于环境的配置:** 开发网和主网通常使用完全不同的代币 mint。请将应用程序配置设置为按环境加载正确的地址——不要硬编码主网地址后在测试时忘记替换,更糟糕的是将开发网地址部署到生产环境。

一些常见的稳定币 mint 如下:

| 代币 | 发行方 | Mint 地址                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

程序地址同样重要。向错误的程序发送指令将会失败——更糟糕的是,可能导致资金不可逆转地丢失。Token Program 的地址如下:

| 程序            | 地址                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Program | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

将正确的地址加入白名单可以防范仿冒代币,但无法防止将资产发送到错误_类型_的账户。接收地址可能是钱包、token account、mint 或程序,每种类型都需要不同的处理方式。如果将原生 SOL 发送到钱包以外的任何地址,发送方将失去对这些资产的控制——发送到 mint 或程序会彻底丢失,发送到 token account 则只有该账户的所有者才能找回——而且不会出现交易失败来提醒用户。

<Callout type="warn" title="发送前验证接收方">
  在签署转账之前,请对每个接收地址进行分类。有关区分钱包、token account、mint 和程序的完整决策树及参考代码,请参阅[验证地址](/docs/payments/send-payments/verify-address)。
</Callout>
