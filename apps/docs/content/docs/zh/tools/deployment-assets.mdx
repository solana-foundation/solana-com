---
title: 部署资产
description: 为部署到主网准备您的程序构建产物
---

在将应用部署到主网之前,请确保您已准备好以下内容:

- 程序 ELF 文件 - 通常是执行 `anchor build` 或
  `cargo-build-sbf` 后生成的以 `.so` 结尾的文件
- 程序 keypair - 一个包含整数数组的 JSON 文件

在本节中,我们将介绍如何找到这些资产以及如何准备它们。

## 准备您的 ELF 文件

ELF 文件包含已编译的字节码、内存布局信息以及元数据,Solana 虚拟机(SVM)需要这些信息来了解如何加载并运行您的程序。ELF 文件在源代码编译时生成。

要创建 ELF 文件,对于 Anchor,您可以运行以下命令:

```bash
anchor build
```

对于其他框架,则运行以下命令:

```bash
cargo build-sbf
```

随后,您可以在类似 `target/deploy/<PROGRAM_NAME>.so` 的目录中找到您的 ELF 文件。

当 ELF 文件被编译为 [sBPFv3](https://www.anza.xyz/blog/migrating-solana-programs-to-sbpfv3) 时,您的程序即已准备就绪。要检查您的程序,可以在 Linux 上运行以下命令:

```bash
readelf -h target/deploy/<PROGRAM_NAME>.so | grep Flags:
```

在 macOS 上则运行以下命令:

```bash
# brew install llvm
$(brew --prefix llvm)/bin/llvm-readelf -h target/deploy/<PROGRAM_NAME>.so | grep Flags:
```

如果您看到类似下面的输出,说明您的程序已准备就绪:

```
  Flags:                             0x3
```

如果不是,请按照此处链接的迁移指南操作:[此处](https://solana.com/upgrades/sbpfv3-programs)。

## 准备您的程序地址

您的程序地址就是用于调用程序指令的程序 ID。您可以:1)使用构建过程中生成的程序 keypair;2)通过暴力搜索生成一个地址以自定义前缀开头的新 keypair;或 3)由基础地址和 seed 派生出一个账户地址。前两种方式会生成可为 program account 签名的 keypair。使用 seed 创建的账户没有自己的私钥,而是由基础账户控制。

### 使用生成的 keypair

默认情况下,`anchor build` 和 `cargo build-sbf` 会将程序 keypair 放置在:

```text
target/deploy/<PROGRAM_NAME>-keypair.json
```

请在清理构建目录之前备份此文件。任何能够访问该 keypair 的人都可以以 program account 的身份签名,因此请勿将其提交到源代码管理中。

### 通过暴力搜索生成带自定义前缀的 keypair

使用 [`vanity`](https://github.com/cavemanloverboy/vanity) 搜索公钥以特定 base58 前缀开头的 Ed25519 keypair。从 crates.io 安装 CPU 版本:

```bash
cargo install vanity
```

该项目还提供 CUDA、Metal 和 OpenCL 构建版本,用于 GPU 加速搜索。有关各后端的要求,请参阅 `vanity` 的安装说明。

```bash
vanity grind-keypair --pattern Acme...
```

找到匹配项后,`vanity` 会输出公钥、十六进制格式的私钥 seed,以及兼容 Solana 的 keypair JSON 数组。请将该 JSON 文件保存在安全的位置,然后确认其中包含预期的公钥:

```bash
solana-keygen pubkey path/to/keypair.json
```

请将命令输出和保存的 JSON 文件视为私钥材料妥善保管。

### 使用 seed 创建账户

为了更快地搜索,`vanity grind` 会为 `CreateAccountWithSeed` 搜索 seed 字符串,而不是生成 Ed25519 keypair。请提供将授权创建账户的基础账户的公钥、账户所有者以及要搜索的前缀。对于可升级的 program account,请使用可升级 BPF 加载器作为所有者:

```bash
vanity grind \
  --base <BASE_ACCOUNT_PUBKEY> \
  --owner BPFLoaderUpgradeab1e11111111111111111111111 \
  --pattern Acme...
```

结果包含派生出的地址和一个 seed 字符串。请在创建账户之前验证它们:

```bash
vanity verify \
  --base <BASE_ACCOUNT_PUBKEY> \
  --owner BPFLoaderUpgradeab1e11111111111111111111111 \
  --seed <SEED>
```

使用相同的基础地址、seed 和所有者,通过 `Pubkey::create_with_seed` 派生地址,然后提交 System Program 的 `create_account_with_seed` 指令。基础账户和出资账户必须对交易进行签名。由于派生账户没有独立的 keypair,此方式需要使用基础账户而非程序 keypair 文件的账户创建和部署流程。

### 更新源代码中的程序地址

选定 keypair 或基于 seed 创建的账户后,请在项目中所有声明程序 ID 的地方使用其公开地址。如果源代码中仍包含旧地址,客户端可能会将指令发送到错误的程序,运行时的 ID 检查也可能失败。

在 Anchor 工作区中,请同时更新根目录 `Anchor.toml` 中的程序条目以及 `programs/<PROGRAM_NAME>/src/lib.rs` 中的 `declare_id!` 调用。`[programs.<CLUSTER>]` 下的键是程序在工作区中的名称。请更新您打算使用新地址的每一个集群表;下面的示例更新的是主网。

在 Anchor.toml 中:

```diff
 [programs.mainnet]
-my_program = "<OLD_PROGRAM_ID>"
+my_program = "<NEW_PROGRAM_ID>"
```

在 `programs/<your_program>/lib.rs` 中:

```diff
-declare_id!("<OLD_PROGRAM_ID>");
+declare_id!("<NEW_PROGRAM_ID>");
```

Pinocchio 不使用 `Anchor.toml`。请更新程序 crate 的 `src/lib.rs` 中的 `declare_id!` 调用。当前的 Pinocchio 项目从 `pinocchio::address` 导入该宏。

Quasar 同样在链上程序 crate 的 `src/lib.rs` 中声明地址,并且不使用 `Anchor.toml`。`declare_id!` 宏可通过 `quasar_lang::prelude::*` 使用。

更改地址后,请重新构建程序,并重新生成所有 IDL 或客户端产物。此外,还请在部署脚本、测试和应用配置中搜索旧的程序 ID,并替换所有硬编码的引用。
