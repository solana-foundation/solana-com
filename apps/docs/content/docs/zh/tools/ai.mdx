# 在 Solana 上使用 LLM 与智能体

在深入了解具体工具之前，让我们先了解 AI
开发技术栈中的关键组成部分：

## 理解 AI 技术栈

1. **大型语言模型（LLM）**
   - 基础 AI 模型（如 GPT-4、Claude 或 Llama）
   - 处理并生成自然语言
   - 提供原始智能与推理能力
   - 示例：OpenAI 的 GPT-4、Anthropic 的 Claude、Meta 的 Llama

2. **智能体框架（如 Eliza）**
   - 基于 LLM 构建，用于创建自主智能体
   - 管理智能体的个性与行为
   - 处理记忆与上下文
   - 提供多平台集成
   - 示例：Eliza、LangChain、AutoGPT、Vercel AI

3. **领域专用智能体套件（如 Solana Agent Kit）**
   - 专为特定用例构建（例如区块链操作）
   - 提供预构建的工具与集成
   - 屏蔽底层技术复杂性
   - 开箱即用的区块链功能
   - 示例：Solana Agent Kit、GOAT Toolkit

可以这样理解：

- LLM 是能够理解和生成语言的「大脑」
- 智能体框架是管理 AI 行为的「操作系统」
- 领域专用套件是赋予 AI 特定能力的「应用程序」

# 为 Solana 构建 AI 智能体

本指南将向您展示如何：

- 使用 SendAI 的 Solana Agent Kit 构建基础 AI 智能体
- 使用 Eliza 框架创建 Twitter 机器人
- 了解链上 AI 集成方案
- 构建高级交易机器人的多种方案

## Solana 上的 AI 智能体简介

Solana 上的 AI 智能体是能够通过自然语言处理和机器学习与
区块链交互的自主程序。它们可以：

- 执行交易
- 监控区块链活动
- 与智能合约交互
- 提供用户协助
- 自动化复杂工作流

## 可用框架

目前有多种框架可用于在 Solana 上构建 AI 智能体：

1. **SendAI 的 Solana Agent Kit**

- 用于在 Solana 上构建智能体的工具集合
- 兼容 Eliza、Langchain 和 Vercel AI SDK
- 内置 Solana 工具与实用程序
- 自然语言处理能力
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [文档](https://docs.solanaagentkit.xyz/)

2. **Eliza 框架**

- 整合了数据层、LLM 与智能体，并提供专用的 Solana 插件
- 可扩展的智能体架构
- 易于与现有项目集成，例如可用于创建
  Twitter (X)、Telegram 或 Discord 机器人
- [GitHub 仓库](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- 全面的开发工具包
- 跨链兼容性
- [GitHub 仓库](https://github.com/goat-sdk/goat)

4. **Rig 框架**

- 原生 Rust 实现
- 适合高性能交易机器人
- 可与 Listen.rs 工具包结合，实现 Solana 集成交易
  监控，以及使用 Jito bundles 发送交易等功能
- [GitHub 仓库](https://github.com/0xPlaygrounds/rig)
- [Listen.rs 仓库](https://github.com/piotrostr/listen)

如果您正在构建 AI 框架，欢迎提交 PR 将您的框架添加到列表中

### 创建智能体脚本

创建一个名为 `agent.ts` 的新文件，内容如下：

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## 使用 Eliza 框架构建

[ElizaOS](https://github.com/elizaOS/eliza)（前身为 Ai16z）是一个
AI 框架，它将多个应用整合为一体并协调其交互。它整合了：

1. 不同的 LLM 以理解用户
2. 具有不同操作的区块链智能体（例如铸造 NFT）
3. 用于在操作之间存储角色状态的数据层，例如
   Redis、PostgreSQL 数据库或本地存储
4. 不同的客户端，如 X、Telegram、Discord 等

它将所有这些整合在一起，使您能够创建一个可与用户交互或自主运行的
「角色」。这些角色在 JSON 文件中定义，该文件规定了角色可执行的操作、
应使用的 LLM 以及定义角色行为的各种提示词。

### 创建角色配置

要创建新角色，我们需要创建一个 character.json 文件。您可以在 Eliza 项目的
characters 文件夹中找到预设角色。创建新角色时，您可以复制并修改

```json filename=characters/sol.character.json

    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
```

这里最重要的部分是 clients 和 modelProvider。在我们的案例中，

## 链上程序智能体集成

如果你想在 Solana 程序中使用代理的回复，你需要使用一个预言机，将回复数据写入你的程序可以读取的账户中。你可以在这里找到一个 LLM 的示例，该示例会将代币转移给任何正确回答问题的用户：

[链上程序与 LLM 的交互](https://github.com/GabrielePicco/super-smart-contracts)

这是一个链上程序示例，该程序与 LLM（AI）预言机集成，创建了一个名为"Mar1o"的交互式代币分发代理。

### 核心功能

1. **AI 代理交互**
   - 用户可以与 Mar1o 聊天，尝试赚取代币
   - 代理根据用户的 Solana 知识评估来决定代币数量
   - 响应为 JSON 格式，包含回复文本和代币数量

2. **代币管理**
   - 创建带有元数据的 MAR1O 代币
   - 可根据 AI 响应铸造 0 至 10,000 枚代币
   - 使用 PDA 进行代币管理

### 程序流程说明

以下是该程序的工作原理：

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

这展示了如何将 AI 能力与链上代币机制相结合，从而创造交互式区块链体验。这里有一个[实时示例](https://mar1o.xyz/)，你可以尝试说服代理向你转移一些代币。

## 用于算法交易的高级 Rust 代理

如果你想用 Rust 编写代理，可以使用
[Rig 框架](https://github.com/0xPlaygrounds/rig)和
[Listen.rs](https://github.com/piotrostr/listen) 库。

这两者配合得非常好。Rig 框架为你提供了连接 LLM 的便捷方式，而 Listen.rs 工具包则提供了 Solana 集成功能，包括交易监控以及使用 Jito bundles 发送交易等。

## 最佳实践

- 请注意，你的代理拥有私钥，因此可以访问你钱包中的资金。如果有人能与你的代理聊天，而代理具有转账功能，用户可能会诱导它将你的资金转走。
- 请使用付费的[RPC 端点](https://solana.com/rpc)。公共端点通常会受到频率限制。
- 监控代理的活动，确保其没有进行任何恶意操作，也没有被与之交互的用户诱导进行恶意行为。
- 为代理操作实现优先费用和交易重试机制，以确保在网络拥堵时交易也能成功上链。
- 如果可能，在部署到主网之前先在开发网上进行测试。大多数代理只需将 RPC URL 作为输入，在准备好上主网之前可以使用开发网的 URL。不过，并非所有操作都可以在开发网上执行。
- 在编写自定义操作时，为其添加集成测试，以便框架能够监控哪些操作因程序或 API 变更而失败。

## 总结

Solana 上的 AI 代理为区块链的自动化与交互开辟了新的可能性。尽管目前并非所有集成都已臻于完善，但它们发展迅速，提供了大量贡献机会，并且在添加自定义集成方面极具灵活性。
