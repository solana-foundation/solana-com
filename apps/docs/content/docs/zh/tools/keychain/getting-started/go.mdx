2.0.0 是 Go 模块的首个稳定版本,因此无需迁移。[2.0 迁移指南](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)介绍了 Rust 和 TypeScript 中相同的能力拆分。

## 安装

每个后端都是独立的 Go 模块,因此你的构建和模块依赖图中只包含你实际导入的后端:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

模块标签格式为 `go/<module>/v2.0.0`(例如 `go/signers/memory/v2.0.0`)。所有模块都要求 Go 1.25.0,但 `gcpkms` 除外,它要求 Go 1.25.8,这是由 `google.golang.org/api` 设定的最低版本所致。Ledger 仅支持 Rust,没有 Go 模块。

### solana-go v2 与 v1 交易

这些模块基于 [`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go) v2.0.0 构建,接收其 `*solana.Transaction`。支持 Legacy、v0 和 v1(`solana.MessageVersionV1`)交易,但启用 `UseProgramCall: true` 的 Fireblocks 例外,它仅接受 Legacy 和 v0。

## 基本用法

每个签名器都实现基础的 [`core.SolanaSigner` 接口](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)(`Pubkey`、`SignMessage`、`IsAvailable`)。方法接收 `context.Context` 并会阻塞。每个后端还恰好实现一个能力接口:

- `core.TransactionSigner`:`SignTransaction` 按原样对你的交易签名。
- `core.ModifyingSigner`:`ModifyAndSignTransaction` 允许服务商改写交易,然后再签名。
- `core.SendingSigner`:`SignAndSendTransaction` 由服务商签名并广播交易。

每个后端包都提供一个 `Config` 结构体和一个 `New` 构造函数:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` 和 `ModifyAndSignTransaction` 返回 `core.SignedTransaction`(`EncodedTransaction`、`Signature`、`Completeness`)。远程 HTTP 后端接受可选的 `HTTPClient` 和 `HTTPClientConfig`(超时设置)。默认客户端强制使用 HTTPS;若提供自定义客户端则会绕过该限制,其安全性由你自行负责。

### 签名器能力

无法对交易签名的后端根本不带 `SignTransaction` 方法,因此对于具体类型,能力是编译期确定的事实;对于 `core.SolanaSigner`,则通过类型断言判断:

| 后端                                                                         | 能力          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | 是                            |
| cdp                                                                             | `TransactionSigner` | 仅支持 UTF-8 负载            |
| utila                                                                           | `TransactionSigner` | 失败并返回 `CodeSigningFailed` |
| fordefi 黑盒(`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | 是                            |
| fordefi 原生手动(`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | 是                            |
| fordefi 原生自动(`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | 是                            |
| crossmint                                                                       | `SendingSigner`     | 失败并返回 `CodeSigningFailed` |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### 初始化

没有单独的 `Init` 步骤。Privy、Fireblocks、Dfns、Crossmint、Para、Openfort 和 Utila 在 `New` 内部解析钱包地址,因此它们的构造函数接收 `context.Context`。请始终通过 `New` 构建签名器:零值的 Crossmint、Para 或 Utila 签名器会返回 `CodeNotInitialized` 错误,而不是为零地址签名。

### 使用任意签名器签名并发送

`core.SignAndSendTransaction` 无论签名器是哪种形态,都能将交易上链。`SendingSigner` 通过其服务商广播,并忽略发送函数;其他形态则先签名,再由你的函数广播 base64 结果,对于 `ModifyingSigner`,该结果是其服务商改写后的交易。Core 不依赖 RPC:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### 批量签名

批量签名以独立辅助函数的形式提供,支持并发,并可为有速率限制的 API 设置可选的逐请求错开间隔:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` 接收 `core.TransactionSigner`,因此由服务商托管广播的签名器(Crossmint、Fordefi 原生自动)以及 Fordefi 原生手动无法通过它批量处理;请逐笔交易调用。若签名器的调用会在服务商侧产生工作(启用 `UseProgramCall` 的 Fireblocks),则通过 `core.BatchServerSideEffects` 上报,此时批处理将按顺序执行。

## 后端配置

### 内存

请恰好提供以下之一:`PrivateKey`(原始字节)、`PrivateKeyString`(base58 或 `[1,2,...]` 字节数组)或 `PrivateKeyPath`(Solana CLI keypair 文件):

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Go 没有可靠的内存清零方式:垃圾回收器可能会复制并保留密钥字节(内存 keypair,以及 Crossmint 和 Openfort 在本地派生的密钥),直到被回收。使用本地密钥后端时,请将整个进程内存视为敏感数据。

### Crossmint

Crossmint 仅支持发送:其 API 在服务端执行每一笔获批交易,因此 `*crossmint.Signer` 只有 `SignAndSendTransaction`,没有 `SignTransaction`。你的交易不会被修改;返回的签名标识的是 Crossmint 实际落链的交易,如果 Crossmint 代付 gas,则可能与你的交易不同。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Fordefi

Fordefi 提供三种签名器类型,由 `Config.Chain` 和 `Config.PushMode` 在构造时确定。三者都支持消息签名:

| 配置                                          | 类型                          | 入口                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| 未设置 `Chain`                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| 已设置 `Chain`,`PushMode` 未设置或为 `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| 已设置 `Chain`,`PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` 根据配置分派并返回 `core.SolanaSigner`;`fordefi.NewBlackBox`、`fordefi.NewNativeAuto` 和 `fordefi.NewNativeManual` 返回具体类型,并拒绝其他模式的配置。API 请求使用 ECDSA P-256 请求签名进行认证:请在 `PrivateKeyPEM` 与 `RequestSigner` 中恰好提供一个(后者可将该密钥保留在 KMS/HSM 中)。

**原生自动模式**:Fordefi 可能会替换 blockhash 和费用,然后签名并广播。它只接受未签名、且唯一所需签名者是该 vault 的交易。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**原生手动模式**:设置 `PushMode: fordefi.PushModeManual`。Fordefi 会改写消息(recent blockhash、Compute Budget 费用指令)并签名,但不广播。`ModifyAndSignTransaction` 会用 Fordefi 签名后的交易替换 `tx`:请始终基于它继续操作。Fordefi 必须是费用支付方,并且必须先于任何其他所需签名者签名,因为改写会使现有签名失效。改写内容不会生成差异对比,因此广播前请检查结果。

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**黑盒模式**:不设置 `Chain`。Fordefi 对你的消息字节原样签名,不进行广播。请搭配 Fordefi 黑盒 vault 使用。

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## 为什么没有统一入口包

Rust 有 `Signer` 枚举,TypeScript 有 `createKeychainSigner`;Go 则有意两者都不提供。Go 不会跨运行时分派的 switch 消除死代码,因此统一入口包会把每个后端的供应商 SDK(AWS、GCP 等)都拉进每个使用者的构建中。导入你需要的后端包就是选择器。若要在运行时选择后端,请在你自己的代码中仅针对所支持的后端编写 switch,并将结果持有为 `core.SolanaSigner`。

## 错误处理

每个错误都是带有稳定 `Code` 的 `*core.SignerError`(`CodeConfigError`、`CodeHTTPError`、`CodeRemoteAPIError`、`CodeSigningFailed`、`CodeNotInitialized`、`CodeBroadcastUnconfirmed` 等)。`Error()` 对每个错误码只返回固定消息,绝不包含密钥材料或服务商的原始响应。可使用 `errors.As`、`errors.Is(err, &core.SignerError{Code: ...})` 或 `core.CodeOf(err)` 进行匹配。

对于 Crossmint 和 Fordefi 原生自动模式,失败并不意味着交易没有上链。当服务商可能已接受该交易时,错误码为 `core.CodeBroadcastUnconfirmed`(`"SIGNER_BROADCAST_UNCONFIRMED"`)。创建请求被接受时会设置 `ProviderTxID`,`IdempotencyKey` 则携带由消息派生的密钥。重新发送字节完全相同的交易是安全的;重新构建的交易(例如使用新的 blockhash)则是一笔新的转账。当你的发送函数失败时,`core.SignAndSendTransaction` 也会报告此错误码,并在 `TransactionSignature` 中附上费用支付方签名。Fireblocks PROGRAM_CALL 仅签名且不发送密钥;只有轮询显示 Fireblocks 仍然广播了交易时,才会报告此错误码。

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

请参阅[安全模型](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md)了解各种签名形态提供的保证,参阅 [Go README](https://github.com/solana-foundation/solana-keychain/blob/main/go/README.md) 获取完整模块列表,参阅 [pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2) 查看 API 参考。

## 添加自定义签名器

请实现 `core.SolanaSigner` 以及恰好一个能力接口,且不要添加后端无法支持的方法:调用方通过类型断言检测能力。若要集成更多密钥管理服务,请参阅[添加签名器指南](/docs/tools/keychain/adding-signers)。
