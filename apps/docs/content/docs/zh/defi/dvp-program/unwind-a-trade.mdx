有四条指令可以在不结算的情况下退还资金:交易开放期间可使用 Reclaim、Cancel 和 Reject,交易关闭后才到账的存款则使用 Recover。它们都不会检查到期时间。如末尾的说明所述,被冻结的 escrow 或被更改的 mint 仍可能导致某条交易腿的资金无法取出。

| 指令  | 签名者               | 范围                         | 之后的交易状态 |
| ------------ | -------------------- | ----------------------------- | ---------------- |
| `ReclaimDvp` | `user_a` 或 `user_b` | 签名者自己的交易腿          | 仍保持开放       |
| `CancelDvp`  | 结算授权方 | 两条交易腿                     | 已关闭           |
| `RejectDvp`  | `user_a` 或 `user_b` | 两条交易腿                     | 已关闭           |
| `RecoverDvp` | `user_a` 或 `user_b` | 交易关闭后签名者的交易腿 | 早已关闭   |

在每种情况下,escrow 中持有的全部资产都会退还给该交易腿所属的一方:escrow A 退到 `user_a` 用于 `mint_a` 的 token account,escrow B 退到 `user_b` 用于 `mint_b` 的 token account,无论由谁出资。对于要求附带 memo 的退款账户,需要提供 memo program account。

本页接续前面的步骤:[创建交易](/docs/defi/dvp-program/create-a-trade)中的客户端和签名者、[为交易腿注资](/docs/defi/dvp-program/fund-the-legs)中的 `userAAtaA` 和 `userBAtaB`,以及[结算交易](/docs/defi/dvp-program/settle-the-trade)中的 `MEMO_PROGRAM_ID` 和 `authority` 均沿用至此。

## 取回一条交易腿

Reclaim 会退还签名者的交易腿并保持交易开放,因此该交易腿可以再次注资。当问题出在对手方的交易腿上时,请使用它;Cancel 和 Reject 则会关闭整笔交易。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getReclaimDvpInstruction } from "./dvp";

    // The asset-leg party takes its asset back.
    const reclaimInstruction = getReclaimDvpInstruction({
      signer: userASigner,
      swapDvp,
      mint: mintA,
      dvpSourceAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
    });

    await client.sendTransaction([reclaimInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::ReclaimDvpBuilder;

    // The asset-leg party takes its asset back.
    let reclaim_ix = ReclaimDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .mint(mint_a)
        .dvp_source_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .instruction();
    ```

  </Tab>
</Tabs>

## 取消或拒绝

Cancel 由结算授权方签名,Reject 由任一交易方签名。两者都会把每个 escrow 中持有的资产退还给对应交易腿所属的一方,并关闭交易记录和两个 escrow,已关闭账户的 rent 归签名者所有。这两条指令使用相同的账户,只是签名者不同。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCancelDvpInstruction, getRejectDvpInstruction } from "./dvp";

    const unwindAccounts = {
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    };

    // Signed by the settlement authority:
    const cancelInstruction = getCancelDvpInstruction({
      settlementAuthority: authoritySigner,
      ...unwindAccounts,
    });

    // Or signed by either party:
    const rejectInstruction = getRejectDvpInstruction({
      signer: userBSigner,
      ...unwindAccounts,
    });
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::{CancelDvpBuilder, RejectDvpBuilder};

    // Signed by the settlement authority:
    let cancel_ix = CancelDvpBuilder::new()
        .settlement_authority(authority)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();

    // Or signed by either party:
    let reject_ix = RejectDvpBuilder::new()
        .signer(user_b)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();
    ```

  </Tab>
</Tabs>

只要某条交易腿持有余额,其退款账户(`userAAtaA`、`userBAtaB`)就必须存在;未初始化的退款账户会导致代币转账失败,并使该指令回滚。从未注资的交易腿无需转账,因此允许对应账户缺失。

## 找回迟到的存款

Settle、Cancel 和 Reject 都会关闭两个 escrow token account,因此直接向已关闭的 escrow 转账会失败。只有当有操作先重新创建了 escrow,存款才会在关闭之后到账,例如:注资交易在转账之前包含了一条 create-idempotent associated token account 指令,而该交易在对手方发送 Reject 时仍在途中。此时代币会留在一个所属交易已不存在的 escrow 中:交易记录已消失,Reclaim 无法找到它,而 nonce 墓碑会阻止在同一地址创建新交易并截获这笔存款。

使用 `RecoverDvp` 时,交易腿所属一方需要提供原始的 seed 输入(结算授权方、双方、两个 mint、nonce)。程序会重新推导交易记录地址,要求其墓碑作为该交易曾经存在的证明,把 escrow 中的资产全部转入签名者自己的 token account,并关闭该 escrow,同时把 escrow 的 rent 退还给签名者。签名者对应的交易腿由签名方决定:`user_a` 对应 `mint_a`,`user_b` 对应 `mint_b`。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getAddressEncoder, getProgramDerivedAddress } from "@solana/kit";
    import { DVP_SWAP_PROGRAM_PROGRAM_ADDRESS, getRecoverDvpInstruction } from "./dvp";

    const [nonceTombstone] = await getProgramDerivedAddress({
      programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
      seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
    });

    const recoverInstruction = getRecoverDvpInstruction({
      signer: userASigner,
      swapDvp,
      nonceTombstone,
      mint: mintA,
      dvpEscrowAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });

    await client.sendTransaction([recoverInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::RecoverDvpBuilder;

    let recover_ix = RecoverDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .nonce_tombstone(nonce_tombstone)
        .mint(mint_a)
        .dvp_escrow_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .settlement_authority(settlement_authority)
        .user_a(user_a)
        .user_b(user_b)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .nonce(nonce)
        .instruction();
    ```

  </Tab>
</Tabs>

恢复能否成功取决于该方是否保留了创建参数。为交易注资的系统应在每笔订单中保存 seed 输入,直到交易关闭且已确认 escrow 余额为空。

## 注意事项

- **被冻结的交易腿。** 对于带有准入控制的 mint,被冻结的 escrow 会阻止这些指令执行的代币转账,直到冻结授权方解冻为止。请参阅[概览](/docs/defi/dvp-program#mint-configuration-constraints)。
- **创建后 mint 发生变更。** 撤销路径会跳过扩展和 mint 权限检查,使程序自身的检查不会阻碍资金恢复。不过 token program 自身的规则仍然适用。mint 只有在供应量为零时才能被关闭,因此在 escrow 中仍有余额时它不会改变;但如果在迟到的存款到账之前,mint 被关闭并重新创建为 NonTransferable 或带有转账手续费的形式,这笔存款可能变得无法转移或需要承担手续费。这就是[支持的代币](/docs/defi/dvp-program#supported-tokens)中列出的对 mint 权限的依赖。
