Інтерфейс командного рядка `solana` налаштовує підключення до кластера, зчитує
стан мережі, надсилає SOL, керує durable nonce, розгортає програми та працює
з акаунтами стейкінгу й голосування.

Цей довідник відповідає [Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Виконайте
`solana --version`, щоб перевірити встановлену версію, і використовуйте `--help`, щоб побачити точні
параметри, доступні в цій версії.

<Callout type="warn">
  Команди, що створюють, переказують, авторизують, виводять або розгортають, надсилають
  транзакції. Перш ніж виконувати їх, перевірте налаштований кластер і підписувача.
  Токени Devnet і Testnet не мають вартості; команди Mainnet використовують реальні SOL.
</Callout>

## Структура команд

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Отримайте довідку на будь-якому рівні:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Глобальні параметри

Глобальні параметри можна розміщувати перед командою. Довідка конкретної команди повторює
параметри, що до неї застосовуються.

| Параметр                          | Призначення                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Вибрати URL RPC або `mainnet-beta`, `testnet`, `devnet` чи `localhost`.      |
| `--ws <URL>`                    | Перевизначити кінцеву точку WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Вибрати файл keypair, `ASK`, stdin (`-`) або підтримуваний URL підписувача.          |
| `-C, --config <FILEPATH>`       | Використати інший файл конфігурації CLI.                                        |
| `--commitment <LEVEL>`          | Читати з рівнем підтвердження `processed`, `confirmed` або `finalized`.                   |
| `--output <FORMAT>`             | Повернути `json` або `json-compact`, де це підтримується.                               |
| `--skip-preflight`              | Надіслати без симуляції RPC. Використовуйте лише тоді, коли розумієте компроміс щодо можливих помилок. |
| `--use-tpu-client`              | Надсилати транзакції через клієнт TPU.                                      |
| `--no-address-labels`           | Виводити адреси без локальних міток.                                          |
| `--skip-seed-phrase-validation` | Дозволити фразу відновлення поза англійським списком BIP39.                       |
| `-v, --verbose`                 | Показувати додатковий вивід команди.                                                |
| `-V, --version`                 | Вивести версію встановленого CLI.                                               |

## Налаштування CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

Конфігурація містить URL RPC, URL WebSocket, підписувача за замовчуванням і
рівень підтвердження. Параметр командного рядка перевизначає збережене значення для цього виклику.

## Типові робочі процеси з акаунтами й транзакціями

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` за замовчуванням приймає SOL. Вкажіть `ALL` як суму, щоб переказати весь доступний
баланс після сплати комісій. Приклади з токенами дивіться в
[короткому посібнику з токенів](/docs/tokens/quickstart).

## Робочі процеси з програмами

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Передайте `--program-id <KEYPAIR_OR_ADDRESS>`, коли розгортання має використовувати відомий
ідентифікатор програми. `--final` робить нове розгортання незмінним; уважно прочитайте його довідку
перед використанням, оскільки повноваження на оновлення неможливо відновити.

## Робочі процеси з durable nonce

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Використовуйте `authorize-nonce-account`, щоб змінити повноваження над nonce, і `nonce-account`,
щоб переглянути повний стан акаунта. Транзакції з nonce також приймають
`--nonce` і `--nonce-authority` у підтримуваних командах.

## Робочі процеси зі стейкінгом

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

Деактивація завершується на межі epoch і може тривати більше ніж один epoch.
Використовуйте `stakes`, `validators`, `stake-history` і `stake-minimum-delegation`, щоб
перевірити стан кластера та делегування перед надсиланням змін.

## Утиліти для адрес

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

seed для PDA мають формат `PREFIX:VALUE`. Підтримувані префікси: `string`, `pubkey`,
`hex`, `u8` та кодування цілих чисел зі знаком або без знака фіксованої ширини, наприклад
`u64le`.

## Off-chain повідомлення та автодоповнення в оболонці

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Вивід для скриптів

Використовуйте `--output json` або `--output json-compact`, де це підтримується, замість
розбору виводу, призначеного для людини:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Не кожна команда підтримує структурований вивід. Перевірте довідку команди, перш ніж
покладатися на нього в автоматизації, і вважайте ненульовий код завершення помилкою.
