Програма Rewards розподіляє токени зі сховища, що належить програмі, між набором
одержувачів, кожен зі своїм графіком вестингу. Authority наповнює сховище й
визначає, хто що отримує. Одержувачі отримують свої розблоковані токени з часом,
а authority може відкликати одержувачів або повернути залишок токенів, якщо
розподіл це дозволяє. Програму створено за допомогою Pinocchio, її підтримує
Solana Foundation, і вона працює як із SPL Token, так і з mint Token-2022, окрім
mint Token-2022 із розширенням transfer hook.

ID програми (mainnet і devnet):

```text
REWArDioXgQJ2fZKkfu9LCLjQfRwYWVVfsvcsR5hoXi
```

## Оберіть тип розподілу

Програма підтримує два типи розподілу. Обидва використовують однакові графіки
вестингу та режими відкликання.

|                  | Прямий                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **Як це працює** | Створює ончейн-акаунт для кожного одержувача     | Зберігає ончейн єдиний корінь дерева Меркла; щоб отримати токени, одержувачі надають докази  |
| **Початкові витрати** | Платник оплачує rent за акаунт кожного одержувача | Жодних акаунтів для окремих одержувачів, доки хтось не забере токени                           |
| **Масштаб**        | Практично — до кількох тисяч одержувачів  | Масштабується до мільйонів одержувачів; обсяг сховища зростає лише в міру того, як одержувачі отримують токени |
| **Змінність**   | Одержувачів можна додавати після створення       | Набір одержувачів фіксується під час створення                                       |
| **Підходить для**   | Невеликих розподілів, що змінюються з часом    | Великих фіксованих розподілів, як-от аірдропи                              |

## Графіки вестингу

Кожне виділення має один із чотирьох графіків. Мітки часу — це секунди Unix.

| Графік      | Поведінка                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | Усі токени доступні для отримання одразу                                                                                    |
| `Linear`      | Токени розблоковуються пропорційно між `startTs` і `endTs`                                                             |
| `Cliff`       | Нічого не розблоковується до `cliffTs`, після чого все розблоковується одразу                                                       |
| `CliffLinear` | Лінійний вестинг від `startTs` до `endTs`, при цьому до `cliffTs` нічого не можна отримати; раніше накопичені токени розблоковуються в момент cliff |

## Акаунти

| Акаунт              | PDA seeds                                        | Зберігає                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | Authority, mint і загальні суми виділень       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | Виділення та вестинг одного одержувача       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | Authority, mint, загальні суми та корінь Меркла |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | Сума, яку вже отримав окремий заявник        |
| `Revocation`         | `["revocation", distribution, user]`             | Маркер, що блокує відкликаного заявника Merkle |

`seed` — це адреса додаткового підписанта, переданого під час створення, тож одна
authority може запускати кілька розподілів для того самого mint. Сховище
кожного розподілу — це associated token account PDA розподілу для його mint.

## Інструкції

### Прямий розподіл

1. Authority викликає `CreateDirectDistribution`, щоб створити PDA розподілу
   та його сховище.
2. Authority викликає `AddDirectRecipient` по одному разу для кожного одержувача,
   вказуючи суму та графік вестингу. Кожен виклик переказує цю суму з
   token account authority до сховища.
3. Одержувачі викликають `ClaimDirect`, щоб вивести розблоковані токени. Передайте
   `amount: 0`, щоб отримати все, що наразі розблоковано.
4. Коли одержувач отримав усе або розподіл закрито, `CloseDirectRecipient`
   закриває акаунт одержувача й повертає rent акаунту, який за нього заплатив.
5. Authority викликає `CloseDirectDistribution`, щоб повернути залишок на сховищі
   та rent. Якщо задано `clawbackTs`, закриття дозволене лише після цього моменту.

### Розподіл Merkle

1. Authority будує дерево Меркла офчейн. Кожен лист містить зобов'язання щодо
   заявника, його загальної суми та графіка вестингу.
2. Authority викликає `CreateMerkleDistribution`, передаючи корінь, загальну суму,
   доступну для отримання, і `clawbackTs`, та наповнює сховище в тій самій
   інструкції.
3. Заявники викликають `ClaimMerkle`, передаючи дані свого листа та доказ. Перше
   отримання створює акаунт `MerkleClaim` заявника. Передайте `amount: 0`, щоб
   отримати все, що наразі розблоковано.
4. Після `clawbackTs` authority викликає `CloseMerkleDistribution`, щоб повернути
   залишок на сховищі та rent.
5. Після закриття розподілу заявники викликають `CloseMerkleClaim`, щоб повернути
   rent за свій акаунт отримання.

Програма хешує листя за допомогою Keccak-256 як
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`, де
`totalAmount` — це `u64` у форматі little-endian, а `schedule` використовує те саме
кодування, що й аргумент `VestingSchedule` інструкції. Вузли доказу хешуються як
відсортовані пари, спочатку менший хеш.

### Відкликання

Відкликання вмикається за бажанням. Бітова маска `revocable`, задана під час
створення, визначає, які режими може використовувати authority: біт 0 вмикає
`NonVested`, біт 1 вмикає `Full`, а `0` вимикає відкликання.

| Режим        | Інструкція                                    | Результат                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` або `RevokeMerkleClaim` | Розблоковані, але не отримані токени надходять користувачу; нерозблоковані токени повертаються authority |
| `Full`      | `RevokeDirectRecipient` або `RevokeMerkleClaim` | Усі неотримані токени, розблоковані й нерозблоковані, повертаються authority               |

Відкликання заявника Merkle створює маркер `Revocation`, який блокує подальші
отримання, навіть якщо заявник ще ніколи не отримував токени. Відкликання прямого
одержувача закриває його акаунт `DirectRecipient` і повертає rent.

## Клієнти

Репозиторій містить клієнти [`@solana/kit`](/docs/clients/official/javascript) та
Rust, згенеровані з IDL програми за допомогою Codama, у
[`clients/`](https://github.com/solana-foundation/rewards/tree/main/clients).
Клієнт ще не опублікований у npm. Зберіть його з вихідного коду за допомогою
`just generate-clients`.
