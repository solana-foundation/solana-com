Програма Rewards розподіляє токени зі сховища, яке належить програмі, між набором
отримувачів, кожен з яких має власний графік вестингу. Розпорядник поповнює сховище й визначає,
хто що отримає. Отримувачі з часом забирають свої розблоковані токени, а
розпорядник може відкликати отримувачів або повернути залишок токенів, якщо
розподіл це дозволяє. Програму створено за допомогою Pinocchio, її підтримує Solana
Foundation, і вона працює з mint-ами як SPL Token, так і Token-2022, окрім
mint-ів Token-2022 з розширенням transfer hook.

ID програми (mainnet і devnet):

```text
REWArDioXgQJ2fZKkfu9LCLjQfRwYWVVfsvcsR5hoXi
```

## Оберіть тип розподілу

Програма підтримує два типи розподілу. Обидва використовують однакові графіки вестингу
та режими відкликання.

|                  | Прямий                                       | Меркла                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **Як це працює** | Створює ончейн-акаунт для кожного отримувача     | Зберігає ончейн єдиний корінь Меркла; щоб отримати токени, отримувачі надають докази  |
| **Початкові витрати** | Платник оплачує rent за акаунт кожного отримувача | Жодних акаунтів для окремих отримувачів, доки хтось не заклеймить токени                           |
| **Масштаб**        | Практично до кількох тисяч отримувачів  | Масштабується до мільйонів отримувачів; обсяг сховища зростає лише в міру того, як отримувачі забирають токени |
| **Змінність**   | Отримувачів можна додавати після створення       | Набір отримувачів фіксується під час створення                                       |
| **Для чого підходить**   | Невеликі розподіли, що змінюються з часом    | Великі фіксовані розподіли, як-от airdrop                              |

## Графіки вестингу

Кожна алокація має один із чотирьох графіків. Часові мітки — це секунди Unix.

| Графік      | Поведінка                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | Усі токени доступні для отримання одразу                                                                                    |
| `Linear`      | Токени розблоковуються пропорційно між `startTs` і `endTs`                                                             |
| `Cliff`       | Нічого не розблоковується до `cliffTs`, після чого все розблоковується одразу                                                       |
| `CliffLinear` | Лінійний вестинг від `startTs` до `endTs`, причому нічого не можна отримати до `cliffTs`; раніше нараховані токени розблоковуються в момент cliff |

## Акаунти

| Акаунт              | PDA seed                                        | Зберігає                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | Розпорядника, mint і загальні суми алокацій       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | Алокацію та вестинг одного отримувача       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | Розпорядника, mint, загальні суми та корінь Меркла |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | Суму, яку вже отримав один заявник        |
| `Revocation`         | `["revocation", distribution, user]`             | Маркер, що блокує відкликаного заявника в розподілі Меркла |

`seed` — це адреса додаткового підписанта, що передається під час створення, тож один
розпорядник може запускати кілька розподілів для того самого mint. Сховище кожного
розподілу — це associated token account для PDA розподілу та його mint.

## Інструкції

### Прямий розподіл

1. Розпорядник викликає `CreateDirectDistribution`, щоб створити PDA розподілу
   та його сховище.
2. Розпорядник викликає `AddDirectRecipient` по одному разу для кожного отримувача, вказуючи суму
   та графік вестингу. Кожен виклик переказує цю суму з token account
   розпорядника до сховища.
3. Отримувачі викликають `ClaimDirect`, щоб вивести розблоковані токени. Передайте `amount: 0`, щоб
   отримати все, що наразі розблоковано.
4. Коли отримувач забрав усе або розподіл закрито,
   `CloseDirectRecipient` закриває акаунт отримувача й повертає rent тому
   акаунту, який за нього заплатив.
5. Розпорядник викликає `CloseDirectDistribution`, щоб повернути залишок
   у сховищі та rent. Якщо задано `clawbackTs`, закрити розподіл можна лише після цього
   моменту.

### Розподіл Меркла

1. Розпорядник будує дерево Меркла офчейн. Кожен лист фіксує заявника,
   загальну суму цього заявника та графік вестингу.
2. Розпорядник викликає `CreateMerkleDistribution`, передаючи корінь, загальну
   суму, доступну для отримання, і `clawbackTs`, та поповнює сховище в тій самій
   інструкції.
3. Заявники викликають `ClaimMerkle`, передаючи дані свого листа та доказ. Перше отримання
   створює акаунт `MerkleClaim` заявника. Передайте `amount: 0`, щоб отримати
   все, що наразі розблоковано.
4. Після `clawbackTs` розпорядник викликає `CloseMerkleDistribution`, щоб повернути
   залишок у сховищі та rent.
5. Після закриття розподілу заявники викликають `CloseMerkleClaim`, щоб
   повернути rent за свій акаунт claim.

Програма хешує листя за допомогою Keccak-256 так:
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`, де
`totalAmount` — це `u64` у little-endian, а `schedule` використовує те саме кодування, що й
аргумент `VestingSchedule` інструкції. Вузли доказу хешуються як відсортовані
пари, спочатку менший хеш.

### Відкликання

Відкликання є опційним. Бітова маска `revocable`, задана під час створення, визначає, які
режими може використовувати розпорядник: біт 0 вмикає `NonVested`, біт 1 вмикає `Full`,
а `0` вимикає відкликання.

| Режим        | Інструкція                                    | Результат                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` або `RevokeMerkleClaim` | Розблоковані, але не отримані токени переходять користувачеві; нерозблоковані токени повертаються розпорядникові |
| `Full`      | `RevokeDirectRecipient` або `RevokeMerkleClaim` | Усі неотримані токени, розблоковані та нерозблоковані, повертаються розпорядникові               |

Відкликання заявника в розподілі Меркла створює маркер `Revocation`, який блокує майбутні
отримання, навіть якщо заявник ще жодного разу не отримував токени. Відкликання прямого отримувача закриває
його акаунт `DirectRecipient` і повертає rent за нього.

## Клієнти

Репозиторій містить клієнти [`@solana/kit`](/docs/clients/official/javascript) та
Rust, згенеровані з IDL програми за допомогою Codama, у
[`clients/`](https://github.com/solana-foundation/rewards/tree/main/clients).
Клієнт ще не опубліковано в npm. Зберіть його з вихідного коду за допомогою
`just generate-clients`.
