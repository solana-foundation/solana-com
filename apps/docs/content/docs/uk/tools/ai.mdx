# Робота з LLM та агентами на Solana

Перш ніж перейти до конкретних інструментів, розберімося з ключовими компонентами стеку розробки ШІ:

## Розуміння стеку ШІ

1. **Великі мовні моделі (LLM)**
   - Базові моделі ШІ (як-от GPT-4, Claude або Llama)
   - Обробляють і генерують природну мову
   - Забезпечують базовий інтелект та можливості міркування
   - Приклади: GPT-4 від OpenAI, Claude від Anthropic, Llama від Meta

2. **Фреймворки агентів (як-от Eliza)**
   - Побудовані на основі LLM для створення автономних агентів
   - Керують особистостями та поведінкою агентів
   - Обробляють пам'ять і контекст
   - Забезпечують інтеграцію з різними платформами
   - Приклади: Eliza, LangChain, AutoGPT, Vercel AI

3. **Спеціалізовані набори агентів (як-от Solana Agent Kit)**
   - Розроблені для конкретних сценаріїв використання (наприклад, операцій з блокчейном)
   - Надають готові інструменти та інтеграції
   - Абстрагують технічну складність
   - Готові до використання функції блокчейну
   - Приклади: Solana Agent Kit, GOAT Toolkit

Уявіть це так:

- LLM — це «мозок», який розуміє та генерує мову
- Фреймворки агентів — це «операційна система», що керує поведінкою ШІ
- Спеціалізовані набори — це «застосунки», що надають ШІ конкретні можливості

# Побудова агентів ШІ для Solana

Цей посібник покаже вам, як:

- Побудувати базового агента ШІ за допомогою Solana Agent Kit від SendAI
- Створити Twitter-бота за допомогою фреймворку Eliza
- Зрозуміти варіанти інтеграції ШІ в мережу
- Варіанти побудови складних торгових ботів

## Вступ до агентів ШІ на Solana

Агенти ШІ на Solana — це автономні програми, що можуть взаємодіяти з блокчейном за допомогою обробки природної мови та машинного навчання. Вони можуть:

- Виконувати транзакції
- Відстежувати активність блокчейну
- Взаємодіяти зі смарт-контрактами
- Надавати допомогу користувачам
- Автоматизувати складні робочі процеси

## Доступні фреймворки

Для побудови агентів ШІ на Solana доступно декілька фреймворків:

1. **Solana Agent Kit від SendAI**

- Набір інструментів для побудови агентів на Solana
- Сумісний з Eliza, Langchain та Vercel AI SDK
- Вбудовані інструменти та утиліти Solana
- Можливості обробки природної мови
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Документація](https://docs.solanaagentkit.xyz/)

2. **Фреймворк Eliza**

- Поєднує рівень даних, LLM та агентів і має спеціальний плагін для Solana
- Розширювана архітектура агентів
- Проста інтеграція з наявними проєктами; може використовуватися, наприклад, для
  ботів у Twitter (X), Telegram або Discord
- [Репозиторій GitHub](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Комплексний набір інструментів для розробки
- Кросчейн-сумісність
- [Репозиторій GitHub](https://github.com/goat-sdk/goat)

4. **Фреймворк Rig**

- Нативна реалізація на Rust
- Підходить для високопродуктивних торгових ботів
- Може поєднуватися з набором інструментів Listen.rs для інтеграції з Solana, моніторингу транзакцій
  та надсилання транзакцій з використанням, наприклад, пакетів Jito
- [Репозиторій GitHub](https://github.com/0xPlaygrounds/rig)
- [Репозиторій Listen.rs](https://github.com/piotrostr/listen)

Якщо ви розробляєте фреймворк ШІ, сміливо відкривайте PR, щоб додати свій фреймворк до списку

### Створення скрипту агента

Створіть новий файл під назвою `agent.ts` з таким вмістом:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## Розробка з фреймворком Eliza

[ElizaOS](https://github.com/elizaOS/eliza) (раніше відомий як Ai16z) — це
фреймворк ШІ. Це означає, що він об'єднує кілька застосунків в один і
організовує їх взаємодію. Він поєднує:

1. Різні LLM для розуміння користувача
2. Агентів блокчейну з різними діями (наприклад, карбування NFT)
3. Рівні даних для зберігання стану персонажів між діями з використанням, наприклад,
   Redis, PostgreSQL DB або локального сховища
4. Різні клієнти: X, Telegram, Discord тощо

Він об'єднує все це у спосіб, що дозволяє створити «Персонажа», який може взаємодіяти з користувачами або діяти автономно. Ці Персонажі визначаються у файлі JSON, який задає доступні для виконання дії, яку LLM використовувати та різні підказки, що визначають поведінку персонажа.

І запустіть за допомогою

### Створення конфігурації персонажа

Щоб створити нового персонажа, необхідно створити файл character.json. Готові персонажі знаходяться у папці characters проєкту Eliza. Щоб створити нового персонажа, ви можете скопіювати та змінити одного з уже наявних або скористатися
[функцією composer у Cursor](https://docs.cursor.com/composer/overview) і описати,
якого персонажа ви хочете створити.

```json filename=characters/sol.character.json
{
    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },
        ...
```

Важливою частиною тут є clients та modelProvider. У нашому випадку ми хочемо використовувати twitter як клієнт і openai як постачальника моделі, оскільки саме для них ми встановили секрети у файлі `.env`.

### Запуск агента

Тепер, коли конфігурацію завершено, ми можемо запустити нашого персонажа:

```bash
pnpm start --character="characters/sol.character.json"
```

Це запустить агента, і тепер ви можете взаємодіяти з ним у Twitter. Персонаж автоматично почне публікувати твіти кожні кілька годин, і під час взаємодії з ним він зможе виконувати дії Solana, наприклад карбувати NFT.

Тут ви можете побачити
[персонажа в дії](https://x.com/solanadevhelper/status/1882222232656847143).

Ви також можете взаємодіяти з персонажем локально за допомогою наступної команди.
Можливо, вам знадобиться звільнити порт 3000 і запустити персонажа з прапорцем `--host`.

```bash
pnpm start --character="characters/sol.character.json" --host
pnpm start:client
```

Якщо ваш клієнт не підключається, переконайтеся, що агент запущено з прапорцем `--host`
і що порт 3000 не зайнятий під час запуску клієнта.

Для отримання додаткової інформації зверніться до
[офіційної документації Eliza](https://elizaos.github.io/eliza/docs/quickstart/)

</Steps>

Відмова від відповідальності: Інтеграція Solana та наявні дії ще не є досконалими, але вони постійно розвиваються і рухаються швидко. Незабаром відбудеться пряма інтеграція набору агентів SendAI у Eliza.

## Використання GOAT Toolkit

[GOAT](https://github.com/goat-sdk/goat) — це, подібно до Solana Agent Kit, колекція різноманітних інструментів для блокчейну, яка також підтримує різні дії Solana та інші мережі. Його також можна інтегрувати, наприклад, у фреймворк Eliza, і він підтримує багато різних гаманців, фреймворків та блокчейнів. Цей
[приклад](https://github.com/goat-sdk/goat/tree/main/typescript/examples/by-use-case/solana-purchase-on-amazon)
показує, як можна використовувати [Crossmint](https://www.crossmint.com/) безпосередньо у
[редакторі коду Windsurf](https://codeium.com/windsurf) для купівлі товарів на Amazon.
Також доступне
[демонстраційне відео](https://x.com/windsurf_ai/status/1903118960633188485).

## Інтеграція агентів у програми мережі

Якщо ви хочете використовувати відповідь агента в програмі Solana, вам потрібно використовувати
оракул, який записує дані відповіді в акаунт, який ваша програма може читати.
Тут ви можете знайти приклад LLM, який переказуватиме токени будь-якому користувачу,
який правильно відповідає на запитання:

[Взаємодія LLM з програмою в мережі](https://github.com/GabrielePicco/super-smart-contracts)

Це приклад програми в мережі, яка інтегрується з оракулом LLM (ШІ)
для створення інтерактивного агента з видачі токенів на ім'я "Mar1o".

### Ключові функції

1. **Взаємодія з ШІ-агентом**
   - Користувачі можуть спілкуватися з Mar1o, щоб спробувати заробити токени
   - Агент оцінює знання користувача про Solana для визначення кількості токенів
   - Відповіді надаються у форматі JSON із текстом відповіді та кількістю токенів

2. **Управління токенами**
   - Створює токени MAR1O з метаданими
   - Може карбувати від 0 до 10 000 токенів на основі відповіді ШІ
   - Використовує PDA для управління токенами

### Опис потоку програми

Ось як працює ця програма:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Це демонструє, як поєднати можливості ШІ з механікою токенів у мережі для
створення інтерактивних блокчейн-досвідів. Ось
[живий приклад](https://mar1o.xyz/), де ви можете спробувати переконати Агента
перевести вам кілька токенів.

## Розширені Rust-агенти для алгоритмічної торгівлі

Якщо ви хочете писати своїх агентів на Rust, ви можете використовувати
[фреймворк Rig](https://github.com/0xPlaygrounds/rig) та
бібліотеку [Listen.rs](https://github.com/piotrostr/listen).

Ці два добре поєднуються між собою. Тоді як фреймворк Rig надає простий спосіб
підключення до LLM, набір інструментів Listen.rs забезпечує інтеграцію з Solana,
включаючи моніторинг транзакцій та надсилання транзакцій за допомогою, наприклад, пакетів Jito.

## Найкращі практики

- Майте на увазі, що ваш агент має приватний ключ і, таким чином, може отримати доступ до коштів у вашому
  гаманці. Якщо хтось може спілкуватися з вашим агентом і він має, наприклад, дію переказу,
  користувачі, мабуть, зможуть змусити його перевести їм ваші кошти.
- Використовуйте платні [RPC-точки доступу](https://solana.com/rpc). Публічні точки доступу
  зазвичай мають обмеження частоти запитів
- Відстежуйте дії агента та переконайтеся, що він не виконує нічого шкідливого
  та не може бути обманутий користувачами, які взаємодіють з ним
- Реалізуйте пріоритетні комісії та повторні спроби транзакцій для дій вашого агента, щоб
  вони також виконувалися під час перевантаження мережі
- По можливості спочатку тестуйте в devnet перед розгортанням у mainnet. Більшість агентів
  просто приймають URL-адресу RPC як вхідні дані, і ви можете використовувати devnet, поки не будете
  готові до mainnet. Проте не всі дії можуть бути можливими в devnet.
- Під час написання власних дій додавайте інтеграційні тести для них, щоб
  фреймворки могли відстежувати, які дії завершуються помилкою через зміни в програмах або
  API

## Висновок

ШІ-агенти на Solana відкривають нові можливості для автоматизації та взаємодії
з блокчейном. Хоча ще не всі інтеграції є досконалими, вони
розвиваються швидко та пропонують багато можливостей для внесення вкладу і є дуже
гнучкими для додавання власних інтеграцій.
