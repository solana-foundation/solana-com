2.0.0 — це перший стабільний випуск модулів Go, тож мігрувати нічого не потрібно. [Посібник із міграції на 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md) описує той самий поділ можливостей для Rust і TypeScript.

## Встановлення

Кожен бекенд — це окремий модуль Go, тож ваша збірка та граф модулів містять лише ті бекенди, які ви імпортуєте:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

Модулі позначаються тегами `go/<module>/v2.0.0` (наприклад, `go/signers/memory/v2.0.0`). Кожен модуль потребує Go 1.25.0, окрім `gcpkms`, який потребує Go 1.25.8 через мінімальну версію, встановлену `google.golang.org/api`. Ledger доступний лише для Rust і не має модуля Go.

### solana-go v2 та транзакції v1

Модулі побудовані на [`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go) v2.0.0 і працюють із його `*solana.Transaction`. Підтримуються транзакції legacy, v0 і v1 (`solana.MessageVersionV1`), за винятком Fireblocks з `UseProgramCall: true`, який приймає лише legacy і v0.

## Базове використання

Кожен підписувач реалізує базовий [інтерфейс `core.SolanaSigner`](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner) (`Pubkey`, `SignMessage`, `IsAvailable`). Методи приймають `context.Context` і є блокувальними. Крім того, кожен бекенд реалізує рівно один інтерфейс можливостей:

- `core.TransactionSigner`: `SignTransaction` підписує вашу транзакцію як є.
- `core.ModifyingSigner`: `ModifyAndSignTransaction` дозволяє провайдеру переписати транзакцію, після чого підписує її.
- `core.SendingSigner`: `SignAndSendTransaction` доручає провайдеру підписати та розіслати її в мережу.

Кожен пакет бекенда надає структуру `Config` і конструктор `New`:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` і `ModifyAndSignTransaction` повертають `core.SignedTransaction` (`EncodedTransaction`, `Signature`, `Completeness`). Віддалені HTTP-бекенди приймають необов’язкові `HTTPClient` і `HTTPClientConfig` (тайм-аути). Клієнт за замовчуванням вимагає HTTPS; якщо ви передаєте власного клієнта, ця вимога обходиться, і відповідальність за його безпеку лежить на вас.

### Можливості підписувачів

Бекенд, який не може підписати транзакцію, взагалі не має методу `SignTransaction`, тому можливість визначається на етапі компіляції для конкретних типів і через перевірку типу (type assertion) для `core.SolanaSigner`:

| Бекенд                                                                         | Можливість          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | Так                            |
| cdp                                                                             | `TransactionSigner` | Лише дані в UTF-8            |
| utila                                                                           | `TransactionSigner` | Завершується помилкою `CodeSigningFailed` |
| fordefi black box (`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | Так                            |
| fordefi native manual (`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | Так                            |
| fordefi native auto (`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | Так                            |
| crossmint                                                                       | `SendingSigner`     | Завершується помилкою `CodeSigningFailed` |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### Ініціалізація

Окремого кроку `Init` немає. Privy, Fireblocks, Dfns, Crossmint, Para, Openfort і Utila визначають адресу гаманця всередині `New`, тому їхні конструктори приймають `context.Context`. Завжди створюйте підписувачів через `New`: підписувач Crossmint, Para або Utila з нульовим значенням завершується помилкою `CodeNotInitialized`, а не підписує для нульової адреси.

### Підпис і надсилання будь-яким підписувачем

`core.SignAndSendTransaction` відправляє транзакцію в мережу незалежно від форми підписувача. `SendingSigner` розсилає транзакцію через свого провайдера та ігнорує функцію надсилання; усі інші форми лише підписують, а ваша функція розсилає результат у base64, який для `ModifyingSigner` є транзакцією, переписаною його провайдером. Core не має залежності від RPC:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### Пакетне підписання

Пакетне підписання реалізоване як вільні допоміжні функції, що працюють паралельно з необов’язковою затримкою між запитами для API з обмеженням частоти:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` приймає `core.TransactionSigner`, тому підписувачі з керованим розсиланням (Crossmint, Fordefi native auto) і Fordefi native manual не можна обробляти пакетно; викликайте їх по одній транзакції. Підписувач, виклики якого створюють роботу на боці провайдера (Fireblocks з `UseProgramCall`), повідомляє про це через `core.BatchServerSideEffects`, після чого пакет виконується послідовно.

## Конфігурація бекендів

### Memory

Вкажіть рівно одне з: `PrivateKey` (необроблені байти), `PrivateKeyString` (base58 або масив байтів `[1,2,...]`) чи `PrivateKeyPath` (файл keypair Solana CLI):

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Go не має надійного способу занулити пам’ять: збирач сміття може копіювати та зберігати байти ключів (memory keypairs і ключі, які Crossmint та Openfort виводять локально) до моменту очищення. Під час використання бекендів із локальними ключами вважайте конфіденційною всю пам’ять процесу.

### Crossmint

Crossmint працює лише на надсилання: його API виконує кожну схвалену транзакцію на стороні сервера, тому `*crossmint.Signer` має `SignAndSendTransaction`, але не має `SignTransaction`. Вашу транзакцію ніколи не змінюють; повернений підпис ідентифікує транзакцію, яку Crossmint записав у мережу, і вона може відрізнятися від вашої, якщо Crossmint спонсорує газ.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Fordefi

Fordefi доступний у вигляді трьох типів підписувачів, які визначаються під час створення через `Config.Chain` і `Config.PushMode`. Усі три підписують повідомлення:

| Config                                          | Тип                          | Точка входу                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` не задано                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` задано, `PushMode` не задано або `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` задано, `PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` вибирає тип за конфігурацією та повертає `core.SolanaSigner`; `fordefi.NewBlackBox`, `fordefi.NewNativeAuto` і `fordefi.NewNativeManual` повертають конкретний тип і відхиляють конфігурації інших режимів. API-запити автентифікуються підписом запиту ECDSA P-256: вкажіть рівно одне з `PrivateKeyPEM` або `RequestSigner`, щоб зберігати цей ключ у KMS/HSM.

**Режим Native auto**: Fordefi може замінити blockhash і комісії, а потім підписує та розсилає транзакцію. Він приймає лише непідписану транзакцію, єдиним обов’язковим підписувачем якої є сховище (vault).

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**Режим Native manual**: установіть `PushMode: fordefi.PushModeManual`. Fordefi переписує повідомлення (recent blockhash, інструкції комісій Compute Budget) і підписує його без розсилання. `ModifyAndSignTransaction` замінює `tx` транзакцією, яку підписав Fordefi: завжди продовжуйте роботу з неї. Fordefi має бути платником комісії та повинен підписати раніше за будь-якого іншого обов’язкового підписувача, оскільки переписування анулює наявні підписи. Переписування не показується у вигляді різниці, тому перевіряйте результат перед розсиланням.

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**Режим Black box**: залиште `Chain` не заданим. Fordefi підписує точні байти вашого повідомлення та не розсилає його. Використовуйте цей режим зі сховищем Fordefi black box.

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## Чому немає універсального пакета

У Rust є enum `Signer`, а в TypeScript — `createKeychainSigner`; у Go свідомо немає ні того, ні іншого. Go не усуває мертвий код через runtime-перемикач, тож універсальний пакет змусив би включати SDK кожного вендора бекенда (AWS, GCP та решти) у збірку кожного споживача. Вибором бекенда є імпорт потрібного вам пакета. Щоб обирати бекенд під час виконання, напишіть перемикач у власному коді лише для підтримуваних вами бекендів і зберігайте результат як `core.SolanaSigner`.

## Обробка помилок

Кожна помилка є `*core.SignerError` зі стабільним `Code` (`CodeConfigError`, `CodeHTTPError`, `CodeRemoteAPIError`, `CodeSigningFailed`, `CodeNotInitialized`, `CodeBroadcastUnconfirmed` та іншими). `Error()` повертає лише фіксоване повідомлення для кожного коду, ніколи не розкриваючи ключовий матеріал чи необроблені відповіді провайдера. Порівнюйте через `errors.As`, `errors.Is(err, &core.SignerError{Code: ...})` або `core.CodeOf(err)`.

У Crossmint і Fordefi в режимі native auto помилка не означає, що нічого не потрапило в мережу. Якщо провайдер міг прийняти транзакцію, код буде `core.CodeBroadcastUnconfirmed` (`"SIGNER_BROADCAST_UNCONFIRMED"`). `ProviderTxID` встановлюється, коли створення було прийнято, а `IdempotencyKey` містить ключ, похідний від повідомлення. Повторне надсилання байт-у-байт ідентичної транзакції безпечне; перебудована транзакція (наприклад, з новим blockhash) є новим переказом. `core.SignAndSendTransaction` також повідомляє цей код, коли ваша функція надсилання завершується помилкою, а підпис платника комісії міститься в `TransactionSignature`. Fireblocks PROGRAM_CALL лише підписує й не надсилає ключ; він повідомляє цей код лише тоді, коли опитування показує, що Fireblocks усе ж розіслав транзакцію.

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

## Додавання власних підписувачів

Реалізуйте `core.SolanaSigner` плюс рівно один інтерфейс можливостей і не додавайте жодного методу, який ваш бекенд не може підтримувати: виклики визначають можливості через перевірку типу. Див. [посібник із додавання підписувачів](/docs/tools/keychain/adding-signers), щоб інтегрувати додаткові сервіси керування ключами.
