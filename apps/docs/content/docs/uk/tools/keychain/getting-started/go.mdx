2.0.0 — це перший стабільний випуск модулів Go, тому мігрувати нічого не потрібно. У
[посібнику з міграції на 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)
описано той самий поділ можливостей для Rust і TypeScript.

## Встановлення

Кожен бекенд є окремим модулем Go, тому ваша збірка та граф модулів містять
лише ті бекенди, які ви імпортуєте:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

Модулі позначаються тегами `go/<module>/v2.0.0` (наприклад,
`go/signers/memory/v2.0.0`). Кожен модуль вимагає Go 1.25.0, окрім `gcpkms`,
який вимагає Go 1.25.8 через мінімальну версію, встановлену в `google.golang.org/api`.
Ledger працює лише з Rust і не має модуля Go.

### solana-go v2 та транзакції v1

Модулі побудовані на
[`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go)
v2.0.0 і приймають його `*solana.Transaction`. Підтримуються транзакції legacy, v0 та v1
(`solana.MessageVersionV1`), за винятком Fireblocks
із `UseProgramCall: true`, який приймає лише legacy та v0.

## Базове використання

Кожен підписувач реалізує базовий
[інтерфейс `core.SolanaSigner`](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)
(`Pubkey`, `SignMessage`, `IsAvailable`). Методи приймають `context.Context` і
є блокувальними. Крім того, кожен бекенд реалізує рівно один інтерфейс можливостей:

- `core.TransactionSigner`: `SignTransaction` підписує вашу транзакцію як є.
- `core.ModifyingSigner`: `ModifyAndSignTransaction` дозволяє провайдеру переписати
  транзакцію, після чого підписує її.
- `core.SendingSigner`: `SignAndSendTransaction` доручає провайдеру підписати
  та транслювати її.

Кожен пакет бекенда надає структуру `Config` і конструктор `New`:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` і `ModifyAndSignTransaction` повертають
`core.SignedTransaction` (`EncodedTransaction`, `Signature`, `Completeness`).
Віддалені HTTP-бекенди приймають необов’язкові `HTTPClient` і `HTTPClientConfig`
(тайм-аути). Клієнт за замовчуванням вимагає HTTPS; якщо ви передаєте власний, ця вимога обходиться,
і відповідальність за його безпеку лежить на вас.

### Можливості підписувачів

Бекенд, який не може підписувати транзакцію, взагалі не має методу `SignTransaction`,
тож можливість — це факт часу компіляції для конкретних типів і перевірка типу
(type assertion) для `core.SolanaSigner`:

| Бекенд                                                                         | Можливість          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | Так                            |
| cdp                                                                             | `TransactionSigner` | Лише дані в UTF-8            |
| utila                                                                           | `TransactionSigner` | Завершується помилкою `CodeSigningFailed` |
| fordefi black box (`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | Так                            |
| fordefi native manual (`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | Так                            |
| fordefi native auto (`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | Так                            |
| crossmint                                                                       | `SendingSigner`     | Завершується помилкою `CodeSigningFailed` |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### Ініціалізація

Окремого кроку `Init` немає. Privy, Fireblocks, Dfns, Crossmint, Para,
Openfort і Utila визначають адресу гаманця всередині `New`, тому їхні
конструктори приймають `context.Context`. Завжди створюйте підписувачі через `New`: підписувач
Crossmint, Para або Utila із нульовим значенням завершується помилкою `CodeNotInitialized`,
а не підписує для нульової адреси.

### Підпис і надсилання будь-яким підписувачем

`core.SignAndSendTransaction` відправляє транзакцію в мережу незалежно від
типу підписувача. `SendingSigner` транслює через свого провайдера й ігнорує функцію
надсилання; усі інші типи підписують, а ваша функція транслює результат у base64,
який для `ModifyingSigner` є транзакцією, переписаною його провайдером.
Core не має залежності від RPC:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### Пакетне підписання

Пакетне підписання надається у вигляді вільних допоміжних функцій, що працюють паралельно, з необов’язковою
затримкою між запитами для API з обмеженням частоти:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` приймає `core.TransactionSigner`, тому
підписувачі з керованою трансляцією (Crossmint, Fordefi native auto) і Fordefi native
manual не можна використовувати в пакеті; викликайте їх по одній транзакції. Підписувач,
виклики якого створюють роботу на боці провайдера (Fireblocks з `UseProgramCall`),
повідомляє про це через `core.BatchServerSideEffects`, і тоді пакет виконується
послідовно.

## Конфігурація бекендів

### Memory

Вкажіть рівно одне з: `PrivateKey` (сирі байти), `PrivateKeyString` (base58 або
масив байтів `[1,2,...]`) чи `PrivateKeyPath` (файл keypair Solana CLI):

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Go не надає надійного способу занулити пам’ять: збирач сміття може копіювати та
зберігати байти ключів (memory keypairs, а також ключі, які Crossmint і Openfort отримують
локально) до моменту збирання. Вважайте всю пам’ять процесу чутливою,
коли використовуєте бекенди з локальними ключами.

### Crossmint

Crossmint працює лише на надсилання: його API виконує кожну схвалену транзакцію
на боці сервера, тому `*crossmint.Signer` має `SignAndSendTransaction` і не має
`SignTransaction`. Вашу транзакцію ніколи не змінюють; повернений підпис
ідентифікує транзакцію, яку Crossmint записав у мережу, і вона може відрізнятися від вашої, якщо
Crossmint спонсорує газ.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

import "github.com/solana-foundation/solana-keychain/go/signers/dfns/v2"

Utila лише підписує транзакції; `SignMessage` завершується помилкою, а підписану

import "github.com/solana-foundation/solana-keychain/go/signers/utila/v2"

signer, err := utila.New(ctx, utila.Config{

### Fordefi

Fordefi має три типи підписувачів, які визначаються під час створення через `Config.Chain` і
`Config.PushMode`. Усі три підписують повідомлення:

| Config                                          | Тип                          | Точка входу                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` не задано                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` задано, `PushMode` не задано або `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` задано, `PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` вибирає тип за конфігурацією та повертає `core.SolanaSigner`;
`fordefi.NewBlackBox`, `fordefi.NewNativeAuto` і `fordefi.NewNativeManual`
повертають конкретний тип і відхиляють конфігурації інших режимів. Запити до API
автентифікуються підписом запиту ECDSA P-256: вкажіть рівно одне з
`PrivateKeyPEM` або `RequestSigner`, щоб зберігати цей ключ у KMS/HSM.

**Режим native auto**: Fordefi може замінити blockhash і комісії, після чого підписує й
транслює. Він приймає лише непідписану транзакцію, єдиним обов’язковим підписувачем якої
є сховище (vault).

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**Режим native manual**: встановіть `PushMode: fordefi.PushModeManual`. Fordefi переписує
повідомлення (recent blockhash, інструкції комісії Compute Budget) і підписує його
без трансляції. `ModifyAndSignTransaction` замінює `tx` на
транзакцію, яку підписав Fordefi: завжди продовжуйте роботу з нею. Fordefi має бути платником
комісії та має підписувати раніше за будь-якого іншого обов’язкового підписувача, оскільки переписування анулює
існуючі підписи. Різниця після переписування не обчислюється, тому перевірте результат перед
трансляцією.

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**Режим black box**: залиште `Chain` не заданим. Fordefi підписує точні байти вашого повідомлення
і не транслює його. Використовуйте це зі сховищем Fordefi black box.

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## Чому немає узагальнювального пакета

У Rust є enum `Signer`, а в TypeScript — `createKeychainSigner`; у Go
свідомо немає ні того, ні іншого. Go не видаляє мертвий код через диспетчеризацію
з перемикачем під час виконання, тож узагальнювальний пакет змусив би включити SDK вендорів усіх бекендів (AWS, GCP
та інших) у збірку кожного споживача. Імпорт потрібного вам пакета бекенда і є вибором.
Щоб вибирати бекенд під час виконання, напишіть перемикач у власному
коді лише для підтримуваних вами бекендів і зберігайте результат як
`core.SolanaSigner`.

## Обробка помилок

Кожна помилка — це `*core.SignerError` зі стабільним `Code` (`CodeConfigError`,
`CodeHTTPError`, `CodeRemoteAPIError`, `CodeSigningFailed`,
`CodeNotInitialized`, `CodeBroadcastUnconfirmed` та інші). `Error()` повертає
лише фіксоване повідомлення для кожного коду, ніколи не ключовий матеріал чи сирі відповіді провайдера.
Порівнюйте за допомогою `errors.As`, `errors.Is(err, &core.SignerError{Code: ...})` або
`core.CodeOf(err)`.

У Crossmint і Fordefi native auto помилка не означає, що нічого не потрапило в мережу.
Якщо провайдер міг прийняти транзакцію, код буде
`core.CodeBroadcastUnconfirmed` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`ProviderTxID` встановлюється, коли створення було прийнято, а `IdempotencyKey` містить
ключ, виведений із повідомлення. Повторне надсилання побайтово ідентичної транзакції
безпечне; перебудована (наприклад, з новим blockhash) є новим переказом.
`core.SignAndSendTransaction` також повідомляє цей код, коли ваша функція надсилання
завершується помилкою, із підписом платника комісії в `TransactionSignature`. Fireblocks
PROGRAM_CALL лише підписує й не надсилає ключ; він повідомляє цей код лише тоді, коли
опитування показує, що Fireblocks усе ж транслював транзакцію.

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

## Додавання власних підписувачів

Реалізуйте `core.SolanaSigner` плюс рівно один інтерфейс можливостей і не додавайте
методів, які ваш бекенд не може забезпечити: виклики визначають можливості за допомогою type assertion.
Див. [посібник із додавання підписувачів](/docs/tools/keychain/adding-signers), щоб інтегрувати
додаткові сервіси керування ключами.
