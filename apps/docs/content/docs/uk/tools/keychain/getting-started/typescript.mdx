## Встановлення

Встановіть загальний пакет або окремі підписанти за потреби:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Потрібен `@solana/kit` 8.1 або новіший. Транзакції v1
(`createTransactionMessage({ version: 1 })`) підтримуються, окрім Fireblocks
із `useProgramCall: true`, який приймає лише legacy та v0.

## Базове використання

### Уніфікована фабрика (рекомендується для додатків, які хочуть підтримувати кілька підписантів)

Використовуйте `createKeychainSigner` з дискримінованою конфігурацією для
створення будь-якого бекенду:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Або встановіть окремий пакет підписанта для меншого обсягу залежностей:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Використання з повідомленнями транзакцій

Кожен бекенд, окрім Crossmint і нативного режиму Fordefi, повертає
`SolanaTransactionSigner`, який є Kit `TransactionPartialSigner` і працює
із допоміжними функціями часткових підписувачів із `@solana/signers`, наведеними нижче. Бекенди з керованим broadcast
описано в розділі [Можливості підписувачів](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Підписання й надсилання з будь-яким підписувачем

`signAndSendTransaction` із `@solana/keychain-core` відправляє транзакцію
в мережу незалежно від типу підписувача. Підписувачі-відправники транслюють її через
свого провайдера; усі інші типи використовують `sendTransaction`, який ви передаєте (core не має
залежності від RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Використання з Kit Client (плагін keychainSigner)

`@solana/keychain-kit-plugin` встановлює підписувач ключового ланцюжка
безпосередньо на [Kit client](https://github.com/anza-xyz/kit), підключаючи його
як `payer` та `identity`, що дозволяє пропустити ручне налаштування `pipe`,
показане вище:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Плагін приймає ту саму конфігурацію з тегом бекенда, що й `createKeychainSigner`,
окрім Crossmint і нативного режиму Fordefi (заданий `chain`). Ці бекенди переписують
транзакцію на стороні сервера, тому не можуть виступати клієнтським `payer` або
`identity`; плагін відхиляє їх під час компіляції та виконання. У збірку включається лише
бекенд, до якого він звертається (пакети бекендів завантажуються через динамічний
`import()`).

Використовуйте `keychainPayer` або `keychainIdentity`, щоб призначити лише одну
роль і поєднувати бекенди на одному клієнті:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Вже маєте `SolanaTransactionSigner`? Це валідний Kit
`TransactionPartialSigner`, тож його можна встановити через
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
(`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Скасування та непідтверджені трансляції

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` та
`signMessages` приймають `{ abortSignal }` другим аргументом. Переривання
припиняє очікування, але не скасовує роботу, яку провайдер уже прийняв.

У нативному авторежимі Crossmint і Fordefi збій не означає, що нічого не
відбулося. Якщо провайдер міг прийняти транзакцію, код помилки —
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` встановлюється, якщо створення було прийнято, а
`context.idempotencyKey` містить ключ, отриманий із повідомлення. Повторне надсилання
побайтово ідентичної транзакції безпечне; перебудована транзакція (наприклад, з новим
blockhash) — це новий переказ. `providerMayHaveAccepted(error)` та
`providerStatus(error)` із `@solana/keychain-core` допомагають класифікувати помилку.
Перед повторною спробою звірте стан із провайдером.

const [signature] = await signer.signAndSendTransactions([transaction]);

### Fordefi

Fordefi має три режими підписання, які фіксуються під час створення через `chain` і
`pushMode`. Кожен режим надає рівно один метод для транзакцій, а всі три підписують
повідомлення:

| Режим          | Конфігурація                                      | Тип                        | Метод                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Чорна скринька     | `chain` не задано                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Нативний авто   | `chain` задано, `pushMode` пропущено або `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Нативний ручний | `chain` задано, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

API-запити автентифікуються підписом запиту ECDSA P-256: передайте
ключ підписання як `privateKeyPem` або зберігайте його в KMS/HSM, передавши
`requestSigner`.

**Нативний авторежим** (рекомендовано для використання в мережі): задайте `chain`, і Fordefi
сам підписує та транслює транзакцію. Оскільки Fordefi може замінити
blockhash або комісії перед підписанням, підписувач є Kit
`TransactionSendingSigner`: використовуйте його з
`signAndSendTransactionMessageWithSigners`, а не за схемою часткового підписувача, наведеною
вище. Нативний авторежим приймає лише непідписану транзакцію, єдиним потрібним
підписувачем якої є сховище (vault), і його не можна використовувати з `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Нативний ручний режим**: задайте `chain` і `pushMode: "manual"`. Fordefi переписує
повідомлення (recent blockhash, інструкції комісії Compute Budget) і підписує його,
але не транслює. `modifyAndSignTransactions()` повертає транзакцію,
підписану Fordefi, яка замінює надіслану вами: завжди продовжуйте з
поверненою транзакцією. Fordefi має бути платником комісії та підписувати раніше
за будь-якого іншого потрібного підписувача. Зміни не показуються у вигляді diff, тому перевіряйте результат перед
трансляцією.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Режим чорної скриньки**: пропустіть `chain`. Fordefi підписує необроблені байти та не транслює; ви самостійно збираєте та надсилаєте транзакцію. Використовуйте це з vault-сховищем типу "чорна скринька" Fordefi.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Можливості підписувачів

`@solana/keychain-core` визначає один інтерфейс для кожного типу підписувача Kit. Кожен додає
`isAvailable(): Promise<boolean>` до відповідного інтерфейсу `@solana/signers`:

- `SolanaTransactionSigner` (Kit `TransactionPartialSigner`): повертає підписи
  для транзакції, якою ви володієте.
- `SolanaModifyingSigner` (Kit `TransactionModifyingSigner`): переписує
  транзакцію, підписує її та повертає нову транзакцію без трансляції.
- `SolanaSendingSigner` (Kit `TransactionSendingSigner`): підписує й транслює
  через свого провайдера.
- `SolanaMessageSigner` (Kit `MessagePartialSigner`): підписує повідомлення поза мережею (off-chain).
  Це окремо від типів для транзакцій.

`SolanaSigner` — це об’єднання трьох типів для транзакцій. Тип, який повертає кожна фабрика,
точно вказує тип свого бекенда. Якщо конфігурація відома лише під час
виконання, звужуйте тип за допомогою `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` або `isSolanaMessageSigner`. `signerCapabilities(signer)`
повідомляє про всі чотири одразу.

| Бекенд                                                                                                     | Тип                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (чорна скринька) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (без підписання повідомлень)  |
| fordefi (нативний ручний)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (нативний авто)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (без підписання повідомлень)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Створення власних підписантів

Реалізуйте інтерфейси можливостей, які підтримує ваш бекенд:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Реалізуйте лише те, що підтримує ваш бекенд. Kit класифікує підписувачів за наявними
методами, тому ніколи не додавайте метод, який просто викидає помилку.

Перегляньте
[посібник із додавання підписантів](/docs/tools/keychain/adding-signers), щоб
інтегрувати додаткові служби керування ключами.
