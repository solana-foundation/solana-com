Keychain абстрагує бекенд підписання, але експлуатація підписанта у production —
все одно ваша відповідальність. Ці практики застосовуються до всіх бекендів; щодо
вибору конкретного — див. [Вибір бекенду](/docs/tools/keychain/choosing-a-backend).

## Розділяйте гарячі та холодні підписанти

Використовуйте операційний підписант із низьким балансом («гарячий») для частих
автоматизованих транзакцій, і окремий підписант із високою вартістю («холодний»)
для переміщення коштів із treasury. Забезпечте холодний підписант MPC-кастодією
або хмарним HSM і вимагайте політик затвердження перед підписанням. Оскільки
інтерфейс однаковий, кожна роль може використовувати різний бекенд, не змінюючи
точок виклику.

## Виконуйте ротацію ключів цілеспрямовано

У Solana ключ підписання _є_ адресою облікового запису, тому ротація ключа створює
нову адресу. Плануйте ротацію як міграцію: створіть новий ключ, переназначте
відповідні повноваження (або перемістіть кошти) на нову адресу, а потім виведіть
старий із використання. Використовуйте окремі ключі для кожного середовища, щоб
ключі devnet ніколи не перевикористовувалися у mainnet.

## Надавайте доступ за принципом найменших привілеїв

Обмежте облікові дані кожного бекенду мінімумом, необхідним для підписання. Для
AWS KMS це `kms:Sign` і `kms:DescribeKey` для конкретного ключа; надавайте перевагу
ролям IAM над статичними обліковими даними. Застосовуйте той самий принцип до
політик Vault і ключів API керованого гаманця.

## Плануйте забезпечення доступності

Віддалені бекенди залежать від мережевого сервісу. Викликайте `isAvailable()` перед
зверненням до підписанта, застосовуйте повторні спроби з відкладенням при
тимчасових збоях і визначте резервний шлях на випадок відмов. Keychain вимагає
HTTPS для віддалених бекендів і застосовує стандартний тайм-аут запиту.

## Захищайте секрети та транспорт

- Усі віддалені бекенди взаємодіють через HTTPS; кінцеві точки без HTTPS відхиляються.
- Надавайте ключі API, токени та облікові дані через менеджер секретів або змінні
  середовища — ніколи не зашивайте їх у код і не зберігайте у системі контролю версій.
- Keychain очищує відповіді з помилками, щоб уникнути витоку секретів у журнали;
  стежте, щоб ваші власні журнали не містили необроблених облікових даних і ключового матеріалу.

## Моніторинг та аудит підписання

Відстежуйте показник успішності підписання, затримку та кількість збоїв, і
налаштуйте сповіщення про аномальні сплески — дивіться метрики у
[Production Readiness](/docs/tools/production-readiness#monitoring). Увімкніть журнали аудиту на стороні провайдера
(KMS, Vault або кастодіан) і звіряйте їх із транзакціями, що надсилає ваш застосунок.
