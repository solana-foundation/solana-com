## Сервіси

Запуск екземпляра Private Channels означає розгортання наступних сервісів Docker Compose:

| Контейнер                                  | Роль                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| `private-channel-postgres-primary`         | База даних стану вузла для запису (PostgreSQL 16)                               |
| `private-channel-postgres-replica`         | База даних стану вузла для читання (потокова репліка)                            |
| `private-channel-postgres-indexer`         | База даних індексатора та оператора                                           |
| `private-channel-write-node`               | Приймає та виконує транзакції (порт 8900, лише loopback)           |
| `private-channel-read-node`                | Обробляє RPC-запити на читання (порт 8901, лише loopback)                     |
| `private-channel-gateway`                  | Маршрутизує запити між вузлами запису та читання; забезпечує RBAC (порт 8899) |
| `private-channel-indexer-solana`           | Відстежує події `Deposit` у Solana через Yellowstone gRPC                |
| `private-channel-indexer-private-channel`  | Відстежує події `Burn` у каналі через RPC-поллінг                   |
| `private-channel-operator-solana`          | Карбує токени каналу після підтвердження депозитів                        |
| `private-channel-operator-private-channel` | Викликає `ReleaseFunds` у Mainnet після підтвердження виведень          |
| `private-channel-auth`                     | Опціональний сервіс JWT/RBAC (профіль Docker: `auth`)                      |

Також включено контейнери спостережуваності (`prometheus`, `grafana`, `cadvisor`).

## Шлюз

Ці параметри мають зумовлені значення за замовчуванням для налаштування Docker Compose у devnet. Перевизначайте їх лише якщо запускаєте шлюз поза Docker або розгортаєте в продакшн.

| Змінна середовища                         | За замовчуванням                                                             | Обов'язково            | Опис                                        |
| ------------------------------- | ------------------------------------------------------------------- | ------------------- | -------------------------------------------------- |
| `GATEWAY_PORT`                  | `8899` (devnet)                                                     | Ні                  | Порт прослуховування                                        |
| `GATEWAY_WRITE_URL`             | `http://write-node:8900` (значення з env-файлу devnet; бінарний файл не має власного значення за замовчуванням) | **Так**             | URL вузла запису — запити `sendTransaction` спрямовуються сюди     |
| `GATEWAY_READ_URL`              | `http://read-node:8901` (значення з env-файлу devnet; бінарний файл не має власного значення за замовчуванням)  | **Так**             | URL вузла читання — всі інші RPC-методи спрямовуються сюди   |
| `GATEWAY_CORS_ALLOWED_ORIGIN`   | `*`                                                                 | Ні                  | Значення заголовка `Access-Control-Allow-Origin`         |
| `JWT_SECRET`                    | -                                                                   | Ні                  | Вмикає RBAC; повинен збігатися з `JWT_SECRET` сервісу авторизації |
| `AUTH_DATABASE_URL`             | -                                                                   | Якщо встановлено `JWT_SECRET` | БД авторизації для перевірки права власності на гаманець                |
| `AUTH_DATABASE_MAX_CONNECTIONS` | `10`                                                                | Ні                  | Розмір пулу з'єднань з БД авторизації                       |
| `METRICS_PORT`                  | `9101`                                                              | Ні                  | Порт метрик Prometheus                            |
| `RUST_LOG`                      | `info`                                                              | Ні                  | Рівень логування                                          |

> `GATEWAY_WRITE_URL` та `GATEWAY_READ_URL` використовують імена сервісів Docker Compose
> (`write-node`, `read-node`) під час роботи в Docker. Використовуйте еквіваленти `localhost`
> лише при запуску бінарного файлу шлюзу безпосередньо поза Docker.
>
> Вбудоване значення за замовчуванням для `GATEWAY_PORT` у бінарному файлі шлюзу — `8898`.
> `.env.example` та `.env.devnet` обидва встановлюють його рівним `8899`, що й
> використовується у налаштуванні Docker Compose (`versions.env` містить лише прив'язки
> версій інструментів і образів, а не порти сервісів). Значення `8898` за замовчуванням
> застосовується лише при запуску бінарного файлу безпосередньо без env-файлу.

<Callout type="warning">
  `GATEWAY_CORS_ALLOWED_ORIGIN` за замовчуванням має значення `*`, що дозволяє будь-якому джерелу
  звертатися до шлюзу з браузера. Обмежте це значення реальним джерелом вашого застосунку
  перед будь-яким розгортанням у продакшн.
</Callout>

## Вузол запису та вузол читання

Повний довідник з конфігурації вузла запису та вузла читання знаходиться у
[`docs/CONFIG.md`](https://github.com/solana-foundation/solana-private-channels/blob/main/docs/CONFIG.md)
в репозиторії.

## Сервіс авторизації

| Змінна середовища                         | Обов'язково            | Опис                                                                                                                  |
| ------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                    | **Так**             | Секрет підпису HS256; повинен збігатися з `JWT_SECRET` шлюзу                                                                  |
| `AUTH_PORT`                     | Ні (за замовчуванням `8903`) | Порт прослуховування                                                                                                                  |
| `AUTH_DATABASE_URL`             | **Так**             | Рядок підключення PostgreSQL до бази даних авторизації                                                                           |
| `CORS_ALLOWED_ORIGIN`           | Ні (за замовчуванням `*`)    | Значення заголовка `Access-Control-Allow-Origin` для цього сервісу (незалежно від `GATEWAY_CORS_ALLOWED_ORIGIN` шлюзу) |
| `AUTH_DATABASE_MAX_CONNECTIONS` | Ні (за замовчуванням `10`)   | Розмір пулу з'єднань з БД авторизації                                                                                                 |

## Довідник портів сервісів

| Сервіс          | Порт хоста  | Прив'язка                                                                           |
| ---------------- | ---------- | --------------------------------------------------------------------------------- |
| Шлюз          | 8899       | Всі інтерфейси                                                                    |
| Вузол запису       | 8900       | Лише loopback                                                                     |
| Вузол читання        | 8901       | Лише loopback                                                                     |
| Стрімер         | 8902       | Лише внутрішній (`expose`, не публікується на хості); не входить до devnet-стека |
| Сервіс авторизації     | 8903       | Всі інтерфейси                                                                    |
| Метрики оператора | 9102, 9103 | Всі інтерфейси                                                                    |
| Grafana          | 37429      | Всі інтерфейси                                                                    |
| Prometheus       | 9090       | Всі інтерфейси                                                                    |
| cAdvisor         | 8080       | Всі інтерфейси                                                                    |

> **Примітка щодо безпеки:** Порти вузла запису та вузла читання прив'язані лише до loopback
> (`127.0.0.1`). Шлюз, сервіс авторизації, метрики оператора, Grafana,
> Prometheus та cAdvisor публікуються на всіх мережевих інтерфейсах у
> налаштуванні Docker Compose для devnet. Захистіть їх брандмауером на рівні хоста або мережі
> для будь-якого використання поза локальною розробкою; RBAC охоплює лише власні JSON-RPC
> методи шлюзу, але не ці інші сервіси. Стрімер є винятком: це
> неавтентифікований внутрішній потік, який Docker ніколи не публікує на хості.
