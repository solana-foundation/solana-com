Kora — це Rust workspace із трьома крейтами:

- `kora-lib` містить основну логіку та RPC-сервер,
- `kora-cli` збирає бінарний файл `kora`, який запускають оператори, а
- `kora-deploy` — спеціалізований інструмент розгортання програм із окремим версіонуванням.
  Усе нижче розташоване в `crates/lib/src`, якщо не зазначено інше.

## Життєвий цикл запиту

На діаграмі нижче показано загальний потік транзакції через Kora.
Розуміння шляху викликів важливе для налаштування вузла Kora та додавання
нових функцій.

## Де розташований кожен етап

| Етап на діаграмі | Джерело                               | Точка входу                           |
| -------------------- | ------------------------------------ | ------------------------------------- |
| Шлюз              | `rpc_server/server.rs`               | `run_rpc_server`                      |
| Диспетчеризація             | `rpc_server/rpc.rs`                  | `KoraRpc`                             |
| Логіка окремих методів     | `rpc_server/method/`                 | один файл на кожен метод JSON-RPC          |
| Валідація           | `validator/transaction_validator.rs` | `TransactionValidator`                |
| Плагіни              | `plugin/mod.rs`                      | `TransactionPluginRunner`             |
| Підписання              | `signer/`                            | на основі крейту `solana-keychain` |

Ще два файли, які варто знати: `config.rs` визначає всю схему `kora.toml`, а
`state.rs` зберігає десеріалізовану конфігурацію в глобальному стані процесу.

### Читання RPC-сервера

`rpc.rs` — це тонкий шар диспетчеризації: один метод на кожну кінцеву точку JSON-RPC і
найшвидший спосіб побачити весь API. Логіка кожного методу міститься в окремому файлі в
`rpc_server/method/`. Прочитайте `sign_transaction.rs` від початку до кінця; інші методи
підписання є його варіаціями.

### Читання валідатора

`transaction_validator.rs` і `transaction/instruction_util.rs` містять логіку для
валідації транзакцій та інструкцій. Крім того, тут є тести властивостей безпеки політики
fee-payer, які розміщені по одному файлу на кожну програму з обмеженим доступом у
`validator/transaction_validator/fee_payer_policy_props/`.

## Корисні домовленості

**Валідація за замовчуванням.** Кожен прапорець у `[validation.fee_payer_policy]`
має значення за замовчуванням `false`, а структури політики мають `#[serde(default)]`. Таке
поєднання зумисне: додавання нової інструкції з обмеженням не повинно ламати
існуючу конфігурацію оператора, і вона має призводити до відмови, а не до
випадкового дозволу. Зберігайте обидві умови, коли додаєте прапорець.

**Валідуйте розв'язану транзакцію, а не необроблену.** Необроблена
`VersionedTransaction` містить лише статичні ключі акаунтів, тому валідація або
розрахунок вартості V0-транзакції на її основі непомітно пропускає акаунти таблиць пошуку
і призводить до заниженої плати. `VersionedTransactionResolved::from_transaction` розв'язує ці
адреси наперед, тому кожен наступний етап приймає розв'язаний тип.

## Додавання плагіна транзакцій

Плагіни реалізують трейт `TransactionPlugin` у `plugin/mod.rs`. Він має два
методи: `validate` виконується для кожної транзакції під час потоків підписання, а
`validate_config` виконується один раз під час запуску й повертає оператору помилки та
попередження. `PluginExecutionContext` повідомляє плагіну, який із чотирьох методів
підписання його викликав.

`TransactionPluginRunner::from_config` виконує зіставлення за `TransactionPluginType`,
визначеним у `config.rs`. Новий вбудований плагін — це новий варіант там плюс нова
гілка match у раннері. Два плагіни, що постачаються нині, — `gas_swap` і
`deploy_authority`.

## Тестування

Kora зберігає конфігурацію в глобальному стані процесу, тому `tests/` оголошує по одній
цілі `[[test]]` на кожну фазу, і кожна ціль запускає власний вбудований surfnet разом із
вузлом Kora, ініціалізованим з нуля. Одна конфігурація на бінарний файл: для нової фази потрібна нова
ціль, а не новий модуль в існуючій.

```bash
cargo test -p tests --test <target>
```

Усе інше налаштовано через `justfile`. Читайте його, а не
відтворюйте команди вручну.
