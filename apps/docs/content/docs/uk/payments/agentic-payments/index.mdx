Агентські платежі дозволяють програмному забезпеченню дізнатися ціну, авторизувати платіж і отримати
ресурс в межах одного HTTP-процесу. Агент може оплатити запит даних, інференс
моделі або виклик інструмента, не створюючи попередньо платіжний акаунт і не копіюючи
API-ключ.

## Загальний потік платежу

MPP і x402 використовують різні заголовки та моделі даних, але їхній базовий HTTP-потік
схожий:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP і x402

Обидва протоколи можуть виконувати розрахунки стейблкоїнами в Solana. Обирайте залежно від
платіжної моделі та сумісності, потрібних вашому сервісу, а не лише за спільним кодом
статусу `402`.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Виклик (challenge)               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| Авторизація клієнта    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Квитанція                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Моделі платежів у Solana   | Разові наміри (intents) `charge` і `session` з лімітом та оплатою за фактом використання           | Схеми, як-от `exact` і `upto`; підтримка залежить від мережі та клієнта |
| Архітектура розрахунків | Перевірка на сервері або необов’язковий релей чи шлюз                | Сервер ресурсу з локальною верифікацією або фасилітатор                 |
| Хороша відправна точка     | API, яким потрібна семантика HTTP-автентифікації або багаторазовий облік використання | Ресурси з оплатою за запит і наявні клієнти x402                      |

MPP — це **Machine Payments Protocol**. Не плутайте його з **Model
Context Protocol (MCP)**. MCP надає агентам доступ до інструментів і ресурсів; MPP або x402
можуть вимагати оплату, коли агент викликає один із цих інструментів.

<Callout type="info">
  Сервіс може пропонувати більше ніж один протокол. Клієнт обирає підтримуваний ним варіант
  оплати, а потім використовує відповідні заголовки виклику, авторизації та
  квитанції протягом усього обміну.
</Callout>
