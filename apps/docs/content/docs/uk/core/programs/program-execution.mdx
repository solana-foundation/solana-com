<Callout type="info" title="Підсумок">
  Програми компілюються в sBPF через LLVM і виконуються в ізольованій VM з бюджетом
  1,4 млн CU на транзакцію. Середовище виконання кешує до 512 скомпільованих програм,
  надає системні виклики для логування, CPI, криптографії та пам'яті, а також затримує
  нові розгортання на 1 slot.
</Callout>

## Компіляція

Solana використовує [LLVM](https://llvm.org/) для компіляції програм у бінарні файли
[ELF](https://en.wikipedia.org/wiki/Executable_and_Linkable_Format),
що містять Solana Bytecode Format (sBPF). ELF-бінарний файл зберігається в мережі у
виконуваному акаунті.

<Callout>
  sBPF — це власний варіант байткоду [eBPF](https://en.wikipedia.org/wiki/EBPF) від Solana,
  адаптований для середовища виконання Solana. Це не стандартний eBPF —
  він містить специфічні для Solana модифікації.
</Callout>

## Написання програм

Програми Solana переважно пишуться на
[Rust](https://rust-book.cs.brown.edu/title-page.html) з використанням одного з трьох
підходів:

<Cards>
  <Card title="Anchor" href="https://www.anchor-lang.com/docs">
    Фреймворк, що використовує макроси Rust для зменшення шаблонного коду. Рекомендується
    більшості розробників.
  </Card>
  <Card title="Pinocchio" href="/docs/clients/official/rust#program-crates">
    Легка бібліотека Rust із нульовим копіюванням, оптимізована для мінімального споживання
    обчислювальних ресурсів і розміру бінарного файлу. Містить спеціалізовані крейти для поширених CPI.
  </Card>
  <Card title="Native Rust" href="/docs/programs/rust">
    Чистий Rust без фреймворків. Надає повний контроль, але вимагає більше ручної
    реалізації.
  </Card>
</Cards>

Дивіться [Cross-Program Invocations](/docs/core/cpi) для ознайомлення з концепціями та прикладами CPI,
що застосовуються в усіх цих підходах.

## Модель виконання програм

Коли транзакція обробляється, середовище виконання послідовно виконує кожну інструкцію
через
[`process_message()`](https://github.com/anza-xyz/agave/blob/v3.1.8/svm/src/message_processor.rs#L15).
Для кожної інструкції середовище виконання:

1. **Готує контекст інструкції.** Викликає
   [`prepare_next_top_level_instruction()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L436),
   щоб зіставити індекси акаунтів інструкції, встановити прапорці підписанта та запису, а також
   налаштувати
   [`TransactionContext`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L467).

2. **Перевіряє прекомпілятори.** Якщо програма є
   [прекомпілятором](/docs/core/programs/precompiles), середовище виконання викликає
   [`process_precompile()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L491),
   що все одно додає та знімає кадр стека (через _rs`push()`_ та _rs`pop()`_),
   але обходить sBPF VM і пошук у кеші програм, виконуючи нативний код
   безпосередньо.

3. **Додає кадр стека.** (Кроки 3–6 відбуваються всередині
   [`InvokeContext::process_instruction()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L481)
   та
   [`process_executable_chain()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L507),
   що викликаються з _rs`process_message()`_.) Викликає
   [`push()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L233)
   на
   [`InvokeContext`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L184),
   що збільшує висоту стека інструкцій і забезпечує дотримання правила повторного входу:
   програма може повторно входити сама в себе лише якщо **безпосередній** викликач (програма
   на поточній вершині стека інструкцій) є тією самою програмою.
   Глибока само-рекурсія (A -> A -> A) дозволена з урахуванням обмежень глибини стека.
   Інші шаблони повторного входу (наприклад, A викликає B, B викликає A) повертають
   _rs`InstructionError::ReentrancyNotAllowed`_.

4. **Визначає програму.** Середовище виконання викликає
   [`process_executable_chain()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L507),
   яка визначає завантажувач. Якщо власником program account є
   [native loader](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L517),
   програма є вбудованою, і її точка входу знаходиться безпосередньо в
   [`ProgramCacheForTxBatch`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L706).
   Якщо власником є один із BPF-завантажувачів (`bpf_loader_deprecated`,
   `bpf_loader`, `bpf_loader_upgradeable` або `loader_v4`), натомість
   викликається власна вбудована точка входу завантажувача.

5. **Виконує BPF-програму.** Для BPF-програм
   [точка входу завантажувача](https://github.com/anza-xyz/agave/blob/v3.1.8/programs/bpf_loader/src/lib.rs#L385)
   знаходить скомпільований виконуваний файл у кеші програм. Потім функція
   [`execute()`](https://github.com/anza-xyz/agave/blob/v3.1.8/programs/bpf_loader/src/lib.rs#L1449):
   - Серіалізує дані акаунтів у плаский буфер параметрів
   - Створює sBPF VM зі стеком, купою та областями пам'яті
   - Запускає скомпільований код, споживаючи обчислювальні одиниці під час виконання. Повертає
     _rs`ComputationalBudgetExceeded`_, якщо бюджет перевищено.
   - Десеріалізує дані акаунтів із буфера назад у стан акаунту

6. **Знімає кадр стека.** Викликає
   [`pop()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/invoke_context.rs#L268),
   яка перевіряє, що інструкція не порушила правила обліку середовища виконання
   (баланси lamport збалансовані, акаунти лише для читання не були змінені,
   розміри даних акаунтів знаходяться в межах допустимого).

7. **Накопичує обчислювальні одиниці.** Обчислювальні одиниці, спожиті інструкцією,
   додаються до загальної суми транзакції через
   [`saturating_add`](https://github.com/anza-xyz/agave/blob/v3.1.8/svm/src/message_processor.rs#L53).

## Кеш програм

Середовище виконання підтримує глобальний
[`ProgramCache`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L677),
що зберігає перевірені та скомпільовані програми. Він підтримує граф форків і обробляє
правила видимості розгортань, виселення та перекомпіляцію на межі epoch.

### Типи записів кешу

Кожна кешована програма має
[`ProgramCacheEntryType`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L132),
що визначає її поведінку під час виконання:

| Тип                                                                                                              | Опис                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`Loaded`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L147)             | Перевірена та скомпільована програма, готова до виконання.                                                                                                                                                                                                                                              |
| [`Builtin`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L149)            | Нативна програма, скомпільована у бінарний файл validator (System, Stake, Vote тощо). Не зберігається в мережі.                                                                                                                                                                                               |
| [`Unloaded`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L145)           | Раніше перевірена програма, скомпільований виконуваний файл якої було виселено з пам'яті для звільнення місця. Все ще відстежує статистику використання. Може бути перезавантажена без повторної перевірки.                                                                                                                             |
| [`FailedVerification`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L134) | Запис-«надгробок» для програм, які не пройшли верифікатор sBPF за поточного набору функцій. Може стати `Loaded`, якщо активація функцій змінить правила верифікації.                                                                                                                              |
| [`Closed`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L139)             | Запис-«надгробок» для програм, які були явно закриті або так і не були розгорнуті. Також використовується для акаунтів (наприклад, буферних), що належать завантажувачу, але не містять виконуваного коду.                                                                                                               |
| [`DelayVisibility`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L141)    | Синтетичний запис-«надгробок», який повертає [`ProgramCacheForTxBatch::find()`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L755), коли запис `Loaded` існує, але ще не набрав чинності (його `effective_slot` знаходиться в майбутньому). Ніколи не зберігається безпосередньо в кеші. |

### Затримка видимості

Щойно розгорнуті або оновлені програми не набирають чинності негайно. Константа
[`DELAY_VISIBILITY_SLOT_OFFSET`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L32)
дорівнює `1`, тобто програма, розгорнута в slot N, набирає чинності в slot
N+1. Протягом slot розгортання будь-яка спроба викликати нову версію повертає
_rs`DelayVisibility`_, і середовище виконання повідомляє «Program is not deployed.»

### Політика виселення

Кеш містить до
[`MAX_LOADED_ENTRY_COUNT`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L31)
(512) записів скомпільованих програм. Коли ліміт досягнуто, найменш використовувані
програми виселяються до стану _rs`Unloaded`_. Використання відстежується за допомогою
[`tx_usage_counter`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L197)
(збільшується щоразу, коли транзакція звертається до програми) та
[`latest_access_slot`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L199).

### Перекомпіляція на межі epoch

Якщо активація функції змінює
[`ProgramRuntimeEnvironments`](https://github.com/anza-xyz/agave/blob/v3.1.8/program-runtime/src/loaded_programs.rs#L529)
на межі epoch, усі кешовані програми
[перекомпілюються](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank.rs#L1494)
під нове середовище.

## Повернення даних

Програми можуть встановлювати повернені дані через системний виклик `sol_set_return_data`. Дані
зберігаються у структурі рівня транзакції
[`TransactionReturnData`](https://github.com/anza-xyz/agave/blob/v3.1.8/transaction-context/src/lib.rs#L499),
яка містить байти даних і `program_id` програми, чия
інструкція викликала системний виклик. Максимальний розмір — 1 024 байти
(_rs`MAX_RETURN_DATA`_).
