Цей розділ надає деякі поширені команди та приклади, щоб допомогти вам розпочати
використання [Anchor CLI](https://www.anchor-lang.com/docs).

<Steps>
<Step>

### Ініціалізуйте проєкт

Створіть новий проєкт Anchor, виконавши наведену нижче команду. Вона створить
новий каталог із назвою проєкту та використає його для ініціалізації нового
проєкту Anchor.

```terminal
$ anchor init <project-name>
```

Наприклад, наведена нижче команда створить проєкт під назвою `my-project`.
Каталог `my-project` міститиме модульну програму на Rust та шаблон тестів на Rust,
який використовує LiteSVM.

```terminal
$ anchor init my-project
```

Щоб натомість згенерувати шаблон тестів на TypeScript, виберіть його явно.
Наприклад, використайте шаблон Mocha:

```terminal
$ anchor init my-project --test-template mocha
```

Шаблони тестів на TypeScript потребують Node.js та менеджера пакетів JavaScript.

Потім перейдіть до каталогу проєкту:

```terminal
$ cd <project-name>
```

Див. [структуру файлів проєкту](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) Anchor.

</Step>
<Step>

### Збірка програми

Щоб зібрати ваш проєкт, виконайте наступну команду:

```terminal
$ anchor build
```

Ви можете знайти скомпільовану програму в каталозі `/target/deploy`.

<Callout type="warn" title="Не вдалося встановити platform tools">
  Якщо під час збірки виникає повідомлення про недійсний каталог platform-tools, перевстановіть інструменти збірки SBF, а потім повторіть збірку:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Розгортання програми

Щоб розгорнути ваш проєкт, виконайте таку команду:

```terminal
$ anchor deploy
```

Ця команда розгортає вашу програму на `cluster`, вказаному у файлі
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml).

</Step>
<Step>

### Тестування програми

Щоб протестувати ваш проєкт, виконайте таку команду:

```terminal
$ anchor test
```

Ця команда збирає, розгортає та запускає тести для вашого проєкту.

<Callout>
  При використанні кластера `localnet`, Anchor автоматично запускає локальний
  валідатор, розгортає програму, виконує тести, а потім зупиняє валідатор.
</Callout>

<Callout type="warn" title="Помилки засобу запуску тестів JavaScript">

Якщо ви вибрали шаблон тестів на JavaScript або TypeScript, будь-яка з наведених нижче помилок може свідчити, що Node.js або налаштований менеджер пакетів не встановлено:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
