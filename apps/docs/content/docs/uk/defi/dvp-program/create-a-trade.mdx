`CreateDvp` фіксує умови угоди та створює два ескроу-акаунти, які
сторони поповнюватимуть. Токени він не переміщує. Надіслати його може будь-хто, тож запис
може надійти від контрагента, оператора розрахункового органу або третьої сторони,
а кожен інший учасник перевіряє збережені умови, перш ніж діяти на їхній підставі (див.
[поповнення частин угоди](/docs/defi/dvp-program/fund-the-legs)).

У фрагментах коду використовується згенерований клієнт напряму, із заповнювачами замість адрес,
щоб було видно задіяні акаунти та підписантів. Вони націлені на devnet, де
програма розгорнута за тією самою адресою, що й у mainnet-beta.

## Встановлення

Станом на 2 жовтня 2026 року для клієнтів DvP не опубліковано жодного пакета. Обидва
генеруються з IDL програми в репозиторії та використовуються з вихідного коду.

Ці сторінки написано для коміту `df9919e`, із `@solana/kit` 8 у
TypeScript та крейтами `solana-*` 2.x у Rust.

Фрагменти коду на кожній сторінці кроку є наступними один за одним: кожна сторінка використовує клієнт, підписантів
та адреси, визначені на попередніх сторінках. `payerSigner`, `userASigner`,
`userBSigner` та `authoritySigner` — це `TransactionSigner` для платника
rent, двох сторін і розрахункового органу, наприклад отримані з
`createKeyPairSignerFromBytes`. Фрагменти Rust лише будують інструкції, а підписання
та надсилання залишають на розсуд викликача.

## Виведення адрес

Запис угоди — це program-derived address, виведена з розрахункового органу,
двох сторін, двох mint-адрес і nonce. Кожен ескроу — це associated
token account запису для одного з mint. Обидва виведення не потребують доступу до мережі.

Використовуйте випадковий 64-бітний nonce для кожної угоди. Оскільки створення не потребує дозволів,
передбачуваний nonce дає змогу третій стороні зайняти адресу, яку мала
використати угода. Передавайте nonce та суми як `bigint` у TypeScript; згенерований
клієнт відхиляє `number`.

Перед запуском замініть кожен заповнювач `..._HERE` на справжню адресу.
`address()` перевіряє base58 і викидає помилку на заповнювачі, а `pubkey!` не
компілюється.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## Фіксація умов

`CreateDvp` приймає дві суми в базових одиницях, строк дії, nonce та чотири
необов'язкові поля: непрозоре посилання розміром до 64 байтів, адресу призначення розрахунку
для кожної зі сторін і найранніший час розрахунку (див. «Примітки»). Адреса призначення —
це місце, куди потрапляють надходження цієї сторони під час розрахунку, наприклад депозитний гаманець
кастодіана; за замовчуванням це власна адреса сторони, і після створення
запису її не можна змінити. Повернення коштів і відшкодування завжди надходять на власний token account
сторони для mint цієї частини угоди, а не на адресу призначення, хоч би хто поповнив ескроу.

Платник сплачує rent для запису, tombstone для nonce та обох ескроу.
При закритті цей rent отримує той, хто підписує інструкцію закриття, а не
платник. Tombstone ніколи не закривається, тож кожна угода залишає невеликий постійний
баланс. Плануючи бюджет SOL для платника, обчислюйте суми rent за допомогою
методу RPC `getMinimumBalanceForRentExemption`, а не прописуйте їх жорстко.

<Tabs items={["TypeScript", "Rust"]}>

Для фрагмента TypeScript потрібні `getProgramDerivedAddress` і `getAddressEncoder`
з `@solana/kit`, а також `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` із клієнта в
області видимості. Білдер Rust залишає system program та associated token program
зі значеннями за замовчуванням.

## Примітки

- **Строк дії.** Лише Settle перевіряє строк дії. Reclaim, Cancel і Reject працюють
  і після його завершення, а депозит, що надійшов після завершення строку, може бути повернений
  стороною цієї частини угоди. Строк дії може становити щонайбільше один рік після створення.
- **Час — це мережевий час.** Програма зчитує ончейн-годинник, який може
  відрізнятися від реального часу, іноді на десятки секунд, і може стрибати
  вперед. Залишайте запас між завершенням строку дії та запланованим часом розрахунку,
  уникайте поповнення чи розрахунку поблизу будь-якої з меж і не покладайтеся на строк дії
  для забезпечення дедлайну з точністю до секунди. У README програми радять закладати
  приблизно хвилину розбіжності.
- **Найраніший розрахунок.** Необов'язково. Якщо задано, Settle відхиляється до цього часу,
  і він не може бути пізнішим за строк дії.
- **Перевірки під час створення.** Створення завершується помилкою `PartyNotSignerCapable`, якщо сторона
  не є акаунтом, що належить system program (це виключає мультипідпис SPL Token),
  а також `SettlementDestinationIsSwapDvp`, `SelfDvp`, `SameMint`, `ZeroAmount`,
  `SettlementAuthorityIsParty` або `ExpiryNotInFuture`. Повний перелік наведено в
  [таблиці помилок](/docs/defi/dvp-program#errors).
