Фінансування — це звичайний `TransferChecked` в ескроу ноги, тому будь-який гаманець
або система зберігання, що може надіслати переказ токена, може профінансувати ногу. Клієнт DvP
потрібен лише для читання запису угоди перед фінансуванням. Програма перевіряє
баланси ескроу лише під час розрахунку; ніщо не перевіряє переказ у момент його надходження,
тому кожна сторона читає запис угоди перед переказом.

Ця сторінка є продовженням розділу
[створення угоди](/docs/defi/dvp-program/create-a-trade); клієнт і підписанти
переносяться.

## Перевірте умови

Створення запису не потребує дозволів, а адреси ескроу виводяться лише із
запису та mint, але ніколи не з умов. Тому переказ в ескроу може
потрапити під умови, з якими ви ніколи не погоджувалися, зокрема під адреси призначення
розрахунку, що перенаправляють виручку вашого контрагента на третю адресу.
Перед фінансуванням прочитайте акаунт `SwapDvp` і звірте його з погодженою
угодою.

`verifySwapDvp` у TypeScript і `verify::decode_swap_dvp_account` у Rust
підтверджують, що акаунт належить програмі DvP, має рівно 458 байтів і
знаходиться за адресою, яка виводиться з його власних полів (`fetchSwapDvpChecked` виконує
лише перші дві перевірки). Звичайні зчитувачі `fetchSwapDvp` і `decodeSwapDvp`
не виконують жодної з цих перевірок. Перевірки сторін, сум, часу та призначень
виконує той, хто викликає, звіряючи їх із погодженою угодою.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { unwrapOption } from "@solana/kit";
    import { verifySwapDvp } from "./dvp";

    const trade = await verifySwapDvp(client.rpc, swapDvp);
    const t = trade.data;

    const expectedAmountA = 1_000_000_000n;
    const expectedAmountB = 998_500_000n;
    const expectedEarliestSettlement: bigint | null = null; // as agreed
    const expectedExpiry = 1_798_761_600n; // as agreed, unix seconds

    if (
      t.userA !== userA ||
      t.userB !== userB ||
      t.mintA !== mintA ||
      t.mintB !== mintB ||
      t.settlementAuthority !== settlementAuthority ||
      t.tokenProgramA !== tokenProgramA ||
      t.tokenProgramB !== tokenProgramB ||
      t.amountA !== expectedAmountA ||
      t.amountB !== expectedAmountB ||
      unwrapOption(t.earliestSettlementTimestamp) !== expectedEarliestSettlement ||
      t.expiryTimestamp !== expectedExpiry ||
      t.userASettlementDestination !== userA ||
      t.userBSettlementDestination !== userB
    ) {
      throw new Error("Stored terms do not match the agreed trade; do not fund");
    }

    if (t.expiryTimestamp <= BigInt(Math.floor(Date.now() / 1000)) + 60n) {
      throw new Error("Trade expires too soon to fund safely");
    }
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::verify::decode_swap_dvp_account;
    use solana_client::rpc_client::RpcClient;
    use solana_commitment_config::CommitmentConfig;

    // Read at confirmed: a record created moments ago is not visible at finalized yet.

        CommitmentConfig::confirmed(),
    );

    let trade = decode_swap_dvp_account(&swap_dvp, &account)?;

    let expected_amount_a: u64 = 1_000_000_000;
    let expected_amount_b: u64 = 998_500_000;
    let expected_earliest_settlement: Option<i64> = None; // as agreed
    let expected_expiry: i64 = 1_798_761_600; // as agreed, unix seconds

    if trade.user_a != user_a
        || trade.user_b != user_b
        || trade.mint_a != mint_a
        || trade.mint_b != mint_b
        || trade.settlement_authority != settlement_authority
        || trade.token_program_a != token_program_a
        || trade.token_program_b != token_program_b
        || trade.amount_a != expected_amount_a
        || trade.amount_b != expected_amount_b
        || trade.earliest_settlement_timestamp != expected_earliest_settlement
        || trade.expiry_timestamp != expected_expiry
        || trade.user_a_settlement_destination != user_a
        || trade.user_b_settlement_destination != user_b
    {
        return Err("stored terms do not match the agreed trade; do not fund".into());
    }

    let now_seconds: i64 = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)?
        .as_secs() as i64;
    if trade.expiry_timestamp <= now_seconds + 60 {
        return Err("trade expires too soon to fund safely".into());
    }
    ```

Якщо запис створив ваш контрагент або розрахунковий орган,
звірте кожне поле з умовами, які ви погодили поза реєстром. Якщо ви створили
його самі, це читання підтверджує, що запис потрапив у мережу в надісланому вигляді.

## Переказ в ескроу

Профінансуйте ногу рівно на погоджену суму. Програма обмежує розрахунок значенням
`amount_x` і повертає будь-який надлишок стороні ноги, тож надлишок не втрачається,
але він додає другий переказ під час розрахунку і може спричинити збій з деякими хуками
переказу (див. примітки нижче).

Використовуйте `TransferChecked`, а не неперевірений `Transfer`. Mint-и Token-2022 із
розширеннями, що залежать від mint account, як-от Pausable, відхиляють переказ,
який його не надає, а mint із хуком переказу потребує, щоб акаунти хука були
визначені й додані так само, як і для будь-якого іншого переказу цього
токена.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    Сторона ноги з активом, підписуючи як `userASigner`, фінансує ескроу A:

    ```ts
    import {
      findAssociatedTokenPda,
      getTransferCheckedInstruction,
    } from "@solana-program/token-2022";

    const [userAAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: userA,
      tokenProgram: tokenProgramA,
    });
    const [userBAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: userB,
      tokenProgram: tokenProgramB,
    });

    const fundAssetLeg = getTransferCheckedInstruction({
      source: userAAtaA,
      mint: mintA,
      destination: escrowA,
      authority: userASigner,
      amount: t.amountA,
      decimals: 6,
    }, { programAddress: tokenProgramA });

    await client.sendTransaction([fundAssetLeg]);
    ```

    Сторона грошової ноги робить те саме для ескроу B з `userBAtaB`, `mintB`,
    `userBSigner`, `t.amountB` і `{ programAddress: tokenProgramB }`.

  </Tab>

    let fund_asset_leg = transfer_checked(

    `user_b` і `trade.amount_b`.

Переказ фінансування, побачений зі статусом [`confirmed`](/docs/rpc#configuring-state-commitment),
ще може бути скасований. Програма зчитує баланс ескроу ончейн під час
розрахунку, тому Settle, надісланий після переказу фінансування, який не потрапив у мережу, завершується
помилкою `LegNotFunded`, і нічого не переміщується; ціна цього — невдалий Settle і повторна спроба.
Вважайте ногу профінансованою, коли її переказ має статус `finalized`.

## Примітки

- **Ноги з wrapped SOL.** Програма зчитує баланс нативного ескроу після
  його синхронізації, тож lamports, надіслані в ескроу wrapped SOL системним переказом,
  враховуються. Ніколи не надсилайте SOL в ескроу для будь-якого іншого mint: програма не може
  його повернути, і він дістанеться тому, хто закриє акаунт.
- **Mint-и з обмеженим доступом.** Для mint зі станом акаунта за замовчуванням Default Account State frozen ескроу
  створюється замороженим, і переказ завершується помилкою, доки емітент не розморозить його або не допустить.
  [Огляд](/docs/defi/dvp-program#mint-configuration-constraints) описує
  взаємодію з Token ACL.
- **Хуки переказу.** Фінансуйте ескроу з хуками рівно на погоджену суму. Якщо
  надлишок змушує повернути кошти під час розрахунку, повернення повторно використовує акаунти хука
  ноги з іншим призначенням і сумою, що деякі хуки відхиляють.
  Відновлення: Reclaim, повторне фінансування на точну суму та новий розрахунок.
- **Фінансування після завершення строку.** Ніщо не зупиняє переказ після `expiry_timestamp`. Він
  потрапляє в мережу, розрахунок уже неможливий, і сторона ноги повертає кошти
  через Reclaim, поки угода відкрита, або через Recover після її закриття. Див.
  [згортання угоди](/docs/defi/dvp-program/unwind-a-trade).
- **Хто фінансує першим.** Програма не задає черговість двох ног. Порядок —
  справа сторін; кожна сторона може повернути власну ногу в будь-який момент
  до розрахунку, якщо тільки орган mint (заморожування, пауза або хук переказу)
  не блокує ескроу.
