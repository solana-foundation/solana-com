Чотири інструкції повертають кошти без розрахунку: Reclaim, Cancel і Reject
працюють, поки угода відкрита, а Recover повертає депозит, який надійшов після
її закриття. Жодна з них не перевіряє строк дії. Заморожений ескроу або змінений
mint усе ще може утримувати ногу, як описано в примітках наприкінці.

| Інструкція  | Підписант               | Охоплення                         | Угода після цього |
| ------------ | -------------------- | ----------------------------- | ---------------- |
| `ReclaimDvp` | `user_a` або `user_b` | Власна нога підписанта          | Залишається відкритою       |
| `CancelDvp`  | Розрахунковий орган | Обидві ноги                     | Закрита           |
| `RejectDvp`  | `user_a` або `user_b` | Обидві ноги                     | Закрита           |
| `RecoverDvp` | `user_a` або `user_b` | Нога підписанта, після закриття | Уже закрита   |

У кожному випадку з ескроу виводиться все, що в ньому є, на користь сторони
відповідної ноги: з ескроу A — на token account користувача `user_a` для `mint_a`,
з ескроу B — на token account користувача `user_b` для `mint_b`, незалежно від
того, хто його поповнив. program account програми memo передається для рахунків
повернення, які вимагають memo.

Ця сторінка продовжує попередні кроки: клієнт і підписанти з розділу
[створення угоди](/docs/defi/dvp-program/create-a-trade), `userAAtaA` і
`userBAtaB` з розділу [поповнення ніг](/docs/defi/dvp-program/fund-the-legs), а також
`MEMO_PROGRAM_ID` і `authority` з розділу
[розрахунку угоди](/docs/defi/dvp-program/settle-the-trade) переносяться далі.

## Повернення ноги

Reclaim повертає ногу підписанта й залишає угоду відкритою, тож ногу можна
поповнити знову. Використовуйте його, коли проблема на нозі контрагента; Cancel
і Reject закривають усю угоду.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getReclaimDvpInstruction } from "./dvp";

    // The asset-leg party takes its asset back.
    const reclaimInstruction = getReclaimDvpInstruction({
      signer: userASigner,
      swapDvp,
      mint: mintA,
      dvpSourceAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
    });

    await client.sendTransaction([reclaimInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::ReclaimDvpBuilder;

    // The asset-leg party takes its asset back.
    let reclaim_ix = ReclaimDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .mint(mint_a)
        .dvp_source_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .instruction();
    ```

  </Tab>
</Tabs>

## Cancel або Reject

Cancel підписує розрахунковий орган, а Reject — будь-яка зі сторін. Обидві
повертають усе, що містить кожен ескроу, стороні відповідної ноги та закривають
запис і обидва ескроу, а rent закритих акаунтів надходить підписанту. Обидві
інструкції приймають однакові акаунти; різниться лише підписант.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCancelDvpInstruction, getRejectDvpInstruction } from "./dvp";

    const unwindAccounts = {
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    };

    // Signed by the settlement authority:
    const cancelInstruction = getCancelDvpInstruction({
      settlementAuthority: authoritySigner,
      ...unwindAccounts,
    });

    // Or signed by either party:
    const rejectInstruction = getRejectDvpInstruction({
      signer: userBSigner,
      ...unwindAccounts,
    });
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::{CancelDvpBuilder, RejectDvpBuilder};

    // Signed by the settlement authority:
    let cancel_ix = CancelDvpBuilder::new()
        .settlement_authority(authority)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();

    // Or signed by either party:
    let reject_ix = RejectDvpBuilder::new()
        .signer(user_b)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();
    ```

  </Tab>
</Tabs>

Рахунки повернення (`userAAtaA`, `userBAtaB`) мають існувати для кожної ноги з
ненульовим балансом; неініціалізований рахунок повернення призводить до збою
переказу токенів і скасування інструкції. Нога, яку ніколи не поповнювали, не
потребує переказу і допускає відсутність рахунку.

## Повернення пізнього депозиту

Settle, Cancel і Reject закривають обидва token account ескроу, тому звичайний
переказ на закритий ескроу завершується помилкою. Депозит потрапляє туди після
закриття, лише якщо щось спершу перестворить ескроу, наприклад транзакція
поповнення, яка містить інструкцію create-idempotent для associated token account
перед переказом і була в обробці, коли контрагент надіслав Reject. Тоді токени
лежать в ескроу, угоди якого більше не існує: запису немає, тому Reclaim не може
його знайти, а nonce tombstone не дозволяє створити нову угоду за тією самою
адресою й перехопити депозит.

Щоб скористатися `RecoverDvp`, сторона ноги надає початкові вхідні дані seed
(розрахунковий орган, обидві сторони, обидва mint, nonce). Програма повторно
обчислює адресу запису, вимагає його tombstone як доказ існування угоди, виводить
вміст ескроу на власний token account підписанта та закриває його, повертаючи rent
ескроу підписанту. Нога підписанта визначається тим, хто підписує: `mint_a` для
`user_a`, `mint_b` для `user_b`.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getAddressEncoder, getProgramDerivedAddress } from "@solana/kit";
    import { DVP_SWAP_PROGRAM_PROGRAM_ADDRESS, getRecoverDvpInstruction } from "./dvp";

    const [nonceTombstone] = await getProgramDerivedAddress({
      programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
      seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
    });

    const recoverInstruction = getRecoverDvpInstruction({
      signer: userASigner,
      swapDvp,
      nonceTombstone,
      mint: mintA,
      dvpEscrowAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });

    await client.sendTransaction([recoverInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::RecoverDvpBuilder;

    let recover_ix = RecoverDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .nonce_tombstone(nonce_tombstone)
        .mint(mint_a)
        .dvp_escrow_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .settlement_authority(settlement_authority)
        .user_a(user_a)
        .user_b(user_b)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .nonce(nonce)
        .instruction();
    ```

  </Tab>
</Tabs>

Відновлення залежить від того, чи зберігає сторона параметри створення. Система,
що поповнює угоди, зберігає вхідні дані seed разом із кожним ордером, доки угоду
не закрито, а порожні баланси ескроу не підтверджено.

## Примітки

- **Заморожені ноги.** На mint із обмеженнями заморожений ескроу блокує переказ
  токенів, який виконують ці інструкції, доки freeze authority не розморозить його.
  Див. [огляд](/docs/defi/dvp-program#mint-configuration-constraints).
- **Зміни mint після створення.** Шляхи скасування пропускають перевірки розширень
  і mint authority, щоб власні перевірки програми не блокували відновлення.
  Власні правила програми токенів усе одно діють. Mint можна закрити лише за
  нульової пропозиції, тому він не може змінитися, поки в ескроу є баланс, але
  mint, закритий і перестворений як NonTransferable або з комісією за переказ до
  надходження пізнього депозиту, може зробити цей депозит неможливим для
  переміщення або таким, що обкладається комісією. Це залежність від mint
  authority, наведена в розділі [підтримувані токени](/docs/defi/dvp-program#supported-tokens).
