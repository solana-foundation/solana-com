エージェント型決済を使うと、ソフトウェアが価格の確認、支払いの承認、リソースの受け取りを
同一のHTTPワークフロー内で行えます。エージェントは、課金アカウントを事前に作成したり
APIキーをコピーしたりすることなく、データクエリ、モデル推論、ツール呼び出しの料金を支払えます。

## 共通の支払いフロー

MPPとx402ではヘッダーやデータモデルが異なりますが、基本的なHTTPフローは
似ています。

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPPとx402

どちらのプロトコルも、Solana上でステーブルコインによる支払いを決済できます。共通の`402`
ステータスコードだけでなく、サービスに必要な支払いモデルや相互運用性に基づいて選択してください。

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| チャレンジ               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| クライアント認可    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| レシート                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Solanaの支払いモデル   | 1回限りの`charge`と、上限付き従量制の`session`インテント           | `exact`や`upto`などのスキーム。サポート状況はネットワークとクライアントによって異なります |
| 決済アーキテクチャ | サーバーでの検証、またはオプションのリレーもしくはゲートウェイ                | ローカル検証を行うリソースサーバー、またはファシリテーター                 |
| 最初の導入に適したケース     | HTTP認証のセマンティクスや繰り返しの従量計測が必要なAPI | リクエスト単位で課金するリソースや既存のx402クライアント                      |

MPPは**Machine Payments Protocol**の略称です。**Model
Context Protocol(MCP)**と混同しないでください。MCPはエージェントにツールやリソースを公開するためのものであり、MPPやx402は、エージェントがそれらのツールを呼び出す際に支払いを要求できます。

<Callout type="info">
  サービスが複数のプロトコルを提示する場合があります。クライアントは対応している支払いオプションを選択し、やり取り全体を通じて、それに対応するチャレンジ、認可、レシートの各ヘッダーを使用します。
</Callout>
