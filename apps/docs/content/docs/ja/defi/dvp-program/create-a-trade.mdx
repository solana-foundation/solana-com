`CreateDvp` は取引の条件を記録し、当事者が資金を預け入れる2つのエスクローアカウントを作成します。トークンは一切移動しません。誰でも送信できるため、レコードは取引相手、決済権限者のオペレーター、または第三者から作成される可能性があります。他のすべての参加者は、保存された条件に基づいて行動する前にそれを検証します([各レッグへの入金](/docs/defi/dvp-program/fund-the-legs)を参照)。

スニペットでは、関係するアカウントと署名者が分かるよう、プレースホルダーのアドレスを使い、生成されたクライアントを直接使用します。対象はdevnetで、プログラムはmainnet-betaと同じアドレスにデプロイされています。

## インストール

2026年10月2日時点で、DvPクライアントのパッケージは公開されていません。どちらもリポジトリ内のプログラムのIDLから生成され、ソースから使用します。

これらのページは、コミット `df9919e` を基準に、TypeScriptでは `@solana/kit` 8、Rustでは `solana-*` 2.x クレートを使用して書かれています。

各ステップのページのスニペットは引き継がれます。各ページでは、前のページで定義したクライアント、署名者、アドレスを使用します。`payerSigner`、`userASigner`、`userBSigner`、`authoritySigner` は、それぞれ rent の支払者、2人の当事者、決済権限者の `TransactionSigner` で、たとえば `createKeyPairSignerFromBytes` で作成できます。Rustのスニペットは instructions を構築するだけで、署名と送信は呼び出し側に任せます。

## アドレスを導出する

取引レコードは、決済権限者、2人の当事者、2つのmint、nonceから導出される Program Derived Address です。各エスクローは、いずれかのmintに対するレコードの associated token account です。どちらの導出もネットワークアクセスは不要です。

取引ごとにランダムな64ビットのnonceを使用してください。作成は誰にでも許可されているため、nonceが予測可能だと、第三者が取引で使うはずだったアドレスを先に占有できてしまいます。nonceと金額はTypeScriptでは `bigint` として渡してください。生成されたクライアントは `number` を拒否します。

実行前に、各 `..._HERE` プレースホルダーを実際のアドレスに置き換えてください。`address()` はbase58を検証し、プレースホルダーだとエラーをスローします。`pubkey!` はコンパイルに失敗します。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## 条件を記録する

`CreateDvp` は、基本単位での2つの金額、有効期限、nonce、および4つの任意フィールド(最大64バイトの不透明な参照、各当事者の決済先、最早決済時刻)を受け取ります(注意事項を参照)。決済先は、決済時にその当事者の受取分が届く先で、たとえばカストディアンの入金用ウォレットです。デフォルトは当事者自身のアドレスで、レコードが作成された後は変更できません。返金と回収は、エスクローに誰が資金を入れたかにかかわらず、決済先ではなく、常にそのレッグのmintに対する当事者自身の token account に送られます。

支払者は、レコード、nonceトゥームストーン、2つのエスクローの rent を負担します。クローズ時には、その rent は支払者に戻らず、クローズ用の instruction に署名した人に渡ります。トゥームストーンは決してクローズされないため、取引ごとに少額の残高が恒久的に残ります。支払者の SOL を見積もる際は、rent の金額をハードコードせず、`getMinimumBalanceForRentExemption` RPCメソッドで導出してください。

  <Tab value="TypeScript">
    ```ts
    import { getCreateDvpInstruction } from "./dvp";

    const nowSeconds = BigInt(Math.floor(Date.now() / 1000));

    const createInstruction = getCreateDvpInstruction({
      payer: payerSigner,
      swapDvp,
      nonceTombstone: (
        await getProgramDerivedAddress({
          programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
          seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
        })
      )[0],
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      tokenProgramA,
      tokenProgramB,
      amountA: 1_000_000_000n, // 1,000 units of a 6-decimal asset
      amountB: 998_500_000n, // 998.50 units of a 6-decimal cash token
      expiryTimestamp: nowSeconds + 60n * 60n * 24n, // one day
      nonce,
      refString: "ORDER-2026-10-02-0001",
      userASettlementDestination: null, // defaults to userA
      userBSettlementDestination: null, // defaults to userB
      earliestSettlementTimestamp: null,

    console.log("Trade record:", swapDvp, "signature:", context.signature);
    ```

TypeScriptのスニペットでは、`@solana/kit` の `getProgramDerivedAddress` と `getAddressEncoder`、およびクライアントの `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` をスコープ内に用意しておく必要があります。Rustのビルダーでは、System Program と Associated Token Program はデフォルトのままです。

## 注意事項

- **有効期限。** 有効期限を確認するのはSettleだけです。Reclaim、Cancel、Rejectは期限後も実行できます。また、期限後に入金されたデポジットは、そのレッグの当事者が回収できます。有効期限は作成時から最長1年後まで設定できます。
- **時刻はネットワーク時刻です。** プログラムはオンチェーンのクロックを読み取ります。これは実時間と異なる場合があり、数十秒ずれることもあれば、前方に飛ぶこともあります。有効期限と想定する決済時刻の間に余裕を持たせ、どちらの境界付近でも入金や決済を避け、秒単位の締切を強制する目的で有効期限に依存しないでください。プログラムのREADMEでは、約1分のずれを見込むことを推奨しています。
- **最早決済時刻。** 任意です。設定した場合、その時刻より前のSettleは拒否されます。また、有効期限より後の時刻は設定できません。
- **作成時のチェック。** 当事者が System Program 所有のアカウントでない場合(SPL Tokenのマルチシグは対象外になります)は `PartyNotSignerCapable` で、そのほか `SettlementDestinationIsSwapDvp`、`SelfDvp`、`SameMint`、`ZeroAmount`、`SettlementAuthorityIsParty`、`ExpiryNotInFuture` の場合にも作成は失敗します。完全な一覧は[エラー表](/docs/defi/dvp-program#errors)にあります。
