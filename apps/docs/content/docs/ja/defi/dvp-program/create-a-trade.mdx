`CreateDvp` は取引の条件を記録し、当事者が資金を入れる2つのエスクローアカウントを作成します。トークンの移動は行いません。誰でも送信できるため、レコードは取引相手、決済権限者のオペレーター、または第三者から作成されることがあり、他のすべての参加者は、保存された条件に基づいて行動する前にそれを検証します([レッグへの入金](/docs/defi/dvp-program/fund-the-legs)を参照)。

スニペットでは、関係するアカウントと署名者が分かるよう、プレースホルダーのアドレスを使って生成されたクライアントを直接使用しています。対象は devnet で、プログラムは mainnet-beta と同じアドレスにデプロイされています。

## インストール

2026年10月2日時点で、DvP クライアント用のパッケージは公開されていません。どちらもリポジトリ内のプログラムの IDL から生成され、ソースから使用します。

これらのページは、コミット `df9919e` を基準に、TypeScript では `@solana/kit` 8、Rust では `solana-*` 2.x クレートを使用して書かれています。

各ステップページのスニペットは引き継がれます。各ページでは、前のページで定義したクライアント、署名者、アドレスを使用します。`payerSigner`、`userASigner`、`userBSigner`、`authoritySigner` は、それぞれ rent の支払者、2人の当事者、決済権限者のための `TransactionSigner` で、たとえば `createKeyPairSignerFromBytes` から取得します。Rust のスニペットは instructions を構築するだけで、署名と送信は呼び出し側に任せます。

## アドレスを導出する

取引レコードは、決済権限者、2人の当事者、2つのミント、nonce から導出される program-derived address です。各エスクローは、いずれかのミントに対するレコードの associated token account です。どちらの導出もネットワークアクセスは不要です。

取引ごとにランダムな64ビットの nonce を使用してください。作成は許可不要(permissionless)なため、nonce が予測可能だと、第三者が取引で使用されるはずだったアドレスを先に占有できてしまいます。TypeScript では nonce と金額を `bigint` で渡してください。生成されたクライアントは `number` を拒否します。

実行前に、各 `..._HERE` プレースホルダーを実際のアドレスに置き換えてください。`address()` は base58 を検証し、プレースホルダーに対しては例外をスローします。`pubkey!` はコンパイルに失敗します。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## 条件を記録する

`CreateDvp` は、基本単位の2つの金額、有効期限、nonce、および4つの任意フィールド(最大64バイトの不透明な参照、各側の決済先、最早決済時刻。「注意事項」を参照)を受け取ります。決済先は、決済時にその当事者の受取分が届く場所で、たとえばカストディアンの入金ウォレットです。デフォルトは当事者自身のアドレスで、レコードが作成された後は変更できません。返金と回収は、エスクローに誰が入金したかにかかわらず、決済先ではなく、常にそのレッグのミントに対する当事者自身の token account に送られます。

支払者は、レコード、nonce のトゥームストーン、および2つのエスクローの rent を負担します。クローズ時には、その rent は支払者ではなく、クローズ instruction に署名した人に渡ります。トゥームストーンはクローズされないため、取引ごとに少額の残高が永続的に残ります。支払者の SOL を見積もる際は、rent の金額をハードコードせず、`getMinimumBalanceForRentExemption` RPC メソッドで導出してください。

    const nowSeconds = BigInt(Math.floor(Date.now() / 1000));

    const createInstruction = getCreateDvpInstruction({
      payer: payerSigner,
      swapDvp,
      nonceTombstone: (
        await getProgramDerivedAddress({
          programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
          seeds: ["nonce", getAddressEncoder().encode(swapDvp)],

      )[0],
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,

      tokenProgramB,
      amountA: 1_000_000_000n, // 1,000 units of a 6-decimal asset
      amountB: 998_500_000n, // 998.50 units of a 6-decimal cash token

      nonce,
      refString: "ORDER-2026-10-02-0001",

TypeScript のスニペットでは、`@solana/kit` の `getProgramDerivedAddress` と `getAddressEncoder`、およびクライアントの `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` をスコープ内に用意しておく必要があります。Rust のビルダーでは、system program と associated token program はデフォルトのままになります。

## 注意事項

- **有効期限。** 有効期限を確認するのは Settle のみです。Reclaim、Cancel、Reject は期限後も実行でき、期限後に入金されたデポジットは、そのレッグの当事者が回収できます。有効期限は作成から最長1年後までです。
- **時刻はネットワーク時刻です。** プログラムはオンチェーンのクロックを読み取ります。これは実時間と異なることがあり、時には数十秒ずれたり、前方に飛んだりすることがあります。有効期限と意図する決済時刻の間には余裕を持たせ、どちらの境界付近でも入金や決済を避け、秒単位の締め切りを強制する目的で有効期限に頼らないでください。プログラムの README では、約1分のずれを見込むことを推奨しています。
- **最早決済時刻。** 任意です。設定すると、その時刻より前の Settle は拒否されます。有効期限より後にすることはできません。
- **作成時のチェック。** 当事者がシステム所有のアカウントでない場合(これにより SPL Token マルチシグは除外されます)、Create は `PartyNotSignerCapable` で失敗します。そのほか `SettlementDestinationIsSwapDvp`、`SelfDvp`、`SameMint`、`ZeroAmount`、`SettlementAuthorityIsParty`、`ExpiryNotInFuture` でも失敗します。完全な一覧は[エラー表](/docs/defi/dvp-program#errors)にあります。
