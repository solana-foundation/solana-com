決済を行わずに資金を返還する instructions は4つあります。取引がオープンの間に使う Reclaim、Cancel、Reject と、クローズ後に届いた入金分のための Recover です。いずれも有効期限はチェックしません。末尾の注記で説明するとおり、フリーズされたエスクローや変更されたミントが原因で、レッグが引き続き保持されることがあります。

| instructions  | 署名者               | 対象範囲                         | その後の取引 |
| ------------ | -------------------- | ----------------------------- | ---------------- |
| `ReclaimDvp` | `user_a` または `user_b` | 署名者自身のレッグ          | オープンのまま       |
| `CancelDvp`  | 決済権限者 | 両方のレッグ                     | クローズ           |
| `RejectDvp`  | `user_a` または `user_b` | 両方のレッグ                     | クローズ           |
| `RecoverDvp` | `user_a` または `user_b` | 署名者のレッグ(クローズ後) | クローズ済み   |

いずれの場合も、エスクローに保持されているものはすべて、そのレッグの当事者に返還されます。エスクロー A は `user_a` の `mint_a` 用 token account に、エスクロー B は `user_b` の `mint_b` 用 token account に、誰が入金したかにかかわらず返還されます。メモを必要とする返金先アカウントのために、memo program account が渡されます。

このページは前のステップの続きです。[取引を作成する](/docs/defi/dvp-program/create-a-trade)のクライアントと署名者、[レッグに入金する](/docs/defi/dvp-program/fund-the-legs)の `userAAtaA` と `userBAtaB`、[取引を決済する](/docs/defi/dvp-program/settle-the-trade)の `MEMO_PROGRAM_ID` と `authority` を引き続き使用します。

## レッグを取り戻す

Reclaim は署名者のレッグを返還し、取引はオープンのままにするため、そのレッグに再度入金できます。問題が相手方のレッグにある場合に使用します。Cancel と Reject は取引全体をクローズします。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getReclaimDvpInstruction } from "./dvp";

    // The asset-leg party takes its asset back.
    const reclaimInstruction = getReclaimDvpInstruction({
      signer: userASigner,
      swapDvp,
      mint: mintA,
      dvpSourceAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
    });

    await client.sendTransaction([reclaimInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::ReclaimDvpBuilder;

    // The asset-leg party takes its asset back.
    let reclaim_ix = ReclaimDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .mint(mint_a)
        .dvp_source_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .instruction();
    ```

  </Tab>
</Tabs>

## Cancel または Reject

Cancel は決済権限者が、Reject はどちらかの当事者が署名します。どちらも各エスクローに保持されているものをレッグの当事者に返還し、レコードと両方のエスクローをクローズします。クローズされたアカウントの rent は署名者に渡ります。この2つの instructions は同じアカウントを取り、署名者だけが異なります。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCancelDvpInstruction, getRejectDvpInstruction } from "./dvp";

    const unwindAccounts = {
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    };

    // Signed by the settlement authority:
    const cancelInstruction = getCancelDvpInstruction({
      settlementAuthority: authoritySigner,
      ...unwindAccounts,
    });

    // Or signed by either party:
    const rejectInstruction = getRejectDvpInstruction({
      signer: userBSigner,
      ...unwindAccounts,
    });
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::{CancelDvpBuilder, RejectDvpBuilder};

    // Signed by the settlement authority:
    let cancel_ix = CancelDvpBuilder::new()
        .settlement_authority(authority)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();

    // Or signed by either party:
    let reject_ix = RejectDvpBuilder::new()
        .signer(user_b)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();
    ```

  </Tab>
</Tabs>

残高を保持しているレッグについては、返金先アカウント(`userAAtaA`、`userBAtaB`)が存在している必要があります。未初期化の返金先アカウントがあるとトークン転送が失敗し、instructions は取り消されます。一度も入金されていないレッグは転送が不要なため、アカウントが存在しなくても問題ありません。

## 遅れて届いた入金を回収する

Settle、Cancel、Reject はいずれも両方のエスクロー token account をクローズするため、クローズ済みのエスクローへの通常の転送は失敗します。クローズ後に入金が反映されるのは、先に何かがエスクローを再作成した場合のみです。たとえば、転送の前に create-idempotent の associated token account instructions を含む入金トランザクションが、相手方が Reject を送信した時点で処理中だった場合などです。その場合、トークンは取引がすでに存在しないエスクローに残されます。レコードは消えているため Reclaim では見つけられず、nonce の tombstone により、同じアドレスに新しい取引を作成して入金を奪取することもできません。

`RecoverDvp` を使うには、レッグの当事者が元の seed 入力(決済権限者、両当事者、両ミント、nonce)を指定します。プログラムはレコードのアドレスを再導出し、取引が存在した証拠としてその tombstone を要求し、エスクローの中身を署名者自身の token account に移して、エスクローをクローズし、エスクローの rent を署名者に返します。署名者のレッグは、どちらの当事者が署名するかで決まります。`user_a` なら `mint_a`、`user_b` なら `mint_b` です。

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getAddressEncoder, getProgramDerivedAddress } from "@solana/kit";
    import { DVP_SWAP_PROGRAM_PROGRAM_ADDRESS, getRecoverDvpInstruction } from "./dvp";

    const [nonceTombstone] = await getProgramDerivedAddress({
      programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
      seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
    });

    const recoverInstruction = getRecoverDvpInstruction({
      signer: userASigner,
      swapDvp,
      nonceTombstone,
      mint: mintA,
      dvpEscrowAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });

    await client.sendTransaction([recoverInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::RecoverDvpBuilder;

    let recover_ix = RecoverDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .nonce_tombstone(nonce_tombstone)
        .mint(mint_a)
        .dvp_escrow_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .settlement_authority(settlement_authority)
        .user_a(user_a)
        .user_b(user_b)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .nonce(nonce)
        .instruction();
    ```

  </Tab>
</Tabs>

リカバリーは、当事者が作成パラメーターを保持していることが前提です。取引に入金を行うシステムは、取引がクローズされ、エスクロー残高が空であることを確認できるまで、各注文とともに seed 入力を保存しておきます。

## 注記

- **フリーズされたレッグ。** ゲート付きミントでは、フリーズされたエスクローは、freeze authority が解除するまで、これらの instructions が実行するトークン転送をブロックします。[概要](/docs/defi/dvp-program#mint-configuration-constraints)を参照してください。
- **作成後のミント変更。** 巻き戻しのパスでは、プログラム自身のチェックがリカバリーを妨げないよう、拡張機能とミント権限のチェックをスキップします。token program 自体のルールは引き続き適用されます。ミントは供給量がゼロのときにしかクローズできないため、エスクローに残高がある間は変更されませんが、遅れた入金が反映される前にミントがクローズされ、NonTransferable や転送手数料付きで再作成された場合、その入金は移動不能になったり、手数料が発生したりすることがあります。これが[サポートされるトークン](/docs/defi/dvp-program#supported-tokens)に記載されている mint-authority 依存です。
