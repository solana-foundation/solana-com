部分署名を使うと、複数の関係者が同じトランザクションに、異なるタイミングや異なるデバイスで署名できます。コーディネーターがメッセージを構築し、必要な各署名者がシリアライズ済みメッセージのバイト列そのものに署名します。コーディネーターは送信前に署名を検証して統合します。

<Callout type="warn" title="署名が承認するのはバイト列であり、意図ではありません">
  手数料支払者、ブロックハッシュ、instructionの順序、アカウントリスト、あるいは instruction data のいずれかを変更すると、別のメッセージになり、すでに収集済みのすべての署名が無効になります。
</Callout>

## 部分署名のフロー

1. トランザクションのinstructionsと、手数料を支払う主体について合意します。
2. トランザクションの有効期間と手数料支払者を設定します。
3. メッセージを一度だけシリアライズします。そのバイト列は変更不可として扱います。
4. メッセージのバイト列と、人が読める概要を各署名者に配布します。
5. 同一のメッセージバイト列に対する各Ed25519署名を収集し、検証します。
6. 署名を、対応する必須署名者のアドレスに紐付けます。
7. 必要な署名がすべて揃っていて有効であることを確認してから、送信します。

## 署名前にメッセージを固定する

すべての署名は、シリアライズされたトランザクションメッセージを対象としています。メッセージには次のすべてが含まれます。

- 手数料支払者
- 最新のブロックハッシュまたはdurable nonce
- すべてのプログラムとアカウントのアドレス
- アカウントの署名者権限と書き込み可能権限
- instructionの順序とinstruction data

まずこれらのフィールドを構築し、メッセージを一度だけシリアライズして、そのバイト配列をすべての署名者に配布します。各署名リクエストと併せてメッセージのダイジェストを保存しておくと便利です。これにより、コーディネーターは別のメッセージに対して返された署名を拒否できます。

メッセージをデシリアライズして変更し、それまでに収集した署名が有効なままであることを期待してはいけません。期限切れのブロックハッシュの差し替えや手数料支払者の変更など、運用上の変更に見えるものであっても、すべての署名者があらためて署名する必要があります。

## 手数料支払者を調整する

手数料支払者は常に必須の署名者であり、メッセージを固定する前に決めておく必要があります。そのアカウントに、基本手数料と優先手数料を支払うのに十分なSOLがあることを確認してください。スポンサーやバックエンドが手数料を支払う場合は、ユーザーの署名を収集する前に、そのアドレスをメッセージに含めてください。スポンサーを後から追加すると、署名対象のバイト列が変わってしまいます。

コーディネーターは、受信した署名が必須署名者として一覧にあるアドレスのものであることを検証する必要があります。任意の公開鍵を受け入れて、トランザクションに追加してはいけません。

## トランザクションの有効期間を管理する

最新のブロックハッシュを使用するトランザクションは、そのブロックハッシュがvalidatorの最近のブロックハッシュキューに残っている間のみ有効です。複数の関係者による署名フローを開始する前に、すべての署名者が `lastValidBlockHeight` までに応答できるかどうかを見積もってください。

ブロックハッシュが期限切れになった場合は、新しいブロックハッシュで新しいメッセージを構築し、すべての署名を再度収集します。より長い時間がかかる可能性があるワークフローや、オフライン署名者が含まれるワークフローでは、[durable nonce](/docs/core/transactions/durable-nonces)を使用してください。durable nonceは最近のブロックハッシュの有効期間の制約を回避できますが、そのnonceを進めたり、それ以外の方法で消費したりすると、保留中のトランザクションは無効になります。

## 送信前に検証する

返された署名ごとに、次の手順を実行します。

1. 固定されたメッセージバイト列と、想定される署名者の公開鍵に対して、署名を検証します。
2. トランザクションの署名配列内で、その署名者に対応する位置に署名を設定します。
3. 組み立てたトランザクションに、必須の署名者全員分の有効な署名が含まれていることを検証します。
4. メッセージを再構築せずに、シリアライズしたトランザクションを送信します。

送信後は、署名済みメッセージに含まれていたものと同じ有効期間情報を使用して確認します。確認の結果、ブロックハッシュの期限切れやnonceの消費済みが報告された場合は、変更したトランザクションで再試行せず、署名フローを最初からやり直してください。
