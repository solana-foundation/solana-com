部分署名を使うと、複数の関係者が異なるタイミングや異なるデバイスで同じトランザクションに署名できます。コーディネーターがメッセージを構築し、必要な各署名者がシリアライズされたメッセージのバイト列そのものに署名します。コーディネーターは送信前に署名を検証して統合します。

<Callout type="warn" title="署名が承認するのはバイト列であり、意図ではありません">
  手数料支払者、ブロックハッシュ、instruction の順序、アカウントリスト、または instruction data を変更すると、別のメッセージになり、それまでに収集したすべての署名が無効になります。
</Callout>

## 部分署名のフロー

1. トランザクションの instructions と、手数料を支払う人を合意します。
2. トランザクションの有効期間と手数料支払者を設定します。
3. メッセージを1回だけシリアライズします。そのバイト列は変更不可として扱います。
4. メッセージのバイト列と、人間が読める概要を各署名者に配布します。
5. 同じメッセージのバイト列に対する各 Ed25519 署名を収集し、検証します。
6. 署名を、対応する必須署名者のアドレスに紐付けます。
7. 必要な署名がすべて揃っていて有効であることを確認してから、送信します。

## 署名前にメッセージを固定する

すべての署名は、シリアライズされたトランザクションメッセージを対象としています。メッセージには次のすべてが含まれます。

- 手数料支払者
- 最新のブロックハッシュまたは durable nonce
- すべてのプログラムとアカウントのアドレス
- アカウントの署名者権限と書き込み可能権限
- instruction の順序と instruction data

まずこれらのフィールドを構築し、メッセージを1回だけシリアライズして、そのバイト配列をすべての署名者に配布します。各署名リクエストと併せてメッセージのダイジェストを保存しておくと、コーディネーターが別のメッセージに対して返された署名を拒否できるため便利です。

メッセージをデシリアライズして変更し、以前に収集した署名が有効なままであると期待してはいけません。期限切れのブロックハッシュの置き換えや手数料支払者の変更など、運用上の変更に見えるものであっても、すべての署名者が再度署名する必要があります。

## 手数料支払者を調整する

手数料支払者は常に必須の署名者であり、メッセージを固定する前に決めておく必要があります。そのアカウントに、基本手数料と優先手数料を支払うのに十分な SOL があることを確認してください。スポンサーやバックエンドが手数料を支払う場合は、ユーザーの署名を収集する前にそのアドレスをメッセージに含めてください。スポンサーを後から追加すると、署名対象のバイト列が変わってしまいます。

コーディネーターは、受け取った署名が必須署名者として一覧にあるアドレスのものであることを検証する必要があります。任意の公開鍵を受け入れてトランザクションに追加してはいけません。

## トランザクションの有効期間を管理する

最新のブロックハッシュを使うトランザクションは、そのブロックハッシュが validator の最新ブロックハッシュキューに残っている間のみ有効です。複数の関係者による署名フローを始める前に、すべての署名者が `lastValidBlockHeight` までに応答できるかどうかを見積もってください。

ブロックハッシュが期限切れになった場合は、新しいブロックハッシュで新しいメッセージを構築し、すべての署名を再度収集します。より長い時間がかかる可能性のあるワークフローや、オフライン署名者を含むワークフローでは、[durable nonce](/docs/core/transactions/durable-nonces) を使用してください。durable nonce は最新ブロックハッシュの有効期間の制約を回避できますが、その nonce を進めたり、その他の方法で消費したりすると、保留中のトランザクションは無効になります。

## 送信前に検証する

返されたすべての署名について、次の手順を行います。

1. 固定されたメッセージのバイト列と、想定される署名者の公開鍵に対して署名を検証します。
2. トランザクションの署名配列にある、その署名者の位置に署名を紐付けます。
3. 組み立てたトランザクションに、すべての必須署名者の有効な署名が含まれていることを確認します。
4. メッセージを再構築せずに、シリアライズしたトランザクションを送信します。

送信後は、署名済みメッセージに含まれていたものと同じ有効期間の情報を使って確認します。確認の結果、ブロックハッシュの期限切れや nonce の消費が報告された場合は、変更したトランザクションで再試行せず、署名フローを最初からやり直してください。
