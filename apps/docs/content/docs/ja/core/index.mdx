Solana開発の基盤を形成する7つのコンセプトがあります。まずアカウントとプログラムから始め、次にinstructionsがトランザクションになる流れを理解しましょう。PDA、CPI、手数料はその実行モデルの上に構築されています。

<DocsDiagram
  src="/assets/docs/diagrams/core-concepts.svg"
  alt="Solana core concepts, ordered from accounts and programs through instructions and transactions, with PDAs, CPIs, and fees"
/>

<Cards>
  <Card title="アカウント" href="/docs/core/accounts">
    Solanaはすべての状態をアカウントに保存します。アカウントとは32バイトのアドレスをキーとするキーバリューストアです。各アカウントには、lamports、data、owner、executable、rent_epochの5つのフィールドがあります。
  </Card>
  <Card title="プログラム" href="/docs/core/programs">
    SolanaのスマートコントラクトはsBPFにコンパイルされます。プログラムはステートレスであり、すべての可変状態はinstructionsを介して渡される別個のデータアカウントに保存されます。
  </Card>
  <Card title="Instructions" href="/docs/core/instructions">
    1つのプログラムを実行するリクエストで、プログラムID、アカウントリスト、およびopaqueなデータバイトを含みます。複数のinstructionsを組み合わせて1つのトランザクションを構成できます。
  </Card>
  <Card title="トランザクション" href="/docs/core/transactions">
    Solanaにおける実行のアトミック単位です。署名とメッセージ（アカウントアドレス、最新のブロックハッシュ、コンパイル済みinstructions）を含みます。最大1232バイト、またはv1フォーマットでは4096バイトです。
  </Card>
  <Card title="手数料" href="/docs/core/fees">
    署名ごとに5,000 lamportsの基本手数料に加え、要求されたコンピュートユニットに基づくオプションの優先手数料が発生します。トランザクションあたりの最大コンピュートユニットは140万です。
  </Card>
  <Card title="Program Derived Addresses（PDA）" href="/docs/core/pda">
    プログラムIDとシードから導出される決定論的なアドレスです。オーナープログラムのみがinvoke_signedを通じてPDAの代わりに署名できます。
  </Card>
  <Card title="Cross-Program Invocations（CPI）" href="/docs/core/cpi">
    あるプログラムがinvokeまたはinvoke_signedを介して別のプログラムを呼び出す仕組みです。署名者および書き込み可能な権限は呼び出し先に引き継がれます。instructionスタックの最大深度は5です（トップレベルとCPIを含む）。
  </Card>
</Cards>
