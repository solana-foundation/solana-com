Anchorイベントは、プログラムのIDLに含まれる、型付けされたBorshシリアライズ形式のレコードです。クライアントは、人間が読めるログメッセージを解析しなくても、プログラムのアクティビティを解釈できます。

イベントはインデックス作成や通知に便利ですが、プログラムの状態ではありません。プログラムが後で再度読み取る必要がある値はアカウントに保存し、イベントは成功したトランザクションから派生した記録として扱ってください。

## イベントの定義と発行

構造体に `#[event]` を付与し、状態の変更が成功した後に `emit!` を呼び出します。

```rust title="lib.rs"
use anchor_lang::prelude::*;

#[program]
pub mod payments {
    use super::*;

    pub fn record_payment(ctx: Context<RecordPayment>, amount: u64) -> Result<()> {
        emit!(PaymentRecorded {
            authority: ctx.accounts.authority.key(),
            amount,
        });
        Ok(())
    }
}

#[derive(Accounts)]
pub struct RecordPayment<'info> {
    pub authority: Signer<'info>,
}

#[event]
pub struct PaymentRecorded {
    pub authority: Pubkey,
    pub amount: u64,
}
```

`emit!` は、Solanaの `sol_log_data` システムコールでイベントのバイト列を書き込みます。トランザクションログには、結果が `Program data: <base64>` として表示されます。エンコードされた値は、イベントのディスクリミネータで始まり、その後にBorshシリアライズされたフィールドが続きます。

イベントは必要最小限にとどめてください。大きな文字列やベクターは、コンピュートを消費し、トランザクションメタデータを増大させ、ログの切り捨ての影響も受けやすくなります。

## ログイベントとCPIイベントの選択

Anchorは2つの発行方法をサポートしています。

| 方法        | 保存場所                  | トレードオフ                                               |
| ----------- | --------------------------------- | ------------------------------------------------------ |
| `emit!`     | プログラムデータログ                 | よりシンプルで低コストですが、ログが切り捨てられる可能性があります         |
| `emit_cpi!` | CPIの内部 instruction data | メタデータの耐久性は高い一方、追加のアカウントとコンピュートが必要です |

CPIイベントを使用するには、Anchorの `event-cpi` 機能を有効にします。

```toml title="Cargo.toml"
[dependencies]
anchor-lang = { version = "1.1.2", features = ["event-cpi"] }
```

次に、インストラクションのアカウント構造体に `#[event_cpi]` を付与し、コンテキスト変数が `ctx` という名前のハンドラーからイベントを発行します。

```rust title="lib.rs"
pub fn record_payment(ctx: Context<RecordPayment>, amount: u64) -> Result<()> {
    emit_cpi!(PaymentRecorded {
        authority: ctx.accounts.authority.key(),
        amount,
    });
    Ok(())
}

#[event_cpi]
#[derive(Accounts)]
pub struct RecordPayment<'info> {
    pub authority: Signer<'info>,
}
```

`#[event_cpi]` は、署名付きの自己CPIに必要なevent authorityアカウントと現在の program account を追加します。CPIイベントはAnchorのログイベントサブスクリプションでは取得できません。代わりに、トランザクションを取得し、対応する内部インストラクションをデコードしてください。

<Callout type="info" title="台帳を信頼できる情報源にする">
  RPCプロバイダーはプログラムログを切り捨てることがあります。イベントを見逃すと残高、権限、その他の正確性が重要なワークフローに影響する場合は、program account またはトランザクションの instruction data から結果を導出してください。イベントはインデックス作成を効率化するために使い、状態の唯一の記録としては使わないでください。
</Callout>

## TypeScriptからのサブスクライブ

現在のAnchor TypeScriptクライアントは `@anchor-lang/core` です。プログラムのIDLから作成した `Program` インスタンスは、一致するログイベントをデコードし、RPCのログサブスクリプション経由で配信できます。

```ts
const listenerId = program.addEventListener(
  "PaymentRecorded",
  (event, slot, signature) => {
    console.log({ event, slot, signature });
  },
  "confirmed"
);

// Remove the websocket subscription when it is no longer needed.
await program.removeEventListener(listenerId);
```

コールバックは、デコードされたイベントデータ、slot、トランザクションシグネチャを受け取ります。サブスクリプションが対象とするのは、接続がアクティブな間に配信されたログのみです。コンシューマーが完全な履歴を必要とする場合は、処理済みのシグネチャを永続化し、切断後に見逃したトランザクションをバックフィルしてください。

## 取得したトランザクションログのデコード

バックフィルや単発の調査では、トランザクションを取得し、各 `Program data:` ペイロードをイベントコーダーに渡します。

```ts
const transaction = await connection.getTransaction(signature, {
  commitment: "confirmed",
  maxSupportedTransactionVersion: 0
});

if (!transaction?.meta || transaction.meta.err) {
  throw new Error("Transaction was not found or did not succeed");
}

for (const log of transaction.meta.logMessages ?? []) {
  const prefix = "Program data: ";
  if (!log.startsWith(prefix)) continue;

  const decoded = program.coder.events.decode(log.slice(prefix.length));
  if (decoded) console.log(decoded.name, decoded.data);
}
```

1つのトランザクションが複数のプログラムを呼び出すことがあります。本番用のパーサーでは、`Program <address> invoke` と `success` のログ境界を追跡するか、Anchorのイベントパーサーを使用して、別のプログラムの `Program data:` エントリを自分のものとしてデコードしないようにしてください。失敗したトランザクションにも、エラーが発生する前に完了した処理のログと内部 instructions が残ることがあるため、どちらの形式のイベントもインデックス化する前に、`err` がnullでないトランザクションメタデータは必ず除外してください。Anchorのログサブスクリプションは、イベントコールバックを配信する前にこの確認を行います。

`emit_cpi!` イベントの場合は、`meta.innerInstructions` から自己CPIを探し、そのプログラムIDが自分のプログラムであることを確認したうえで、その instruction data をbase58デコードします。バイトを取り除く前に、Anchorの [`EVENT_IX_TAG_LE`](https://github.com/solana-foundation/anchor/blob/v1.1.2/lang/src/event.rs#L1-L3) を検証してください。

```ts
import bs58 from "bs58";

const EVENT_IX_TAG_LE = Buffer.from("e445a52e51cb9a1d", "hex");
const instructionData = Buffer.from(bs58.decode(innerInstruction.data));

if (!instructionData.subarray(0, 8).equals(EVENT_IX_TAG_LE)) {
  // This is an ordinary self-CPI, not an emit_cpi! event.
  continue;
}

const eventData = instructionData.subarray(8).toString("base64");
const decoded = program.coder.events.decode(eventData);
```

プログラムIDとタグの両方を確認することで、通常の自己CPIがイベントと誤認されるのを防げます。

## イベントスキーマのバージョン管理

デフォルトでは、Anchorはイベント名から8バイトのイベントディスクリミネータを導出します。`#[event(discriminator = ...)]` で明示的にディスクリミネータを指定することもできます。ディスクリミネータはプログラム内で一意であり、イベントをデコードするすべてのクライアントに対して不変である必要があります。

発行する構造体のフィールドを変更すると、Borshのレイアウトが変わります。互換性のないスキーマ変更を行う場合は、`PaymentRecorded` を黙って変更するのではなく、`PaymentRecordedV2` のような新しいイベントを定義してください。既存のインデクサーがまだ古いイベントに依存している間は、移行期間中も古いイベントの発行を続けてください。

進化させる可能性のあるデータには、固定幅のフィールドと、インデクサーがより詳細なアカウントデータを別途取得できる識別子を使うことをお勧めします。コンシューマーが新しいイベントをすぐにデコードできるよう、プログラムのアップグレードより前、またはアップグレードと同時に、更新したIDLを公開してください。

## イベントのテスト

base64文字列ではなく、デコード後のコントラクトをテストしてください。インストラクションを送信する前にリスナーを登録し、デコードされたフィールドとトランザクションシグネチャをアサートし、最後に必ずリスナーを削除します。

```ts
let listenerId = 0;
const received = new Promise<{
  event: { authority: PublicKey; amount: BN };
  signature: string;
}>((resolve) => {
  listenerId = program.addEventListener(
    "PaymentRecorded",
    (event, _slot, signature) => resolve({ event, signature }),
    "confirmed"
  );
});

try {
  const signature = await program.methods.recordPayment(new BN(500)).rpc();
  const result = await received;

  assert.equal(result.signature, signature);
  assert.equal(result.event.amount.toString(), "500");
} finally {
  await program.removeEventListener(listenerId);
}
```

また、インデクサーが失敗したトランザクションのメタデータに残るイベントバイトを無視することもテストし、サポートする各イベントバージョンのフィクスチャを追加してください。`emit_cpi!` を使用する場合は、ログリスナーはそれらのイベントを直接受信しないため、`innerInstructions` からのデコードをテストしてください。
