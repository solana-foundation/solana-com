Anchor イベントは、プログラムの IDL に含まれる、型付けされ Borsh でシリアライズされたレコードです。クライアントは、人間が読めるログメッセージを解析しなくても、プログラムのアクティビティを解釈できます。

イベントはインデックス作成や通知に便利ですが、プログラムの状態ではありません。プログラムが再度読み取る必要のある値はアカウントに保存し、イベントは成功したトランザクションから派生した記録として扱ってください。

## イベントを定義して発行する

構造体に `#[event]` を追加し、状態の変更が成功した後に `emit!` を呼び出します。

```rust title="lib.rs"
use anchor_lang::prelude::*;

#[program]
pub mod payments {
    use super::*;

    pub fn record_payment(ctx: Context<RecordPayment>, amount: u64) -> Result<()> {
        emit!(PaymentRecorded {
            authority: ctx.accounts.authority.key(),
            amount,
        });
        Ok(())
    }
}

#[derive(Accounts)]
pub struct RecordPayment<'info> {
    pub authority: Signer<'info>,
}

#[event]
pub struct PaymentRecorded {
    pub authority: Pubkey,
    pub amount: u64,
}
```

`emit!` は Solana の `sol_log_data` システムコールでイベントのバイト列を書き込みます。トランザクションログには結果が `Program data: <base64>` として表示されます。エンコードされた値は、イベントのディスクリミネータで始まり、その後に Borsh でシリアライズされたフィールドが続きます。

イベントは小さくまとめてください。大きな文字列やベクターはコンピュートを消費し、トランザクションのメタデータを増やし、ログの切り詰めの影響を受けやすくなります。

## ログイベントと CPI イベントの選択

Anchor は 2 つの発行経路をサポートしています。

| 経路        | 保存場所                  | トレードオフ                                               |
| ----------- | --------------------------------- | ------------------------------------------------------ |
| `emit!`     | プログラムデータログ                 | よりシンプルで低コストですが、ログが切り詰められる可能性があります         |
| `emit_cpi!` | CPI の inner instruction data | メタデータの耐久性は高くなりますが、追加のアカウントとコンピュートが必要です |

CPI イベントを使用するには、Anchor の `event-cpi` 機能を有効にします。

```toml title="Cargo.toml"
[dependencies]
anchor-lang = { version = "1.1.2", features = ["event-cpi"] }
```

次に、instruction のアカウント構造体に `#[event_cpi]` を付与し、コンテキスト変数の名前が `ctx` であるハンドラーから発行します。

```rust title="lib.rs"
pub fn record_payment(ctx: Context<RecordPayment>, amount: u64) -> Result<()> {
    emit_cpi!(PaymentRecorded {
        authority: ctx.accounts.authority.key(),
        amount,
    });
    Ok(())
}

#[event_cpi]
#[derive(Accounts)]
pub struct RecordPayment<'info> {
    pub authority: Signer<'info>,
}
```

`#[event_cpi]` は、署名付きの自己 CPI に必要なイベント認可アカウント(event authority)と現在のプログラムアカウントを追加します。CPI イベントは Anchor のログイベントサブスクリプションでは取得できません。代わりにトランザクションを取得し、一致する inner instruction をデコードしてください。

<Callout type="info" title="台帳を信頼できる情報源にする">
  RPC プロバイダーはプログラムログを切り詰める場合があります。イベントを取りこぼすと残高、権限、その他の正確性が重要なワークフローに影響する場合は、プログラムアカウントまたはトランザクションの instruction data から結果を導出してください。イベントはインデックス作成を効率化するために使用し、状態の唯一の記録にはしないでください。
</Callout>

## TypeScript からサブスクライブする

現在の Anchor TypeScript クライアントは `@anchor-lang/core` です。プログラムの IDL から作成した `Program` インスタンスは、一致するログイベントをデコードし、RPC のログサブスクリプション経由で配信できます。

```ts
const listenerId = program.addEventListener(
  "PaymentRecorded",
  (event, slot, signature) => {
    console.log({ event, slot, signature });
  },
  "confirmed"
);

// Remove the websocket subscription when it is no longer needed.
await program.removeEventListener(listenerId);
```

コールバックは、デコードされたイベントデータ、slot、トランザクション署名を受け取ります。サブスクリプションがカバーするのは、接続がアクティブな間に配信されたログのみです。コンシューマーが完全な履歴を必要とする場合は、処理済みの署名を保存し、切断後に取りこぼしたトランザクションをバックフィルしてください。

## 取得したトランザクションログのデコード

バックフィルや単発の確認では、トランザクションを取得し、各 `Program data:` ペイロードをイベントコーダーに渡します。

```ts
const transaction = await connection.getTransaction(signature, {
  commitment: "confirmed",
  maxSupportedTransactionVersion: 0
});

if (!transaction?.meta || transaction.meta.err) {
  throw new Error("Transaction was not found or did not succeed");
}

for (const log of transaction.meta.logMessages ?? []) {
  const prefix = "Program data: ";
  if (!log.startsWith(prefix)) continue;

  const decoded = program.coder.events.decode(log.slice(prefix.length));
  if (decoded) console.log(decoded.name, decoded.data);
}
```

1 つのトランザクションが複数のプログラムを呼び出すことがあります。本番用のパーサーでは、`Program <address> invoke` と `success` のログ境界を追跡するか、Anchor のイベントパーサーを使用して、他のプログラムの `Program data:` エントリが自分のものとしてデコードされないようにしてください。失敗したトランザクションにも、エラー前に完了した処理のログや inner instructions が残ることがあるため、どちらの形式のイベントもインデックス化する前に、`err` が null でないトランザクションメタデータは必ず除外してください。Anchor のログサブスクリプションは、イベントコールバックを配信する前にこのチェックを行います。

`emit_cpi!` イベントの場合は、`meta.innerInstructions` から自己 CPI を見つけ、そのプログラム ID が自分のプログラムであることを確認し、その instruction data を base58 デコードします。バイトを取り除く前に、Anchor の [`EVENT_IX_TAG_LE`](https://github.com/solana-foundation/anchor/blob/v1.1.2/lang/src/event.rs#L1-L3) を検証してください。

```ts
import bs58 from "bs58";

const EVENT_IX_TAG_LE = Buffer.from("e445a52e51cb9a1d", "hex");
const instructionData = Buffer.from(bs58.decode(innerInstruction.data));

if (!instructionData.subarray(0, 8).equals(EVENT_IX_TAG_LE)) {
  // This is an ordinary self-CPI, not an emit_cpi! event.
  continue;
}

const eventData = instructionData.subarray(8).toString("base64");
const decoded = program.coder.events.decode(eventData);
```

プログラム ID とタグの両方を確認することで、通常の自己 CPI がイベントと誤認されるのを防げます。

## イベントスキーマのバージョン管理

デフォルトでは、Anchor はイベント名から 8 バイトのイベントディスクリミネータを導出します。`#[event(discriminator = ...)]` により、明示的なディスクリミネータを指定することもできます。ディスクリミネータはプログラム内で一意であり、イベントをデコードするすべてのクライアントに対して不変である必要があります。

発行する構造体のフィールドを変更すると、Borsh のレイアウトが変わります。破壊的なスキーマ変更を行う場合は、`PaymentRecorded` を暗黙的に変更せず、`PaymentRecordedV2` のような新しいイベントを定義してください。既存のインデクサーがまだ依存している間は、移行期間中も古いイベントを発行し続けてください。

進化させるデータには、固定幅のフィールドと、インデクサーがより詳細なアカウントデータを別途取得できる識別子を使用することをお勧めします。コンシューマーが新しいイベントをすぐにデコードできるよう、更新した IDL はプログラムのアップグレード前、またはアップグレードと同時に公開してください。

## イベントのテスト

base64 文字列ではなく、デコード後のコントラクトをテストします。instruction を送信する前にリスナーを登録し、デコードされたフィールドとトランザクション署名をアサートし、最後に必ずリスナーを削除してください。

```ts
let listenerId = 0;
const received = new Promise<{
  event: { authority: PublicKey; amount: BN };
  signature: string;
}>((resolve) => {
  listenerId = program.addEventListener(
    "PaymentRecorded",
    (event, _slot, signature) => resolve({ event, signature }),
    "confirmed"
  );
});

try {
  const signature = await program.methods.recordPayment(new BN(500)).rpc();
  const result = await received;

  assert.equal(result.signature, signature);
  assert.equal(result.event.amount.toString(), "500");
} finally {
  await program.removeEventListener(listenerId);
}
```

あわせて、インデクサーが失敗したトランザクションのメタデータに残るイベントのバイト列を無視することをテストし、サポートする各イベントバージョンのフィクスチャを追加してください。`emit_cpi!` を使用する場合は、ログリスナーはそれらのイベントを直接受信しないため、`innerInstructions` からのデコードをテストしてください。
