2.0.0 は Go モジュールの最初の安定版リリースであるため、移行作業は不要です。Rust と TypeScript における同じ機能分割については、[2.0 移行ガイド](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)で説明しています。

## インストール

各バックエンドは独立した Go モジュールであるため、ビルドとモジュールグラフには、インポートしたバックエンドだけが含まれます:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

モジュールには `go/<module>/v2.0.0` の形式でタグが付けられます(例: `go/signers/memory/v2.0.0`)。すべてのモジュールは Go 1.25.0 を必要としますが、`gcpkms` のみ、`google.golang.org/api` が定める下限のため Go 1.25.8 が必要です。Ledger は Rust 専用で、Go モジュールはありません。

### solana-go v2 と v1 トランザクション

これらのモジュールは [`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go) v2.0.0 上に構築されており、その `*solana.Transaction` を受け取ります。レガシー、v0、v1(`solana.MessageVersionV1`)のトランザクションがサポートされています。ただし、`UseProgramCall: true` を指定した Fireblocks はレガシーと v0 のみを受け付けます。

## 基本的な使い方

すべてのシグナーは、基本となる [`core.SolanaSigner` インターフェース](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)(`Pubkey`、`SignMessage`、`IsAvailable`)を実装します。メソッドは `context.Context` を受け取り、処理をブロックします。各バックエンドは、さらにケイパビリティインターフェースをちょうど 1 つ実装します:

- `core.TransactionSigner`: `SignTransaction` は、渡されたトランザクションをそのまま署名します。
- `core.ModifyingSigner`: `ModifyAndSignTransaction` は、プロバイダーにトランザクションを書き換えさせたうえで署名します。
- `core.SendingSigner`: `SignAndSendTransaction` は、プロバイダーが署名とブロードキャストを行います。

各バックエンドパッケージは、`Config` 構造体と `New` コンストラクタを公開しています:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` と `ModifyAndSignTransaction` は `core.SignedTransaction`(`EncodedTransaction`、`Signature`、`Completeness`)を返します。リモート HTTP バックエンドは、オプションの `HTTPClient` と `HTTPClientConfig`(タイムアウト)を受け付けます。デフォルトのクライアントは HTTPS を強制します。独自のクライアントを指定するとこの制限は回避されるため、そのセキュリティ対策はご自身の責任となります。

### シグナーのケイパビリティ

トランザクションに署名できないバックエンドには `SignTransaction` メソッド自体が存在しません。そのため、ケイパビリティは具象型ではコンパイル時に確定し、`core.SolanaSigner` では型アサーションによって判別されます:

| バックエンド                                                                         | ケイパビリティ          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | はい                            |
| cdp                                                                             | `TransactionSigner` | UTF-8 ペイロードのみ            |
| utila                                                                           | `TransactionSigner` | `CodeSigningFailed` で失敗します |
| fordefi ブラックボックス(`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | はい                            |
| fordefi ネイティブ手動(`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | はい                            |
| fordefi ネイティブ自動(`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | はい                            |
| crossmint                                                                       | `SendingSigner`     | `CodeSigningFailed` で失敗します |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### 初期化

個別の `Init` ステップはありません。Privy、Fireblocks、Dfns、Crossmint、Para、Openfort、Utila はウォレットアドレスを `New` の内部で解決するため、それらのコンストラクタは `context.Context` を受け取ります。シグナーは必ず `New` を通じて作成してください。ゼロ値の Crossmint、Para、Utila のシグナーは、ゼロアドレスで署名するのではなく、`CodeNotInitialized` で失敗します。

### 任意のシグナーで署名と送信を行う

`core.SignAndSendTransaction` は、シグナーの種類にかかわらず、トランザクションをオンチェーンに送信します。`SendingSigner` はプロバイダー経由でブロードキャストし、send 関数は無視されます。それ以外の種類では署名のみが行われ、base64 形式の結果をご自身の関数でブロードキャストします。`ModifyingSigner` の場合、この結果はプロバイダーが書き換えたトランザクションです。Core は RPC に依存しません:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### バッチ署名

バッチ署名は、独立したヘルパー関数として提供されており、並行して実行されます。レート制限のある API 向けに、リクエストごとの間隔(stagger)を任意で指定できます:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` は `core.TransactionSigner` を受け取るため、ブロードキャスト管理型のシグナー(Crossmint、Fordefi ネイティブ自動)と Fordefi ネイティブ手動は、この関数ではバッチ処理できません。これらは 1 トランザクションずつ呼び出してください。呼び出しによってプロバイダー側で処理が発生するシグナー(`UseProgramCall` を指定した Fireblocks)は、`core.BatchServerSideEffects` を通じてそれを報告し、その場合バッチは順次実行されます。

## バックエンドの設定

### Memory

`PrivateKey`(生のバイト列)、`PrivateKeyString`(base58 または `[1,2,...]` 形式のバイト配列)、`PrivateKeyPath`(Solana CLI の keypair ファイル)のいずれか 1 つだけを指定してください:

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Go には、メモリをゼロクリアする信頼できる方法がありません。ガベージコレクターが鍵のバイト列をコピーして、回収されるまで保持する場合があります(memory の keypair や、Crossmint と Openfort がローカルで導出する鍵が該当します)。ローカル鍵バックエンドを使用する場合は、プロセスのメモリ全体を機密情報として扱ってください。

import "github.com/solana-foundation/solana-keychain/go/signers/vault/v2"

### Crossmint

Crossmint は送信専用です。承認されたすべてのトランザクションが API によってサーバー側で実行されるため、`*crossmint.Signer` には `SignAndSendTransaction` があり、`SignTransaction` はありません。トランザクションが変更されることはありません。返される署名は Crossmint がオンチェーンに反映したトランザクションを示しており、Crossmint がガス代をスポンサーする場合は、お客様のトランザクションと異なることがあります。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Utila

Utila はトランザクションの署名のみを行います。`SignMessage` は失敗するため、署名済みトランザクションはご自身でブロードキャストしてください。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/utila/v2"

signer, err := utila.New(ctx, utila.Config{
	ServiceAccountEmail:         "sa@example.com",
	ServiceAccountPrivateKeyPEM: "-----BEGIN PRIVATE KEY-----\n...",
	VaultID:                     "vault_id",
	WalletID:                    "wallet_id",
	Network:                     "networks/solana-devnet",
})
```

### Fordefi

Fordefi には 3 種類のシグナータイプがあり、`Config.Chain` と `Config.PushMode` によって構築時に決まります。3 つとも、メッセージへの署名に対応しています:

| Config                                          | 型                          | エントリーポイント                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` 未設定                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` 設定済み、`PushMode` 未設定または `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` 設定済み、`PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` は設定に応じて振り分けを行い、`core.SolanaSigner` を返します。`fordefi.NewBlackBox`、`fordefi.NewNativeAuto`、`fordefi.NewNativeManual` は具象型を返し、他のモードの設定は拒否します。API リクエストは ECDSA P-256 のリクエスト署名で認証されます。`PrivateKeyPEM` か、鍵を KMS/HSM 内に保持するための `RequestSigner` のいずれか 1 つだけを指定してください。

**ネイティブ自動モード**: Fordefi がブロックハッシュと手数料を置き換えたうえで、署名してブロードキャストする場合があります。受け付けるのは、必要な署名者がボールトのみである未署名のトランザクションに限られます。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**ネイティブ手動モード**: `PushMode: fordefi.PushModeManual` を設定します。Fordefi はメッセージ(最新のブロックハッシュ、Compute Budget の手数料 instructions)を書き換えて署名し、ブロードキャストは行いません。`ModifyAndSignTransaction` は `tx` を Fordefi が署名したトランザクションに置き換えます。以降の処理は必ずそのトランザクションから続けてください。書き換えによって既存の署名は無効になるため、Fordefi が手数料支払者であり、他の必要な署名者よりも先に署名する必要があります。書き換えの差分は提供されないため、ブロードキャストする前に結果を確認してください。

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**ブラックボックスモード**: `Chain` を未設定のままにします。Fordefi はお客様のメッセージのバイト列をそのまま署名し、ブロードキャストは行いません。Fordefi のブラックボックスボールトと組み合わせて使用してください。

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## アンブレラパッケージがない理由

Rust には `Signer` 列挙型、TypeScript には `createKeychainSigner` がありますが、Go には意図的にどちらもありません。Go は実行時のディスパッチ switch をまたいだデッドコード除去を行わないため、アンブレラパッケージを用意すると、すべてのバックエンドのベンダー SDK(AWS、GCP など)があらゆる利用者のビルドに含まれてしまいます。必要なバックエンドのパッケージをインポートすること自体が、選択の手段です。実行時にバックエンドを選ぶ場合は、サポートするバックエンドだけを対象とした switch をご自身のコードに記述し、その結果を `core.SolanaSigner` として保持してください。

## エラー処理

すべてのエラーは、安定した `Code`(`CodeConfigError`、`CodeHTTPError`、`CodeRemoteAPIError`、`CodeSigningFailed`、`CodeNotInitialized`、`CodeBroadcastUnconfirmed` など)を持つ `*core.SignerError` です。`Error()` はコードごとに固定されたメッセージのみを返し、鍵情報やプロバイダーの生のレスポンスを返すことはありません。判定には `errors.As`、`errors.Is(err, &core.SignerError{Code: ...})`、または `core.CodeOf(err)` を使用してください。

Crossmint と Fordefi ネイティブ自動モードでは、失敗したからといって何も反映されていないとは限りません。プロバイダーがトランザクションを受け付けた可能性がある場合、コードは `core.CodeBroadcastUnconfirmed`(`"SIGNER_BROADCAST_UNCONFIRMED"`)になります。作成が受け付けられた場合は `ProviderTxID` が設定され、`IdempotencyKey` にはメッセージから導出されたキーが格納されます。バイト単位で同一のトランザクションを再送しても安全ですが、再構築したトランザクション(たとえば新しいブロックハッシュを使用したもの)は新しい送金として扱われます。`core.SignAndSendTransaction` も、お客様の send 関数が失敗した場合にこのコードを報告し、手数料支払者の署名を `TransactionSignature` に格納します。Fireblocks の PROGRAM_CALL は署名専用で鍵を送信しません。このコードを報告するのは、ポーリングの結果、Fireblocks が実際にはブロードキャストしていたことが判明した場合のみです。

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

各署名形態が保証する内容については[セキュリティモデル](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md)を、モジュールの完全な一覧については [Go README](https://github.com/solana-foundation/solana-keychain/blob/main/go/README.md) を、API リファレンスについては [pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2) をご覧ください。

## カスタムシグナーの追加

`core.SolanaSigner` と、ケイパビリティインターフェースをちょうど 1 つ実装し、バックエンドが対応できないメソッドは追加しないでください。呼び出し側は型アサーションによってケイパビリティを判別します。追加の鍵管理サービスを統合する方法については、[シグナー追加ガイド](/docs/tools/keychain/adding-signers)をご覧ください。
