をご覧ください。

## インストール

各バックエンドは独立したGoモジュールになっているため、ビルドとモジュールグラフには、インポートしたバックエンドのみが含まれます。

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

モジュールには `go/<module>/v2.0.0` の形式でタグが付けられます(例:
`go/signers/memory/v2.0.0`)。すべてのモジュールはGo 1.25.0を必要としますが、`gcpkms` だけは `google.golang.org/api` が定める最低バージョンの関係でGo 1.25.8が必要です。
LedgerはRust専用で、Goモジュールはありません。

### solana-go v2とv1トランザクション

これらのモジュールは
[`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go)
v2.0.0をベースに構築されており、その `*solana.Transaction` を受け取ります。レガシー、v0、v1
(`solana.MessageVersionV1`)のトランザクションに対応していますが、`UseProgramCall: true` を指定したFireblocksはレガシーとv0のみ対応です。

## 基本的な使い方

すべてのsignerは、基本の
[`core.SolanaSigner` インターフェース](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)
(`Pubkey`、`SignMessage`、`IsAvailable`)を実装しています。メソッドは `context.Context` を受け取り、ブロックします。さらに各バックエンドは、capabilityインターフェースをちょうど1つ実装しています。

- `core.TransactionSigner`: `SignTransaction` は、渡されたトランザクションをそのまま署名します。
- `core.ModifyingSigner`: `ModifyAndSignTransaction` は、プロバイダーがトランザクションを書き換えたうえで署名します。
- `core.SendingSigner`: `SignAndSendTransaction` は、プロバイダーが署名とブロードキャストを行います。

各バックエンドパッケージは、`Config` 構造体と `New` コンストラクターを公開しています。

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` と `ModifyAndSignTransaction` は、`core.SignedTransaction`
(`EncodedTransaction`、`Signature`、`Completeness`)を返します。
リモートHTTPバックエンドでは、オプションで `HTTPClient` と `HTTPClientConfig`
(タイムアウト)を指定できます。デフォルトのクライアントはHTTPSを強制します。独自のクライアントを指定するとこの制約は回避されますが、そのセキュリティ対策はご自身の責任となります。

### Signerのcapability

トランザクションに署名できないバックエンドには、`SignTransaction` メソッドそのものがありません。そのため、具象型ではcapabilityはコンパイル時に確定し、`core.SolanaSigner` では型アサーションで判定します。

| バックエンド                                                                         | Capability          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | 対応                            |
| cdp                                                                             | `TransactionSigner` | UTF-8ペイロードのみ            |
| utila                                                                           | `TransactionSigner` | `CodeSigningFailed` で失敗 |
| fordefi ブラックボックス(`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | 対応                            |
| fordefi ネイティブ手動(`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | 対応                            |
| fordefi ネイティブ自動(`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | 対応                            |
| crossmint                                                                       | `SendingSigner`     | `CodeSigningFailed` で失敗 |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### 初期化

独立した `Init` ステップはありません。Privy、Fireblocks、Dfns、Crossmint、Para、OpenfortおよびUtilaは `New` の中でウォレットアドレスを解決します。そのため、これらのコンストラクターは `context.Context` を受け取ります。signerは必ず `New` で構築してください。ゼロ値のCrossmint、ParaまたはUtila signerは、ゼロアドレスで署名するのではなく、`CodeNotInitialized` で失敗します。

### 任意のSignerでの署名と送信

`core.SignAndSendTransaction` は、signerの形態を問わず、トランザクションをオンチェーンに反映させます。`SendingSigner` はプロバイダー経由でブロードキャストし、送信関数は無視されます。それ以外の形態では署名のみを行い、base64形式の結果をご自身の関数でブロードキャストします。`ModifyingSigner` の場合、この結果はプロバイダーが書き換えたトランザクションです。
CoreはRPCに依存しません。

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### バッチ署名

バッチ署名は、フリーのヘルパーとして提供されています。並行して実行され、レート制限のあるAPI向けにリクエストごとの間隔(stagger)を任意で指定できます。

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` は `core.TransactionSigner` を受け取るため、ブロードキャスト管理型のsigner(Crossmint、Fordefiネイティブ自動)とFordefiネイティブ手動はバッチ処理できません。これらは1トランザクションずつ呼び出してください。呼び出しによってプロバイダー側で処理が発生するsigner(`UseProgramCall` を指定したFireblocks)は、`core.BatchServerSideEffects` を通じてそれを通知し、その場合バッチは順次実行されます。

## バックエンドの設定

### Memory

`PrivateKey`(生のバイト列)、`PrivateKeyString`(base58または `[1,2,...]` 形式のバイト配列)、`PrivateKeyPath`(Solana CLIのkeypairファイル)のうち、ちょうど1つを指定してください。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Goにはメモリをゼロクリアする確実な方法がありません。ガベージコレクターが、回収されるまでキーのバイト列をコピーして保持する場合があります(memoryのkeypairや、CrossmintとOpenfortがローカルで導出するキーなど)。ローカルキー型のバックエンドを使用する場合は、プロセスのメモリ全体を機密として扱ってください。

import "github.com/solana-foundation/solana-keychain/go/signers/vault/v2"

```go
import "github.com/solana-foundation/solana-keychain/go/signers/cdp/v2"

signer, err := cdp.New(cdp.Config{
	APIKeyID:     "api_key_id",

```

CDPの `SignMessage` はUTF-8ペイロードのみ受け付けます。

### Crossmint

Crossmintは送信専用です。承認されたトランザクションはすべてAPI側(サーバー側)で実行されるため、`*crossmint.Signer` には `SignAndSendTransaction` があり、`SignTransaction` はありません。トランザクションが変更されることはありません。返される署名は、Crossmintが実際にオンチェーンに反映させたトランザクションを示し、Crossmintがガス代を肩代わりする場合は、お客様のトランザクションと異なることがあります。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

import "github.com/solana-foundation/solana-keychain/go/signers/dfns/v2"

### Utila

Utilaはトランザクションへの署名のみに対応しています。`SignMessage` は失敗するため、署名済みトランザクションはご自身でブロードキャストしてください。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/utila/v2"

signer, err := utila.New(ctx, utila.Config{
	ServiceAccountEmail:         "sa@example.com",
	ServiceAccountPrivateKeyPEM: "-----BEGIN PRIVATE KEY-----\n...",
	VaultID:                     "vault_id",
	WalletID:                    "wallet_id",
	Network:                     "networks/solana-devnet",
})
```

### Fordefi

Fordefiには3種類のsignerタイプがあり、構築時に `Config.Chain` と `Config.PushMode` によって決まります。3つとも、メッセージに署名できます。

| Config                                          | タイプ                          | エントリーポイント                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` 未設定                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` 設定済み、`PushMode` 未設定または `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` 設定済み、`PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` はconfigに応じて振り分け、`core.SolanaSigner` を返します。`fordefi.NewBlackBox`、`fordefi.NewNativeAuto`、`fordefi.NewNativeManual` は具象型を返し、他のモードのconfigは拒否します。APIリクエストはECDSA P-256のリクエスト署名で認証されます。`PrivateKeyPEM` をちょうど1つ指定するか、キーをKMS/HSM内に保持する場合は `RequestSigner` を指定してください。

**ネイティブ自動モード**: Fordefiはblockhashと手数料を置き換えたうえで、署名してブロードキャストする場合があります。受け付けるのは、必要な署名者がvaultのみである未署名のトランザクションに限られます。

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**ネイティブ手動モード**: `PushMode: fordefi.PushModeManual` を設定します。Fordefiはメッセージ(最新のblockhash、Compute Budgetのfee instructions)を書き換え、ブロードキャストせずに署名します。`ModifyAndSignTransaction` は `tx` をFordefiが署名したトランザクションに置き換えるため、以降は必ずそれを使って処理を続けてください。Fordefiは手数料支払者である必要があり、書き換えによって既存の署名は無効になるため、他の必要な署名者より先に署名しなければなりません。書き換え内容の差分は取得されないため、ブロードキャストする前に結果を確認してください。

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**ブラックボックスモード**: `Chain` を未設定のままにします。Fordefiはメッセージのバイト列をそのまま署名し、ブロードキャストは行いません。Fordefiのブラックボックスvaultでご利用ください。

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## 包括パッケージが存在しない理由

Rustには `Signer` enum、TypeScriptには `createKeychainSigner` がありますが、Goにはどちらもあえて用意していません。Goは、ランタイムのディスパッチswitchをまたいだデッドコード除去を行わないため、包括パッケージを用意すると、すべてのバックエンドのベンダーSDK(AWS、GCPなど)がすべての利用者のビルドに含まれてしまいます。必要なバックエンドのパッケージをインポートすること自体が、選択の手段です。実行時にバックエンドを選びたい場合は、対応するバックエンドだけを対象にswitchをご自身のコードに記述し、結果を `core.SolanaSigner` として保持してください。

## エラー処理

すべてのエラーは、安定した `Code`(`CodeConfigError`、`CodeHTTPError`、`CodeRemoteAPIError`、`CodeSigningFailed`、`CodeNotInitialized`、`CodeBroadcastUnconfirmed` など)を持つ `*core.SignerError` です。`Error()` はコードごとに固定されたメッセージのみを返し、キー素材やプロバイダーの生のレスポンスは含まれません。判定には `errors.As`、`errors.Is(err, &core.SignerError{Code: ...})`、または `core.CodeOf(err)` を使用してください。

CrossmintおよびFordefiのネイティブ自動モードでは、失敗したからといって何も反映されていないとは限りません。プロバイダーがトランザクションを受け付けた可能性がある場合、コードは `core.CodeBroadcastUnconfirmed`(`"SIGNER_BROADCAST_UNCONFIRMED"`)になります。作成が受け付けられた場合は `ProviderTxID` が設定され、`IdempotencyKey` にはメッセージから導出されたキーが格納されます。バイト列が完全に同一のトランザクションを再送するのは安全ですが、再構築したもの(たとえば新しいblockhashを使ったもの)は新しい送金として扱われます。`core.SignAndSendTransaction` も、送信関数が失敗した場合にこのコードを報告し、手数料支払者の署名を `TransactionSignature` に格納します。FireblocksのPROGRAM_CALLは署名専用でキーを送信しません。このコードを報告するのは、ポーリングの結果、Fireblocksが実際にブロードキャストしていたことが判明した場合のみです。

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

各署名形態が保証する内容については
[セキュリティモデル](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md)
、モジュールの一覧については
[Go README](https://github.com/solana-foundation/solana-keychain/blob/main/go/README.md)
、APIリファレンスについては
[pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2)
をご覧ください。

## カスタムSignerの追加

`core.SolanaSigner` と、capabilityインターフェースをちょうど1つ実装し、バックエンドが対応できないメソッドは追加しないでください。呼び出し側は型アサーションでcapabilityを判定します。
その他のキー管理サービスを統合する方法については、[Signer追加ガイド](/docs/tools/keychain/adding-signers)をご覧ください。
