## インストール

必要に応じて、統合パッケージまたは個別の署名者をインストールします：

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

`@solana/kit` 8.1以降が必要です。v1トランザクション（`createTransactionMessage({ version: 1 })`）はサポートされていますが、`useProgramCall: true`を指定したFireblocksは例外で、レガシーとv0のみを受け付けます。

## 基本的な使い方

### 統合ファクトリ（複数の署名者をサポートしたいアプリに推奨）

`createKeychainSigner`を判別可能な設定と共に使用して、任意のバックエンドを作成します：

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

または、依存関係のフットプリントを小さくするために、個別の署名者パッケージをインストールします：

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### トランザクションメッセージでの使用

CrossmintとFordefiネイティブモードを除くすべてのバックエンドは`SolanaTransactionSigner`を返します。これはKitの`TransactionPartialSigner`であり、以下の`@solana/signers`のpartial-signerヘルパーで使用できます。マネージドブロードキャスト型のバックエンドについては、[署名者の機能](#signer-capabilities)で説明しています。

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### 任意の署名者で署名して送信する

`@solana/keychain-core`の`signAndSendTransaction`は、署名者の形態を問わずトランザクションをオンチェーンに送信します。送信型の署名者はプロバイダー経由でブロードキャストし、それ以外の形態では渡された`sendTransaction`を使用します（coreはRPCに依存しません）：

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Kit クライアントでの使用方法（keychainSigner プラグイン）

`@solana/keychain-kit-plugin` は、キーチェーン署名者を
[Kit クライアント](https://github.com/anza-xyz/kit)に直接インストールし、`payer`
および `identity` として自動的に設定するため、上記の手動による `pipe`
のセットアップを省略できます：

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

プラグインは`createKeychainSigner`と同じバックエンドタグ付き設定を受け付けますが、CrossmintとFordefiネイティブモード（`chain`を設定した場合）は除きます。これらのバックエンドはサーバー側でトランザクションを書き換えるため、クライアントの`payer`や`identity`として機能できず、プラグインはコンパイル時と実行時にこれらを拒否します。ディスパッチ先のバックエンドのみがバンドルされます（バックエンドパッケージは動的な`import()`で読み込まれます）。

`keychainPayer` または `keychainIdentity`
を使用して単一のロールのみを設定し、単一クライアント上で複数のバックエンドを混在させることができます：

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

すでに`SolanaTransactionSigner`をお持ちですか？これは有効なKitの`TransactionPartialSigner`なので、代わりに[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)でインストールできます（`pnpm add @solana/kit-plugin-signer`）：

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### キャンセルと未確認のブロードキャスト

`signTransactions`、`modifyAndSignTransactions`、`signAndSendTransactions`、`signMessages`はいずれも、第2引数に`{ abortSignal }`を指定できます。中止すると待機は止まりますが、プロバイダーがすでに受け付けた処理が取り消されるわけではありません。

CrossmintおよびFordefiのネイティブ自動モードでは、失敗したからといって何も反映されていないとは限りません。プロバイダーがトランザクションを受け付けた可能性がある場合、エラーコードは`SignerErrorCode.BROADCAST_UNCONFIRMED`（`"SIGNER_BROADCAST_UNCONFIRMED"`）になります。作成リクエストが受理された場合は`context.providerTransactionId`が設定され、`context.idempotencyKey`にはメッセージから導出されたキーが格納されます。バイト単位で同一のトランザクションを再送しても安全ですが、再構築したもの（たとえば新しいブロックハッシュを使用したもの）は新しい送金になります。`@solana/keychain-core`の`providerMayHaveAccepted(error)`と`providerStatus(error)`は、エラーの分類に役立ちます。再試行する前に、プロバイダー側の状態と照合してください。

### Crossmint

```typescript

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmintは送信専用です。そのAPIは承認済みのトランザクションを常にサーバー側で実行し、ガス代をスポンサーするため、署名者が公開するのは`signAndSendTransactions()`のみです。`signTransactions()`や`signMessages()`はなく、`@solana/keychain-kit-plugin`でインストールすることもできません。返される署名は、Crossmintが反映したトランザクションを識別します。

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

Fordefiには3つの署名モードがあり、`chain`と`pushMode`によって構築時に固定されます。各モードが公開するトランザクションメソッドはちょうど1つで、3つのモードすべてがメッセージに署名できます：

| モード          | 設定                                      | 型                        | メソッド                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| ブラックボックス     | `chain`未設定                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| ネイティブ自動   | `chain`を設定、`pushMode`は省略または`"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| ネイティブ手動 | `chain`を設定、`pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

APIリクエストはECDSA P-256のリクエスト署名で認証されます。署名鍵を`privateKeyPem`として指定するか、`requestSigner`を渡してKMS/HSM内に保管したままにします。

**ネイティブ自動モード**（オンチェーンでの利用に推奨）：`chain`を設定すると、Fordefi自身がトランザクションに署名してブロードキャストします。Fordefiは署名前にブロックハッシュや手数料を置き換える場合があるため、署名者はKitの`TransactionSendingSigner`となります。上記のpartial-signerのフローではなく、`signAndSendTransactionMessageWithSigners`で使用してください。ネイティブ自動モードが受け付けるのは、唯一必要な署名者がボールトである未署名トランザクションのみで、`@solana/keychain-kit-plugin`と併用することはできません。

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**ネイティブ手動モード**：`chain`と`pushMode: "manual"`を設定します。Fordefiはメッセージ（最新のブロックハッシュ、Compute Budgetのfee instructions）を書き換えて署名しますが、ブロードキャストは行いません。`modifyAndSignTransactions()`はFordefiが署名したトランザクションを返し、これは送信したものと置き換わります。必ず返されたトランザクションから処理を続けてください。Fordefiは手数料支払者である必要があり、他の必要な署名者より先に署名しなければなりません。書き換え内容の差分は提供されないため、ブロードキャストの前に結果を確認してください。

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**ブラックボックスモード**：`chain`を省略します。Fordefiは生のバイト列に署名しますが、ブロードキャストは行いません。トランザクションのアセンブルと送信はご自身で行ってください。このモードはFordefiのブラックボックスボールトと組み合わせて使用します。

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## 署名者の機能

`@solana/keychain-core`は、Kitの署名者の形態ごとに1つのインターフェースを定義しています。それぞれが、対応する`@solana/signers`のインターフェースに`isAvailable(): Promise<boolean>`を追加したものです：

- `SolanaTransactionSigner`（Kitの`TransactionPartialSigner`）：ユーザーが所有するトランザクションに対する署名を返します。
- `SolanaModifyingSigner`（Kitの`TransactionModifyingSigner`）：トランザクションを書き換えて署名し、ブロードキャストせずに新しいトランザクションを返します。
- `SolanaSendingSigner`（Kitの`TransactionSendingSigner`）：プロバイダー経由で署名とブロードキャストを行います。
- `SolanaMessageSigner`（Kitの`MessagePartialSigner`）：オフチェーンメッセージに署名します。トランザクションの形態とは別のものです。

`SolanaSigner`は3つのトランザクション形態のユニオン型です。各ファクトリーの戻り値の型は、そのバックエンドの正確な形態を示します。設定が実行時にしか分からない場合は、`isSolanaTransactionSigner`、`isSolanaModifyingSigner`、`isSolanaSendingSigner`、`isSolanaMessageSigner`で絞り込みます。`signerCapabilities(signer)`は4つすべてを一度に返します。

| バックエンド                                                                                                     | 形態                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi（ブラックボックス） | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner`（メッセージ署名なし）  |
| fordefi（ネイティブ手動）                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi（ネイティブ自動）                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner`（メッセージ署名なし）      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## カスタム署名者の構築

バックエンドが対応する機能のインターフェースを実装します：

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

バックエンドが対応するものだけを実装してください。Kitはどのメソッドが存在するかで署名者を分類するため、例外を投げるだけのメソッドは追加しないでください。

追加の鍵管理サービスを統合するには、[署名者の追加ガイド](/docs/tools/keychain/adding-signers)を参照してください。
