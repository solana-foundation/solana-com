---
title: デプロイ用アセット
description: プログラムのビルドを Mainnet へデプロイするために準備する
---

アプリケーションを Mainnet にデプロイする前に、次のものが揃っていることを確認してください:

- プログラムの ELF ファイル - 通常は `anchor build` または `cargo-build-sbf` の結果として生成される、`.so` で終わるファイル
- プログラムの keypair - 整数の配列を含む JSON ファイル

このセクションでは、これらのアセットの入手先と準備方法について説明します。

## ELF ファイルを準備する [#preparing-your-elf-file]

ELF ファイルには、コンパイル済みのバイトコード、メモリレイアウト情報、そして Solana 仮想マシン(SVM)がプログラムのロードと実行方法を理解するために必要なメタデータが含まれています。ELF ファイルは、ソースコードのコンパイル時に作成されます。

Anchor 用の ELF ファイルを作成するには、次のコマンドを実行します:

```bash
anchor build
```

他のフレームワークの場合は、次のコマンドを実行します:

```bash
cargo build-sbf
```

ELF ファイルは、`target/deploy/<PROGRAM_NAME>.so` のようなディレクトリにあります。

ELF ファイルが [sBPFv3](https://www.anza.xyz/blog/migrating-solana-programs-to-sbpfv3) にコンパイルされていれば、プログラムの準備は完了です。プログラムを確認するには、Linux で次のコマンドを実行します:

```bash
readelf -h target/deploy/<PROGRAM_NAME>.so | grep Flags:
```

macOS では、次のコマンドを実行します:

```bash
# brew install llvm
$(brew --prefix llvm)/bin/llvm-readelf -h target/deploy/<PROGRAM_NAME>.so | grep Flags:
```

次のような出力が表示されれば、プログラムの準備は完了です:

```
  Flags:                             0x3
```

そうでない場合は、[こちら](https://solana.com/upgrades/sbpfv3-programs)にリンクされている移行ガイドに従ってください。

## プログラムアドレスを準備する [#preparing-your-program-address]

プログラムアドレスは、プログラムの instructions を呼び出す際に使用するプログラム ID です。1) ビルド時に生成されたプログラムの keypair を使用する、2) カスタムプレフィックスで始まるアドレスを持つ新しい keypair をグラインドする、3) ベースアドレスと seed からアカウントアドレスを導出する、のいずれかを選べます。最初の 2 つのオプションでは、program account の署名に使用できる keypair が生成されます。seed を使って作成されたアカウントは独自の秘密鍵を持たず、ベースアカウントによって制御されます。

### 生成された keypair を使用する

デフォルトでは、`anchor build` と `cargo build-sbf` はプログラムの keypair を次の場所に配置します:

```text
target/deploy/<PROGRAM_NAME>-keypair.json
```

ビルドディレクトリをクリーンする前に、このファイルをバックアップしてください。keypair にアクセスできる人は誰でも program account として署名できるため、ソース管理にコミットしないでください。

### カスタムプレフィックスで keypair をグラインドする

[`vanity`](https://github.com/cavemanloverboy/vanity) を使うと、公開鍵が特定の base58 プレフィックスで始まる Ed25519 keypair を検索できます。CPU 版は crates.io からインストールします:

```bash
cargo install vanity
```

このプロジェクトでは、GPU による高速検索向けに CUDA、Metal、OpenCL のビルドも提供されています。各バックエンドの要件については、`vanity` のインストール instructions を参照してください。

```bash
vanity grind-keypair --pattern Acme...
```

一致するものが見つかると、`vanity` は公開鍵、16 進数形式の秘密シード、そして Solana 互換の keypair JSON 配列を出力します。JSON ファイルを安全な場所に保存し、想定した公開鍵が含まれていることを確認してください:

```bash
solana-keygen pubkey path/to/keypair.json
```

コマンドの出力と保存した JSON ファイルは、秘密鍵の情報として扱ってください。

### seed を使ってアカウントを作成する

より高速に検索するには、`vanity grind` を使います。Ed25519 keypair を生成する代わりに、`CreateAccountWithSeed` 用の seed 文字列を検索します。作成を承認するベースアカウントの公開鍵、アカウントの所有者、検索するプレフィックスを指定してください。アップグレード可能な program account の場合、所有者にはアップグレード可能な BPF ローダーを指定します:

```bash
vanity grind \
  --base <BASE_ACCOUNT_PUBKEY> \
  --owner BPFLoaderUpgradeab1e11111111111111111111111 \
  --pattern Acme...
```

結果には、導出されたアドレスと seed 文字列が含まれます。アカウントを作成する前に、これらを検証してください:

```bash
vanity verify \
  --base <BASE_ACCOUNT_PUBKEY> \
  --owner BPFLoaderUpgradeab1e11111111111111111111111 \
  --seed <SEED>
```

同じベースアドレス、seed、所有者を使って `Pubkey::create_with_seed` でアドレスを導出し、System Program の `create_account_with_seed` instructions を送信します。ベースアカウントと資金提供アカウントがトランザクションに署名する必要があります。導出されたアカウントには単独の keypair がないため、このオプションでは、プログラムの keypair ファイルではなくベースアカウントを使用するアカウント作成およびデプロイのフローが必要です。

### ソース内のプログラムアドレスを更新する

keypair または seed 付きアカウントを選んだら、その公開アドレスを、プロジェクト内でプログラム ID を宣言しているすべての箇所でプログラム ID として使用してください。ソースに古いアドレスが残っていると、クライアントが誤ったプログラムに instructions を送信したり、ランタイムの ID チェックが失敗したりする可能性があります。

Anchor ワークスペースでは、ルートの `Anchor.toml` 内のプログラムエントリと、`programs/<PROGRAM_NAME>/src/lib.rs` 内の `declare_id!` 呼び出しの両方を更新します。`[programs.<CLUSTER>]` 配下のキーは、プログラムのワークスペース名です。新しいアドレスを使用する予定のすべてのクラスターテーブルを更新してください。以下の例では Mainnet を更新します。

Anchor.toml の場合:

```diff
 [programs.mainnet]
-my_program = "<OLD_PROGRAM_ID>"
+my_program = "<NEW_PROGRAM_ID>"
```

`programs/<your_program>/lib.rs` の場合:

```diff
-declare_id!("<OLD_PROGRAM_ID>");
+declare_id!("<NEW_PROGRAM_ID>");
```

Pinocchio は `Anchor.toml` を使用しません。プログラムクレートの `src/lib.rs` 内の `declare_id!` 呼び出しを更新してください。現在の Pinocchio プロジェクトでは、マクロを `pinocchio::address` からインポートします。

Quasar も、オンチェーンプログラムクレートの `src/lib.rs` でアドレスを宣言し、`Anchor.toml` は使用しません。`declare_id!` マクロは `quasar_lang::prelude::*` から利用できます。

アドレスを変更したら、プログラムを再ビルドし、IDL やクライアントの成果物を再生成してください。また、デプロイスクリプト、テスト、アプリケーション設定内に古いプログラム ID がないか検索し、ハードコードされた参照をすべて置き換えてください。
