`solana`コマンドラインインターフェースでは、クラスター接続の設定、ネットワーク状態の読み取り、SOLの送信、durable nonceの管理、プログラムのデプロイ、ステークアカウントおよび投票アカウントの操作を行えます。

このリファレンスは[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1)に準拠しています。`solana --version`を実行してインストール済みのリリースを確認し、そのバージョンで利用可能なオプションの詳細は`--help`で確認してください。

<Callout type="warn">
  作成、転送、承認、引き出し、デプロイを行うコマンドはトランザクションを送信します。実行する前に、設定されているクラスターと署名者を確認してください。DevnetとTestnetのトークンに価値はありませんが、Mainnetのコマンドは実際のSOLを使用します。
</Callout>

## コマンドの構造

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

どの階層でもヘルプを表示できます:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## グローバルオプション

グローバルオプションはコマンドの前に指定できます。コマンド固有のヘルプには、そのコマンドに適用されるオプションが再掲されます。

| オプション                          | 目的                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | RPC URL、または`mainnet-beta`、`testnet`、`devnet`、`localhost`のいずれかを選択します。      |
| `--ws <URL>`                    | WebSocketエンドポイントを上書きします。                                               |
| `-k, --keypair <KEYPAIR>`       | keypairファイル、`ASK`、標準入力(`-`)、または対応する署名者URLを選択します。          |
| `-C, --config <FILEPATH>`       | 別のCLI設定ファイルを使用します。                                        |
| `--commitment <LEVEL>`          | `processed`、`confirmed`、`finalized`のいずれかのコミットメントで読み取ります。                   |
| `--output <FORMAT>`             | 対応しているコマンドで`json`または`json-compact`を返します。                               |
| `--skip-preflight`              | RPCシミュレーションなしで送信します。失敗時のトレードオフを理解している場合にのみ使用してください。 |
| `--use-tpu-client`              | TPUクライアント経由でトランザクションを送信します。                                      |
| `--no-address-labels`           | ローカルラベルなしでアドレスを出力します。                                          |
| `--skip-seed-phrase-validation` | BIP39の英語単語リストにないリカバリーフレーズを許可します。                       |
| `-v, --verbose`                 | コマンドの追加出力を表示します。                                                |
| `-V, --version`                 | インストール済みのCLIバージョンを出力します。                                               |

## CLIの設定

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

設定には、RPC URL、WebSocket URL、デフォルトの署名者、コミットメントが含まれます。コマンドラインオプションを指定すると、その実行に限り保存済みの値が上書きされます。

## アカウントとトランザクションの主なワークフロー

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer`はデフォルトでSOLを扱います。金額に`ALL`を指定すると、手数料を差し引いた利用可能な残高をすべて移動します。トークンの例については、[トークンのクイックスタート](/docs/tokens/quickstart)を参照してください。

## プログラムのワークフロー

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

デプロイで既知のプログラムIDを使用する必要がある場合は、`--program-id <KEYPAIR_OR_ADDRESS>`を指定します。`--final`を指定すると、新しいデプロイは不変になります。アップグレード権限は復元できないため、使用する前にヘルプをよくお読みください。

## Durable nonceのワークフロー

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

nonceの権限を変更するには`authorize-nonce-account`を、アカウントの完全な状態を確認するには`nonce-account`を使用します。nonceを使用するトランザクションでは、対応するコマンドで`--nonce`と`--nonce-authority`も指定できます。

## ステークのワークフロー

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

非アクティブ化はepochの境界で完了し、1 epoch以上かかる場合があります。変更を送信する前に、`stakes`、`validators`、`stake-history`、`stake-minimum-delegation`を使用して、クラスターと委任の状態を確認してください。

## アドレスユーティリティ

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

PDAのseedは`PREFIX:VALUE`の形式で指定します。サポートされているプレフィックスには、`string`、`pubkey`、`hex`、`u8`、および`u64le`などの固定幅の符号付き・符号なし整数エンコーディングがあります。

## オフチェーンメッセージとシェル補完

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

| `authorize-nonce-account`           | durable nonceアカウントの権限を割り当てます。                                         |
| `balance`                           | アカウントのSOL残高を表示します。                                                    |
| `block`                             | slotを指定して、承認済みブロックを取得します。                                                  |
| `block-height`                      | 現在のブロック高を表示します。                                                    |
| `block-production`                  | 指定したslot範囲におけるリーダーのブロック生成状況を表示します。                                    |
| `block-time`                        | ブロックの生成時刻を推定します。                                          |
| `catchup`                           | validatorがクラスターに追いつくまで待機します。                                |

| `confirm`                           | トランザクション署名の承認状況を確認します。                              |

## スクリプトでの出力

人間向けの出力を解析する代わりに、対応しているコマンドでは`--output json`または`--output json-compact`を使用してください:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

すべてのコマンドが構造化出力に対応しているわけではありません。自動化で利用する前にコマンドのヘルプを確認し、ゼロ以外の終了ステータスは失敗として扱ってください。
