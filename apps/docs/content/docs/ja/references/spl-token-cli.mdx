`spl-token` コマンドラインインターフェースを使用すると、ミント、token account、権限(authority)、転送、Token-2022 拡張機能を作成・管理できます。

このリファレンスは、Agave v4.2.1 にバンドルされているバージョンである [`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1) に準拠しています。お使いのバージョンで利用可能なオプションを正確に確認するには、`spl-token --version` を実行し、`<command> --help` を使用してください。

<Callout type="warn">
  ミントの作成、転送、権限の変更、バーン、フリーズ、アカウントのクローズはトランザクションを送信します。コマンドを実行する前に、クラスター、Token Program、署名者、アドレスを必ず確認してください。メインネットでの変更は実際の資産に影響します。
</Callout>

## インストールとヘルプの確認

Agave CLI のリリースバンドルには `spl-token` が含まれています。インストールされていない場合は、公開されている Rust クレートを使用してください。

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

ルートレベルまたはコマンドレベルでヘルプを確認できます。

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## グローバルオプション

グローバルオプションはコマンドの前に指定します。

| オプション                                       | 用途                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | RPC URL、または `mainnet-beta`、`testnet`、`devnet`、`localhost` を選択します。 |
| `-C, --config <PATH>`                        | 別の Solana CLI 設定ファイルを使用します。                            |
| `--fee-payer <KEYPAIR>`                      | トランザクション手数料を支払うアカウントを選択します。                            |
| `-p, --program-id <ADDRESS>`                 | Token Program ID を明示的に指定します。                                         |
| `--program-2022`                             | Token-2022(`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`)を使用します。           |
| `--output <FORMAT>`                          | 対応しているコマンドで `json` または `json-compact` 形式で出力します。                          |
| `--with-compute-unit-limit <UNITS>`          | トランザクションのコンピュートユニット上限を設定します。                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | コンピュートユニットあたりの優先価格を設定します。                                  |
| `-v, --verbose`                              | 追加の出力を表示します。                                                   |
| `-V, --version`                              | インストールされている CLI のバージョンを表示します。                                          |

デフォルトのプログラムは元の Token Program です。Token-2022 のミントまたはアカウントには、読み取る場合も含めて `--program-2022` を使用してください。選択したプログラムが指定したアドレスを所有していない場合、コマンドは失敗します。

## トークンの作成と使用

コマンドは作成されたアドレスを出力します。`create-token` が返すミントアドレスは、以降のコマンドで使用するため保存しておいてください。

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

数量はミントの小数桁数(decimals)に応じて調整された UI 上のトークン数量です。`transfer`、`burn`、`unwrap-sol` などのコマンドでは、ヘルプに記載されている箇所で `ALL` を指定できます。

## Token-2022 ミントの作成

拡張機能はミントまたはアカウントの状態として追加の領域を割り当てるため、通常はミントの作成時に選択する必要があります。この例では、メタデータの埋め込みに対応した小数桁数 6 のミントを作成します。

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

`create-token` の一般的な拡張機能オプションは次のとおりです。

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` および `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` または `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` と `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Token-2022 プログラムで併用が許可されている拡張機能のみを組み合わせてください。元に戻せないミント設定を作成する前に、関連する [Token-2022 拡張機能ガイド](/docs/tokens/extensions)を確認してください。

## 権限とデリゲートの管理

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` は、ミント、フリーズ、オーナー、クローズ、および拡張機能固有の権限タイプに対応しています。`--disable` で権限を削除すると、他のプログラムの仕組みで復元できない場合は永久に削除されます。

## フリーズ、バーン、クローズ

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` はアカウントの残高と総供給量の両方を減らします。`close` はアカウントに残っている lamport を設定された受取先に返しますが、バーンされたトークンは回復されません。

## SOL のラップとアンラップ

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

ラップされた SOL の token account に lamport を直接転送した後は、`sync-native` を使用して、そのトークン数量を基礎となる lamport と一致させてください。

## マルチシグ署名

最大 11 人のメンバーで構成される M-of-N の Token Program マルチシグを作成します。

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

そのマルチシグが管理するトランザクションでは、マルチシグのアドレスを該当する権限として指定し、`--multisig-signer` を繰り返してメンバーの keypair を渡します。主要な権限フラグは操作によって異なるため、対象コマンドのヘルプを確認してください。

## 機密残高(Confidential Balance)

機密残高のコマンドには、機密転送が設定された Token-2022 ミントと、設定済みの受取アカウントが必要です。

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

`configure-confidential-transfer-account` と `apply-pending-balance` では、`--address <TOKEN_ACCOUNT_ADDRESS>` か位置引数の `<MINT_ADDRESS>` のどちらか一方のみを指定してください。両方は指定できません。位置引数を使用する場合は、オーナーの associated token account が使用されます。入金と出金では常にミントを指定し、`--address` を指定することでデフォルトのアカウントを上書きできます。

`enable-confidential-credits`、`disable-confidential-credits`、`enable-non-confidential-credits`、`disable-non-confidential-credits` を使用して、アカウントが受け入れる入金を制御できます。これらの設定はアカウントのプライバシーと支払いの互換性に影響するため、変更する前にアカウントを確認してください。

## 構造化出力とオフライン署名

表示テキストを解析するのではなく、構造化出力を使用してください。

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

トランザクションを生成するコマンドの多くは、`--sign-only`、`--blockhash`、`--signer <PUBKEY=SIGNATURE>`、`--nonce`、`--nonce-authority` に対応しています。オフラインで必要な入力は、コマンド、ミントの小数桁数、権限の構成によって異なります。そのため、そのコマンドの `--help` の instructions に従って未署名メッセージを生成し、署名を収集する前にすべてのアドレスを確認してください。
