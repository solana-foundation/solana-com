`spl-token` コマンドラインインターフェースを使用すると、ミント、token accounts、権限、転送、Token-2022 拡張機能を作成・管理できます。

このリファレンスは、Agave v4.2.1 にバンドルされているバージョン [`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1) に準拠しています。ご利用中のバージョンで使用可能なオプションについては、`spl-token --version` を実行し、`<command> --help` を参照してください。

<Callout type="warn">
  ミントの作成、転送、権限の変更、バーン、フリーズ、アカウントのクローズは、いずれもトランザクションを送信します。コマンドを実行する前に、クラスター、Token Program、署名者、アドレスを必ず確認してください。メインネットでの変更では実際の資産が使用されます。
</Callout>

## インストールとヘルプの表示

Agave CLI のリリースバンドルには `spl-token` が含まれています。インストールされていない場合は、公開されている Rust クレートを使用してください:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

ルートまたはコマンド単位でヘルプを確認します:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## グローバルオプション

グローバルオプションはコマンドの前に指定します。

| オプション                                       | 用途                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | RPC URL、または `mainnet-beta`、`testnet`、`devnet`、`localhost` を指定します。 |
| `-C, --config <PATH>`                        | 別の Solana CLI 設定ファイルを使用します。                            |
| `--fee-payer <KEYPAIR>`                      | トランザクション手数料を支払うアカウントを指定します。                            |
| `-p, --program-id <ADDRESS>`                 | Token Program ID を明示的に指定して使用します。                                         |
| `--program-2022`                             | Token-2022(`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`)を使用します。           |
| `--output <FORMAT>`                          | サポートされているコマンドで `json` または `json-compact` 形式で出力します。                          |
| `--with-compute-unit-limit <UNITS>`          | トランザクションのコンピュートユニット上限を設定します。                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | コンピュートユニットあたりの優先度価格を設定します。                                  |
| `-v, --verbose`                              | 追加の出力を表示します。                                                   |
| `-V, --version`                              | インストールされている CLI のバージョンを表示します。                                          |

デフォルトのプログラムは元の Token Program です。Token-2022 のミントやアカウントには、読み取り時も含め `--program-2022` を使用してください。選択したプログラムが指定されたアドレスを所有していない場合、コマンドは失敗します。

## トークンの作成と使用

コマンドは作成されたアドレスを出力します。`create-token` が返すミントアドレスは、以降のコマンドで使用するため保存しておいてください。

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

金額はミントの小数桁数に合わせて調整された UI トークン額です。`transfer`、`burn`、`unwrap-sol` などのコマンドでは、ヘルプに記載されている箇所で `ALL` を指定できます。

## Token-2022 ミントの作成

拡張機能は追加のミントまたはアカウント状態を割り当てるため、通常はミントの作成時に選択する必要があります。次の例では、メタデータの埋め込みをサポートする小数点以下 6 桁のミントを作成します:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

`create-token` の一般的な拡張オプションには次のものがあります:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` と `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` または `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` と `--transfer-fee-maximum-fee <AMOUNT>` の併用
- `--ui-amount-multiplier <MULTIPLIER>`

Token-2022 プログラムで併用が許可されている拡張機能のみを組み合わせてください。元に戻せないミント構成を作成する前に、関連する [Token-2022 拡張機能ガイド](/docs/tokens/extensions) を確認してください。

## 権限とデリゲートの管理

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` は、ミント、フリーズ、オーナー、クローズ、および拡張機能固有の権限タイプをサポートします。`--disable` で権限を削除すると、他のプログラムの仕組みで復元できない場合は永続的になります。

## フリーズ、バーン、クローズ

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` はアカウントの残高と総供給量の両方を減らします。`close` はアカウントに残っている lamports を設定された受取先に返しますが、バーンされたトークンは回復されません。

## SOL のラップとアンラップ

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

ラップされた SOL の token account に lamports を直接転送した後は、`sync-native` を使用して、トークン額を基になる lamports に一致させてください。

## マルチシグ署名

最大 11 メンバーの M-of-N Token Program マルチシグを作成します:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

そのマルチシグが管理するトランザクションでは、マルチシグのアドレスを該当する権限として渡し、メンバーの keypair を `--multisig-signer` の値として繰り返し指定します。主要な権限フラグは操作によって異なるため、対象コマンドのヘルプを確認してください。

## コンフィデンシャル残高

コンフィデンシャル残高のコマンドには、コンフィデンシャル転送用に構成された Token-2022 ミントと、構成済みの受取アカウントが必要です。

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

`configure-confidential-transfer-account` と `apply-pending-balance` では、`--address <TOKEN_ACCOUNT_ADDRESS>` か位置引数の `<MINT_ADDRESS>` のどちらか一方を指定します。両方は指定できません。位置引数形式では、オーナーの associated token account が使用されます。入金と出金は常にミントを受け取り、`--address` を指定することでそのデフォルトのアカウントを上書きできます。

`enable-confidential-credits`、`disable-confidential-credits`、`enable-non-confidential-credits`、`disable-non-confidential-credits` を使用して、アカウントが受け入れる入金を制御します。これらの設定はアカウントのプライバシーと支払いの互換性に影響するため、変更する前にアカウントを確認してください。

## 構造化出力とオフライン署名

表示テキストを解析するのではなく、構造化出力を使用してください:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

トランザクションを生成するコマンドは、一般に `--sign-only`、`--blockhash`、`--signer <PUBKEY=SIGNATURE>`、`--nonce`、`--nonce-authority` をサポートしています。必要なオフライン入力は、コマンド、ミントの小数桁数、権限の構成によって異なります。そのため、そのコマンドの `--help` に記載された instructions に従って未署名メッセージを生成し、署名を収集する前にすべてのアドレスを確認してください。
