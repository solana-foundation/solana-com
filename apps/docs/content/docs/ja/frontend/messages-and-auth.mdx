description:
  Solanaウォレットでメッセージに署名し、ユーザーの認証、同意の記録、オフチェーン操作の承認を行います。オフチェーンメッセージ署名を使用し、未対応のウォレット向けにはフォールバックを用意します。
---

メッセージへの署名は、ユーザーがウォレットを管理していることを証明するものです。トランザクションも手数料もネットワーク呼び出しも必要ありません。アプリは署名済みメッセージを、ユーザーのサインイン、利用規約への同意の記録、ウォレットと既存アカウントの紐付け、注文の発注などオフチェーンで行われる操作の承認に使用します。

Solanaウォレットがメッセージに署名する方法は2つあります。

- **オフチェーンメッセージ**(`solana:signOffchainMessage`)は、オフチェーンメッセージ署名(OCMS)の[仕様](https://docs.anza.xyz/proposals/off-chain-message-signing)で定義された標準フォーマットでテキストをラップします。このフォーマットはトランザクションと誤認されることがなく、署名が必要なアカウントを明示します。ハードウェアウォレットが署名するのもこのフォーマットです。
- **生メッセージ**(`solana:signMessage`)は、アプリが渡したバイト列をそのまま署名します。プレフィックスも署名者の宣言もありません。ほとんどのソフトウェアウォレットが対応していますが、バイト列自体にはトランザクションではなくメッセージであることを示すものがありません。

ウォレットが対応している場合はオフチェーンメッセージを使用し、対応していない場合は生メッセージにフォールバックします。このガイドの以降の部分ではサインインを例に説明しますが、署名と検証の手順はどのメッセージにも共通です。

## メッセージフォーマットを選ぶ

|                           | オフチェーンメッセージ     | 生メッセージ   | トランザクション                   |
| ------------------------- | --------------------- | ------------- | ----------------------------- |
| ウォレットの機能            | `signOffchainMessage` | `signMessage` | `signTransaction`             |
| ハードウェアウォレットの対応   | デバイスによる     | いいえ            | はい                           |
| ユーザーが内容を読める      | はい                   | ソフトウェアのみ | デバイスによる             |
| 必要な署名者を宣言 | はい                   | いいえ            | はい                           |
| RPC呼び出しと手数料        | なし                  | なし          | ブロックハッシュ取得、送信、手数料、確認 |

### なぜトランザクションではないのか

以前は、ハードウェアウォレットで読み取り可能なメッセージに署名する方法がありませんでした。そのため多くのアプリは、代わりに何も行わないトランザクションへの署名をユーザーに求めていました。この方法でも動作はしますが、レイテンシ、コスト、リスクが増えます。

- **ネットワーク手数料。** トランザクションは、何も実行しない場合でも手数料がかかります。
- **複数のRPC呼び出し。** アプリはブロックハッシュを取得し、シミュレーションと送信を行い、その後で確認をポーリングします。
- **レイテンシの増加。** これらの呼び出しはそれぞれ往復通信であり、ユーザーがサインインするまでに時間がかかります。
- **読める内容がない。** ユーザーが承認するのはトランザクションのバイト列であり、何に同意するのかを示す文面ではありません。
- **行動面のリスク。** ログインのためだけにトランザクションへの署名を求めると、ユーザーが有害なトランザクションにだまされて署名しやすくなります。

オフチェーンメッセージなら、これらはすべて不要です。往復通信は自社のサーバーとの間だけで済みます。

## ウォレットが署名する内容

オフチェーンメッセージは、固定の署名ドメイン `\xffsolana offchain` で始まります。有効なトランザクションがこのバイト列で始まることはないため、署名済みメッセージをトランザクションとして使用することはできません。バージョン1のフォーマットでは、続いて必要な署名者の一覧と、UTF-8テキストとしてのメッセージ本文が含まれます。長さの上限はありません。

ウォレットはこれらのバイト列を組み立てて署名し、署名とともに返します。レガシーのバージョン0を含むフォーマット全体は、[仕様](https://docs.anza.xyz/proposals/off-chain-message-signing)で説明されています。

## サインイン方法を選ぶ

オフチェーンメッセージにまだ対応していないウォレットもあります。署名を要求する前に、接続中のアカウントの機能を確認し、対応していない場合はフォールバックしてください。

1. アカウントがメッセージバージョン1で `solana:signOffchainMessage` に対応している場合は、オフチェーンメッセージに署名します。
2. 対応していない場合は、同じチャレンジを `solana:signMessage` で署名します。ほとんどのソフトウェアウォレットが対応しています。
3. メッセージ署名に対応していないハードウェアウォレットのユーザーには、「ハードウェアウォレットを使用中」のトグルなど、明示的にオプトインできる手段を用意し、代わりにサインイン用トランザクションに署名してもらいます。デフォルトでこの経路に誘導しないでください。

## ブラウザーでメッセージに署名する

<Tabs items={["Wallet Standard (Kit)", "Wallet Adapter"]}>
  <Tab value="Wallet Standard (Kit)">
    Kitと一緒にWallet Standardのパッケージをインストールします。

    ```terminal
    $ npm install @solana/kit @solana/wallet-standard-features @wallet-standard/ui @wallet-standard/ui-features @wallet-standard/ui-registry
    ```

    これらのヘルパーは `UiWalletAccount` を受け取ります。たとえば、[Reactガイド](/docs/frontend/react-hooks)の `useConnectedWallet` が返す `account` です。

    ```ts title="offchain-message.ts"
    import {
      SolanaSignOffchainMessage,
      type SolanaSignOffchainMessageFeature
    } from "@solana/wallet-standard-features";
    import type { UiWalletAccount } from "@wallet-standard/ui";
    import { getWalletAccountFeature } from "@wallet-standard/ui-features";
    import { getWalletAccountForUiWalletAccount } from "@wallet-standard/ui-registry";

    type OffchainMessageFeature =
      SolanaSignOffchainMessageFeature[typeof SolanaSignOffchainMessage];

    export function supportsOffchainMessages(account: UiWalletAccount) {
      if (!account.features.includes(SolanaSignOffchainMessage)) return false;
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      return feature.supportedMessageVersions.includes(1);
    }

    export async function signOffchainMessage(
      account: UiWalletAccount,
      message: string
    ) {
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      const [output] = await feature.signOffchainMessage({
        messageVersion: 1,
        account: getWalletAccountForUiWalletAccount(account),
        message,
        requiredSigners: [account.publicKey]
      });
      return output;
    }
    ```

  </Tab>

  <Tab value="Wallet Adapter">
    `@solana/wallet-adapter` の `useWallet` は、接続中のアカウントが `solana:signOffchainMessage` に対応している場合にのみ `signOffchainMessage` を公開します。接続中のアカウントを必須署名者としてバージョン1のメッセージに署名し、ウォレットがバージョン1に署名できない場合は `WalletNotReadyError` で拒否されます。

    ```terminal
    $ npm install @solana/web3.js@3 @solana/wallet-adapter
    ```

    ```tsx title="SignOffchainMessage.tsx"
    "use client";

    import { useWallet } from "@solana/wallet-adapter";

    export function SignOffchainMessage({ challenge }: { challenge: string }) {
      const { publicKey, signOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!publicKey || !signOffchainMessage) return;
        const { signature, signedOffchainMessage } =
          await signOffchainMessage(challenge);
        const valid = await publicKey.verifySignature(
          signature,
          signedOffchainMessage
        );
        // Server logic
      };

      return (
        <button onClick={onClick} disabled={!signOffchainMessage}>
          Sign in
        </button>
      );
    }
    ```

    `publicKey.verifySignature` は、署名済みのバイト列に対する署名をブラウザー上で検証します。ただし、そのバイト列が発行したチャレンジと一致するかどうかは、サーバーで確認する必要があります。`signOffchainMessage` が `undefined` の場合は、同じフックの `signMessage` にフォールバックしてください。

  </Tab>
</Tabs>

`signOffchainMessage` は、ウォレットが署名した完全なバイト列である `signedOffchainMessage` と、`signature` を返します。両方をBase64エンコードし、ウォレットアドレスとともにサーバーに送信してください。

チャレンジは、小さな画面でも読みやすいように書いてください。アプリ名とドメインを明記し、署名によって何が行われるかを説明し、サーバーが発行した使い捨てのnonceと発行時刻を含めます。

```text
swap.app wants you to sign in with your Solana account.

Signing in costs nothing and does not submit a transaction.

Nonce: 8f3a1c9e
Issued at: 2026-09-29T17:04:00Z
```

## サーバーで署名を検証する

検証はローカルでの署名チェックであり、RPC接続は不要です。ウォレットが署名したバイト列をデコードし、発行したチャレンジと一致することを確認してから、署名を検証します。

```ts title="verify-sign-in.ts"
import {
  address,
  assertOffchainMessageV1Equal,
  getBase64Encoder,
  getOffchainMessageDecoder,
  verifyOffchainMessageEnvelope,
  type OffchainMessageBytes,
  type SignatureBytes
} from "@solana/kit";

export async function verifySignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signedOffchainMessage: string;
  signature: string;
}) {
  const signer = address(input.walletAddress);
  const base64 = getBase64Encoder();
  const content = base64.encode(
    input.signedOffchainMessage
  ) as OffchainMessageBytes;
  const signature = base64.encode(input.signature) as SignatureBytes;

  const received = getOffchainMessageDecoder().decode(content);
  if (received.version !== 1) {
    throw new Error(`Expected a v1 message, got v${received.version}`);
  }
  assertOffchainMessageV1Equal(received, {
    version: 1,
    requiredSignatories: [{ address: signer }],
    content: input.expectedMessage
  });

  await verifyOffchainMessageEnvelope({
    content,
    signatures: { [signer]: signature }
  });
}
```

`assertOffchainMessageV1Equal` は、内容または署名者が想定と異なる場合にスローします。`verifyOffchainMessageEnvelope` は、署名が存在しない場合や無効な場合にスローします。`expectedMessage` は、クライアントが返してきたコピーを信用せず、サーバー上でnonceをキーにして取得してください。検証に成功したらnonceを消費し、同じ署名で二重にサインインできないようにします。

### 生メッセージを検証する

`signMessage` の署名はチャレンジのバイト列を直接対象とするため、クライアントが送信するのは署名とウォレットアドレスだけで済みます。発行したチャレンジと照合してください。

```ts title="verify-raw-sign-in.ts"
import {
  address,
  getBase64Encoder,
  getPublicKeyFromAddress,
  getUtf8Encoder,
  signatureBytes,
  verifySignature
} from "@solana/kit";

export async function verifyRawSignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signature: string;
}) {
  const publicKey = await getPublicKeyFromAddress(address(input.walletAddress));
  const signature = signatureBytes(getBase64Encoder().encode(input.signature));
  const message = getUtf8Encoder().encode(input.expectedMessage);
  if (!(await verifySignature(publicKey, signature, message))) {
    throw new Error("Invalid signature");
  }
}
```

nonceのルールは同じです。`expectedMessage` をnonceで取得し、検証に成功したら消費します。

<Callout type="info">
  `@solana/kit` は、これらのヘルパーを `@solana/offchain-messages` から再エクスポートしています。サーバーがKitに依存していない場合は、単体のパッケージを使用してください。
</Callout>

## Sign In With Solana

[Sign In With Solana](https://github.com/phantom/sign-in-with-solana)(SIWS)は、チャレンジ自体を標準化します。アプリは `domain`、`statement`、`nonce`、`issuedAt` などの構造化されたフィールドをウォレットの `solana:signIn` 機能に渡します。ウォレットはそれらを標準メッセージに整形し、必要に応じて接続を行い、1ステップで署名します。

`solana:signIn` のバージョン `1.1.0` では、`useOffchainMessage` オプションが追加されました。`useOffchainMessage: { messageVersion: 1 }` を渡すと、ウォレットは署名アカウントのみを必須署名者として、SIWSテキストをバージョン1のオフチェーンメッセージでラップします。ハードウェアウォレットでも表示と署名が可能で、出力には `signedMessageFormat: { kind: "offchainMessage", messageVersion: 1 }` が報告されます。バージョン `1.0.0` を公開しているウォレットはこのオプションを認識しないため、まず機能のバージョンを確認し、該当する場合は省略してください。

<Tabs items={["Wallet Standard", "Wallet Adapter"]}>
  <Tab value="Wallet Standard">
    `solana:signIn` はアカウントの機能ではなくウォレットの機能であるため、これらのヘルパーは `UiWallet` を受け取ります。

    ```ts title="sign-in.ts"
    import {
      SolanaSignIn,
      type SolanaSignInFeature,
      type SolanaSignInInput
    } from "@solana/wallet-standard-features";
    import type { UiWallet } from "@wallet-standard/ui";
    import { getWalletFeature } from "@wallet-standard/ui-features";

    type SignInFeature = SolanaSignInFeature[typeof SolanaSignIn];

    export function supportsOffchainSignIn(wallet: UiWallet) {
      if (!wallet.features.includes(SolanaSignIn)) return false;
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      return feature.version === "1.1.0";
    }

    export async function signIn(wallet: UiWallet, input: SolanaSignInInput) {
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      const [output] = await feature.signIn({
        ...input,
        ...(supportsOffchainSignIn(wallet) && {
          useOffchainMessage: { messageVersion: 1 }
        })
      });
      return output;
    }
    ```

  </Tab>

  <Tab value="Wallet Adapter">
    `useWallet` は、選択したウォレットが `solana:signIn` に対応している場合に `signIn` を公開し、バージョン `1.1.0` を公開している場合は `supportsSignInWithOffchainMessage` も公開します。対応していないウォレットに `useOffchainMessage` を渡すと、`WalletSignInError` で拒否されます。

    ```tsx title="SignIn.tsx"
    "use client";

    import {
      useWallet,
      verifySignIn,
      type SolanaSignInInput
    } from "@solana/wallet-adapter";

    export function SignIn({ input }: { input: SolanaSignInInput }) {
      const { signIn, supportsSignInWithOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!signIn) return;
        const output = await signIn({
          ...input,
          ...(supportsSignInWithOffchainMessage && {
            useOffchainMessage: { messageVersion: 1 }
          })
        });
        const valid = await verifySignIn(input, output);
      };

      return (
        <button onClick={onClick} disabled={!signIn}>
          Sign in with Solana
        </button>
      );
    }
    ```

    `verifySignIn` は、署名済みメッセージが入力のすべてのフィールドを再現していること、および署名アカウントによる有効な署名を持つことを確認します。ウォレットが署名したのがプレーンなSIWSテキストでもオフチェーンメッセージでも同様です。同じチェックをサーバーで実行するには、Reactに依存しない `@solana/wallet-adapter/core` からインポートしてください。

  </Tab>
</Tabs>

入力はサーバーで構築し、使い捨ての `nonce` と `issuedAt` の時刻を含めて、nonceをキーにしたコピーを保持してください。サインインの検証に成功したら、nonceを消費します。

Wallet Adapterを使用しない場合、`@solana/wallet-standard-util` の `verifySignIn` が検証できるのはプレーンなSIWSの出力のみです。`signedMessageFormat` がオフチェーンメッセージを報告している場合、`signedMessage` は、SIWSテキストを内容とするオフチェーンメッセージです。保存しておいた入力と署名アドレスから、`@solana/wallet-standard-util` の `createSignInMessageText` を使って想定されるテキストを再構築し、[サーバーで署名を検証する](#verify-the-signature-on-your-server)と同様に、他のオフチェーンメッセージと同じ方法で検証してください。Kitでのこのフローについては、[`@solana/offchain-messages` のREADME](https://github.com/anza-xyz/kit/tree/main/packages/offchain-messages#verifying-a-signed-offchain-message)で説明されています。

## ウォレット開発者向け

ウォレットは、`@solana/wallet-standard-features` の Wallet Standard 機能 `solana:signOffchainMessage` を実装することで対応します。

- `version: "1.0.0"` を報告し、署名可能なメッセージバージョンを `supportedMessageVersions` に列挙してください。現時点では `[1]` です。
- `requiredSigners` をソートして重複をチェックし、そこからバージョン1のプリアンブルを構築します。アカウントが必須署名者に含まれていない場合は、リクエストを拒否してください。
- 署名の前に、ハードウェアデバイス上も含めて、メッセージテキストの全文をユーザーに表示してください。
- 署名した正確なバイト列を、Ed25519の `signature` とともに `signedOffchainMessage` として返します。
- オフチェーンでの Sign In With Solana に対応するには、`solana:signIn` に対して `version: "1.1.0"` を報告します。入力に `useOffchainMessage` が含まれている場合は、SIWS のテキストをバージョン1のオフチェーンメッセージとして署名し、そのバイト列を `signedMessage` として返し、`signedMessageFormat` を設定します。
- `solana:signMessage` のサポートは引き続き維持してください。この機能に変更はなく、アプリは今でもフォールバックとして使用しています。
