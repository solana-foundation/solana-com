description:
  Solanaウォレットでメッセージに署名し、ユーザーの認証、同意の記録、オフチェーンアクションの承認を行います。オフチェーンメッセージ署名を使用し、未対応のウォレット向けにフォールバックも用意します。
---

メッセージに署名すると、ユーザーがウォレットを管理していることを証明できます。トランザクションも手数料もネットワーク呼び出しも不要です。アプリでは、署名済みメッセージを、ユーザーのサインイン、利用規約への同意の記録、ウォレットと既存アカウントの紐付け、注文の送信などオフチェーンで行われるアクションの承認に使用します。

Solanaウォレットがメッセージに署名する方法は2つあります。

- **オフチェーンメッセージ**(`solana:signOffchainMessage`)は、テキストをオフチェーンメッセージ署名(OCMS)の[仕様](https://docs.anza.xyz/proposals/off-chain-message-signing)で定められた標準フォーマットで包みます。このフォーマットはトランザクションと誤認されることがなく、署名が必要なアカウントを明示し、ハードウェアウォレットが署名する形式でもあります。
- **生メッセージ**(`solana:signMessage`)は、アプリが渡したバイト列を、プレフィックスや署名者の宣言なしでそのまま署名します。ほとんどのソフトウェアウォレットが対応していますが、バイト列自体には、トランザクションではなくメッセージであることを示すものがありません。

ウォレットが対応している場合はオフチェーンメッセージを使用し、対応していない場合は生メッセージにフォールバックします。このガイドの以降の部分ではサインインを例に説明しますが、署名と検証の手順はどのメッセージにも共通です。

## メッセージフォーマットを選ぶ

|                           | オフチェーンメッセージ     | 生メッセージ   | トランザクション                   |
| ------------------------- | --------------------- | ------------- | ----------------------------- |
| ウォレット機能            | `signOffchainMessage` | `signMessage` | `signTransaction`             |
| ハードウェアウォレット対応   | デバイスによる     | いいえ            | はい                           |
| ユーザーが内容を読める      | はい                   | ソフトウェアウォレットのみ | デバイスによる             |
| 必要な署名者を宣言 | はい                   | いいえ            | はい                           |
| RPC呼び出しと手数料        | なし                  | なし          | ブロックハッシュ取得、送信、手数料、確認 |

### なぜトランザクションではないのか?

ハードウェアウォレットには、かつて読み取り可能なメッセージに署名する手段がありませんでした。そのため多くのアプリは、代わりに何も実行しないトランザクションへの署名をこれらのユーザーに求めていました。この方法でも機能しますが、レイテンシ、コスト、リスクが増えます。

- **ネットワーク手数料。** トランザクションは、何も実行しない場合でも手数料がかかります。
- **複数のRPC呼び出し。** アプリはブロックハッシュを取得し、シミュレーションと送信を行い、その後ポーリングで承認を確認します。
- **レイテンシの増加。** これらの呼び出しはそれぞれ往復通信となり、ユーザーがサインインするまでの時間が延びます。
- **内容が読めない。** ユーザーが承認するのはトランザクションのバイト列であり、何に同意しようとしているのかを示す文言ではありません。
- **行動面のリスク。** ログインのためだけにトランザクションへの署名を求めると、有害なトランザクションにも署名するよう騙されやすくなります。

オフチェーンメッセージなら、これらはすべて不要です。往復通信は自社のサーバーとの間だけです。

## ウォレットが署名する内容

オフチェーンメッセージは、固定の署名ドメイン `\xffsolana offchain` で始まります。有効なトランザクションがこのバイト列で始まることはないため、署名済みメッセージがトランザクションとして使われることはありません。フォーマットのバージョン1では、続けて必要な署名者を列挙し、メッセージを長さ制限のないUTF-8テキストとして格納します。

ウォレットはこれらのバイト列を構築して署名し、署名とともに返します。レガシーのバージョン0を含むフォーマット全体については、[仕様](https://docs.anza.xyz/proposals/off-chain-message-signing)を参照してください。

## サインイン方式を選ぶ

すべてのウォレットがオフチェーンメッセージに対応しているわけではありません。署名を求める前に接続中のアカウントの機能を確認し、機能がない場合はフォールバックします。

1. アカウントがメッセージバージョン1の `solana:signOffchainMessage` に対応している場合は、オフチェーンメッセージに署名します。
2. そうでない場合は、同じチャレンジを `solana:signMessage` で署名します。ほとんどのソフトウェアウォレットが対応しています。
3. メッセージ署名に対応していないハードウェアウォレットのユーザーには、「ハードウェアウォレットを使用しています」というトグルなど明示的なオプトインを用意し、代わりにサインイン用トランザクションに署名してもらいます。デフォルトでこの方法に誘導しないでください。

## ブラウザでメッセージに署名する

<Tabs items={["Wallet Standard (Kit)", "Wallet Adapter"]}>
  <Tab value="Wallet Standard (Kit)">
    Kitと併せてWallet Standardパッケージをインストールします。

    ```terminal
    $ npm install @solana/kit @solana/wallet-standard-features @wallet-standard/ui @wallet-standard/ui-features @wallet-standard/ui-registry
    ```

    これらのヘルパーは `UiWalletAccount` を受け取ります。たとえば、[Reactガイド](/docs/frontend/react-hooks)の `useConnectedWallet` が返す `account` です。

    ```ts title="offchain-message.ts"
    import {
      SolanaSignOffchainMessage,
      type SolanaSignOffchainMessageFeature
    } from "@solana/wallet-standard-features";
    import type { UiWalletAccount } from "@wallet-standard/ui";
    import { getWalletAccountFeature } from "@wallet-standard/ui-features";
    import { getWalletAccountForUiWalletAccount } from "@wallet-standard/ui-registry";

    type OffchainMessageFeature =
      SolanaSignOffchainMessageFeature[typeof SolanaSignOffchainMessage];

    export function supportsOffchainMessages(account: UiWalletAccount) {
      if (!account.features.includes(SolanaSignOffchainMessage)) return false;
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      return feature.supportedMessageVersions.includes(1);
    }

    export async function signOffchainMessage(
      account: UiWalletAccount,
      message: string
    ) {
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      const [output] = await feature.signOffchainMessage({
        messageVersion: 1,
        account: getWalletAccountForUiWalletAccount(account),
        message,
        requiredSigners: [account.publicKey]
      });
      return output;
    }
    ```

  </Tab>

  <Tab value="Wallet Adapter">
    `@solana/wallet-adapter` の `useWallet` は、接続中のアカウントが `solana:signOffchainMessage` に対応している場合にのみ `signOffchainMessage` を公開します。接続中のアカウントを必要な署名者としてバージョン1のメッセージに署名し、ウォレットがバージョン1に署名できない場合は `WalletNotReadyError` で拒否されます。

    ```terminal
    $ npm install @solana/web3.js@3 @solana/wallet-adapter
    ```

    ```tsx title="SignOffchainMessage.tsx"
    "use client";

    import { useWallet } from "@solana/wallet-adapter";

    export function SignOffchainMessage({ challenge }: { challenge: string }) {
      const { publicKey, signOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!publicKey || !signOffchainMessage) return;
        const { signature, signedOffchainMessage } =
          await signOffchainMessage(challenge);
        const valid = await publicKey.verifySignature(
          signature,
          signedOffchainMessage
        );
        // Server logic
      };

      return (
        <button onClick={onClick} disabled={!signOffchainMessage}>
          Sign in
        </button>
      );
    }
    ```

    `publicKey.verifySignature` は、署名されたバイト列に対する署名をブラウザ内で検証します。それらのバイト列が発行したチャレンジであることは、サーバー側で別途確認する必要があります。`signOffchainMessage` が `undefined` の場合は、同じフックの `signMessage` にフォールバックします。

  </Tab>
</Tabs>

`signOffchainMessage` は、ウォレットが署名した完全なバイト列である `signedOffchainMessage` と、`signature` を返します。両方をBase64エンコードし、ウォレットアドレスとともにサーバーに送信します。

小さな画面でも読みやすいように、チャレンジを書きます。アプリ名とドメイン、署名によって何が行われるかを記載し、サーバーが発行した使い捨てのnonceと発行時刻を含めます。

```text
swap.app wants you to sign in with your Solana account.

Signing in costs nothing and does not submit a transaction.

Nonce: 8f3a1c9e
Issued at: 2026-09-29T17:04:00Z
```

## サーバーで署名を検証する

検証はローカルでの署名チェックであり、RPC接続は不要です。ウォレットが署名したバイト列をデコードし、発行したチャレンジと一致することを確認してから、署名を検証します。

```ts title="verify-sign-in.ts"
import {
  address,
  assertOffchainMessageV1Equal,
  getBase64Encoder,
  getOffchainMessageDecoder,
  verifyOffchainMessageEnvelope,
  type OffchainMessageBytes,
  type SignatureBytes
} from "@solana/kit";

export async function verifySignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signedOffchainMessage: string;
  signature: string;
}) {
  const signer = address(input.walletAddress);
  const base64 = getBase64Encoder();
  const content = base64.encode(
    input.signedOffchainMessage
  ) as OffchainMessageBytes;
  const signature = base64.encode(input.signature) as SignatureBytes;

  const received = getOffchainMessageDecoder().decode(content);
  if (received.version !== 1) {
    throw new Error(`Expected a v1 message, got v${received.version}`);
  }
  assertOffchainMessageV1Equal(received, {
    version: 1,
    requiredSignatories: [{ address: signer }],
    content: input.expectedMessage
  });

  await verifyOffchainMessageEnvelope({
    content,
    signatures: { [signer]: signature }
  });
}
```

`assertOffchainMessageV1Equal` は、内容または署名者が想定と異なる場合にスローします。`verifyOffchainMessageEnvelope` は、署名がない、または無効な場合にスローします。`expectedMessage` は、クライアントが返してきたコピーを信用せず、サーバー側でnonceをキーにして取得してください。検証に成功したらnonceを消費し、同じ署名で二度サインインできないようにします。

### 生メッセージを検証する

`signMessage` の署名はチャレンジのバイト列を直接対象とするため、クライアントが送る必要があるのは署名とウォレットアドレスだけです。発行したチャレンジと照合して確認します。

```ts title="verify-raw-sign-in.ts"
import {
  address,
  getBase64Encoder,
  getPublicKeyFromAddress,
  getUtf8Encoder,
  signatureBytes,
  verifySignature
} from "@solana/kit";

export async function verifyRawSignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signature: string;
}) {
  const publicKey = await getPublicKeyFromAddress(address(input.walletAddress));
  const signature = signatureBytes(getBase64Encoder().encode(input.signature));
  const message = getUtf8Encoder().encode(input.expectedMessage);
  if (!(await verifySignature(publicKey, signature, message))) {
    throw new Error("Invalid signature");
  }
}
```

nonceのルールは同じです。`expectedMessage` をnonceで取得し、検証に成功したら消費します。

<Callout type="info">
  `@solana/kit` は、これらのヘルパーを `@solana/offchain-messages` から再エクスポートしています。サーバーがKitに依存していない場合は、単体のパッケージを使用してください。
</Callout>

## Sign In With Solana

[Sign In With Solana](https://github.com/phantom/sign-in-with-solana)(SIWS)は、チャレンジそのものを標準化します。アプリは `domain`、`statement`、`nonce`、`issuedAt` などの構造化されたフィールドをウォレットの `solana:signIn` 機能に渡します。ウォレットはそれらを標準メッセージに整形し、必要に応じて接続したうえで、1ステップで署名します。

`solana:signIn` のバージョン `1.1.0` では、`useOffchainMessage` オプションが追加されました。`useOffchainMessage: { messageVersion: 1 }` を渡すと、ウォレットはSIWSテキストを、署名アカウントのみを必要な署名者とするバージョン1のオフチェーンメッセージで包みます。ハードウェアウォレットでも表示と署名が可能で、出力では `signedMessageFormat: { kind: "offchainMessage", messageVersion: 1 }` が報告されます。バージョン `1.0.0` を宣言しているウォレットはこのオプションを認識しないため、まず機能のバージョンを確認し、該当しない場合は省略してください。

<Tabs items={["Wallet Standard", "Wallet Adapter"]}>
  <Tab value="Wallet Standard">
    `solana:signIn` はアカウントの機能ではなくウォレットの機能であるため、これらのヘルパーは `UiWallet` を受け取ります。

    ```ts title="sign-in.ts"
    import {
      SolanaSignIn,
      type SolanaSignInFeature,
      type SolanaSignInInput
    } from "@solana/wallet-standard-features";
    import type { UiWallet } from "@wallet-standard/ui";
    import { getWalletFeature } from "@wallet-standard/ui-features";

    type SignInFeature = SolanaSignInFeature[typeof SolanaSignIn];

    export function supportsOffchainSignIn(wallet: UiWallet) {
      if (!wallet.features.includes(SolanaSignIn)) return false;
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      return feature.version === "1.1.0";
    }

    export async function signIn(wallet: UiWallet, input: SolanaSignInInput) {
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      const [output] = await feature.signIn({
        ...input,
        ...(supportsOffchainSignIn(wallet) && {
          useOffchainMessage: { messageVersion: 1 }
        })
      });
      return output;
    }
    ```

  </Tab>

  <Tab value="Wallet Adapter">
    `useWallet` は、選択中のウォレットが `solana:signIn` に対応している場合に `signIn` を公開し、バージョン `1.1.0` を宣言している場合に `supportsSignInWithOffchainMessage` を公開します。`useOffchainMessage` を未対応のウォレットに渡すと、`WalletSignInError` で拒否されます。

    ```tsx title="SignIn.tsx"
    "use client";

    import {
      useWallet,
      verifySignIn,
      type SolanaSignInInput
    } from "@solana/wallet-adapter";

    export function SignIn({ input }: { input: SolanaSignInInput }) {
      const { signIn, supportsSignInWithOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!signIn) return;
        const output = await signIn({
          ...input,
          ...(supportsSignInWithOffchainMessage && {
            useOffchainMessage: { messageVersion: 1 }
          })
        });
        const valid = await verifySignIn(input, output);
      };

      return (
        <button onClick={onClick} disabled={!signIn}>
          Sign in with Solana
        </button>
      );
    }
    ```

    `verifySignIn` は、署名されたメッセージが入力のすべてのフィールドを再現していること、および署名アカウントによる有効な署名が付いていることを、ウォレットが通常のSIWSテキストに署名した場合でもオフチェーンメッセージに署名した場合でも検証します。同じチェックは、Reactに依存しない `@solana/wallet-adapter/core` からインポートすることで、サーバー側でも実行できます。

  </Tab>
</Tabs>

入力はサーバーで、使い捨ての `nonce` と `issuedAt` の時刻を付けて構築し、nonceをキーにしたコピーを保持します。サインインの検証に成功したら、nonceを消費します。

Wallet Adapterを使わない場合、`@solana/wallet-standard-util` の `verifySignIn` は通常のSIWS出力のみを検証します。`signedMessageFormat` がオフチェーンメッセージを示している場合、`signedMessage` は内容がSIWSテキストであるオフチェーンメッセージです。保存しておいた入力と署名アドレスから、`@solana/wallet-standard-util` の `createSignInMessageText` を使って想定テキストを再構築し、[サーバーで署名を検証する](#verify-the-signature-on-your-server)と同様に、他のオフチェーンメッセージと同じ方法で検証します。Kitでのこのフローについては、[`@solana/offchain-messages` のREADME](https://github.com/anza-xyz/kit/tree/main/packages/offchain-messages#verifying-a-signed-offchain-message)を参照してください。

## ウォレット開発者向け

ウォレットは、`@solana/wallet-standard-features` の Wallet Standard 機能である `solana:signOffchainMessage` を実装することで対応できます。

- `version: "1.0.0"` を報告し、署名可能なメッセージバージョンを `supportedMessageVersions` に列挙します。現時点では `[1]` です。
- `requiredSigners` からバージョン1のプリアンブルを構築します。その際、`requiredSigners` をソートし、重複がないかを確認してください。アカウントが必須署名者に含まれていない場合は、リクエストを拒否します。
- 署名する前に、ハードウェアデバイス上も含め、メッセージのテキスト全体をユーザーに表示してください。
- 署名したバイト列をそのまま `signedOffchainMessage` として、Ed25519 の `signature` とともに返します。
- オフチェーンでの Sign In With Solana をサポートするには、`solana:signIn` に対して `version: "1.1.0"` を報告します。入力に `useOffchainMessage` が含まれている場合は、SIWS テキストをバージョン1のオフチェーンメッセージとして署名し、そのバイト列を `signedMessage` として返したうえで、`signedMessageFormat` を設定してください。
- `solana:signMessage` のサポートは引き続き維持してください。この機能は変更されておらず、アプリは今でもフォールバックとして使用しています。
