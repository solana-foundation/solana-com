Sieben Konzepte bilden das Fundament der Solana-Entwicklung. Beginne mit Konten
und Programmen, und verfolge dann, wie  Anweisungen zu Transaktionen werden. PDAs, CPIs und
Fee bauen auf diesem Ausführungsmodell auf.

<DocsDiagram
  src="/assets/docs/diagrams/core-concepts.svg"
  alt="Solana core concepts, ordered from accounts and programs through instructions and transactions, with PDAs, CPIs, and fees"
/>

<Cards>
  <Card title="Konten" href="/docs/core/accounts">
    Solana speichert den gesamten Zustand in Konten, einem Key-Value-Speicher mit 32-Byte-
    Adressen als Schlüssel. Jedes Konto hat fünf Felder: lamports, data, owner, executable
    und rent_epoch.
  </Card>
  <Card title="Programme" href="/docs/core/programs">
    Solanas Smart Contracts, kompiliert nach sBPF. Programme sind zustandslos und der
    gesamte veränderliche Zustand liegt in separaten Datenkonten, die über  Anweisungen übergeben werden.
  </Card>
  <Card title=" Anweisungen" href="/docs/core/instructions">
    Eine Anfrage zur Ausführung eines Programms, bestehend aus einer Programm-ID, einer Kontenliste
    und opaken Datenbytes. Mehrere  Anweisungen werden zu einer einzigen
    Transaktion zusammengefasst.
  </Card>
  <Card title="Transaktionen" href="/docs/core/transactions">
    Die atomare Ausführungseinheit auf Solana. Enthält Signaturen und eine Nachricht
    (Kontoadressen, aktuellen Blockhash und kompilierte  Anweisungen). Max. 1232
    Bytes, oder 4096 mit dem v1-Format.
  </Card>
  <Card title="Fee" href="/docs/core/fees">
    Grundgebühr von 5.000 lamports pro Signatur, zuzüglich einer optionalen priority fee
    basierend auf den angeforderten Compute Units. Max. 1,4 Mio. Compute Units pro Transaktion.
  </Card>
  <Card title="Program Derived Addresses (PDAs)" href="/docs/core/pda">
    Deterministische Adressen, die aus einer Programm-ID und Seeds abgeleitet werden. Nur das
    besitzende Programm kann im Auftrag einer PDA über invoke_signed signieren.
  </Card>
  <Card title="Cross-Program Invocations (CPIs)" href="/docs/core/cpi">
    Ein Programm ruft ein anderes über invoke oder invoke_signed auf. Signer- und Schreibrechte
    werden auf den Aufgerufenen übertragen. Maximale Anweisungs-Stack-Tiefe von 5 (oberste Ebene
    plus CPIs).
  </Card>
</Cards>
