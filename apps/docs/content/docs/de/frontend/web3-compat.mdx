Wenn Sie von `@solana/web3.js` (Legacy), `@solana/wallet-adapter-*`
oder den früheren Framework-Kit-Paketen (`@solana/client`, `@solana/react-hooks`,
`@solana/web3-compat`) kommen, empfehlen wir die Migration zu `@solana/kit`-Plugins oder
`@solana/web3.js` v3 (oder höher).

Diese Seite ordnet die Konzepte, die Sie bereits kennen, ihren Kit-Entsprechungen zu.

## Konzept-Mapping

| web3.js (Legacy) / wallet-adapter      | Kit                                                                  |
| -------------------------------------- | -------------------------------------------------------------------- |
| `new Connection(url)`                  | `createSolanaRpc(url)`, oder `.use(solanaRpc({ rpcUrl }))` auf einem Client |
| `PublicKey`                            | `Address` — String umwandeln mit `address("...")`                    |
| `Keypair`                              | `generateKeyPairSigner()` oder die `@solana/kit-plugin-signer`-Plugins |
| `SystemProgram.transfer(...)`          | `getTransferSolInstruction(...)` aus `@solana-program/system`       |
| `LAMPORTS_PER_SOL`-Arithmetik                | `lamports(...)` aus `@solana/kit`                                   |
| `Transaction` / `VersionedTransaction` | Transaktionsnachrichten, die vom Transaction Planner erstellt und verpackt werden     |
| `sendAndConfirmTransaction(...)`       | `client.sendTransaction([...])` (Planner signiert, sendet und bestätigt) |
| `@solana/wallet-adapter-*`             | `@solana/kit-plugin-wallet` + Wallet Standard Discovery              |

web3.js v3 behält die oben genannten klassenbasierten Namen – `Connection`, `Keypair`,
`Transaction`, `PublicKey` – als dünne Wrapper über den Kit-Interna bei, sodass die Kit-
Spalte auch beschreibt, was diese Klassen in v3 im Hintergrund tun.

## Von web3.js migrieren?

Wenn Sie eine große `@solana/web3.js`-(Legacy-)Codebasis pflegen und ein vollständiges Rewrite
zu Kit nicht praktikabel ist, ist web3.js v3 die Brücke. Installieren Sie es mit
`@solana/web3.js@3`. Es baut die klassische klassenbasierte API – `Connection`,
`Keypair`, `Transaction`, `PublicKey` – auf den Interna von `@solana/kit` neu auf.
Da es auf Kit aufsetzt, ist die Interoperabilität eng: `PublicKey` ist der primäre Adresstyp,
und dessen `.toBase58()` gibt Kits „Branded“ `Address`-String zurück, und ein v3-`Keypair`
implementiert Kits `KeyPairSigner`, sodass Sie es direkt an Kit-
APIs, Plugins und mit Codama generierte Clients übergeben können.

<Callout type="warn" title="v1-Transaktionen und web3.js (Legacy)">
  Wenn Sie v1-Transaktionen mit web3.js senden, müssen Sie v3 oder höher verwenden.
</Callout>

Für die Migration selbst finden Sie den offiziellen
[Migrationsleitfaden von web3.js v1 auf v3](https://github.com/solana-foundation/solana-web3.js/blob/main/docs/web3js-v1-to-v3-migration.md).

## Wallets

Kit verwendet keinen wallet-adapter. `@solana/kit-plugin-wallet` erkennt Wallet
Standard-Wallets und stellt sie über `client.wallet` sowie die
[React-Hooks](/docs/frontend/react-hooks) bereit. Moderne Wallets (Phantom,
Solflare, Backpack und andere) melden sich selbst über den Wallet Standard an,
sodass kein wallet-spezifisches Adapter-Paket erforderlich ist.

Sie können auch vorgefertigte Tools wie
[@solana/connector](https://www.npmjs.com/package/@solana/connector) verwenden,
das Kit-Primitive direkt zur Verbindung mit Wallets nutzt.

<Callout type="info" title="Noch auf wallet-adapter?">
  Wenn Sie eine App pflegen, die auf `@solana/wallet-adapter-*` basiert und noch
  nicht zur Migration bereit sind, bleibt das [wallet-adapter
  Repository](https://github.com/anza-xyz/wallet-adapter) die Referenz für
  diesen Stack. Für alle Neuentwicklungen empfehlen wir das Kit-Wallet-Plugin.
</Callout>
