Die `spl-token`-Befehlszeilenschnittstelle erstellt und verwaltet Mints, token accounts,
Berechtigungen, Transfers und Token-2022-Erweiterungen.

Diese Referenz folgt
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
der in Agave v4.2.1 enthaltenen Version. Führen Sie `spl-token --version` aus und verwenden Sie
`<command> --help`, um die genauen Optionen Ihrer installierten Version zu sehen.

<Callout type="warn">
  Mint-Erstellung, Transfers, Berechtigungsänderungen, Burns, Freezes und das Schließen von Konten
  übermitteln Transaktionen. Bestätigen Sie Cluster, Token Program, Signer und
  Adressen, bevor Sie einen Befehl ausführen. Änderungen im Mainnet betreffen echte Vermögenswerte.
</Callout>

## Installation und Hilfe

Das Agave-CLI-Release-Bundle enthält `spl-token`. Falls es nicht installiert ist, verwenden Sie
das veröffentlichte Rust-Crate:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Hilfe auf Root- oder Befehlsebene anzeigen:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Globale Optionen

Platzieren Sie globale Optionen vor dem Befehl.

| Option                                       | Zweck                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Wählt eine RPC-URL oder `mainnet-beta`, `testnet`, `devnet` oder `localhost` aus. |
| `-C, --config <PATH>`                        | Verwendet eine andere Solana-CLI-Konfigurationsdatei.                            |
| `--fee-payer <KEYPAIR>`                      | Wählt unter den Konten dasjenige aus, das die Transaktions-Fee zahlt.                            |
| `-p, --program-id <ADDRESS>`                 | Verwendet eine explizite Token-Program-ID.                                         |
| `--program-2022`                             | Verwendet Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Gibt `json` oder `json-compact` zurück, sofern unterstützt.                          |
| `--with-compute-unit-limit <UNITS>`          | Legt das Compute-Unit-Limit der Transaktion fest.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Legt den Prioritätspreis pro Compute Unit fest.                                  |
| `-v, --verbose`                              | Zeigt zusätzliche Ausgaben an.                                                   |
| `-V, --version`                              | Gibt die installierte CLI-Version aus.                                          |

Das Standardprogramm ist das ursprüngliche Token Program. Verwenden Sie `--program-2022` für
Token-2022-Mints oder -Konten, auch beim Lesen. Ein Befehl schlägt fehl, wenn das
ausgewählte Programm nicht Eigentümer der angegebenen Adresse ist.

## Token erstellen und verwenden

Die Befehle geben die erstellten Adressen aus. Speichern Sie die von
`create-token` zurückgegebene Mint-Adresse für die folgenden Befehle.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Beträge sind UI-Token-Beträge, angepasst an die Dezimalstellen des Mints. Befehle wie
`transfer`, `burn` und `unwrap-sol` akzeptieren `ALL`, wo es in ihrer Hilfe angegeben ist.

## Token-2022-Mint erstellen

Erweiterungen reservieren zusätzlichen Zustand für Mints oder Konten und müssen in der Regel bei der
Erstellung des Mints gewählt werden. Dieses Beispiel erstellt einen Mint mit sechs Dezimalstellen und
integrierter Metadaten-Unterstützung:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Gängige `create-token`-Erweiterungsoptionen sind:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` und `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` oder `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` mit
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Kombinieren Sie nur Erweiterungen, die das Token-2022-Programm gemeinsam zulässt. Prüfen Sie vor dem Erstellen
einer unumkehrbaren Mint-Konfiguration den relevanten [Token-2022-Erweiterungsleitfaden](/docs/tokens/extensions).

## Berechtigungen und Delegates verwalten

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` unterstützt Mint-, Freeze-, Owner-, Close- und erweiterungsspezifische
Berechtigungstypen. Das Entfernen einer Berechtigung mit `--disable` ist dauerhaft, wenn kein
anderer Programmmechanismus sie wiederherstellen kann.

## Einfrieren, Burn und Schließen

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` verringert sowohl das Guthaben auf Konten als auch den Gesamtbestand. `close` gibt die
verbleibenden lamports der Konten an den konfigurierten Empfänger zurück; es stellt keine
verbrannten Tokens wieder her.

## SOL wrappen und unwrappen

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Verwenden Sie `sync-native`, nachdem Sie lamports direkt auf ein wrapped-SOL-token account
überwiesen haben, damit dessen Token-Betrag den zugrunde liegenden lamports entspricht.

## Multisig-Signierung

Erstellen Sie eine M-of-N-Token-Program-Multisig mit bis zu 11 Mitgliedern:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

Übergeben Sie für eine von dieser Multisig kontrollierte Transaktion die Multisig-Adresse als die
relevante Berechtigung und geben Sie die Mitglieds-keypairs über wiederholte
`--multisig-signer`-Werte an. Prüfen Sie die Hilfe des Zielbefehls, da sich dessen primäres
Berechtigungs-Flag je nach Operation unterscheidet.

## Vertrauliche Guthaben

Befehle für vertrauliche Guthaben erfordern einen für vertrauliche Transfers konfigurierten
Token-2022-Mint und konfigurierte Empfänger-Konten.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Übergeben Sie für `configure-confidential-transfer-account` und `apply-pending-balance`
entweder `--address <TOKEN_ACCOUNT_ADDRESS>` oder eine positionale `<MINT_ADDRESS>`, aber nicht
beides. Die positionale Form verwendet das associated token account des Owners. Einzahlung und
Auszahlung nehmen immer den Mint entgegen und akzeptieren `--address`, um dieses Standard-token account zu überschreiben.

Verwenden Sie `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits` und `disable-non-confidential-credits`, um zu steuern,
welche Einzahlungen die Konten akzeptieren. Diese Einstellungen beeinflussen den Datenschutz und die
Zahlungskompatibilität der Konten; prüfen Sie die Konten, bevor Sie sie ändern.

## Strukturierte und Offline-Signierung

Verwenden Sie strukturierte Ausgabe, anstatt Anzeigetext zu parsen:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Befehle, die Transaktionen erzeugen, unterstützen häufig `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce` und `--nonce-authority`. Die genauen
Offline-Eingaben hängen vom Befehl, den Dezimalstellen des Mints und der Berechtigungsstruktur ab.
Erzeugen Sie daher die unsignierte Nachricht gemäß den Anweisungen in der `--help` des jeweiligen Befehls und
prüfen Sie jede Adresse, bevor Sie Signaturen einholen.
