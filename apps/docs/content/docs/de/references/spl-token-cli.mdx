Die `spl-token`-Befehlszeilenschnittstelle erstellt und verwaltet Mints, token accounts,
Autoritäten, Transfers und Token-2022-Erweiterungen.

Diese Referenz folgt
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
der mit Agave v4.2.1 gebündelten Version. Führe `spl-token --version` aus und nutze
`<command> --help`, um die genauen Optionen deiner installierten Version zu sehen.

<Callout type="warn">
  Mint-Erstellung, Transfers, Autoritätsänderungen, Burns, Freezes und das Schließen von Konten
  senden Transaktionen. Bestätige vor dem Ausführen eines Befehls Cluster, Token Program, Signer und
  Adressen. Änderungen im Mainnet betreffen echte Assets.
</Callout>

## Installation und Hilfe

Das Agave-CLI-Release-Bundle enthält `spl-token`. Falls es nicht installiert ist, verwende
das veröffentlichte Rust-Crate:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Rufe die Hilfe auf Root- oder Befehlsebene auf:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Globale Optionen

Platziere globale Optionen vor dem Befehl.

| Option                                       | Zweck                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Wähle eine RPC-URL oder `mainnet-beta`, `testnet`, `devnet` oder `localhost` aus. |
| `-C, --config <PATH>`                        | Verwende eine andere Solana-CLI-Konfigurationsdatei.                            |
| `--fee-payer <KEYPAIR>`                      | Wähle das Konto aus, das die Transaktions-Fee zahlt.                            |
| `-p, --program-id <ADDRESS>`                 | Verwende eine explizite Token-Program-ID.                                         |
| `--program-2022`                             | Verwende Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Gib `json` oder `json-compact` zurück, sofern unterstützt.                          |
| `--with-compute-unit-limit <UNITS>`          | Lege das Compute-Unit-Limit der Transaktion fest.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Lege den Prioritätspreis pro Compute Unit fest.                                  |
| `-v, --verbose`                              | Zeige zusätzliche Ausgaben an.                                                   |
| `-V, --version`                              | Gib die installierte CLI-Version aus.                                          |

Das Standardprogramm ist das ursprüngliche Token Program. Verwende `--program-2022` für einen
Token-2022-Mint oder ein Token-2022-Konto, auch beim Lesen. Ein Befehl schlägt fehl, wenn das
ausgewählte Programm die angegebene Adresse nicht besitzt.

## Token erstellen und verwenden

Die Befehle geben die erstellten Adressen aus. Speichere die von
`create-token` zurückgegebene Mint-Adresse für die folgenden Befehle.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Beträge sind UI-Token-Beträge, angepasst an die Dezimalstellen des Mints. Befehle wie
`transfer`, `burn` und `unwrap-sol` akzeptieren `ALL`, wo es in ihrer Hilfe angegeben ist.

## Einen Token-2022-Mint erstellen

Erweiterungen belegen zusätzlichen Mint- oder Kontozustand und müssen in der Regel bei der
Erstellung des Mints ausgewählt werden. Dieses Beispiel erstellt einen Mint mit sechs
Dezimalstellen und Unterstützung für eingebettete Metadaten:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Gängige Erweiterungsoptionen von `create-token` sind:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` und `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` oder `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` mit
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Kombiniere nur Erweiterungen, die das Token-2022-Programm gemeinsam zulässt. Lies vor dem
Erstellen einer unumkehrbaren Mint-Konfiguration die entsprechende
[Token-2022-Erweiterungsanleitung](/docs/tokens/extensions).

## Autoritäten und Delegates verwalten

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` unterstützt Mint-, Freeze-, Owner-, Close- und erweiterungsspezifische
Autoritätstypen. Das Entfernen einer Autorität mit `--disable` ist dauerhaft, sofern kein
anderer Programmmechanismus sie wiederherstellen kann.

## Einfrieren, Verbrennen und Schließen

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` verringert sowohl den Kontostand als auch die Gesamtmenge (Total Supply). `close` gibt die
verbleibenden lamports des Kontos an den konfigurierten Empfänger zurück; verbrannte
Token werden dadurch nicht wiederhergestellt.

## SOL wrappen und unwrappen

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Verwende `sync-native`, nachdem du lamports direkt auf ein gewrapptes SOL-token account
übertragen hast, damit der Token-Betrag mit den zugrunde liegenden lamports übereinstimmt.

## Multisig-Signierung

Erstelle ein M-of-N-Multisig des Token Program mit bis zu 11 Mitgliedern:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

Übergib bei einer von diesem Multisig kontrollierten Transaktion die Multisig-Adresse als
relevante Autorität und gib die keypairs der Mitglieder über wiederholte
`--multisig-signer`-Werte an. Prüfe die Hilfe des jeweiligen Befehls, da sein primäres
Autoritäts-Flag je nach Operation variiert.

## Vertrauliche Guthaben

Befehle für vertrauliche Guthaben erfordern einen für vertrauliche Transfers konfigurierten
Token-2022-Mint und ein konfiguriertes Empfängerkonto.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Gib für `configure-confidential-transfer-account` und `apply-pending-balance` entweder
`--address <TOKEN_ACCOUNT_ADDRESS>` oder eine positionale `<MINT_ADDRESS>` an, nicht
beides. Die positionale Form verwendet das associated token account des Owners. Einzahlung und
Auszahlung nehmen immer den Mint entgegen und akzeptieren `--address`, um dieses
Standardkonto zu überschreiben.

Verwende `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits` und `disable-non-confidential-credits`, um zu
steuern, welche Einzahlungen das Konto akzeptiert. Diese Einstellungen beeinflussen die
Privatsphäre des Kontos und die Zahlungskompatibilität; prüfe das Konto, bevor du sie änderst.

## Strukturiertes und Offline-Signieren

Verwende strukturierte Ausgabe, anstatt Anzeigetext zu parsen:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Befehle, die Transaktionen erzeugen, unterstützen häufig `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce` und `--nonce-authority`. Die genauen
Offline-Eingaben hängen vom Befehl, den Dezimalstellen des Mints und der Autoritätskonfiguration ab.
Erzeuge daher die unsignierte Nachricht gemäß den Anweisungen in der `--help` dieses Befehls und
prüfe jede Adresse, bevor du Signaturen einholst.
