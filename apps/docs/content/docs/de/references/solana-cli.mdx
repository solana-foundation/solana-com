Die Befehlszeilenschnittstelle `solana` konfiguriert eine Cluster-Verbindung, liest
den Netzwerkstatus, sendet SOL, verwaltet Durable Nonces, deployt Programme und verwaltet
Stake- und Vote-Konten.

Diese Referenz folgt
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Mit
`solana --version` lässt sich die installierte Version prüfen; `--help` zeigt die genauen
Optionen, die in dieser Version verfügbar sind.

<Callout type="warn">
  Befehle, mit denen etwas erstellt, übertragen, autorisiert, abgehoben oder deployt wird, senden
  Transaktionen. Vor der Ausführung sollten der konfigurierte Cluster und der Signer geprüft werden.
  Devnet- und Testnet-Token haben keinen Wert; Mainnet-Befehle verwenden echtes SOL.
</Callout>

## Befehlsstruktur

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Hilfe auf jeder Ebene abrufen:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Globale Optionen

Globale Optionen können vor dem Befehl stehen. Die befehlsspezifische Hilfe wiederholt
die Optionen, die für den jeweiligen Befehl gelten.

| Option                          | Zweck                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Wählt eine RPC-URL oder `mainnet-beta`, `testnet`, `devnet` oder `localhost` aus.      |
| `--ws <URL>`                    | Überschreibt den WebSocket-Endpunkt.                                               |
| `-k, --keypair <KEYPAIR>`       | Wählt eine Keypair-Datei, `ASK`, stdin (`-`) oder eine unterstützte Signer-URL aus.          |
| `-C, --config <FILEPATH>`       | Verwendet eine andere CLI-Konfigurationsdatei.                                        |
| `--commitment <LEVEL>`          | Liest mit dem Commitment-Level `processed`, `confirmed` oder `finalized`.                   |
| `--output <FORMAT>`             | Gibt `json` oder `json-compact` zurück, sofern unterstützt.                               |
| `--skip-preflight`              | Sendet ohne RPC-Simulation. Nur verwenden, wenn die Risiken eines möglichen Fehlschlags bekannt sind. |
| `--use-tpu-client`              | Sendet Transaktionen über den TPU-Client.                                      |
| `--no-address-labels`           | Gibt Adressen ohne lokale Labels aus.                                          |
| `--skip-seed-phrase-validation` | Erlaubt eine Recovery-Phrase außerhalb der englischen BIP39-Liste.                       |
| `-v, --verbose`                 | Zeigt zusätzliche Befehlsausgaben an.                                                |
| `-V, --version`                 | Gibt die installierte CLI-Version aus.                                               |

## Die CLI konfigurieren

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

Die Konfiguration enthält eine RPC-URL, eine WebSocket-URL, den Standard-Signer und das
Commitment. Eine Befehlszeilenoption überschreibt den gespeicherten Wert für den jeweiligen Aufruf.

## Gängige Workflows für Konten und Transaktionen

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` akzeptiert standardmäßig SOL. Mit `ALL` als Betrag wird das verfügbare
Guthaben nach Abzug der Fee übertragen. Beispiele für Token siehe
[Token-Quickstart](/docs/tokens/quickstart).

## Programm-Workflows

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

`--program-id <KEYPAIR_OR_ADDRESS>` angeben, wenn ein Deployment eine bekannte
Programm-ID verwenden muss. `--final` macht ein neues Deployment unveränderlich; vor der
Verwendung die Hilfe sorgfältig lesen, da die Upgrade-Authority nicht wiederhergestellt werden kann.

## Durable-Nonce-Workflows

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Mit `authorize-nonce-account` wird die Nonce-Authority geändert, mit `nonce-account`
der vollständige Kontostatus abgerufen. Transaktionen mit einer Nonce akzeptieren bei
unterstützten Befehlen außerdem `--nonce` und `--nonce-authority`.

## Stake-Workflows

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

Die Deaktivierung wird an einer Epoch-Grenze abgeschlossen und kann mehr als eine Epoch dauern.
Mit `stakes`, `validators`, `stake-history` und `stake-minimum-delegation` lassen sich der
Cluster- und Delegierungsstatus prüfen, bevor Änderungen gesendet werden.

## Adress-Hilfsprogramme

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

PDA-Seeds verwenden das Format `PREFIX:VALUE`. Unterstützte Präfixe sind unter anderem `string`, `pubkey`,
`hex`, `u8` sowie vorzeichenbehaftete oder vorzeichenlose Integer-Kodierungen mit fester Breite, wie
`u64le`.

## Off-Chain-Nachrichten und Shell-Vervollständigung

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Skriptausgabe

Anstatt die für Menschen lesbare Ausgabe zu parsen, sollte `--output json` oder
`--output json-compact` verwendet werden, sofern unterstützt:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Nicht jeder Befehl unterstützt strukturierte Ausgabe. Vor dem Einsatz in der Automatisierung
die Hilfe des Befehls prüfen und einen Exit-Status ungleich null als Fehler behandeln.
