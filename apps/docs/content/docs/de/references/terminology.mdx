Die folgenden Begriffe werden in der Solana-Dokumentation und im Entwicklungs-Ökosystem verwendet.

## Konten

Ein Eintrag im Solana-Ledger, der entweder Daten enthält oder ein ausführbares Programm ist.

Wie ein Konto bei einer herkömmlichen Bank kann ein Solana-Konto Guthaben in Form von [lamports](#lamport) halten. Jedes Konto in einem [cluster](#cluster) hat eine eindeutige [Adresse](#address).

## App

Eine Frontend-Anwendung, die mit einem Solana-Cluster interagiert.

## Adresse

Der Speicherort in Solana, der verwendet werden kann, um ein Konto zu finden. Jede Adresse ist eindeutig im Solana-[cluster](#cluster).

Adressen in Solana können entweder ein Ed25519-[öffentlicher Schlüssel](#public-key-pubkey) oder eine [program derived address](#program-derived-address-pda) sein.

## Adress-Lookup-Tabelle (ALT)

Eine Datenstruktur, die eine Liste von Kontenadressen speichert und es [versionierten Transaktionen](#versioned-transaction) ermöglicht, auf Konten über kompakte 1-Byte-Indizes statt über vollständige 32-Byte-Public-Keys zu verweisen. Adress-Lookup-Tabellen ermöglichen es einer einzelnen Transaktion, auf mehr Konten zu verweisen, als das ursprüngliche Transaktionsformat erlaubt. Nur Transaktionen der Version 0 (`v0`) unterstützen Adress-Lookup-Tabellen; Version 1 (`v1`) entfernt sie zugunsten einer größeren Transaktionsgröße, die die gleichen Adressen direkt einbettet.

## Anchor

Ein Framework zum Erstellen von Solana-[Onchain-Programmen](#onchain-program) in Rust. Anchor stellt Makros bereit, die Boilerplate reduzieren, ein standardisiertes Kontenvalidierungssystem und generiert eine [IDL](#idl), die die Schnittstelle des Programms beschreibt. Es ist das am weitesten verbreitete Framework für die Solana-Programmentwicklung.

## associated token account (ATA)

Ein [token account](#token-account), dessen Adresse deterministisch aus einer Wallet-Adresse und einem [Token-Mint](#token-mint) abgeleitet wird. Das Associated Token Account Program stellt sicher, dass jede Wallet ein kanonisches token account pro Token-Typ hat.

## Autorität

Die Adresse eines Benutzers, der eine bestimmte Berechtigung über ein Konto hat.

Zum Beispiel:

- Die Fähigkeit, neue Token zu prägen, wird dem Konto gewährt, das die „Mint-Autorität“ für den Token-Mint ist.
- Die Fähigkeit, ein Programm zu aktualisieren, wird dem Konto gewährt, das die „Upgrade-Autorität“ eines Programms ist.

## Automatischer Market Maker (AMM)

Ein Onchain-Börsenmodell, bei dem Benutzer gegen einen Pool von Token-Reserven handeln, der durch eine Preisformel gesteuert wird, anstatt gegen die ruhenden Aufträge einer Gegenpartei. Die Preise bewegen sich in Abhängigkeit von den Reserven, sodass Trades einen [Slippage](#slippage) proportional zur Größe verursachen.

## Bank-Zustand

Das Ergebnis der Interpretation aller Programme im Ledger bei einer bestimmten [Tick-Höhe](#tick-height). Es umfasst mindestens die Menge aller [Konten](#account), die nicht-null [native Token](#native-token) halten.

## Block

Eine zusammenhängende Menge von [Einträgen](#entry) im Ledger, die durch eine [Abstimmung](#ledger-vote) abgedeckt wird. Ein [Leader](#leader) produziert höchstens einen Block pro [slot](#slot).

## Blockhash

Ein eindeutiger Wert ([Hash](#hash)), der einen Datensatz (Block) identifiziert. Solana berechnet einen Blockhash aus der letzten [Eintrags-ID](#entry-id) des Blocks.

## Blockhöhe

Die Anzahl der [Blöcke](#block) unterhalb des aktuellen Blocks. Der erste Block nach dem [Genesis-Block](#genesis-block) hat die Höhe eins.

## Bootstrap-Validator

Der [validator](#validator), der den Genesis-Block (ersten [Block](#block)) einer Blockchain produziert.

## BPF-Loader

Das Solana-Programm, das [BPF](/docs/core/programs)-[Onchain-Programme](#onchain-program) besitzt und lädt und dem Programm ermöglicht, mit der Laufzeitumgebung zu interagieren.

## Bump

Ein einzelnes Byte (0–255), das an [Seeds](#seed) angehängt wird, wenn eine [program derived address](#program-derived-address-pda) abgeleitet wird, um sicherzustellen, dass die resultierende Adresse außerhalb der ed25519-Kurve liegt und daher eine gültige PDA ist. Der kanonische Bump ist der höchste Wert, der eine gültige PDA erzeugt, und wird typischerweise in den Kontendaten gespeichert, um eine erneute Berechnung zu vermeiden.

## Zentrales Limitorderbuch (CLOB)

Ein Börsenmodell, das eine sortierte Liste ruhender Kauf- und Verkaufsaufträge führt; ein Handel findet statt, wenn ein eingehender Auftrag einen Auftrag auf der gegenüberliegenden Seite kreuzt. Im Gegensatz zum [automatischen Market Maker](#automated-market-maker-amm).

## Client

Ein Computerprogramm, das auf das Solana-Server-Netzwerk ([Cluster](#cluster)) zugreift.

## Commitment

Ein Maß für die Netzwerkbestätigung für den [Block](#block).

## Kompaktes Array-Format

Ein kompaktes Array ist ein Array, das im folgenden Format serialisiert wird:

- Die Array-Länge (kodiert als [compact-u16](https://github.com/anza-xyz/agave/blob/v2.1.13/short-vec/src/lib.rs))
- Die Array-Elemente nacheinander aufgelistet

![Kompaktes Array-Format](/assets/docs/core/transactions/compact_array_format.png)

Das kompakte Array-Format wird verwendet, um sowohl das Array der [Kontenadressen](/docs/core/transactions/transaction-structure#account-addresses) als auch das Array der [ Anweisungen](/docs/core/transactions/transaction-structure#instructions) in Transaktionsnachrichten zu kodieren.

## Cluster

Eine Gruppe von [Validatoren](#validator), die ein einzelnes [Ledger](#ledger) pflegen.

## Compute-Budget

Die maximale Anzahl von [Compute-Units](#compute-units), die pro Transaktion verbraucht werden dürfen.

## Compute-Units

Die kleinste Maßeinheit für den Verbrauch von Rechenressourcen der Blockchain. Compute-Units werden verwendet, um die Rechenressourcen zu messen, die für die Verarbeitung einer Transaktion benötigt werden.

## Bestätigungszeit

Die Wanduhrzeit zwischen dem Erstellen eines [Tick-Eintrags](#leader) durch einen [Leader](#tick) und dem Erstellen eines [bestätigten Blocks](#confirmed-block).

## Bestätigter Block

Ein [Block](#block), der eine [absolute Mehrheit](#supermajority) der [Ledger-Abstimmungen](#ledger-vote) erhalten hat.

## Kontrollebene

Ein Gossip-Netzwerk, das alle [Knoten](#node) eines [Clusters](#cluster) verbindet.

## Abkühlungsphase

Eine bestimmte Anzahl von [epochs](#epoch), nachdem ein [Stake](#stake) deaktiviert wurde, während dem er schrittweise für die Auszahlung verfügbar wird. Während dieser Zeit gilt der Stake als „deaktivierend“. Weitere Informationen: [Aufwärm- und Abkühlungsphase](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)

## Kosteneinheiten

Auch als `Transaktionskosten` bezeichnet, ist eine umfassende Schätzung aller Ressourcen, die zur Verarbeitung einer Transaktion erforderlich sind, gemessen in [Compute-Units](#compute-units). Weitere Informationen [hier](https://www.anza.xyz/blog/why-solana-transaction-costs-and-compute-units-matter-for-developers).

## Guthaben

Siehe [Abstimmungsguthaben](#vote-credit).

## cross-program invocation (CPI)

Ein Aufruf von einem [Onchain-Programm](#onchain-program) an ein anderes. Weitere Informationen finden Sie unter [Aufrufe zwischen Programmen](/docs/core/cpi).

## Datenebene

Ein Multicast-Netzwerk, das zur effizienten Validierung von [Einträgen](#entry) und zur Konsensfindung verwendet wird.

## Drone

Ein Offchain-Dienst, der als Verwalter des privaten Schlüssels eines Benutzers fungiert. Er dient in der Regel zur Validierung und Unterzeichnung von Transaktionen.

## Eintrag

Ein Eintrag im [Ledger](#ledger), entweder ein [Tick](#tick) oder ein [Transaktionseintrag](#transactions-entry).

## Eintrags-ID

Ein preimage-resistenter [Hash](#hash) über den endgültigen Inhalt eines Eintrags, der als global eindeutiger Bezeichner des [Eintrags](#entry) dient. Der Hash dient als Nachweis für:

- Den Eintrag, der nach einer bestimmten Zeitspanne generiert wurde
- Die angegebenen [Transaktionen](#transaction) sind diejenigen, die im Eintrag enthalten sind
- Die Position des Eintrags in Bezug auf andere Einträge im [Ledger](#ledger)

Siehe [Proof of History](#proof-of-history-poh).

## epoch

Die Zeit, d. h. die Anzahl der [slots](#slot), für die ein [Leader-Zeitplan](#leader-schedule) gültig ist.

## Treuhand (Escrow)

Ein Muster, bei dem ein [Onchain-Programm](#onchain-program) Token in einem [Tresor](#vault) im Auftrag von zwei oder mehr Parteien hält, bis die vom Programm definierten Bedingungen erfüllt sind, und sie dann freigibt. Wird verwendet, um die Notwendigkeit zu beseitigen, dass die Parteien einander direkt vertrauen müssen.

## Gebührenkonto

Das Gebührenkonto in der Transaktion ist das Konto, das die Kosten für die Aufnahme der Transaktion in das Ledger bezahlt. Dies ist das erste Konto in der Transaktion. Dieses Konto muss in der Transaktion als Lese-Schreib-Konto (beschreibbar) deklariert werden, da die Bezahlung der Transaktion das Kontoguthaben reduziert.

## Finalität

Wenn Knoten, die 2/3 des [Stakes](#stake) repräsentieren, eine gemeinsame [Wurzel](#root) haben.

## Fork

Ein [Ledger](#ledger), der aus gemeinsamen Einträgen abgeleitet wurde, sich aber dann unterschieden hat.

## Genesis-Block

Der erste [Block](#block) in der Kette.

## Genesis-Konfiguration

Die Konfigurationsdatei, die das [Ledger](#ledger) für den [Genesis-Block](#genesis-block) vorbereitet.

## Hash

Ein digitaler Fingerabdruck einer Bytefolge.

## Inflation

Eine Zunahme des Token-Angebots im Laufe der Zeit, die zur Finanzierung von Validierungsbelohnungen und zur Unterstützung der kontinuierlichen Entwicklung von Solana verwendet wird.

## Interne Anweisung

Siehe [cross-program invocation](#cross-program-invocation-cpi).

## Anweisung

Ein Aufruf zum Ausführen eines bestimmten [Anweisungs-Handlers](#instruction-handler) in einem [Programm](#program). Eine Anweisung gibt auch an, welche Konten gelesen oder geändert werden sollen, sowie zusätzliche Daten, die als Hilfseingabe für den [Anweisungs-Handler](#instruction-handler) dienen. Ein [Client](#client) muss mindestens eine Anweisung in eine [Transaktion](#transaction) aufnehmen, und alle Anweisungen müssen abgeschlossen sein, damit die Transaktion als erfolgreich gilt.

## Anweisungs-Handler

Anweisungs-Handler sind [Programm](#program)-Funktionen, die [ Anweisungen](#instruction) aus [Transaktionen](#transaction) verarbeiten. Ein Anweisungs-Handler kann eine oder mehrere [cross-program invocations](#cross-program-invocation-cpi) enthalten.

## IDL

Interface Definition Language. Eine JSON-Datei, die von [Anchor](#anchor) generiert wird und die [Anweisungs-Handler](#instruction-handler), Konten und Typen eines Programms beschreibt. Die IDL ermöglicht es Client-Bibliotheken, automatisch typisierte Schnittstellen für die Interaktion mit einem [Onchain-Programm](#onchain-program) zu generieren.

## keypair

Ein [öffentlicher Schlüssel](#public-key-pubkey) und der entsprechende [private Schlüssel](#private-key) für den Zugriff auf ein Konto.

## lamport

Ein gebrochener [nativer Token](#native-token) mit dem Wert von 0,000000001 [SOL](#sol).

> Im Rahmen des Compute-Budgets wird eine Menge von
> _[Mikro-lamports](https://github.com/solana-labs/solana/blob/ced8f6a512c61e0dd5308095ae8457add4a39e94/program-runtime/src/prioritization_fee.rs#L1-L2)_
> bei der Berechnung von [Priorisierungsgebühren](#prioritization-fee) verwendet.

## Leader

Die Rolle eines [validator](#validator)s, wenn er [Einträge](#entry) an das [Ledger](#ledger) anhängt.

## Leader-Zeitplan

Eine Sequenz von [validator](#validator)-[öffentlichen Schlüsseln](#public-key-pubkey), die [slots](#slot) zugeordnet sind. Der Cluster verwendet den Leader-Zeitplan, um zu bestimmen, welcher Validator zu einem bestimmten Zeitpunkt der [Leader](#leader) ist.

## Ledger

Eine Liste von [Einträgen](#entry), die [Transaktionen](#transaction) enthalten, die von [Clients](#client) signiert wurden. Konzeptionell kann dies bis zum [Genesis-Block](#genesis-block) zurückverfolgt werden, aber das Ledger eines tatsächlichen [validator](#validator)s enthält möglicherweise nur neuere [Blöcke](#block), um Speicherplatz zu reduzieren, da ältere Blöcke für die Validierung zukünftiger Blöcke by Design nicht benötigt werden.

## Ledger-Abstimmung

Ein [Hash](#hash) des [Validator-Zustands](#bank-state) bei einer bestimmten [Tick-Höhe](#tick-height). Er umfasst die Bestätigung eines [Validators](#validator), dass ein empfangener [Block](#block) verifiziert wurde, sowie ein Versprechen, für eine bestimmte Zeitspanne, die [Lockout](#lockout)-Periode, nicht für einen konkurrierenden [Block](#block) \(d. h. [Fork](#fork)\) zu stimmen.

## Light-Client

Ein [Client](#client)-Typ, der überprüfen kann, ob er auf einen gültigen
[Cluster](#cluster) zeigt. Er führt mehr Ledger-Überprüfungen durch als ein
[Thin Client](#thin-client) und weniger als ein [validator](#validator).

## Liquidität

Die Tiefe der Aufträge oder gepoolten Reserven, die zum aktuellen Preis oder in dessen Nähe zum Handel zur Verfügung stehen. Tiefere Liquidität reduziert [Slippage](#slippage). In einem
[CLOB](#central-limit-order-book-clob) wird Liquidität durch
[Maker-Orders](#maker) bereitgestellt; in einem [AMM](#automated-market-maker-amm) wird sie
von Liquiditätsanbietern bereitgestellt, die Token-Paare in den Pool einzahlen.

## Loader

Ein [Programm](#program) mit der Fähigkeit, die binäre Kodierung anderer
[Onchain-Programme](#onchain-program) zu interpretieren.

## Lockout

Die Zeitspanne, während der ein [validator](#validator) nicht in der Lage ist,
für einen anderen [Fork](#ledger-vote) zu [voten](#fork).

## Maker

Ein Händler, dessen Order [Liquidität](#liquidity) zu einem
[CLOB](#central-limit-order-book-clob) hinzufügt, indem sie im Orderbuch verbleibt, anstatt
sofort die Gegenseite zu kreuzen. Eine solche Order wird als Maker-Order bezeichnet.
Maker zahlen in der Regel keine Fee oder erhalten eine Rückvergütung von der Handelsplattform.

## Market Maker

Eine Einheit, die [Liquidität](#liquidity) bereitstellt, indem sie kontinuierlich sowohl
Gebote als auch Angebote platziert. Auf Solana sind Market Maker entweder Programme (wie
[AMMs](#automated-market-maker-amm)) oder Offchain-Unternehmen, die Bots betreiben, die
[Maker-Orders](#maker) auf [CLOBs](#central-limit-order-book-clob) platzieren.

## Nachricht

Der strukturierte Inhalt einer [Transaktion](#transaction). Enthält in der Regel einen
Header, ein Array von Kontenadressen, einen aktuellen [Blockhash](#blockhash) und ein Array
von [ Anweisungen](#instruction).

Erfahren Sie mehr über die
[Nachrichtenformatierung innerhalb von Transaktionen](/docs/core/transactions/transaction-structure#header)
hier.

## Micro-Lamport

1.000.000 Micro-Lamports = 1 [lamport](#lamport)

## Nakamoto-Koeffizient

Ein Maß für Dezentralisierung: Der Nakamoto-Koeffizient ist die kleinste Anzahl
unabhängiger Einheiten, die kollektiv handeln können, um eine Blockchain abzuschalten. Der
Begriff wurde von Balaji S. Srinivasan und Leland Lee in
[Quantifying Decentralization](https://news.earn.com/quantifying-decentralization-e39db233c28e) geprägt.

## Nativer Token

Der [Token](#token), der verwendet wird, um die von [Nodes](#node) in einem Cluster geleistete Arbeit zu verfolgen.

## Node

Ein Computer, der an einem [Cluster](#cluster) teilnimmt.

## Node-Anzahl

Die Anzahl der [Validatoren](#validator), die an einem [Cluster](#cluster) teilnehmen.

## Offchain

Bezeichnet Daten, Prozesse oder Dienste, die außerhalb der Solana-Blockchain existieren oder ausgeführt werden, wie z. B. RPC-Clients, Indexer, Frontends und Offchain-Orderbuch-Maker. Gegenstück zu [Onchain](#onchain). "Offchain" (ohne Bindestrich) ist die
bevorzugte Schreibweise.

## Onchain

Bezeichnet Daten oder Programme, die auf einer Blockchain existieren oder ausgeführt werden. "Onchain" (ohne Bindestrich) ist die bevorzugte Schreibweise.

## Onchain-Programm

Der ausführbare Code auf der Solana-Blockchain, der die
[ Anweisungen](#instruction) interpretiert, die in jeder [Transaktion](#transaction) gesendet werden, um
Konten zu lesen und zu ändern, über die es die Kontrolle hat. Diese Programme werden auf anderen Blockchains oft als
"[_Smart Contracts_](/docs/core/programs)" bezeichnet.

## Oracle

Ein [Onchain-Programm](#onchain-program), das Daten von außerhalb der
Chain veröffentlicht – meistens Preise von realen Vermögenswerten – damit andere Programme diese lesen können.

## Eigentümer

Kann sich entweder auf das [besitzende Programm](#owning-program) oder die
[besitzende Wallet](#owning-wallet) beziehen. Zum Beispiel gibt
[getTokenAccountsByOwner](https://solana.com/docs/rpc/http/gettokenaccountsbyowner)
token account zurück, die einer bestimmten Wallet gehören, wobei das besitzende Programm für
diese token account jedoch das [Token Program](#token-program) ist.

Um Verwirrung zu vermeiden, ist es vorzuziehen, entweder
[besitzendes Programm](#owning-program) oder [besitzende Wallet](#owning-wallet) anstatt
des generischen Begriffs 'Eigentümer' zu verwenden.

## Besitzendes Programm

Die [Adresse](#address) des [Programms](#onchain-program), dem das
Konto gehört. Nur das besitzende Programm kann das Konto ändern.

Siehe auch [Autorität](#authority).

## Besitzende Wallet

Die Wallet, die einem Konto zugeordnet ist. Zum Beispiel wird das Token Program verwendet,
um token account zu speichern, die einer bestimmten Wallet und einem Mint zugeordnet sind, unter Verwendung
einer Adresse aus dieser [Wallet](#wallet) und diesem [Mint](#token-mint).

## PoH

Siehe [Proof of History](#proof-of-history-poh).

## Punkt

Ein gewichtetes [Guthaben](#credit) in einem Belohnungssystem. Im [validator](#validator)
[Belohnungssystem](https://docs.anza.xyz/consensus/stake-delegation-and-rewards)
ist die Anzahl der Punkte, die einem [Stake](#stake) bei der Einlösung zustehen, das Produkt
aus den verdienten [Vote Credits](#vote-credit) und der Anzahl der
eingesetzten [lamports](#lamport).

## Privater Schlüssel

Der private Schlüssel eines [keypair](#keypair).

## Programm

Siehe [Onchain-Programm](#onchain-program).

## Program Derived Address (PDA)

Ein Konto, dessen Adresse basierend auf einem
[Onchain-Programm](#onchain-program) und einem oder mehreren [seeds](#seed), die vom
Programmautor erstellt wurden, abgeleitet wird. PDA-Adressen sind keine öffentlichen Schlüssel, und PDAs haben
keine privaten Schlüssel.

Die Signierungsberechtigung für eine PDA ist das [Onchain-Programm](#onchain-program), das
ihre [besitzendes Programm](#owning-program) ist.

## Programm-ID

Der öffentliche Schlüssel der [Konten](#account), die ein
[Programm](#onchain-program) enthalten.

## Proof of History (PoH)

Ein Stapel von Beweisen, von denen jeder beweist, dass bestimmte Daten vor der Erstellung des Beweises existierten und dass eine genaue Zeitspanne seit dem vorherigen
Beweis vergangen ist. Wie ein [VDF](#verifiable-delay-function-vdf) kann ein Proof of History
in weniger Zeit verifiziert werden, als er zur Erzeugung benötigt hat.

## Priorisierungsgebühr

Eine zusätzliche Fee, die Benutzer in der Compute-Budget-[Anweisung](#instruction) angeben können, um ihre [Transaktionen](#transaction) zu priorisieren.

Die Priorisierungsgebühr wird berechnet, indem die angeforderten maximalen
Compute Units mit dem Compute-Unit-Preis (angegeben in Schritten von 0,000001
[lamports](#lamport) pro Compute Unit) multipliziert und auf den nächsten
[lamport](#lamport) aufgerundet wird.

Transaktionen sollten die für die Ausführung erforderliche Mindestanzahl an Compute Units anfordern, um Fee zu minimieren.

## Öffentlicher Schlüssel (pubkey)

Der öffentliche Schlüssel eines [keypair](#keypair). Ein öffentlicher Schlüssel ist einer der verschiedenen
Typen von [Adressen](#address), die ein Konto auf Solana verwenden kann.

## rent

Fee, die von [Konten](#account) und [Programmen](#program) gezahlt wird, um Daten auf der
Blockchain zu speichern. Wenn Konten kein ausreichendes Guthaben haben, um rent zu bezahlen, können sie
durch Garbage Collection entfernt werden.

Siehe auch [rent-befreit](#rent-exempt) unten. Erfahren Sie mehr über rent hier:
[Was ist rent?](/docs/core/accounts/account-structure).

## Rent-befreit

Konten, die ein Mindestguthaben an lamports aufrechterhalten, das proportional zur
Menge der auf dem Konto gespeicherten Daten ist. Alle neu erstellten Konten werden
permanent onchain gespeichert, bis das Konto geschlossen wird. Es ist nicht möglich, ein
Konto zu erstellen, das unter den rent-Befreiungsschwellenwert fällt.

## Root

Ein [Block](#block) oder [slot](#slot), der maximalen [Lockout](#lockout)
auf einem [validator](#validator) erreicht hat. Der Root ist der höchste Block, der ein Vorfahre
aller aktiven Forks auf einem validator ist. Alle Vorfahren-Blöcke eines Roots sind ebenfalls
transitiv ein Root. Blöcke, die weder ein Vorfahre noch ein Nachfahre des
Roots sind, werden vom Konsens ausgeschlossen und können verworfen werden.

## Laufzeitumgebung

Die Komponente eines [validator](#validator), die für die Ausführung von [Programmen](#program)
verantwortlich ist.

## Sealevel

Solanas parallele Laufzeitumgebung für [Onchain-Programme](#onchain-program).

## seed

Ein Byte-Wert oder ein Array von Byte-Werten, der als Eingabe bei der Ableitung einer
[Program Derived Address](#program-derived-address-pda) verwendet wird. Ein Programm kann eine beliebige
Kombination aus statischen Strings, öffentlichen Schlüsseln oder anderen Daten als seeds verwenden. Seeds werden
mit der Programm-ID und einem [Bump](#bump) kombiniert, um eine eindeutige PDA-
Adresse zu erzeugen.

## Shred

Ein Bruchteil eines [Blocks](#block); die kleinste Einheit, die zwischen
[Validatoren](#validator) übertragen wird.

## Signatur

Eine 64-Byte ed25519-Signatur aus R (32 Bytes) und S (32 Bytes). Mit der
Anforderung, dass R ein gepackter Edwards-Punkt nicht kleiner Ordnung ist und S ein
Skalar im Bereich `0 <= S < L` ist. Diese Anforderung stellt sicher, dass keine Signatur-
Formbarkeit besteht. Jede Transaktion muss mindestens eine Signatur für das
[Fee-Konto](#fee-account) haben. Somit kann die erste Signatur in einer Transaktion als
[Transaktions-ID](#transaction-id) behandelt werden.

## Signer

Ein [Konto](#account), das eine [ Anweisung](#instruction) oder
[Transaktion](#transaction) autorisiert hat. Bei einem regulären [keypair](#keypair) bedeutet dies eine
kryptografische [Signatur](#signature) über die Transaktion. Bei einer
[Program Derived Address](#program-derived-address-pda) wird die Autorisierung
vom [besitzenden Programm](#owning-program) geltend gemacht, wenn es eine
[Cross-Program Invocation](#cross-program-invocation-cpi) durchführt, da eine PDA keinen
privaten Schlüssel hat.

## Skip-Rate

Der Prozentsatz der [übersprungenen Slots](#skipped-slot) an der Gesamtzahl der Leader-Slots
in der aktuellen epoch. Diese Kennzahl kann irreführend sein, da sie nach der epoch-Grenze eine hohe Varianz aufweist, wenn die Stichprobengröße klein ist, sowie für
Validatoren mit einer geringen Anzahl von Leader-Slots; sie kann jedoch auch nützlich sein,
um Node-Fehlkonfigurationen zu bestimmten Zeiten zu identifizieren.

## Übersprungener Slot

Ein vergangener [slot](#slot), der keinen [Block](#block) produziert hat, weil der Leader
offline war oder der [Fork](#fork), der den slot enthielt, durch den Cluster-Konsens zugunsten einer besseren
Alternative aufgegeben wurde. Ein übersprungener slot erscheint nicht als Vorfahre
für Blöcke bei nachfolgenden Slots, erhöht nicht die [Blockhöhe](#block-height)
und lässt den ältesten `recent_blockhash` nicht ablaufen.

Ob ein slot übersprungen wurde, lässt sich erst bestimmen, wenn er älter ist
als der neueste [gewurzelte](#root) (also nicht übersprungene) slot.

## Slippage

Die Differenz zwischen dem vom Händler erwarteten Preis und dem Preis, zu dem sein
Handel tatsächlich ausgeführt wurde. Bei [AMMs](#automated-market-maker-amm) entsteht sie durch
die Bewegung der Preiskurve, wenn sich die Reserven ändern; bei
[CLOBs](#central-limit-order-book-clob) entsteht sie dadurch, dass eine einzelne Order
mehrere ruhende Orders zu sukzessiv schlechteren Preisen konsumiert.

## slot

Der Zeitraum, in dem jeder [Leader](#leader) Transaktionen aufnimmt und
einen [Block](#block) produziert.

Gemeinsam bilden Slots eine logische Uhr. Slots sind sequenziell geordnet und
nicht überlappend und umfassen gemäß [PoH](#proof-of-history-poh) ungefähr gleiche reale Zeit.

## System Program

Ein natives Solana-Programm (Programm-ID `11111111111111111111111111111111`),
das für die Erstellung neuer [Konten](#account), die Zuweisung von Kontodaten,
die Zuweisung von Konten zu Programmen und die Übertragung von [SOL](#sol) zwischen Konten zuständig ist.
Alle neuen Konten auf Solana gehören dem System Program, bis sie neu zugewiesen werden.

## sysvar

Ein System-[Konto](#account). [Sysvars](https://docs.anza.xyz/runtime/sysvars)
liefern Informationen über den Cluster-Zustand, wie z. B. die aktuelle Tick-Höhe, Belohnungs-[Punkte](#point)werte usw. Programme können über ein Sysvar-Konto
(pubkey) oder durch eine Syscall-Abfrage auf Sysvars zugreifen.

## Taker

Ein Händler, dessen Order [Liquidität](#liquidity) aus einem
[CLOB](#central-limit-order-book-clob) entnimmt, indem er die gegenüberliegende Seite des Orderbuchs kreuzt
und gegen eine oder mehrere ruhende Orders matched. Eine solche Order wird als Taker-Order bezeichnet, und der Taker zahlt in der Regel die Handelsgebühr der Plattform.

## Thin Client

Guthaben, die zugehörige [Token-Mint](#token-mint) und die Wallet-Adresse des Eigentümers.

hat die Programm-ID `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` und umfasst
alle Funktionen des [Token Program](#token-program), bietet jedoch zusätzlich
Erweiterungen wie vertrauliche Guthaben, benutzerdefinierte Übertragungslogik, erweiterte

## Token Program

## Transaktion

Eine oder mehrere [ Anweisungen](#instruction), die von einem [Client](#client) mit einem

Ergebnissen ausgeführt werden: Erfolg oder Fehler.

Die erste [Signatur](#signature) in einer [Transaktion](#transaction), die dazu verwendet werden kann,

## validator

Ein vollständiger Teilnehmer in einem Solana-Netzwerk-[Cluster](#cluster), der neue
[Blöcke](#block) produziert. Ein Validatoren validiert die dem
[Ledger](#ledger) hinzugefügten Transaktionen.

## Vault

Ein [token account](#token-account), der einem
[Onchain-Programm](#onchain-program) gehört und gepoolte Assets im Auftrag von Nutzern hält
– zum Beispiel die Basis- und Kursreserven eines
[AMM](#automated-market-maker-amm), die gesperrten Token in einem [Escrow](#escrow)
oder die ruhenden Guthaben und aufgelaufenen Fee eines
[CLOB](#central-limit-order-book-clob). Nur das besitzende Programm kann Token
aus dem Vault bewegen, typischerweise in das eigene [token account](#token-account) eines Nutzers,
sobald eine Handels- oder Freigabebedingung erfüllt ist.

## Verifizierbare Verzögerungsfunktion (VDF)

Eine Funktion, deren Ausführung eine feste Zeitspanne benötigt und einen Beweis erzeugt,
dass sie ausgeführt wurde. Dieser Beweis kann in kürzerer Zeit verifiziert werden, als seine Erzeugung gedauert hat.

## Versionierte Transaktion

Ein Transaktionsformat, das zusätzliche Funktionen über das ursprüngliche
[Transaktions](#transaction)format hinaus unterstützt. Version 0 (`v0`) ist das erste versionierte
Format und fügt Unterstützung für [Address Lookup Tables](#address-lookup-table-alt) hinzu,
wodurch Transaktionen auf mehr Konten verweisen können als das ursprüngliche Format
erlaubt. Version 1 (`v1`), aktiv auf allen Clustern, erhöht die maximale Transaktionsgröße
auf 4.096 Bytes, enthält Ressourcenlimits in einem Konfigurationsabschnitt der Nachricht
anstelle von ComputeBudget- Anweisungen und verzichtet auf die Unterstützung von Address Lookup Tables.
Siehe [versionierte Transaktionen](/docs/core/transactions/versioned-transactions).
