# Arbeiten mit LLMs und Agenten auf Solana

Bevor wir uns mit spezifischen Tools befassen, wollen wir die wichtigsten Komponenten des KI-Entwicklungs-Stacks verstehen:

## Den KI-Stack verstehen

1. **Large Language Models (LLMs)**
   - Die grundlegenden KI-Modelle (wie GPT-4, Claude oder Llama)
   - Verarbeiten und generieren natürliche Sprache
   - Bieten grundlegende Intelligenz und Reasoning-Fähigkeiten
   - Beispiele: OpenAIs GPT-4, Anthropics Claude, Metas Llama

2. **Agent-Frameworks (wie Eliza)**
   - Aufgebaut auf LLMs zur Erstellung autonomer Agenten
   - Verwaltung von Agentenpersönlichkeiten und -verhalten
   - Speicher- und Kontextverwaltung
   - Multi-Plattform-Integration
   - Beispiele: Eliza, LangChain, AutoGPT, Vercel AI

3. **Domänenspezifische Agent-Kits (wie das Solana Agent Kit)**
   - Entwickelt für spezifische Anwendungsfälle (z. B. Blockchain-Operationen)
   - Bieten vorgefertigte Tools und Integrationen
   - Abstrahieren technische Komplexität
   - Einsatzbereite Blockchain-Funktionen
   - Beispiele: Solana Agent Kit, GOAT Toolkit

Stell es dir so vor:

- LLMs sind das „Gehirn“, das Sprache verstehen und generieren kann
- Agent-Frameworks sind das „Betriebssystem“, das das Verhalten der KI steuert
- Domänenspezifische Kits sind die „Apps“, die der KI spezifische Fähigkeiten verleihen

# KI-Agenten für Solana entwickeln

Dieser Leitfaden zeigt dir, wie du:

- Einen einfachen KI-Agenten mit SendAIs Solana Agent Kit erstellst
- Einen Twitter-Bot mit dem Eliza Framework erstellst
- Onchain-KI-Integrationsoptionen verstehst
- Optionen zum Aufbau fortgeschrittener Trading-Bots kennenlernst

## Einführung in KI-Agenten auf Solana

KI-Agenten auf Solana sind autonome Programme, die mithilfe von Natural Language Processing und maschinellem Lernen mit der Blockchain interagieren können. Sie können:

- Transaktionen ausführen
- Blockchain-Aktivitäten überwachen
- Mit Smart Contracts interagieren
- Nutzerunterstützung bieten
- Komplexe Workflows automatisieren

## Verfügbare Frameworks

Für die Entwicklung von KI-Agenten auf Solana stehen mehrere Frameworks zur Verfügung:

1. **SendAIs Solana Agent Kit**

- Eine Sammlung von Tools zur Entwicklung von Agenten auf Solana
- Kompatibel mit Eliza, Langchain und dem Vercel AI SDK
- Integrierte Solana-Tools und Hilfsfunktionen
- Natural-Language-Processing-Fähigkeiten
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Dokumentation](https://docs.solanaagentkit.xyz/)

2. **Eliza Framework**

- Kombiniert Datenschicht, LLM und Agenten und verfügt über ein dediziertes Solana-Plugin
- Erweiterbare Agentenarchitektur
- Einfache Integration in bestehende Projekte und kann beispielsweise für
  Twitter (X)-, Telegram- oder Discord-Bots verwendet werden
- [GitHub-Repository](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Umfassendes Entwicklungs-Toolkit
- Cross-Chain-Kompatibilität
- [GitHub-Repository](https://github.com/goat-sdk/goat)

4. **Rig Framework**

- Native Rust-Implementierung
- Gut geeignet für hochperformante Trading-Bots
- Kann mit dem Listen.rs-Toolkit für Solana-Integration, Transaktionsüberwachung und das Senden von Transaktionen über Jito-Bundles kombiniert werden
- [GitHub-Repository](https://github.com/0xPlaygrounds/rig)
- [Listen.rs-Repository](https://github.com/piotrostr/listen)

Wenn du ein KI-Framework entwickelst, kannst du gerne einen PR öffnen, um dein Framework zur Liste hinzuzufügen

### Das Agenten-Skript erstellen

Erstelle eine neue Datei namens `agent.ts` mit folgendem Inhalt:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## Entwicklung mit dem Eliza Framework

Das [ElizaOS](https://github.com/elizaOS/eliza) (früher bekannt als Ai16z) ist ein
KI-Framework. Das bedeutet, es kombiniert mehrere Anwendungen in einer und
organisiert deren Interaktionen. Es vereint:

1. Verschiedene LLMs zum Verstehen des Nutzers
2. Blockchain-Agenten mit verschiedenen Aktionen (wie z. B. das Minting eines NFTs)
3. Datenschichten zur Speicherung des Charakterzustands zwischen Aktionen, z. B. mit
   Redis, PostgreSQL oder lokalem Speicher
4. Verschiedene Clients wie X, Telegram, Discord usw.

Es fügt all diese Dinge zusammen, sodass du einen „Charakter“ erstellen kannst, der mit Nutzern interagieren oder autonom agieren kann. Diese Charaktere werden in einer JSON-Datei definiert, die festlegt, welche Aktionen er ausführen kann, welches LLM er verwenden soll und verschiedene Prompts, die das Verhalten des Charakters bestimmen.

### Charakterkonfiguration erstellen

Um einen neuen Charakter zu erstellen, müssen wir eine character.json-Datei anlegen. Die vordefinierten Charaktere findest du im Characters-Ordner des Eliza-Projekts. Um einen neuen Charakter zu erstellen, kannst du einen der vorhandenen Charaktere kopieren und anpassen oder die
[Composer-Funktion in Cursor](https://docs.cursor.com/composer/overview) verwenden und
angeben, welche Art von Charakter du erstellen möchtest.

```json filename=characters/sol.character.json
{
    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },
        ...
```

Der wichtige Teil hier sind die Clients und der modelProvider. In unserem Fall möchten wir Twitter als Client und OpenAI als Model-Provider verwenden, da wir dafür auch unsere Secrets in der `.env`-Datei hinterlegt haben.

### Den Agenten ausführen

Jetzt, da die Konfiguration abgeschlossen ist, können wir unseren Charakter starten:

```bash
pnpm start --character="characters/sol.character.json"
```

Dadurch wird der Agent gestartet und du kannst nun auf Twitter mit ihm interagieren. Der Charakter wird automatisch alle paar Stunden Tweets posten, und wenn wir mit ihm interagieren, kann er Solana-Aktionen wie das Minting von NFTs ausführen.

Hier kannst du den
[Charakter in Aktion](https://x.com/solanadevhelper/status/1882222232656847143) sehen.

Du kannst auch lokal mit dem Charakter interagieren, indem du folgenden Befehl verwendest:
Möglicherweise musst du Port 3000 freigeben und deinen Charakter mit dem `--host`-Flag starten.

```bash
pnpm start --character="characters/sol.character.json" --host
pnpm start:client
```

Wenn dein Client keine Verbindung herstellt, stelle sicher, dass du deinen Agenten mit dem `--host`-Flag ausführst und dass Port 3000 nicht belegt ist, wenn du den Client startest.

Weitere Informationen findest du in der
[offiziellen Eliza-Dokumentation](https://elizaos.github.io/eliza/docs/quickstart/)

## Onchain-Programm-Agenten-Integration

Wenn du die Antwort eines Agenten innerhalb eines Solana-Programms verwenden möchtest, musst du ein
Orakel verwenden, das die Antwortdaten in ein Konten schreibt, das dein Programm lesen kann.
Hier findest du ein Beispiel für ein LLM, das Token an jeden Nutzer überträgt, der
Fragen richtig beantwortet:

[Onchain-Programm-LLM-Interaktion](https://github.com/GabrielePicco/super-smart-contracts)

Dies ist ein Beispiel für ein Onchain-Programm, das mit einem LLM (KI)-Orakel integriert ist,
um einen interaktiven Token-Ausgabe-Agenten namens "Mar1o" zu erstellen.

### Hauptfunktionen

1. **KI-Agenten-Interaktion**
   - Nutzer können mit Mar1o chatten, um Token zu verdienen
   - Der Agent bewertet das Solana-Wissen des Nutzers, um Token-Beträge festzulegen
   - Antworten liegen im JSON-Format mit Antworttext und Token-Betrag vor

2. **Token-Verwaltung**
   - Erstellt MAR1O-Token mit Metadaten
   - Kann zwischen 0 und 10.000 Token basierend auf der KI-Antwort prägen
   - Verwendet PDAs für die Token-Verwaltung

### Programmablauf erklärt

So funktioniert dieses Programm:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Dies zeigt, wie KI-Fähigkeiten mit Onchain-Token-Mechanismen kombiniert werden können, um
interaktive Blockchain-Erlebnisse zu schaffen. Hier ist ein
[Live-Beispiel](https://mar1o.xyz/), bei dem du versuchen kannst, den Agenten dazu zu bringen,
dir einige Token zu übertragen.

## Erweiterte Rust-Agenten für algorithmischen Handel

Wenn du deine Agenten in Rust schreiben möchtest, kannst du das
[Rig-Framework](https://github.com/0xPlaygrounds/rig) und die
[Listen.rs](https://github.com/piotrostr/listen)-Bibliothek verwenden.

Diese beiden funktionieren gut zusammen. Während das Rig-Framework dir eine einfache Möglichkeit bietet,
eine Verbindung zu LLMs herzustellen, stellt das Listen.rs-Toolkit die Solana-Integration bereit,
einschließlich Transaktionsüberwachung und dem Senden von Transaktionen mithilfe von Jito-Bundles,
zum Beispiel.

## Best Practices

- Beachte, dass dein Agent einen privaten Schlüssel besitzt und somit Zugriff auf die Mittel in deiner
  Wallet hat. Wenn jemand mit deinem Agenten chatten kann und dieser beispielsweise eine Übertragungs-Aktion besitzt,
  können Nutzer ihn wahrscheinlich dazu bringen, ihnen deine Mittel zu übertragen.
- Verwende kostenpflichtige [RPC-Endpunkte](https://solana.com/rpc). Die öffentlichen Endpunkte
  werden in der Regel durch Rate-Limiting eingeschränkt
- Überwache die Aktivitäten des Agenten und stelle sicher, dass er nichts Bösartiges tut
  oder von Nutzern, die mit ihm interagieren, dazu verleitet wird
- Implementiere priority fee und Transaktionswiederholungen in deinen Agenten-Aktionen, damit
  diese auch bei Netzwerküberlastung ausgeführt werden
- Teste wenn möglich zuerst auf Devnet, bevor du auf Mainnet deployst. Die meisten Agenten
  nehmen die RPC-URL als Eingabe entgegen und du kannst eine Devnet-URL verwenden, bis du für
  Mainnet bereit bist. Allerdings sind möglicherweise nicht alle Aktionen auf Devnet durchführbar.
- Wenn du eigene Aktionen schreibst, füge Integrationstests hinzu, damit die
  Frameworks überwachen können, welche Aktionen aufgrund geänderter Programme oder
  APIs fehlschlagen

## Fazit

KI-Agenten auf Solana eröffnen neue Möglichkeiten für Automatisierung und Interaktion
mit der Blockchain. Auch wenn noch nicht alle Integrationen perfekt sind, werden sie
schnell weiterentwickelt und bieten viele Möglichkeiten für Beiträge und sind sehr
flexibel bei der Einbindung eigener Integrationen.
