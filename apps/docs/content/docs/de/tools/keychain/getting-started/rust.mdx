## Installation

Fügen Sie `solana-keychain` zu Ihrer `Cargo.toml` hinzu, und zwar nur mit den
Backends, die Sie benötigen:

```toml title="Cargo.toml"
[dependencies]
# Memory signer only (default, Solana SDK 2.x)
solana-keychain = "2.0"

# Or specify backends explicitly (pick exactly one SDK feature)
solana-keychain = { version = "2.0", default-features = false, features = ["vault", "aws_kms", "sdk-v2"] }

# All remote backends on the Solana 4.x SDK line
solana-keychain = { version = "2.0", default-features = false, features = ["all", "sdk-v4"] }
```

Upgrade von 1.x? Siehe den
[Migrationsleitfaden zu 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md).

### Feature-Flags

| Funktion        | Beschreibung                                                           |
| -------------- | --------------------------------------------------------------------- |
| `memory`       | Lokale keypair-Signierung (Standard)                                       |
| `vault`        | HashiCorp Vault Transit Engine                                        |
| `aws_kms`      | AWS KMS mit Ed25519                                                  |
| `gcp_kms`      | GCP Cloud KMS mit Ed25519                                            |
| `privy`        | Privy Embedded Wallets                                                |
| `turnkey`      | Turnkey API                                                           |
| `fireblocks`   | Fireblocks MPC                                                        |
| `cdp`          | Coinbase Developer Platform                                           |
| `crossmint`    | Crossmint Managed Wallets                                             |
| `dfns`         | Dfns Wallet-Infrastruktur                                            |
| `openfort`     | Openfort Embedded Wallets                                             |
| `para`         | Para MPC Wallets                                                      |
| `utila`        | Utila MPC Custody                                                     |
| `fordefi`      | Fordefi MPC-Verwahrung                                                   |
| `ledger`       | Ledger-Hardware-Wallet über USB-HID (nur Rust, Opt-in, nicht in `all` enthalten) |
| `all`          | Alle Backends außer `ledger` aktivieren                                  |
| `sdk-v2`       | Solana SDK 2.x (Standard)                                              |
| `sdk-v3`       | Solana SDK 3.x                                                        |
| `sdk-v4`       | Solana SDK 4.x (erforderlich für v1-Transaktionen)                         |
| `unsafe-debug` | Protokolliert vollständige Fehlerantworten des Providers; niemals in der Produktion aktivieren        |

Genau eines von `sdk-v2`, `sdk-v3` und `sdk-v4` muss aktiviert sein.

## Grundlegende Verwendung

Alle Signer implementieren den Basis-
[`SolanaSigner`-Trait](https://github.com/solana-foundation/solana-keychain/blob/main/rust/src/traits.rs)
(`pubkey`, `sign_message`, `is_available`). Außerdem implementiert jedes Backend genau
einen Capability-Trait:

- `TransactionSigner`: signiert Ihre Transaktion unverändert.
- `ModifyingSigner`: Der Provider schreibt die Transaktion um und signiert sie anschließend.
- `SendingSigner`: Der Provider signiert und sendet sie.

```rust
use solana_keychain::{SignerError, SolanaSigner, TransactionSigner};
use solana_sdk::transaction::VersionedTransaction;

async fn sign_transaction(
    signer: &impl TransactionSigner,
    tx: &mut VersionedTransaction,
) -> Result<(), SignerError> {
    // Get the signer's public key
    let pubkey = signer.pubkey();
    println!("Signing with: {}", pubkey);

    // Check availability (useful for remote signers)
    if !signer.is_available().await {
        return Err(SignerError::NotAvailable("Signer offline".into()));
    }

    // Sign the transaction: returns Complete or Partial
    let result = signer.sign_transaction(tx).await?;
    let (base64_tx, signature) = result.into_signed_transaction();
    println!("Signature: {}", signature);

    Ok(())
}
```

Wandeln Sie eine Legacy-`Transaction` mit `.into()` um. Legacy- und v0-Transaktionen funktionieren
mit jedem SDK-Feature; v1-Transaktionen erfordern `sdk-v4`.

### Signer-Funktionen

| Backend                              | Capability-Trait    | `sign_message`                  |
| ------------------------------------ | ------------------- | ------------------------------- |
| Crossmint                            | `SendingSigner`     | Nicht unterstützt                   |
| Fordefi Native Auto                  | `SendingSigner`     | Ja                             |
| Fordefi Native Manual                | `ModifyingSigner`   | Ja                             |
| Utila                                | `TransactionSigner` | Nicht unterstützt                   |
| CDP                                  | `TransactionSigner` | Nur UTF-8-Payloads             |
| Ledger                               | `TransactionSigner` | Ja, über einen Off-Chain-Envelope |
| Alle anderen (inkl. Fordefi Black Box) | `TransactionSigner` | Ja                             |

Die `Signer::from_*`-Konstruktoren führen `init()` für Sie aus. Wenn Sie die Signer-Typen für
Privy, Fireblocks, Dfns, Crossmint, Para, Openfort oder Utila
direkt erzeugen, rufen Sie vor der Verwendung `init().await` auf.

## Backend-Konfiguration

### Memory Signer

Für Entwicklung und Tests mit lokalen keypairs:

```rust
use solana_keychain::Signer;

// From base58 private key
let signer = Signer::from_memory("base58_private_key")?;

// From JSON keypair file path
let signer = Signer::from_memory_file("/path/to/keypair.json")?;

// From byte array string
let signer = Signer::from_memory("[1,2,3,...]")?;
```

### HashiCorp Vault

Für selbst gehostetes HSM mit Transit-Engine:

```rust
use solana_keychain::Signer;

let signer = Signer::from_vault(
    "https://vault.example.com:8200".to_string(), // Vault address
    "hvs.xxxxx".to_string(),                      // Vault token
    "my-solana-key".to_string(),                  // Key name in Transit
    "base58_public_key".to_string(),              // Expected public key
    None,                                         // Default HTTP timeouts
)?;
```

### AWS KMS

Für Cloud-natives Signieren mit AWS KMS Ed25519-Schlüsseln:

```rust
use solana_keychain::Signer;

let signer = Signer::from_aws_kms(
    "alias/my-solana-key".to_string(),   // KMS key ID or alias
    "base58_public_key".to_string(),     // Expected public key
    Some("us-east-1".to_string()),       // Region (optional)
).await?;
```

### Privy

Für Embedded-Wallet-Signierung:

```rust
use solana_keychain::Signer;

let signer = Signer::from_privy(
    "app_id".to_string(),      // Privy app ID
    "app_secret".to_string(),  // Privy app secret
    "wallet_id".to_string(),   // Wallet ID
    None,                      // Default HTTP timeouts
).await?;
```

### Turnkey

Für nicht-verwahrende Signierung:

```rust
use solana_keychain::Signer;

let signer = Signer::from_turnkey(
    "api_public_key".to_string(),   // Turnkey API public key
    "api_private_key".to_string(),  // Turnkey API private key
    "org_id".to_string(),           // Organization ID
    "private_key_id".to_string(),   // Private key ID in Turnkey
    "base58_public_key".to_string(),// Expected public key
    None,                           // Default HTTP timeouts
)?;
```

### Fireblocks

Für institutionelles MPC-Signing:

```rust
use solana_keychain::{Signer, FireblocksSignerConfig};

let config = FireblocksSignerConfig {
    api_key: "api_key".to_string(),
    private_key_pem: "-----BEGIN RSA PRIVATE KEY-----\n...".to_string(),
    vault_account_id: "0".to_string(),
    asset_id: Some("SOL".to_string()), // None defaults to "SOL"; "SOL_TEST" for devnet
    api_base_url: None,
    poll_interval_ms: None,
    max_poll_attempts: None,
    use_program_call: None, // Some(true) signs via PROGRAM_CALL (sign-only, legacy/v0, hot wallet)
    http_client_config: None,
};

let signer = Signer::from_fireblocks(config).await?;
```

### GCP KMS

Für cloud-natives Signing mit GCP Cloud KMS Ed25519-Schlüsseln:

```rust
use solana_keychain::Signer;

let signer = Signer::from_gcp_kms(
    "projects/my-project/locations/us-east1/keyRings/my-ring/cryptoKeys/my-key/cryptoKeyVersions/1".to_string(),
    "base58_public_key".to_string(),
).await?;
```

### CDP (Coinbase Developer Platform)

Für Coinbase Managed Wallet Signing:

```rust
use solana_keychain::{Signer, CdpSignerConfig, CDP_NETWORK_MAINNET};

let signer = Signer::from_cdp(CdpSignerConfig {
    api_key_id: "api_key_id".to_string(),           // CDP API key ID
    api_key_secret: "api_key_secret".to_string(),   // CDP API private key (base64 Ed25519)
    wallet_secret: "wallet_secret".to_string(),     // CDP wallet secret (base64 PKCS#8 DER)
    address: "base58_address".to_string(),          // Solana account address
    network: Some(CDP_NETWORK_MAINNET.to_string()), // Required to sign transactions with address lookup tables
    api_base_url: None,
    http_client_config: None,                       // Default HTTP timeouts
})?;
```

`sign_message` von CDP akzeptiert nur UTF-8-Payloads.

### Crossmint

Crossmint unterstützt nur das Senden: Die API führt jede genehmigte Transaktion
serverseitig aus, daher gibt es keinen reinen Signierpfad, und `sign_message` schlägt fehl. Rufen Sie
`sign_and_send_transaction` auf; dies lässt Ihre Transaktion unverändert und gibt
die Signatur der Transaktion zurück, die tatsächlich verarbeitet wurde. Diese Transaktion kann von
Ihrer abweichen, wenn Crossmint Gas sponsert.

```rust
use solana_keychain::{Signer, CrossmintSignerConfig};

let config = CrossmintSignerConfig {
    api_key: "api_key".to_string(),
    wallet_locator: "wallet_locator".to_string(),
    signer_secret: None,
    signer: None,
    api_base_url: None,
    poll_interval_ms: None,
    max_poll_attempts: None,
};

let signer = Signer::from_crossmint(config).await?;

let signature = signer
    .as_sending_signer()
    .expect("Crossmint is a sending signer")
    .sign_and_send_transaction(&tx)
    .await?;
```

### Fordefi

Für das Signieren mit Fordefi-MPC-Verwahrung. API-Anfragen werden mit einer ECDSA-
P-256-Anfragesignatur authentifiziert. Geben Sie genau eines von `private_key_pem` oder
`request_signer` (ein `Arc<dyn FordefiRequestSigner>`, um diesen Schlüssel in einem
KMS/HSM zu belassen) an.

Fordefi gibt es in drei Signer-Typen, die bei der Erzeugung durch `chain` und
`push_mode` festgelegt werden:

| `chain`    | `push_mode`      | Typ                        | Capability          | Verhalten                                                           |
| ---------- | ---------------- | --------------------------- | ------------------- | ------------------------------------------------------------------ |
| `None`     | beliebig              | `FordefiBlackBoxSigner`     | `TransactionSigner` | Signiert Rohbytes; Sie senden selbst                                     |
| `Some(..)` | `None` oder `Auto` | `FordefiNativeAutoSigner`   | `SendingSigner`     | Fordefi kann den Blockhash und die Fee umschreiben, signiert und sendet   |
| `Some(..)` | `Manual`         | `FordefiNativeManualSigner` | `ModifyingSigner`   | Fordefi schreibt um und signiert; Sie senden die zurückgegebene Transaktion |

Der Native-Manual-Modus ersetzt Ihre Transaktion durch die von Fordefi signierte.
Machen Sie damit weiter, niemals mit der von Ihnen erstellten. Er muss vor jedem anderen
erforderlichen Signer ausgeführt werden.

```rust
use solana_keychain::{
    Signer, FordefiSignerConfig, FordefiPushMode, SolanaChainUniqueId, FordefiSolanaFee,
    FordefiPriorityLevel,
};

let config = FordefiSignerConfig {
    access_token: "api_token".to_string(),
    vault_id: "vault_uuid".to_string(),
    private_key_pem: Some(std::fs::read_to_string("./secret/private.pem")?),
    request_signer: None,                           // Or Some(Arc::new(your_kms_signer))
    public_key: "base58_public_key".to_string(),    // Solana vault address
    chain: Some(SolanaChainUniqueId::SolanaDevnet), // None for black box mode
    fee: Some(FordefiSolanaFee::Priority {
        priority_level: FordefiPriorityLevel::Medium,
    }),
    push_mode: Some(FordefiPushMode::Auto),         // Manual: sign without broadcasting
    api_base_url: None,       // Default: https://api.fordefi.com
    poll_interval_ms: None,   // Default: 2000
    max_poll_attempts: None,  // Default: 50
    http_client_config: None, // Default HTTP timeouts
};

let signer = Signer::from_fordefi(config).await?;
```

### Ledger

Für das Signieren mit Hardware-Wallets über USB-HID (nur Rust). Erfordert das `ledger`-
Feature, ein entsperrtes Gerät mit der Solana-App und unter Linux die udev-Regeln von Ledger.
Ledger ist vom aktuellen Audit nicht abgedeckt; siehe
[Audit-Status](https://github.com/solana-foundation/solana-keychain/blob/main/audits/AUDIT_STATUS.md).

```rust
use solana_keychain::{LedgerConfig, Signer};

let signer = Signer::from_ledger(LedgerConfig {
    confirm_pubkey_on_device: true,
    ..LedgerConfig::default()
})
.await?;
```

`sign_message` signiert einen Off-Chain-Envelope, der Ihre Payload umschließt, nicht die rohen
Bytes; erstellen Sie ihn mit `solana_keychain::ledger::ledger_offchain_envelope` neu, um
zu verifizieren. Setzen Sie `auto_open_app: false` für den unbeaufsichtigten Betrieb. Eine auf dem
Gerät abgelehnte Aufforderung gibt `SignerError::UserRejected` zurück.

## Unified Signer Enum

Verwenden Sie das `Signer` Enum, um Backends zur Laufzeit auszuwählen:

```rust
use solana_keychain::{Signer, SolanaSigner, SignerError};

async fn get_signer(backend: &str) -> Result<Signer, SignerError> {
    match backend {
        "memory" => Signer::from_memory("base58_key"),
        "vault" => Signer::from_vault(/* ... */),
        "kms" => Signer::from_aws_kms(/* ... */).await,
        _ => Err(SignerError::ConfigError("Unknown backend".into())),
    }
}

// Use it generically
let signer = get_signer("kms").await?;
let pubkey = signer.pubkey();
```

`Signer` implementiert nur `SolanaSigner`. Eine Capability erreichen Sie über
`as_transaction_signer()`, `as_modifying_signer()` oder `as_sending_signer()`;
diese geben `None` zurück, wenn dem Backend diese Form fehlt:

```rust
if let Some(transaction_signer) = signer.as_transaction_signer() {
    let result = transaction_signer.sign_transaction(&mut tx).await?;
}
```

Oder lassen Sie `sign_and_send` nach Backend routen. Die Crate enthält keinen RPC-Client, daher
stellen Sie das Senden bereit; bei einem sendenden Backend wird die Closure nie aufgerufen:

```rust
let signature = signer
    .sign_and_send(&mut tx, |encoded| async move { broadcast(encoded).await })
    .await?;
```

## Fehlerbehandlung

`SignerError::BroadcastUnconfirmed { provider_tx_id, idempotency_key, transaction_signature, .. }`
(von Crossmint, Fordefi Native Auto oder einer fehlschlagenden `sign_and_send`-Closure)
bedeutet, dass die Transaktion möglicherweise verarbeitet wurde. Wiederholen Sie nicht blind: Gleichen Sie zuerst
`provider_tx_id` oder `transaction_signature` ab, oder senden Sie nur die
byteidentische Transaktion erneut. Erschöpfende `match`-Ausdrücke auf `SignerError` benötigen diesen Zweig.
Was jede Signierform garantiert, steht im
[Sicherheitsmodell](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md).
