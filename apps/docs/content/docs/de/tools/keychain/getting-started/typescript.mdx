## Installation

Installieren Sie das Umbrella-Paket oder einzelne Signer nach Bedarf:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Erfordert `@solana/kit` 8.1 oder höher. v1-Transaktionen
(`createTransactionMessage({ version: 1 })`) werden unterstützt, außer von Fireblocks
mit `useProgramCall: true`, das nur Legacy und v0 akzeptiert.

## Grundlegende Verwendung

### Einheitliche Factory (Empfohlen für Apps, die mehrere Signer unterstützen möchten)

Verwenden Sie `createKeychainSigner` mit einer diskriminierten Konfiguration, um
ein beliebiges Backend zu erstellen:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Oder installieren Sie ein einzelnes Signer-Paket für einen kleineren
Dependency-Footprint:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Verwendung mit Transaktionsnachrichten

Jedes Backend außer Crossmint und dem nativen Modus von Fordefi gibt einen
`SolanaTransactionSigner` zurück, der ein Kit-`TransactionPartialSigner` ist und mit
den unten aufgeführten Partial-Signer-Helfern aus `@solana/signers` funktioniert. Backends mit verwaltetem Broadcast
werden unter [Signer-Fähigkeiten](#signer-capabilities) behandelt.

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Mit jedem Signer signieren und senden

`signAndSendTransaction` aus `@solana/keychain-core` bringt eine Transaktion
unabhängig von der Form des Signers on-chain. Sendende Signer übertragen über ihren
Anbieter; jede andere Form verwendet die von dir übergebene Funktion `sendTransaction` (Core hat keine
RPC-Abhängigkeit):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Verwendung mit einem Kit-Client (keychainSigner-Plugin)

`@solana/keychain-kit-plugin` installiert einen Keychain-Signer direkt auf einem
[Kit-Client](https://github.com/anza-xyz/kit) und richtet ihn als `payer` und
`identity` ein, sodass die manuelle `pipe`-Einrichtung wie oben beschrieben
entfällt:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Das Plugin akzeptiert dieselbe Backend-getaggte Konfiguration wie `createKeychainSigner`,
mit Ausnahme von Crossmint und dem nativen Modus von Fordefi (`chain` gesetzt). Diese Backends schreiben
die Transaktion serverseitig um, daher können sie nicht als Client-`payer` oder
`identity` fungieren; das Plugin lehnt sie zur Kompilierzeit und zur Laufzeit ab. Nur das
Backend, an das delegiert wird, wird gebündelt (Backend-Pakete werden über dynamisches
`import()` geladen).

Verwende `keychainPayer` oder `keychainIdentity`, um nur eine Rolle festzulegen,
und kombiniere Backends auf einem einzelnen Client:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Du hast bereits einen `SolanaTransactionSigner`? Er ist ein gültiger Kit-
`TransactionPartialSigner`, daher kannst du ihn stattdessen mit
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
installieren (`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Abbruch und unbestätigte Broadcasts

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` und
`signMessages` akzeptieren alle `{ abortSignal }` als zweites Argument. Ein Abbruch
beendet das Warten; er macht keine Arbeit rückgängig, die ein Anbieter bereits angenommen hat.

Bei Crossmint und Fordefi im nativen Auto-Modus bedeutet ein Fehler nicht, dass nichts
angekommen ist. Wenn der Anbieter die Transaktion möglicherweise akzeptiert hat, lautet der Fehlercode
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` ist gesetzt, wenn die Erstellung akzeptiert wurde, und
`context.idempotencyKey` enthält den aus der Nachricht abgeleiteten Schlüssel. Das erneute Senden der
bytegleichen Transaktion ist sicher; eine neu erstellte (zum Beispiel mit einem neuen
Blockhash) ist eine neue Überweisung. `providerMayHaveAccepted(error)` und
`providerStatus(error)` aus `@solana/keychain-core` helfen bei der Klassifizierung des Fehlers.
Gleiche den Stand mit dem Anbieter ab, bevor du es erneut versuchst.

### Crossmint

```typescript
import { createCrossmintSigner } from "@solana/keychain-crossmint";

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmint unterstützt nur Senden. Die API führt eine genehmigte Transaktion immer
serverseitig aus und übernimmt die Gasgebühren, daher stellt der Signer nur
`signAndSendTransactions()` bereit: Er hat weder `signTransactions()` noch `signMessages()`
und lässt sich nicht mit `@solana/keychain-kit-plugin` installieren. Die zurückgegebene
Signatur identifiziert die Transaktion, die Crossmint on-chain gebracht hat.

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

Fordefi hat drei Signiermodi, die bei der Erstellung durch `chain` und
`pushMode` festgelegt werden. Jeder Modus stellt genau eine Transaktionsmethode bereit, und alle drei signieren
Nachrichten:

| Modus          | Konfiguration                                      | Typ                        | Methode                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Blackbox     | `chain` nicht gesetzt                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Nativ automatisch   | `chain` gesetzt, `pushMode` weggelassen oder `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Nativ manuell | `chain` gesetzt, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

API-Anfragen werden mit einer ECDSA-P-256-Anfragesignatur authentifiziert: Übergib den
Signierschlüssel als `privateKeyPem` oder bewahre ihn in einem KMS/HSM auf, indem du einen
`requestSigner` übergibst.

**Nativer Auto-Modus** (empfohlen für die On-Chain-Nutzung): Setze `chain`, und Fordefi
signiert und überträgt die Transaktion selbst. Da Fordefi vor dem Signieren den
Blockhash oder die Fee ersetzen kann, ist der Signer ein Kit-
`TransactionSendingSigner`: Verwende ihn mit
`signAndSendTransactionMessageWithSigners`, nicht mit dem oben gezeigten Partial-Signer-Ablauf.
Der native Auto-Modus akzeptiert nur eine unsignierte Transaktion, deren einziger erforderlicher
Signer der Vault ist, und er kann nicht mit `@solana/keychain-kit-plugin` verwendet werden.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Nativer manueller Modus**: Setze `chain` und `pushMode: "manual"`. Fordefi schreibt
die Nachricht um (aktueller Blockhash, Compute-Budget-Fee-Anweisungen) und signiert sie,
überträgt sie aber nicht. `modifyAndSignTransactions()` gibt die von
Fordefi signierte Transaktion zurück, die die von dir eingereichte ersetzt: Mache immer mit der
zurückgegebenen Transaktion weiter. Fordefi muss der Fee Payer sein und vor jedem
anderen erforderlichen Signer signieren. Das Umschreiben wird nicht per Diff dargestellt, also prüfe das Ergebnis vor dem
Broadcast.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Black-Box-Modus**: Lassen Sie `chain` weg. Fordefi signiert rohe Bytes und sendet diese nicht; Sie stellen die Transaktion selbst zusammen und übermitteln sie. Verwenden Sie dies mit einem Fordefi-Black-Box-Vault.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Signer-Fähigkeiten

`@solana/keychain-core` definiert für jede Kit-Signer-Form ein Interface. Jedes ergänzt
`isAvailable(): Promise<boolean>` im passenden `@solana/signers`-Interface:

- `SolanaTransactionSigner` (Kit-`TransactionPartialSigner`): gibt Signaturen
  für eine Transaktion zurück, die dir gehört.
- `SolanaModifyingSigner` (Kit-`TransactionModifyingSigner`): schreibt die
  Transaktion um, signiert sie und gibt die neue Transaktion ohne Broadcast zurück.
- `SolanaSendingSigner` (Kit-`TransactionSendingSigner`): signiert und überträgt
  über seinen Anbieter.
- `SolanaMessageSigner` (Kit-`MessagePartialSigner`): signiert Off-Chain-Nachrichten.
  Dies ist getrennt von den Transaktionsformen.

`SolanaSigner` ist die Vereinigung der drei Transaktionsformen. Der Rückgabetyp jeder Factory
benennt die exakte Form ihres Backends. Wenn die Konfiguration erst zur
Laufzeit bekannt ist, grenze mit `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` oder `isSolanaMessageSigner` ein. `signerCapabilities(signer)`
meldet alle vier auf einmal.

| Backend                                                                                                     | Form                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (Blackbox) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (keine Nachrichtensignierung)  |
| fordefi (nativ manuell)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (nativ automatisch)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (keine Nachrichtensignierung)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Benutzerdefinierte Signer erstellen

Implementiere die Capability-Interfaces, die dein Backend unterstützt:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Implementiere nur, was dein Backend unterstützt. Kit klassifiziert Signer danach, welche
Methoden vorhanden sind, also füge niemals eine Methode hinzu, die nur einen Fehler wirft.

Weitere Informationen zur Integration zusätzlicher Schlüsselverwaltungsdienste
findest du im
[Leitfaden zum Hinzufügen von Signern](/docs/tools/keychain/adding-signers).
