---
title: Konfiguration
description: Setter-Methoden zur Konfiguration von LiteSVM in Go
---

Jeder Setter spiegelt die entsprechende Builder-Methode des Rust-Typs `LiteSVM` wider.
Änderungen treten sofort in Kraft und geben einen `error` zurück.

## Typisches Test-Setup

```go
svm, err := litesvm.New()
if err != nil {
    t.Fatal(err)
}
defer svm.Close()

// Each setter returns an error. The calls below are infallible in practice,
// so the docs use _ = ... for brevity; check the error in production code.
_ = svm.SetSigverify(false)        // skip signature verification (faster)
_ = svm.SetBlockhashCheck(false)   // skip blockhash validation (simpler)
_ = svm.SetSysvars()               // reset Clock, Rent, etc. to defaults
_ = svm.SetBuiltins()              // reload built-in programs
_ = svm.SetTransactionHistory(100) // keep the last 100 transactions
```

## Signatur und Blockhash

### SetSigverify

```go
func (s *LiteSVM) SetSigverify(enabled bool) error
```

Transaktionssignaturprüfung aktivieren oder deaktivieren.

```go
if err := svm.SetSigverify(false); err != nil { // accept unsigned / badly-signed txs
    t.Fatal(err)
}
if err := svm.SetSigverify(true); err != nil {  // restore production-like behavior
    t.Fatal(err)
}
```

<Callout type="info">
  Das Deaktivieren der Signaturprüfung macht Tests schneller, aber weniger realitätsnah.
</Callout>

### Sigverify

```go
func (s *LiteSVM) Sigverify() (bool, error)
```

Aktuelle Einstellung auslesen.

### SetBlockhashCheck

```go
func (s *LiteSVM) SetBlockhashCheck(enabled bool) error
```

Prüfung des aktuellen Blockhash bei eingereichten Transaktionen aktivieren oder deaktivieren.

```go
if err := svm.SetBlockhashCheck(false); err != nil { // accept any blockhash
    t.Fatal(err)
}
```

## Programme und Sysvars

### SetSysvars

```go
func (s *LiteSVM) SetSysvars() error
```

Die eingebauten Sysvars (Clock, rent, EpochSchedule, ...) auf ihre
Standardwerte zurücksetzen.

### SetBuiltins

```go
func (s *LiteSVM) SetBuiltins() error
```

Den Standardsatz eingebauter Programme laden.

### SetDefaultPrograms

```go
func (s *LiteSVM) SetDefaultPrograms() error
```

Die Standard-SPL-Programme laden (System Program, SPL Token, Memo, ...).

### SetPrecompiles

```go
func (s *LiteSVM) SetPrecompiles() error
```

Die vorkompilierten Programme ed25519 / secp256k1 aktivieren.

### WithNativeMints

```go
func (s *LiteSVM) WithNativeMints() error
```

Die nativen Mint-Konten von SPL Token / Token-2022 (wrapped SOL) mit seed befüllen. Kein Effekt, wenn das
zugehörige Programm nicht geladen ist; rufe zuerst `SetDefaultPrograms` auf, wenn du
beides möchtest.

## Ressourcenlimits

### SetLamports

```go
func (s *LiteSVM) SetLamports(lamports uint64) error
```

Den Standard-lamport-Kontostand des internen Airdrop-Pool-Kontos festlegen.

```go
if err := svm.SetLamports(1 << 40); err != nil { // ~1.1 trillion lamports (~1,100 SOL)
    t.Fatal(err)
}
```

### SetLogBytesLimit

```go
func (s *LiteSVM) SetLogBytesLimit(limit int) error
```

Die gesamten protokollierten Bytes pro Transaktion begrenzen. Ein negativer Wert
hebt das Limit auf.

```go
if err := svm.SetLogBytesLimit(10_000); err != nil { // 10 KB cap
    t.Fatal(err)
}
if err := svm.SetLogBytesLimit(-1); err != nil {     // unlimited
    t.Fatal(err)
}
```

### SetTransactionHistory

```go
func (s *LiteSVM) SetTransactionHistory(capacity int) error
```

Die Kapazität des In-Memory-Transaktionsverlaufs festlegen. Übergib `0`, um die Deduplizierung zu deaktivieren
und das erneute Abspielen identischer Transaktionen zu erlauben.

```go
if err := svm.SetTransactionHistory(100); err != nil { // cap at 100 entries
    t.Fatal(err)
}
if err := svm.SetTransactionHistory(0); err != nil {   // disable dedup entirely
    t.Fatal(err)
}
```

## Compute Budget

```go
type ComputeBudget struct {
    // See litesvm-go/litesvm.go for the full field list.
    // usize fields are normalized to uint64; HeapSize stays uint32.
    ComputeUnitLimit uint64
    HeapSize         uint32
    // ...
}
```

### ComputeBudget

```go
func (s *LiteSVM) ComputeBudget() (ComputeBudget, bool, error)
```

Das aktuelle Compute Budget auslesen. Der zweite Rückgabewert gibt an, ob ein
Budget explizit gesetzt wurde; ist er `false`, enthält das Struct die Standardwerte,
die verwendet werden.

```go
budget, set, err := svm.ComputeBudget()
if err != nil {
    t.Fatal(err)
}
if !set {
    budget.ComputeUnitLimit = 1_400_000
}
if err := svm.SetComputeBudget(budget); err != nil {
    t.Fatal(err)
}
```

### SetComputeBudget

```go
func (s *LiteSVM) SetComputeBudget(b ComputeBudget) error
```

Ein Compute Budget für nachfolgende Transaktionen festlegen.

## Feature-Sets

`FeatureSet` ist ein undurchsichtiges Handle – erzeuge es, verändere es mit `Activate` /
`Deactivate`, und installiere es anschließend mit `SetFeatureSet`. Schließe selbst erstellte Handles.

```go
// Start with all features off, then activate what you care about.
fs, err := litesvm.NewFeatureSet()
if err != nil {
    t.Fatal(err)
}
defer fs.Close()
if err := fs.Activate(featureID, 0); err != nil {
    t.Fatal(err)
}

// Or start from "everything enabled" and flip specific features off.
fs2, err := litesvm.NewFeatureSetAllEnabled()
if err != nil {
    t.Fatal(err)
}
defer fs2.Close()
if err := fs2.Deactivate(featureID); err != nil {
    t.Fatal(err)
}

if err := svm.SetFeatureSet(fs); err != nil {
    t.Fatal(err)
}
```

| Methode                                                   | Beschreibung                       |
| -------------------------------------------------------- | --------------------------------- |
| `litesvm.NewFeatureSet() (*FeatureSet, error)`           | Leeres Set (alle Features inaktiv) |
| `litesvm.NewFeatureSetAllEnabled() (*FeatureSet, error)` | Alle Features aktiv               |
| `fs.Activate(featureID, slot) error`                     | Feature ab slot als aktiv markieren       |
| `fs.Deactivate(featureID) error`                         | Feature als inaktiv markieren             |
| `fs.IsActive(featureID) bool`                            | Aktivitätsprüfung                      |
| `fs.ActivatedSlot(featureID) (uint64, bool)`             | slot, in dem ein Feature aktiviert wurde   |
| `fs.ActiveCount() int`                                   | Anzahl aktiver Features              |
| `fs.InactiveCount() int`                                 | Anzahl inaktiver Features            |
| `fs.ActiveFeatures() []solana.PublicKey`                 | Aktive Feature-IDs auflisten           |
| `fs.InactiveFeatures() []solana.PublicKey`               | Inaktive Feature-IDs auflisten         |
| `fs.Close()`                                             | Handle freigeben                |
| `svm.SetFeatureSet(*FeatureSet) error`                   | In der SVM installieren                |

<Callout type="info">
  Nutze Feature-Gating, um das Verhalten von Programmen unter einer bestimmten Solana-Version zu testen
  – aktiviere die Features, die mit dem angestrebten Release ausgeliefert wurden, und
  deaktiviere alle, die erst später hinzugekommen sind.
</Callout>
