Token Extensions -laajennus ja Transfer Hook Interface mahdollistavat
Mint Account -tilien luomisen, jotka suorittavat mukautettua käskylogiikkaa jokaisessa token-siirrossa.

Tämä avaa monia uusia käyttötapauksia token-siirroille, kuten:

- NFT-rojaltien pakottaminen
- Tokeneja vastaanottavien lompakoiden musta- tai valkolistaus
- Mukautettujen maksujen toteuttaminen token-siirroissa
- Mukautettujen token-siirtotapahtumien luominen
- Tilastojen seuranta token-siirroistasi
- Ja paljon muuta

Tämän saavuttamiseksi kehittäjien on rakennettava ohjelma, joka toteuttaa
[Transfer Hook Interface](https://github.com/solana-labs/solana-program-library/tree/master/token/transfer-hook/interface)
-rajapinnan ja alustettava Mint Account, jossa Token Extensions -laajennus on käytössä.

Jokaista Token Extensions Program -ohjelman kautta tapahtuvaa token-siirtoa varten ohjelma tekee Cross Program Invocation (CPI) -kutsun suorittaakseen käskyn Transfer Hook -ohjelmassa.

<Callout type="info">

Kun Token Extensions Program tekee CPI-kutsun Transfer Hook -ohjelmaan, kaikki alkuperäisen siirron tilit muunnetaan vain luku -tileiksi. Tämä tarkoittaa, että lähettäjän allekirjoitusoikeudet eivät ulotu Transfer Hook -ohjelmaan.

Tämä suunnittelupäätös on tehty estämään Transfer Hook -ohjelmien haitallinen käyttö.

</Callout>

Tässä oppaassa luomme Transfer Hook -ohjelman käyttäen Anchor-kehystä,
mutta Transfer Hook Interface on mahdollista toteuttaa myös natiiviohjelmalla. Lue lisää Anchor-kehyksestä täältä:
[Anchor Framework](https://www.anchor-lang.com/)

## Transfer Hook Interface -yleiskatsaus

Transfer Hook Interface tarjoaa kehittäjille tavan toteuttaa mukautettua
käskylogiikkaa, joka suoritetaan jokaisessa token-siirrossa tietylle Mint Account -tilille.

Transfer Hook Interface määrittelee seuraavat
[käskyt](https://github.com/solana-labs/solana-program-library/blob/master/token/transfer-hook/interface/src/instruction.rs):

- `Execute`: Käsky, jonka Token Extensions Program käynnistää jokaisessa
  token-siirrossa.
- `InitializeExtraAccountMetaList` (valinnainen): Luo tilin, joka tallentaa
  luettelon mukautetun `Execute`-käskyn vaatimista lisätileistä.
- `UpdateExtraAccountMetaList` (valinnainen): Päivittää lisätilien luettelon
  korvaamalla olemassa olevan luettelon.

Teknisesti `InitializeExtraAccountMetaList`-käskyn toteuttaminen rajapintaa käyttäen
ei ole pakollista. Tilin voi luoda mikä tahansa Transfer Hook -ohjelman käsky.

Program Derived Address (PDA) tilille on kuitenkin johdettava
seuraavien seed-arvojen avulla:

- Kovakoodattu merkkijono "extra-account-metas"
- Mint Account -osoite
- Transfer Hook -ohjelman tunnus

```js
const [pda] = PublicKey.findProgramAddressSync(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBuffer()],
  program.programId // transfer hook program ID
);
```

Tallentamalla `Execute`-käskyn vaatimat lisätilit ennalta määriteltyyn PDA-osoitteeseen,
nämä tilit voidaan lisätä automaattisesti asiakkaan token-siirtokäskyyn.

## Hello-world Transfer hook

Tämä esimerkki on transfer hook -toiminnon hello world. Se on yksinkertainen transfer hook,
joka tulostaa viestin jokaisessa token-siirrossa. Aloitamme avaamalla
esimerkin Solana Playgroundissa, verkkopohjainen työkalu Solana-ohjelmien rakentamiseen ja julkaisemiseen:
[link](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/hello_world)

Esimerkki koostuu Anchor-ohjelmasta, joka toteuttaa transfer hook
-rajapinnan, sekä testitiedostosta ohjelman testaamiseksi.

Tämä ohjelma sisältää vain 3 käskyä:

1. `initialize_extra_account_meta_list`: Luo tilin, joka tallentaa luettelon
   `transfer_hook`-käskyn vaatimista lisätileistä. Hello world -esimerkissä
   jätämme tämän tyhjäksi.
2. `transfer_hook`: Tämä käsky käynnistetään CPI:n kautta jokaisessa token-siirrossa
   käärityn SOL-tokenin siirron suorittamiseksi.
3. `fallback`: Koska käytämme Anchoria ja token-ohjelma on natiivi
   ohjelma, meidän on lisättävä fallback-käsky manuaalisesti vastaamaan
   käskyn erottajaa ja käynnistämään mukautettu `transfer_hook`-käsky.
   Tätä funktiota ei tarvitse muuttaa.

Aina kun token siirretään, token-ohjelma kutsuu tätä `transfer_hook`-funktiota.

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    Ok(())
}
```

Tässä funktiossa voit nyt lisätä omaa logiikkaasi. Voit esimerkiksi
estää siirron aina kun siirrettävä summa on suurempi kuin 50
seuraavasti:

```rust
#[error_code]
pub enum MyError {
    #[msg("The amount is too big")]
    AmountTooBig,
}

pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    if amount > 50 {
        return err!(MyError::AmountTooBig);
    }

    Ok(())
}
```

## Counter Transfer hook

Seuraava esimerkki näyttää, kuinka voit kasvattaa laskuria aina kun
tokenisi on siirretty.
[link](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/counter)

Jos haluat lisätä transfer hook -toimintoon logiikkaa, joka tarvitsee lisätilejä,
sinun on lisättävä ne ExtraAccountMetaList-tilille. Tässä tapauksessa
haluamme PDA:n, joka tallentaa kuinka monta kertaa token on siirretty.

Tämä voidaan tehdä lisäämällä seuraava koodi
`initialize_extra_account_meta_list`-käskyyn:

```rust
let account_metas = vec![
    ExtraAccountMeta::new_with_seeds(
        &[Seed::Literal {
            bytes: "counter".as_bytes().to_vec(),
        }],
        false, // is_signer
        true,  // is_writable
    )?,
];
```

Lisäksi meidän on luotava tämä tili, kun alustamme uuden mint account -tilin,
ja meidän on välitettävä se joka kerta, kun siirretään token.

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        init_if_needed,
        seeds = [b"counter"],
        bump,
        payer = payer,
        space = 16
    )]
    pub counter_account: Account<'info, CounterAccount>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(
        token::mint = mint,
        token::authority = owner,
    )]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        token::mint = mint,
    )]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(
        mut,
        seeds = [b"counter"],
        bump
    )]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Ja tili sisältää `u64`-laskurimuuttujan:

```rust
#[account]
pub struct CounterAccount {
    counter: u64,
}
```

Nyt transfer hook -funktiossa voimme kasvattaa tätä laskuria yhdellä aina
kun sitä kutsutaan:

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {
```

Koska tässä kasvatamme laskuria aina kun token siirretään, meidän on
varmistettava, että transfer hook -käskyä voidaan kutsua vain siirron aikana,
muuten joku voisi kutsua transfer hook -käskyä suoraan ja sekoittaa

Voit lisätä tarkistuksen seuraavasti:

```rust
fn assert_is_transferring(ctx: &Context<TransferHook>) -> Result<()> {
    let source_token_info = ctx.accounts.source_token.to_account_info();
    let mut account_data_ref: RefMut<&mut [u8]> = source_token_info.try_borrow_mut_data()?;
    let mut account = PodStateWithExtensionsMut::<PodAccount>::unpack(*account_data_ref)?;
    let account_extension = account.get_extension_mut::<TransferHookAccount>()?;

    if !bool::from(account_extension.transferring) {
        return err!(TransferError::IsNotCurrentlyTransferring);
    }

    Ok(())
}
```

Ja kutsu sitä sitten `transfer_hook`-funktiosi alussa:

```rust
    #[error_code]
    pub enum TransferError {
        #[msg("The token is not currently transferring")]
        IsNotCurrentlyTransferring,
    }

    #[interface(spl_transfer_hook_interface::execute)]
    pub fn transfer_hook(ctx: Context<TransferHook>, _amount: u64) -> Result<()> {
        // Fail this instruction if it is not called from within a transfer hook
        assert_is_transferring(&ctx)?;

        ctx.accounts.counter_account.counter.checked_add(1).unwrap();
        msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

        Ok(())
    }
```

## Transfer Hook wSOL-siirtomaksulla (edistynyt esimerkki)

Oppaan seuraavassa osassa rakennamme kehittyneemmän Transfer Hook -ohjelman
käyttäen Anchor-kehystä. Tämä ohjelma vaatii lähettäjää maksamaan wSOL-maksun
jokaisesta token-siirrosta.

wSOL-siirrot suoritetaan käyttäen delegaattia, joka on Transfer Hook -ohjelmasta
johdettava PDA. Tämä on välttämätöntä, koska alkuperäisen token-siirtokäskyn
lähettäjän allekirjoitus ei ole käytettävissä Transfer Hook -ohjelmassa.

Tämä ohjelma sisältää vain 3 käskyä:

1. `initialize_extra_account_meta_list`: Luo tilin, joka tallentaa luettelon
   `transfer_hook`-käskyn vaatimista lisätileistä.
2. `transfer_hook`: Tämä käsky käynnistetään CPI:n kautta jokaisessa token-siirrossa
   käärityn SOL-tokenin siirron suorittamiseksi.
3. `fallback`: Transfer Hook Interface -käskyillä on erityiset
   erottajat (käskyn tunnisteet). Anchor-ohjelmassa voimme käyttää
   fallback-käskyä manuaalisesti vastaamaan käskyn erottajaa ja
   käynnistämään mukautetun `transfer_hook`-käskymme.

Tämä ohjelma vaatii lähettäjää maksamaan maksun käärityssä SOL:ssa (wSOL) jokaisesta
token-siirrosta. Tässä on
[valmis ohjelma](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/main).

### Initialize ExtraAccountMetas Account -käsky

Tässä vaiheessa toteutamme `initialize_extra_account_meta_list`
-käskyn Transfer Hook -ohjelmallemme. Tämä käsky luo
ExtraAccountMetas-tilin, johon tallennetaan `transfer_hook`-käskymme
vaatimat lisätilit.

Tässä esimerkissä `initialize_extra_account_meta_list`-käsky vaatii 7
tiliä:

- `payer`: Tili, jota käytetään ExtraAccountMetas-tilin luomisesta
  aiheutuvien kulujen maksamiseen.
- `extra_account_meta_list`: ExtraAccountMetas-tili, joka luodaan tallentamaan
  luettelo `transfer_hook`-käskymme vaatimista tileistä.
- `mint`: Mint Account, joka osoittaa tähän Transfer Hook -ohjelmaan. Mint-osoite
  on pakollinen seed `extra_account_meta_list`-PDA:n johtamisessa.
- `wsol_mint`: Kääritty SOL mint.
- `token_program`: Alkuperäinen Token Program -tunnus
- `associated_token_program`: Associated Token Program -tunnus.
- `system_program`: System Program, joka on pakollinen tili
  uusia tilejä luotaessa.

`mint`-, `wsol_mint`- ja `associated_token_program`-osoitteita käytetään
wSOL:n associated token account -tilien osoitteiden johtamiseen. Nämä
tilit ovat `transfer_hook`-käskyn vaatimia ja tallennetaan
ExtraAccountMetas-tilille.

Päivitä `InitializeExtraAccountMetaList`-rakenne korvaamalla seuraava
aloituskoodi:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList {}
```

Alla annetulla koodilla:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    pub wsol_mint: InterfaceAccount<'info, Mint>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}
```

Päivitä seuraavaksi `initialize_extra_account_meta_list`-käsky korvaamalla
seuraava aloituskoodi:

```rust
pub fn initialize_extra_account_meta_list(
    ctx: Context<InitializeExtraAccountMetaList>,
) -> Result<()> {
    Ok(())
}
```

Alla olevalla koodilla:

```rust
pub fn initialize_extra_account_meta_list(
        ctx: Context<InitializeExtraAccountMetaList>,
    ) -> Result<()> {
        // index 0-3 are the accounts required for token transfer (source, mint, destination, owner)
        // index 4 is address of ExtraAccountMetaList account
        // The `addExtraAccountsToInstruction` JS helper function resolving incorrectly
        let account_metas = vec![
            // index 5, wrapped SOL mint
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.wsol_mint.key(), false, false)?,
            // index 6, token program
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.token_program.key(), false, false)?,
            // index 7, associated token program
            ExtraAccountMeta::new_with_pubkey(
                &ctx.accounts.associated_token_program.key(),
                false,
                false,
            )?,
            // index 8, delegate PDA
            ExtraAccountMeta::new_with_seeds(
                &[Seed::Literal {
                    bytes: "delegate".as_bytes().to_vec(),
                }],
                false, // is_signer
                false,  // is_writable
            )?,
            // index 9, delegate wrapped SOL token account
            ExtraAccountMeta::new_external_pda_with_seeds(
                7, // associated token program index
                &[
                    Seed::AccountKey { index: 8 }, // owner index (delegate PDA)
                    Seed::AccountKey { index: 6 }, // token program index
                    Seed::AccountKey { index: 5 }, // wsol mint index
                ],
                false, // is_signer
                true,  // is_writable
            )?,
            // index 10, sender wrapped SOL token account
            ExtraAccountMeta::new_external_pda_with_seeds(
                7, // associated token program index
                &[
                    Seed::AccountKey { index: 3 }, // owner index
                    Seed::AccountKey { index: 6 }, // token program index
                    Seed::AccountKey { index: 5 }, // wsol mint index
                ],
                false, // is_signer
                true,  // is_writable
            )?,
        ];

        // calculate account size
        let account_size = ExtraAccountMetaList::size_of(account_metas.len())? as u64;
        // calculate minimum required lamports
        let lamports = Rent::get()?.minimum_balance(account_size as usize);

        let mint = ctx.accounts.mint.key();
        let signer_seeds: &[&[&[u8]]] = &[&[
            b"extra-account-metas",
            &mint.as_ref(),
            &[ctx.bumps.extra_account_meta_list],
        ]];

        // create ExtraAccountMetaList account
        create_account(
            CpiContext::new(
                ctx.accounts.system_program.to_account_info(),
                CreateAccount {
                    from: ctx.accounts.payer.to_account_info(),
                    to: ctx.accounts.extra_account_meta_list.to_account_info(),
                },
            )
            .with_signer(signer_seeds),
            lamports,
            account_size,
            ctx.program_id,
        )?;

        // initialize ExtraAccountMetaList account with extra accounts
        ExtraAccountMetaList::init::<ExecuteInstruction>(
            &mut ctx.accounts.extra_account_meta_list.try_borrow_mut_data()?,
            &account_metas,
        )?;

        Ok(())
    }
```

### Mukautettu Transfer Hook -käsky

Seuraavaksi toteutetaan mukautettu `transfer_hook`-käsky. Tämä on käsky, jonka Token Extension -ohjelma kutsuu jokaisen token-siirron yhteydessä.

Tässä esimerkissä vaadimme wSOL-maksu jokaisen token-siirron yhteydessä. Yksinkertaisuuden vuoksi maksun määrä on yhtä suuri kuin token-siirron määrä.

Päivitä `TransferHook`-rakenne korvaamalla seuraava aloituskoodi:

```rust
// Require SOL fee on transfer, lamport fee is equal to transfer amount
// If this fails, the initial token transfer fails
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {
    msg!("Transfer WSOL using delegate PDA");

    let signer_seeds: &[&[&[u8]]] = &[&[b"delegate", &[ctx.bumps.delegate]]];

    // transfer WSOL from sender to delegate token account using delegate PDA
    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.to_account_info(),
            TransferChecked {
                from: ctx.accounts.sender_wsol_token_account.to_account_info(),
                mint: ctx.accounts.wsol_mint.to_account_info(),
                to: ctx.accounts.delegate_wsol_token_account.to_account_info(),
                authority: ctx.accounts.delegate.to_account_info(),
            },
        )
        .with_signer(signer_seeds),
        amount,
        ctx.accounts.wsol_mint.decimals,
```

### Varakäsky (Fallback Instruction)

Lopuksi meidän on lisättävä varakäsky Anchor-ohjelmaan käsittelemään CPI-kutsu Token Extensions -ohjelmalta.

Tämä vaihe on pakollinen, koska Anchorin generoimat käskyn erottimet poikkeavat Transfer Hook -rajapinnan käskyissä käytetyistä. `transfer_hook`-käskyn erotin ei vastaa Transfer Hook -rajapinnan erotinta.

Päivitä `fallback`-käsky korvaamalla seuraava aloituskoodi:

```rust
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    Ok(())
}
```

Alla olevalla päivitetyllä koodilla:

```rust
// fallback instruction handler as workaround to anchor instruction discriminator check
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    let instruction = TransferHookInstruction::unpack(data)?;

    // match instruction discriminator to transfer hook interface execute instruction
    // token2022 program CPIs this instruction on token transfer
    match instruction {
        TransferHookInstruction::Execute { amount } => {
            let amount_bytes = amount.to_le_bytes();

            // invoke custom transfer hook instruction on our program
            __private::__global::transfer_hook(program_id, accounts, &amount_bytes)
        }
        _ => return Err(ProgramError::InvalidInstructionData.into()),
    }
}
```

Varakäsky tarkistaa, vastaako saapuvan käskyn erotin Transfer Hook -rajapinnan `Execute`-käskyä. Jos vastaavuus löytyy, se kutsuu `transfer_hook`-käskyä Anchor-ohjelmastamme.

<Callout type="info">

Tällä hetkellä on olemassa julkaisematon Anchor-ominaisuus, joka yksinkertaistaa tätä prosessia. Se poistaisi varakäskyn tarpeen.

</Callout>

### Tokenien Siirtäminen

Olemme nyt valmiita lähettämään token-siirron. Siirtokäskyn lisäksi tarvitaan muutamia muita käskyjä.

### Token account -datan Käyttäminen Transfer Hookissa

Joskus saatat haluta käyttää tilidataa lisätilien johtamiseen extra account metas -kokoelmassa. Tämä on hyödyllistä esimerkiksi silloin, kun haluat käyttää token account -tilin omistajaa seed-arvona PDA:lle.

ExtraAccountMeta-tiliä luotaessa voit käyttää minkä tahansa tilin dataa ylimääräisenä seed-arvona. Tässä tapauksessa haluamme johtaa laskuritilin token account -tilin omistajasta ja merkkijonosta 'counter'. Tämä tarkoittaa, että voimme aina nähdä, kuinka usein kyseinen token account -tilin omistaja on siirtänyt tokeneita.

Näin se määritetään `extra_account_metas()`-funktiossa.

```rust
// Define extra account metas to store on extra_account_meta_list account
impl<'info> InitializeExtraAccountMetaList<'info> {
    pub fn extra_account_metas() -> Result<Vec<ExtraAccountMeta>> {
        Ok(
            vec![
                ExtraAccountMeta::new_with_seeds(
                    &[
                        Seed::Literal {
                            bytes: b"counter".to_vec(),
                        },
                        Seed::AccountData { account_index: 0, data_index: 32, length: 32 },
                    ],
                    false, // is_signer
                    true // is_writable
                )?
            ]
        )
    }
}
```

Tarkastellaan token account -rakennetta ymmärtääksemme, miten tilin data tallennetaan. Alla on esimerkki token account -rakenteesta. Voimme ottaa 32 tavua positioista 32–64 token account -tilin omistajana, joka sijaitsee kohdassa 'account_index: 0'. 'account_index' viittaa tilin indeksiin tilitaulukossa. Transfer hookin tapauksessa omistajan token account on tilitaulukon ensimmäinen merkintä. Toinen tili on aina mint ja kolmas tili on kohde-token account. Tilien järjestys on sama kuin vanhassa token program -ohjelmassa.


Meidän tapauksessamme haluamme johtaa laskuritilin lähettäjän token account -tilin omistajalta, joten kun luomme ExtraAccountMeta-tilit, alustamme (`init`) tämän PDA-laskuritilin, joka johdetaan lähettäjän token account -tilin omistajasta ja merkkijonosta 'counter'. Kun PDA-laskuritili on alustettu, voimme käyttää sitä transfer hookissa arvon kasvattamiseen jokaisen siirron yhteydessä.

Meidän on myös määriteltävä tämä ylimääräinen laskuritili TransferHook-rakenteessa. Nämä ovat tilit, jotka välitetään TransferHook-ohjelmallemme joka kerta, kun siirto tehdään. Asiakas saa nämä lisätilit ExtraAccountsMetaList-PDA:lta ja sisällyttää ne token-siirtokäskyyn, mutta tässä ohjelmassa meidän on silti määriteltävä se.

```rust
#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(token::mint = mint, token::authority = owner)]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(token::mint = mint)]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(seeds = [b"extra-account-metas", mint.key().as_ref()], bump)]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(seeds = [b"counter", owner.key().as_ref()], bump)]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Huomaa, että laskuritili johdetaan token account -tilin omistajalta ja se täytyy alustaa ennen siirron tekemistä. Tässä esimerkissä alustamme laskuritilin, kun alustamme extra account metas -tilit. Meillä on siis laskuri-PDA vain sen token account -tilin omistajalle, joka kutsui kyseistä funktiota. Jos haluat laskuritilin jokaiselle mintisi token account -tilille, sinun täytyy luoda toiminnallisuus näiden PDA-tilien luomiseksi etukäteen. Dappissasi voisi olla painike laskuriin rekisteröitymiseksi, joka luo tämän PDA-tilin, minkä jälkeen käyttäjät voivat käyttää tätä laskuri-tokenia.
