Transfer Hook -laajennus ja Transfer Hook Interface mahdollistavat
Mint Account -tilien luomisen siten, että ne suorittavat mukautettua
instruktiologiikkaa jokaisen tokensiirron yhteydessä.

Tämä avaa monia uusia käyttötapauksia tokensiirroille, kuten:

- NFT-rojaltien valvonta
- Tokeneita vastaanottavien lompakoiden estolista tai sallittujen lista
- Mukautettujen maksujen toteuttaminen tokensiirroille
- Mukautettujen tokensiirtotapahtumien luominen
- Tokensiirtojen tilastojen seuranta
- Ja monia muita

Tämän toteuttamiseksi kehittäjien on rakennettava ohjelma, joka toteuttaa
[Transfer Hook Interface](https://github.com/solana-program/token-2022/tree/main/interface/src/extension/transfer_hook)
-rajapinnan, ja alustettava Mint Account, jossa Transfer Hook -laajennus on käytössä.

Jokaisen sellaisen tokensiirron yhteydessä, johon liittyy Mint Account -tilin
tokeneita, Token Extensions program tekee Cross Program Invocation -kutsun (CPI)
suorittaakseen instruktion Transfer Hook -ohjelmassa.

<Callout type="info">

Kun Token Extensions program tekee CPI-kutsun Transfer Hook -ohjelmaan, kaikki
alkuperäisen siirron tilit muunnetaan vain luku -tileiksi. Tämä tarkoittaa, että
lähettäjän allekirjoitusoikeudet eivät ulotu Transfer Hook -ohjelmaan.

Tämä suunnitteluratkaisu on tehty Transfer Hook -ohjelmien väärinkäytön estämiseksi.

</Callout>

Tässä oppaassa luomme Transfer Hook -ohjelman Anchor-kehyksellä, mutta Transfer
Hook Interface voidaan toteuttaa myös natiiviohjelmalla. Lue lisää Anchor-kehyksestä täältä:
[Anchor-kehys](https://www.anchor-lang.com/)

## Transfer Hook Interface -rajapinnan yleiskatsaus

Transfer Hook Interface tarjoaa kehittäjille tavan toteuttaa mukautettua
instruktiologiikkaa, joka suoritetaan jokaisen tietyn Mint Account -tilin
tokensiirron yhteydessä.

Transfer Hook Interface määrittelee seuraavat
[instruktiot](https://github.com/solana-program/token-2022/blob/main/interface/src/extension/transfer_hook/instruction.rs):

- `Execute`: Instruktio, jonka Token Extension program kutsuu jokaisen
  tokensiirron yhteydessä.
- `InitializeExtraAccountMetaList` (valinnainen): Luo tilin, joka tallentaa
  luettelon mukautetun `Execute`-instruktion tarvitsemista lisätileistä.
- `UpdateExtraAccountMetaList` (valinnainen): Päivittää lisätilien luettelon
  korvaamalla olemassa olevan luettelon.

Teknisesti `InitializeExtraAccountMetaList`-instruktion toteuttaminen
rajapinnan kautta ei ole pakollista. Tilin voi luoda mikä tahansa Transfer Hook
-ohjelman instruktio.

Tilin Program Derived Address (PDA) on kuitenkin johdettava seuraavilla
seed-arvoilla:

- Kovakoodattu merkkijono "extra-account-metas"
- Mint Account -tilin osoite
- Transfer Hook -ohjelman ID

<CodeTabs>

```js !! title="Web3.js v3"
const [pda] = await PublicKey.findProgramAddress(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBytes()],
  program.programId // transfer hook program ID
);
```

```js !! title="Web3.js (legacy)"
const [pda] = PublicKey.findProgramAddressSync(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBuffer()],
  program.programId // transfer hook program ID
);
```

</CodeTabs>

Kun `Execute`-instruktion tarvitsemat lisätilit tallennetaan ennalta määritettyyn
PDA:han, nämä tilit voidaan lisätä automaattisesti tokensiirtoinstruktioon
asiakasohjelmassa.

## Hello world -Transfer Hook

Tämä esimerkki on transfer hookien hello world. Se on yksinkertainen transfer
hook, joka vain tulostaa viestin jokaisen tokensiirron yhteydessä. Aloitamme
avaamalla esimerkin Solana Playgroundissa, verkkotyökalussa Solana-ohjelmien
rakentamiseen ja julkaisemiseen:
[linkki](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/hello_world)

Esimerkki koostuu Anchor-ohjelmasta, joka toteuttaa transfer hook -rajapinnan,
sekä testitiedostosta ohjelman testaamiseen.

Tämä ohjelma sisältää vain 3 instruktiota:

1. `initialize_extra_account_meta_list`: Luo tilin, joka tallentaa luettelon
   `transfer_hook`-instruktion tarvitsemista lisätileistä. Hello worldissa
   jätämme sen tyhjäksi.
2. `transfer_hook`: Tämä instruktio kutsutaan CPI:n kautta jokaisen tokensiirron
   yhteydessä wrapped SOL -tokensiirron suorittamiseksi.
3. `fallback`: Koska käytämme Anchoria ja Token Program on natiiviohjelma,
   meidän on lisättävä fallback-instruktio, joka täsmäyttää instruktion
   discriminatorin manuaalisesti ja kutsuu mukautettua `transfer_hook`-instruktiotamme.
   Tätä funktiota ei tarvitse muuttaa.

Aina kun token siirretään, Token Program kutsuu tätä `transfer_hook`-funktiota.

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    Ok(())
}
```

Tähän funktioon voit nyt lisätä oman lisälogiikkasi. Voisit esimerkiksi
antaa siirron epäonnistua aina, kun siirrettävä määrä on suurempi kuin 50,
seuraavasti:

```rust
#[error_code]
pub enum MyError {
    #[msg("The amount is too big")]
    AmountTooBig,
}

pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    if amount > 50 {
        return err!(MyError::AmountTooBig);
    }

    Ok(())
}
```

## Counter Transfer Hook

Seuraava esimerkki näyttää, miten voit kasvattaa laskuria aina, kun tokeniasi
on siirretty.
[linkki](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/counter)

Jos haluat lisätä transfer hookiisi logiikkaa, joka tarvitsee lisätilejä,
sinun on lisättävä ne ExtraAccountMetaList-tilille. Tässä tapauksessa
tarvitsemme PDA:n, joka tallentaa, kuinka monta kertaa token on siirretty.

Tämä onnistuu lisäämällä seuraava koodi
`initialize_extra_account_meta_list`-instruktioon:

```rust
let account_metas = vec![
    ExtraAccountMeta::new_with_seeds(
        &[Seed::Literal {
            bytes: "counter".as_bytes().to_vec(),
        }],
        false, // is_signer
        true,  // is_writable
    )?,
];
```

Meidän on myös luotava tämä tili, kun alustamme uuden mint accountin, ja
siirrettävä se mukaan joka kerta, kun token siirretään.

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        init_if_needed,
        seeds = [b"counter"],
        bump,
        payer = payer,
        space = 16
    )]
    pub counter_account: Account<'info, CounterAccount>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(
        token::mint = mint,
        token::authority = owner,
    )]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        token::mint = mint,
    )]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(
        mut,
        seeds = [b"counter"],
        bump
    )]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Tili sisältää `u64`-tyyppisen laskurimuuttujan:

```rust
#[account]
pub struct CounterAccount {
    counter: u64,
}
```

Nyt transfer hook -funktiossamme voimme yksinkertaisesti kasvattaa tätä laskuria
yhdellä aina, kun funktiota kutsutaan:

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    ctx.accounts.counter_account.counter.checked_add(1).unwrap();
    msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

    Ok(())
}
```

aikana. Muuten kuka tahansa voisi kutsua transfer hook -instruktiota

transfer hookeihisi.

Voit lisätä tarkistuksen näin:

```rust
fn assert_is_transferring(ctx: &Context<TransferHook>) -> Result<()> {
    let source_token_info = ctx.accounts.source_token.to_account_info();
    let mut account_data_ref: RefMut<&mut [u8]> = source_token_info.try_borrow_mut_data()?;
    let mut account = PodStateWithExtensionsMut::<PodAccount>::unpack(*account_data_ref)?;
    let account_extension = account.get_extension_mut::<TransferHookAccount>()?;

    if !bool::from(account_extension.transferring) {
        return err!(TransferError::IsNotCurrentlyTransferring);
    }

    Ok(())
}
```

Kutsu sitä sitten `transfer_hook`-funktiosi alussa:

```rust
    #[error_code]
    pub enum TransferError {
        #[msg("The token is not currently transferring")]
        IsNotCurrentlyTransferring,
    }

    #[interface(spl_transfer_hook_interface::execute)]
    pub fn transfer_hook(ctx: Context<TransferHook>, _amount: u64) -> Result<()> {
        // Fail this instruction if it is not called from within a transfer hook
        assert_is_transferring(&ctx)?;

        ctx.accounts.counter_account.counter.checked_add(1).unwrap();
        msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

        Ok(())
    }
```

## Transfer Hook wSOl-siirtomaksulla (edistynyt esimerkki)

Oppaan seuraavassa osassa rakennamme edistyneemmän Transfer Hook -ohjelman
Anchor-kehyksellä. Tämä ohjelma edellyttää, että lähettäjä maksaa wSOL-maksun
jokaisesta tokensiirrosta.

wSOL-siirrot suoritetaan delegaatin kautta, joka on Transfer Hook -ohjelmasta
johdettu PDA. Tämä on tarpeen, koska tokensiirtoinstruktion alkuperäisen
lähettäjän allekirjoitus ei ole käytettävissä Transfer Hook -ohjelmassa.

Tämä ohjelma sisältää vain 3 instruktiota:

1. `initialize_extra_account_meta_list`: Luo tilin, joka tallentaa luettelon
   `transfer_hook`-instruktion tarvitsemista lisätileistä.
2. `transfer_hook`: Tämä instruktio kutsutaan CPI:n kautta jokaisen tokensiirron
   yhteydessä wrapped SOL -tokensiirron suorittamiseksi.
3. `fallback`: Transfer hook -rajapinnan instruktioilla on tietyt
   discriminatorit (instruktioiden tunnisteet). Anchor-ohjelmassa voimme käyttää
   fallback-instruktiota täsmäyttämään instruktion discriminatorin manuaalisesti
   ja kutsumaan mukautettua `transfer_hook`-instruktiotamme.

Tämä ohjelma edellyttää, että lähettäjä maksaa maksun wrapped SOL:na (wSOL)
jokaisesta tokensiirrosta. Tässä on
[valmis ohjelma](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/main).

### ExtraAccountMetas-tilin alustusinstruktio

Tässä vaiheessa toteutamme Transfer Hook -ohjelmamme
`initialize_extra_account_meta_list`-instruktion. Tämä instruktio luo
ExtraAccountMetas-tilin, joka tallentaa `transfer_hook`-instruktiomme
tarvitsemat lisätilit.

Tässä esimerkissä `initialize_extra_account_meta_list`-instruktio tarvitsee 7
tiliä:

- `payer`: Tili, jolla maksetaan ExtraAccountMetas-tilin luominen.
- `extra_account_meta_list`: ExtraAccountMetas-tili, joka luodaan
  `transfer_hook`-instruktiomme tarvitsemien tilien luettelon tallentamiseksi.
- `mint`: Mint Account, joka osoittaa tähän Transfer Hook -ohjelmaan. Mint-osoite
  on pakollinen seed-arvo `extra_account_meta_list`-PDA:n johtamisessa.
- `wsol_mint`: Wrapped SOL mint.
- `token_program`: Alkuperäisen Token program -ohjelman ID
- `associated_token_program`: Associated Token program -ohjelman ID.
- `system_program`: System Program, joka on pakollinen tili uusia tilejä
  luotaessa.

Osoitteita `mint`, `wsol_mint` ja `associated_token_program` käytetään
wSOL associated token account -tilien osoitteiden johtamiseen. Nämä tilit ovat
`transfer_hook`-instruktion tarvitsemia, ja ne tallennetaan
ExtraAccountMetas-tilille.

Päivitä `InitializeExtraAccountMetaList`-struct korvaamalla seuraava
aloituskoodi:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList {}
```

Alla olevalla koodilla:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    pub wsol_mint: InterfaceAccount<'info, Mint>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,

```

Päivitä seuraavaksi `initialize_extra_account_meta_list`-instruktio korvaamalla
seuraava aloituskoodi:

```rust
pub fn initialize_extra_account_meta_list(
    ctx: Context<InitializeExtraAccountMetaList>,
) -> Result<()> {
    Ok(())
}
```

Seuraavalla koodilla:

```rust
pub fn initialize_extra_account_meta_list(
        ctx: Context<InitializeExtraAccountMetaList>,
    ) -> Result<()> {
        // index 0-3 are the accounts required for token transfer (source, mint, destination, owner)
        // index 4 is address of ExtraAccountMetaList account
        // The `addExtraAccountsToInstruction` JS helper function resolving incorrectly
        let account_metas = vec![
            // index 5, wrapped SOL mint
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.wsol_mint.key(), false, false)?,
            // index 6, token program
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.token_program.key(), false, false)?,
            // index 7, associated token program
            ExtraAccountMeta::new_with_pubkey(
                &ctx.accounts.associated_token_program.key(),
                false,
                false,
            )?,
            // index 8, delegate PDA
            ExtraAccountMeta::new_with_seeds(
                &[Seed::Literal {
                    bytes: "delegate".as_bytes().to_vec(),
                }],
                false, // is_signer
                false,  // is_writable
            )?,
            // index 9, delegate wrapped SOL token account
            ExtraAccountMeta::new_external_pda_with_seeds(
                7, // associated token program index
                &[
                    Seed::AccountKey { index: 8 }, // owner index (delegate PDA)
                    Seed::AccountKey { index: 6 }, // token program index
                    Seed::AccountKey { index: 5 }, // wsol mint index
                ],
                false, // is_signer
                true,  // is_writable
            )?,
            // index 10, sender wrapped SOL token account
            ExtraAccountMeta::new_external_pda_with_seeds(
                7, // associated token program index
                &[
                    Seed::AccountKey { index: 3 }, // owner index
                    Seed::AccountKey { index: 6 }, // token program index
                    Seed::AccountKey { index: 5 }, // wsol mint index
                ],
                false, // is_signer
                true,  // is_writable
            )?,
        ];

        // calculate account size
        let account_size = ExtraAccountMetaList::size_of(account_metas.len())? as u64;
        // calculate minimum required lamports
        let lamports = Rent::get()?.minimum_balance(account_size as usize);

        let mint = ctx.accounts.mint.key();
        let signer_seeds: &[&[&[u8]]] = &[&[
            b"extra-account-metas",
            &mint.as_ref(),
            &[ctx.bumps.extra_account_meta_list],
        ]];

        // create ExtraAccountMetaList account
        create_account(
            CpiContext::new(
                ctx.accounts.system_program.to_account_info(),
                CreateAccount {
                    from: ctx.accounts.payer.to_account_info(),
                    to: ctx.accounts.extra_account_meta_list.to_account_info(),
                },
            )
            .with_signer(signer_seeds),
            lamports,
            account_size,
            ctx.program_id,
        )?;

        // initialize ExtraAccountMetaList account with extra accounts
        ExtraAccountMetaList::init::<ExecuteInstruction>(
            &mut ctx.accounts.extra_account_meta_list.try_borrow_mut_data()?,
            &account_metas,
        )?;

        Ok(())
    }
```

### Mukautettu Transfer Hook -instruction

Toteutetaan seuraavaksi mukautettu `transfer_hook`-instruction. Token Extension
-ohjelma kutsuu tätä instructionia jokaisen token-siirron yhteydessä.

Tässä esimerkissä vaadimme jokaisesta token-siirrosta wSOL-tokeneilla maksettavan
maksun. Yksinkertaisuuden vuoksi maksun suuruus on sama kuin siirrettävä token-määrä.

Päivitä `TransferHook`-struct korvaamalla seuraava aloituskoodi:

```rust
#[derive(Accounts)]

```

Seuraavalla päivitetyllä koodilla:

<Callout type="info">

Huomaa, että tilien järjestyksellä tässä structissa on merkitystä. Token Extensions
Program toimittaa tilit tässä järjestyksessä, kun se tekee CPI-kutsun tähän
Transfer Hook -ohjelmaan.

</Callout>

```rust
// Order of accounts matters for this struct.
// The first 4 accounts are the accounts required for token transfer (source, mint, destination, owner)
// Remaining accounts are the extra accounts required from the ExtraAccountMetaList account
// These accounts are provided via CPI to this program from the token2022 program
#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(
        token::mint = mint,
        token::authority = owner,
    )]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        token::mint = mint,
    )]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    pub wsol_mint: InterfaceAccount<'info, Mint>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    #[account(
        seeds = [b"delegate"],
        bump
    )]
    pub delegate: SystemAccount<'info>,
    #[account(
        mut,
        token::mint = wsol_mint,
        token::authority = delegate,
    )]
    pub delegate_wsol_token_account: InterfaceAccount<'info, TokenAccount>,
    #[account(
        mut,
        token::mint = wsol_mint,
        token::authority = owner,
    )]
    pub sender_wsol_token_account: InterfaceAccount<'info, TokenAccount>,
}
```

Seuraavalla päivitetyllä koodilla:

```rust
// Require SOL fee on transfer, lamport fee is equal to transfer amount
// If this fails, the initial token transfer fails
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {
    msg!("Transfer WSOL using delegate PDA");

    let signer_seeds: &[&[&[u8]]] = &[&[b"delegate", &[ctx.bumps.delegate]]];

    // transfer WSOL from sender to delegate token account using delegate PDA
    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.to_account_info(),
            TransferChecked {
                from: ctx.accounts.sender_wsol_token_account.to_account_info(),
                mint: ctx.accounts.wsol_mint.to_account_info(),
                to: ctx.accounts.delegate_wsol_token_account.to_account_info(),
                authority: ctx.accounts.delegate.to_account_info(),
            },
        )
        .with_signer(signer_seeds),
        amount,
        ctx.accounts.wsol_mint.decimals,
    )?;
```

token-siirrossa lähettäjän täytyy ensin hyväksyä delegate siirrettävälle määrälle.

### Fallback-instruction

Lopuksi meidän täytyy lisätä Anchor-ohjelmaan fallback-instruction, joka käsittelee
Token Extensions Programin tekemän CPI-kutsun.

Tämä vaihe on tarpeen, koska Anchor muodostaa instruction discriminatorit eri
tavalla kuin Transfer Hook -rajapinnan instructionit käyttämät. `transfer_hook`-
instructionin discriminator ei vastaa Transfer Hook -rajapinnan discriminatoria.

Päivitä `fallback`-instruction korvaamalla seuraava aloituskoodi:

```rust
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    Ok(())
}
```

Seuraavalla päivitetyllä koodilla:

```rust
// fallback instruction handler as workaround to anchor instruction discriminator check
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    let instruction = TransferHookInstruction::unpack(data)?;

    // match instruction discriminator to transfer hook interface execute instruction
    // token2022 program CPIs this instruction on token transfer
    match instruction {
        TransferHookInstruction::Execute { amount } => {
            let amount_bytes = amount.to_le_bytes();

            // invoke custom transfer hook instruction on our program
            __private::__global::transfer_hook(program_id, accounts, &amount_bytes)
        }
        _ => return Err(ProgramError::InvalidInstructionData.into()),
    }
}
```

Fallback-instruction tarkistaa, vastaako saapuvan instructionin discriminator
Transfer Hook -rajapinnan `Execute`-instructionia. Jos vastaavuus löytyy, se
kutsuu Anchor-ohjelmamme `transfer_hook`-instructionia.

<Callout type="info">

Anchorissa on tällä hetkellä julkaisematon ominaisuus, joka yksinkertaistaa
tätä prosessia. Se poistaisi fallback-instructionin tarpeen.

</Callout>

```js
      sourceTokenAccount,
      wallet.publicKey,
      amount,
      [],
      TOKEN_2022_PROGRAM_ID
    )
  );

  const txSig = await sendAndConfirmTransaction(
    connection,
    transaction,
    [wallet.payer],
    { skipPreflight: true }
  );

  console.log(`Transaction Signature: ${txSig}`);
});
```

### Token account -datan käyttö transfer hookissa

Joskus tilin dataa halutaan käyttää lisätilien johtamiseen extra account
metoissa. Tämä on hyödyllistä esimerkiksi silloin, kun token accountin omistajaa
halutaan käyttää PDA:n seed-arvona.

ExtraAccountMetaa luodessasi voit käyttää minkä tahansa tilin dataa ylimääräisenä
seed-arvona. Tässä tapauksessa haluamme johtaa counter-tilin token accountin
omistajasta ja merkkijonosta 'counter'. Näin voimme aina nähdä, kuinka usein
kyseinen token accountin omistaja on siirtänyt tokeneita.

Näin tämä määritetään `extra_account_metas()`-funktiossa.

```rust
// Define extra account metas to store on extra_account_meta_list account
impl<'info> InitializeExtraAccountMetaList<'info> {
    pub fn extra_account_metas() -> Result<Vec<ExtraAccountMeta>> {
        Ok(
            vec![
                ExtraAccountMeta::new_with_seeds(
                    &[
                        Seed::Literal {
                            bytes: b"counter".to_vec(),
                        },
                        Seed::AccountData { account_index: 0, data_index: 32, length: 32 },
                    ],
                    false, // is_signer
                    true // is_writable
                )?
            ]
        )
    }
}
```

Katsotaan token account -structia ymmärtääksemme, miten tilin data tallennetaan.
Alla on esimerkki token account -rakenteesta. Voimme siis ottaa 32 tavua
kohdasta 32–64 token accountin omistajaksi, joka on kohdassa
'account_index: 0'. 'account_index' viittaa tilin indeksiin accounts-taulukossa.
Transfer hookin tapauksessa omistajan token account on accounts-taulukon
ensimmäinen alkio. Toinen tili on aina mint ja kolmas tili on kohteen token
account. Tämä tilien järjestys on sama kuin vanhassa Token Programissa.

```rust
/// Account data.
#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct Account {
    /// The mint associated with this account
    pub mint: Pubkey,
    /// The owner of this account.
    pub owner: Pubkey,
    /// The amount of tokens this account holds.
    pub amount: u64,
    pub delegate: COption<Pubkey>,
    pub state: AccountState,
    pub is_native: COption<u64>,
    pub delegated_amount: u64,
    pub close_authority: COption<Pubkey>,
}
```

Meidän tapauksessamme haluamme johtaa counter-tilin lähettäjän token accountin
omistajasta. Kun siis luomme ExtraAccountMeta-tilit, `init`-alustamme tämän PDA
counter -tilin, joka johdetaan lähettäjän token accountin omistajasta ja
merkkijonosta 'counter'. Kun PDA counter -tili on alustettu, voimme käyttää sitä
transfer hookissa arvon kasvattamiseen jokaisen siirron yhteydessä.


Meidän täytyy myös määritellä tämä ylimääräinen counter-tili TransferHook-structissa.
Nämä ovat tilit, jotka välitetään TransferHook-ohjelmallemme aina, kun siirto
tehdään. Client hakee nämä lisätilit ExtraAccountsMetaList PDA:sta ja sisällyttää
ne token-siirron instructioniin, mutta ohjelmassa meidän täytyy silti määritellä
se.

```rust
#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(token::mint = mint, token::authority = owner)]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(token::mint = mint)]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(seeds = [b"extra-account-metas", mint.key().as_ref()], bump)]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(seeds = [b"counter", owner.key().as_ref()], bump)]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Huomaa, että counter-tili johdetaan token accountin omistajasta, ja se täytyy
alustaa ennen siirron tekemistä. Tässä esimerkissä alustamme counter-tilin
samalla, kun alustamme extra account metat. Siksi counter-PDA on vain sen token
accountin omistajalle, joka kutsui kyseistä funktiota. Jos haluat counter-tilin
jokaiselle mintisi token accountille, tarvitset toiminnallisuuden, jolla nämä PDA:t
luodaan etukäteen. Dappissasi voisi olla painike, jolla käyttäjä rekisteröityy
counteriin ja joka luo tämän PDA-tilin, ja siitä lähtien käyttäjät voivat käyttää
tätä counter-tokenia.
