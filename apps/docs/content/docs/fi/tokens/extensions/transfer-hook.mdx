Transfer Hook -laajennus ja Transfer Hook Interface mahdollistavat sellaisten
Mint Account -tilien luomisen, jotka suorittavat mukautettua käskylogiikkaa
jokaisen token-siirron yhteydessä.

Tämä avaa monia uusia käyttötapauksia token-siirroille, kuten:

- NFT-rojaltien pakottaminen
- Tokeneita vastaanottavien lompakoiden asettaminen musta- tai valkolistalle
- Mukautettujen maksujen toteuttaminen token-siirroille
- Mukautettujen token-siirtotapahtumien luominen
- Token-siirtojen tilastojen seuraaminen
- Ja paljon muuta

Tämän toteuttamiseksi kehittäjien on rakennettava ohjelma, joka toteuttaa
[Transfer Hook Interfacen](https://github.com/solana-program/token-2022/tree/main/interface/src/extension/transfer_hook)
ja alustettava Mint Account, jossa Transfer Hook -laajennus on otettu käyttöön.

Jokaisen sellaisen token-siirron yhteydessä, johon liittyy Mint Accountin
tokeneita, Token Extensions -ohjelma tekee Cross Program Invocationin (CPI)
suorittaakseen käskyn Transfer Hook -ohjelmassa.

<Callout type="info">

Kun Token Extensions -ohjelma tekee CPI-kutsun Transfer Hook -ohjelmaan, kaikki
alkuperäisen siirron tilit muunnetaan vain luku -tileiksi. Tämä tarkoittaa, että
lähettäjän allekirjoitusoikeudet eivät ulotu Transfer Hook -ohjelmaan.

Tämä suunnitteluratkaisu on tehty Transfer Hook -ohjelmien haitallisen käytön estämiseksi.

</Callout>

Tässä oppaassa luomme Transfer Hook -ohjelman Anchor-kehyksellä, mutta
Transfer Hook Interface on mahdollista toteuttaa myös natiiviohjelmalla. Lue
lisää Anchor-kehyksestä täältä:
[Anchor-kehys](https://www.anchor-lang.com/)

## Transfer Hook Interfacen yleiskatsaus

Transfer Hook Interface tarjoaa kehittäjille tavan toteuttaa mukautettua
käskylogiikkaa, joka suoritetaan jokaisen tietyn Mint Accountin token-siirron
yhteydessä.

Transfer Hook Interface määrittelee seuraavat
[käskyt](https://github.com/solana-program/token-2022/blob/main/interface/src/extension/transfer_hook/instruction.rs):

- `Execute`: Käsky, jonka Token Extensions -ohjelma kutsuu jokaisen token-siirron
  yhteydessä.
- `InitializeExtraAccountMetaList` (valinnainen): Luo tilin, joka tallentaa
  luettelon lisätileistä, joita mukautettu `Execute`-käsky tarvitsee.
- `UpdateExtraAccountMetaList` (valinnainen): Päivittää lisätilien luettelon
  korvaamalla olemassa olevan luettelon.

Teknisesti `InitializeExtraAccountMetaList`-käskyn toteuttaminen rajapinnan
mukaisesti ei ole pakollista. Tilin voi luoda mikä tahansa Transfer Hook
-ohjelman käsky.

Tilin Program Derived Address (PDA) on kuitenkin johdettava käyttäen seuraavia
seed-arvoja:

- Kovakoodattu merkkijono "extra-account-metas"
- Mint Accountin osoite
- Transfer Hook -ohjelman ID

<CodeTabs>

```js !! title="Web3.js v3"
const [pda] = await PublicKey.findProgramAddress(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBytes()],
  program.programId // transfer hook program ID
);
```

```js !! title="Web3.js (legacy)"
const [pda] = PublicKey.findProgramAddressSync(
  [Buffer.from("extra-account-metas"), mint.publicKey.toBuffer()],
  program.programId // transfer hook program ID
);
```

</CodeTabs>

Kun `Execute`-käskyn tarvitsemat lisätilit tallennetaan ennalta määritettyyn
PDA:han, nämä tilit voidaan lisätä automaattisesti token-siirtokäskyyn
asiakasohjelmassa.

## Hello world -Transfer Hook

Tämä esimerkki on transfer hookien hello world. Se on yksinkertainen transfer
hook, joka tulostaa viestin jokaisen token-siirron yhteydessä. Aloitamme
avaamalla esimerkin Solana Playgroundissa, verkkotyökalussa Solana-ohjelmien
rakentamiseen ja julkaisemiseen:
[linkki](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/hello_world)

Esimerkki koostuu Anchor-ohjelmasta, joka toteuttaa Transfer Hook Interfacen,
ja testitiedostosta ohjelman testaamiseen.

Tämä ohjelma sisältää vain 3 käskyä:

1. `initialize_extra_account_meta_list`: Luo tilin, joka tallentaa luettelon
   `transfer_hook`-käskyn tarvitsemista lisätileistä. Hello world -esimerkissä
   jätämme sen tyhjäksi.
2. `transfer_hook`: Tämä käsky kutsutaan CPI:n kautta jokaisen token-siirron
   yhteydessä wrapped SOL -token-siirron suorittamiseksi.
3. `fallback`: Koska käytämme Anchoria ja Token Program on natiiviohjelma, meidän
   on lisättävä fallback-käsky, joka täsmäyttää käskyn discriminatorin
   manuaalisesti ja kutsuu mukautettua `transfer_hook`-käskyämme. Tätä
   funktiota ei tarvitse muuttaa.

Aina kun token siirretään, Token Program kutsuu tätä `transfer_hook`-funktiota.

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    Ok(())
}
```

Tähän funktioon voit nyt lisätä oman lisälogiikkasi. Voisit esimerkiksi antaa
siirron epäonnistua aina, kun siirrettävä määrä on suurempi kuin 50, näin:

```rust
#[error_code]
pub enum MyError {
    #[msg("The amount is too big")]
    AmountTooBig,
}

pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    msg!("Hello Transfer Hook!");

    if amount > 50 {
        return err!(MyError::AmountTooBig);
    }

    Ok(())
}
```

## Laskurin Transfer Hook

Seuraava esimerkki näyttää, miten voit kasvattaa laskuria aina, kun tokenisi on
siirretty.
[linkki](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/counter)

Jos haluat lisätä transfer hookiisi logiikkaa, joka tarvitsee lisätilejä, sinun
on lisättävä ne ExtraAccountMetaList-tiliin. Tässä tapauksessa tarvitsemme PDA:n,
joka tallentaa, kuinka monta kertaa tokeni on siirretty.

Tämä onnistuu lisäämällä seuraava koodi
`initialize_extra_account_meta_list`-käskyyn:

```rust
let account_metas = vec![
    ExtraAccountMeta::new_with_seeds(
        &[Seed::Literal {
            bytes: "counter".as_bytes().to_vec(),
        }],
        false, // is_signer
        true,  // is_writable
    )?,
];
```

Meidän on myös luotava tämä tili, kun alustamme uuden Mint Accountin, ja se on
välitettävä mukana joka kerta, kun token siirretään.

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        init_if_needed,
        seeds = [b"counter"],
        bump,
        payer = payer,
        space = 16
    )]
    pub counter_account: Account<'info, CounterAccount>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}

#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(
        token::mint = mint,
        token::authority = owner,
    )]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(
        token::mint = mint,
    )]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(
        mut,
        seeds = [b"counter"],
        bump
    )]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Tili sisältää `u64`-tyyppisen laskurimuuttujan:

```rust
#[account]
pub struct CounterAccount {
    counter: u64,
}
```

Nyt transfer hook -funktiossamme voimme yksinkertaisesti kasvattaa tätä laskuria
yhdellä aina, kun funktio kutsutaan:

```rust
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {

    ctx.accounts.counter_account.counter.checked_add(1).unwrap();
    msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

    Ok(())
}
```

Koska kasvatamme tässä laskuria aina, kun token siirretään, meidän on varmistettava,
että transfer hook -käskyn voi kutsua vain siirron aikana. Muuten joku voisi

joka kannattaa lisätä kaikkiin transfer hookeihisi.

</Callout>

Voit lisätä tarkistuksen näin:

```rust
fn assert_is_transferring(ctx: &Context<TransferHook>) -> Result<()> {
    let source_token_info = ctx.accounts.source_token.to_account_info();
    let mut account_data_ref: RefMut<&mut [u8]> = source_token_info.try_borrow_mut_data()?;
    let mut account = PodStateWithExtensionsMut::<PodAccount>::unpack(*account_data_ref)?;
    let account_extension = account.get_extension_mut::<TransferHookAccount>()?;

    if !bool::from(account_extension.transferring) {
        return err!(TransferError::IsNotCurrentlyTransferring);
    }

    Ok(())
}
```

Kutsu sitä sitten `transfer_hook`-funktiosi alussa:

```rust
    #[error_code]
    pub enum TransferError {
        #[msg("The token is not currently transferring")]
        IsNotCurrentlyTransferring,
    }

    #[interface(spl_transfer_hook_interface::execute)]
    pub fn transfer_hook(ctx: Context<TransferHook>, _amount: u64) -> Result<()> {
        // Fail this instruction if it is not called from within a transfer hook
        assert_is_transferring(&ctx)?;

        ctx.accounts.counter_account.counter.checked_add(1).unwrap();
        msg!("This token has been transferred {0} times", ctx.accounts.counter_account.counter);

        Ok(())
    }
```

## Transfer Hook wSOL-siirtomaksulla (edistynyt esimerkki)

Tämän oppaan seuraavassa osassa rakennamme edistyneemmän Transfer Hook -ohjelman
Anchor-kehyksellä. Tämä ohjelma edellyttää, että lähettäjä maksaa wSOL-maksun
jokaisesta token-siirrosta.

wSOL-siirrot suoritetaan delegaatilla, joka on Transfer Hook -ohjelmasta johdettu
PDA. Tämä on tarpeen, koska token-siirtokäskyn alkuperäisen lähettäjän
allekirjoitus ei ole käytettävissä Transfer Hook -ohjelmassa.

Tämä ohjelma sisältää vain 3 käskyä:

1. `initialize_extra_account_meta_list`: Luo tilin, joka tallentaa luettelon
   `transfer_hook`-käskyn tarvitsemista lisätileistä.
2. `transfer_hook`: Tämä käsky kutsutaan CPI:n kautta jokaisen token-siirron
   yhteydessä wrapped SOL -token-siirron suorittamiseksi.
3. `fallback`: Transfer hook -rajapinnan käskyillä on omat discriminatorinsa
   (käskytunnisteet). Anchor-ohjelmassa voimme käyttää fallback-käskyä, joka
   täsmäyttää käskyn discriminatorin manuaalisesti ja kutsuu mukautettua
   `transfer_hook`-käskyämme.

Tämä ohjelma edellyttää, että lähettäjä maksaa maksun wrapped SOLilla (wSOL)
jokaisesta token-siirrosta. Tässä on
[lopullinen ohjelma](https://beta.solpg.io/github.com/solana-developers/anchor-transfer-hook/tree/main).

### ExtraAccountMetas-tilin alustuskäsky

Tässä vaiheessa toteutamme Transfer Hook -ohjelmamme
`initialize_extra_account_meta_list`-käskyn. Tämä käsky luo
ExtraAccountMetas-tilin, johon tallennetaan `transfer_hook`-käskymme tarvitsemat
lisätilit.

Tässä esimerkissä `initialize_extra_account_meta_list`-käsky tarvitsee 7 tiliä:

- `payer`: Tili, jolla maksetaan ExtraAccountMetas-tilin luominen.
- `extra_account_meta_list`: ExtraAccountMetas-tili, joka luodaan
  `transfer_hook`-käskymme tarvitsemien tilien luettelon tallentamiseksi.
- `mint`: Mint Account, joka osoittaa tähän Transfer Hook -ohjelmaan. Mint-osoite
  on pakollinen seed `extra_account_meta_list`-PDA:n johtamiseksi.
- `wsol_mint`: Wrapped SOL -mint.
- `token_program`: Alkuperäisen Token Programin ID
- `associated_token_program`: Associated Token Programin ID.
- `system_program`: System Program, joka on pakollinen tili uusia tilejä
  luotaessa.

Osoitteita `mint`, `wsol_mint` ja `associated_token_program` käytetään
wSOL-tilien (associated token account) osoitteiden johtamiseen. Nämä tilit ovat
`transfer_hook`-käskyn vaatimia, ja ne tallennetaan ExtraAccountMetas-tilille.

Päivitä `InitializeExtraAccountMetaList`-struct korvaamalla seuraava
aloituskoodi:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList {}
```

Alla olevalla koodilla:

```rust
#[derive(Accounts)]
pub struct InitializeExtraAccountMetaList<'info> {
    #[account(mut)]
    payer: Signer<'info>,

    /// CHECK: ExtraAccountMetaList Account, must use these seeds
    #[account(
        mut,
        seeds = [b"extra-account-metas", mint.key().as_ref()],
        bump
    )]
    pub extra_account_meta_list: AccountInfo<'info>,
    pub mint: InterfaceAccount<'info, Mint>,
    pub wsol_mint: InterfaceAccount<'info, Mint>,
    pub token_program: Interface<'info, TokenInterface>,
    pub associated_token_program: Program<'info, AssociatedToken>,
    pub system_program: Program<'info, System>,
}
```

Päivitä seuraavaksi `initialize_extra_account_meta_list`-käsky korvaamalla
seuraava aloituskoodi:

```rust
pub fn initialize_extra_account_meta_list(
    ctx: Context<InitializeExtraAccountMetaList>,
) -> Result<()> {
    Ok(())
}
```

Alla olevalla koodilla:

```rust
pub fn initialize_extra_account_meta_list(
        ctx: Context<InitializeExtraAccountMetaList>,
    ) -> Result<()> {
        // index 0-3 are the accounts required for token transfer (source, mint, destination, owner)
        // index 4 is address of ExtraAccountMetaList account
        // The `addExtraAccountsToInstruction` JS helper function resolving incorrectly
        let account_metas = vec![
            // index 5, wrapped SOL mint
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.wsol_mint.key(), false, false)?,
            // index 6, token program
            ExtraAccountMeta::new_with_pubkey(&ctx.accounts.token_program.key(), false, false)?,
            // index 7, associated token program
            ExtraAccountMeta::new_with_pubkey(
                &ctx.accounts.associated_token_program.key(),
                false,
                false,
            )?,
            // index 8, delegate PDA
            ExtraAccountMeta::new_with_seeds(
                &[Seed::Literal {
                    bytes: "delegate".as_bytes().to_vec(),
                }],
                false, // is_signer
                false,  // is_writable
            )?,
            // index 9, delegate wrapped SOL token account
            ExtraAccountMeta::new_external_pda_with_seeds(
                7, // associated token program index
                &[
                    Seed::AccountKey { index: 8 }, // owner index (delegate PDA)
                    Seed::AccountKey { index: 6 }, // token program index
                    Seed::AccountKey { index: 5 }, // wsol mint index
                ],
                false, // is_signer
                true,  // is_writable
            )?,
            // index 10, sender wrapped SOL token account
            ExtraAccountMeta::new_external_pda_with_seeds(
                7, // associated token program index
                &[
                    Seed::AccountKey { index: 3 }, // owner index
                    Seed::AccountKey { index: 6 }, // token program index
                    Seed::AccountKey { index: 5 }, // wsol mint index
                ],

                    to: ctx.accounts.extra_account_meta_list.to_account_info(),

    }
```

### Mukautettu Transfer Hook -instruktio

Toteutetaan seuraavaksi mukautettu `transfer_hook`-instruktio. Token Extensions Program kutsuu tätä instruktiota jokaisen token-siirron yhteydessä.

Tässä esimerkissä edellytämme jokaiselta token-siirrolta wSOL-muodossa maksettavan maksun. Yksinkertaisuuden vuoksi maksun suuruus on sama kuin siirrettävä token-määrä.

Päivitä `TransferHook`-struct korvaamalla seuraava aloituskoodi:


Alla olevalla päivitetyllä koodilla:

<Callout type="info">

Huomaa, että tilien järjestyksellä tässä structissa on merkitystä. Token Extensions Program toimittaa tilit tässä järjestyksessä, kun se tekee CPI-kutsun tähän Transfer Hook -ohjelmaan.

</Callout>

```rust
// Require SOL fee on transfer, lamport fee is equal to transfer amount
// If this fails, the initial token transfer fails
pub fn transfer_hook(ctx: Context<TransferHook>, amount: u64) -> Result<()> {
    msg!("Transfer WSOL using delegate PDA");

    let signer_seeds: &[&[&[u8]]] = &[&[b"delegate", &[ctx.bumps.delegate]]];

    // transfer WSOL from sender to delegate token account using delegate PDA
    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.to_account_info(),
            TransferChecked {
                from: ctx.accounts.sender_wsol_token_account.to_account_info(),
                mint: ctx.accounts.wsol_mint.to_account_info(),
                to: ctx.accounts.delegate_wsol_token_account.to_account_info(),
                authority: ctx.accounts.delegate.to_account_info(),
            },
        )
        .with_signer(signer_seeds),
        amount,
        ctx.accounts.wsol_mint.decimals,
```

### Fallback-instruktio

Lopuksi meidän on lisättävä Anchor-ohjelmaan fallback-instruktio, joka käsittelee Token Extensions Programin tekemän CPI-kutsun.

Tämä vaihe on tarpeen, koska Anchor generoi instruktioiden discriminatorit eri tavalla kuin Transfer Hook -rajapinnan instruktioissa käytetyt discriminatorit. `transfer_hook`-instruktion discriminator ei täsmää Transfer Hook -rajapinnan discriminatorin kanssa.

Päivitä `fallback`-instruktio korvaamalla seuraava aloituskoodi:

```rust
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    Ok(())
}
```

Alla olevalla päivitetyllä koodilla:

```rust
// fallback instruction handler as workaround to anchor instruction discriminator check
pub fn fallback<'info>(
    program_id: &Pubkey,
    accounts: &'info [AccountInfo<'info>],
    data: &[u8],
) -> Result<()> {
    let instruction = TransferHookInstruction::unpack(data)?;

    // match instruction discriminator to transfer hook interface execute instruction
    // token2022 program CPIs this instruction on token transfer
    match instruction {
        TransferHookInstruction::Execute { amount } => {
            let amount_bytes = amount.to_le_bytes();

            // invoke custom transfer hook instruction on our program
            __private::__global::transfer_hook(program_id, accounts, &amount_bytes)
        }
        _ => return Err(ProgramError::InvalidInstructionData.into()),
    }
}
```

Fallback-instruktio tarkistaa, vastaako saapuvan instruktion discriminator Transfer Hook -rajapinnan `Execute`-instruktiota. Jos vastaavuus löytyy, se kutsuu Anchor-ohjelmamme `transfer_hook`-instruktiota.

<Callout type="info">

Anchor-kehyksessä on tällä hetkellä julkaisematon ominaisuus, joka yksinkertaistaa tätä prosessia. Se poistaisi tarpeen fallback-instruktiolle.

</Callout>

### Token account -datan käyttäminen transfer hookissa

Joskus tilin dataa voi haluta käyttää lisätilien johtamiseen extra account metas -listassa. Tämä on hyödyllistä esimerkiksi silloin, kun PDA:n johtamisessa halutaan käyttää seed-arvona token account -tilin omistajaa.

ExtraAccountMetaa luodessasi voit käyttää minkä tahansa tilin dataa ylimääräisenä seed-arvona. Tässä tapauksessa haluamme johtaa counter-tilin token account -tilin omistajasta ja merkkijonosta 'counter'. Näin voimme aina nähdä, kuinka usein kyseisen token account -tilin omistaja on siirtänyt tokeneita.

Näin se määritetään `extra_account_metas()`-funktiossa.

```rust
// Define extra account metas to store on extra_account_meta_list account
impl<'info> InitializeExtraAccountMetaList<'info> {
    pub fn extra_account_metas() -> Result<Vec<ExtraAccountMeta>> {
        Ok(
            vec![
                ExtraAccountMeta::new_with_seeds(
                    &[
                        Seed::Literal {
                            bytes: b"counter".to_vec(),
                        },
                        Seed::AccountData { account_index: 0, data_index: 32, length: 32 },
                    ],
                    false, // is_signer
                    true // is_writable
                )?
            ]
        )
    }
}
```

Tarkastellaan token account -structia ymmärtääksemme, miten tilin data tallennetaan. Alla on esimerkki token account -rakenteesta. Voimme siis ottaa 32 tavua kohdasta 32–64 token account -tilin omistajaksi, joka on kohdassa 'account_index: 0'. 'account_index' viittaa tilin indeksiin accounts-taulukossa. Transfer hookin tapauksessa omistajan token account on accounts-taulukon ensimmäinen alkio. Toinen tili on aina mint ja kolmas tili on kohde-token account. Tämä tilien järjestys on sama kuin vanhassa Token Program -ohjelmassa.


Meidän tapauksessamme haluamme johtaa counter-tilin lähettäjän token account -tilin omistajasta. Siksi kun luomme ExtraAccountMeta-tilejä, alustamme (`init`) tämän PDA counter -tilin, joka johdetaan lähettäjän token account -tilin omistajasta ja merkkijonosta 'counter'. Kun PDA counter -tili on alustettu, voimme käyttää sitä transfer hookissa arvon kasvattamiseen jokaisessa siirrossa.

Meidän on myös määriteltävä tämä ylimääräinen counter-tili TransferHook-structissa. Nämä ovat tilit, jotka välitetään TransferHook-ohjelmallemme aina siirron yhteydessä. Asiakas hakee nämä lisätilit ExtraAccountsMetaList PDA:sta ja sisällyttää ne token-siirtoinstruktioon, mutta ohjelmassa ne on silti määriteltävä.

```rust
#[derive(Accounts)]
pub struct TransferHook<'info> {
    #[account(token::mint = mint, token::authority = owner)]
    pub source_token: InterfaceAccount<'info, TokenAccount>,
    pub mint: InterfaceAccount<'info, Mint>,
    #[account(token::mint = mint)]
    pub destination_token: InterfaceAccount<'info, TokenAccount>,
    /// CHECK: source token account owner, can be SystemAccount or PDA owned by another program
    pub owner: UncheckedAccount<'info>,
    /// CHECK: ExtraAccountMetaList Account,
    #[account(seeds = [b"extra-account-metas", mint.key().as_ref()], bump)]
    pub extra_account_meta_list: UncheckedAccount<'info>,
    #[account(seeds = [b"counter", owner.key().as_ref()], bump)]
    pub counter_account: Account<'info, CounterAccount>,
}
```

Huomaa, että counter-tili johdetaan token account -tilin omistajasta, ja se on alustettava ennen siirron tekemistä. Tässä esimerkissä alustamme counter-tilin samalla, kun alustamme extra account metas -tilin. Siten counter-PDA on vain sen token account -tilin omistajalle, joka kutsui kyseistä funktiota.
