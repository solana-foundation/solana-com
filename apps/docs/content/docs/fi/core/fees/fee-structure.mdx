<Callout type="info" title="Yhteenveto">
  Kokonaismaksu = perusmaksu (5 000 lamports/allekirjoitus, 50 % poltetaan) + priorisointimaksu
  (CU_price * CU_limit / 1M lamports, 100 % validatorille). Veloitetaan riippumatta siitä,
  onnistuuko tapahtuma vai ei.
</Callout>

## Maksunlaskenta-algoritmi

Tapahtuman kokonaismaksu lasketaan funktiolla
[`calculate_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L53-L72):

```text title="Total fee formula"
total_fee = base_fee + prioritization_fee
```

Syötteinä ovat tapahtumaviesti, nykyinen `lamports_per_signature`
(tällä hetkellä 5 000) ja compute budget -ohjeista johdettu priorisointimaksu. Kokonaismaksu
vähennetään maksajalta ennen suorituksen alkamista. Jos tapahtuma epäonnistuu, maksu
veloitetaan silti.

## Perusmaksu

Perusmaksu kattaa Ed25519-allekirjoitusten varmentamisen sekä mahdolliset
esikäännösohjelmakohtaiset allekirjoitusten varmentamiset. Kaikista tapahtuman allekirjoituksista
veloitetaan maksu, mukaan lukien Ed25519-, Secp256k1- ja Secp256r1-esikäännösohjelmien
varmentamat allekirjoitukset.

Funktio
[`calculate_signature_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L75-L92)
laskee:

```text title="Base fee formula"
signature_count = num_transaction_signatures
                + num_ed25519_signatures
                + num_secp256k1_signatures
                + num_secp256r1_signatures   (if feature enabled)

base_fee = signature_count * lamports_per_signature
```

- `num_transaction_signatures`: tapahtuman Ed25519-allekirjoitusten määrä
  (yleensä yksi allekirjoittajaa kohti).
- `num_ed25519_signatures`, `num_secp256k1_signatures`,
  `num_secp256r1_signatures`: vastaavien esikäännösohjelmien varmentamat allekirjoitukset.
- `lamports_per_signature`: tällä hetkellä
  [5 000 lamports](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-structure/src/lib.rs#L210).

### Maksujen jakautuminen

Perusmaksu ja priorisointimaksu jakautuvat eri tavoin. Funktion
[`calculate_reward_and_burn_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L85-L98)
laskelmat ajonaikaisessa ympäristössä:

```text title="Fee distribution"
burn_amount     = transaction_fee * 50 / 100
validator_share = (transaction_fee - burn_amount) + priority_fee
```

- **Perusmaksu (transaction_fee)**: 50 % [poltetaan](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L93)
  (poistetaan kierrosta) ja 50 % menee lohkon tuottavalle validatorille. Poltettava osuus on
  [`DEFAULT_BURN_PERCENT = 50`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-calculator/src/lib.rs#L70).
- **Priorisointimaksu**: 100 % menee validatorille (mitään ei polteta),
  [SIMD-0096](https://github.com/solana-foundation/solana-improvement-documents/blob/main/proposals/0096-reward-collected-priority-fee-in-entirety.md):n mukaisesti.

Validatorin kokonaispalkkio tapahtumasta on:

```text
validator_reward = (base_fee / 2) + prioritization_fee
```

## Priorisointimaksu

Priorisointimaksu on valinnainen maksu, joka nostaa tapahtuman ajoitusprioriteettia.
Laskentayksikkö (CU) on laskentayksikkö, jota ajoympäristö mittaa tapahtuman suorituksen
aikana. Jokainen operaatio (aritmetiikka, muistin käyttö, syscall) maksaa kiinteän määrän
CU:ja. Voit asettaa priorisointimaksun sisällyttämällä compute budget -ohjeita tapahtumaasi.
(Katso [Prioriteettimaksujen käyttöopas](/docs/core/fees) lisätietoja varten.)

### Priorisointimaksun kaava

Funktio
[`get_prioritization_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L61-L69)
laskee:

```text title="Prioritization fee formula"
micro_lamport_fee = compute_unit_price * compute_unit_limit
prioritization_fee = ceil(micro_lamport_fee / 1,000,000)
```

| Muuttuja             | Kuvaus                                                                                                                                                                       | Oletus                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `compute_unit_price` | Mikro-lamports per CU, asetetaan `SetComputeUnitPrice`-ohjeella                                                                                                                              | 0 mikro-lamports                |
| `compute_unit_limit` | CU:jen enimmäismäärä, jonka tapahtuma voi kuluttaa, asetetaan `SetComputeUnitLimit`-ohjeella                                                                                                            | Ohjauskohtaisten oletusarvojen summa |
| `1 000 000`          | Muunnoskerroin mikro-lamportsista lamportsiin ([`MICRO_LAMPORTS_PER_LAMPORT`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L17)) | --                              |

<Callout type="info" title="v1-tapahtumat asettavat maksun suoraan">
  Tämä hinta kertaa raja -kaava koskee legacy- ja v0-tapahtumia. [v1-formaatissa](/docs/core/transactions/versioned-transactions#v1-format)
  priorisointimaksu on absoluuttinen kokonaissumma lamportsina, joka asetetaan suoraan
  viestikonfiguraatiossa — ei CU-kohtaista hintaa, ei kertolaskua, ei pyöristystä.
</Callout>

### Laskentayksiköiden raja

Laskentayksiköiden raja on CU:jen enimmäismäärä, jonka tapahtuma voi kuluttaa.
Jos
[`SetComputeUnitLimit`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L32)-ohjetta
ei sisällytetä, oletusarvo lasketaan ohjeiden määrän ja tyypin perusteella
(200 000 CU:ta ei-sisäänrakennettua ohjetta kohti, 3 000 sisäänrakennettua kohti). Katso
[Compute Budget](/docs/core/fees/compute-budget) lisätietoja oletusarvon laskennasta.

<Callout type="warn">
  Priorisointimaksu perustuu pyydettyyn CU-rajaan, ei todelliseen CU-kulutukseen.
  Korkeamman rajan asettaminen kuin tarvitaan tarkoittaa maksamista käyttämättömistä laskentayksiköistä.
</Callout>

### Laskentayksikön hinta

Laskentayksikön hinta on valinnainen mikro-lamports-määrä, joka maksetaan jokaisesta
pyydetystä CU:sta. CU-hinta määrää suoraan priorisointimaksun suuruuden. Aseta CU-hinta
sisällyttämällä
[`SetComputeUnitPrice`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L35)-ohje
tapahtumaasi.

<Callout>
  CU-hinnan oletusarvo on 0, eli priorisointimaksun oletusarvo on myös 0.
</Callout>

Reaaliaikaisia CU-hinta-arvioita varten katso alla olevat prioriteettimaksujen API-palveluntarjoajat.

| Palveluntarjoaja                                | Prioriteettimaksun API                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| [Helius](https://www.helius.dev/)       | [Dokumentaatio](https://docs.helius.dev/solana-apis/priority-fee-api)             |
| [QuickNode](https://www.quicknode.com/) | [Dokumentaatio](https://marketplace.quicknode.com/add-on/solana-priority-fee)     |
| [Triton](https://triton.one/)           | [Dokumentaatio](https://docs.triton.one/chains/solana/improved-priority-fees-api) |

### Tapahtumien ajoitusprioriteetti

Ajastin järjestää tapahtumat funktiolla
[`calculate_priority_and_cost`](https://github.com/anza-xyz/agave/blob/v3.1.8/core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs#L526-L546):

```text title="Transaction priority formula"
Priority = reward * 1,000,000 / (cost + 1)
```

- **reward**: validatorin maksutuotto = priorisointimaksu + perusmaksun polttamaton osuus.
  Lasketaan funktiolla [`calculate_reward_for_transaction`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L64-L83).
- **cost**: ajastimen [arvioitu CU-kustannus](https://github.com/anza-xyz/agave/blob/v3.1.8/cost-model/src/cost_model.rs#L37-L57)
  (allekirjoituskustannukset + kirjoituslukituskustannukset + instruction data -kustannukset +
  ohjelman suorituskustannukset + ladattujen tilien datakokokustannus). Katso
  [Compute Budget](/docs/core/fees/compute-budget#scheduler-cost-model) lisätietoja varten.
- **1 000 000**: tarkkuuden säilyttämiseksi käytetty kerroin, koska kustannus ylittää usein
  palkkion raakoina lamportsina.
- **+1**: estää nollalla jakamisen.

Prioriteetti määrittää järjestyksen, jossa tapahtumat poistetaan ajastimen puskurista
suoritettavaksi.

```ts !! title="Web3.js v3"
import {
  LAMPORTS_PER_SOL,
  SystemProgram,
  Transaction,
  Keypair,
  Connection,
  ComputeBudgetProgram,
  sendAndConfirmTransaction
} from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");

const sender = await Keypair.generate();
const recipient = await Keypair.generate();

const airdropSignature = await connection.requestAirdrop(
  sender.publicKey,
  LAMPORTS_PER_SOL
);
await connection.confirmTransaction(airdropSignature, "confirmed");

// Create compute budget instructions
const limitInstruction = ComputeBudgetProgram.setComputeUnitLimit({
  units: 300_000
});
const priceInstruction = ComputeBudgetProgram.setComputeUnitPrice({
  microLamports: 1
});

const transferInstruction = SystemProgram.transfer({
  fromPubkey: sender.publicKey,
  toPubkey: recipient.publicKey,
  lamports: 0.01 * LAMPORTS_PER_SOL
});

// Add the compute budget and transfer instructions to a new transaction
const transaction = new Transaction()
  .add(limitInstruction)
  .add(priceInstruction)
  .add(transferInstruction);

const signature = await sendAndConfirmTransaction(connection, transaction, [
  sender
]);

console.log("Transaction Signature:", signature);
```

```rust !! title="Rust"
use solana_client::nonblocking::rpc_client::RpcClient;
use solana_commitment_config::CommitmentConfig;
use solana_compute_budget_interface::ComputeBudgetInstruction;
use solana_sdk::{
    native_token::LAMPORTS_PER_SOL,
    signature::{Keypair, Signer},
    transaction::Transaction,
};
use solana_system_interface::instruction::transfer;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = RpcClient::new_with_commitment(
        String::from("http://localhost:8899"),
        CommitmentConfig::confirmed(),
    );

    let sender = Keypair::new();
    let recipient = Keypair::new();

    let airdrop_signature = client
        .request_airdrop(&sender.pubkey(), LAMPORTS_PER_SOL)
        .await?;

    loop {
        let confirmed = client.confirm_transaction(&airdrop_signature).await?;
        if confirmed {
            break;
        }
    }

    // Create compute budget instructions
    let limit_instruction = ComputeBudgetInstruction::set_compute_unit_limit(300_000);
    let price_instruction = ComputeBudgetInstruction::set_compute_unit_price(1);

    let transfer_amount = LAMPORTS_PER_SOL / 100;
    let transfer_instruction = transfer(&sender.pubkey(), &recipient.pubkey(), transfer_amount);

    let recent_blockhash = client.get_latest_blockhash().await?;

    let mut transaction = Transaction::new_with_payer(
        &[limit_instruction, price_instruction, transfer_instruction],
        Some(&sender.pubkey()),
    );
    transaction.sign(&[&sender], recent_blockhash);

    let signature = client.send_and_confirm_transaction(&transaction).await?;
    println!("Transaction Signature: {}", signature);

    Ok(())
}
```
