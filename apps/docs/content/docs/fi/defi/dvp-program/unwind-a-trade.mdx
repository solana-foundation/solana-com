Neljä instruktiota palauttaa varat ilman selvitystä: Reclaim, Cancel ja Reject
kaupan ollessa avoin sekä Recover talletukselle, joka saapuu kaupan sulkeutumisen
jälkeen. Mikään niistä ei tarkista vanhenemisaikaa. Jäädytetty escrow tai
muuttunut mint voi silti pitää osuuden lukittuna, kuten lopun huomiot kuvaavat.

| Instruktio  | Allekirjoittaja               | Laajuus                         | Kauppa sen jälkeen |
| ------------ | -------------------- | ----------------------------- | ---------------- |
| `ReclaimDvp` | `user_a` tai `user_b` | Allekirjoittajan oma osuus          | Yhä avoin       |
| `CancelDvp`  | Selvitysvaltuutettu | Molemmat osuudet                     | Suljettu           |
| `RejectDvp`  | `user_a` tai `user_b` | Molemmat osuudet                     | Suljettu           |
| `RecoverDvp` | `user_a` tai `user_b` | Allekirjoittajan osuus sulkemisen jälkeen | Jo suljettu   |

Kussakin tapauksessa escrow tyhjennetään kaikesta, mitä se sisältää, osuuden
osapuolelle: escrow A `user_a`:n `mint_a`-tokenin token account -tilille, escrow B
`user_b`:n `mint_b`-tokenin token account -tilille, riippumatta siitä, kuka sen
rahoitti. Memo-ohjelman program account annetaan palautustileille, jotka vaativat
memon.

Tämä sivu jatkaa aiemmista vaiheista: asiakas ja allekirjoittajat kohdasta
[luo kauppa](/docs/defi/dvp-program/create-a-trade), `userAAtaA` ja
`userBAtaB` kohdasta [rahoita osuudet](/docs/defi/dvp-program/fund-the-legs) sekä
`MEMO_PROGRAM_ID` ja `authority` kohdasta
[selvitä kauppa](/docs/defi/dvp-program/settle-the-trade) siirtyvät tähän.

## Ota osuus takaisin

Reclaim palauttaa allekirjoittajan osuuden ja jättää kaupan avoimeksi, joten
osuus voidaan rahoittaa uudelleen. Käytä sitä, kun ongelma on vastapuolen
osuudessa; Cancel ja Reject sulkevat koko kaupan.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getReclaimDvpInstruction } from "./dvp";

    // The asset-leg party takes its asset back.
    const reclaimInstruction = getReclaimDvpInstruction({
      signer: userASigner,
      swapDvp,
      mint: mintA,
      dvpSourceAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
    });

    await client.sendTransaction([reclaimInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::ReclaimDvpBuilder;

    // The asset-leg party takes its asset back.
    let reclaim_ix = ReclaimDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .mint(mint_a)
        .dvp_source_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .instruction();
    ```

  </Tab>
</Tabs>

## Cancel tai Reject

Cancel allekirjoitetaan selvitysvaltuutetun avaimella ja Reject kummalla tahansa
osapuolella. Molemmat palauttavat kunkin escrowin sisällön osuuden osapuolelle
sekä sulkevat tietueen ja molemmat escrowt, ja suljettujen tilien rent menee
allekirjoittajalle. Instruktiot käyttävät samoja tilejä; vain allekirjoittaja
eroaa.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCancelDvpInstruction, getRejectDvpInstruction } from "./dvp";

    const unwindAccounts = {
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    };

    // Signed by the settlement authority:
    const cancelInstruction = getCancelDvpInstruction({
      settlementAuthority: authoritySigner,
      ...unwindAccounts,
    });

    // Or signed by either party:
    const rejectInstruction = getRejectDvpInstruction({
      signer: userBSigner,
      ...unwindAccounts,
    });
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::{CancelDvpBuilder, RejectDvpBuilder};

    // Signed by the settlement authority:
    let cancel_ix = CancelDvpBuilder::new()
        .settlement_authority(authority)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();

    // Or signed by either party:
    let reject_ix = RejectDvpBuilder::new()
        .signer(user_b)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();
    ```

  </Tab>
</Tabs>

Palautustilien (`userAAtaA`, `userBAtaB`) on oltava olemassa kaikille osuuksille,
joilla on saldo; alustamaton palautustili saa token-siirron epäonnistumaan ja
peruu instruktion. Osuus, jota ei koskaan rahoitettu, ei tarvitse siirtoa ja
sietää puuttuvaa tiliä.

## Myöhästyneen talletuksen palautus

Settle, Cancel ja Reject sulkevat kaikki molemmat escrow token account -tilit,
joten pelkkä siirto suljettuun escrowiin epäonnistuu. Talletus päätyy perille
sulkemisen jälkeen vain, jos jokin luo escrowin ensin uudelleen, esimerkiksi
rahoitustransaktio, joka sisältää ennen siirtoa idempotentin associated token
account -tilin luontiinstruktion ja oli lähetettynä, kun vastapuoli lähetti
Rejectin. Tokenit jäävät silloin escrowiin, jonka kauppaa ei enää ole: tietue on
poissa, joten Reclaim ei löydä sitä, ja noncen tombstone-merkintä estää luomasta
uutta kauppaa samaan osoitteeseen ja kaappaamasta talletusta.

`RecoverDvp`-instruktion käyttämiseksi osuuden osapuoli antaa alkuperäiset
seed-syötteet (selvitysvaltuutettu, molemmat osapuolet, molemmat mintit, nonce).
Ohjelma johtaa tietueen osoitteen uudelleen, vaatii sen tombstone-merkinnän
todisteeksi kaupan olemassaolosta, tyhjentää escrowin allekirjoittajan omalle
token account -tilille ja sulkee sen, jolloin escrowin rent palautuu
allekirjoittajalle. Allekirjoittajan osuus määräytyy sen mukaan, kumpi osapuoli
allekirjoittaa: `mint_a` osapuolelle `user_a`, `mint_b` osapuolelle `user_b`.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getAddressEncoder, getProgramDerivedAddress } from "@solana/kit";
    import { DVP_SWAP_PROGRAM_PROGRAM_ADDRESS, getRecoverDvpInstruction } from "./dvp";

    const [nonceTombstone] = await getProgramDerivedAddress({
      programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
      seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
    });

    const recoverInstruction = getRecoverDvpInstruction({
      signer: userASigner,
      swapDvp,
      nonceTombstone,
      mint: mintA,
      dvpEscrowAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });

    await client.sendTransaction([recoverInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::RecoverDvpBuilder;

    let recover_ix = RecoverDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .nonce_tombstone(nonce_tombstone)
        .mint(mint_a)
        .dvp_escrow_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .settlement_authority(settlement_authority)
        .user_a(user_a)
        .user_b(user_b)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .nonce(nonce)
        .instruction();
    ```

  </Tab>
</Tabs>

Palautus edellyttää, että osapuoli säilyttää luontiparametrit. Kauppoja
rahoittava järjestelmä tallentaa seed-syötteet kunkin toimeksiannon mukana, kunnes
kauppa on suljettu ja escrow-saldojen on vahvistettu olevan tyhjät.

## Huomioita

- **Jäädytetyt osuudet.** Rajoitetulla (gated) mintillä jäädytetty escrow estää
  näiden instruktioiden suorittaman token-siirron, kunnes freeze authority purkaa
  jäädytyksen. Katso [yleiskatsaus](/docs/defi/dvp-program#mint-configuration-constraints).
- **Mintin muutokset luonnin jälkeen.** Purkupolut ohittavat laajennus- ja mint
  authority -tarkistukset, jotta ohjelman omat tarkistukset eivät estä palautusta.
  Token Program -ohjelman omat säännöt silti pätevät. Mint voidaan sulkea vain,
  kun sen kokonaistarjonta on nolla, joten se ei voi muuttua escrowissa olevan
  saldon aikana. Mint, joka suljetaan ja luodaan uudelleen NonTransferable-
  tyyppisenä tai siirtomaksulla ennen myöhäisen talletuksen saapumista, voi
  kuitenkin tehdä talletuksesta siirtokelvottoman tai maksullisen. Tämä on
  [tuetut tokenit](/docs/defi/dvp-program#supported-tokens) -kohdassa mainittu mint authority -riippuvuus.
