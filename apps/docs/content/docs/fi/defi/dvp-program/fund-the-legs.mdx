Rahoitus on tavallinen `TransferChecked`-siirto osuuden escrow-tilille, joten mikä tahansa lompakko tai
säilytysjärjestelmä, joka pystyy lähettämään tokensiirron, voi rahoittaa osuuden. Vain kauppatietueen
luku ennen rahoitusta vaatii DvP-asiakasohjelman. Ohjelma tarkistaa
escrow-saldot vasta selvityksessä; mikään ei tarkista siirtoa sen saapuessa,
joten kunkin osapuolen on luettava kauppatietue ennen siirtoa.

Tämä sivu jatkaa sivulta
[luo kauppa](/docs/defi/dvp-program/create-a-trade); asiakasohjelma ja allekirjoittajat
jatkuvat sellaisinaan.

## Tarkista ehdot

Tietueen luominen ei vaadi lupaa, ja escrow-osoitteet johdetaan pelkästään
tietueesta ja mintistä, ei koskaan ehdoista. Siirto escrow-tilille voi siksi
osua ehtoihin, joista et ole koskaan sopinut, mukaan lukien selvityksen
kohteet, jotka ohjaavat vastapuolesi tuotot kolmanteen osoitteeseen.
Lue ennen rahoitusta `SwapDvp`-tili ja vertaa sitä sovittuun kauppaan.

TypeScriptin `verifySwapDvp` ja Rustin `verify::decode_swap_dvp_account`
varmistavat, että tilin omistaa DvP-ohjelma, että sen koko on täsmälleen 458 tavua ja että
se sijaitsee osoitteessa, joka johdetaan sen omista kentistä (`fetchSwapDvpChecked` suorittaa
vain kaksi ensimmäistä tarkistusta). Tavalliset `fetchSwapDvp`- ja `decodeSwapDvp`-lukijat
eivät tee mitään näistä tarkistuksista. Osapuolten, summien, aikojen ja kohteiden tarkistukset
tekee kutsuja sovittua kauppaa vasten.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { unwrapOption } from "@solana/kit";
    import { verifySwapDvp } from "./dvp";

    const trade = await verifySwapDvp(client.rpc, swapDvp);
    const t = trade.data;

    const expectedAmountA = 1_000_000_000n;
    const expectedAmountB = 998_500_000n;
    const expectedEarliestSettlement: bigint | null = null; // as agreed
    const expectedExpiry = 1_798_761_600n; // as agreed, unix seconds

    if (
      t.userA !== userA ||
      t.userB !== userB ||
      t.mintA !== mintA ||
      t.mintB !== mintB ||
      t.settlementAuthority !== settlementAuthority ||
      t.tokenProgramA !== tokenProgramA ||
      t.tokenProgramB !== tokenProgramB ||
      t.amountA !== expectedAmountA ||
      t.amountB !== expectedAmountB ||
      unwrapOption(t.earliestSettlementTimestamp) !== expectedEarliestSettlement ||
      t.expiryTimestamp !== expectedExpiry ||
      t.userASettlementDestination !== userA ||
      t.userBSettlementDestination !== userB
    ) {
      throw new Error("Stored terms do not match the agreed trade; do not fund");
    }

    if (t.expiryTimestamp <= BigInt(Math.floor(Date.now() / 1000)) + 60n) {
      throw new Error("Trade expires too soon to fund safely");
    }
    ```

  </Tab>

  <Tab value="Rust">
    ```rust

    use solana_client::rpc_client::RpcClient;
    use solana_commitment_config::CommitmentConfig;

        CommitmentConfig::confirmed(),

    let trade = decode_swap_dvp_account(&swap_dvp, &account)?;

    let expected_amount_a: u64 = 1_000_000_000;
    let expected_amount_b: u64 = 998_500_000;
    let expected_earliest_settlement: Option<i64> = None; // as agreed
    let expected_expiry: i64 = 1_798_761_600; // as agreed, unix seconds

    if trade.user_a != user_a
        || trade.user_b != user_b
        || trade.mint_a != mint_a
        || trade.mint_b != mint_b
        || trade.settlement_authority != settlement_authority
        || trade.token_program_a != token_program_a
        || trade.token_program_b != token_program_b
        || trade.amount_a != expected_amount_a
        || trade.amount_b != expected_amount_b
        || trade.earliest_settlement_timestamp != expected_earliest_settlement
        || trade.expiry_timestamp != expected_expiry
        || trade.user_a_settlement_destination != user_a
        || trade.user_b_settlement_destination != user_b
    {
        return Err("stored terms do not match the agreed trade; do not fund".into());
    }

        .duration_since(std::time::UNIX_EPOCH)?
        .as_secs() as i64;
    if trade.expiry_timestamp <= now_seconds + 60 {
        return Err("trade expires too soon to fund safely".into());
    }
    ```

Jos vastapuolesi tai selvitysviranomainen loi tietueen,
vertaa jokaista kenttää ehtoihin, joista sovit pääkirjan ulkopuolella. Jos loit
sen itse, tämä luku vahvistaa, että se tallentui lähetetyssä muodossa.

## Siirrä varat escrow-tilille

Rahoita osuus täsmälleen sovitulla summalla. Ohjelma rajaa selvityksen
summaan `amount_x` ja palauttaa ylimenevän osan osuuden osapuolelle, joten ylijäämä ei katoa,
mutta se lisää selvitykseen toisen siirron ja voi epäonnistua joidenkin transfer hookien kanssa
(katso alla olevat huomautukset).

Käytä `TransferChecked`-siirtoa, älä tarkistamatonta `Transfer`-siirtoa. Token-2022-mintit,
joiden laajennukset riippuvat mint accountista, kuten Pausable, hylkäävät siirron,
joka ei sisällä sitä, ja mint, jolla on transfer hook, vaatii hookin
tilien selvittämisen ja liittämisen samalla tavalla kuin minkä tahansa muun
kyseisen tokenin siirron kohdalla.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    Omaisuusosuuden osapuoli rahoittaa allekirjoittajanaan `userASigner` escrow A:n:

    ```ts
    import {
      findAssociatedTokenPda,
      getTransferCheckedInstruction,
    } from "@solana-program/token-2022";

    const [userAAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: userA,
      tokenProgram: tokenProgramA,
    });
    const [userBAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: userB,
      tokenProgram: tokenProgramB,
    });

    const fundAssetLeg = getTransferCheckedInstruction({
      source: userAAtaA,
      mint: mintA,
      destination: escrowA,
      authority: userASigner,
      amount: t.amountA,
      decimals: 6,
    }, { programAddress: tokenProgramA });

    await client.sendTransaction([fundAssetLeg]);
    ```

    Käteisosuuden osapuoli tekee saman escrow B:lle käyttäen arvoja `userBAtaB`, `mintB`,
    `userBSigner`, `t.amountB` ja `{ programAddress: tokenProgramB }`.

  </Tab>

  <Tab value="Rust">

    Käteisosuuden osapuoli rakentaa saman instruktion escrow B:lle käyttäen arvoja `mint_b`,
    `user_b` ja `trade.amount_b`.

Rahoitussiirto, joka näkyy tilassa [`confirmed`](/docs/rpc#configuring-state-commitment),
voi silti korvautua toisella. Ohjelma lukee escrow-saldon ketjusta
selvityshetkellä, joten Settle-instruktio, joka lähetetään sellaista rahoitussiirtoa vasten, joka ei tallentunut, epäonnistuu
virheeseen `LegNotFunded` eikä mikään liiku; kustannuksena on epäonnistunut Settle ja uusi yritys.
Käsittele osuutta rahoitettuna vasta, kun sen siirto on tilassa `finalized`.

## Huomautukset

- **Wrapped SOL -osuudet.** Ohjelma lukee natiivin escrow-tilin saldon
  synkronoituaan sen, joten järjestelmäsiirrolla wrapped SOL -escrow-tilille lähetetyt lamport-yksiköt
  lasketaan mukaan. Älä koskaan lähetä SOLia escrow-tilille minkään muun mintin osalta: ohjelma ei voi
  palauttaa sitä, ja se päätyy sille, joka sulkee tilin.
- **Rajatut mintit.** Mintillä, jonka Default Account State on frozen, escrow-tili
  luodaan jäädytettynä, ja siirto epäonnistuu, kunnes liikkeeseenlaskija sulattaa tilin tai hyväksyy sen.
  [Yleiskatsaus](/docs/defi/dvp-program#mint-configuration-constraints) kuvaa
  vuorovaikutuksen Token ACL:n kanssa.
- **Transfer hookit.** Rahoita hookia käyttävät escrow-tilit täsmälleen sovitulla summalla. Jos
  ylijäämä pakottaa palautuksen selvityksessä, palautus käyttää uudelleen osuuden hook-tilejä
  eri kohteella ja summalla, minkä jotkin hookit hylkäävät. Korjaus on
  Reclaim, rahoitus uudelleen täsmällisellä summalla ja uusi selvitys.
- **Rahoitus eräpäivän jälkeen.** Mikään ei estä siirtoa `expiry_timestamp`-ajan jälkeen. Se
  tallentuu, selvitys ei ole enää mahdollinen, ja osuuden osapuoli saa varat takaisin
  Reclaim-instruktiolla kaupan ollessa avoin tai Recover-instruktiolla sen sulkeuduttua. Katso
  [kaupan purkaminen](/docs/defi/dvp-program/unwind-a-trade).
- **Kuka rahoittaa ensin.** Ohjelma ei järjestä kahta osuutta jonoon. Järjestys
  on osapuolten sovittavissa; kumpi tahansa osapuoli voi lunastaa oman osuutensa takaisin milloin tahansa
  ennen selvitystä, ellei mintin valtuutettu (freeze, pause tai transfer hook)
  estä escrow-tiliä.
