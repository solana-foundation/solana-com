`CreateDvp` tallentaa kaupan ehdot ja luo kaksi escrow-tiliä, jotka osapuolet rahoittavat. Se ei siirrä tokeneita. Kuka tahansa voi lähettää sen, joten tietue voi tulla vastapuolelta, selvitysvaltuutetun operaattorilta tai kolmannelta osapuolelta, ja jokainen muu osallistuja tarkistaa tallennetut ehdot ennen kuin toimii niiden pohjalta (katso [osuuksien rahoittaminen](/docs/defi/dvp-program/fund-the-legs)).

Katkelmat käyttävät generoitua clientia suoraan ja paikkamerkkiosoitteita, jotta mukana olevat tilit ja allekirjoittajat näkyvät selvästi. Ne kohdistuvat devnetiin, jossa ohjelma on otettu käyttöön samassa osoitteessa kuin mainnet-betassa.

## Asennus

DvP-clienteille ei ole julkaistu pakettia 2.10.2026 mennessä. Molemmat generoidaan ohjelman IDL:stä repositoriossa, ja niitä käytetään lähdekoodista.

Nämä sivut on kirjoitettu commitia `df9919e` vasten, käyttäen TypeScriptissä `@solana/kit` 8 -kirjastoa ja Rustissa `solana-*` 2.x -crateja.

Jokaisen vaihesivun katkelmat jatkavat toisistaan: kukin sivu käyttää aiemmilla sivuilla määriteltyä clientia, allekirjoittajia ja osoitteita. `payerSigner`, `userASigner`, `userBSigner` ja `authoritySigner` ovat `TransactionSigner`-olioita rent-maksajalle, kahdelle osapuolelle ja selvitysvaltuutetulle, esimerkiksi funktiolla `createKeyPairSignerFromBytes` luotuina. Rust-katkelmat rakentavat käskyt ja jättävät allekirjoittamisen ja lähettämisen kutsujan vastuulle.

## Johda osoitteet

Kaupan tietue on program-derived address, joka johdetaan selvitysvaltuutetusta, kahdesta osapuolesta, kahdesta mintistä ja noncesta. Kumpikin escrow on tietueen associated token account jommallekummalle mintille. Kumpikin johtaminen onnistuu ilman verkkoyhteyttä.

Käytä jokaiselle kaupalle satunnaista 64-bittistä noncea. Koska luonti on avointa kaikille, ennustettava nonce antaa kolmannelle osapuolelle mahdollisuuden varata osoitteen, jota kauppa olisi käyttänyt. Anna nonce ja määrät TypeScriptissä `bigint`-tyyppisinä; generoitu client hylkää `number`-arvon.

Korvaa jokainen `..._HERE`-paikkamerkki oikealla osoitteella ennen suorittamista. `address()` validoi base58-muodon ja heittää virheen paikkamerkistä, ja `pubkey!` ei käänny.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## Tallenna ehdot

`CreateDvp` ottaa vastaan kaksi määrää perusyksiköinä, vanhenemisajan, noncen ja neljä valinnaista kenttää: enintään 64 tavun mittaisen läpinäkymättömän viitteen, kummallekin osapuolelle selvityskohteen ja aikaisimman selvitysajan (katso Huomioita). Selvityskohde on paikka, johon kyseisen osapuolen tuotto päätyy selvityksessä, esimerkiksi säilyttäjän talletuslompakko; oletuksena se on osapuolen oma osoite, ja se lukitaan, kun tietue on luotu. Hyvitykset ja takaisinotot menevät aina osapuolen omalle token accountille kyseisen osuuden mintille, ei koskaan selvityskohteeseen, riippumatta siitä, kuka escrow'n rahoitti.

Maksaja rahoittaa tietueen, noncen tombstonen ja molempien escrow-tilien rentin. Sulkemisen yhteydessä tämä rent menee sulkevan käskyn allekirjoittajalle, ei takaisin maksajalle. Tombstonea ei koskaan suljeta, joten jokainen kauppa jättää pienen pysyvän saldon. Kun budjetoit maksajan SOL-määrää, johda rent-summat `getMinimumBalanceForRentExemption`-RPC-metodilla äläkä kovakoodaa niitä.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCreateDvpInstruction } from "./dvp";

    const nowSeconds = BigInt(Math.floor(Date.now() / 1000));

    const createInstruction = getCreateDvpInstruction({
      payer: payerSigner,
      swapDvp,
      nonceTombstone: (
        await getProgramDerivedAddress({
          programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
          seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
        })
      )[0],
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      tokenProgramA,
      tokenProgramB,
      amountA: 1_000_000_000n, // 1,000 units of a 6-decimal asset
      amountB: 998_500_000n, // 998.50 units of a 6-decimal cash token
      expiryTimestamp: nowSeconds + 60n * 60n * 24n, // one day
      nonce,
      refString: "ORDER-2026-10-02-0001",
      userASettlementDestination: null, // defaults to userA
      userBSettlementDestination: null, // defaults to userB
      earliestSettlementTimestamp: null,
    });

    const { context } = await client.sendTransaction([createInstruction]);
    console.log("Trade record:", swapDvp, "signature:", context.signature);
    ```

TypeScript-katkelma vaatii, että `getProgramDerivedAddress` ja `getAddressEncoder` paketista `@solana/kit` sekä `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` clientista ovat käytettävissä (in scope). Rust-builder jättää system programin ja associated token programin oletusarvoihinsa.

## Huomioita

- **Vanhenemisaika.** Vain Settle tarkistaa vanhenemisajan. Reclaim, Cancel ja Reject toimivat sen jälkeenkin, ja vanhenemisen jälkeen saapuneen talletuksen voi periä takaisin kyseisen osuuden osapuoli. Vanhenemisaika voi olla enintään vuosi luomishetkestä.
- **Aika on verkon aikaa.** Ohjelma lukee ketjun kelloa, joka voi poiketa seinäkellon ajasta, ajoittain kymmenillä sekunneilla, ja voi hypätä eteenpäin. Jätä vanhenemisajan ja aiotun selvitysajan väliin marginaali, vältä rahoitusta tai selvitystä kummankaan rajan lähellä äläkä luota siihen, että vanhenemisaika pakottaa määräajan sekunnin tarkkuudella. Ohjelman README ehdottaa noin minuutin ajautumisvaraa.
- **Aikaisin selvitysaika.** Valinnainen. Jos se on asetettu, Settle hylätään ennen sitä, eikä se saa olla vanhenemisaikaa myöhäisempi.
- **Luontihetken tarkistukset.** Create epäonnistuu virheeseen `PartyNotSignerCapable`, jos osapuoli ei ole System Program -ohjelman omistama tili (tämä sulkee pois SPL Token -multisigin), tai johonkin virheistä `SettlementDestinationIsSwapDvp`, `SelfDvp`, `SameMint`, `ZeroAmount`, `SettlementAuthorityIsParty` tai `ExpiryNotInFuture`. Täydellinen luettelo on [virhetaulukossa](/docs/defi/dvp-program#errors).
