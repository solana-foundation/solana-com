`CreateDvp` tallentaa kaupan ehdot ja luo kaksi escrow-tiliä, jotka osapuolet
rahoittavat. Se ei siirrä yhtään tokenia. Kuka tahansa voi lähettää sen, joten
tietue voi tulla vastapuolelta, selvitysvaltuuden operaattorilta tai kolmannelta
osapuolelta, ja jokaisen muun osallistujan tulee tarkistaa tallennetut ehdot
ennen kuin toimii niiden perusteella (ks. [rahoita osuudet](/docs/defi/dvp-program/fund-the-legs)).

Koodinpätkät käyttävät generoitua clientia suoraan ja paikkamerkkiosoitteita,
jotta mukana olevat tilit ja allekirjoittajat näkyvät selvästi. Ne kohdistuvat
devnetiin, jossa ohjelma on otettu käyttöön samassa osoitteessa kuin
mainnet-betassa.

## Asennus

DvP-clienteille ei ole julkaistu pakettia 2. lokakuuta 2026 mennessä. Molemmat
generoidaan ohjelman IDL:stä repositoriossa ja niitä käytetään lähdekoodista.

Nämä sivut on kirjoitettu commitia `df9919e` vasten: TypeScriptissä
`@solana/kit` 8:lla ja Rustissa `solana-*` 2.x -crateilla.

Jokaisen vaihesivun koodinpätkät jatkuvat edellisistä: kukin sivu käyttää
aiemmilla sivuilla määriteltyä clientia, allekirjoittajia ja osoitteita.
`payerSigner`, `userASigner`, `userBSigner` ja `authoritySigner` ovat
`TransactionSigner`-olioita rent-maksajalle, kahdelle osapuolelle ja
selvitysvaltuudelle, esimerkiksi `createKeyPairSignerFromBytes`-funktiosta.
Rust-koodinpätkät rakentavat instruktiot ja jättävät allekirjoittamisen ja
lähettämisen kutsujalle.

## Johda osoitteet

Kauppatietue on Program Derived Address, joka johdetaan selvitysvaltuudesta,
kahdesta osapuolesta, kahdesta mintistä ja noncesta. Kukin escrow on tietueen
associated token account yhdelle minteistä. Kumpikin johto toimii ilman
verkkoyhteyttä.

Käytä jokaiselle kaupalle satunnaista 64-bittistä noncea. Koska luonti ei vaadi
lupaa, ennustettava nonce sallii kolmannen osapuolen varata osoitteen, jota
kauppa olisi aikonut käyttää. Anna nonce ja summat TypeScriptissä
`bigint`-tyyppisinä; generoitu client hylkää `number`-arvon.

Korvaa jokainen `..._HERE`-paikkamerkki oikealla osoitteella ennen ajoa.
`address()` validoi base58-muodon ja heittää virheen paikkamerkistä, ja
`pubkey!` ei käänny.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

  <Tab value="Rust">

## Tallenna ehdot

`CreateDvp` ottaa parametreikseen kaksi summaa perusyksiköissä, erääntymisajan,
noncen ja neljä valinnaista kenttää: enintään 64 tavun mittaisen läpinäkymättömän
viitteen, kummankin puolen selvityskohteen sekä aikaisimman selvitysajan (ks.
Huomiot). Selvityskohde on paikka, johon kyseisen osapuolen tuotot päätyvät
selvityksessä, esimerkiksi säilytyspalvelun talletuslompakko; oletuksena se on
osapuolen oma osoite, ja se lukitaan, kun tietue on luotu. Palautukset ja
takaisinvaaditut varat menevät aina osapuolen omalle token account -tilille
kyseisen osuuden mintille, eivät koskaan selvityskohteeseen, riippumatta siitä,
kuka escrow-tilin rahoitti.

Maksaja rahoittaa tietueen, nonce-tombstonen ja molempien escrow-tilien rentin.
Suljettaessa rent menee sille, joka allekirjoittaa sulkevan instruktion, ei
takaisin maksajalle. Tombstonea ei koskaan suljeta, joten jokainen kauppa jättää
jälkeensä pienen pysyvän saldon. Kun budjetoit maksajan SOL-määrää, johda
rent-summat RPC-metodilla `getMinimumBalanceForRentExemption` sen sijaan, että
kovakoodaisit ne.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCreateDvpInstruction } from "./dvp";

    const nowSeconds = BigInt(Math.floor(Date.now() / 1000));

    const createInstruction = getCreateDvpInstruction({
      payer: payerSigner,
      swapDvp,
      nonceTombstone: (
        await getProgramDerivedAddress({
          programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
          seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
        })
      )[0],
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      tokenProgramA,
      tokenProgramB,
      amountA: 1_000_000_000n, // 1,000 units of a 6-decimal asset
      amountB: 998_500_000n, // 998.50 units of a 6-decimal cash token
      expiryTimestamp: nowSeconds + 60n * 60n * 24n, // one day
      nonce,
      refString: "ORDER-2026-10-02-0001",
      userASettlementDestination: null, // defaults to userA
      userBSettlementDestination: null, // defaults to userB
      earliestSettlementTimestamp: null,
    });

    const { context } = await client.sendTransaction([createInstruction]);
    console.log("Trade record:", swapDvp, "signature:", context.signature);
    ```

TypeScript-koodinpätkä edellyttää, että `getProgramDerivedAddress` ja
`getAddressEncoder` paketista `@solana/kit` sekä
`DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` clientista ovat näkyvissä. Rust-builderissa
System Program ja Associated Token Program jäävät oletusarvoihinsa.

## Huomiot

- **Erääntyminen.** Vain Settle tarkistaa erääntymisajan. Reclaim, Cancel ja
  Reject toimivat sen jälkeenkin, ja erääntymisen jälkeen saapuneen talletuksen
  osuuden osapuoli voi periä takaisin. Erääntymisaika voi olla enintään vuosi
  luonnista.
- **Aika on verkon aikaa.** Ohjelma lukee onchain-kelloa, joka voi poiketa
  seinäkellon ajasta, ajoittain kymmenillä sekunneilla, ja voi hypätä eteenpäin.
  Jätä erääntymisen ja aiotun selvitysajan väliin marginaali, vältä rahoitusta
  tai selvitystä kummankaan rajan lähellä äläkä luota siihen, että erääntyminen
  pakottaisi määräajan sekunnintarkasti. Ohjelman README suosittelee varaamaan
  noin minuutin verran ajautumaa.
- **Aikaisin selvitys.** Valinnainen. Jos arvo on asetettu, Settle hylätään ennen
  sitä, eikä se saa olla erääntymisaikaa myöhäisempi.
- **Luontihetken tarkistukset.** Luonti epäonnistuu virheeseen
  `PartyNotSignerCapable`, jos osapuoli ei ole System Programin omistama tili
  (tämä sulkee pois SPL Token -multisigin), tai virheisiin
  `SettlementDestinationIsSwapDvp`, `SelfDvp`, `SameMint`, `ZeroAmount`,
  `SettlementAuthorityIsParty` tai `ExpiryNotInFuture`. Täydellinen luettelo on
  [virhetaulukossa](/docs/defi/dvp-program#errors).
