## Avainten hallinta

- **Älä koskaan paljasta yksityisiä avaimia frontend-koodissa.** Käytä backend-allekirjoitusta, laitelompakoita, monen allekirjoittajan lompakoita tai avainhallintapalveluita.
- **Erota kuumat ja kylmät lompakot toisistaan.** Käytä kuumaa lompakkoa
  päivittäiseen toimintaan ja kylmää lompakkoa omaisuuden säilytykseen.
- **Varmuuskopioi kaikki tuotantoavaimet.** Säilytä salatut varmuuskopiot
  useissa turvallisissa paikoissa. Avaimen menettäminen tarkoittaa pääsyn
  menettämistä pysyvästi.
- **Käytä eri avaimia devnetissä ja mainnetissä.** Devnet-avaintesi ei pitäisi
  olla samoja kuin mainnet-avaintesi. Käytä ympäristöpohjaista konfiguraatiota,
  jotta kullekin verkolle ladataan oikeat avaimet.

## Allekirjoitusinfrastruktuuri

Tuotantokäytön backend-allekirjoitukseen kannattaa käyttää [Keychainia](/docs/tools/keychain) – yhtenäistä
allekirjoituskirjastoa, joka abstrahoi useita avainhallinnan taustajärjestelmiä yhden
rajapinnan taakse: Memory, Vault, Privy, Turnkey, AWS KMS, Fireblocks, GCP KMS, CDP,
Para, Dfns, Crossmint, Openfort ja Utila. Näin voit kehittää paikallisesti
muistissa olevilla avaimilla ja siirtyä sen jälkeen tuotantotason taustajärjestelmiin muuttamatta
sovelluskoodia.

Etkö ole varma, mikä taustajärjestelmä sopii sinulle? Katso
[Taustajärjestelmän valinta](/docs/tools/keychain/choosing-a-backend). Keychain on
saatavilla sekä [Rustille](https://crates.io/crates/solana-keychain) että
[TypeScriptille](https://www.npmjs.com/package/@solana/keychain).

## RPC-tietoturva

Kohtele RPC-päätepisteitä kuten API-avaimia – älä paljasta niitä frontend-koodissa, josta
ne voidaan poimia ja joutua väärinkäytetyiksi. Käytä backend-välityspalvelinta tai ympäristömuuttujia,
jotka eivät päädy asiakaskoodin pakettiin.

- [QuickNode: päätepisteiden tietoturvan parhaat käytännöt](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: suojaa Solana API -avaimesi: tietoturvan parhaat käytännöt](https://www.helius.dev/docs/rpc/protect-your-keys)

## Valvonta

Seuraa tuotannossa näitä mittareita:

| Mittari                   | Syy                    |
| ------------------------ | ---------------------- |
| Transaktioiden onnistumisprosentti | Havaitse ongelmat ajoissa    |
| Vahvistuksen viive     | Seuraa verkon tilaa |
| Prioriteettimaksuihin kuluva summa       | Kustannusten hallinta        |
| RPC-virheiden osuus           | Palveluntarjoajan tila        |

Määritä hälytykset seuraaville:

- Kynnysarvon ylittävät siirrot omaisuuden säilytyslompakosta
- Epäonnistuneiden transaktioiden osuuden äkilliset piikit
- Epätavalliset vastaanottajakuviot
- RPC-virheiden osuuden kasvu

Jos tarvitset reaaliaikaista transaktioiden valvontaa laajassa mittakaavassa, katso
[indeksointiopas](/docs/payments/accept-payments/indexing).

## Tarkista osoitteet

Jokaisella tokenilla ja ohjelmalla on mainnetissa täsmälleen yksi oikea osoite. Väärennetyt
tokenit, jotka matkivat USDC:tä tai muita stablecoineja, ovat yleisiä – niillä on sama nimi
ja symboli, mutta eri mint. Sovelluksesi tulisi kovakoodata tai sallia vain tietyt
mint-osoitteet (tarpeidesi mukaan) eikä koskaan hyväksyä niitä dynaamisesti
epäluotettavista lähteistä.

**Ympäristöpohjainen konfiguraatio:** Devnet ja Mainnet käyttävät usein täysin
eri token-mintejä. Määritä sovelluksesi konfiguraatio lataamaan oikeat
osoitteet kullekin ympäristölle – älä kovakoodaa mainnet-osoitteita ja unohda vaihtaa
niitä testauksen aikana, tai mikä pahempaa, julkaise devnet-osoitteita tuotantoon.

Joitakin yleisiä stablecoin-mintejä ovat:

| Token | Liikkeeseenlaskija | Mint-osoite                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

Myös ohjelmien osoitteilla on väliä. Ohjeiden lähettäminen väärälle ohjelmalle epäonnistuu
– tai mikä pahempaa, johtaa varojen peruuttamattomaan menetykseen. Token Program -ohjelmien
osoitteet ovat:

| Ohjelma            | Osoite                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Program | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

Oikeiden osoitteiden salliminen suojaa väärennetyiltä tokeneilta, mutta se ei
suojaa siltä, että lähetät varoja väärän _tyyppiselle_ tilille. Vastaanottajan osoite
voi olla lompakko, token account, mint tai ohjelma, ja jokainen vaatii
erilaista käsittelyä. Muuhun kuin lompakkoon lähetetty natiivi SOL poistuu
lähettäjän hallinnasta – se menetetään lopullisesti, jos kohde on mint tai ohjelma, ja
vain tilin omistaja voi saada sen takaisin, jos kohde on token account – eikä
epäonnistunut transaktio varoita käyttäjää.

<Callout type="warn" title="Tarkista vastaanottajat ennen lähettämistä">
  Luokittele jokainen vastaanottajan osoite ennen siirron allekirjoittamista. Katso [Osoitteen
  tarkistus](/docs/payments/send-payments/verify-address), jossa on täydellinen päätöspuu
  ja viitekoodi, joka erottaa toisistaan lompakot, token account -tilit, mintit ja
  ohjelmat.
</Callout>
