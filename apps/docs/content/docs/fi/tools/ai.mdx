# LLM:ien ja agenttien käyttö Solanassa

Ennen kuin syvennymme tiettyihin työkaluihin, ymmärretään tekoälykehityspinon
tärkeimmät komponentit:

## Tekoälypinon ymmärtäminen

1. **Suuret kielimallit (LLM:t)**
   - Perustavanlaatuiset tekoälymallit (kuten GPT-4, Claude tai Llama)
   - Käsittelevät ja tuottavat luonnollista kieltä
   - Tarjoavat raakaa älykkyyttä ja päättelykykyä
   - Esimerkkejä: OpenAI:n GPT-4, Anthropicin Claude, Metan Llama

2. **Agenttikehykset (kuten Eliza)**
   - Rakennettu LLM:ien päälle autonomisten agenttien luomiseksi
   - Hallitsevat agenttien persoonallisuuksia ja käyttäytymistä
   - Käsittelevät muistia ja kontekstia
   - Tarjoavat monialustaisen integraation
   - Esimerkkejä: Eliza, LangChain, AutoGPT, Vercel AI

3. **Toimialakohtaiset agenttipakkaukset (kuten Solana Agent Kit)**
   - Rakennettu tiettyihin käyttötapauksiin (esim. lohkoketjutoiminnot)
   - Tarjoavat valmiiksi rakennettuja työkaluja ja integraatioita
   - Piilottavat teknisen monimutkaisuuden
   - Käyttövalmiit lohkoketjutoiminnot
   - Esimerkkejä: Solana Agent Kit, GOAT Toolkit

Ajattele asiaa näin:

- LLM:t ovat "aivot", jotka voivat ymmärtää ja tuottaa kieltä
- Agenttikehykset ovat "käyttöjärjestelmä", joka hallitsee tekoälyn käyttäytymistä
- Toimialakohtaiset pakkaukset ovat "sovellukset", jotka antavat tekoälylle erityisiä kykyjä

# Tekoälyagenttien rakentaminen Solanalle

Tässä oppaassa opit:

- Rakentamaan perustason tekoälyagentin käyttäen SendAI:n Solana Agent Kittiä
- Luomaan Twitter-botin Eliza-kehyksellä
- Ymmärtämään ketjussa tapahtuvan tekoälyintegraation vaihtoehtoja
- Vaihtoehtoja edistyneiden kaupankäyntibottien rakentamiseen

## Johdanto tekoälyagentteihin Solanassa

Solanan tekoälyagentit ovat autonomisia ohjelmia, jotka voivat olla vuorovaikutuksessa
lohkoketjun kanssa käyttäen luonnollisen kielen käsittelyä ja koneoppimista. Ne voivat:

- Suorittaa transaktioita
- Seurata lohkoketjun toimintaa
- Olla vuorovaikutuksessa älysopimusten kanssa
- Tarjota käyttäjätukea
- Automatisoida monimutkaisia työnkulkuja

## Saatavilla olevat kehykset

Solanan tekoälyagenttien rakentamiseen on saatavilla useita kehyksiä:

1. **SendAI:n Solana Agent Kit**

- Kokoelma työkaluja Solana-agenttien rakentamiseen
- Yhteensopiva Elizan, Langchainin ja Vercel AI SDK:n kanssa
- Sisäänrakennetut Solana-työkalut ja -apuohjelmat
- Luonnollisen kielen käsittelykyvyt
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Dokumentaatio](https://docs.solanaagentkit.xyz/)

2. **Eliza-kehys**

- Yhdistää tietokerroksen, LLM:n ja agentit ja sisältää erillisen Solana-laajennuksen
- Laajennettava agenttiarkkitehtuuri
- Helppo integrointi olemassa oleviin projekteihin ja soveltuu esimerkiksi
  Twitter (X)-, Telegram- tai Discord-botteihin
- [GitHub-repositorio](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Kattava kehitystyökalupakkaus
- Ketjujen välinen yhteensopivuus
- [GitHub-repositorio](https://github.com/goat-sdk/goat)

4. **Rig-kehys**

- Natiivi Rust-toteutus
- Soveltuu hyvin suorituskykyisiin kaupankäyntibotteihin
- Voidaan yhdistää Listen.rs-työkalupakkauksen kanssa Solana-integraatiota, transaktioiden
  seurantaa ja transaktioiden lähettämistä varten käyttäen esimerkiksi Jito-nippuja
- [GitHub-repositorio](https://github.com/0xPlaygrounds/rig)
- [Listen.rs-repositorio](https://github.com/piotrostr/listen)

Jos rakennat tekoälykehystä, lähetä vapaasti PR lisätäksesi kehyksesi listalle

### Luo agenttiskriti

Luo uusi tiedosto nimeltä `agent.ts` seuraavalla sisällöllä:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## Rakentaminen Eliza-kehyksellä

[ElizaOS](https://github.com/elizaOS/eliza) (aiemmin tunnettu nimellä Ai16z) on
tekoälykehys. Se tarkoittaa, että se yhdistää useita sovelluksia yhdeksi ja
järjestää niiden vuorovaikutukset. Se yhdistää:

1. Eri LLM:t käyttäjän ymmärtämiseen
2. Lohkoketjuagentit eri toiminnoilla (kuten NFT:n luominen esimerkiksi)
3. Tietokerrokset hahmon tilan tallentamiseen toimintojen välillä käyttäen esimerkiksi
   Redisiä, PostgreSQL-tietokantaa tai paikallista tallennustilaa
4. Eri asiakassovellukset kuten X, Telegram, Discord jne.

Se kokoaa kaikki nämä asiat yhteen tavalla, jolla voit luoda
"Hahmon", joka voi olla vuorovaikutuksessa käyttäjien kanssa tai toimia autonomisesti. Nämä hahmot
määritellään JSON-tiedostossa, joka määrittää mitä toimintoja se voi suorittaa, mitä LLM:ää se
käyttää ja eri kehotteita, jotka määrittävät hahmon käyttäytymisen.

### Luo hahmon konfiguraatio

Uuden hahmon luomiseksi meidän täytyy luoda character.json-tiedosto. Löydät
valmiit hahmot Eliza-projektin characters-kansiosta. Uuden hahmon luomiseksi
voit kopioida ja muokata jotakin olemassa olevista hahmoista tai

[Cursorin composer-ominaisuutta](https://docs.cursor.com/composer/overview) ja kertoa

```json filename=characters/sol.character.json

    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },

```

Tärkeimmät osat ovat clients ja modelProvider. Meidän tapauksessamme
haluamme käyttää twitteriä asiakkaana ja openaita mallin tarjoajana, koska
nämä ovat ne, joille asetimme salaisuudet `.env`-tiedostossa.

Nyt kun konfiguraatio on valmis, voimme käynnistää hahmomme:

```bash

```

Hahmo alkaa automaattisesti julkaista twiittejä muutaman tunnin välein, ja kun
olemme vuorovaikutuksessa sen kanssa, se pystyy suorittamaan Solana-toimintoja,
kuten NFT:iden luomista esimerkiksi.

Täältä näet
[hahmon toiminnassa](https://x.com/solanadevhelper/status/1882222232656847143).

Voit myös olla vuorovaikutuksessa hahmon kanssa paikallisesti seuraavalla komennolla:
Sinun saattaa täytyä vapauttaa portti 3000 ja käynnistää hahmosi `--host`-lipulla.

```bash
pnpm start --character="characters/sol.character.json" --host
pnpm start:client
```

Jos asiakassovelluksesi ei muodosta yhteyttä, varmista että käynnistät agentin `--host`-lipulla
ja että portti 3000 ei ole käytössä, kun käynnistät asiakassovelluksen.

Lisätietoja saat seuraamalla
[virallista Eliza-dokumentaatiota](https://elizaos.github.io/eliza/docs/quickstart/)

## Ketjussa olevan ohjelman agentti-integraatio

Jos haluat käyttää agentin vastausta Solana-ohjelmassa, sinun täytyy käyttää
orakkelia, joka kirjoittaa vastauksen tiedot tilille, jota ohjelmasi voi lukea.
Täältä löydät esimerkin LLM:stä, joka siirtää tokeneita käyttäjille, jotka
vastaavat kysymyksiin oikein:

[Ketjussa olevan ohjelman LLM-vuorovaikutus](https://github.com/GabrielePicco/super-smart-contracts)

Tämä on esimerkki ketjussa olevasta ohjelmasta, joka integroituu LLM (AI) -orakkeliin
luodakseen interaktiivisen tokeneja jakavan agentin nimeltä "Mar1o".

### Tärkeimmät ominaisuudet

1. **Tekoälyagentin vuorovaikutus**
   - Käyttäjät voivat jutella Mar1on kanssa yrittäen ansaita tokeneita
   - Agentti arvioi käyttäjän Solana-osaamista päättääkseen tokenimäärät
   - Vastaukset ovat JSON-muodossa sisältäen vastauksen tekstin ja tokenimäärän

2. **Tokenien hallinta**
   - Luo MAR1O-tokeneita metatiedoilla
   - Voi luoda 0–10 000 tokenia tekoälyn vastauksen perusteella
   - Käyttää PDA:ita tokenien hallintaan

### Ohjelman kulku selitettynä

Näin tämä ohjelma toimii:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Tämä havainnollistaa, kuinka tekoälyn ominaisuuksia voidaan yhdistää ketjussa oleviin
tokenimekaniikkoihin interaktiivisten lohkoketjukokemusten luomiseksi. Tässä on
[live-esimerkki](https://mar1o.xyz/), jossa voit yrittää vakuuttaa agentin
siirtämään sinulle joitain tokeneita.

## Edistyneet Rust-agentit algoritmiseen kaupankäyntiin

Jos haluat kirjoittaa agenttiasi Rustilla, voit käyttää
[Rig-kehystä](https://github.com/0xPlaygrounds/rig) ja
[Listen.rs](https://github.com/piotrostr/listen)-kirjastoa.

Nämä kaksi toimivat hyvin yhdessä. Rig-kehys tarjoaa helpon tavan
yhdistää LLM:iin, kun taas Listen.rs-työkalupakki tarjoaa Solana-integraation,
joka sisältää transaktioiden seurannan ja transaktioiden lähettämisen esimerkiksi
Jito-nippujen avulla.

## Parhaat käytännöt

- Muista, että agentillasi on yksityinen avain ja se voi siten käyttää
  lompakkosi varoja. Jos joku voi jutella agenttiasi ja sillä on esimerkiksi
  siirtotoiminto, käyttäjät voivat todennäköisesti saada sen siirtämään varojasi heille.
- Käytä maksullisia [RPC-päätepisteitä](https://solana.com/rpc). Julkiset päätepisteet
  rajoitetaan yleensä nopeuden osalta
- Seuraa agentin toimintoja ja varmista, etteivät ne tee mitään haitallista
  tai että käyttäjät eivät huijaa niitä tekemään niin
- Toteuta prioriteettimaksut ja transaktioiden uudelleenyritykset agenttitoimintoihin,
  jotta ne onnistuvat myös verkon ruuhkautuessa
- Testaa mahdollisuuksien mukaan ensin devnetissä ennen mainnetiin siirtymistä. Useimmat
  agentit ottavat RPC-osoitteen syötteenä ja voit käyttää devnetin osoitetta, kunnes
  olet valmis mainnetiin. Kaikkia toimintoja ei välttämättä voi tehdä devnetissä.
- Kun kirjoitat omia toimintojasi, lisää niihin integraatiotestit, jotta
  kehykset voivat seurata, mitkä toiminnot epäonnistuvat muuttuneiden ohjelmien tai
  rajapintojen takia

## Yhteenveto

Tekoälyagentit Solanassa avaavat uusia mahdollisuuksia automaatiolle ja
lohkoketjuvuorovaikutukselle. Vaikka kaikki integraatiot eivät ole vielä täydellisiä,
niitä kehitetään nopeasti ja ne tarjoavat runsaasti mahdollisuuksia osallistumiselle
ja ovat erittäin joustavia omien integraatioiden lisäämiseen.
