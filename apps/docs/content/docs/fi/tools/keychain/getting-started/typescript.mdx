## Asennus

Asenna kattopaketti tai yksittäiset allekirjoittajat tarpeen mukaan:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Vaatii `@solana/kit`-kirjaston version 8.1 tai uudemman. v1-transaktioita
(`createTransactionMessage({ version: 1 })`) tuetaan, paitsi Fireblocksin kanssa
asetuksella `useProgramCall: true`, joka hyväksyy vain legacy- ja v0-transaktiot.

## Peruskäyttö

### Yhtenäinen Factory (Suositeltu sovelluksille, jotka haluavat tukea useita allekirjoittajia)

Käytä `createKeychainSigner` -metodia erottelevalla konfiguraatiolla luodaksesi
minkä tahansa backendin:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Tai asenna yksittäinen allekirjoittajapaketti pienemmän riippuvuusjalanjäljen
saamiseksi:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Käyttö transaktiviestien kanssa

Jokainen taustajärjestelmä paitsi Crossmint ja Fordefin natiivitila palauttaa
`SolanaTransactionSigner`-allekirjoittajan, joka on Kitin `TransactionPartialSigner` ja toimii
alla olevien `@solana/signers`-kirjaston osittaisten allekirjoittajien apufunktioiden kanssa. Hallitun lähetyksen
taustajärjestelmät on käsitelty osiossa [Allekirjoittajan ominaisuudet](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Allekirjoita ja lähetä millä tahansa allekirjoittajalla

`signAndSendTransaction` kirjastosta `@solana/keychain-core` vie transaktion
ketjuun allekirjoittajan tyypistä riippumatta. Lähettävät allekirjoittajat lähettävät transaktion
omalla palveluntarjoajallaan; kaikki muut tyypit käyttävät antamaasi `sendTransaction`-funktiota (core ei
riipu RPC:stä):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Käyttö Kit-asiakkaan kanssa (keychainSigner-laajennus)

`@solana/keychain-kit-plugin` asentaa avainnimiketun allekirjoittajan suoraan
[Kit-asiakkaaseen](https://github.com/anza-xyz/kit) ja kytkee sen `payer`- ja
`identity`-rooleiksi, joten voit ohittaa yllä näytetyn manuaalisen
`pipe`-määrityksen:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Laajennus hyväksyy saman taustajärjestelmällä merkityn konfiguraation kuin `createKeychainSigner`,
paitsi Crossmintin ja Fordefin natiivitilan (`chain` asetettu). Nämä taustajärjestelmät kirjoittavat
transaktion uudelleen palvelinpuolella, joten ne eivät voi toimia asiakkaan `payer`- tai
`identity`-roolissa; laajennus hylkää ne sekä käännösvaiheessa että ajon aikana. Vain
se taustajärjestelmä, jolle kutsu ohjataan, sisällytetään pakettiin (taustajärjestelmäpaketit ladataan dynaamisella
`import()`-kutsulla).

Käytä `keychainPayer`- tai `keychainIdentity`-toimintoa asettaaksesi vain yhden
roolin ja yhdistääksesi useita taustapalveluita yhdellä asiakkaalla:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Onko sinulla jo `SolanaTransactionSigner`? Se on kelvollinen Kitin
`TransactionPartialSigner`, joten voit asentaa sen sen sijaan
laajennuksella [`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
(`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Peruutus ja vahvistamattomat lähetykset

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` ja
`signMessages` hyväksyvät kaikki toisena argumenttinaan `{ abortSignal }`. Keskeyttäminen
lopettaa odottamisen, mutta se ei kumoa työtä, jonka palveluntarjoaja on jo hyväksynyt.

Crossmintin ja Fordefin natiivin auto-tilan kohdalla virhe ei tarkoita, ettei mitään
olisi tapahtunut. Kun palveluntarjoaja on voinut hyväksyä transaktion, virhekoodi on
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` asetetaan, kun luonti hyväksyttiin, ja
`context.idempotencyKey` sisältää viestistä johdetun avaimen. Täsmälleen samana
tavujonona olevan transaktion uudelleenlähetys on turvallista; uudelleen rakennettu transaktio (esimerkiksi uudella
blockhashilla) on uusi siirto. Kirjaston `@solana/keychain-core` funktiot `providerMayHaveAccepted(error)` ja
`providerStatus(error)` auttavat luokittelemaan virheen.
Tarkista tilanne palveluntarjoajalta ennen uudelleenyritystä.

  privateKeyPath: "/path/to/id.json"
});

### Crossmint

```typescript

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmint on vain lähettävä. Sen API suorittaa hyväksytyn transaktion aina
palvelinpuolella ja sponsoroi gas-maksun, joten allekirjoittaja tarjoaa vain
`signAndSendTransactions()`-metodin: siinä ei ole `signTransactions()`- tai `signMessages()`-metodia,
eikä sitä voi asentaa `@solana/keychain-kit-plugin`-laajennuksella. Palautettu
allekirjoitus tunnistaa transaktion, jonka Crossmint vei ketjuun.

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

Fordefilla on kolme allekirjoitustilaa, jotka määräytyvät luontihetkellä `chain`- ja
`pushMode`-asetusten mukaan. Jokainen tila tarjoaa täsmälleen yhden transaktiometodin, ja kaikki kolme allekirjoittavat
viestejä:

| Tila          | Konfiguraatio                                      | Tyyppi                        | Metodi                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Musta laatikko     | `chain` asettamatta                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Natiivi auto   | `chain` asetettu, `pushMode` puuttuu tai on `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Natiivi manuaalinen | `chain` asetettu, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

API-pyynnöt todennetaan ECDSA P-256 -pyyntöallekirjoituksella: anna
allekirjoitusavain arvona `privateKeyPem` tai säilytä se KMS:ssä/HSM:ssä antamalla
`requestSigner`.

**Natiivi auto-tila** (suositeltu ketjussa käytettäväksi): aseta `chain`, jolloin Fordefi
allekirjoittaa ja lähettää transaktion itse. Koska Fordefi voi vaihtaa
blockhashin tai maksut ennen allekirjoitusta, allekirjoittaja on Kitin
`TransactionSendingSigner`: käytä sitä funktiolla
`signAndSendTransactionMessageWithSigners`, älä yllä esitetyllä osittaisen allekirjoittajan kululla. Natiivi auto-tila hyväksyy vain allekirjoittamattoman transaktion, jonka ainoa vaadittu
allekirjoittaja on vault, eikä sitä voi käyttää `@solana/keychain-kit-plugin`-laajennuksen kanssa.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Natiivi manuaalinen tila**: aseta `chain` ja `pushMode: "manual"`. Fordefi kirjoittaa
viestin uudelleen (tuore blockhash, Compute Budget -maksuohjeet) ja allekirjoittaa sen,
mutta ei lähetä sitä. `modifyAndSignTransactions()` palauttaa transaktion,
jonka Fordefi allekirjoitti ja joka korvaa lähettämäsi: jatka aina
palautetusta transaktiosta. Fordefin on oltava maksujen maksaja, ja sen on allekirjoitettava ennen muita
vaadittuja allekirjoittajia. Uudelleenkirjoituksesta ei muodosteta diffiä, joten tarkista tulos ennen
lähettämistä.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Musta laatikko -tila**: jätä `chain` pois. Fordefi allekirjoittaa raakatavut eikä lähetä transaktiota; kokoa ja lähetä transaktio itse. Käytä tätä Fordefin musta laatikko -holvin kanssa.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Allekirjoittajan ominaisuudet

`@solana/keychain-core` määrittelee yhden rajapinnan jokaista Kitin allekirjoittajatyyppiä varten. Jokainen lisää
`isAvailable(): Promise<boolean>` vastaavaan `@solana/signers`-rajapintaan:

- `SolanaTransactionSigner` (Kitin `TransactionPartialSigner`): palauttaa allekirjoitukset
  omistamallesi transaktiolle.
- `SolanaModifyingSigner` (Kitin `TransactionModifyingSigner`): kirjoittaa
  transaktion uudelleen, allekirjoittaa sen ja palauttaa uuden transaktion lähettämättä sitä.
- `SolanaSendingSigner` (Kitin `TransactionSendingSigner`): allekirjoittaa ja lähettää
  palveluntarjoajansa kautta.
- `SolanaMessageSigner` (Kitin `MessagePartialSigner`): allekirjoittaa ketjun ulkopuolisia viestejä.
  Tämä on erillinen transaktiotyypeistä.

`SolanaSigner` on kolmen transaktiotyypin yhdiste. Jokaisen tehtaan
paluutyyppi nimeää taustajärjestelmänsä tarkan tyypin. Kun konfiguraatio tiedetään vasta
ajon aikana, rajaa tyyppiä funktioilla `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` tai `isSolanaMessageSigner`. `signerCapabilities(signer)`
palauttaa kaikki neljä kerralla.

| Taustajärjestelmä                                                                                                     | Tyyppi                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (musta laatikko) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (ei viestien allekirjoitusta)  |
| fordefi (natiivi manuaalinen)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (natiivi auto)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (ei viestien allekirjoitusta)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Mukautettujen allekirjoittajien rakentaminen

Toteuta ne ominaisuusrajapinnat, joita taustajärjestelmäsi tukee:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Toteuta vain se, mitä taustajärjestelmäsi tukee. Kit luokittelee allekirjoittajat sen mukaan, mitkä
metodit niillä on, joten älä koskaan lisää metodia, joka vain heittää virheen.

Katso [Allekirjoittajien lisääminen -opas](/docs/tools/keychain/adding-signers)
lisätäksesi uusia avainten hallintapalveluita.
