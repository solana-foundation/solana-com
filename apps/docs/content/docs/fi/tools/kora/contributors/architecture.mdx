Kora on Rust-työtila (workspace), jossa on kolme crate-pakettia:

- `kora-lib` sisältää ydinlogiikan ja RPC-palvelimen,
- `kora-cli` rakentaa `kora`-binäärin, jota operaattorit ajavat, ja
- `kora-deploy` on erikoistunut ohjelmien käyttöönottotyökalu, jolla on oma versiointinsa.
  Kaikki alla oleva sijaitsee hakemistossa `crates/lib/src`, ellei toisin mainita.

## Pyynnön elinkaari

Alla oleva kaavio kuvaa transaktion yleisen kulun Koran läpi.
Kutsupolun ymmärtäminen on tärkeää Kora-solmun konfiguroinnissa ja
uusien ominaisuuksien lisäämisessä.

## Missä kukin vaihe sijaitsee

| Kaavion vaihe | Lähde                               | Aloituskohta                           |
| -------------------- | ------------------------------------ | ------------------------------------- |
| Yhdyskäytävä              | `rpc_server/server.rs`               | `run_rpc_server`                      |
| Reititys             | `rpc_server/rpc.rs`                  | `KoraRpc`                             |
| Metodikohtainen logiikka     | `rpc_server/method/`                 | yksi tiedosto kutakin JSON-RPC-metodia kohti          |
| Validointi           | `validator/transaction_validator.rs` | `TransactionValidator`                |
| Laajennukset              | `plugin/mod.rs`                      | `TransactionPluginRunner`             |
| Allekirjoitus              | `signer/`                            | `solana-keychain`-crate-paketin tukema |

Kaksi muuta tiedostoa kannattaa tuntea: `config.rs` määrittelee koko `kora.toml`-skeeman, ja
`state.rs` sisältää deserialisoidun konfiguraation prosessin globaalissa tilassa.

### RPC-palvelimen läpikäynti

`rpc.rs` on ohut reitityskerros, jossa on yksi metodi kutakin JSON-RPC-päätepistettä kohti, ja
nopein tapa nähdä koko API. Kunkin metodin logiikka on omassa tiedostossaan hakemistossa
`rpc_server/method/`. Lue `sign_transaction.rs` alusta loppuun; muut allekirjoitusmetodit
ovat sen muunnelmia.

### Validointilogiikan läpikäynti

`transaction_validator.rs` ja `transaction/instruction_util.rs` sisältävät logiikan
transaktioiden ja instruktioiden validointiin. Lisäksi mukana ovat fee-payer-policy-
turvallisuusominaisuuksien testit, jotka sijaitsevat yhdessä tiedostossa kutakin rajattua ohjelmaa kohti hakemistossa
`validator/transaction_validator/fee_payer_policy_props/`.

## Hyödyllisiä käytäntöjä

**Oletusvalidointi.** Jokaisen `[validation.fee_payer_policy]`-osion lipun
oletusarvo on `false`, ja policy-structeissa on `#[serde(default)]`. Tämä
yhdistelmä on tarkoituksellinen: uuden rajatun instruktion lisääminen ei saa rikkoa
olemassa olevan operaattorin konfiguraatiota, ja sen on päädyttävä kieltona eikä
vahingossa sallittuna. Säilytä molemmat, kun lisäät lipun.

**Validoi ratkaistu transaktio, älä koskaan raakaa.** Raaka
`VersionedTransaction` paljastaa vain staattiset tiliavaimet, joten V0-transaktion
validointi tai hinnoittelu sen pohjalta ohittaa hiljaa lookup-table-tilit ja
perii liian vähän. `VersionedTransactionResolved::from_transaction` ratkaisee nämä
osoitteet etukäteen, minkä vuoksi jokainen myöhempi vaihe ottaa vastaan ratkaistun tyypin.

## Transaktiolaajennuksen lisääminen

Laajennukset toteuttavat `TransactionPlugin`-traitin tiedostossa `plugin/mod.rs`. Siinä on kaksi
metodia: `validate` suoritetaan transaktiokohtaisesti allekirjoitusvirroissa, ja
`validate_config` suoritetaan kerran käynnistyksen yhteydessä ja palauttaa virheet ja varoitukset
operaattorille. `PluginExecutionContext` kertoo laajennukselle, mikä neljästä allekirjoitusmetodista
sen kutsui.

`TransactionPluginRunner::from_config` tekee vastaavuusvertailun `TransactionPluginType`-tyypillä,
joka on määritelty tiedostossa `config.rs`. Uusi sisäänrakennettu laajennus tarkoittaa uutta varianttia siellä sekä uutta
match-haaraa runnerissa. Kaksi tällä hetkellä mukana toimitettavaa laajennusta ovat `gas_swap` ja
`deploy_authority`.

## Testaus

Kora säilyttää konfiguraation prosessin globaalissa tilassa, joten `tests/` määrittelee yhden
`[[test]]`-kohteen kutakin vaihetta kohti, ja jokainen kohde käynnistää oman upotetun surfnetinsä sekä
Kora-solmunsa, jotka alustetaan tyhjästä. Yksi konfiguraatio binääriä kohti: uusi vaihe vaatii uuden
kohteen, ei uutta moduulia olemassa olevaan.

```bash
cargo test -p tests --test <target>
```

Kaikki muu on kytketty `justfile`-tiedoston kautta. Lue se sen sijaan, että
rakentaisit komennot käsin.
