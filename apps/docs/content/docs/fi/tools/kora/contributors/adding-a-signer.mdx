## Arkkitehtuurin Yleiskatsaus

Kora käyttää ulkoista
[`solana-keychain`](https://github.com/solana-foundation/solana-keychain)
crate-pakettia kaikkiin allekirjoitusoperaatioihin. Tämä arkkitehtuuri tarjoaa
yhtenäisen allekirjoitusrajapinnan Solana-tapahtumien allekirjoittamiseen. Uuden
allekirjoittajan lisäämiseksi Koraan sinun täytyy:

1. **Ensin**: Lisää allekirjoittajatoteutuksesi `solana-keychain`
   crate-pakettiin
2. **Toiseksi**: Lisää määritystuki allekirjoittajallesi Korassa

### Lisää allekirjoittajatuki Koraan

Varmista ensin, että allekirjoittajasi on tuettu `solana-keychain`-crate:ssa.
Jos sitä ei tueta, noudata ohjetta osoitteessa:
**[https://github.com/solana-foundation/solana-keychain/blob/main/docs/ADDING_SIGNERS.md](https://github.com/solana-foundation/solana-keychain/blob/main/docs/ADDING_SIGNERS.md)**

#### Vaihe 1: Päivitä Cargo.toml

Päivitä Cargo.toml:n riippuvuus siten, että `solana-keychain`-crate käyttää
uusinta versiota (joka sisältää allekirjoittajasi):

```toml
[dependencies]
solana-keychain = { version = "X.Y.Z", default-features = false, features = [
    "all",
    "sdk-v3",
] }
```

#### Vaihe 2: Määrittele konfiguraatiorakenne

Lisää `crates/lib/src/signer/config.rs`-tiedostoon uusi konfiguraatiorakenne
allekirjoittajallesi, joka määrittelee tarvittavat ympäristömuuttujat.
Esimerkiksi:

```rust
/// YourService signer configuration
#[derive(Clone, Serialize, Deserialize)]
pub struct YourServiceSignerConfig {
    pub api_key_env: String,
    pub api_secret_env: String,
    pub wallet_id_env: String,
}
```

#### Vaihe 2: Lisää allekirjoittajasi `SignerTypeConfig`-enumiin

Lisää allekirjoittajavarianttisi `SignerTypeConfig`-enumiin
`crates/lib/src/signer/config.rs`-tiedostossa:

```rust
/// Signer type-specific configuration
#[derive(Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum SignerTypeConfig {
    // Existing signer variants
    Memory { #[serde(flatten)] config: MemorySignerConfig },
    // ... existing variants ...

    // Add your signer here
    YourService {
        #[serde(flatten)]
        config: YourServiceSignerConfig,
    },
}
```

#### Vaihe 3: Lisää rakennuslogiikka

Lisää samaan tiedostoon (`config.rs`) metodi, joka rakentaa allekirjoittajasi
konfiguraatiosta `SignerConfig`-toteutuksessa:

```rust
impl SignerConfig {
    pub async fn build_signer_from_config(config: &SignerConfig) -> Result<Signer, KoraError> {
        match &config.config {
            // ... existing cases

            SignerTypeConfig::YourService { config: your_service_config } => {
                Self::build_your_service_signer(your_service_config, &config.name).await
            }
        }
    }

    // Add this new method
    async fn build_your_service_signer(
        config: &YourServiceSignerConfig,
        signer_name: &str,
    ) -> Result<Signer, KoraError> {
        // Update the environment variable names to match your signer's configuration
        let api_key = get_env_var_for_signer(&config.api_key_env, signer_name)?;
        let api_secret = get_env_var_for_signer(&config.api_secret_env, signer_name)?;
        let wallet_id = get_env_var_for_signer(&config.wallet_id_env, signer_name)?;

        // Call the constructor from solana-keychain crate
        Signer::from_your_service(api_key, api_secret, wallet_id)
            .await
            .map_err(|e| {
                KoraError::SigningError(format!(
                    "Failed to create YourService signer '{signer_name}': {}",
                    sanitize_error!(e)
                ))
            })
    }
}
```

**Huomautus**: Metodin nimen `Signer::from_your_service()` tulisi vastata sitä,
minkä toteutit `solana-keychain`-cratessa.

#### Vaihe 4: Lisää validointilogiikka

Lisää validointi allekirjoittajasi konfiguraatiolle
`validate_individual_signer_config`-metodissa:

```rust
impl SignerConfig {
    pub fn validate_individual_signer_config(&self, index: usize) -> Result<(), KoraError> {
        // ... existing validation

        match &self.config {
            // ... existing cases

            SignerTypeConfig::YourService { config } => {
                Self::validate_your_service_config(config, &self.name)
            }
        }
    }

    // Add this new validation method
    fn validate_your_service_config(
        config: &YourServiceSignerConfig,
        signer_name: &str,
    ) -> Result<(), KoraError> {
        // Update the environment variable names to match your signer's configuration
        let env_vars = [
            ("api_key_env", &config.api_key_env),
            ("api_secret_env", &config.api_secret_env),
            ("wallet_id_env", &config.wallet_id_env),
        ];

        for (field_name, env_var) in env_vars {
            if env_var.is_empty() {
                return Err(KoraError::ValidationError(format!(
                    "YourService signer '{signer_name}' must specify non-empty {field_name}"
                )));
            }
        }
        Ok(())
    }
}
```

## Integraation testaaminen

### Lisää testimock-rakentaja

Testauksen helpottamiseksi lisää rakentajametodi
`SignerPoolConfigBuilder`-rakenteeseen
`crates/lib/src/tests/config_mock.rs`-tiedostossa:

```rust
impl SignerPoolConfigBuilder {
    // ... existing methods

    pub fn with_your_service_signer(
        mut self,
        name: String,
        api_key_env: String,
        api_secret_env: String,
        wallet_id_env: String,
        weight: Option<u32>,
    ) -> Self {
        let signer = SignerConfig {
            name,
            weight,
            config: SignerTypeConfig::YourService {
                config: YourServiceSignerConfig {
                    api_key_env,
                    api_secret_env,
                    wallet_id_env,
                },
            },
        };
        self.config.signers.push(signer);
        self
    }
}
```

Tämä mahdollistaa muiden testien luoda helposti mock-konfiguraatioita, jotka
sisältävät allekirjoittajasi:

```rust
use crate::tests::config_mock::SignerPoolConfigBuilder;

let config = SignerPoolConfigBuilder::new()
    .with_your_service_signer(
        "yourservice_test".to_string(),
        "YOUR_SERVICE_API_KEY".to_string(),
        "YOUR_SERVICE_API_SECRET".to_string(),
        "YOUR_SERVICE_WALLET_ID".to_string(),
        Some(1)
    )
    .build();
```

### Integraatiotestit

Jokainen integraatiovaihe on oma `[[test]]`-kohteensa tiedostossa `tests/Cargo.toml`. Jokainen
kohde käynnistää upotetun surfnetin ja Kora-solmun `harness_context`:in kautta,
alustettuna tyhjästä. Kora säilyttää konfiguraation prosessikohtaisessa globaalissa tilassa, joten uusi
allekirjoittaja tarvitsee uuden kohteen eikä uutta moduulia olemassa olevaan kohteeseen.

#### 1. Lisää allekirjoittajan testiaineisto

Luo allekirjoittajan konfiguraatio hakemistoon `tests/src/common/fixtures/`:

```toml
# tests/src/common/fixtures/signers-your-service.toml
[signer_pool]
strategy = "round_robin"

[[signers]]
name = "yourservice_main"
type = "your_service"
api_key_env = "YOUR_SERVICE_API_KEY"
api_secret_env = "YOUR_SERVICE_API_SECRET"
wallet_id_env = "YOUR_SERVICE_WALLET_ID"
```

#### 2. Lisää testikohde

Rekisteröi vaihe tiedostossa `tests/Cargo.toml`:

```toml
[[test]]
name = "your_service"
path = "your_service/main.rs"
```

Luo sitten `tests/your_service/main.rs`. Se osoittaa testikehyksen aineistoosi
ja sen on sisällettävä vähintään yksi `#[tokio::test]`, joka testaa allekirjoittajaa:

```rust
#[path = "../src/common/mod.rs"]
mod common;

use common::*;
use jsonrpsee::rpc_params;

pub async fn ctx() -> TestContext {
    harness_context(KoraSpec {
        config: "tests/src/common/fixtures/kora-test.toml",
        signers: "tests/src/common/fixtures/signers-your-service.toml",
        initialize_payments_atas: false,
    })
    .await
}

#[tokio::test]
async fn test_your_service_signs_as_fee_payer() {
    let ctx = ctx().await;

    let response: serde_json::Value = ctx
        .rpc_call("getPayerSigner", rpc_params![])
        .await
        .expect("Failed to get payer signer");

    response.assert_success();
    assert!(response["signer_address"].as_str().is_some());
}
```

Lisää myös `signTransaction`-testi, jotta allekirjoittajan allekirjoituspolku tulee ajettua eikä pelkästään
avaimen haku. `tests/multi_signer/` on täydellinen esimerkki, jota voit käyttää mallina.

#### 3. Testien suorittaminen

```bash
just install

export YOUR_SERVICE_API_KEY="your_key"
export YOUR_SERVICE_API_SECRET="your_secret"
export YOUR_SERVICE_WALLET_ID="your_wallet"

# Run only your phase
cargo test -p tests --test your_service

# Run every integration phase
just integration-test
```
