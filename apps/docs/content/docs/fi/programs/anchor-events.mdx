Anchor-tapahtumat ovat tyypitettyjä, Borsh-serialisoituja tietueita, jotka sisältyvät ohjelman IDL-kuvaukseen.
Niiden avulla asiakasohjelmat voivat tulkita ohjelman toimintaa jäsentämättä ihmisen
luettavia lokiviestejä.

Tapahtumat sopivat indeksointiin ja ilmoituksiin, mutta ne eivät ole ohjelman
tila. Tallenna tileille kaikki arvot, jotka ohjelman täytyy lukea uudelleen, ja käsittele
tapahtumia onnistuneesta transaktiosta johdettuna tietueena.

## Tapahtuman määrittely ja lähettäminen

Lisää `#[event]` structiin ja kutsu `emit!` sen jälkeen, kun tilamuutos on onnistunut.

```rust title="lib.rs"
use anchor_lang::prelude::*;

#[program]
pub mod payments {
    use super::*;

    pub fn record_payment(ctx: Context<RecordPayment>, amount: u64) -> Result<()> {
        emit!(PaymentRecorded {
            authority: ctx.accounts.authority.key(),
            amount,
        });
        Ok(())
    }
}

#[derive(Accounts)]
pub struct RecordPayment<'info> {
    pub authority: Signer<'info>,
}

#[event]
pub struct PaymentRecorded {
    pub authority: Pubkey,
    pub amount: u64,
}
```

`emit!` kirjoittaa tapahtuman tavut Solanan `sol_log_data`-syscallilla. Transaktiolokit
näyttävät tuloksen muodossa `Program data: <base64>`. Koodattu arvo alkaa
tapahtuman discriminatorilla, jota seuraavat sen Borsh-serialisoidut kentät.

Pidä tapahtumat tiiviinä. Suuret merkkijonot ja vektorit kuluttavat laskentaa, kasvattavat
transaktion metatietoja ja joutuvat todennäköisemmin lokien katkaisun kohteeksi.

## Lokitapahtumien ja CPI-tapahtumien välillä valitseminen

Anchor tukee kahta lähetystapaa:

| Tapa        | Tallennuspaikka                  | Kompromissi                                               |
| ----------- | --------------------------------- | ------------------------------------------------------ |
| `emit!`     | Program data -lokit                 | Yksinkertaisempi ja edullisempi, mutta lokit voivat katketa         |
| `emit_cpi!` | CPI-kutsun sisäinen instruction data | Kestävämmät metatiedot, mutta vaatii lisätilejä ja laskentaa |

Jos haluat käyttää CPI-tapahtumia, ota käyttöön Anchorin `event-cpi`-ominaisuus:

```toml title="Cargo.toml"
[dependencies]
anchor-lang = { version = "1.1.2", features = ["event-cpi"] }
```

Merkitse sitten instruktion tilien struct attribuutilla `#[event_cpi]` ja lähetä tapahtuma
käsittelijästä, jonka kontekstimuuttujan nimi on `ctx`:

```rust title="lib.rs"
pub fn record_payment(ctx: Context<RecordPayment>, amount: u64) -> Result<()> {
    emit_cpi!(PaymentRecorded {
        authority: ctx.accounts.authority.key(),
        amount,
    });
    Ok(())
}

#[event_cpi]
#[derive(Accounts)]
pub struct RecordPayment<'info> {
    pub authority: Signer<'info>,
}
```

`#[event_cpi]` lisää tapahtuman authority-tilin ja nykyisen ohjelman tilit, joita
allekirjoitettu itse-CPI tarvitsee. CPI-tapahtumia ei voi vastaanottaa Anchorin lokitapahtumatilauksen
kautta. Hae sen sijaan transaktio ja dekoodaa siitä vastaava sisäinen
instruktio.

<Callout type="info" title="Käytä pääkirjaa lähteenä">
  RPC-palveluntarjoajat voivat katkaista ohjelmalokeja. Jos tapahtuman puuttuminen vaikuttaisi
  saldoihin, oikeuksiin tai muuhun oikeellisuuden kannalta kriittiseen työnkulkuun, johda
  tulos ohjelman tileistä tai transaktion instruction data -tiedoista. Käytä tapahtumia
  indeksoinnin tehostamiseen, älä ainoana tilan tietueena.
</Callout>

## Tilaus TypeScriptillä

Nykyinen Anchorin TypeScript-asiakas on `@anchor-lang/core`. Ohjelman IDL:stä luotu `Program`-
instanssi voi dekoodata vastaavat lokitapahtumat ja välittää
ne RPC-lokitilauksen kautta:

```ts
const listenerId = program.addEventListener(
  "PaymentRecorded",
  (event, slot, signature) => {
    console.log({ event, slot, signature });
  },
  "confirmed"
);

// Remove the websocket subscription when it is no longer needed.
await program.removeEventListener(listenerId);
```

Takaisinkutsu saa dekoodatut tapahtumatiedot, slot-arvon ja transaktion
allekirjoituksen. Tilaukset kattavat vain ne lokit, jotka toimitetaan yhteyden ollessa
aktiivinen. Tallenna käsitellyt allekirjoitukset ja täydennä puuttuvat transaktiot yhteyden
checkin katkeamisen jälkeen, jos kuluttaja tarvitsee täydellisen historian.

## Haettujen transaktiolokien dekoodaus

Täydennyshakuja ja kertaluonteista tarkastelua varten hae transaktio ja anna jokainen
`Program data:` -sisältö tapahtumakooderille:

```ts
const transaction = await connection.getTransaction(signature, {
  commitment: "confirmed",
  maxSupportedTransactionVersion: 0
});

if (!transaction?.meta || transaction.meta.err) {
  throw new Error("Transaction was not found or did not succeed");
}

for (const log of transaction.meta.logMessages ?? []) {
  const prefix = "Program data: ";
  if (!log.startsWith(prefix)) continue;

  const decoded = program.coder.events.decode(log.slice(prefix.length));
  if (decoded) console.log(decoded.name, decoded.data);
}
```

Transaktio voi kutsua useita ohjelmia. Tuotantokäyttöön tarkoitetussa jäsentimessä seuraa
lokien `Program <address> invoke`- ja `success`-rajoja tai käytä Anchorin tapahtumajäsennintä,
jotta toisen ohjelman `Program data:` -merkintää ei dekoodata omaksesi.
Epäonnistuneet transaktiot voivat säilyttää lokit ja sisäiset instruktiot virhettä
edeltäneestä työstä, joten hylkää aina transaktion metatiedot, joiden `err` ei ole null,
ennen kummankin tapahtumamuodon indeksointia. Anchorin lokitilaus tekee tämän tarkistuksen
ennen kuin se kutsuu tapahtuman takaisinkutsua.

Etsi `emit_cpi!`-tapahtumalle itse-CPI kohdasta `meta.innerInstructions`,
varmista, että sen ohjelmatunnus on oman ohjelmasi, ja base58-dekoodaa sen instruction data.
Ennen tavujen poistamista varmista Anchorin
[`EVENT_IX_TAG_LE`](https://github.com/solana-foundation/anchor/blob/v1.1.2/lang/src/event.rs#L1-L3):

```ts
import bs58 from "bs58";

const EVENT_IX_TAG_LE = Buffer.from("e445a52e51cb9a1d", "hex");
const instructionData = Buffer.from(bs58.decode(innerInstruction.data));

if (!instructionData.subarray(0, 8).equals(EVENT_IX_TAG_LE)) {
  // This is an ordinary self-CPI, not an emit_cpi! event.
  continue;
}

const eventData = instructionData.subarray(8).toString("base64");
const decoded = program.coder.events.decode(eventData);
```

Sekä ohjelmatunnuksen että tagin tarkistaminen estää tavallista itse-CPI:tä
virheellisesti tulkitsemasta tapahtumaksi.

## Tapahtumaskeemojen versiointi

Oletuksena Anchor johtaa tapahtuman nimestä 8-tavuisen tapahtuman discriminatorin.
Anchor tukee myös eksplisiittistä discriminatoria attribuutilla
`#[event(discriminator = ...)]`. Discriminatorien on pysyttävä yksilöllisinä
ohjelmassa ja vakaina jokaiselle tapahtuman dekoodaavalle asiakkaalle.

Lähetetyn structin kenttien muuttaminen muuttaa sen Borsh-rakennetta. Taaksepäin
yhteensopimattomassa skeemamuutoksessa määritä uusi tapahtuma, kuten `PaymentRecordedV2`, sen sijaan että
muuttaisit `PaymentRecorded`-tapahtumaa hiljaa. Jatka vanhan tapahtuman lähettämistä
siirtymäaikana, jos nykyiset indeksoijat ovat siitä vielä riippuvaisia.

Kehittyvälle datalle suosi kiinteän levyisiä kenttiä ja tunnisteita, joiden avulla
indeksoija voi hakea runsaampia tilitietoja erikseen. Julkaise päivitetty IDL ennen ohjelmapäivitystä tai
sen yhteydessä, jotta kuluttajat voivat dekoodata uuden tapahtuman heti.

## Tapahtumien testaus

Testaa dekoodattua sopimusta, älä base64-merkkijonoa. Rekisteröi kuuntelija ennen
instruktion lähettämistä, varmista dekoodatut kentät ja transaktion allekirjoitus
ja poista kuuntelija aina lopuksi:

```ts
let listenerId = 0;
const received = new Promise<{
  event: { authority: PublicKey; amount: BN };
  signature: string;
}>((resolve) => {
  listenerId = program.addEventListener(
    "PaymentRecorded",
    (event, _slot, signature) => resolve({ event, signature }),
    "confirmed"
  );
});

try {
  const signature = await program.methods.recordPayment(new BN(500)).rpc();
  const result = await received;

  assert.equal(result.signature, signature);
  assert.equal(result.event.amount.toString(), "500");
} finally {
  await program.removeEventListener(listenerId);
}
```

Testaa myös, että indeksoija ohittaa epäonnistuneiden transaktioiden metatietoihin jääneet
tapahtumatavut, ja lisää testiaineisto jokaiselle tuetulle tapahtumaversiolle. Jos käytät
`emit_cpi!`-kutsua, testaa dekoodaus kentästä `innerInstructions`, koska lokikuuntelijat eivät
saa näitä tapahtumia suoraan.
