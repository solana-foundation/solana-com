Tämä osio tarjoaa joitakin yleisiä komentoja ja esimerkkejä, jotka auttavat
sinua alkuun [Anchor CLI:n](https://www.anchor-lang.com/docs) käytössä.

<Steps>
<Step>

### Alusta projekti

Luo uusi Anchor-projekti suorittamalla alla oleva komento. Se luo uuden
hakemiston projektin nimellä ja alustaa sen avulla uuden Anchor-projektin.

```terminal
$ anchor init <project-name>
```

Esimerkiksi alla oleva komento luo projektin nimeltä `my-project`. Hakemisto
`my-project` sisältää modulaarisen Rust-ohjelman ja Rust-testipohjan, joka
käyttää LiteSVM:ää.

```terminal
$ anchor init my-project
```

Jos haluat luoda sen sijaan TypeScript-testipohjan, valitse se erikseen.
Käytä esimerkiksi Mocha-pohjaa:

```terminal
$ anchor init my-project --test-template mocha
```

TypeScript-testipohjat vaativat Node.js:n ja JavaScript-paketinhallinnan.

Siirry sen jälkeen projektin hakemistoon:

```terminal
$ cd <project-name>
```

Katso Anchorin
[projektin tiedostorakenne](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure).

</Step>
<Step>

### Rakenna ohjelma

Rakentaaksesi projektisi, suorita seuraava komento:

```terminal
$ anchor build
```

Löydät käännetyn ohjelman `/target/deploy`-hakemistosta.

<Callout type="warn" title="Alustatyökalujen asennus epäonnistui">
  Jos koontiversio ilmoittaa virheellisestä platform-tools-hakemistosta, asenna SBF-
  koontityökalut uudelleen ja yritä sitten koontia uudelleen:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Julkaise ohjelma

Julkaistaksesi projektisi, suorita seuraava komento:

```terminal
$ anchor deploy
```

Tämä komento julkaisee ohjelmasi
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml)-tiedostossa
määriteltyyn `cluster`-klusteriin.

</Step>
<Step>

### Testaa ohjelma

Testataksesi projektisi, suorita seuraava komento:

```terminal
$ anchor test
```

Tämä komento kääntää, julkaisee ja suorittaa projektisi testit.

<Callout>
  Kun käytät `localnet`-klusteria, Anchor käynnistää automaattisesti paikallisen
  validatorin, julkaisee ohjelman, suorittaa testit ja pysäyttää sitten
  validatorin.
</Callout>

<Callout type="warn" title="JavaScript-testinsuorittajan virheet">

Jos valitsit JavaScript- tai TypeScript-testipohjan, jompikumpi seuraavista
virheistä voi tarkoittaa, että Node.js tai määritetty paketinhallinta ei ole
asennettu:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
