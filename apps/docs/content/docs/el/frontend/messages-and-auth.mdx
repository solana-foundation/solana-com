Η υπογραφή ενός μηνύματος αποδεικνύει ότι ο χρήστης ελέγχει ένα πορτοφόλι, χωρίς συναλλαγή,
χωρίς χρέωση και χωρίς κλήση δικτύου. Οι εφαρμογές χρησιμοποιούν υπογεγραμμένα μηνύματα για να συνδέουν χρήστες, να καταγράφουν ότι
ο χρήστης αποδέχτηκε όρους, να συνδέουν ένα πορτοφόλι με υπάρχων λογαριασμό ή να εξουσιοδοτούν
μια ενέργεια που γίνεται off-chain, όπως η υποβολή μιας παραγγελίας.

Τα πορτοφόλια Solana υπογράφουν μηνύματα με δύο τρόπους:

- Τα **μηνύματα off-chain** (`solana:signOffchainMessage`) τυλίγουν το κείμενό σας σε μια
  τυποποιημένη μορφή, που ορίζεται από την [προδιαγραφή](https://docs.anza.xyz/proposals/off-chain-message-signing)
  υπογραφής μηνυμάτων off-chain (OCMS).
  Η μορφή αυτή δεν μπορεί ποτέ να εκληφθεί ως συναλλαγή, ονομάζει τους λογαριασμούς που
  πρέπει να την υπογράψουν και είναι η μορφή που υπογράφουν τα hardware πορτοφόλια.
- Τα **ακατέργαστα μηνύματα** (`solana:signMessage`) υπογράφουν ακριβώς τα bytes που περνά η εφαρμογή σας,
  χωρίς πρόθεμα και χωρίς δηλωμένους υπογράφοντες. Τα περισσότερα software πορτοφόλια τα υποστηρίζουν,
  αλλά τίποτα στα bytes δεν τα επισημαίνει ως μήνυμα και όχι ως
  συναλλαγή.

Χρησιμοποιήστε μηνύματα off-chain όπου το πορτοφόλι τα υποστηρίζει και καταφύγετε σε ακατέργαστα
μηνύματα όπου δεν τα υποστηρίζει. Ο υπόλοιπος οδηγός χρησιμοποιεί τη σύνδεση χρήστη ως πρακτικό
παράδειγμα, αλλά τα ίδια βήματα υπογραφής και επαλήθευσης ισχύουν για οποιοδήποτε μήνυμα.

## Επιλέξτε μορφή μηνύματος

|                           | Μήνυμα off-chain     | Ακατέργαστο μήνυμα   | Συναλλαγή                   |
| ------------------------- | --------------------- | ------------- | ----------------------------- |
| Λειτουργία πορτοφολιού            | `signOffchainMessage` | `signMessage` | `signTransaction`             |
| Υποστήριξη hardware πορτοφολιού   | Εξαρτάται από τη συσκευή     | Όχι            | Ναι                           |
| Αναγνώσιμο από τον χρήστη      | Ναι                   | Μόνο σε software πορτοφόλια | Εξαρτάται από τη συσκευή             |
| Δηλώνει τους απαιτούμενους υπογράφοντες | Ναι                   | Όχι            | Ναι                           |
| Κλήσεις RPC και χρεώσεις        | Καμία                  | Καμία          | Blockhash, αποστολή, χρέωση, επιβεβαίωση |

### Γιατί όχι συναλλαγή;

Παλαιότερα, τα hardware πορτοφόλια δεν είχαν τρόπο να υπογράψουν ένα αναγνώσιμο μήνυμα. Πολλές εφαρμογές
κατέφευγαν στο να ζητούν από τους χρήστες αυτούς να υπογράψουν μια συναλλαγή χωρίς ενέργεια (no-op). Αυτό λειτουργεί, αλλά
προσθέτει καθυστέρηση, κόστος και κίνδυνο:

- **Χρεώσεις δικτύου.** Μια συναλλαγή πληρώνει χρέωση, ακόμη κι όταν δεν κάνει τίποτα.
- **Πολλαπλές κλήσεις RPC.** Η εφαρμογή σας ανακτά ένα blockhash, εκτελεί προσομοίωση, στέλνει και
  έπειτα ελέγχει διαδοχικά για επιβεβαίωση.
- **Πρόσθετη καθυστέρηση.** Κάθε μία από αυτές τις κλήσεις είναι μια μετάβαση μετ' επιστροφής πριν ο χρήστης
  συνδεθεί.
- **Τίποτα αναγνώσιμο.** Ο χρήστης εγκρίνει bytes συναλλαγής, όχι μια δήλωση για
  το τι συμφωνεί να κάνει.
- **Κίνδυνος συμπεριφοράς.** Το να ζητάτε από τους χρήστες να υπογράψουν μια συναλλαγή μόνο και μόνο για να συνδεθούν τους κάνει
  πιο εύκολο να εξαπατηθούν και να υπογράψουν μια επιβλαβή συναλλαγή.

Ένα μήνυμα off-chain τα παρακάμπτει όλα αυτά. Η μόνη μετάβαση μετ' επιστροφής γίνεται προς τον δικό σας
διακομιστή.

## Τι υπογράφει το πορτοφόλι

Ένα μήνυμα off-chain ξεκινά με ένα σταθερό πεδίο υπογραφής, `\xffsolana offchain`.
Καμία έγκυρη συναλλαγή δεν ξεκινά με αυτά τα bytes, επομένως ένα υπογεγραμμένο μήνυμα δεν μπορεί ποτέ να
χρησιμοποιηθεί ως συναλλαγή. Η έκδοση 1 της μορφής στη συνέχεια απαριθμεί τους απαιτούμενους υπογράφοντες
και μεταφέρει το μήνυμα ως κείμενο UTF-8, χωρίς όριο μήκους.

Το πορτοφόλι δημιουργεί αυτά τα bytes, τα υπογράφει και τα επιστρέφει μαζί με την
υπογραφή. Η
[προδιαγραφή](https://docs.anza.xyz/proposals/off-chain-message-signing)
καλύπτει την πλήρη μορφή, συμπεριλαμβανομένης της παλαιότερης έκδοσης 0.

/>

## Επιλέξτε μέθοδο σύνδεσης

Δεν υποστηρίζουν όλα τα πορτοφόλια μηνύματα off-chain ακόμη. Ελέγξτε τις λειτουργίες του συνδεδεμένου λογαριασμού
πριν ζητήσετε υπογραφή και καταφύγετε σε εναλλακτική λύση όταν η λειτουργία
λείπει:

1. Αν ο λογαριασμός υποστηρίζει το `solana:signOffchainMessage` με έκδοση μηνύματος 1,
   υπογράψτε ένα μήνυμα off-chain.
2. Διαφορετικά, υπογράψτε το ίδιο challenge με το `solana:signMessage`. Τα περισσότερα software
   πορτοφόλια το υποστηρίζουν.
3. Δώστε στους χρήστες hardware πορτοφολιού χωρίς υποστήριξη μηνυμάτων μια ρητή επιλογή συμμετοχής, όπως ένας
   διακόπτης «Χρησιμοποιώ hardware πορτοφόλι», που υπογράφει αντί γι' αυτό μια συναλλαγή σύνδεσης.
   Μην τους κατευθύνετε σε αυτή τη διαδρομή από προεπιλογή.

    ```ts title="offchain-message.ts"
      SolanaSignOffchainMessage,
      type SolanaSignOffchainMessageFeature
    } from "@solana/wallet-standard-features";
    import type { UiWalletAccount } from "@wallet-standard/ui";
    import { getWalletAccountFeature } from "@wallet-standard/ui-features";
    import { getWalletAccountForUiWalletAccount } from "@wallet-standard/ui-registry";

    type OffchainMessageFeature =
      SolanaSignOffchainMessageFeature[typeof SolanaSignOffchainMessage];

    export function supportsOffchainMessages(account: UiWalletAccount) {
      if (!account.features.includes(SolanaSignOffchainMessage)) return false;
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      return feature.supportedMessageVersions.includes(1);
    }

    export async function signOffchainMessage(
      account: UiWalletAccount,
      message: string
    ) {
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      const [output] = await feature.signOffchainMessage({
        messageVersion: 1,
        account: getWalletAccountForUiWalletAccount(account),
        message,
        requiredSigners: [account.publicKey]
      });
      return output;
    }
    ```

    ```tsx title="SignOffchainMessage.tsx"
    export function SignOffchainMessage({ challenge }: { challenge: string }) {

      const onClick = async () => {
        if (!publicKey || !signOffchainMessage) return;
    ```

## Επαληθεύστε την υπογραφή στον διακομιστή σας

Η επαλήθευση είναι ένας τοπικός έλεγχος υπογραφής και δεν χρειάζεται σύνδεση RPC. Αποκωδικοποιήστε τα
bytes που υπέγραψε το πορτοφόλι, επιβεβαιώστε ότι ταιριάζουν με το challenge που εκδώσατε και έπειτα ελέγξτε
την υπογραφή:

```ts title="verify-sign-in.ts"
import {
  address,
  assertOffchainMessageV1Equal,
  getBase64Encoder,
  getOffchainMessageDecoder,
  verifyOffchainMessageEnvelope,
  type OffchainMessageBytes,
  type SignatureBytes
} from "@solana/kit";

export async function verifySignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signedOffchainMessage: string;
  signature: string;
}) {
  const signer = address(input.walletAddress);
  const base64 = getBase64Encoder();
  const content = base64.encode(
    input.signedOffchainMessage
  ) as OffchainMessageBytes;
  const signature = base64.encode(input.signature) as SignatureBytes;

  const received = getOffchainMessageDecoder().decode(content);
  if (received.version !== 1) {
    throw new Error(`Expected a v1 message, got v${received.version}`);
  }
  assertOffchainMessageV1Equal(received, {
    version: 1,
    requiredSignatories: [{ address: signer }],
    content: input.expectedMessage
  });

  await verifyOffchainMessageEnvelope({
    content,
    signatures: { [signer]: signature }
  });
}
```

Το `assertOffchainMessageV1Equal` προκαλεί σφάλμα αν το περιεχόμενο ή οι υπογράφοντες διαφέρουν από
αυτά που περιμένατε. Το `verifyOffchainMessageEnvelope` προκαλεί σφάλμα αν η υπογραφή
λείπει ή δεν είναι έγκυρη. Αναζητήστε το `expectedMessage` με βάση το nonce στον διακομιστή σας αντί να
εμπιστεύεστε το αντίγραφο που στέλνει πίσω ο client. Καταναλώστε το nonce μόλις
επαληθευτεί, ώστε η ίδια υπογραφή να μην μπορεί να χρησιμοποιηθεί για σύνδεση δύο φορές.

### Επαληθεύστε ένα ακατέργαστο μήνυμα

Μια υπογραφή `signMessage` καλύπτει απευθείας τα bytes του challenge, επομένως ο client
χρειάζεται να στείλει μόνο την υπογραφή και τη διεύθυνση του πορτοφολιού. Ελέγξτε την με βάση το
challenge που εκδώσατε:

```ts title="verify-raw-sign-in.ts"
import {
  address,
  getBase64Encoder,
  getPublicKeyFromAddress,
  getUtf8Encoder,
  signatureBytes,
  verifySignature
} from "@solana/kit";

export async function verifyRawSignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signature: string;
}) {
  const publicKey = await getPublicKeyFromAddress(address(input.walletAddress));
  const signature = signatureBytes(getBase64Encoder().encode(input.signature));
  const message = getUtf8Encoder().encode(input.expectedMessage);
  if (!(await verifySignature(publicKey, signature, message))) {
    throw new Error("Invalid signature");
  }
}
```

Ισχύουν οι ίδιοι κανόνες για το nonce: αναζητήστε το `expectedMessage` με βάση το nonce και καταναλώστε το
μόλις επαληθευτεί.

<Callout type="info">
  Το `@solana/kit` επανεξάγει αυτές τις βοηθητικές συναρτήσεις από το `@solana/offchain-messages`. Χρησιμοποιήστε
  το αυτόνομο πακέτο αν ο διακομιστής σας δεν εξαρτάται από το Kit.
</Callout>

## Sign In With Solana

Το [Sign In With Solana](https://github.com/phantom/sign-in-with-solana) (SIWS)
τυποποιεί το ίδιο το challenge. Η εφαρμογή σας περνά δομημένα πεδία, όπως
`domain`, `statement`, `nonce` και `issuedAt`, στη λειτουργία `solana:signIn`
του πορτοφολιού. Το πορτοφόλι τα μορφοποιεί σε ένα τυπικό μήνυμα, συνδέεται αν χρειαστεί
και το υπογράφει σε ένα βήμα.

Η έκδοση `1.1.0` του `solana:signIn` προσθέτει μια επιλογή `useOffchainMessage`. Όταν
περάσετε `useOffchainMessage: { messageVersion: 1 }`, το πορτοφόλι τυλίγει το κείμενο SIWS
σε ένα μήνυμα off-chain έκδοσης 1 με τον λογαριασμό υπογραφής ως μοναδικό απαιτούμενο
υπογράφοντα. Τα hardware πορτοφόλια μπορούν να το εμφανίσουν και να το υπογράψουν, και η έξοδος αναφέρει
`signedMessageFormat: { kind: "offchainMessage", messageVersion: 1 }`. Τα πορτοφόλια
που δηλώνουν την έκδοση `1.0.0` δεν γνωρίζουν την επιλογή, οπότε ελέγξτε πρώτα την έκδοση της λειτουργίας
και παραλείψτε την σε αυτή την περίπτωση.

  <Tab value="Wallet Standard">
    Το `solana:signIn` είναι λειτουργία πορτοφολιού και όχι λογαριασμού, επομένως αυτές οι
    βοηθητικές συναρτήσεις δέχονται ένα `UiWallet`:

    ```ts title="sign-in.ts"
    import {
      SolanaSignIn,
      type SolanaSignInFeature,
      type SolanaSignInInput
    } from "@solana/wallet-standard-features";
    import type { UiWallet } from "@wallet-standard/ui";
    import { getWalletFeature } from "@wallet-standard/ui-features";

    type SignInFeature = SolanaSignInFeature[typeof SolanaSignIn];

    export function supportsOffchainSignIn(wallet: UiWallet) {
      if (!wallet.features.includes(SolanaSignIn)) return false;
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      return feature.version === "1.1.0";
    }

    export async function signIn(wallet: UiWallet, input: SolanaSignInInput) {
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      const [output] = await feature.signIn({
        ...input,
        ...(supportsOffchainSignIn(wallet) && {
          useOffchainMessage: { messageVersion: 1 }
        })
      });
      return output;
    }
    ```

  </Tab>

  <Tab value="Wallet Adapter">
    Το `useWallet` εκθέτει το `signIn` όταν το επιλεγμένο πορτοφόλι υποστηρίζει
    το `solana:signIn`, και το `supportsSignInWithOffchainMessage` όταν δηλώνει
    την έκδοση `1.1.0`. Η μετάδοση του `useOffchainMessage` σε πορτοφόλι που δεν το
    υποστηρίζει απορρίπτεται με `WalletSignInError`:

    ```tsx title="SignIn.tsx"
    "use client";

    import {
      useWallet,
      verifySignIn,
      type SolanaSignInInput
    } from "@solana/wallet-adapter";

    export function SignIn({ input }: { input: SolanaSignInInput }) {
      const { signIn, supportsSignInWithOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!signIn) return;
        const output = await signIn({
          ...input,
          ...(supportsSignInWithOffchainMessage && {
            useOffchainMessage: { messageVersion: 1 }
          })
        });
        const valid = await verifySignIn(input, output);
      };

      return (
        <button onClick={onClick} disabled={!signIn}>
          Sign in with Solana
        </button>
      );
    }
    ```

    Το `verifySignIn` ελέγχει ότι το υπογεγραμμένο μήνυμα αναπαράγει κάθε πεδίο της
    εισόδου και φέρει έγκυρη υπογραφή από τον λογαριασμό υπογραφής, είτε το
    πορτοφόλι υπέγραψε απλό κείμενο SIWS είτε μήνυμα off-chain. Εκτελέστε τον ίδιο έλεγχο στον
    διακομιστή σας εισάγοντάς το από το `@solana/wallet-adapter/core`, το οποίο δεν έχει
    εξάρτηση από το React.

  </Tab>
</Tabs>

Δημιουργήστε την είσοδο στον διακομιστή σας, με ένα `nonce` μίας χρήσης και μια ώρα `issuedAt`,
και κρατήστε ένα αντίγραφο με κλειδί το nonce. Καταναλώστε το nonce μόλις η σύνδεση
επαληθευτεί.

Χωρίς το Wallet Adapter, το `verifySignIn` από το `@solana/wallet-standard-util`
ελέγχει μόνο απλή έξοδο SIWS. Όταν το `signedMessageFormat` αναφέρει μήνυμα off-chain,
το `signedMessage` είναι ένα μήνυμα off-chain του οποίου το περιεχόμενο είναι το κείμενο SIWS.
Ανακατασκευάστε το αναμενόμενο κείμενο από την αποθηκευμένη είσοδό σας και τη διεύθυνση υπογραφής με
το `createSignInMessageText` από το `@solana/wallet-standard-util` και έπειτα επαληθεύστε το
όπως οποιοδήποτε άλλο μήνυμα off-chain, όπως στην ενότητα
[Επαληθεύστε την υπογραφή στον διακομιστή σας](#verify-the-signature-on-your-server). Το
[README του `@solana/offchain-messages`](https://github.com/anza-xyz/kit/tree/main/packages/offchain-messages#verifying-a-signed-offchain-message)
καλύπτει αυτή τη ροή στο Kit.

## Για πορτοφόλια

Τα πορτοφόλια προσθέτουν υποστήριξη υλοποιώντας τη λειτουργία Wallet Standard `solana:signOffchainMessage`
από το `@solana/wallet-standard-features`:

- Δηλώστε `version: "1.0.0"` και απαριθμήστε τις εκδόσεις μηνυμάτων που μπορείτε να υπογράψετε στο
  `supportedMessageVersions`. Σήμερα, αυτή είναι η `[1]`.
- Δημιουργήστε το preamble έκδοσης 1 από το `requiredSigners`, το οποίο ταξινομείτε και ελέγχετε
  για διπλότυπα. Απορρίψτε το αίτημα εάν ο λογαριασμός δεν ανήκει στους απαιτούμενους
  υπογράφοντες.
- Εμφανίστε το κείμενο του μηνύματος στον χρήστη στο σύνολό του πριν από την υπογραφή, ακόμη και σε
  συσκευές hardware.
- Επιστρέψτε τα ακριβή byte που υπογράψατε ως `signedOffchainMessage`, μαζί με την
  υπογραφή `signature` Ed25519.
- Για να υποστηρίξετε το off-chain Sign In With Solana, δηλώστε `version: "1.1.0"` για το
  `solana:signIn`. Όταν η είσοδος περιλαμβάνει το `useOffchainMessage`, υπογράψτε το κείμενο SIWS
  ως off-chain μήνυμα έκδοσης 1, επιστρέψτε τα byte του ως `signedMessage`
  και ορίστε το `signedMessageFormat`.
- Συνεχίστε να υποστηρίζετε το `solana:signMessage`. Παραμένει αμετάβλητο και οι εφαρμογές εξακολουθούν να το
  χρησιμοποιούν ως εναλλακτική λύση.
