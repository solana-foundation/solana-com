Οι παρακάτω όροι χρησιμοποιούνται σε όλη την τεκμηρίωση και το οικοσύστημα ανάπτυξης του Solana.

## account

Μια εγγραφή στο καθολικό του Solana που είτε αποθηκεύει δεδομένα είτε αποτελεί εκτελέσιμο πρόγραμμα.

Όπως ένας λογαριασμός σε μια παραδοσιακή τράπεζα, ένα account στο Solana μπορεί να κρατά κεφάλαια που ονομάζονται
[lamports](#lamport). Κάθε account σε ένα [cluster](#cluster) έχει μια μοναδική
[διεύθυνση](#address).

## app

Μια εφαρμογή frontend που αλληλεπιδρά με ένα cluster του Solana.

## διεύθυνση (address)

Η τοποθεσία στο Solana που μπορεί να χρησιμοποιηθεί για την εύρεση ενός account. Κάθε διεύθυνση είναι
μοναδική στο [cluster](#cluster) του Solana.

Οι διευθύνσεις στο Solana μπορεί να είναι είτε ένα Ed25519 [δημόσιο κλειδί](#public-key-pubkey) είτε
μια [program derived address](#program-derived-address-pda).

## address lookup table (ALT)

Μια δομή δεδομένων που αποθηκεύει μια λίστα διευθύνσεων account, επιτρέποντας σε
[versioned transactions](#versioned-transaction) να αναφέρονται σε accounts χρησιμοποιώντας
συμπαγείς δείκτες 1 byte αντί για πλήρη δημόσια κλειδιά 32 byte. Οι address lookup
tables επιτρέπουν σε μια μόνο συναλλαγή να αναφέρεται σε περισσότερα accounts από όσα επιτρέπει η αρχική
μορφή συναλλαγής. Μόνο οι συναλλαγές έκδοσης 0 (`v0`) υποστηρίζουν address lookup
tables· η έκδοση 1 (`v1`) τις αφαιρεί υπέρ μεγαλύτερου μεγέθους συναλλαγής που χωράει τις ίδιες διευθύνσεις ενσωματωμένες.

## Anchor

Ένα framework για την ανάπτυξη [onchain programs](#onchain-program) του Solana σε Rust.
Το Anchor παρέχει macros που μειώνουν τον επαναλαμβανόμενο κώδικα, ένα τυποποιημένο σύστημα επικύρωσης account,
και δημιουργεί ένα [IDL](#idl) που περιγράφει το interface του προγράμματος.
Αποτελεί το πιο διαδεδομένο framework για την ανάπτυξη προγραμμάτων Solana.

## associated token account (ATA)

Ένα [token account](#token-account) του οποίου η διεύθυνση προκύπτει ντετερμινιστικά
από μια διεύθυνση πορτοφολιού και ένα [token mint](#token-mint). Το πρόγραμμα associated token
account διασφαλίζει ότι κάθε πορτοφόλι έχει ένα κανονικό token account ανά τύπο token.

## εξουσιοδότηση (authority)

Η διεύθυνση ενός χρήστη που έχει κάποιου είδους δικαίωμα επί ενός account.

Για παράδειγμα:

- Η δυνατότητα έκδοσης νέων tokens δίνεται στο account που είναι η 'mint
  authority' για το token mint.
- Η δυνατότητα αναβάθμισης ενός προγράμματος δίνεται στο account που είναι η 'upgrade
  authority' του προγράμματος.

## automated market maker (AMM)

Ένα μοντέλο ανταλλαγής onchain όπου οι χρήστες συναλλάσσονται έναντι ενός pool αποθεμάτων token
που διέπεται από έναν τύπο τιμολόγησης, αντί έναντι εντολής αντισυμβαλλομένου. Οι τιμές κινούνται ως συνάρτηση των αποθεμάτων, οπότε οι συναλλαγές υφίστανται
[slippage](#slippage) ανάλογο με το μέγεθός τους.

## κατάσταση τράπεζας (bank state)

Το αποτέλεσμα ερμηνείας όλων των προγραμμάτων στο καθολικό σε δεδομένο
[tick height](#tick-height). Περιλαμβάνει τουλάχιστον το σύνολο όλων των
[accounts](#account) που κατέχουν μη μηδενικά [native tokens](#native-token).

## block

Ένα συνεχόμενο σύνολο [entries](#entry) στο καθολικό που καλύπτεται από
μια [ψηφοφορία](#ledger-vote). Ένας [leader](#leader) παράγει το πολύ ένα block ανά
[slot](#slot).

## blockhash

Μια μοναδική τιμή ([hash](#hash)) που προσδιορίζει μια εγγραφή (block). Το Solana υπολογίζει
ένα blockhash από το τελευταίο [entry id](#entry-id) του block.

## ύψος block (block height)

Ο αριθμός των [blocks](#block) κάτω από το τρέχον block. Το πρώτο block μετά
το [genesis block](#genesis-block) έχει ύψος ένα.

## bootstrap validator

Ο [validator](#validator) που παράγει το genesis (πρώτο) [block](#block)
μιας αλυσίδας block.

## BPF loader

Το πρόγραμμα Solana που κατέχει και φορτώνει [BPF](/docs/core/programs)
[onchain programs](#onchain-program), επιτρέποντας στο πρόγραμμα να διασυνδέεται με το
runtime.

## bump

Ένα μεμονωμένο byte (0–255) που προσαρτάται στα [seeds](#seed) κατά την εξαγωγή μιας
[program derived address](#program-derived-address-pda) για να διασφαλιστεί ότι η προκύπτουσα
διεύθυνση βρίσκεται εκτός της καμπύλης ed25519 και είναι επομένως έγκυρη PDA. Το κανονικό
bump είναι η υψηλότερη τιμή που παράγει έγκυρη PDA και αποθηκεύεται συνήθως στα
δεδομένα του account για να αποφεύγεται ο επανυπολογισμός του.

## central limit order book (CLOB)

Ένα μοντέλο ανταλλαγής που τηρεί ταξινομημένη λίστα εκκρεμών εντολών αγοράς και πώλησης· μια συναλλαγή
πραγματοποιείται όταν μια εισερχόμενη εντολή διασταυρωθεί με εντολή στην αντίθετη πλευρά. Σε αντιδιαστολή
με το [automated market maker](#automated-market-maker-amm).

## client

Ένα πρόγραμμα υπολογιστή που προσπελάζει το δίκτυο διακομιστών [cluster](#cluster) του Solana.

## δέσμευση (commitment)

Ένα μέτρο επιβεβαίωσης δικτύου για το [block](#block).

## μορφή compact array

Ένας compact array είναι ένας πίνακας που σειριοποιείται στην ακόλουθη μορφή:

- Το μήκος του πίνακα (κωδικοποιημένο ως
  [compact-u16](https://github.com/anza-xyz/agave/blob/v2.1.13/short-vec/src/lib.rs))
- Τα στοιχεία του πίνακα αναφερόμενα το ένα μετά το άλλο

![Μορφή compact array](/assets/docs/core/transactions/compact_array_format.png)

Η μορφή compact array χρησιμοποιείται για την κωδικοποίηση τόσο του πίνακα
[διευθύνσεων account](/docs/core/transactions/transaction-structure#account-addresses)
όσο και του πίνακα
[εντολών](/docs/core/transactions/transaction-structure#instructions)
σε μηνύματα συναλλαγών.

## cluster

Ένα σύνολο [validators](#validator) που τηρούν ένα ενιαίο [καθολικό](#ledger).

## υπολογιστικός προϋπολογισμός (compute budget)

Ο μέγιστος αριθμός [compute units](#compute-units) που καταναλώνονται ανά συναλλαγή.

## compute units

Η μικρότερη μονάδα μέτρησης κατανάλωσης υπολογιστικών πόρων του blockchain. Τα compute units χρησιμοποιούνται για τη μέτρηση των υπολογιστικών πόρων που απαιτούνται για την επεξεργασία μιας συναλλαγής.

## χρόνος επιβεβαίωσης (confirmation time)

Η διάρκεια ρολογιού τοίχου μεταξύ της δημιουργίας μιας [tick entry](#tick) από έναν [leader](#leader) και της δημιουργίας ενός [confirmed block](#confirmed-block).

## επιβεβαιωμένο block (confirmed block)

Ένα [block](#block) που έχει λάβει [υπερπλειοψηφία](#supermajority)
[ψήφων καθολικού](#ledger-vote).

## επίπεδο ελέγχου (control plane)

Ένα δίκτυο gossip που συνδέει όλους τους [κόμβους](#node) ενός [cluster](#cluster).

## περίοδος ψύξης (cooldown period)

Ορισμένος αριθμός [epochs](#epoch) μετά την απενεργοποίηση του [stake](#stake), κατά τους οποίους
αυτό γίνεται σταδιακά διαθέσιμο για ανάληψη. Κατά τη διάρκεια αυτής της περιόδου, το stake
θεωρείται «απενεργοποιούμενο». Περισσότερες πληροφορίες:
[warmup and cooldown](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)

## μονάδες κόστους (cost units)

Αναφέρεται επίσης ως `transaction cost`, αποτελεί μια ολοκληρωμένη εκτίμηση όλων των
πόρων που απαιτούνται για την επεξεργασία μιας συναλλαγής, μετρούμενη σε
[compute units](#compute-units). Περισσότερες πληροφορίες
[εδώ](https://www.anza.xyz/blog/why-solana-transaction-costs-and-compute-units-matter-for-developers).

## πίστωση (credit)

Βλέπε [vote credit](#vote-credit).

## cross-program invocation (CPI)

Μια κλήση από ένα [onchain program](#onchain-program) σε άλλο. Για περισσότερες
πληροφορίες, βλέπε [κλήση μεταξύ προγραμμάτων](/docs/core/cpi).

## επίπεδο δεδομένων (data plane)

Ένα δίκτυο multicast που χρησιμοποιείται για αποδοτική επικύρωση [entries](#entry) και επίτευξη
συναίνεσης.

## drone

Μια υπηρεσία offchain που λειτουργεί ως θεματοφύλακας του ιδιωτικού κλειδιού ενός χρήστη. Συνήθως χρησιμεύει
για επικύρωση και υπογραφή συναλλαγών.

## entry

Μια εγγραφή στο [καθολικό](#ledger), είτε ένα [tick](#tick) είτε
μια [εγγραφή συναλλαγής](#transactions-entry).

## entry id

Ένα [hash](#hash) ανθεκτικό σε preimage επί του τελικού περιεχομένου μιας entry, το οποίο
λειτουργεί ως παγκοσμίως μοναδικό αναγνωριστικό της [entry](#entry). Το hash αποτελεί
απόδειξη για:

- Την entry που δημιουργήθηκε μετά από διάστημα χρόνου
- Οι καθορισμένες [συναλλαγές](#transaction) είναι αυτές που περιλαμβάνονται στην entry
- Τη θέση της entry σε σχέση με άλλες entries στο [καθολικό](#ledger)

Βλέπε [proof of history](#proof-of-history-poh).

## epoch

Ο χρόνος, δηλαδή ο αριθμός των [slots](#slot), για τον οποίο
ισχύει ένα [πρόγραμμα leader](#leader-schedule).

## escrow

Ένα πρότυπο κατά το οποίο ένα [onchain program](#onchain-program) κρατά tokens σε
ένα [vault](#vault) για λογαριασμό δύο ή περισσότερων μερών έως ότου πληρωθούν οι συνθήκες που ορίζει το
πρόγραμμα, οπότε τα αποδεσμεύει. Χρησιμοποιείται για την εξάλειψη της ανάγκης τα μέρη να εμπιστεύονται άμεσα το ένα το άλλο.

## λογαριασμός τέλους (fee account)

Ο fee account στη συναλλαγή είναι ο λογαριασμός που πληρώνει το κόστος
συμπερίληψης της συναλλαγής στο καθολικό. Αυτός είναι ο πρώτος λογαριασμός στη
συναλλαγή. Ο λογαριασμός αυτός πρέπει να δηλωθεί ως Read-Write (εγγράψιμος) στη
συναλλαγή, καθώς η πληρωμή για τη συναλλαγή μειώνει το υπόλοιπο του λογαριασμού.

## οριστικοποίηση (finality)

Όταν κόμβοι που εκπροσωπούν τα 2/3 του [stake](#stake) έχουν κοινή
[ρίζα](#root).

## διακλάδωση (fork)

Ένα [καθολικό](#ledger) που προέρχεται από κοινές εγγραφές αλλά έπειτα αποκλίνει.

## genesis block

Το πρώτο [block](#block) στην αλυσίδα.

## genesis config

Το αρχείο ρυθμίσεων που προετοιμάζει το [καθολικό](#ledger) για το
[genesis block](#genesis-block).

## hash

Ένα ψηφιακό αποτύπωμα μιας ακολουθίας bytes.

## πληθωρισμός (inflation)

Αύξηση της προσφοράς token με την πάροδο του χρόνου, που χρησιμοποιείται για τη χρηματοδότηση ανταμοιβών επικύρωσης και τη
συνεχή ανάπτυξη του Solana.

## εσωτερική εντολή (inner instruction)

Βλέπε [cross-program invocation](#cross-program-invocation-cpi).

## εντολή (instruction)

Μια κλήση για επίκληση ενός συγκεκριμένου [instruction handler](#instruction-handler) σε ένα
[πρόγραμμα](#program). Μια εντολή καθορίζει επίσης ποια accounts θέλει να
διαβάσει ή να τροποποιήσει, καθώς και πρόσθετα δεδομένα που χρησιμεύουν ως βοηθητική είσοδος στον
[instruction handler](#instruction-handler). Ένας [client](#client) πρέπει να συμπεριλάβει τουλάχιστον
μια εντολή σε μια [συναλλαγή](#transaction), και όλες οι εντολές
πρέπει να ολοκληρωθούν για να θεωρηθεί επιτυχής η συναλλαγή.

## instruction handler

Οι instruction handlers είναι συναρτήσεις [προγράμματος](#program) που επεξεργάζονται
[εντολές](#instruction) από [συναλλαγές](#transaction). Ένας instruction
handler μπορεί να περιέχει μία ή περισσότερες
[cross-program invocations](#cross-program-invocation-cpi).

## IDL

Interface Definition Language. Ένα αρχείο JSON που δημιουργείται από το [Anchor](#anchor) και
περιγράφει τους [instruction handlers](#instruction-handler), τα accounts
και τους τύπους ενός προγράμματος. Το IDL επιτρέπει στις βιβλιοθήκες client να δημιουργούν αυτόματα
τυποποιημένα interfaces για αλληλεπίδραση με ένα [onchain program](#onchain-program).

## keypair

Ένα [δημόσιο κλειδί](#public-key-pubkey) και το αντίστοιχο [ιδιωτικό κλειδί](#private-key)
για πρόσβαση σε ένα account.

## lamport

Ένα κλασματικό [native token](#native-token) με αξία 0,000000001
[SOL](#sol).

> Στο πλαίσιο του compute budget, μια ποσότητα
> _[micro-lamports](https://github.com/solana-labs/solana/blob/ced8f6a512c61e0dd5308095ae8457add4a39e94/program-runtime/src/prioritization_fee.rs#L1-L2)_
> χρησιμοποιείται στον υπολογισμό των [prioritization fees](#prioritization-fee).

## leader

Ο ρόλος ενός [validator](#validator) όταν προσαρτά [entries](#entry) στο
[καθολικό](#ledger).

## πρόγραμμα leader (leader schedule)

Μια ακολουθία [δημόσιων κλειδιών](#public-key-pubkey) [validator](#validator) αντιστοιχισμένη
σε [slots](#slot). Το cluster χρησιμοποιεί το πρόγραμμα leader για να προσδιορίσει ποιος
validator είναι ο [leader](#leader) σε κάθε χρονική στιγμή.

## καθολικό (ledger)

Μια λίστα [entries](#entry) που περιέχει [συναλλαγές](#transaction) υπογεγραμμένες από
[clients](#client). Εννοιολογικά, αυτό μπορεί να ανιχνευθεί μέχρι το
[genesis block](#genesis-block), αλλά το καθολικό ενός πραγματικού [validator](#validator)
μπορεί να περιέχει μόνο νεότερα [blocks](#block) για να μειωθεί ο αποθηκευτικός χώρος, καθώς τα παλαιότερα δεν είναι
απαραίτητα για την επικύρωση μελλοντικών blocks εκ σχεδιασμού.

## ψήφος καθολικού (ledger vote)

Ένα [hash](#hash) της [κατάστασης του validator](#bank-state) σε δεδομένο
[tick height](#tick-height). Περιλαμβάνει την επιβεβαίωση του [validator](#validator)
ότι ένα [block](#block) που έχει λάβει έχει επαληθευτεί, καθώς και
μια υπόσχεση να μην ψηφίσει για αντικρουόμενο [block](#block) \(δηλ. [fork](#fork)\)
για συγκεκριμένο χρονικό διάστημα, την περίοδο [lockout](#lockout).

## light client

Ένας τύπος [πελάτη](#client) που μπορεί να επαληθεύσει ότι δείχνει σε έγκυρο
[cluster](#cluster). Εκτελεί περισσότερη επαλήθευση του καθολικού από έναν
[thin client](#thin-client) και λιγότερη από έναν [validator](#validator).

## ρευστότητα

Το βάθος των εντολών ή των δεσμευμένων αποθεμάτων που είναι διαθέσιμα για συναλλαγές στην τρέχουσα
τιμή ή κοντά σε αυτήν. Μεγαλύτερη ρευστότητα μειώνει το [slippage](#slippage). Σε ένα
[CLOB](#central-limit-order-book-clob), η ρευστότητα παρέχεται από
[maker orders](#maker)· σε ένα [AMM](#automated-market-maker-amm) παρέχεται
από παρόχους ρευστότητας που καταθέτουν ζεύγη token στη δεξαμενή.

## loader

Ένα [πρόγραμμα](#program) με τη δυνατότητα να ερμηνεύει την δυαδική κωδικοποίηση άλλων
[onchain προγραμμάτων](#onchain-program).

## lockout

Η χρονική διάρκεια κατά την οποία ένας [validator](#validator) δεν μπορεί να
[ψηφίσει](#ledger-vote) σε άλλο [fork](#fork).

## maker

Ένας trader της οποίας η εντολή προσθέτει [ρευστότητα](#liquidity) σε ένα
[CLOB](#central-limit-order-book-clob) αναμένοντας στο βιβλίο αντί να
συμψηφιστεί άμεσα με την αντίθετη πλευρά. Μια τέτοια εντολή ονομάζεται maker order.
Οι makers συνήθως δεν πληρώνουν χρέωση ή λαμβάνουν έκπτωση από τo venue.

## market maker

Μια οντότητα που παρέχει [ρευστότητα](#liquidity) δημοσιεύοντας συνεχώς τόσο
προσφορές αγοράς όσο και πώλησης. Στο Solana, οι market makers είναι είτε προγράμματα (όπως
[AMMs](#automated-market-maker-amm)) είτε εξωτερικές εταιρείες που εκτελούν bots και δημοσιεύουν
[maker orders](#maker) σε [CLOBs](#central-limit-order-book-clob).

## μήνυμα

Τα δομημένα περιεχόμενα μιας [συναλλαγής](#transaction). Γενικά περιέχει μια
κεφαλίδα, έναν πίνακα διευθύνσεων λογαριασμών, ένα πρόσφατο [blockhash](#blockhash) και έναν πίνακα
[εντολών](#instruction).

Μάθετε περισσότερα για τη
[μορφοποίηση μηνυμάτων μέσα σε συναλλαγές](/docs/core/transactions/transaction-structure#header)
εδώ.

## micro-lamport

1.000.000 micro-lamports = 1 [lamport](#lamport)

## συντελεστής Nakamoto

Ένα μέτρο αποκέντρωσης, ο Συντελεστής Nakamoto είναι ο μικρότερος αριθμός
ανεξάρτητων οντοτήτων που μπορούν να δράσουν συλλογικά για να τερματίσουν ένα blockchain. Ο
όρος επινοήθηκε από τους Balaji S. Srinivasan και Leland Lee στο
[Quantifying Decentralization](https://news.earn.com/quantifying-decentralization-e39db233c28e).

## native token

Το [token](#token) που χρησιμοποιείται για την παρακολούθηση της εργασίας που εκτελείται από τους [κόμβους](#node) σε ένα cluster.

## κόμβος

Ένας υπολογιστής που συμμετέχει σε ένα [cluster](#cluster).

## πλήθος κόμβων

Ο αριθμός των [validators](#validator) που συμμετέχουν σε ένα [cluster](#cluster).

## offchain

Περιγράφει δεδομένα, διαδικασίες ή υπηρεσίες που υπάρχουν ή εκτελούνται εκτός του blockchain του Solana,
όπως RPC clients, indexers, frontends και offchain order book
makers. Συμπλήρωμα του [onchain](#onchain). Η ορθογραφία "Offchain" (χωρίς παύλα) είναι
προτιμώμενη.

## onchain

Περιγράφει δεδομένα ή προγράμματα που υπάρχουν ή εκτελούνται σε ένα blockchain. Η ορθογραφία "Onchain" (χωρίς
παύλα) είναι προτιμώμενη.

## onchain πρόγραμμα

Ο εκτελέσιμος κώδικας στο blockchain του Solana που ερμηνεύει τις
[εντολές](#instruction) που αποστέλλονται μέσα σε κάθε [συναλλαγή](#transaction) για
ανάγνωση και τροποποίηση λογαριασμών επί των οποίων έχει έλεγχο. Αυτά τα προγράμματα αναφέρονται συχνά
ως "[_smart contracts_](/docs/core/programs)" σε άλλα blockchains.

## oracle

Ένα [onchain πρόγραμμα](#onchain-program) που δημοσιεύει δεδομένα από εκτός της
αλυσίδας — συνήθως τιμές πραγματικών περιουσιακών στοιχείων — για ανάγνωση από άλλα προγράμματα.

## ιδιοκτήτης

Μπορεί να αναφέρεται είτε στο [κατέχον πρόγραμμα](#owning-program) είτε στο
[κατέχον πορτοφόλι](#owning-wallet). Για παράδειγμα,
[getTokenAccountsByOwner](https://solana.com/docs/rpc/http/gettokenaccountsbyowner)
λαμβάνει token accounts που ανήκουν σε ένα συγκεκριμένο πορτοφόλι, ωστόσο το κατέχον πρόγραμμα για
αυτά τα token accounts είναι το [token program](#token-program).

Για να αποφευχθεί σύγχυση, προτιμάται η χρήση είτε του
[κατέχοντος προγράμματος](#owning-program) είτε του [κατέχοντος πορτοφολιού](#owning-wallet) αντί του
γενικού όρου «ιδιοκτήτης».

## proof of history (PoH)

Μια στοίβα αποδείξεων, καθεμία από τις οποίες αποδεικνύει ότι κάποια δεδομένα υπήρχαν πριν δημιουργηθεί η απόδειξη
και ότι παρήλθε ακριβής χρονική διάρκεια πριν από την προηγούμενη
απόδειξη. Όπως ένα [VDF](#verifiable-delay-function-vdf), ένα Proof of History μπορεί να
επαληθευτεί σε λιγότερο χρόνο από αυτόν που χρειάστηκε για να παραχθεί.

## χρέωση προτεραιότητας

Μια πρόσθετη χρέωση που μπορεί να ορίσει ο χρήστης στην [εντολή](#instruction) compute budget
για να δώσει προτεραιότητα στις [συναλλαγές](#transaction) του.

Η χρέωση προτεραιότητας υπολογίζεται πολλαπλασιάζοντας τις ζητούμενες μέγιστες
μονάδες υπολογισμού με την τιμή ανά μονάδα υπολογισμού (που καθορίζεται σε προσαυξήσεις των 0,000001
[lamports](#lamport) ανά μονάδα υπολογισμού) στρογγυλοποιημένη προς τα πάνω στο πλησιέστερο
[lamport](#lamport).

Οι συναλλαγές θα πρέπει να ζητούν τον ελάχιστο αριθμό μονάδων υπολογισμού που απαιτείται για
εκτέλεση, ώστε να ελαχιστοποιηθούν τα τέλη.

## rent

Χρέωση που καταβάλλουν [Λογαριασμοί](#account) και [Προγράμματα](#program) για την αποθήκευση δεδομένων στο
blockchain. Όταν οι λογαριασμοί δεν έχουν επαρκές υπόλοιπο για να πληρώσουν rent, ενδέχεται να
απαλειφθούν (Garbage Collected).

Δείτε επίσης [rent exempt](#rent-exempt) παρακάτω. Μάθετε περισσότερα για το rent εδώ:
[Τι είναι το rent;](/docs/core/accounts/account-structure).

## rent exempt

Λογαριασμοί που διατηρούν ένα ελάχιστο υπόλοιπο σε lamports ανάλογο με
την ποσότητα δεδομένων που αποθηκεύονται στον λογαριασμό. Όλοι οι νέοι λογαριασμοί αποθηκεύονται
onchain μόνιμα έως ότου κλείσει ο λογαριασμός. Δεν είναι δυνατή η δημιουργία
λογαριασμού που πέφτει κάτω από το όριο απαλλαγής rent.

## root

Ένα [block](#block) ή [slot](#slot) που έχει φτάσει στο μέγιστο [lockout](#lockout)
σε έναν [validator](#validator). Το root είναι το υψηλότερο block που είναι πρόγονος
όλων των ενεργών forks σε έναν validator. Όλα τα προγονικά blocks ενός root είναι επίσης
μεταβατικά roots. Τα blocks που δεν είναι πρόγονος ούτε απόγονος του
root αποκλείονται από τη διαδικασία συναίνεσης και μπορούν να απορριφθούν.

## seed

Μια τιμή byte ή πίνακας τιμών byte που χρησιμοποιείται ως είσοδος κατά την παραγωγή μιας
[program derived address](#program-derived-address-pda). Ένα πρόγραμμα μπορεί να χρησιμοποιεί οποιονδήποτε
συνδυασμό στατικών συμβολοσειρών, δημόσιων κλειδιών ή άλλων δεδομένων ως seeds. Τα seeds συνδυάζονται
με το ID του προγράμματος και ένα [bump](#bump) για να παράγουν μια μοναδική διεύθυνση PDA.

## υπογραφή

Μια υπογραφή ed25519 64 bytes από R (32 bytes) και S (32 bytes). Με την
απαίτηση ότι το R είναι ένα συμπαγές σημείο Edwards που δεν είναι μικρής τάξης και το S είναι ένα
scalar στο εύρος `0 <= S < L`. Αυτή η απαίτηση διασφαλίζει την απουσία malleability υπογραφής. Κάθε συναλλαγή πρέπει να έχει τουλάχιστον μία υπογραφή για τον
[λογαριασμό χρέωσης](#fee-account). Επομένως, η πρώτη υπογραφή στη συναλλαγή μπορεί να
θεωρηθεί ως [transaction id](#transaction-id)

## υπογράφων

Ένας [λογαριασμός](#account) που έχει εξουσιοδοτήσει μια [εντολή](#instruction) ή
[συναλλαγή](#transaction). Για ένα κανονικό [keypair](#keypair) αυτό σημαίνει μια
κρυπτογραφική [υπογραφή](#signature) επί της συναλλαγής. Για ένα
[program derived address](#program-derived-address-pda), η εξουσιοδότηση
βεβαιώνεται από το [κατέχον πρόγραμμα](#owning-program) όταν κάνει μια
[cross-program invocation](#cross-program-invocation-cpi), καθώς ένα PDA δεν έχει
ιδιωτικό κλειδί.

## ποσοστό παράλειψης

Το ποσοστό των [παραλειφθέντων slots](#skipped-slot) επί του συνόλου των leader slots
στο τρέχον epoch. Αυτή η μετρική μπορεί να παραπλανά καθώς έχει υψηλή διακύμανση
μετά το όριο epoch όταν το μέγεθος δείγματος είναι μικρό, καθώς και για
validators με μικρό αριθμό leader slots, ωστόσο μπορεί επίσης να είναι χρήσιμη για
την αναγνώριση εσφαλμένων ρυθμίσεων κόμβου σε ορισμένες στιγμές.

## παραλειφθέν slot

Ένα παρελθοντικό [slot](#slot) που δεν παρήγαγε [block](#block), επειδή ο leader
ήταν εκτός σύνδεσης ή το [fork](#fork) που περιείχε το slot εγκαταλείφθηκε υπέρ μιας καλύτερης
εναλλακτικής από τη συναίνεση του cluster. Ένα παραλειφθέν slot δεν θα εμφανιστεί ως πρόγονος
για blocks σε επόμενα slots, ούτε θα αυξήσει το [block height](#block-height),
ούτε θα λήξει το παλαιότερο `recent_blockhash`.

Το αν ένα slot έχει παραλειφθεί μπορεί να προσδιοριστεί μόνο όταν γίνει παλαιότερο
από το πιο πρόσφατο [rooted](#root) (άρα μη παραλειφθέν) slot.

## slippage

Η διαφορά μεταξύ της τιμής που ανέμενε ένας trader και της τιμής στην οποία
εκτελέστηκε πραγματικά η συναλλαγή. Σε [AMMs](#automated-market-maker-amm) προκύπτει από
τη μετακίνηση της καμπύλης τιμολόγησης καθώς αλλάζουν τα αποθέματα· σε
[CLOBs](#central-limit-order-book-clob) προκύπτει από μία μόνο εντολή που καταναλώνει
αρκετές εκκρεμείς εντολές σε διαδοχικά χειρότερες τιμές.

## slot

Η χρονική περίοδος κατά την οποία κάθε [leader](#leader) επεξεργάζεται συναλλαγές και
παράγει ένα [block](#block).

Συνολικά, τα slots δημιουργούν ένα λογικό ρολόι. Τα slots είναι διατεταγμένα διαδοχικά και
δεν αλληλεπικαλύπτονται, αποτελώντας περίπου ίσο πραγματικό χρόνο σύμφωνα με το
[PoH](#proof-of-history-poh).

## verifiable delay function (VDF)

Μια συνάρτηση που χρειάζεται σταθερό χρόνο για να εκτελεστεί και παράγει μια απόδειξη
ότι εκτελέστηκε, η οποία μπορεί στη συνέχεια να επαληθευτεί σε λιγότερο χρόνο από αυτόν που χρειάστηκε για να παραχθεί.

## versioned transaction

Μια μορφή συναλλαγής που υποστηρίζει πρόσθετες δυνατότητες πέρα από την αρχική
μορφή [συναλλαγής](#transaction). Η έκδοση 0 (`v0`) είναι η πρώτη εκδοχή με εκδόσεις
και προσθέτει υποστήριξη για [address lookup tables](#address-lookup-table-alt),
επιτρέποντας στις συναλλαγές να αναφέρονται σε περισσότερους λογαριασμούς από ό,τι επιτρέπει η αρχική μορφή.
Η έκδοση 1 (`v1`), ενεργή σε όλα τα clusters, αυξάνει το μέγιστο μέγεθος συναλλαγής
σε 4.096 bytes, φέρει όρια πόρων σε ένα τμήμα config του μηνύματος
αντί για εντολές ComputeBudget και καταργεί την υποστήριξη address lookup table.
Βλέπε [versioned transactions](/docs/core/transactions/versioned-transactions).
