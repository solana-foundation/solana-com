Μια συναλλαγή εκτελείται μόνο εφόσον φέρει έγκυρη
[υπογραφή](/docs/core/transactions/transaction-structure#signatures) από κάθε
απαιτούμενο υπογράφοντα. Κατά την τοπική ανάπτυξη συνήθως κρατάτε αυτό το κλειδί ως
[`Keypair`](/developers/cookbook/wallets/create-keypair) και υπογράφετε απευθείας. Στην
παραγωγή το σημαντικό ερώτημα είναι διαφορετικό: **πού βρίσκεται το ιδιωτικό κλειδί
και ποιος δικαιούται να εγκρίνει μια υπογραφή με αυτό;**

<Callout type="warn">
  Ποτέ μην ενσωματώνετε ιδιωτικά κλειδιά σε κώδικα πλευράς πελάτη, μην τα συμπεριλαμβάνετε σε ένα frontend bundle και μην τα κάνετε commit σε source control. Όποιος αποκτήσει ένα κλειδί αποκτά πλήρη έλεγχο των κεφαλαίων του συγκεκριμένου λογαριασμού.
</Callout>

## Προσεγγίσεις υπογραφής

| Προσέγγιση                  | Πού βρίσκεται το κλειδί                                     | Ποιος υπογράφει                                          | Ιδανικό για                                                      |
| ------------------------- | ------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **Τοπικό keypair**         | Ένα αρχείο ή μια μεταβλητή περιβάλλοντος στο μηχάνημα           | Ο κώδικάς σας, απευθείας                                | Τοπική ανάπτυξη, δοκιμές, CI                                  |
| **Πορτοφόλι προγράμματος περιήγησης**        | Το πορτοφόλι του τελικού χρήστη (π.χ. Phantom, Solflare)          | Ο τελικός χρήστης, ανά συναλλαγή                      | dApps frontend όπου οι χρήστες υπογράφουν τις δικές τους συναλλαγές        |
| **Cloud KMS / HSM**       | Μια υπηρεσία κλειδιών βασισμένη σε υλικό (AWS KMS, GCP KMS, Vault) | Το backend σας ζητά υπογραφή από την υπηρεσία | Υπηρεσίες backend, λειτουργίες ταμείου (treasury), ρυθμιζόμενα περιβάλλοντα |
| **Διαχειριζόμενα πορτοφόλια / πορτοφόλια MPC** | Διαμοιρασμένο ή υπό φύλαξη στην υποδομή ενός παρόχου   | Ο πάροχος συνυπογράφει σύμφωνα με την πολιτική σας     | Ενσωματωμένα πορτοφόλια, ροές έγκρισης, θεσμική φύλαξη   |

Το τοπικό keypair είναι η μόνη προσέγγιση που τοποθετεί ωμό υλικό κλειδιού μέσα στην
εφαρμογή σας. Κάθε προσέγγιση παραγωγής κρατά το κλειδί σε ειδική υποδομή
και ζητά από αυτήν την υποδομή να υπογράψει εκ μέρους σας.

## Υπογραφή από το backend

Όταν ένας διακομιστής χρειάζεται να υπογράψει (πληρωμή τελών, αποστολή συναλλαγών προγραμμάτων ή
διαχείριση ταμείου), χρησιμοποιήστε ένα ειδικό backend διαχείρισης κλειδιών αντί για ωμό
keypair. Το Solana Foundation συντηρεί το [Keychain](/docs/tools/keychain), μια
ενοποιημένη βιβλιοθήκη υπογραφής (Rust, TypeScript, Python και Go) που εκθέτει μία
διεπαφή `SolanaSigner` σε όλα τα backend του παραπάνω πίνακα: Memory,
HashiCorp Vault, AWS KMS, GCP KMS, Fireblocks, Privy, Turnkey, CDP, Crossmint,
Dfns, Para, Openfort, Utila και Fordefi.

Επειδή η διεπαφή είναι κοινή σε όλα τα backend, μπορείτε να αναπτύσσετε τοπικά με ένα
κλειδί στη μνήμη και να περνάτε σε ένα backend παραγωγής μέσω ρυθμίσεων, χωρίς
να ξαναγράψετε τον κώδικα της εφαρμογής (τα backend που κάνουν εκπομπή για λογαριασμό σας, όπως το Crossmint,
καλούνται μέσω διαδρομής υπογραφής και αποστολής). Το Keychain είναι συμβατό με
το [`@solana/kit`](/docs/clients/official/javascript), το
[Rust SDK](/docs/clients/official/rust), το `solders` (Python) και το `solana-go` v2
(Go).
