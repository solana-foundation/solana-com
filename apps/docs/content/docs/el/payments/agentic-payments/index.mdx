Οι πληρωμές από agents επιτρέπουν στο λογισμικό να ανακαλύπτει μια τιμή, να εξουσιοδοτεί μια πληρωμή και να λαμβάνει
έναν πόρο στην ίδια ροή εργασίας HTTP. Ένας agent μπορεί να πληρώσει για ένα ερώτημα δεδομένων, μια εξαγωγή συμπερασμάτων από μοντέλο
ή μια κλήση εργαλείου χωρίς να δημιουργήσει πρώτα λογαριασμό χρέωσης ή να αντιγράψει ένα
κλειδί API.

## Η κοινή ροή πληρωμής

Τα MPP και x402 χρησιμοποιούν διαφορετικές κεφαλίδες και μοντέλα δεδομένων, αλλά η βασική ροή HTTP τους είναι
παρόμοια:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP και x402

Και τα δύο πρωτόκολλα μπορούν να διακανονίσουν πληρωμές με stablecoins στο Solana. Επιλέξτε με βάση το
μοντέλο πληρωμής και τη διαλειτουργικότητα που χρειάζεται η υπηρεσία σας, και όχι μόνο τον κοινό κωδικό κατάστασης `402`.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Πρόκληση (challenge)               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| Εξουσιοδότηση πελάτη    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Απόδειξη                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Μοντέλα πληρωμής στο Solana   | Εφάπαξ `charge` και `session` με όριο και μέτρηση χρήσης           | Σχήματα όπως `exact` και `upto`· η υποστήριξη διαφέρει ανά δίκτυο και πελάτη |
| Αρχιτεκτονική διακανονισμού | Επικύρωση από τον διακομιστή ή προαιρετικός relay ή gateway                | Διακομιστής πόρων με τοπική επαλήθευση ή facilitator                 |
| Καλό σημείο εκκίνησης     | APIs που χρειάζονται σημασιολογία ελέγχου ταυτότητας HTTP ή επαναλαμβανόμενη μέτρηση χρήσης | Πόροι με πληρωμή ανά αίτημα και υπάρχοντες πελάτες x402                      |

Το MPP είναι το **Machine Payments Protocol**. Μην το συγχέετε με το **Model
Context Protocol (MCP)**. Το MCP εκθέτει εργαλεία και πόρους σε agents· το MPP ή το x402
μπορεί να απαιτεί πληρωμή όταν ένας agent επικαλείται ένα από αυτά τα εργαλεία.

<Callout type="info">
  Μια υπηρεσία μπορεί να διαφημίζει περισσότερα από ένα πρωτόκολλα. Ο πελάτης επιλέγει μια επιλογή πληρωμής
  που υποστηρίζει και, στη συνέχεια, χρησιμοποιεί τις αντίστοιχες κεφαλίδες πρόκλησης, εξουσιοδότησης και
  απόδειξης για ολόκληρη την ανταλλαγή.
</Callout>
