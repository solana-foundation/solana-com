Οι πληρωμές από πράκτορες (agentic payments) επιτρέπουν σε ένα λογισμικό να ανακαλύπτει την τιμή, να εξουσιοδοτεί μια πληρωμή και να λαμβάνει
έναν πόρο στην ίδια ροή εργασίας HTTP. Ένας πράκτορας μπορεί να πληρώσει για ένα ερώτημα δεδομένων, μια συμπερασματική διαδικασία μοντέλου
(model inference) ή μια κλήση εργαλείου, χωρίς να χρειαστεί πρώτα να δημιουργήσει λογαριασμό χρέωσης ή να αντιγράψει
κλειδί API.

## Η κοινή ροή πληρωμής

Τα MPP και x402 χρησιμοποιούν διαφορετικές κεφαλίδες και μοντέλα δεδομένων, αλλά η βασική ροή HTTP τους
είναι παρόμοια:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP και x402

Και τα δύο πρωτόκολλα μπορούν να διακανονίζουν πληρωμές σε stablecoin στο Solana. Επιλέξτε με βάση το
μοντέλο πληρωμής και τη διαλειτουργικότητα που χρειάζεται η υπηρεσία σας, και όχι μόνο με βάση τον κοινό κωδικό κατάστασης `402`.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Πρόκληση (Challenge)               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| Εξουσιοδότηση πελάτη    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Απόδειξη                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Μοντέλα πληρωμής στο Solana   | Εφάπαξ `charge` και `session` intents με όριο και μέτρηση χρήσης           | Σχήματα όπως `exact` και `upto`· η υποστήριξη διαφέρει ανά δίκτυο και πελάτη |
| Αρχιτεκτονική διακανονισμού | Επικύρωση από τον διακομιστή ή προαιρετικά relay ή gateway                | Διακομιστής πόρου με τοπική επαλήθευση ή facilitator                 |
| Καλό σημείο εκκίνησης     | APIs που χρειάζονται σημασιολογία ελέγχου ταυτότητας HTTP ή επαναλαμβανόμενη μέτρηση χρήσης | Πόροι με πληρωμή ανά αίτημα και υπάρχοντες πελάτες x402                      |

Το MPP είναι το **Machine Payments Protocol**. Μην το μπερδεύετε με το **Model
Context Protocol (MCP)**. Το MCP εκθέτει εργαλεία και πόρους σε πράκτορες· το MPP ή το x402
μπορούν να απαιτούν πληρωμή όταν ένας πράκτορας καλεί κάποιο από αυτά τα εργαλεία.

<Callout type="info">
  Μια υπηρεσία μπορεί να διαφημίζει περισσότερα από ένα πρωτόκολλα. Ο πελάτης επιλέγει μια επιλογή πληρωμής
  που υποστηρίζει και, στη συνέχεια, χρησιμοποιεί τις αντίστοιχες κεφαλίδες πρόκλησης, εξουσιοδότησης και
  απόδειξης για ολόκληρη την ανταλλαγή.
</Callout>
