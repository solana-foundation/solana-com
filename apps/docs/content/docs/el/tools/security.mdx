## Διαχείριση κλειδιών

- **Μην εκθέτετε ποτέ ιδιωτικά κλειδιά στον κώδικα frontend.** Χρησιμοποιήστε υπογραφή από το backend, πορτοφόλια υλικού (hardware wallets), πορτοφόλια πολλαπλών υπογραφών ή υπηρεσίες διαχείρισης κλειδιών.
- **Διαχωρίστε τα hot και τα cold πορτοφόλια.** Το hot πορτοφόλι για τις λειτουργίες, το cold για το treasury.
- **Δημιουργήστε αντίγραφα ασφαλείας για όλα τα κλειδιά παραγωγής.** Αποθηκεύστε κρυπτογραφημένα αντίγραφα ασφαλείας σε πολλαπλές ασφαλείς τοποθεσίες. Η απώλεια ενός κλειδιού σημαίνει μόνιμη απώλεια πρόσβασης.
- **Χρησιμοποιήστε διαφορετικά κλειδιά για το devnet και το mainnet.** Τα κλειδιά του devnet δεν πρέπει να είναι τα ίδια με τα κλειδιά του mainnet. Χρησιμοποιήστε ρύθμιση παραμέτρων βάσει περιβάλλοντος, ώστε να φορτώνονται τα σωστά κλειδιά για κάθε δίκτυο.

## Υποδομή υπογραφής

Για υπογραφή στο backend σε περιβάλλον παραγωγής, χρησιμοποιήστε το [Keychain](/docs/tools/keychain)—μια ενοποιημένη βιβλιοθήκη υπογραφής που αφαιρεί την πολυπλοκότητα πολλαπλών backend διαχείρισης κλειδιών μέσω μιας ενιαίας διεπαφής: Memory, Vault, Privy, Turnkey, AWS KMS, Fireblocks, GCP KMS, CDP, Para, Dfns, Crossmint, Openfort και Utila. Έτσι μπορείτε να αναπτύσσετε τοπικά με κλειδιά στη μνήμη και στη συνέχεια να μεταβείτε σε backend επιπέδου παραγωγής χωρίς να αλλάξετε τον κώδικα της εφαρμογής σας.

Δεν είστε σίγουροι ποιο backend ταιριάζει; Δείτε την ενότητα [Επιλογή backend](/docs/tools/keychain/choosing-a-backend). Το Keychain είναι διαθέσιμο τόσο για [Rust](https://crates.io/crates/solana-keychain) όσο και για [TypeScript](https://www.npmjs.com/package/@solana/keychain).

## Ασφάλεια RPC

Αντιμετωπίστε τα endpoints RPC όπως τα κλειδιά API—μην τα εκθέτετε στον κώδικα frontend, όπου μπορούν να εξαχθούν και να γίνει κατάχρησή τους. Χρησιμοποιήστε ένα backend proxy ή μεταβλητές περιβάλλοντος που δεν συμπεριλαμβάνονται στον κώδικα του client.

- [QuickNode: Βέλτιστες πρακτικές ασφάλειας των endpoints](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: Προστατέψτε τα κλειδιά API σας για το Solana: Βέλτιστες πρακτικές ασφάλειας](https://www.helius.dev/docs/rpc/protect-your-keys)

## Παρακολούθηση

Παρακολουθήστε αυτές τις μετρικές στο περιβάλλον παραγωγής:

| Μετρική                   | Γιατί                    |
| ------------------------ | ---------------------- |
| Ποσοστό επιτυχίας συναλλαγών | Έγκαιρος εντοπισμός προβλημάτων    |
| Καθυστέρηση επιβεβαίωσης     | Παρακολούθηση της υγείας του δικτύου |
| Δαπάνη τελών προτεραιότητας       | Διαχείριση κόστους        |
| Ποσοστό σφαλμάτων RPC           | Υγεία του παρόχου        |

Ρυθμίστε ειδοποιήσεις για:

- Μεταφορές από το treasury πάνω από ένα όριο
- Απότομες αυξήσεις στο ποσοστό αποτυχημένων συναλλαγών
- Ασυνήθιστα μοτίβα παραληπτών
- Αυξήσεις στο ποσοστό σφαλμάτων RPC

Για παρακολούθηση συναλλαγών σε πραγματικό χρόνο και σε μεγάλη κλίμακα, δείτε τον [Οδηγό ευρετηρίασης](/docs/payments/accept-payments/indexing).

## Επαλήθευση διευθύνσεων

Κάθε token και πρόγραμμα έχει ακριβώς μία σωστή διεύθυνση στο mainnet. Τα πλαστά tokens που μιμούνται το USDC ή άλλα stablecoins είναι συνηθισμένα—έχουν το ίδιο όνομα και σύμβολο, αλλά διαφορετικό mint. Η εφαρμογή σας θα πρέπει να ορίζει σταθερά ή να τηρεί λίστα επιτρεπόμενων (allowlist) για τις διευθύνσεις mint (ανάλογα με τις απαιτήσεις σας) και να μην τις δέχεται ποτέ δυναμικά από μη αξιόπιστες πηγές.

**Ρύθμιση παραμέτρων βάσει περιβάλλοντος:** Το Devnet και το Mainnet χρησιμοποιούν συχνά εντελώς διαφορετικά token mints. Ρυθμίστε τη διαμόρφωση της εφαρμογής σας ώστε να φορτώνει τις σωστές διευθύνσεις ανά περιβάλλον—μην ορίζετε σταθερά τις διευθύνσεις του mainnet και ξεχνάτε να τις αλλάξετε κατά τις δοκιμές ή, ακόμη χειρότερα, να στείλετε διευθύνσεις του devnet στην παραγωγή.

Μερικά συνηθισμένα stablecoin mints είναι:

| Token | Εκδότης | Διεύθυνση mint                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

Οι διευθύνσεις των προγραμμάτων έχουν επίσης σημασία. Η αποστολή εντολών στο λάθος πρόγραμμα θα αποτύχει—ή, ακόμη χειρότερα, θα οδηγήσει σε μη αναστρέψιμη απώλεια κεφαλαίων. Οι διευθύνσεις του Token Program είναι:

| Πρόγραμμα            | Διεύθυνση                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Πρόγραμμα Token-2022 | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

Η τήρηση λίστας επιτρεπόμενων για τις σωστές διευθύνσεις προστατεύει από πλαστά tokens, αλλά δεν προστατεύει από την αποστολή σε λάθος _είδος_ λογαριασμού. Μια διεύθυνση παραλήπτη μπορεί να είναι πορτοφόλι, token account, mint ή πρόγραμμα, και το καθένα απαιτεί διαφορετικό χειρισμό. Το εγγενές SOL που αποστέλλεται σε οτιδήποτε άλλο εκτός από πορτοφόλι βγαίνει από τον έλεγχο του αποστολέα — χάνεται οριστικά αν πρόκειται για mint ή πρόγραμμα και ανακτάται μόνο από τον κάτοχο του λογαριασμού αν πρόκειται για token account — χωρίς καμία αποτυχημένη συναλλαγή που να προειδοποιεί τον χρήστη.

<Callout type="warn" title="Επαληθεύστε τους παραλήπτες πριν από την αποστολή">
  Κατηγοριοποιήστε κάθε διεύθυνση παραλήπτη πριν υπογράψετε μια μεταφορά. Δείτε την ενότητα [Επαλήθευση διεύθυνσης](/docs/payments/send-payments/verify-address) για το πλήρες δέντρο αποφάσεων και τον κώδικα αναφοράς που διακρίνει πορτοφόλια, token accounts, mints και προγράμματα.
</Callout>
