## Υποδομή RPC

[Τα δημόσια endpoints](https://solana.com/docs/references/clusters#solana-public-rpc-endpoints)
(`api.mainnet.solana.com`) έχουν περιορισμό ρυθμού αιτημάτων και δεν διαθέτουν SLA. Είναι ΟΚ για
ανάπτυξη, αλλά θα αποτύχουν στις ροές πληρωμών παραγωγής—σαν να προσπαθείτε να λειτουργήσετε έναν επεξεργαστή
πληρωμών μέσω ενός κοινόχρηστου API χωρίς εγγύηση διαθεσιμότητας.

<Callout type="caution" title="Μην χρησιμοποιείτε ποτέ δημόσιο RPC στην παραγωγή">
  Χρησιμοποιήστε έναν [ιδιωτικό πάροχο RPC](https://solana.com/rpc) για αξιόπιστη πρόσβαση με χαμηλή
  καθυστέρηση.
</Callout>

Όταν επιλέγετε πάροχο RPC, αναζητήστε:

- **Αξιοπιστία**: SLA με εγγυήσεις διαθεσιμότητας (99,9%+)
- **Καθυστέρηση**: Γεωγραφική εγγύτητα στους χρήστες σας
- **Λειτουργίες**: Λειτουργίες προσγείωσης συναλλαγών, indexing, API προτεραιότητας τελών

Για μια πλήρη λίστα παρόχων RPC, δείτε τον οδηγό
[Πάροχοι υποδομής RPC](https://solana.com/rpc).

### Διαμόρφωση πλεονάζοντος RPC

Όπως κάθε πάροχος υπηρεσιών δικτύου, οι πάροχοι RPC μπορεί να παρουσιάσουν διακοπές λειτουργίας ή
περιόδους μειωμένης απόδοσης. Για να διασφαλίσετε ότι η εφαρμογή σας είναι ανθεκτική,
πρέπει να τη διαμορφώσετε ώστε να χρησιμοποιεί πολλαπλούς παρόχους RPC.

Το [Solana Kit](https://github.com/anza-xyz/kit/tree/main/packages/rpc-transport-http)
παρέχει μια βιβλιοθήκη για την προσαρμογή των RPC transports, η οποία σας επιτρέπει να δημιουργήσετε
τον δικό σας redundant RPC client. Ακολουθεί ένα παράδειγμα για το πώς μπορείτε να τη χρησιμοποιήσετε για να δημιουργήσετε έναν
redundant RPC client:

```ts
import { RpcTransport } from "@solana/rpc-spec";
import { RpcResponse } from "@solana/rpc-spec-types";
import { createHttpTransport } from "@solana/rpc-transport-http";

// Create a transport for each RPC server
const transports = [
  createHttpTransport({ url: "https://mainnet-beta.my-server-1.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-2.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-3.com" })
];

// Create a wrapper transport that distributes requests to them
let nextTransport = 0;
async function roundRobinTransport<TResponse>(
  ...args: Parameters<RpcTransport>
): Promise<RpcResponse<TResponse>> {
  const transport = transports[nextTransport];
  nextTransport = (nextTransport + 1) % transports.length;
  return await transport(...args);
}
```

Αν προτιμάτε να μην δημιουργήσετε δικά σας εργαλεία δρομολόγησης, μπορείτε να αξιοποιήσετε μια υπηρεσία
τρίτου μέρους, όπως το [Iron Forge](https://www.ironforge.sanctum.so/), για να αναλάβει
τη δρομολόγηση για εσάς.

## Προσγείωση συναλλαγών

Στο Devnet, οι συναλλαγές προσγειώνονται αρκετά εύκολα. Στο Mainnet, ανταγωνίζεστε για
χώρο στα blocks. Για να αυξήσετε τις πιθανότητες να συμπεριληφθεί η συναλλαγή σας σε ένα
block, πρέπει να βεβαιωθείτε ότι έχετε συναρμολογήσει σωστά τη συναλλαγή σας. Αυτό
σημαίνει:

- συμπερίληψη ενός πρόσφατου blockhash πριν από την αποστολή της συναλλαγής
- συμπερίληψη μιας εντολής τέλους προτεραιότητας στη συναλλαγή με ανταγωνιστικό
  τέλος προτεραιότητας
- συμπερίληψη μιας εντολής ορίου compute units στη συναλλαγή, με όριο compute
  units βασισμένο στα εκτιμώμενα compute units που απαιτούνται για τη συναλλαγή

Επιπλέον, θα πρέπει να εξετάσετε άλλα εργαλεία, όπως τα Jito Bundles, για να αυξήσετε τις
πιθανότητες να συμπεριληφθεί η συναλλαγή σας σε ένα block. Ας εξερευνήσουμε αυτά τα εργαλεία
αναλυτικότερα.

### Διαμόρφωση αποστολής συναλλαγών

Κατά την αποστολή συναλλαγών στο Mainnet, διαμορφώστε αυτές τις παραμέτρους για βέλτιστα
ποσοστά προσγείωσης:

**Διαχείριση blockhash:**

- Ανάκτηση με δέσμευση `confirmed`
- Αποθηκεύστε το `lastValidBlockHeight` που επιστρέφει η `getLatestBlockhash`—αυτό σας λέει
  πότε λήγει η συναλλαγή σας
- Τα blockhashes λήγουν μετά από χρόνο που ορίζεται από το πρωτόκολλο και εξαρτάται από τη διάρκεια του
  slot.

**Επιλογές αποστολής:**

- `maxRetries: 0` — Απενεργοποιεί τις αυτόματες επαναπροσπάθειες του RPC. Διαχειριστείτε εσείς τις επαναπροσπάθειες, ώστε
  να μπορείτε να ανανεώσετε το blockhash όταν χρειάζεται.
- `skipPreflight: true` — Παρακάμπτει την προσομοίωση πριν από την αποστολή. Χρησιμοποιήστε το όταν έχετε
  ήδη επικυρώσει τη συναλλαγή και θέλετε τη χαμηλότερη καθυστέρηση. Διατηρήστε το `false`
  κατά την ανάπτυξη για να εντοπίζετε σφάλματα νωρίς.

```typescript
import { createSolanaRpc } from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);

// 1. Get blockhash with confirmed commitment
const { value: latestBlockhash } = await rpc
  .getLatestBlockhash({ commitment: "confirmed" })
  .send();

// 2. Build and sign your transaction with the blockhash
// ... (transaction building code)

// 3. Send with production settings
const signature = await rpc
  .sendTransaction(encodedTransaction, {
    encoding: "base64",
    maxRetries: 0n, // Handle retries yourself
    skipPreflight: true, // Skip simulation for speed (use false during dev)
    preflightCommitment: "confirmed"
  })
  .send();

// 4. Track expiration using lastValidBlockHeight
const { lastValidBlockHeight } = latestBlockhash;
// Stop retrying when current block height exceeds lastValidBlockHeight
```

### Χρήση τελών προτεραιότητας

Κάθε συναλλαγή Solana απαιτεί ένα τέλος συναλλαγής, που πληρώνεται σε SOL. Τα τέλη
συναλλαγής χωρίζονται σε δύο μέρη: το βασικό τέλος και το τέλος προτεραιότητας. Το βασικό τέλος
αποζημιώνει τους validators για την επεξεργασία της συναλλαγής. Το τέλος προτεραιότητας είναι ένα
προαιρετικό τέλος, που αυξάνει την πιθανότητα ο τρέχων leader να επεξεργαστεί τη
συναλλαγή σας. Σκεφτείτε το σαν ταχυμεταφορά: πληρώνετε περισσότερο για ταχύτερη και πιο
αξιόπιστη παράδοση.

**Πώς λειτουργούν τα τέλη:**

```
Total fee = Base fee (5,000 lamports per signature) + Priority fee
Priority fee (legacy/v0) = ceil(compute_unit_price * compute_unit_limit / 1,000,000) lamports
Priority fee (v1 only) = Absolute total in lamports set in the message config
```

**Κόστη στον πραγματικό κόσμο:**

- Απλή μεταφορά USDC: ~$0,001-0,005 υπό κανονικές συνθήκες
- Σε περίοδο congestion: ~$0,01-0,05
- Σε κορύφωση congestion: Μπορεί να αυξηθεί ακόμη περισσότερο

**Παράδειγμα υλοποίησης:**

Το πακέτο
[`@solana-program/compute-budget`](https://github.com/solana-program/compute-budget)
παρέχει μια βοηθητική συνάρτηση για εύκολη ενημέρωση ή προσθήκη της εντολής τιμής compute unit
(σε micro-lamports) σε μια συναλλαγή.

```typescript
import { updateOrAppendSetComputeUnitPriceInstruction } from "@solana-program/compute-budget";

const tx = pipe(
  createTransactionMessage({ version: 0 }),
  (m) => setTransactionMessageFeePayerSigner(payer, m),
  (m) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, m),
  (m) => appendTransactionMessageInstructions([myInstructions], m),
  (m) => updateOrAppendSetComputeUnitPriceInstruction(1000n as MicroLamports, m)
);
```

**Λήψη εκτιμήσεων τελών:** Οι περισσότεροι πάροχοι RPC προσφέρουν API τελών προτεραιότητας:

- [Helius Priority Fee API](https://docs.helius.dev/solana-apis/priority-fee-api)
- [QuickNode Priority Fee Add-on](https://marketplace.quicknode.com/add-on/solana-priority-fee)
- [Triton Priority Fees API](https://docs.triton.one/chains/solana/improved-priority-fees-api)

Για τη πλήρη λειτουργία των τελών, δείτε τα [Τέλη συναλλαγών](/docs/core/fees) και τον
οδηγό μας:
[Πώς να προσθέσετε τέλη προτεραιότητας σε μια συναλλαγή](https://solana.com/developers/cookbook/transactions/add-priority-fees).

### Βελτιστοποίηση compute units

Ο υπολογισμός στο Solana μετριέται σε compute units (CUs), που αποτελούν μια πρόχειρη εκτίμηση
του όγκου εργασίας που εκτελεί το πρόγραμμα. Τα σημερινά όρια υπολογισμού είναι 50 εκατομμύρια
CUs ανά block και 1,4 εκατομμύρια CUs ανά συναλλαγή. Όταν υποβάλλετε μια
συναλλαγή, πρέπει να εκτιμήσετε τον όγκο υπολογισμού που θα χρησιμοποιηθεί και να
ορίσετε αντίστοιχα το όριο compute units - ουσιαστικά πρόκειται για αίτημα σχετικά με το πόσο
από τη συνολική χωρητικότητα πρέπει να δεσμευτεί για τη συναλλαγή σας. Στην
πράξη, αυτό σημαίνει ότι η σωστή εκτίμηση των compute units που απαιτούνται για τη
συναλλαγή σας είναι κρίσιμη για τη συμπερίληψή της σε ένα block (και
σημαντική για τη διαχείριση των τελών προτεραιότητάς σας). Το όριο υπολογισμού της συναλλαγής και του block
καθορίζεται από το πρωτόκολλο.

Το Solana JSON RPC API διαθέτει μια μέθοδο
[`simulatetransaction`](/docs/rpc/http/simulatetransaction) που μπορεί να
χρησιμοποιηθεί για την εκτίμηση των compute units που απαιτούνται για μια συναλλαγή, και περιλαμβάνει μια
εκτίμηση των compute units που θα χρησιμοποιηθούν.
Το [`@solana/kit`](https://github.com/anza-xyz/kit) παρέχει βοηθητικές συναρτήσεις που
εκτιμούν τα όρια πόρων μιας συναλλαγής και τα ορίζουν στο μήνυμα με ένα μόνο βήμα
(χρησιμοποιώντας εσωτερικά τη μέθοδο `simulatetransaction`). Για συναλλαγές έκδοσης 1,
αυτές οι βοηθητικές συναρτήσεις εκτιμούν επίσης το όριο μεγέθους δεδομένων των φορτωμένων λογαριασμών.

```ts
import {
  estimateResourceLimitsFactory,
  estimateAndSetResourceLimitsFactory
} from "@solana/kit";

const estimateResourceLimits = estimateResourceLimitsFactory({ rpc });
const estimateAndSetResourceLimits = estimateAndSetResourceLimitsFactory(
  estimateResourceLimits
);
const txWithResourceLimits = await estimateAndSetResourceLimits(tx);
```

<Callout type="info">
  Αν δημιουργείτε και στέλνετε συναλλαγές με έναν kit plugin client, συνήθως
  δεν χρειάζεστε αυτό το βήμα — ο client προσθέτει για εσάς τις εντολές compute budget
  όταν στέλνει (`.sendTransaction()`). Η παραπάνω χειροκίνητη ροή αφορά την περίπτωση που
  συναρμολογείτε συναλλαγές απευθείας με το `@solana/kit`.
</Callout>

Στην παραγωγή, αν επαναλαμβάνετε πολλές φορές τον ίδιο τύπο συναλλαγής,
θα πρέπει να εξετάσετε το ενδεχόμενο caching της εκτίμησης compute για τον συγκεκριμένο τύπο συναλλαγής, ώστε να
αποφύγετε το κόστος της εκτίμησης των compute units κάθε φορά.

### Στρατηγικές επαναπροσπάθειας

Οι συναλλαγές μπορεί να αποτύχουν για πολλούς λόγους. Σε αντίθεση με τα παραδοσιακά API πληρωμών, που
επιστρέφουν άμεσα επιτυχία/αποτυχία, οι συναλλαγές blockchain απαιτούν παρακολούθηση
επιβεβαίωσης.

**Βασικές έννοιες:**

- **Λήξη blockhash**: Λήξη blockhash: Τα blockhashes των συναλλαγών παραμένουν
  έγκυρα για 150 slots (περίπου 30 δευτερόλεπτα με χρόνο slot 200ms). Ο πραγματικός
  χρόνος λήξης μπορεί να διαφέρει ανάλογα με την ταχύτητα παραγωγής των blocks. Χρησιμοποιήστε το
  lastValidBlockHeight για να προσδιορίσετε πότε έχει λήξει ένα blockhash.
- **Αυτοδυναμία (Idempotency)**: Η ίδια υπογεγραμμένη συναλλαγή παράγει πάντα την ίδια
  υπογραφή—η επανυποβολή είναι ασφαλής
- **Εκθετικό backoff**: Αποφύγετε την υπερφόρτωση του δικτύου με γρήγορες επαναπροσπάθειες

```typescript
import {
  createSolanaRpc,
  createSolanaRpcSubscriptions,
  sendAndConfirmTransactionFactory,
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED
} from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);
const rpcSubscriptions = createSolanaRpcSubscriptions(process.env.RPC_WSS_URL!);

const sendAndConfirmTransaction = sendAndConfirmTransactionFactory({
  rpc,
  rpcSubscriptions
});

// Send with automatic confirmation tracking and block height monitoring
try {
  await sendAndConfirmTransaction(signedTransaction, {
    commitment: "confirmed",
    // Optional: abort after 75 seconds
    abortSignal: AbortSignal.timeout(75_000)
  });
} catch (e) {
  if (isSolanaError(e, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED)) {
    // Blockhash expired—rebuild transaction with fresh blockhash and retry
    rebuildAndRetryTransaction(); // implement your own logic for rebuilding and retrying the transaction
  }
  throw e;
}
```

Η `sendAndConfirmTransactionFactory` από το `@solana/kit` χειρίζεται αυτόματα το polling
επιβεβαίωσης και την παρακολούθηση του ύψους block. Εκπέμπει το
`SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED` όταν το blockhash της συναλλαγής λήγει,
υποδεικνύοντας ότι πρέπει να ξαναδημιουργήσετε τη συναλλαγή με ένα πρόσφατο blockhash.

## Διαχείριση σφαλμάτων

Το Solana Kit παρέχει τυποποιημένα σφάλματα μέσω της `isSolanaError()`. Χρησιμοποιήστε συγκεκριμένους κωδικούς σφαλμάτων
αντί για αντιστοίχιση συμβολοσειρών:

```typescript
import {
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED,
  SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE,
  SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND,
  SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS
} from "@solana/kit";

function handlePaymentError(error: unknown): {
  message: string;
  retryable: boolean;
} {
  // Blockhash expired—rebuild and retry
  if (
    isSolanaError(error, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED) ||
    isSolanaError(error, SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND)
  ) {
    return { message: "Transaction expired—rebuilding", retryable: true };
  }

  // Insufficient SOL for fees
  if (
    isSolanaError(
      error,
      SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE
    )
  ) {
    return { message: "Not enough SOL for fees", retryable: false };
  }

  // Insufficient token balance
  if (
    isSolanaError(error, SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS)
  ) {
    return { message: "Insufficient balance", retryable: false };
  }

  // Unknown error
  console.error("Payment error:", error);
  return { message: "Payment failed—please retry", retryable: true };
}
```

**Συνήθεις κωδικοί σφαλμάτων:**

| Κωδικός σφάλματος                   | Αιτία                 | Αποκατάσταση                                                                                                 |
| ---------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------- |
| `BLOCK_HEIGHT_EXCEEDED`      | Το blockhash έληξε     | Ξαναδημιουργήστε με πρόσφατο blockhash                                                                             |
| `BLOCKHASH_NOT_FOUND`        | Το blockhash δεν βρέθηκε   | Ξαναδημιουργήστε με πρόσφατο blockhash                                                                             |
| `INSUFFICIENT_FUNDS_FOR_FEE` | Μη επαρκή SOL        | Χρηματοδοτήστε τον πληρωτή τελών ή χρησιμοποιήστε την [αφαίρεση τελών (fee abstraction)](/docs/payments/send-payments/payment-processing/fee-abstraction) |
| `INSUFFICIENT_FUNDS`         | Μη επαρκή tokens     | Ο χρήστης χρειάζεται μεγαλύτερο υπόλοιπο                                                                                  |
| `ACCOUNT_NOT_FOUND`          | Λείπει το token account | Δημιουργήστε ATA στη συναλλαγή                                                                                |

## Συναλλαγές χωρίς gas

Οι χρήστες αναμένουν να πληρώνουν σε stablecoins, όχι να αποκτούν SOL για τα τέλη δικτύου. Οι
συναλλαγές χωρίς gas λύνουν αυτό το πρόβλημα—όπως οι χρήστες του Venmo δεν σκέφτονται τα τέλη ACH.
Δείτε την
[Αφαίρεση τελών (Fee Abstraction)](/docs/payments/send-payments/payment-processing/fee-abstraction)
για την πλήρη υλοποίηση.
