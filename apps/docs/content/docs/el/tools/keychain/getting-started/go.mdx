Η έκδοση 2.0.0 είναι η πρώτη σταθερή έκδοση των modules της Go, επομένως δεν υπάρχει τίποτα προς μεταφορά. Ο
[οδηγός μετάβασης στην έκδοση 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)
καλύπτει τον ίδιο διαχωρισμό δυνατοτήτων για Rust και TypeScript.

## Εγκατάσταση

Κάθε backend είναι ένα ξεχωριστό module της Go, οπότε το build και το γράφημα των modules σας περιέχουν
μόνο τα backends που εισάγετε:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

Τα modules φέρουν tag `go/<module>/v2.0.0` (για παράδειγμα
`go/signers/memory/v2.0.0`). Κάθε module απαιτεί Go 1.25.0, εκτός από το `gcpkms`,
που απαιτεί Go 1.25.8 λόγω του ελάχιστου ορίου που θέτει το `google.golang.org/api`.
Το Ledger υποστηρίζεται μόνο στη Rust και δεν διαθέτει module Go.

### solana-go v2 και συναλλαγές v1

Τα modules βασίζονται στο
[`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go)
v2.0.0 και δέχονται το `*solana.Transaction` του. Υποστηρίζονται συναλλαγές legacy, v0 και v1
(`solana.MessageVersionV1`), εκτός από το Fireblocks
με `UseProgramCall: true`, που δέχεται μόνο legacy και v0.

## Βασική χρήση

Κάθε signer υλοποιεί τη βασική
[διεπαφή `core.SolanaSigner`](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)
(`Pubkey`, `SignMessage`, `IsAvailable`). Οι μέθοδοι δέχονται ένα `context.Context` και
είναι blocking. Κάθε backend υλοποιεί επίσης ακριβώς μία διεπαφή δυνατοτήτων:

- `core.TransactionSigner`: το `SignTransaction` υπογράφει τη συναλλαγή σας ως έχει.
- `core.ModifyingSigner`: το `ModifyAndSignTransaction` επιτρέπει στον πάροχο να ξαναγράψει
  τη συναλλαγή και στη συνέχεια την υπογράφει.
- `core.SendingSigner`: το `SignAndSendTransaction` αναθέτει στον πάροχο την υπογραφή και
  το broadcast της συναλλαγής.

Κάθε πακέτο backend εκθέτει ένα struct `Config` και έναν constructor `New`:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

Τα `SignTransaction` και `ModifyAndSignTransaction` επιστρέφουν ένα
`core.SignedTransaction` (`EncodedTransaction`, `Signature`, `Completeness`).
Τα απομακρυσμένα HTTP backends δέχονται προαιρετικά `HTTPClient` και `HTTPClientConfig`
(timeouts). Ο προεπιλεγμένος client επιβάλλει HTTPS· αν δώσετε δικό σας, αυτό παρακάμπτεται
και η ασφάλειά του είναι δική σας ευθύνη.

### Δυνατότητες signer

Ένα backend που δεν μπορεί να υπογράψει συναλλαγή δεν διαθέτει καθόλου μέθοδο `SignTransaction`,
επομένως η δυνατότητα είναι γεγονός compile-time για τους συγκεκριμένους τύπους και
type assertion για ένα `core.SolanaSigner`:

| Backend                                                                         | Δυνατότητα          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | Ναι                            |
| cdp                                                                             | `TransactionSigner` | Μόνο payloads UTF-8            |
| utila                                                                           | `TransactionSigner` | Αποτυγχάνει με `CodeSigningFailed` |
| fordefi black box (`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | Ναι                            |
| fordefi native manual (`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | Ναι                            |
| fordefi native auto (`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | Ναι                            |
| crossmint                                                                       | `SendingSigner`     | Αποτυγχάνει με `CodeSigningFailed` |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### Αρχικοποίηση

Δεν υπάρχει ξεχωριστό βήμα `Init`. Τα Privy, Fireblocks, Dfns, Crossmint, Para,
Openfort και Utila επιλύουν τη διεύθυνση του πορτοφολιού μέσα στο `New`, γι' αυτό και οι
constructors τους δέχονται ένα `context.Context`. Δημιουργείτε πάντα τους signers μέσω του `New`: ένας
signer Crossmint, Para ή Utila με μηδενική τιμή (zero-value) αποτυγχάνει με `CodeNotInitialized`
αντί να υπογράψει για τη μηδενική διεύθυνση.

### Υπογραφή και αποστολή με οποιονδήποτε signer

Το `core.SignAndSendTransaction` οδηγεί μια συναλλαγή στο chain όποια κι αν είναι η μορφή
του signer. Ένας `SendingSigner` κάνει broadcast μέσω του παρόχου του και αγνοεί τη συνάρτηση
αποστολής· κάθε άλλη μορφή υπογράφει και η δική σας συνάρτηση κάνει broadcast το αποτέλεσμα σε base64,
το οποίο για έναν `ModifyingSigner` είναι η συναλλαγή που ξαναέγραψε ο πάροχός του.
Ο πυρήνας (core) δεν έχει εξάρτηση από RPC:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### Υπογραφή σε παρτίδες

Η υπογραφή σε παρτίδες παρέχεται ως ανεξάρτητα βοηθητικά functions, με ταυτόχρονη εκτέλεση και προαιρετική
χρονική καθυστέρηση ανά αίτημα για APIs με περιορισμό ρυθμού:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

Το `core.SignTransactions` δέχεται ένα `core.TransactionSigner`, επομένως οι
signers με διαχειριζόμενο broadcast (Crossmint, Fordefi native auto) και το Fordefi native
manual δεν μπορούν να υπογράψουν σε παρτίδες μέσω αυτού· καλέστε τους μία συναλλαγή τη φορά. Ένας
signer του οποίου οι κλήσεις δημιουργούν εργασία από την πλευρά του παρόχου (Fireblocks με `UseProgramCall`)
το δηλώνει μέσω του `core.BatchServerSideEffects`, και τότε η παρτίδα εκτελείται
διαδοχικά.

## Διαμόρφωση backend

### Memory

Δώστε ακριβώς ένα από τα `PrivateKey` (ακατέργαστα bytes), `PrivateKeyString` (base58 ή πίνακας bytes
`[1,2,...]`) ή `PrivateKeyPath` (αρχείο keypair του Solana CLI):

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Η Go δεν προσφέρει αξιόπιστο τρόπο μηδενισμού της μνήμης: ο garbage collector μπορεί να αντιγράψει και να
διατηρήσει bytes κλειδιών (keypair στη μνήμη, καθώς και τα κλειδιά που παράγουν τοπικά το Crossmint και το Openfort)
μέχρι τη συλλογή. Αντιμετωπίστε ολόκληρη τη μνήμη της διεργασίας ως ευαίσθητη όταν
χρησιμοποιείτε backends τοπικών κλειδιών.

### Crossmint

Το Crossmint είναι μόνο για αποστολή: το API του εκτελεί κάθε εγκεκριμένη συναλλαγή
από την πλευρά του διακομιστή, οπότε το `*crossmint.Signer` διαθέτει `SignAndSendTransaction` και όχι
`SignTransaction`. Η συναλλαγή σας δεν τροποποιείται ποτέ· η υπογραφή που επιστρέφεται
προσδιορίζει τη συναλλαγή που κατέγραψε το Crossmint, η οποία μπορεί να διαφέρει από τη δική σας αν
το Crossmint επιδοτεί το gas.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Fordefi

Το Fordefi διατίθεται με τρεις τύπους signer, που καθορίζονται κατά την κατασκευή από τα `Config.Chain` και
`Config.PushMode`. Και οι τρεις υπογράφουν μηνύματα:

| Config                                          | Τύπος                          | Σημείο εισόδου                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` μη ορισμένο                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` ορισμένο, `PushMode` μη ορισμένο ή `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` ορισμένο, `PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

Το `fordefi.New` κάνει dispatch ανάλογα με το config και επιστρέφει ένα `core.SolanaSigner`·
τα `fordefi.NewBlackBox`, `fordefi.NewNativeAuto` και `fordefi.NewNativeManual`
επιστρέφουν τον συγκεκριμένο τύπο και απορρίπτουν τα configs των άλλων τρόπων λειτουργίας. Τα αιτήματα API
πιστοποιούνται με υπογραφή αιτήματος ECDSA P-256: δώστε ακριβώς ένα από τα
`PrivateKeyPEM` ή `RequestSigner`, ώστε το κλειδί να παραμένει σε KMS/HSM.

**Λειτουργία native auto**: το Fordefi μπορεί να αντικαταστήσει το blockhash και τα τέλη και στη συνέχεια υπογράφει και
κάνει broadcast. Δέχεται μόνο μη υπογεγραμμένη συναλλαγή της οποίας ο μοναδικός απαιτούμενος signer
είναι το vault.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**Λειτουργία native manual**: ορίστε `PushMode: fordefi.PushModeManual`. Το Fordefi ξαναγράφει
το μήνυμα (πρόσφατο blockhash, εντολές τελών Compute Budget) και το υπογράφει
χωρίς broadcast. Το `ModifyAndSignTransaction` αντικαθιστά το `tx` με τη
συναλλαγή που υπέγραψε το Fordefi: συνεχίστε πάντα από αυτήν. Το Fordefi πρέπει να είναι ο fee
payer και πρέπει να υπογράψει πριν από οποιονδήποτε άλλο απαιτούμενο signer, αφού η αναδιατύπωση ακυρώνει
τις υπάρχουσες υπογραφές. Η αναδιατύπωση δεν παρέχεται ως diff, γι' αυτό ελέγξτε το αποτέλεσμα πριν
κάνετε broadcast.

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**Λειτουργία black box**: αφήστε το `Chain` μη ορισμένο. Το Fordefi υπογράφει ακριβώς τα bytes του μηνύματός σας
και δεν κάνει broadcast. Χρησιμοποιήστε την με ένα vault Fordefi black box.

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## Γιατί δεν υπάρχει ενιαίο πακέτο (umbrella)

Η Rust διαθέτει ένα enum `Signer` και η TypeScript το `createKeychainSigner`· η Go
σκόπιμα δεν έχει κανένα από τα δύο. Η Go δεν εξαλείφει νεκρό κώδικα (dead-code elimination) πέρα από ένα runtime
dispatch switch, οπότε ένα umbrella πακέτο θα έβαζε το vendor SDK κάθε backend (AWS, GCP
και τα υπόλοιπα) στο build κάθε καταναλωτή. Η εισαγωγή του πακέτου backend που
χρειάζεστε είναι ο επιλογέας. Για να επιλέξετε backend κατά το runtime, γράψτε το switch στον δικό σας
κώδικα μόνο για τα backends που υποστηρίζετε και κρατήστε το αποτέλεσμα ως
`core.SolanaSigner`.

## Διαχείριση σφαλμάτων

Κάθε σφάλμα είναι ένα `*core.SignerError` με σταθερό `Code` (`CodeConfigError`,
`CodeHTTPError`, `CodeRemoteAPIError`, `CodeSigningFailed`,
`CodeNotInitialized`, `CodeBroadcastUnconfirmed` και άλλα). Το `Error()` επιστρέφει
μόνο ένα σταθερό μήνυμα ανά κωδικό, ποτέ υλικό κλειδιών ή ακατέργαστες απαντήσεις παρόχου.
Κάντε match με `errors.As`, `errors.Is(err, &core.SignerError{Code: ...})` ή
`core.CodeOf(err)`.

Στο Crossmint και στη λειτουργία Fordefi native auto, μια αποτυχία δεν σημαίνει ότι δεν
καταχωρίστηκε τίποτα. Όταν ο πάροχος μπορεί να έχει αποδεχτεί τη συναλλαγή, ο κωδικός είναι
`core.CodeBroadcastUnconfirmed` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
Το `ProviderTxID` ορίζεται όταν η δημιουργία έγινε αποδεκτή και το `IdempotencyKey` φέρει
το κλειδί που προκύπτει από το μήνυμα. Η επαναποστολή της πανομοιότυπης (byte-identical) συναλλαγής είναι
ασφαλής· μια συναλλαγή που ξαναχτίστηκε (για παράδειγμα με νέο blockhash) αποτελεί νέα μεταφορά.
Το `core.SignAndSendTransaction` αναφέρει επίσης αυτόν τον κωδικό όταν η συνάρτηση αποστολής σας
αποτύχει, με την υπογραφή του fee payer στο `TransactionSignature`. Το Fireblocks
PROGRAM_CALL είναι μόνο για υπογραφή και δεν στέλνει κλειδί· αναφέρει αυτόν τον κωδικό μόνο όταν ένα
poll δείξει ότι το Fireblocks έκανε broadcast παρ' όλα αυτά.

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

## Προσθήκη προσαρμοσμένων signers

Υλοποιήστε το `core.SolanaSigner` συν ακριβώς μία διεπαφή δυνατοτήτων και μην προσθέσετε καμία
μέθοδο που το backend σας δεν μπορεί να τηρήσει: οι καλούντες εντοπίζουν τη δυνατότητα με type assertion.
Δείτε τον [οδηγό Adding Signers](/docs/tools/keychain/adding-signers) για να ενσωματώσετε
πρόσθετες υπηρεσίες διαχείρισης κλειδιών.
