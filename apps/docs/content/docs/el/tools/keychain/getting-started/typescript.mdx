## Εγκατάσταση

Εγκαταστήστε το ενιαίο πακέτο ή μεμονωμένους υπογράφοντες ανάλογα με τις ανάγκες
σας:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Απαιτεί `@solana/kit` 8.1 ή νεότερη έκδοση. Οι συναλλαγές v1
(`createTransactionMessage({ version: 1 })`) υποστηρίζονται, με εξαίρεση το Fireblocks
με `useProgramCall: true`, το οποίο δέχεται μόνο legacy και v0.

## Βασική Χρήση

### Ενιαίο Factory (Συνιστάται για εφαρμογές που θέλουν να υποστηρίζουν πολλαπλούς υπογράφοντες)

Χρησιμοποιήστε το `createKeychainSigner` με μια διακριτή διαμόρφωση για να
δημιουργήσετε οποιοδήποτε backend:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Ή εγκαταστήστε ένα μεμονωμένο πακέτο υπογράφοντος για μικρότερο footprint
εξαρτήσεων:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Χρήση με Μηνύματα Συναλλαγών

Κάθε backend, εκτός από το Crossmint και τη native λειτουργία του Fordefi, επιστρέφει έναν
`SolanaTransactionSigner`, ο οποίος είναι ένας Kit `TransactionPartialSigner` και λειτουργεί
με τους βοηθητικούς μηχανισμούς partial-signer του `@solana/signers` που ακολουθούν. Τα backend με managed broadcast
περιγράφονται στην ενότητα [Δυνατότητες Signer](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Υπογραφή και αποστολή με οποιονδήποτε Signer

Η `signAndSendTransaction` από το `@solana/keychain-core` καταχωρεί μια συναλλαγή στο
blockchain ανεξάρτητα από τη μορφή του signer. Οι sending signers κάνουν broadcast μέσω του
παρόχου τους· κάθε άλλη μορφή χρησιμοποιεί τη `sendTransaction` που περνάτε εσείς (το core δεν έχει
εξάρτηση από RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Χρήση με Kit Client (πρόσθετο keychainSigner)

Το `@solana/keychain-kit-plugin` εγκαθιστά απευθείας ένα keychain signer σε έναν
[Kit client](https://github.com/anza-xyz/kit), συνδέοντάς το ως `payer` και
`identity`, ώστε να παρακάμψετε τη χειροκίνητη ρύθμιση `pipe` που φαίνεται
παραπάνω:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Το plugin δέχεται την ίδια config με ετικέτα backend όπως η `createKeychainSigner`,
εκτός από το Crossmint και τη native λειτουργία του Fordefi (με ορισμένο το `chain`). Αυτά τα backend τροποποιούν
τη συναλλαγή από την πλευρά του server, επομένως δεν μπορούν να λειτουργήσουν ως `payer` ή
`identity` του client· το plugin τα απορρίπτει κατά τη μεταγλώττιση και κατά το runtime. Συμπεριλαμβάνεται μόνο το
backend στο οποίο γίνεται η δρομολόγηση (τα πακέτα των backend φορτώνονται μέσω δυναμικού
`import()`).

Χρησιμοποιήστε `keychainPayer` ή `keychainIdentity` για να ορίσετε έναν μόνο
ρόλο και να συνδυάσετε backends σε έναν μόνο client:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Έχετε ήδη έναν `SolanaTransactionSigner`; Είναι έγκυρος Kit
`TransactionPartialSigner`, οπότε μπορείτε να τον εγκαταστήσετε με το
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
αντί γι' αυτό (`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Ακύρωση και μη επιβεβαιωμένα broadcasts

Οι `signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` και
`signMessages` δέχονται όλες το `{ abortSignal }` ως δεύτερο όρισμα. Η ακύρωση
διακόπτει την αναμονή· δεν αναιρεί εργασία που έχει ήδη γίνει δεκτή από τον πάροχο.

Στο Crossmint και στη native auto λειτουργία του Fordefi, μια αποτυχία δεν σημαίνει ότι δεν
καταχωρήθηκε τίποτα. Όταν ο πάροχος ενδέχεται να έχει δεχθεί τη συναλλαγή, ο κωδικός σφάλματος είναι
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
Το `context.providerTransactionId` ορίζεται όταν η δημιουργία έγινε δεκτή, και το
`context.idempotencyKey` περιέχει το κλειδί που προκύπτει από το μήνυμα. Η εκ νέου αποστολή της
πανομοιότυπης (byte-identical) συναλλαγής είναι ασφαλής· μια συναλλαγή που ξαναχτίστηκε (για παράδειγμα με νέο
blockhash) αποτελεί νέα μεταφορά. Οι `providerMayHaveAccepted(error)` και
`providerStatus(error)` από το `@solana/keychain-core` βοηθούν στην ταξινόμηση του σφάλματος.
Συμφωνήστε την κατάσταση με τον πάροχο πριν επαναλάβετε την προσπάθεια.

### Fordefi

Το Fordefi διαθέτει τρεις λειτουργίες υπογραφής, οι οποίες καθορίζονται κατά τη δημιουργία από τα `chain` και
`pushMode`. Κάθε λειτουργία εκθέτει ακριβώς μία μέθοδο συναλλαγής, και και οι τρεις υπογράφουν
μηνύματα:

| Λειτουργία          | Config                                      | Τύπος                        | Μέθοδος                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Black box     | `chain` μη ορισμένο                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Native auto   | `chain` ορισμένο, `pushMode` παραλείπεται ή `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Native manual | `chain` ορισμένο, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

Τα αιτήματα API πιστοποιούνται με υπογραφή αιτήματος ECDSA P-256: δώστε το
κλειδί υπογραφής ως `privateKeyPem`, ή κρατήστε το σε KMS/HSM περνώντας έναν
`requestSigner`.

**Native auto λειτουργία** (προτείνεται για χρήση on-chain): ορίστε το `chain`, και το Fordefi
υπογράφει και κάνει broadcast τη συναλλαγή μόνο του. Επειδή το Fordefi μπορεί να αντικαταστήσει το
blockhash ή τα τέλη πριν από την υπογραφή, ο signer είναι ένας Kit
`TransactionSendingSigner`: χρησιμοποιήστε τον με το
`signAndSendTransactionMessageWithSigners`, όχι με τη ροή partial-signer που φαίνεται
παραπάνω. Η native auto λειτουργία δέχεται μόνο μη υπογεγραμμένη συναλλαγή της οποίας ο μοναδικός απαιτούμενος
signer είναι το vault, και δεν μπορεί να χρησιμοποιηθεί με το `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Native manual λειτουργία**: ορίστε το `chain` και `pushMode: "manual"`. Το Fordefi τροποποιεί
το μήνυμα (πρόσφατο blockhash, εντολές τελών Compute Budget) και το υπογράφει,
αλλά δεν κάνει broadcast. Η `modifyAndSignTransactions()` επιστρέφει τη συναλλαγή που
υπέγραψε το Fordefi, η οποία αντικαθιστά αυτήν που υποβάλατε: συνεχίστε πάντα από τη
συναλλαγή που επιστράφηκε. Το Fordefi πρέπει να είναι ο fee payer και πρέπει να υπογράψει πριν από
οποιονδήποτε άλλο απαιτούμενο signer. Η τροποποίηση δεν παρουσιάζεται ως diff, οπότε ελέγξτε το αποτέλεσμα πριν
κάνετε broadcast.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Λειτουργία Black Box**: παραλείψτε το `chain`. Το Fordefi υπογράφει ανεπεξέργαστα bytes και δεν μεταδίδει· εσείς συναρμολογείτε και υποβάλλετε τη συναλλαγή μόνοι σας. Χρησιμοποιήστε το με ένα θησαυροφυλάκιο black box του Fordefi.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Δυνατότητες Signer

Το `@solana/keychain-core` ορίζει μία διεπαφή για κάθε μορφή Kit signer. Κάθε μία προσθέτει
τη μέθοδο `isAvailable(): Promise<boolean>` στην αντίστοιχη διεπαφή του `@solana/signers`:

- `SolanaTransactionSigner` (Kit `TransactionPartialSigner`): επιστρέφει υπογραφές
  για μια συναλλαγή που κατέχετε.
- `SolanaModifyingSigner` (Kit `TransactionModifyingSigner`): τροποποιεί τη
  συναλλαγή, την υπογράφει και επιστρέφει τη νέα συναλλαγή χωρίς να κάνει broadcast.
- `SolanaSendingSigner` (Kit `TransactionSendingSigner`): υπογράφει και κάνει broadcast
  μέσω του παρόχου του.
- `SolanaMessageSigner` (Kit `MessagePartialSigner`): υπογράφει μηνύματα off-chain.
  Είναι ξεχωριστή από τις μορφές συναλλαγών.

Το `SolanaSigner` είναι η ένωση (union) των τριών μορφών συναλλαγών. Ο τύπος επιστροφής κάθε factory
καθορίζει την ακριβή μορφή του backend του. Όταν η config είναι γνωστή μόνο κατά το
runtime, περιορίστε τον τύπο με τα `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` ή `isSolanaMessageSigner`. Η `signerCapabilities(signer)`
επιστρέφει και τις τέσσερις ταυτόχρονα.

| Backend                                                                                                     | Μορφή                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (black box) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (χωρίς υπογραφή μηνυμάτων)  |
| fordefi (native manual)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (native auto)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (χωρίς υπογραφή μηνυμάτων)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Δημιουργία Προσαρμοσμένων Signers

Υλοποιήστε τις διεπαφές δυνατοτήτων που υποστηρίζει το backend σας:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Υλοποιήστε μόνο ό,τι υποστηρίζει το backend σας. Το Kit ταξινομεί τους signers ανάλογα με το ποιες
μέθοδοι υπάρχουν, γι' αυτό μην προσθέτετε ποτέ μέθοδο που απλώς κάνει throw.

Δείτε τον [οδηγό Adding Signers](/docs/tools/keychain/adding-signers) για να
ενσωματώσετε πρόσθετες υπηρεσίες διαχείρισης κλειδιών.
