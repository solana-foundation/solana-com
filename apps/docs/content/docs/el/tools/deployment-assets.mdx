description: Προετοιμασία του build του προγράμματός σας για ανάπτυξη στο Mainnet
---

Πριν αναπτύξετε την εφαρμογή σας στο Mainnet, βεβαιωθείτε ότι έχετε τα εξής:

- Το αρχείο ELF του προγράμματος - συνήθως το αποτέλεσμα της εντολής `anchor build` ή
  `cargo-build-sbf`, που τελειώνει σε `.so`
- Το keypair του προγράμματος - Ένα αρχείο JSON που περιέχει έναν πίνακα ακεραίων

Σε αυτή την ενότητα θα περιγράψουμε πού θα βρείτε αυτά τα στοιχεία και πώς να
τα προετοιμάσετε.

## Προετοιμασία του αρχείου ELF

Το αρχείο ELF περιέχει τον μεταγλωττισμένο bytecode, πληροφορίες για τη διάταξη της μνήμης και
μεταδεδομένα που απαιτούνται ώστε η εικονική μηχανή του Solana (SVM) να κατανοήσει πώς να φορτώσει
και να εκτελέσει το πρόγραμμά σας. Το αρχείο ELF δημιουργείται κατά τη μεταγλώττιση του πηγαίου κώδικα.

Για να δημιουργήσετε το αρχείο ELF, μπορείτε να εκτελέσετε την ακόλουθη εντολή για το Anchor:

```bash
anchor build
```

ή την ακόλουθη για άλλα frameworks:

```bash
cargo build-sbf
```

Στη συνέχεια, μπορείτε να βρείτε το αρχείο ELF σε έναν κατάλογο όπως
`target/deploy/<PROGRAM_NAME>.so`.

Το πρόγραμμά σας είναι έτοιμο όταν το αρχείο ELF έχει μεταγλωττιστεί σε
[sBPFv3](https://www.anza.xyz/blog/migrating-solana-programs-to-sbpfv3). Για να
ελέγξετε το πρόγραμμά σας, μπορείτε να εκτελέσετε την ακόλουθη εντολή σε Linux:

```bash
readelf -h target/deploy/<PROGRAM_NAME>.so | grep Flags:
```

Και τις ακόλουθες εντολές σε macOS:

```bash
# brew install llvm
$(brew --prefix llvm)/bin/llvm-readelf -h target/deploy/<PROGRAM_NAME>.so | grep Flags:
```

Αν δείτε αποτέλεσμα όπως το παρακάτω, το πρόγραμμά σας είναι έτοιμο:

```
  Flags:                             0x3
```

Αν όχι, ακολουθήστε τον οδηγό μετάβασης που υπάρχει
[εδώ](https://solana.com/upgrades/sbpfv3-programs).

## Προετοιμασία της διεύθυνσης του προγράμματός σας

Η διεύθυνση του προγράμματός σας είναι το αναγνωριστικό προγράμματος (program ID) που θα χρησιμοποιείτε για να καλείτε τις εντολές
του προγράμματός σας. Μπορείτε είτε 1) να χρησιμοποιήσετε το keypair προγράμματος που δημιουργήθηκε κατά το
build, 2) να παράγετε (grind) ένα νέο keypair του οποίου η διεύθυνση ξεκινά με ένα προσαρμοσμένο πρόθεμα, είτε 3)
να παράγετε τη διεύθυνση ενός λογαριασμού από μια βασική διεύθυνση και ένα seed. Οι δύο πρώτες επιλογές
παράγουν ένα keypair που μπορεί να υπογράφει για το program account. Ένας λογαριασμός που δημιουργείται με
seed δεν έχει δικό του ιδιωτικό κλειδί· τον ελέγχει ο βασικός λογαριασμός.

### Χρήση του keypair που δημιουργήθηκε

Από προεπιλογή, οι εντολές `anchor build` και `cargo build-sbf` τοποθετούν το keypair του προγράμματος στη διαδρομή:

```text
target/deploy/<PROGRAM_NAME>-keypair.json
```

Δημιουργήστε αντίγραφο ασφαλείας αυτού του αρχείου πριν καθαρίσετε τον κατάλογο του build. Όποιος έχει πρόσβαση στο
keypair μπορεί να υπογράψει ως το program account, γι' αυτό μην το κάνετε commit στον έλεγχο εκδόσεων.

### Παραγωγή (grind) ενός keypair με προσαρμοσμένο πρόθεμα

Χρησιμοποιήστε το [`vanity`](https://github.com/cavemanloverboy/vanity) για να αναζητήσετε ένα
keypair Ed25519 του οποίου το δημόσιο κλειδί ξεκινά με συγκεκριμένο πρόθεμα base58. Εγκαταστήστε
την έκδοση για CPU από το crates.io:

```bash
cargo install vanity
```

Το έργο παρέχει επίσης builds CUDA, Metal και OpenCL για αναζητήσεις με επιτάχυνση GPU.
Δείτε τις οδηγίες εγκατάστασης του `vanity` για τις απαιτήσεις
κάθε backend.

```bash
vanity grind-keypair --pattern Acme...
```

Όταν βρει αντιστοιχία, το `vanity` εκτυπώνει το δημόσιο κλειδί, τον ιδιωτικό σπόρο σε δεκαεξαδική μορφή
και έναν πίνακα JSON keypair συμβατό με το Solana. Αποθηκεύστε το αρχείο JSON σε μια ασφαλή
τοποθεσία και στη συνέχεια επιβεβαιώστε ότι περιέχει το αναμενόμενο δημόσιο κλειδί:

```bash
solana-keygen pubkey path/to/keypair.json
```

Αντιμετωπίστε την έξοδο της εντολής και το αποθηκευμένο αρχείο JSON ως υλικό ιδιωτικού κλειδιού.

### Δημιουργία λογαριασμού με seed

Για ταχύτερη αναζήτηση, η εντολή `vanity grind` αναζητά συμβολοσειρές seed για το
`CreateAccountWithSeed` αντί να παράγει keypairs Ed25519. Δώστε το
δημόσιο κλειδί του βασικού λογαριασμού που θα εγκρίνει τη δημιουργία, τον ιδιοκτήτη του λογαριασμού
και το πρόθεμα προς αναζήτηση. Για ένα αναβαθμίσιμο program account, χρησιμοποιήστε τον
αναβαθμίσιμο φορτωτή BPF ως ιδιοκτήτη:

```bash
vanity grind \
  --base <BASE_ACCOUNT_PUBKEY> \
  --owner BPFLoaderUpgradeab1e11111111111111111111111 \
  --pattern Acme...
```

Το αποτέλεσμα περιλαμβάνει την παραγόμενη διεύθυνση και μια συμβολοσειρά seed. Επαληθεύστε τα πριν
δημιουργήσετε τον λογαριασμό:

```bash
vanity verify \
  --base <BASE_ACCOUNT_PUBKEY> \
  --owner BPFLoaderUpgradeab1e11111111111111111111111 \
  --seed <SEED>
```

Χρησιμοποιήστε την ίδια βασική διεύθυνση, το ίδιο seed και τον ίδιο ιδιοκτήτη για να παράγετε τη διεύθυνση με
το `Pubkey::create_with_seed` και, στη συνέχεια, υποβάλετε μια εντολή `create_account_with_seed` του System Program.
Ο βασικός λογαριασμός και ο λογαριασμός χρηματοδότησης
πρέπει να υπογράψουν τη συναλλαγή. Επειδή ο παραγόμενος λογαριασμός δεν έχει αυτόνομο
keypair, αυτή η επιλογή απαιτεί μια ροή δημιουργίας λογαριασμού και ανάπτυξης που χρησιμοποιεί
τον βασικό λογαριασμό αντί για αρχείο keypair προγράμματος.

### Ενημέρωση της διεύθυνσης του προγράμματος στον πηγαίο κώδικα

Αφού επιλέξετε ένα keypair ή έναν λογαριασμό με seed, χρησιμοποιήστε τη δημόσια διεύθυνσή του ως
program ID παντού όπου το έργο το δηλώνει. Αν ο πηγαίος κώδικας εξακολουθεί να περιέχει την
παλιά διεύθυνση, οι clients μπορεί να στείλουν εντολές σε λάθος πρόγραμμα και οι έλεγχοι ID του runtime
μπορεί να αποτύχουν.

Σε ένα workspace Anchor, ενημερώστε τόσο την καταχώριση του προγράμματος στο βασικό `Anchor.toml`
όσο και την κλήση `declare_id!` στο `programs/<PROGRAM_NAME>/src/lib.rs`. Το
κλειδί κάτω από το `[programs.<CLUSTER>]` είναι το όνομα του προγράμματος στο workspace. Ενημερώστε κάθε
πίνακα cluster στον οποίο σκοπεύετε να χρησιμοποιήσετε τη νέα διεύθυνση· το παρακάτω παράδειγμα ενημερώνει το
Mainnet.

Στο Anchor.toml:

```diff
 [programs.mainnet]
-my_program = "<OLD_PROGRAM_ID>"
+my_program = "<NEW_PROGRAM_ID>"
```

Στο `programs/<your_program>/lib.rs`:

```diff
-declare_id!("<OLD_PROGRAM_ID>");
+declare_id!("<NEW_PROGRAM_ID>");
```

Το Pinocchio δεν χρησιμοποιεί το `Anchor.toml`. Ενημερώστε την κλήση `declare_id!` στο
`src/lib.rs` του crate του προγράμματος. Τα τρέχοντα έργα Pinocchio εισάγουν το macro από το
`pinocchio::address`.

Το Quasar δηλώνει επίσης τη διεύθυνση στο `src/lib.rs` του crate του onchain προγράμματος και
δεν χρησιμοποιεί το `Anchor.toml`. Το macro `declare_id!` είναι διαθέσιμο μέσω του
`quasar_lang::prelude::*`.

Κάντε ξανά build το πρόγραμμα και αναδημιουργήστε τυχόν αρχεία IDL ή client μετά την αλλαγή
της διεύθυνσης. Αναζητήστε επίσης στα scripts ανάπτυξης, στα τεστ και στις ρυθμίσεις της εφαρμογής
το παλιό program ID και αντικαταστήστε τυχόν σταθερές αναφορές (hardcoded).
