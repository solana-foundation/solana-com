Agentowe płatności pozwalają oprogramowaniu poznać cenę, autoryzować płatność i otrzymać
zasób w ramach tego samego przepływu HTTP. Agent może zapłacić za zapytanie o dane, inferencję modelu
lub wywołanie narzędzia bez wcześniejszego zakładania konta rozliczeniowego i kopiowania
klucza API.

## Wspólny przepływ płatności

MPP i x402 używają różnych nagłówków i modeli danych, ale ich podstawowy przepływ HTTP jest
podobny:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP i x402

Oba protokoły mogą rozliczać płatności w stablecoinach na Solanie. Wybierz ten, który lepiej pasuje do
modelu płatności i interoperacyjności potrzebnych Twojej usłudze, a nie kieruj się wyłącznie wspólnym kodem statusu `402`.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Wezwanie do zapłaty (challenge)               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| Autoryzacja klienta    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Potwierdzenie                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Modele płatności na Solanie   | Jednorazowe intencje `charge` oraz limitowane, rozliczane według zużycia intencje `session`           | Schematy, takie jak `exact` i `upto`; obsługa zależy od sieci i klienta |
| Architektura rozliczeń | Walidacja po stronie serwera lub opcjonalny przekaźnik (relay) albo brama (gateway)                | Serwer zasobów z lokalną weryfikacją lub facilitator                 |
| Dobry punkt wyjścia     | API, które wymagają semantyki uwierzytelniania HTTP lub powtarzalnego pomiaru zużycia | Zasoby płatne za żądanie oraz istniejący klienci x402                      |

MPP to **Machine Payments Protocol**. Nie należy go mylić z **Model
Context Protocol (MCP)**. MCP udostępnia agentom narzędzia i zasoby, a MPP lub x402
mogą wymagać płatności, gdy agent wywołuje jedno z tych narzędzi.

<Callout type="info">
  Usługa może udostępniać więcej niż jeden protokół. Klient wybiera obsługiwaną
  przez siebie opcję płatności, a następnie używa pasujących nagłówków wezwania, autoryzacji i
  potwierdzenia w trakcie całej wymiany.
</Callout>
