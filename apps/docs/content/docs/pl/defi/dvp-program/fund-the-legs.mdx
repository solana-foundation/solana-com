Zasilenie to zwykły `TransferChecked` na escrow danej nogi, więc każdy portfel
lub system custody, który potrafi wysłać transfer tokenów, może zasilić nogę.
Klienta DvP wymaga tylko odczyt rekordu transakcji przed zasileniem. Program
sprawdza salda escrow wyłącznie w momencie rozliczenia; nic nie weryfikuje
transferu w chwili jego zaksięgowania, dlatego każda ze stron odczytuje rekord
transakcji przed wykonaniem transferu.

Ta strona stanowi kontynuację sekcji
[tworzenie transakcji](/docs/defi/dvp-program/create-a-trade); klient i sygnatariusze
pozostają ci sami.

## Zweryfikuj warunki

Utworzenie rekordu nie wymaga uprawnień, a adresy escrow wywodzą się wyłącznie
z rekordu i mint, nigdy z warunków. Transfer na escrow może więc trafić do
transakcji o warunkach, na które nigdy się nie zgodziłeś, w tym z miejscami
docelowymi rozliczenia, które przekierowują wpływy Twojej kontrahenta lub
kontrahenta na trzeci adres. Przed zasileniem odczytaj konto `SwapDvp` i
porównaj je z uzgodnioną transakcją.

`verifySwapDvp` w TypeScript oraz `verify::decode_swap_dvp_account` w Rust
potwierdzają, że konto należy do programu DvP, ma dokładnie 458 bajtów i
znajduje się pod adresem wynikającym z jego własnych pól (`fetchSwapDvpChecked`
wykonuje tylko dwie pierwsze kontrole). Zwykłe czytniki `fetchSwapDvp` i
`decodeSwapDvp` nie sprawdzają żadnej z nich. Kontrole stron, kwot, czasów i
miejsc docelowych wykonuje wywołujący, porównując je z uzgodnioną transakcją.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { unwrapOption } from "@solana/kit";
    import { verifySwapDvp } from "./dvp";

    const trade = await verifySwapDvp(client.rpc, swapDvp);
    const t = trade.data;

    const expectedAmountA = 1_000_000_000n;
    const expectedAmountB = 998_500_000n;
    const expectedEarliestSettlement: bigint | null = null; // as agreed
    const expectedExpiry = 1_798_761_600n; // as agreed, unix seconds

    if (
      t.userA !== userA ||
      t.userB !== userB ||
      t.mintA !== mintA ||
      t.mintB !== mintB ||
      t.settlementAuthority !== settlementAuthority ||
      t.tokenProgramA !== tokenProgramA ||
      t.tokenProgramB !== tokenProgramB ||
      t.amountA !== expectedAmountA ||
      t.amountB !== expectedAmountB ||
      unwrapOption(t.earliestSettlementTimestamp) !== expectedEarliestSettlement ||
      t.expiryTimestamp !== expectedExpiry ||
      t.userASettlementDestination !== userA ||
      t.userBSettlementDestination !== userB
    ) {
      throw new Error("Stored terms do not match the agreed trade; do not fund");
    }

    if (t.expiryTimestamp <= BigInt(Math.floor(Date.now() / 1000)) + 60n) {
      throw new Error("Trade expires too soon to fund safely");
    }
    ```

  </Tab>

  <Tab value="Rust">
    ```rust

    use solana_client::rpc_client::RpcClient;
    use solana_commitment_config::CommitmentConfig;

    let trade = decode_swap_dvp_account(&swap_dvp, &account)?;

    let expected_amount_a: u64 = 1_000_000_000;
    let expected_amount_b: u64 = 998_500_000;
    let expected_earliest_settlement: Option<i64> = None; // as agreed
    let expected_expiry: i64 = 1_798_761_600; // as agreed, unix seconds

    if trade.user_a != user_a
        || trade.user_b != user_b
        || trade.mint_a != mint_a
        || trade.mint_b != mint_b
        || trade.settlement_authority != settlement_authority
        || trade.token_program_a != token_program_a
        || trade.token_program_b != token_program_b
        || trade.amount_a != expected_amount_a
        || trade.amount_b != expected_amount_b
        || trade.earliest_settlement_timestamp != expected_earliest_settlement
        || trade.expiry_timestamp != expected_expiry
        || trade.user_a_settlement_destination != user_a
        || trade.user_b_settlement_destination != user_b
    {
        return Err("stored terms do not match the agreed trade; do not fund".into());
    }

    let now_seconds: i64 = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH)?
        .as_secs() as i64;
    if trade.expiry_timestamp <= now_seconds + 60 {
        return Err("trade expires too soon to fund safely".into());
    }
    ```

Jeśli rekord utworzył Twój kontrahent lub organ rozliczający, porównaj każde
pole z warunkami uzgodnionymi poza księgą. Jeśli utworzyłeś go samodzielnie,
ten odczyt potwierdza, że trafił do księgi tak, jak został wysłany.

## Transfer na escrow

Zasil nogę dokładnie uzgodnioną kwotą. Program ogranicza rozliczenie do
`amount_x` i zwraca ewentualną nadwyżkę stronie danej nogi, więc nadwyżka nie
przepada, ale powoduje dodatkowy transfer podczas rozliczenia i może się nie
powieść w przypadku niektórych transfer hooks (zob. uwagi poniżej).

Używaj `TransferChecked`, a nie niesprawdzanego `Transfer`. Mints Token-2022 z
rozszerzeniami zależnymi od mint account, takimi jak Pausable, odrzucają
transfer, który go nie zawiera, a mint z transfer hook wymaga, by konta hooka
zostały rozwiązane i dołączone tak samo jak przy każdym innym transferze tego
tokena.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    Strona nogi z aktywem, podpisująca jako `userASigner`, zasila escrow A:

    ```ts
    import {
      findAssociatedTokenPda,
      getTransferCheckedInstruction,
    } from "@solana-program/token-2022";

    const [userAAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: userA,
      tokenProgram: tokenProgramA,
    });
    const [userBAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: userB,
      tokenProgram: tokenProgramB,
    });

    const fundAssetLeg = getTransferCheckedInstruction({
      source: userAAtaA,
      mint: mintA,
      destination: escrowA,
      authority: userASigner,
      amount: t.amountA,
      decimals: 6,
    }, { programAddress: tokenProgramA });

    await client.sendTransaction([fundAssetLeg]);
    ```

    Strona nogi gotówkowej robi to samo dla escrow B, używając `userBAtaB`, `mintB`,
    `userBSigner`, `t.amountB` oraz `{ programAddress: tokenProgramB }`.

  </Tab>

  <Tab value="Rust">
    ```rust
    use spl_associated_token_account_client::address::get_associated_token_address_with_program_id;
    use spl_token_2022_interface::instruction::transfer_checked;

    let user_a_ata_a =
        get_associated_token_address_with_program_id(&user_a, &mint_a, &token_program_a);

    let fund_asset_leg = transfer_checked(
        &token_program_a,
        &user_a_ata_a,
        &mint_a,
        &escrow_a,
        &user_a,
        &[],
        trade.amount_a,
        6,
    )?;
    ```

    Strona nogi gotówkowej buduje tę samą instrukcję dla escrow B z użyciem `mint_b`,
    `user_b` i `trade.amount_b`.

  </Tab>
</Tabs>

Transfer zasilający widoczny na poziomie [`confirmed`](/docs/rpc#configuring-state-commitment)
może nadal zostać zastąpiony. Program odczytuje saldo escrow onchain w momencie
rozliczenia, więc Settle wysłany po transferze zasilającym, który nie został
zaksięgowany, kończy się błędem `LegNotFunded` i nic się nie przemieszcza;
kosztem jest nieudany Settle i ponowna próba. Uznaj nogę za zasiloną dopiero,
gdy jej transfer jest `finalized`.

## Uwagi

- **Nogi z wrapped SOL.** Program odczytuje saldo natywnego escrow po jego
  synchronizacji, więc lamports wysłane na escrow wrapped SOL zwykłym transferem
  systemowym są wliczane. Nigdy nie wysyłaj SOL na escrow dla żadnego innego mint:
  program nie może go zwrócić, a trafia on do osoby, która zamknie konto.
- **Mints z ograniczeniami.** W przypadku mint z Default Account State ustawionym na
  frozen escrow jest tworzone jako zamrożone, a transfer kończy się błędem, dopóki
  emitent go nie odmrozi lub nie dopuści. [Przegląd](/docs/defi/dvp-program#mint-configuration-constraints)
  opisuje współdziałanie z Token ACL.
- **Transfer hooks.** Zasilaj escrow z hookami dokładnie uzgodnioną kwotą. Jeśli
  nadwyżka wymusza zwrot podczas rozliczenia, zwrot ponownie używa kont hooka
  danej nogi z innym adresem docelowym i inną kwotą, co niektóre hooki odrzucają.
  Sposób naprawy to Reclaim, ponowne zasilenie dokładną kwotą i ponowne
  rozliczenie.
- **Zasilenie po wygaśnięciu.** Nic nie blokuje transferu po `expiry_timestamp`.
  Transfer się zaksięguje, rozliczenie nie jest już możliwe, a strona nogi odzyskuje
  środki przez Reclaim, gdy transakcja jest otwarta, lub Recover po jej zamknięciu.
  Zobacz [cofnięcie transakcji](/docs/defi/dvp-program/unwind-a-trade).
- **Kto zasila pierwszy.** Program nie ustala kolejności obu nóg. Kolejność jest
  sprawą stron; każda ze stron może w dowolnym momencie przed rozliczeniem odzyskać
  własną nogę, chyba że mint authority (freeze, pause lub transfer hook) blokuje
  escrow.
