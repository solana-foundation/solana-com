`CreateDvp` zapisuje warunki transakcji i tworzy dwa konta escrow, które
strony następnie zasilą. Nie przenosi żadnych tokenów. Może go wysłać każdy,
dlatego rekord może pochodzić od kontrahenta, operatora podmiotu rozliczającego
lub osoby trzeciej, a każdy inny uczestnik weryfikuje zapisane warunki, zanim
na ich podstawie podejmie działanie (zob. [zasilenie nóg transakcji](/docs/defi/dvp-program/fund-the-legs)).

Fragmenty kodu korzystają bezpośrednio z wygenerowanego klienta i używają
adresów zastępczych, dzięki czemu widać, jakie konta i podpisujący są
zaangażowani. Dotyczą sieci devnet, w której program jest wdrożony pod tym
samym adresem co w mainnet-beta.

## Instalacja

Na dzień 2 października 2026 nie opublikowano żadnego pakietu z klientami DvP.
Oba klienty są generowane z IDL programu znajdującego się w repozytorium i
używane bezpośrednio ze źródeł.

Fragmenty kodu na kolejnych stronach kroków są ze sobą powiązane: każda strona

obiekty `TransactionSigner` odpowiednio dla płatnika rent, obu stron oraz
podmiotu rozliczającego, na przykład utworzone za pomocą
`createKeyPairSignerFromBytes`. Fragmenty w Rust budują instrukcje, a
podpisywanie i wysyłanie pozostawiają wywołującemu.

## Wyprowadzanie adresów

Rekord transakcji ma adres typu Program Derived Address, wyprowadzany na
podstawie podmiotu rozliczającego, obu stron, obu mintów oraz wartości nonce.
Każde konto escrow jest associated token account rekordu dla jednego z mintów.
Oba wyprowadzenia nie wymagają dostępu do sieci.

Dla każdej transakcji używaj losowej 64-bitowej wartości nonce. Ponieważ
tworzenie transakcji jest dostępne dla każdego (permissionless), przewidywalny
nonce pozwala osobie trzeciej zająć adres, którego miała użyć transakcja.
W TypeScript przekazuj nonce i kwoty jako `bigint`; wygenerowany klient odrzuca
`number`.

Przed uruchomieniem zastąp każdy symbol zastępczy `..._HERE` prawdziwym
adresem. `address()` waliduje base58 i zgłasza błąd dla symbolu zastępczego,
a `pubkey!` nie skompiluje się.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## Zapisywanie warunków

`CreateDvp` przyjmuje dwie kwoty w jednostkach bazowych, termin wygaśnięcia,
nonce oraz cztery pola opcjonalne: nieprzezroczysty identyfikator referencyjny
o długości do 64 bajtów, miejsce docelowe rozliczenia dla każdej ze stron oraz
najwcześniejszy czas rozliczenia (zob. Uwagi). Miejsce docelowe to adres, na
który trafiają środki danej strony przy rozliczeniu, na przykład portfel
depozytowy powiernika; domyślnie jest to własny adres strony i nie można go
zmienić po utworzeniu rekordu. Zwroty i odzyskiwanie środków zawsze trafiają na
własne token account strony dla mintu danej nogi, nigdy na miejsce docelowe,
niezależnie od tego, kto zasilił konto escrow.

Płatnik pokrywa rent dla rekordu, tombstone nonce’a oraz obu kont escrow.
Przy zamknięciu ten rent trafia do osoby podpisującej instrukcję zamknięcia,
a nie z powrotem do płatnika. Tombstone nigdy nie jest zamykany, więc każda
transakcja pozostawia niewielkie trwałe saldo. Planując budżet SOL płatnika,
wyznaczaj kwoty rent za pomocą metody RPC `getMinimumBalanceForRentExemption`,
zamiast wpisywać je na stałe.

          programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
          seeds: ["nonce", getAddressEncoder().encode(swapDvp)],

      )[0],

`getAddressEncoder` z `@solana/kit` oraz `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS`

z wartościami domyślnymi.

## Uwagi

- **Wygaśnięcie.** Termin wygaśnięcia sprawdza tylko Settle. Reclaim, Cancel
  i Reject działają także po jego upływie, a depozyt, który trafi na konto po
  wygaśnięciu, może odzyskać strona danej nogi. Termin wygaśnięcia może
  przypadać najpóźniej rok po utworzeniu.
- **Czas to czas sieci.** Program odczytuje zegar onchain, który może się
  różnić od czasu rzeczywistego, czasem o dziesiątki sekund, i może skoczyć
  do przodu. Zostaw margines między terminem wygaśnięcia a planowanym czasem
  rozliczenia, unikaj zasilania i rozliczania w pobliżu obu granic i nie polegaj
  na terminie wygaśnięcia przy egzekwowaniu terminu z dokładnością do sekundy.
  README programu sugeruje zaplanowanie około minuty rozbieżności.
- **Najwcześniejsze rozliczenie.** Opcjonalne. Jeśli jest ustawione, Settle jest
  odrzucane przed tym czasem, a wartość nie może być późniejsza niż termin
  wygaśnięcia.
- **Kontrole przy tworzeniu.** Create kończy się błędem `PartyNotSignerCapable`,
  jeśli strona nie jest kontem należącym do System Program (wyklucza to multisig
  SPL Token), a także błędami `SettlementDestinationIsSwapDvp`, `SelfDvp`,
  `SameMint`, `ZeroAmount`, `SettlementAuthorityIsParty` lub
  `ExpiryNotInFuture`. Pełną listę znajdziesz w [tabeli błędów](/docs/defi/dvp-program#errors).
