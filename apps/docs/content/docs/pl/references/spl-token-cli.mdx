Interfejs wiersza poleceń `spl-token` tworzy mint i zarządza nimi, a także obsługuje
token accounts, uprawnienia (authorities), transfery oraz rozszerzenia Token-2022.

Ta dokumentacja odpowiada wersji
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
dołączonej do Agave v4.2.1. Uruchom `spl-token --version` i użyj
`<command> --help`, aby sprawdzić dokładne opcje dostępne w zainstalowanej wersji.

<Callout type="warn">
  Tworzenie mintów, transfery, zmiany uprawnień, spalanie tokenów, zamrażanie oraz zamykanie kont
  wysyłają transakcje. Przed uruchomieniem polecenia potwierdź klaster, token program, podpisującego i
  adresy. Zmiany w sieci mainnet dotyczą prawdziwych aktywów.
</Callout>

## Instalacja i pomoc

Pakiet wydania Agave CLI zawiera `spl-token`. Jeśli nie jest zainstalowany, użyj
opublikowanego crate'a Rusta:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Wyświetl pomoc na poziomie głównym lub konkretnego polecenia:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Opcje globalne

Umieszczaj opcje globalne przed poleceniem.

| Opcja                                       | Zastosowanie                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Wybiera adres URL RPC albo `mainnet-beta`, `testnet`, `devnet` lub `localhost`. |
| `-C, --config <PATH>`                        | Używa innego pliku konfiguracyjnego Solana CLI.                            |
| `--fee-payer <KEYPAIR>`                      | Wybiera konto, które płaci opłaty transakcyjne.                            |
| `-p, --program-id <ADDRESS>`                 | Używa jawnie podanego identyfikatora Token Program.                                         |
| `--program-2022`                             | Używa Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Zwraca `json` lub `json-compact` tam, gdzie jest to obsługiwane.                          |
| `--with-compute-unit-limit <UNITS>`          | Ustawia limit jednostek obliczeniowych transakcji.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Ustawia cenę priorytetową za jednostkę obliczeniową.                                  |
| `-v, --verbose`                              | Wyświetla dodatkowe dane wyjściowe.                                                   |
| `-V, --version`                              | Wyświetla zainstalowaną wersję CLI.                                          |

Domyślnym programem jest oryginalny Token Program. Użyj `--program-2022` dla
mintu lub konta Token-2022, także podczas jego odczytu. Polecenie kończy się błędem,
jeśli wybrany program nie jest właścicielem podanego adresu.

## Tworzenie i używanie tokena

Polecenia wypisują adresy utworzonych obiektów. Zapisz adres mintu zwrócony przez
`create-token`, aby użyć go w kolejnych poleceniach.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Kwoty są podawane w jednostkach UI tokena, z uwzględnieniem liczby miejsc dziesiętnych mintu. Polecenia takie jak
`transfer`, `burn` i `unwrap-sol` akceptują `ALL` tam, gdzie wskazuje to ich pomoc.

## Tworzenie mintu Token-2022

Rozszerzenia alokują dodatkowy stan mintu lub konta i zazwyczaj trzeba je wybrać podczas
tworzenia mintu. Poniższy przykład tworzy mint z sześcioma miejscami dziesiętnymi i obsługą
osadzonych metadanych:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Typowe opcje rozszerzeń `create-token` obejmują:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` i `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` lub `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` wraz z
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Łącz tylko te rozszerzenia, które program Token-2022 dopuszcza jednocześnie. Zapoznaj się z
odpowiednim [przewodnikiem po rozszerzeniach Token-2022](/docs/tokens/extensions) przed utworzeniem
nieodwracalnej konfiguracji mintu.

## Zarządzanie uprawnieniami i delegatami

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` obsługuje uprawnienia typu mint, freeze, owner, close oraz uprawnienia
specyficzne dla rozszerzeń. Usunięcie uprawnienia za pomocą `--disable` jest trwałe, jeśli żaden
inny mechanizm programu nie może go przywrócić.

## Zamrażanie, spalanie i zamykanie

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` zmniejsza zarówno saldo konta, jak i całkowitą podaż. `close` zwraca
pozostałe lamports konta skonfigurowanemu odbiorcy; nie odzyskuje spalonych
tokenów.

## Opakowywanie i rozpakowywanie SOL

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Użyj `sync-native` po bezpośrednim przesłaniu lamports na token account z wrapped SOL,
aby ilość tokenów na nim odpowiadała znajdującym się na nim lamports.

## Podpisywanie multisig

Utwórz multisig M-of-N Token Program z maksymalnie 11 członkami:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

W przypadku transakcji kontrolowanej przez ten multisig przekaż adres multisig jako
odpowiednie uprawnienie (authority) i podaj keypairs członków za pomocą powtarzanych
wartości `--multisig-signer`. Sprawdź pomoc docelowego polecenia, ponieważ jego główna
flaga uprawnienia różni się w zależności od operacji.

## Salda poufne

Polecenia sald poufnych wymagają mintu Token-2022 skonfigurowanego pod
transfery poufne oraz skonfigurowanego konta odbiorcy.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Dla `configure-confidential-transfer-account` i `apply-pending-balance` podaj
albo `--address <TOKEN_ACCOUNT_ADDRESS>`, albo pozycyjny `<MINT_ADDRESS>`, ale
nie oba naraz. Forma pozycyjna używa associated token account właściciela. Wpłata i
wypłata zawsze przyjmują mint i akceptują `--address`, aby zastąpić to domyślne
konto.

Użyj `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits` i `disable-non-confidential-credits`, aby
kontrolować, jakie wpłaty akceptuje konto. Te ustawienia wpływają na prywatność
konta i zgodność płatności; sprawdź konto przed ich zmianą.

## Ustrukturyzowane i offline'owe podpisywanie

Używaj ustrukturyzowanych danych wyjściowych zamiast parsowania tekstu wyświetlanego:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Polecenia tworzące transakcje zwykle obsługują `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce` i `--nonce-authority`. Dokładne
dane wejściowe w trybie offline zależą od polecenia, liczby miejsc dziesiętnych mintu i konfiguracji uprawnień,
dlatego wygeneruj niepodpisaną wiadomość zgodnie z instrukcjami `--help` danego polecenia i
zweryfikuj każdy adres przed zebraniem podpisów.
