Interfejs wiersza poleceń `solana` konfiguruje połączenie z klastrem, odczytuje
stan sieci, wysyła SOL, zarządza trwałymi nonce, wdraża programy oraz obsługuje
konta stake i konta głosowania.

Ta dokumentacja odpowiada wersji
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Uruchom
`solana --version`, aby sprawdzić zainstalowaną wersję, i użyj `--help`, aby zobaczyć dokładne
opcje dostępne w tej wersji.

<Callout type="warn">
  Polecenia, które tworzą, przesyłają, autoryzują, wypłacają lub wdrażają, wysyłają
  transakcje. Przed ich uruchomieniem potwierdź skonfigurowany klaster i podpisującego.
  Tokeny w Devnet i Testnet nie mają wartości; polecenia w Mainnet używają prawdziwych SOL.
</Callout>

## Struktura poleceń

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Uzyskaj pomoc na dowolnym poziomie:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Opcje globalne

Opcje globalne można umieścić przed poleceniem. Pomoc dla konkretnego polecenia powtarza
opcje, które mają do niego zastosowanie.

| Opcja                          | Przeznaczenie                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Wybierz adres URL RPC albo `mainnet-beta`, `testnet`, `devnet` lub `localhost`.      |
| `--ws <URL>`                    | Zastąp punkt końcowy WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Wybierz plik keypair, `ASK`, stdin (`-`) lub obsługiwany adres URL podpisującego.          |
| `-C, --config <FILEPATH>`       | Użyj innego pliku konfiguracyjnego CLI.                                        |
| `--commitment <LEVEL>`          | Odczytuj na poziomie zatwierdzenia `processed`, `confirmed` lub `finalized`.                   |
| `--output <FORMAT>`             | Zwróć `json` lub `json-compact` tam, gdzie jest to obsługiwane.                               |
| `--skip-preflight`              | Wyślij bez symulacji RPC. Używaj tylko wtedy, gdy rozumiesz kompromis związany z możliwością niepowodzenia. |
| `--use-tpu-client`              | Wysyłaj transakcje przez klienta TPU.                                      |
| `--no-address-labels`           | Wyświetlaj adresy bez lokalnych etykiet.                                          |
| `--skip-seed-phrase-validation` | Zezwól na frazę odzyskiwania spoza angielskiej listy BIP39.                       |
| `-v, --verbose`                 | Pokaż dodatkowe dane wyjściowe polecenia.                                                |
| `-V, --version`                 | Wyświetl zainstalowaną wersję CLI.                                               |

## Konfiguracja CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

Konfiguracja zawiera adres URL RPC, adres URL WebSocket, domyślnego podpisującego oraz
poziom zatwierdzenia. Opcja wiersza poleceń zastępuje zapisaną wartość na czas danego wywołania.

## Typowe przepływy pracy z kontami i transakcjami

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` domyślnie przyjmuje SOL. Użyj `ALL` jako kwoty, aby przenieść dostępne
środki po odliczeniu opłat. Przykłady dotyczące tokenów znajdziesz w
[krótkim przewodniku po tokenach](/docs/tokens/quickstart).

## Przepływy pracy z programami

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Przekaż `--program-id <KEYPAIR_OR_ADDRESS>`, gdy wdrożenie musi użyć znanego
identyfikatora programu. `--final` sprawia, że nowe wdrożenie jest niezmienne; przeczytaj uważnie jego pomoc
przed użyciem, ponieważ upgrade authority nie można przywrócić.

## Przepływy pracy z trwałym nonce

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Użyj `authorize-nonce-account`, aby zmienić authority nonce, oraz `nonce-account`,
aby sprawdzić pełny stan konta. Transakcje korzystające z nonce akceptują również
`--nonce` i `--nonce-authority` w obsługiwanych poleceniach.

## Przepływy pracy ze stake

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

Dezaktywacja kończy się na granicy epoch i może potrwać dłużej niż jeden epoch.
Użyj `stakes`, `validators`, `stake-history` i `stake-minimum-delegation`, aby
sprawdzić stan klastra i delegacji przed przesłaniem zmian.

## Narzędzia adresowe

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

Seedy PDA używają formatu `PREFIX:VALUE`. Obsługiwane prefiksy to m.in. `string`, `pubkey`,
`hex`, `u8` oraz kodowania liczb całkowitych ze znakiem lub bez znaku o stałej szerokości, takie jak
`u64le`.

## Wiadomości off-chain i uzupełnianie poleceń w powłoce

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Dane wyjściowe skryptów

Użyj `--output json` lub `--output json-compact` tam, gdzie jest to obsługiwane, zamiast
parsowania danych wyjściowych przeznaczonych dla człowieka:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Nie każde polecenie obsługuje uporządkowane dane wyjściowe. Sprawdź pomoc polecenia, zanim
uzależnisz od nich automatyzację, i traktuj niezerowy kod wyjścia jako błąd.
