Ta sekcja zawiera kilka popularnych poleceń i przykładów, które pomogą Ci
rozpocząć pracę z [Anchor CLI](https://www.anchor-lang.com/docs).

<Steps>
<Step>

### Inicjalizacja projektu

Utwórz nowy projekt Anchor, uruchamiając poniższe polecenie. Spowoduje to utworzenie
nowego katalogu o nazwie projektu, który posłuży do zainicjalizowania nowego projektu
Anchor.

```terminal
$ anchor init <project-name>
```

Na przykład poniższe polecenie utworzy projekt o nazwie `my-project`. Katalog
`my-project` będzie zawierał modularny program w języku Rust oraz szablon
testów w Ruście wykorzystujący LiteSVM.

```terminal
$ anchor init my-project
```

Aby zamiast tego wygenerować szablon testów w TypeScript, wybierz go jawnie. Na
przykład użyj szablonu Mocha:

```terminal
$ anchor init my-project --test-template mocha
```

Szablony testów w TypeScript wymagają Node.js oraz menedżera pakietów JavaScript.

Następnie przejdź do katalogu projektu:

```terminal
$ cd <project-name>
```

Zobacz
[strukturę plików projektu](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) w Anchor.

</Step>
<Step>

### Budowanie programu

Aby zbudować swój projekt, uruchom następujące polecenie:

```terminal
$ anchor build
```

Skompilowany program znajdziesz w katalogu `/target/deploy`.

<Callout type="warn" title="Nie udało się zainstalować narzędzi platformy">
  Jeśli podczas kompilacji pojawi się informacja o nieprawidłowym katalogu platform-tools, zainstaluj ponownie narzędzia
  do kompilacji SBF, a następnie ponów kompilację:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Wdróż program

Aby wdrożyć swój projekt, uruchom następujące polecenie:

```terminal
$ anchor deploy
```

To polecenie wdraża Twój program do `cluster` określonego w pliku
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml).

</Step>
<Step>

### Przetestuj program

Aby przetestować swój projekt, uruchom następujące polecenie:

```terminal
$ anchor test
```

To polecenie buduje, wdraża i uruchamia testy Twojego projektu.

<Callout>
  Podczas korzystania z klastra `localnet` Anchor automatycznie uruchamia
  lokalnego validatora, wdraża program, uruchamia testy, a następnie zatrzymuje
  validatora.
</Callout>

<Callout type="warn" title="Błędy narzędzia do uruchamiania testów JavaScript">

Jeśli wybrano szablon testów JavaScript lub TypeScript, każdy z poniższych
błędów może oznaczać, że Node.js lub skonfigurowany menedżer pakietów nie jest
zainstalowany:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
