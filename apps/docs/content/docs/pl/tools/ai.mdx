# Praca z LLM i agentami na Solanie

Zanim przejdziemy do konkretnych narzędzi, poznajmy kluczowe elementy stosu
technologicznego do tworzenia AI:

## Zrozumienie stosu AI

1. **Duże modele językowe (LLM)**
   - Podstawowe modele AI (takie jak GPT-4, Claude czy Llama)
   - Przetwarzają i generują język naturalny
   - Zapewniają bazową inteligencję i zdolności rozumowania
   - Przykłady: GPT-4 od OpenAI, Claude od Anthropic, Llama od Meta

2. **Frameworki agentów (jak Eliza)**
   - Zbudowane na bazie LLM w celu tworzenia autonomicznych agentów
   - Zarządzają osobowościami i zachowaniami agentów
   - Obsługują pamięć i kontekst
   - Zapewniają integrację z wieloma platformami
   - Przykłady: Eliza, LangChain, AutoGPT, Vercel AI

3. **Zestawy narzędzi dla konkretnych dziedzin (jak Solana Agent Kit)**
   - Zbudowane dla konkretnych przypadków użycia (np. operacji blockchain)
   - Dostarczają gotowe narzędzia i integracje
   - Ukrywają złożoność techniczną
   - Gotowe do użycia funkcje blockchain
   - Przykłady: Solana Agent Kit, GOAT Toolkit

Można to porównać do następującego schematu:

- LLM to „mózg“, który potrafi rozumieć i generować język
- Frameworki agentów to „system operacyjny“ zarządzający zachowaniem AI
- Zestawy narzędzi dziedzinowych to „aplikacje“ nadające AI konkretne możliwości

# Budowanie agentów AI dla Solany

Ten przewodnik pokaże Ci, jak:

- Zbudować podstawowego agenta AI przy użyciu Solana Agent Kit od SendAI
- Stworzyć bota na Twitterze z frameworkiem Eliza
- Zrozumieć opcje integracji AI onchain
- Poznać opcje budowania zaawansowanych botów tradingowych

## Wprowadzenie do agentów AI na Solanie

Agenci AI na Solanie to autonomiczne programy, które mogą współdziałać z
blockchain przy użyciu przetwarzania języka naturalnego i uczenia maszynowego. Potrafią:

- Wykonywać transakcje
- Monitorować aktywność na blockchainie
- Współdziałać ze smart kontraktami
- Zapewniać pomoc użytkownikom
- Automatyzować złożone procesy

## Dostępne frameworki

Do budowania agentów AI na Solanie dostępnych jest kilka frameworków:

1. **Solana Agent Kit od SendAI**

- Zbiór narzędzi do budowania agentów na Solanie
- Kompatybilny z Eliza, Langchain i Vercel AI SDK
- Wbudowane narzędzia i biblioteki Solany
- Możliwości przetwarzania języka naturalnego
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Dokumentacja](https://docs.solanaagentkit.xyz/)

2. **Framework Eliza**

- Łączy warstwę danych, LLM i agentów oraz posiada dedykowany plugin dla Solany
- Rozszerzalna architektura agentów
- Łatwa integracja z istniejącymi projektami, może być używany np. do tworzenia
  botów na Twitterze (X), Telegramie lub Discordzie
- [Repozytorium GitHub](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Kompleksowy zestaw narzędzi deweloperskich
- Kompatybilność między łańcuchami bloków
- [Repozytorium GitHub](https://github.com/goat-sdk/goat)

4. **Framework Rig**

- Natywna implementacja w języku Rust
- Odpowiedni do wysokowydajnych botów tradingowych
- Może być łączony z zestawem narzędzi Listen.rs do integracji z Solaną, monitorowania
  transakcji i wysyłania transakcji przy użyciu np. pakietów Jito
- [Repozytorium GitHub](https://github.com/0xPlaygrounds/rig)
- [Repozytorium Listen.rs](https://github.com/piotrostr/listen)

Jeśli tworzysz framework AI, śmiało otwórz PR, aby dodać swój framework
do listy

### Utwórz skrypt agenta

Utwórz nowy plik o nazwie `agent.ts` z następującą zawartością:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## Budowanie z frameworkiem Eliza

[ElizaOS](https://github.com/elizaOS/eliza) (dawniej znany jako Ai16z) to
framework AI. Oznacza to, że łączy wiele aplikacji w jedną i
organizuje ich interakcje. Składa się z:

1. Różnych LLM do rozumienia użytkownika
2. Agentów blockchain z różnymi akcjami (np. wybijanie NFT)
3. Warstw danych do przechowywania stanu postaci między akcjami, używając np.
   Redis, PostgreSQL DB lub lokalnego magazynu
4. Różnych klientów, takich jak X, Telegram, Discord itp.

Łączy to wszystko w sposób umożliwiający tworzenie
„Postaci“, która może wchodzić w interakcje z użytkownikami lub działać autonomicznie. Postacie te są
zdefiniowane w pliku JSON, który określa, jakie akcje może wykonywać, jakiego LLM powinna
używać oraz różne prompty definiujące zachowanie postaci.

### Utwórz konfigurację postaci

Aby stworzyć nową postać, musimy utworzyć plik character.json. Gotowe
postacie znajdziesz w folderze characters projektu Eliza. Aby stworzyć nową
postać, możesz skopiować i zmodyfikować jedną z już istniejących lub

```json filename=characters/sol.character.json

    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {

            "model": "en_US-neural"
```

Ważną częścią są tutaj klienci i modelProvider. W naszym przypadku

Teraz, gdy konfiguracja jest gotowa, możemy uruchomić naszą postać:

```bash

```

To uruchomi agenta i możesz teraz wchodzić z nim w interakcje na Twitterze.
Postać będzie automatycznie publikować tweety co kilka godzin, a gdy
będziemy z nią rozmawiać, będzie w stanie wykonywać akcje Solany, takie jak
np. wybijanie NFT.

Tutaj możesz zobaczyć
[postać w akcji](https://x.com/solanadevhelper/status/1882222232656847143).


Jeśli Twój klient nie łączy się, upewnij się, że uruchamiasz agenta z flagą `--host`
i że port 3000 nie jest zajęty podczas uruchamiania klienta.

Więcej informacji znajdziesz w
[oficjalnej dokumentacji Elizy](https://elizaos.github.io/eliza/docs/quickstart/)

## Integracja agenta z programem onchain

Jeśli chcesz wykorzystać odpowiedź agenta w programie Solana, musisz użyć
oczekiwacza (oracle), który zapisuje dane odpowiedzi na koncie, które Twój program może odczytać.
Przykład modelu LLM, który transferuje tokeny do dowolnego użytkownika
poprawnie odpowiadającego na pytania, znajdziesz tutaj:

[Interakcja programu on-chain z LLM](https://github.com/GabrielePicco/super-smart-contracts)

To jest przykład programu on-chain integrującego się z wyrocznią LLM (AI)
w celu stworzenia interaktywnego agenta dystrybuującego tokeny o nazwie "Mar1o".

### Kluczowe funkcje

1. **Interakcja z agentem AI**
   - Użytkownicy mogą rozmawiać z Mar1o, aby spróbować zdobyć tokeny
   - Agent ocenia wiedzę użytkownika na temat Solany, aby zdecydować o liczbie tokenów
   - Odpowiedzi są w formacie JSON zawierającym tekst odpowiedzi i liczbę tokenów

2. **Zarządzanie tokenami**
   - Tworzy tokeny MAR1O z metadanymi
   - Może mintować od 0 do 10 000 tokenów na podstawie odpowiedzi AI
   - Używa PDA do zarządzania tokenami

### Opis przepływu programu

Oto jak działa ten program:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Demonstruje to, jak łączyć możliwości AI z mechaniką tokenów on-chain, aby
tworzyć interaktywne doświadczenia blockchain. Oto
[przykład na żywo](https://mar1o.xyz/), gdzie możesz spróbować przekonać Agenta,
aby przesłał Ci trochę tokenów.

## Zaawansowani agenci Rust do tradingu algorytmicznego

Jeśli chcesz pisać swoich agentów w języku Rust, możesz użyć
[frameworku Rig](https://github.com/0xPlaygrounds/rig) oraz
biblioteki [Listen.rs](https://github.com/piotrostr/listen).

Te dwa narzędzia dobrze ze sobą współpracują. Framework Rig zapewnia łatwy sposób
podłączenia się do modeli LLM, natomiast zestaw narzędzi Listen.rs dostarcza integrację z Solaną,
w tym monitorowanie transakcji i ich wysyłanie przy użyciu pakietów Jito
na przykład.

## Najlepsze praktyki

- Pamiętaj, że Twój agent posiada klucz prywatny i tym samym ma dostęp do środków w Twoim
  portfelu. Jeśli ktoś może rozmawiać z Twoim agentem i ma on np. akcję transferu,
  użytkownicy mogą prawdopodobnie nakłonić go do przetransferowania Twoich środków.
- Używaj płatnych [punktów końcowych RPC](https://solana.com/rpc). Publiczne punkty końcowe
  są zazwyczaj objęte limitami zapytań
- Monitoruj aktywność agenta i upewnij się, że nie wykonuje żadnych złośliwych działań
  ani nie zostaje do nich nakłoniony przez użytkowników z nim rozmawiających
- Implementuj opłaty priorytetowe i ponawianie transakcji w akcjach agenta, aby
  były realizowane nawet w przypadku przeciążenia sieci
- Jeśli to możliwe, najpierw przetestuj na devnecie przed wdrożeniem na mainnecie. Większość agentów
  przyjmuje adres URL RPC jako dane wejściowe i możesz używać devnetowego, dopóki nie będziesz
  gotowy na mainnet. Nie wszystkie akcje mogą być jednak możliwe do wykonania na devnecie.
- Pisząc własne akcje, dodaj do nich testy integracyjne, aby
  frameworki mogły monitorować, które akcje zawodzą z powodu zmienionych programów lub
  API

## Podsumowanie

Agenci AI na Solanie otwierają nowe możliwości automatyzacji i interakcji
z blockchainem. Choć nie wszystkie integracje są jeszcze doskonałe, są
szybko rozwijane i oferują wiele możliwości do współtworzenia oraz są bardzo
elastyczne w zakresie dodawania własnych integracji.
