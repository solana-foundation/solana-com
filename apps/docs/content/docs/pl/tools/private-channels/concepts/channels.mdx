## Czym jest kanał prywatny?

Kanał prywatny to sieć płatności off-chain zakotwiczona w Solanie. Użytkownicy
wpłacają tokeny SPL do programu escrow on-chain, a następnie dokonują transakcji off-chain
poprzez bramkę z dużą prędkością i zerowym kosztem za transfer. Rozliczenie z powrotem do
Solana Mainnet odbywa się za pomocą dowodu Sparse Merkle Tree, co zapewnia, że środki są zawsze
wymienialne, a podwójne wydanie jest niemożliwe.

W odróżnieniu od natywnego przepływu płatności Solany, transfery w ramach kanału nie pojawiają się
on-chain aż do momentu wypłaty przez użytkownika. Sieć kanałów działa na własnym potoku transakcyjnym
(dedup -> sig verify -> sequencer -> executor -> settler), który
przetwarza transakcje niezależnie od czasu bloku Solany.

## Uczestnicy

### Administrator instancji

Administrator wdraża PDA `Instance` za pomocą `CreateInstance` i kontroluje, które mint-y SPL
są akceptowane (`AllowMint` / `BlockMint`). Administrator przydziela i
odwołuje operatorów za pomocą `AddOperator` / `RemoveOperator`, a prawa administratora może przekazać
za pomocą `SetNewAdmin`. Na każdą instancję przypada jeden administrator. Przekazanie praw administratora
jest nieodwracalne w jednym kroku: obecny administrator nie może odzyskać roli
bez współpracy nowego administratora.

### Operatorzy

Operatorzy są przydzielani przez administratora. Posiadają PDA `Operator` i są jedynymi
kontami uprawnionymi do wywoływania `ReleaseFunds` (w celu rozliczania wypłat do
Mainnet) oraz `ResetSmtRoot` (do rotacji Sparse Merkle Tree). Operatorzy omijają
wszystkie sprawdzenia właścicielstwa w bramce i mają dostęp do wszystkich metod JSON-RPC,
w tym `getBlock`, `getTransaction` i `simulateTransaction`. Rola JWT:
`"operator"`. Operatorzy muszą być przydzieleni bezpośrednio w bazie danych; nie istnieje
samodzielna eskalacja uprawnień. Zapoznaj się z
[przewodnikiem dla operatorów](/docs/tools/private-channels/operators), aby uzyskać szczegółowe informacje na temat wdrożenia i
konfiguracji.

### Użytkownicy

Użytkownicy samodzielnie rejestrują się za pośrednictwem Auth Service. Rola JWT: `"user"`. Użytkownicy mogą wywoływać
`Deposit` bezpośrednio w programie Escrow Program i inicjować wypłaty za pomocą
instrukcji `WithdrawFunds` po stronie kanału w programie Withdraw Program. Dostęp do bramki
jest ograniczony do ich własnych zweryfikowanych portfeli; nie mogą wywoływać `getBlock`,
`getTransaction` ani `simulateTransaction`.

## Cykl życia kanału

```mermaid
sequenceDiagram
    participant Admin
    participant Alice
    participant Mainnet as Solana Mainnet
    participant Channel as Private Channel Network

    Note over Admin,Channel: SETUP (one time)
    Admin->>Mainnet: CreateInstance
    Admin->>Mainnet: AllowMint
    Admin->>Mainnet: AddOperator

    Note over Alice,Channel: DEPOSIT
    Alice->>Mainnet: Deposit (tokens to escrow ATA)
    Note over Channel: Indexer detects deposit event,<br/>credits Alice's channel balance

    Note over Alice,Channel: OFF-CHAIN TRANSFERS
    Alice->>Channel: SPL token transfer (via gateway)
    Channel-->>Alice: Confirmed (~100 ms, no Mainnet fee)

    Note over Alice,Mainnet: WITHDRAWAL
    Alice->>Channel: WithdrawFunds (burns channel balance)
    Note over Channel: Indexer detects burn (~1 s),<br/>operator submits ReleaseFunds
    Channel->>Mainnet: ReleaseFunds (with SMT exclusion proof)
    Mainnet-->>Alice: Tokens released to Mainnet wallet
```

1. **Tworzenie instancji** — Administrator wywołuje `CreateInstance`, tworząc PDA `Instance`
   i konfigurując dozwolone mint-y.
2. **Wpłata** — Użytkownicy wpłacają tokeny SPL do escrow za pomocą instrukcji `Deposit`.
   Tokeny trafiają do associated token account instancji.
3. **Transfery off-chain** — Użytkownicy wysyłają transfery przez bramkę. Transfery
   są sekwencjonowane i wykonywane w sieci kanałów bez kontaktu z Mainnet.
4. **Inicjowanie wypłaty** — Użytkownik wywołuje `WithdrawFunds` w programie Withdraw
   Program (po stronie kanału), aby spalić swoje saldo i zasygnalizować wypłatę.
5. **Rozliczenie na Mainnet** — Operator dostarcza ważny dowód wykluczenia SMT i
   wywołuje `ReleaseFunds` w programie Escrow Program (Mainnet), uwalniając tokeny do
   portfela użytkownika.
6. **Rotacja drzewa** — Gdy SMT zbliża się do pojemności (65 536 liści), operator
   wywołuje `ResetSmtRoot`, aby dokonać rotacji drzewa i rozpocząć nowy epoch.

### Transfer

```mermaid
sequenceDiagram
    participant Alice
    participant Bob
    participant GW as Gateway
    participant Pipeline as Write Node Pipeline
    participant DB as Channel State

    Alice->>GW: SPL token transfer to Bob
    GW->>Pipeline: Route to write node

    Note over Pipeline: 1. Dedup - reject duplicates and replays<br/>2. SigVerify - validate signatures<br/>3. Sequencer - order into conflict-free batch<br/>4. Executor - apply to off-chain account state<br/>5. Settler - commit to database, update blockhash

    Pipeline->>DB: Commit updated balances
    GW-->>Alice: Confirmed (off-chain, not recorded on Mainnet)
    Note over Bob: Balance updated in channel state
```

### Wypłata

```mermaid
sequenceDiagram
    participant Bob
    participant Channel as Private Channel Network
    participant Indexer as indexer-private-channel
    participant Operator as operator-private-channel
    participant Mainnet as Solana Mainnet

    Bob->>Channel: WithdrawFunds (burns channel-side balance)
    Channel-->>Bob: Burn confirmed off-chain

    Note over Indexer: Polls gateway every 1 s
    Indexer->>Channel: Detect burn event
    Indexer->>Indexer: Write pending withdrawal to database

    Operator->>Indexer: Pick up pending record
    Operator->>Mainnet: ReleaseFunds (SMT exclusion proof)
    Mainnet-->>Bob: Tokens transferred to Mainnet ATA
```

## Kiedy używać kanałów prywatnych

Używaj kanałów prywatnych, gdy Twoja aplikacja potrzebuje:

- **Przepustowości off-chain** — wolumen transferów nasyciłby TPS Solany lub
  potrzebujesz potwierdzenia w czasie poniżej sekundy
- **Prywatności** — tożsamości stron i kwoty transferów nie mogą pojawiać się
  on-chain
- **Zerowych opłat za transfer** — częste przelewy, gdzie koszt SOL za transakcję
  jest zbyt wysoki

Używaj natywnych transferów SPL zamiast tego, gdy:

- **Komponowalność on-chain** jest wymagana (DeFi, swapy, pożyczki; inne programy
  muszą mieć możliwość obserwowania transferu lub działania na jego podstawie)
- **Rozliczenie w jednym transferze** jest wystarczające i prywatność nie jest problemem
- **Brak infrastruktury bramki** jest dostępnej lub wykonalnej operacyjnie
