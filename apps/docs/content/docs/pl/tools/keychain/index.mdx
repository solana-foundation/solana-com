**Solana Keychain zapewnia ujednolicony interfejs do podpisywania transakcji Solana
w wielu backendach zarządzania kluczami.** Pracuj lokalnie z kluczem przechowywanym
w pamięci, a następnie przejdź na produkcji na korporacyjne zarządzanie kluczami, chmurowe moduły HSM lub zarządzane usługi
portfeli, bez przepisywania kodu podpisującego.

### Dlaczego Keychain?

- **Jeden interfejs**: Jeden bazowy interfejs `SolanaSigner` dla wszystkich backendów
  oraz jedna funkcjonalność na backend: podpisywanie, modyfikowanie i podpisywanie lub podpisywanie i rozgłaszanie
- **Wymienne backendy**: Zmieniaj dostawców zarządzania kluczami za pomocą konfiguracji; miejsca
  wywołań zmieniają się tylko wtedy, gdy nowy backend ma inną funkcjonalność (natywne tryby Crossmint
  i Fordefi)
- **Płać tylko za to, czego używasz**: Flagi funkcji Rust, pakiety npm dla poszczególnych backendów, dodatki (extras) Pythona
  oraz moduły Go dla poszczególnych backendów zawierają tylko te backendy, których potrzebujesz
- **Po audycie**: Rust, TypeScript, Python i Go zostały poddane audytowi przez
  [OtterSec](https://osec.io) (opcjonalny backend Ledger nie był objęty zakresem); wcześniejszy
  audyt [Accretion](https://accretion.xyz) obejmował Rust i TypeScript.
  Zobacz
  [status audytów](https://github.com/solana-foundation/solana-keychain/blob/main/audits/AUDIT_STATUS.md).

### Architektura

- **Języki**: Rust, TypeScript, Python i Go, z zachowaniem parytetu (backend Ledger
  jest dostępny tylko w Rust)
- **Interfejs**: baza `SolanaSigner` (`pubkey`, `sign_message`, `is_available`)
  oraz dokładnie jedna funkcjonalność na backend: `TransactionSigner`,
  `ModifyingSigner` lub `SendingSigner`
- **Backendy**: Memory, Vault, AWS KMS, GCP KMS, Privy, Turnkey, Fireblocks,
  CDP, Crossmint, Dfns, Openfort, Para, Utila, Fordefi, Ledger (tylko Rust,
  opcjonalny, bez audytu)
- **Zgodność**: `@solana/kit` i `@solana/signers` 8.1+ (TypeScript) |
  `solana-sdk` 2.x, 3.x lub 4.x przez funkcje `sdk-v2` / `sdk-v3` / `sdk-v4`
  (Rust; transakcje v1 wymagają `sdk-v4`) | `solders` (Python) | `solana-go` v2
  (Go)

### Obsługiwane backendy

Backendy obejmują lokalny rozwój, samodzielnie hostowane i chmurowe zarządzanie
kluczami oraz zarządzane usługi portfeli MPC. Zobacz
[Wybór backendu](/docs/tools/keychain/choosing-a-backend), aby porównać modele
powiernicze i wybrać odpowiedni.

## Szybki start

### Rust

Zainstaluj crate Rust:

```bash
cargo add solana-keychain
```

Podstawowe użycie:

```rust
use solana_keychain::{Signer, SolanaSigner};

// Create a signer from any backend
let signer = Signer::from_memory("base58_private_key")?;
let pubkey = signer.pubkey();

// Transaction signing is a capability; `tx` is a VersionedTransaction
if let Some(tx_signer) = signer.as_transaction_signer() {
    let result = tx_signer.sign_transaction(&mut tx).await?;
}

// Or let the umbrella route any backend shape and supply the RPC hop yourself
let signature = signer
    .sign_and_send(&mut tx, |encoded| async move { broadcast(encoded).await })
    .await?;
```

- [Przewodnik po Rust](/docs/tools/keychain/getting-started/rust) - Pełna
  instalacja i konfiguracja backendu
- [Crates.io](https://crates.io/crates/solana-keychain) - Crate Rust

### TypeScript

Zainstaluj pakiet TypeScript:

```bash
pnpm add @solana/keychain
```

Podstawowe użycie:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers";

// Create any signer via the unified factory
const signer = await createKeychainSigner({
  backend: "vault",
  vaultAddr: "https://vault.example.com:8200",
  vaultToken: "hvs.xxxxx",
  keyName: "my-solana-key",
  publicKey: "base58_public_key"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

- [Przewodnik po TypeScript](/docs/tools/keychain/getting-started/typescript) -
  `@solana/keychain` pakiety
- [Pakiet npm](https://www.npmjs.com/package/@solana/keychain) - Pakiet npm

Aby zainstalować signera Keychain w kliencie [Kit](https://github.com/anza-xyz/kit)
jako jego `payer` lub `identity`, użyj `@solana/keychain-kit-plugin` (natywne tryby Crossmint i
Fordefi są wyłączone, ponieważ modyfikują transakcje).

### Python

Zainstaluj pakiet (cięższe backendy są dostępne jako dodatki, na przykład
`solana-keychain[aws-kms]`):

```bash
pip install solana-keychain
```

Podstawowe użycie:

```python
import os

from solana_keychain import VaultSignerConfig, create_vault_signer

signer = await create_vault_signer(
    VaultSignerConfig(
        api_base_url="https://vault.example.com:8200",
        token=os.environ["VAULT_TOKEN"],
        key_name="my-solana-key",
        public_key="base58_public_key",
    )
)

# tx is a solders VersionedTransaction
result = await signer.sign_transaction(tx)
```

- [Przewodnik po Pythonie](/docs/tools/keychain/getting-started/python) – Pełna
  instalacja, dodatki i konfiguracja backendów
- [PyPI](https://pypi.org/project/solana-keychain/) – pakiet Pythona

### Go

Każdy backend jest osobnym modułem Go, więc pobierasz tylko te backendy, które importujesz:

```bash
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2@latest
```

Podstawowe użycie:

```go
import "github.com/solana-foundation/solana-keychain/go/signers/vault/v2"

signer, err := vault.New(vault.Config{
	VaultAddr: "https://vault.example.com:8200",
	Token:     os.Getenv("VAULT_TOKEN"),
	KeyName:   "my-solana-key",
	Pubkey:    "base58_public_key",
})
if err != nil {
	return err
}

// tx is a *solana.Transaction from solana-go v2
res, err := signer.SignTransaction(ctx, tx)
```

- [Przewodnik po Go](/docs/tools/keychain/getting-started/go) – Moduły, funkcjonalności
  i konfiguracja backendów
- [pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2) –
  dokumentacja Go
