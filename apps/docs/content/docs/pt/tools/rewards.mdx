O programa Rewards distribui tokens de um cofre pertencente ao programa para um conjunto de
destinatários, cada um com um cronograma de vesting. Uma autoridade financia o cofre e define
quem recebe o quê. Os destinatários resgatam seus tokens liberados ao longo do tempo, e a
autoridade pode revogar destinatários ou recuperar os tokens restantes quando a distribuição
o permitir. O programa é construído com Pinocchio, mantido pela Solana
Foundation, e funciona com mints SPL Token e Token-2022, exceto
mints Token-2022 com a extensão transfer hook.

ID do programa (mainnet e devnet):

```text
REWArDioXgQJ2fZKkfu9LCLjQfRwYWVVfsvcsR5hoXi
```

## Escolha um tipo de distribuição

O programa oferece suporte a dois tipos de distribuição. Ambos usam os mesmos cronogramas de vesting
e modos de revogação.

|                  | Direct                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **Como funciona** | Cria uma conta onchain para cada destinatário     | Armazena uma única raiz merkle onchain; os destinatários apresentam provas para resgatar  |
| **Custo inicial** | O pagador financia a rent de todas as contas de destinatários | Nenhuma conta por destinatário até que alguém resgate                           |
| **Escala**        | Prático para até alguns milhares de destinatários  | Escala para milhões de destinatários; o armazenamento cresce apenas conforme os destinatários resgatam |
| **Mutabilidade**   | Destinatários podem ser adicionados após a criação       | O conjunto de destinatários é fixado na criação                                       |
| **Use para**   | Distribuições pequenas que mudam ao longo do tempo    | Distribuições grandes e fixas, como airdrops                              |

## Cronogramas de vesting

Cada alocação segue um de quatro cronogramas. Os timestamps são em segundos Unix.

| Cronograma      | Comportamento                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | Todos os tokens podem ser resgatados imediatamente                                                                                    |
| `Linear`      | Os tokens são liberados proporcionalmente entre `startTs` e `endTs`                                                             |
| `Cliff`       | Nada é liberado até `cliffTs`; então tudo é liberado de uma só vez                                                       |
| `CliffLinear` | Vesting linear de `startTs` a `endTs`, sem nada resgatável até `cliffTs`; o valor acumulado antes disso é liberado no cliff |

## Contas

| Conta              | Seeds do PDA                                        | Armazena                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | Autoridade, mint e totais de alocação       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | A alocação e o vesting de um destinatário       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | Autoridade, mint, totais e a raiz merkle |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | Valor resgatado até o momento por um beneficiário        |
| `Revocation`         | `["revocation", distribution, user]`             | Marcador que bloqueia um beneficiário merkle revogado |

O `seed` é o endereço de um signatário adicional informado na criação, de modo que uma
mesma autoridade possa executar várias distribuições para o mesmo mint. O cofre de cada
distribuição é a associated token account do PDA da distribuição para o respectivo mint.

## Instruções

### Distribuição direta

1. A autoridade chama `CreateDirectDistribution` para criar o PDA da distribuição
   e seu cofre.
2. A autoridade chama `AddDirectRecipient` uma vez por destinatário, com um valor
   e um cronograma de vesting. Cada chamada transfere esse valor da
   token account da autoridade para o cofre.
3. Os destinatários chamam `ClaimDirect` para sacar os tokens liberados. Informe `amount: 0` para
   resgatar tudo o que estiver liberado no momento.
4. Quando um destinatário tiver resgatado tudo, ou a distribuição for encerrada,
   `CloseDirectRecipient` fecha a conta do destinatário e reembolsa a rent à
   conta que a pagou.
5. A autoridade chama `CloseDirectDistribution` para recuperar o saldo restante
   do cofre e a rent. Se `clawbackTs` estiver definido, o encerramento só é permitido após esse
   momento.

### Distribuição Merkle

1. A autoridade constrói uma árvore merkle offchain. Cada folha registra um beneficiário,
   o valor total desse beneficiário e um cronograma de vesting.
2. A autoridade chama `CreateMerkleDistribution` com a raiz, o valor total
   resgatável e um `clawbackTs`, e financia o cofre na mesma
   instrução.
3. Os beneficiários chamam `ClaimMerkle` com os dados da sua folha e a prova. O primeiro resgate
   cria a conta `MerkleClaim` do beneficiário. Informe `amount: 0` para resgatar
   tudo o que estiver liberado no momento.
4. Após `clawbackTs`, a autoridade chama `CloseMerkleDistribution` para recuperar
   o saldo restante do cofre e a rent.
5. Depois que a distribuição é encerrada, os beneficiários chamam `CloseMerkleClaim` para
   recuperar a rent da sua conta de resgate.

O programa calcula o hash das folhas com Keccak-256 como
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`, em que
`totalAmount` é um `u64` em little-endian e `schedule` usa a mesma codificação do
argumento `VestingSchedule` da instrução. Os nós da prova são combinados em hash como pares
ordenados, com o menor hash primeiro.

### Revogação

A revogação é opcional (opt-in). O bitmask `revocable` definido na criação escolhe quais
modos a autoridade pode usar: o bit 0 habilita `NonVested`, o bit 1 habilita `Full`,
e `0` desabilita a revogação.

| Modo        | Instrução                                    | Resultado                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` ou `RevokeMerkleClaim` | Os tokens liberados e não resgatados vão para o usuário; os tokens não liberados retornam à autoridade |
| `Full`      | `RevokeDirectRecipient` ou `RevokeMerkleClaim` | Todos os tokens não resgatados, liberados ou não, retornam à autoridade               |

Revogar um beneficiário merkle cria um marcador `Revocation` que bloqueia resgates
futuros, mesmo que ele nunca tenha resgatado. Revogar um destinatário direto fecha
sua conta `DirectRecipient` e reembolsa a respectiva rent.

## Clientes

O repositório inclui clientes [`@solana/kit`](/docs/clients/official/javascript) e
Rust gerados a partir do IDL do programa com Codama, em
[`clients/`](https://github.com/solana-foundation/rewards/tree/main/clients).
O cliente ainda não foi publicado no npm. Compile-o a partir do código-fonte com
`just generate-clients`.
