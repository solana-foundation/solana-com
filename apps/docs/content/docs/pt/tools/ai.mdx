# Trabalhando com LLMs e Agentes na Solana

Antes de mergulhar nas ferramentas específicas, vamos entender os principais componentes da
pilha de desenvolvimento de IA:

## Entendendo a Pilha de IA

1. **Grandes Modelos de Linguagem (LLMs)**
   - Os modelos de IA fundamentais (como GPT-4, Claude ou Llama)
   - Processam e geram linguagem natural
   - Fornecem inteligência bruta e capacidades de raciocínio
   - Exemplos: GPT-4 da OpenAI, Claude da Anthropic, Llama da Meta

2. **Frameworks de Agentes (como Eliza)**
   - Construídos sobre LLMs para criar agentes autônomos
   - Gerenciam personalidades e comportamentos dos agentes
   - Lidam com memória e contexto
   - Fornecem integração multiplataforma
   - Exemplos: Eliza, LangChain, AutoGPT, Vercel AI

3. **Kits de Agentes de Domínio Específico (como o Solana Agent Kit)**
   - Criados para casos de uso específicos (ex.: operações em blockchain)
   - Fornecem ferramentas e integrações pré-construídas
   - Abstraem a complexidade técnica
   - Funções blockchain prontas para uso
   - Exemplos: Solana Agent Kit, GOAT Toolkit

Pense da seguinte forma:

- Os LLMs são o "cérebro" que consegue entender e gerar linguagem
- Os frameworks de agentes são o "sistema operacional" que gerencia o comportamento da IA
- Os kits de domínio específico são os "aplicativos" que conferem à IA capacidades específicas

# Construindo Agentes de IA para a Solana

Este guia mostrará como:

- Construir um agente de IA básico usando o Solana Agent Kit da SendAI
- Criar um bot para o Twitter com o Eliza Framework
- Entender as opções de integração de IA onchain
- Opções de como construir bots de trading avançados

## Introdução aos Agentes de IA na Solana

Os agentes de IA na Solana são programas autônomos que podem interagir com a
blockchain usando processamento de linguagem natural e aprendizado de máquina. Eles podem:

- Executar transações
- Monitorar a atividade da blockchain
- Interagir com contratos inteligentes
- Fornecer suporte ao usuário
- Automatizar fluxos de trabalho complexos

## Frameworks Disponíveis

Vários frameworks estão disponíveis para construir agentes de IA na Solana:

1. **Solana Agent Kit da SendAI**

- Uma coleção de ferramentas para construir agentes na Solana
- Compatível com Eliza, Langchain e Vercel AI SDK
- Ferramentas e utilitários Solana integrados
- Capacidades de processamento de linguagem natural
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Documentação](https://docs.solanaagentkit.xyz/)

2. **Eliza Framework**

- Combina camada de dados, LLM e agentes, e possui um plugin dedicado para Solana
- Arquitetura de agentes extensível
- Fácil integração com projetos existentes e pode ser usado, por exemplo, para
  bots no Twitter (X), Telegram ou Discord
- [Repositório no GitHub](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Kit de desenvolvimento abrangente
- Compatibilidade entre cadeias (cross-chain)
- [Repositório no GitHub](https://github.com/goat-sdk/goat)

4. **Rig Framework**

- Implementação nativa em Rust
- Ideal para bots de trading de alto desempenho
- Pode ser combinado com o toolkit Listen.rs para integração com Solana, monitoramento de transações
  e envio de transações usando bundles Jito, por exemplo
- [Repositório no GitHub](https://github.com/0xPlaygrounds/rig)
- [Repositório Listen.rs](https://github.com/piotrostr/listen)

Se você está construindo um framework de IA, sinta-se à vontade para abrir um PR e adicionar seu framework
à lista

### Criar o script do agente

Crie um novo arquivo chamado `agent.ts` com o seguinte conteúdo:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

## Construindo com o Eliza Framework

O [ElizaOS](https://github.com/elizaOS/eliza) (anteriormente conhecido como Ai16z) é um
framework de IA. Isso significa que ele combina múltiplas aplicações em uma só e
organiza suas interações. Ele combina:

1. Diferentes LLMs para entender o usuário
2. Agentes de blockchain com diferentes ações (como cunhar um NFT, por exemplo)
3. Camadas de dados para armazenar o estado dos personagens entre ações, usando por exemplo
   Redis, banco de dados PostgreSQL ou armazenamento local
4. Diferentes clientes como X, Telegram, Discord, etc.

Ele une todas essas coisas de uma forma que você pode criar um
"Personagem" capaz de interagir com usuários ou de forma autônoma. Esses Personagens são
definidos em um arquivo JSON, que define quais ações ele pode executar, qual LLM
deve usar e diferentes prompts que definem o comportamento do personagem.

### Criar a configuração do personagem

Para criar um novo personagem, precisamos criar um arquivo character.json. Você pode encontrar
os personagens predefinidos na pasta characters do projeto Eliza. Para criar um
novo personagem, você pode copiar e modificar um dos personagens já existentes ou
usar o
[recurso composer no Cursor](https://docs.cursor.com/composer/overview) e descrever
o tipo de personagem que deseja criar.

```json filename=characters/sol.character.json

    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },
        ...
```

A parte importante aqui são os clients e o modelProvider. No nosso caso,
queremos usar o twitter como cliente e o openai como provedor de modelo, pois é
isto que também configuramos nos nossos secrets no arquivo `.env`.

Agora que a configuração está concluída, podemos executar nosso personagem:

personagem começará automaticamente a publicar tweets a cada poucas horas e, quando
interagirmos com ele, será capaz de executar ações na Solana como cunhar NFTs,

Se o seu cliente não conectar, certifique-se de executar o agente com a flag `--host`

## Integração de agentes com programas onchain

Se quiser usar a resposta de um agente dentro de um programa Solana, você precisa usar um
oracle que grave os dados da resposta em uma conta que seu programa possa ler.
Você pode encontrar um exemplo de um LLM que transferirá tokens para qualquer usuário que
responda corretamente às perguntas aqui:

[Interação de programa LLM on-chain](https://github.com/GabrielePicco/super-smart-contracts)

Este é um exemplo de um programa onchain que se integra com um oracle LLM (IA)
para criar um agente interativo de distribuição de tokens chamado "Mar1o".

### Principais Funcionalidades

1. **Interação com Agente de IA**
   - Os usuários podem conversar com Mar1o para tentar ganhar tokens
   - O agente avalia o conhecimento de Solana do usuário para decidir os valores de tokens
   - As respostas estão em formato JSON com texto de resposta e quantidade de tokens

2. **Gestão de Tokens**
   - Cria tokens MAR1O com metadados
   - Pode cunhar entre 0 e 10.000 tokens com base na resposta da IA
   - Usa PDAs para gestão de tokens

### Fluxo do programa explicado

Veja como este programa funciona:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Isso demonstra como combinar capacidades de IA com mecânicas de tokens onchain para
crirar experiências interativas em blockchain. Aqui está um
[exemplo ao vivo](https://mar1o.xyz/) onde você pode tentar convencer o Agente a
transferir alguns tokens para você.

## Agentes Rust avançados para negociação algorítmica

Se quiser escrever seus agentes em Rust, você pode usar o
[framework Rig](https://github.com/0xPlaygrounds/rig) e a
biblioteca [Listen.rs](https://github.com/piotrostr/listen).

Esses dois funcionam bem juntos. Enquanto o framework Rig oferece uma maneira fácil de
conectar-se a LLMs, o toolkit Listen.rs fornece a integração com Solana,
incluindo monitoramento de transações e envio de transações usando bundles Jito,
por exemplo.

## Boas Práticas

- Saiba que seu agente possui uma chave privada e, portanto, pode acessar os fundos na sua
  carteira. Se alguém puder conversar com seu agente e ele tiver uma ação de transferência,
  por exemplo, os usuários provavelmente conseguirão fazê-lo transferir seus fundos.
- Use [endpoints RPC](https://solana.com/rpc) pagos. Os endpoints públicos
  geralmente ficam com limite de taxa
- Monitore as atividades do agente e certifique-se de que ele não está fazendo nada malicioso
  ou sendo enganado por usuários que interagem com ele
- Implemente taxas de prioridade e novas tentativas de transação nas ações do seu agente para que
  elas também sejam processadas quando houver congestionamento na rede
- Se possível, teste na devnet primeiro antes de implantar na mainnet. A maioria dos agentes
  apenas recebe a URL do RPC como entrada e você pode usar uma da devnet até estar
  pronto para a mainnet. Porém, nem todas as ações podem ser possíveis de executar na devnet.
- Ao escrever suas próprias ações, adicione testes de integração para que os
  frameworks possam monitorar quais ações estão falhando devido a programas ou
  APIs modificados
