## Infraestrutura de RPC

Os [endpoints públicos](https://solana.com/docs/references/clusters#solana-public-rpc-endpoints)
(`api.mainnet.solana.com`) têm limite de requisições e não oferecem SLA. Servem
para desenvolvimento, mas falharão em fluxos de pagamento em produção — como
tentar operar um processador de pagamentos por meio de uma API compartilhada, sem
garantia de disponibilidade.

<Callout type="caution" title="Nunca use RPC público em produção">
  Use um [provedor de RPC privado](https://solana.com/rpc) para obter um acesso
  confiável e de baixa latência.
</Callout>

Ao escolher um provedor de RPC, procure por:

- **Confiabilidade**: SLAs com garantia de disponibilidade (99,9%+)
- **Latência**: Proximidade geográfica dos seus usuários
- **Recursos**: Recursos de inclusão de transações, indexação, APIs de taxa de prioridade

Para ver a lista completa de provedores de RPC, consulte o guia
[Provedores de infraestrutura de RPC](https://solana.com/rpc).

### Configuração de RPC redundante

Como qualquer provedor de serviços de rede, os provedores de RPC podem sofrer
interrupções ou períodos de desempenho degradado. Para garantir que seu
aplicativo seja resiliente, configure-o para usar vários provedores de RPC.

O [Solana Kit](https://github.com/anza-xyz/kit/tree/main/packages/rpc-transport-http)
fornece uma biblioteca para personalizar transportes de RPC, o que permite criar
seu próprio cliente de RPC redundante. Veja um exemplo de como você pode usá-la
para criar um cliente de RPC redundante:

```ts
import { RpcTransport } from "@solana/rpc-spec";
import { RpcResponse } from "@solana/rpc-spec-types";
import { createHttpTransport } from "@solana/rpc-transport-http";

// Create a transport for each RPC server
const transports = [
  createHttpTransport({ url: "https://mainnet-beta.my-server-1.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-2.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-3.com" })
];

// Create a wrapper transport that distributes requests to them
let nextTransport = 0;
async function roundRobinTransport<TResponse>(
  ...args: Parameters<RpcTransport>
): Promise<RpcResponse<TResponse>> {
  const transport = transports[nextTransport];
  nextTransport = (nextTransport + 1) % transports.length;
  return await transport(...args);
}
```

Se preferir não criar suas próprias ferramentas de roteamento, você pode usar um
serviço de terceiros como o [Iron Forge](https://www.ironforge.sanctum.so/) para
cuidar do roteamento por você.

## Inclusão de transações

Na Devnet, as transações são incluídas com bastante facilidade. Na Mainnet, você
compete por espaço nos blocos. Para aumentar as chances de sua transação ser
incluída em um bloco, é preciso montá-la corretamente. Isso significa:

- incluir um blockhash recente antes de enviar a transação
- incluir na transação uma instrução de taxa de prioridade com uma taxa de
  prioridade competitiva
- incluir na transação uma instrução de limite de unidades de computação, com um
  limite baseado na estimativa de unidades de computação necessárias para a
  transação

Além disso, considere outras ferramentas, como os Jito Bundles, para aumentar as
chances de sua transação ser incluída em um bloco. Vamos explorar essas
ferramentas em mais detalhes.

### Configuração de envio de transações

Ao enviar transações na Mainnet, configure estes parâmetros para obter as
melhores taxas de inclusão:

**Gerenciamento do blockhash:**

- Obtenha com o commitment `confirmed`
- Armazene o `lastValidBlockHeight` retornado por `getLatestBlockhash` — ele
  indica quando sua transação expira
- Os blockhashes expiram após um tempo definido pelo protocolo, que depende da
  duração do slot.

**Opções de envio:**

- `maxRetries: 0` — Desativa as novas tentativas automáticas do RPC. Gerencie as
  novas tentativas por conta própria para poder atualizar o blockhash quando
  necessário.
- `skipPreflight: true` — Ignora a simulação antes do envio. Use quando já tiver
  validado a transação e quiser a menor latência possível. Mantenha como `false`
  durante o desenvolvimento para detectar erros logo no início.

```typescript
import { createSolanaRpc } from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);

// 1. Get blockhash with confirmed commitment
const { value: latestBlockhash } = await rpc
  .getLatestBlockhash({ commitment: "confirmed" })
  .send();

// 2. Build and sign your transaction with the blockhash
// ... (transaction building code)

// 3. Send with production settings
const signature = await rpc
  .sendTransaction(encodedTransaction, {
    encoding: "base64",
    maxRetries: 0n, // Handle retries yourself
    skipPreflight: true, // Skip simulation for speed (use false during dev)
    preflightCommitment: "confirmed"
  })
  .send();

// 4. Track expiration using lastValidBlockHeight
const { lastValidBlockHeight } = latestBlockhash;
// Stop retrying when current block height exceeds lastValidBlockHeight
```

### Use taxas de prioridade

Toda transação Solana exige uma taxa de transação, paga em SOL. As taxas de
transação se dividem em duas partes: a taxa base e a taxa de prioridade. A taxa
base remunera os validators pelo processamento da transação. A taxa de
prioridade é opcional e aumenta a chance de o líder atual processar sua
transação. Pense nela como uma entrega expressa: você paga mais por uma entrega
mais rápida e confiável.

**Como as taxas funcionam:**

```
Total fee = Base fee (5,000 lamports per signature) + Priority fee
Priority fee (legacy/v0) = ceil(compute_unit_price * compute_unit_limit / 1,000,000) lamports
Priority fee (v1 only) = Absolute total in lamports set in the message config
```

**Custos no mundo real:**

- Transferência simples de USDC: ~US$ 0,001-0,005 em condições normais
- Durante congestionamento: ~US$ 0,01-0,05
- Pico de congestionamento: pode subir ainda mais

**Exemplo de implementação:**

O pacote
[`@solana-program/compute-budget`](https://github.com/solana-program/compute-budget)
fornece uma função auxiliar para atualizar ou acrescentar facilmente a instrução
de preço da unidade de computação (em micro-lamports) a uma transação.

```typescript
import { updateOrAppendSetComputeUnitPriceInstruction } from "@solana-program/compute-budget";

const tx = pipe(
  createTransactionMessage({ version: 0 }),
  (m) => setTransactionMessageFeePayerSigner(payer, m),
  (m) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, m),
  (m) => appendTransactionMessageInstructions([myInstructions], m),
  (m) => updateOrAppendSetComputeUnitPriceInstruction(1000n as MicroLamports, m)
);
```

**Como obter estimativas de taxa:** a maioria dos provedores de RPC oferece APIs de taxa de prioridade:

- [API de taxa de prioridade da Helius](https://docs.helius.dev/solana-apis/priority-fee-api)
- [Add-on de taxa de prioridade da QuickNode](https://marketplace.quicknode.com/add-on/solana-priority-fee)
- [API de taxas de prioridade da Triton](https://docs.triton.one/chains/solana/improved-priority-fees-api)

Para conhecer a mecânica completa das taxas, consulte [Taxas de transação](/docs/core/fees) e nosso
guia:
[Como adicionar taxas de prioridade a uma transação](https://solana.com/developers/cookbook/transactions/add-priority-fees).

### Otimize as unidades de computação

A computação na Solana é medida em unidades de computação (CUs), que são uma
estimativa aproximada da quantidade de trabalho realizado pelo programa. Hoje, os
limites de computação são de 50 milhões de CUs por bloco e 1,4 milhão de CUs por
transação. Ao enviar uma transação, você precisa estimar a quantidade de
computação que será usada e definir o limite de unidades de computação de acordo
— na prática, trata-se de um pedido de quanto da capacidade total deve ser
reservado para a sua transação. Na prática, isso significa que estimar
corretamente as unidades de computação necessárias para a transação é essencial
para que ela seja incluída em um bloco (e importante para gerenciar suas taxas de
prioridade). Os limites de computação da transação e do bloco são determinados
pelo protocolo.

A API JSON RPC da Solana tem um método
[`simulatetransaction`](/docs/rpc/http/simulatetransaction) que pode ser
usado para estimar as unidades de computação necessárias para uma transação.
O [`@solana/kit`](https://github.com/anza-xyz/kit) fornece funções auxiliares que
estimam os limites de recursos de uma transação e os definem na mensagem em uma
única etapa (usando o método `simulatetransaction` internamente). Para
transações da versão 1, essas funções auxiliares também estimam o limite de
tamanho dos dados das contas carregadas.

```ts
import {
  estimateResourceLimitsFactory,
  estimateAndSetResourceLimitsFactory
} from "@solana/kit";

const estimateResourceLimits = estimateResourceLimitsFactory({ rpc });
const estimateAndSetResourceLimits = estimateAndSetResourceLimitsFactory(
  estimateResourceLimits
);
const txWithResourceLimits = await estimateAndSetResourceLimits(tx);
```

<Callout type="info">
  Se você cria e envia transações com um cliente de plugin do kit, normalmente
  não precisa desta etapa — o cliente adiciona as instruções de orçamento de
  computação para você ao enviar (`.sendTransaction()`). O fluxo manual acima é
  para quando você monta as transações diretamente com `@solana/kit`.
</Callout>

Em produção, se você repete o mesmo tipo de transação várias vezes, considere
armazenar em cache a estimativa de computação para esse tipo de transação, a fim
de evitar o custo de estimar as unidades de computação a cada vez.

### Jito Bundles

Os Jito Bundles são uma ferramenta para gerenciar a execução atômica de várias
transações. Isso é feito enviando várias transações à rede Jito com uma gorjeta
(tip). As gorjetas podem ser usadas para incentivar a rede Jito a incluir suas
transações em um bloco.

### Estratégias de nova tentativa

As transações podem falhar por vários motivos. Ao contrário das APIs de
pagamento tradicionais, que retornam sucesso ou falha imediatamente, as
transações em blockchain exigem o acompanhamento da confirmação.

**Conceitos-chave:**

- **Expiração do blockhash**: Expiração do blockhash: os blockhashes de transação
  permanecem válidos por 150 slots (cerca de 30 segundos, com slots de 200 ms).
  O tempo real de expiração pode variar conforme a velocidade de produção de
  blocos. Use lastValidBlockHeight para determinar quando um blockhash expirou.
- **Idempotência**: a mesma transação assinada sempre produz a mesma
  assinatura — reenviá-la é seguro
- **Backoff exponencial**: evite sobrecarregar a rede com novas tentativas muito rápidas

```typescript
import {
  createSolanaRpc,
  createSolanaRpcSubscriptions,
  sendAndConfirmTransactionFactory,
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED
} from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);
const rpcSubscriptions = createSolanaRpcSubscriptions(process.env.RPC_WSS_URL!);

const sendAndConfirmTransaction = sendAndConfirmTransactionFactory({
  rpc,
  rpcSubscriptions
});

// Send with automatic confirmation tracking and block height monitoring
try {
  await sendAndConfirmTransaction(signedTransaction, {
    commitment: "confirmed",
    // Optional: abort after 75 seconds
    abortSignal: AbortSignal.timeout(75_000)
  });
} catch (e) {
  if (isSolanaError(e, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED)) {
    // Blockhash expired—rebuild transaction with fresh blockhash and retry
    rebuildAndRetryTransaction(); // implement your own logic for rebuilding and retrying the transaction
  }
  throw e;
}
```

O `sendAndConfirmTransactionFactory` do `@solana/kit` cuida automaticamente do
polling de confirmação e do acompanhamento da altura do bloco. Ele lança
`SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED` quando o blockhash da transação expira,
sinalizando que você precisa reconstruir a transação com um blockhash novo.

## Tratamento de erros

O Solana Kit fornece erros tipados por meio de `isSolanaError()`. Use códigos de
erro específicos em vez de comparação de strings:

```typescript
import {
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED,
  SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE,
  SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND,
  SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS
} from "@solana/kit";

function handlePaymentError(error: unknown): {
  message: string;
  retryable: boolean;
} {
  // Blockhash expired—rebuild and retry
  if (
    isSolanaError(error, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED) ||
    isSolanaError(error, SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND)
  ) {
    return { message: "Transaction expired—rebuilding", retryable: true };
  }

  // Insufficient SOL for fees
  if (
    isSolanaError(
      error,
      SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE
    )
  ) {
    return { message: "Not enough SOL for fees", retryable: false };
  }

  // Insufficient token balance
  if (
    isSolanaError(error, SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS)
  ) {
    return { message: "Insufficient balance", retryable: false };
  }

  // Unknown error
  console.error("Payment error:", error);
  return { message: "Payment failed—please retry", retryable: true };
}
```

**Códigos de erro comuns:**

| Código de erro                   | Causa                 | Recuperação                                                                                                 |
| ---------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------- |
| `BLOCK_HEIGHT_EXCEEDED`      | Blockhash expirado     | Reconstruir com um blockhash novo                                                                             |
| `BLOCKHASH_NOT_FOUND`        | Blockhash não encontrado   | Reconstruir com um blockhash novo                                                                             |
| `INSUFFICIENT_FUNDS_FOR_FEE` | SOL insuficiente        | Adicionar fundos ao pagador da taxa ou usar a [abstração de taxas](/docs/payments/send-payments/payment-processing/fee-abstraction) |
| `INSUFFICIENT_FUNDS`         | Tokens insuficientes     | O usuário precisa de mais saldo                                                                                  |
| `ACCOUNT_NOT_FOUND`          | token account ausente | Criar a ATA na transação                                                                                |

## Transações sem gas

Os usuários esperam pagar em stablecoins, e não adquirir SOL para as taxas de
rede. As transações sem gas resolvem isso — de forma semelhante a como os
usuários do Venmo não pensam nas taxas de ACH. Consulte
[Abstração de taxas](/docs/payments/send-payments/payment-processing/fee-abstraction)
para ver a implementação completa.
