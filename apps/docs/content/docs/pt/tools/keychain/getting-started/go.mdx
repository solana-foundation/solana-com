A versão 2.0.0 é a primeira versão estável dos módulos Go, portanto não há nada para
migrar. O
[guia de migração para a 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)
cobre a mesma divisão de capacidades para Rust e TypeScript.

## Instalação

Cada backend é seu próprio módulo Go, de modo que seu build e seu grafo de módulos
contenham apenas os backends que você importa:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

Os módulos são marcados com a tag `go/<module>/v2.0.0` (por exemplo,
`go/signers/memory/v2.0.0`). Todos os módulos exigem Go 1.25.0, exceto o `gcpkms`,
que exige Go 1.25.8 por causa do piso definido por `google.golang.org/api`.
O Ledger é exclusivo do Rust e não tem módulo Go.

### solana-go v2 e transações v1

Os módulos são construídos sobre
[`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go)
v2.0.0 e recebem o seu `*solana.Transaction`. Transações legacy, v0 e v1
(`solana.MessageVersionV1`) são suportadas, exceto pela Fireblocks
com `UseProgramCall: true`, que aceita apenas legacy e v0.

## Uso básico

Todo signer implementa a
[interface base `core.SolanaSigner`](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)
(`Pubkey`, `SignMessage`, `IsAvailable`). Os métodos recebem um `context.Context` e
são bloqueantes. Cada backend também implementa exatamente uma interface de capacidade:

- `core.TransactionSigner`: `SignTransaction` assina a sua transação como ela foi fornecida.
- `core.ModifyingSigner`: `ModifyAndSignTransaction` permite que o provedor reescreva
  a transação e depois a assina.
- `core.SendingSigner`: `SignAndSendTransaction` faz o provedor assinar e
  transmitir a transação.

Cada pacote de backend expõe uma struct `Config` e um construtor `New`:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` e `ModifyAndSignTransaction` retornam um
`core.SignedTransaction` (`EncodedTransaction`, `Signature`, `Completeness`).
Os backends HTTP remotos aceitam um `HTTPClient` e um `HTTPClientConfig` opcionais
(timeouts). O cliente padrão exige HTTPS; ao fornecer o seu próprio, você ignora essa exigência
e passa a ser responsável pela postura de segurança dele.

### Capacidades dos signers

Um backend que não consegue assinar uma transação não possui nenhum método `SignTransaction`,
portanto a capacidade é um fato em tempo de compilação para tipos concretos e uma
asserção de tipo para um `core.SolanaSigner`:

| Backend                                                                         | Capacidade          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | Sim                            |
| cdp                                                                             | `TransactionSigner` | Apenas payloads UTF-8            |
| utila                                                                           | `TransactionSigner` | Falha com `CodeSigningFailed` |
| fordefi black box (`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | Sim                            |
| fordefi native manual (`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | Sim                            |
| fordefi native auto (`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | Sim                            |
| crossmint                                                                       | `SendingSigner`     | Falha com `CodeSigningFailed` |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### Inicialização

Não há uma etapa `Init` separada. Privy, Fireblocks, Dfns, Crossmint, Para,
Openfort e Utila resolvem o endereço da carteira dentro de `New`, e é por isso que seus
construtores recebem um `context.Context`. Sempre crie signers por meio de `New`: um
signer Crossmint, Para ou Utila com valor zero falha com `CodeNotInitialized`
em vez de assinar para o endereço zero.

### Assinar e enviar com qualquer signer

`core.SignAndSendTransaction` coloca uma transação na blockchain, seja qual for o
formato do signer. Um `SendingSigner` transmite por meio do seu provedor e ignora a função
de envio; todos os outros formatos assinam e a sua função transmite o resultado
em base64, que, para um `ModifyingSigner`, é a transação reescrita pelo seu provedor.
O Core não tem dependência de RPC:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### Assinatura em lote

A assinatura em lote é oferecida como helpers livres, de forma concorrente, com um escalonamento
opcional por requisição para APIs com limite de taxa:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` recebe um `core.TransactionSigner`, portanto os
signers com transmissão gerenciada (Crossmint, Fordefi native auto) e o Fordefi native
manual não podem ser processados em lote por ele; chame-os uma transação por vez. Um
signer cujas chamadas criam trabalho no lado do provedor (Fireblocks com `UseProgramCall`)
informa isso por meio de `core.BatchServerSideEffects`, e o lote passa então a ser executado
de forma sequencial.

## Configuração do backend

### Memory

Forneça exatamente um entre `PrivateKey` (bytes brutos), `PrivateKeyString` (base58 ou um
array de bytes `[1,2,...]`) ou `PrivateKeyPath` (arquivo keypair da Solana CLI):

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

O Go não oferece uma forma confiável de zerar a memória: o coletor de lixo pode copiar e
reter bytes de chaves (keypairs em memória e as chaves que Crossmint e Openfort derivam
localmente) até a coleta. Trate toda a memória do processo como sensível ao
usar backends com chaves locais.

```go

	APIKeyID:     "api_key_id",
```

O `SignMessage` do CDP aceita apenas payloads UTF-8.

### Crossmint

O Crossmint é somente de envio: sua API executa cada transação aprovada
no lado do servidor, portanto `*crossmint.Signer` tem `SignAndSendTransaction` e nenhum
`SignTransaction`. Sua transação nunca é modificada; a assinatura retornada
identifica a transação que o Crossmint efetivou, que pode diferir da sua se o
Crossmint patrocinar o gás.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Utila

O Utila apenas assina transações; `SignMessage` falha, e você mesmo transmite a
transação assinada.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/utila/v2"

signer, err := utila.New(ctx, utila.Config{
	ServiceAccountEmail:         "sa@example.com",
	ServiceAccountPrivateKeyPEM: "-----BEGIN PRIVATE KEY-----\n...",
	VaultID:                     "vault_id",
	WalletID:                    "wallet_id",
	Network:                     "networks/solana-devnet",
})
```

### Fordefi

O Fordefi vem em três tipos de signer, definidos na construção por `Config.Chain` e
`Config.PushMode`. Os três assinam mensagens:

| Config                                          | Tipo                          | Ponto de entrada                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` não definido                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` definido, `PushMode` não definido ou `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` definido, `PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` faz o despacho com base na configuração e retorna um `core.SolanaSigner`;
`fordefi.NewBlackBox`, `fordefi.NewNativeAuto` e `fordefi.NewNativeManual`
retornam o tipo concreto e rejeitam as configurações dos outros modos. As requisições à API são
autenticadas com uma assinatura de requisição ECDSA P-256: forneça exatamente um entre
`PrivateKeyPEM` ou um `RequestSigner` para manter essa chave em um KMS/HSM.

**Modo native auto**: o Fordefi pode substituir o blockhash e as taxas, depois assina e
transmite. Ele aceita apenas uma transação não assinada cujo único signatário necessário
seja o vault.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**Modo native manual**: defina `PushMode: fordefi.PushModeManual`. O Fordefi reescreve
a mensagem (blockhash recente, instruções de taxa do Compute Budget) e a assina
sem transmiti-la. `ModifyAndSignTransaction` substitui `tx` pela
transação que o Fordefi assinou: sempre continue a partir dela. O Fordefi deve ser o pagador
da taxa e deve assinar antes de qualquer outro signatário necessário, já que a reescrita invalida
as assinaturas existentes. A reescrita não gera diff, portanto inspecione o resultado antes de
transmitir.

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**Modo black box**: deixe `Chain` sem definir. O Fordefi assina os bytes exatos da sua mensagem
e não transmite. Use este modo com um vault black box do Fordefi.

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## Por que não existe um pacote guarda-chuva

O Rust tem um enum `Signer` e o TypeScript tem `createKeychainSigner`; o Go
deliberadamente não tem nenhum dos dois. O Go não elimina código morto através de um switch
de despacho em tempo de execução, então um pacote guarda-chuva forçaria o SDK de cada fornecedor de backend (AWS, GCP
e os demais) no build de todos os consumidores. Importar o pacote de backend de que você
precisa é o seletor. Para escolher um backend em tempo de execução, escreva o switch no seu próprio
código apenas para os backends que você suporta e guarde o resultado como um
`core.SolanaSigner`.

## Tratamento de erros

Todo erro é um `*core.SignerError` com um `Code` estável (`CodeConfigError`,
`CodeHTTPError`, `CodeRemoteAPIError`, `CodeSigningFailed`,
`CodeNotInitialized`, `CodeBroadcastUnconfirmed` e outros). `Error()` retorna
apenas uma mensagem fixa por código, nunca material de chave nem respostas brutas do provedor.
Faça a correspondência com `errors.As`, `errors.Is(err, &core.SignerError{Code: ...})` ou
`core.CodeOf(err)`.

No Crossmint e no modo native auto do Fordefi, uma falha não significa que nada
foi efetivado. Quando o provedor pode ter aceitado a transação, o código é
`core.CodeBroadcastUnconfirmed` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`ProviderTxID` é definido quando a criação foi aceita, e `IdempotencyKey` carrega
a chave derivada da mensagem. Reenviar a transação idêntica byte a byte é
seguro; uma reconstruída (por exemplo, com um novo blockhash) é uma nova transferência.
`core.SignAndSendTransaction` também informa esse código quando a sua função de envio
falha, com a assinatura do pagador da taxa em `TransactionSignature`. O PROGRAM_CALL
do Fireblocks é somente de assinatura e não envia nenhuma chave; ele informa esse código apenas quando uma
consulta mostra que o Fireblocks transmitiu mesmo assim.

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

Consulte o
[modelo de segurança](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md)
para saber o que cada formato de assinatura garante, o
[README do Go](https://github.com/solana-foundation/solana-keychain/blob/main/go/README.md)
para a lista completa de módulos e o
[pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2)
para a referência da API.

## Adicionando signers personalizados

Implemente `core.SolanaSigner` mais exatamente uma interface de capacidade e não adicione nenhum
método que o seu backend não possa cumprir: os chamadores detectam a capacidade por asserção de tipo.
Consulte o [guia Adding Signers](/docs/tools/keychain/adding-signers) para integrar
outros serviços de gerenciamento de chaves.
