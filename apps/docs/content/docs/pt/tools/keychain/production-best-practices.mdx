O Keychain abstrai o backend de assinatura, mas operar um assinante em produção ainda é sua responsabilidade. Essas práticas se aplicam a todos os backends; consulte [Escolhendo um backend](/docs/tools/keychain/choosing-a-backend) para selecionar um.

## Separe assinantes quentes e frios

Use um assinante operacional de baixo saldo ("quente") para transações frequentes e automatizadas, e um assinante separado de alto valor ("frio") para movimentações do tesouro. Proteja o assinante frio com custódia MPC ou um HSM em nuvem e exija políticas de aprovação antes que ele assine. Como a interface é idêntica, cada função pode usar um backend diferente sem alterar os pontos de chamada.

## Rotacione chaves de forma deliberada

No Solana, a chave de assinatura _é_ o endereço da conta, portanto, rotacionar uma chave gera um novo endereço. Planeje a rotação como uma migração: provisione uma nova chave, reatribua as autoridades relevantes (ou mova os fundos) para o novo endereço e, em seguida, desative o antigo. Use chaves distintas por ambiente para que as chaves da devnet nunca sejam reutilizadas na mainnet.

## Conceda acesso com privilégio mínimo

Limite as credenciais de cada backend ao mínimo necessário para assinar. Para o AWS KMS, isso é `kms:Sign` e `kms:DescribeKey` na chave específica; prefira funções IAM em vez de credenciais estáticas. Aplique o mesmo princípio às políticas do Vault e às chaves de API de carteiras gerenciadas.

## Planeje a disponibilidade

Backends remotos dependem de um serviço de rede. Chame `isAvailable()` antes de depender de um assinante, aplique tentativas com recuo exponencial em falhas transitórias e defina um caminho de fallback para interrupções. O Keychain aplica HTTPS para backends remotos e utiliza um tempo limite de requisição padrão.

## Proteja segredos e o transporte

- Todos os backends remotos se comunicam via HTTPS; endpoints não-HTTPS são rejeitados.
- Forneça chaves de API, tokens e credenciais a partir de um gerenciador de segredos ou variáveis de ambiente — nunca os codifique diretamente no código nem os envie para o controle de versão.
- O Keychain sanitiza as respostas de erro para evitar que segredos vazem nos logs; mantenha seus próprios registros livres de credenciais brutas e material de chave.

## Monitore e audite as assinaturas

Acompanhe a taxa de sucesso, a latência e a contagem de falhas das assinaturas, e configure alertas para picos — consulte as métricas em [Prontidão para Produção](/docs/tools/production-readiness#monitoring). Ative os logs de auditoria do provedor (KMS, Vault ou custodiante) e reconcilie-os com as transações que sua aplicação envia.
