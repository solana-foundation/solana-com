Esta seção fornece alguns comandos e exemplos comuns para ajudá-lo a começar a
usar a [CLI do Anchor](https://www.anchor-lang.com/docs).

<Steps>
<Step>

### Inicializar o projeto

Crie um novo projeto Anchor executando o comando mostrado abaixo. Ele criará um
novo diretório com o nome do projeto e o utilizará para inicializar um novo
projeto Anchor.

```terminal
$ anchor init <project-name>
```

Por exemplo, o comando abaixo criará um projeto chamado `my-project`. O
diretório `my-project` conterá um programa Rust modular e um modelo de testes em Rust
que usa o LiteSVM.

```terminal
$ anchor init my-project
```

Para gerar um modelo de testes em TypeScript, escolha um explicitamente. Por
exemplo, use o modelo Mocha:

```terminal
$ anchor init my-project --test-template mocha
```

Os modelos de testes em TypeScript exigem Node.js e um gerenciador de pacotes JavaScript.

Em seguida, navegue até o diretório do projeto:

```terminal
$ cd <project-name>
```

Consulte a
[estrutura de arquivos do projeto](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) do Anchor.

</Step>
<Step>

### Compilar o programa

Para compilar seu projeto, execute o seguinte comando:

```terminal
$ anchor build
```

Você pode encontrar o programa compilado no diretório `/target/deploy`.

<Callout type="warn" title="Falha na instalação das ferramentas da plataforma">
  Se a compilação indicar um diretório platform-tools inválido, reinstale as
  ferramentas de compilação SBF e tente compilar novamente:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Implantar o programa

Para implantar seu projeto, execute o seguinte comando:

```terminal
$ anchor deploy
```

Este comando implanta seu programa no `cluster` especificado no arquivo
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml).

</Step>
<Step>

### Testar o programa

Para testar seu projeto, execute o seguinte comando:

```terminal
$ anchor test
```

Este comando compila, implanta e executa os testes do seu projeto.

<Callout>
  Ao usar o cluster `localnet`, o Anchor inicia automaticamente um validador
  local, implanta o programa, executa os testes e depois para o validador.
</Callout>

<Callout type="warn" title="Erros do executor de testes JavaScript">

Se você selecionou um modelo de testes em JavaScript ou TypeScript, qualquer um dos
seguintes erros pode indicar que o Node.js ou o gerenciador de pacotes configurado
não está instalado:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
