A interface de linha de comandos `solana` configura a ligação a um cluster, lê o
estado da rede, envia SOL, gere nonces duráveis, implanta programas e opera
contas de stake e de voto.

Esta referência segue o
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Execute
`solana --version` para verificar a versão instalada e utilize `--help` para ver as
opções exatas disponíveis nessa versão.

<Callout type="warn">
  Os comandos que criam, transferem, autorizam, levantam ou implantam submetem
  transações. Confirme o cluster e o signatário configurados antes de os executar.
  Os tokens da Devnet e da Testnet não têm valor; os comandos da Mainnet usam SOL real.
</Callout>

## Estrutura dos comandos

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Obtenha ajuda em qualquer nível:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Opções globais

As opções globais podem ser colocadas antes do comando. A ajuda específica de cada comando repete
as opções que se aplicam a esse comando.

| Opção                          | Finalidade                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Seleciona um URL de RPC ou `mainnet-beta`, `testnet`, `devnet` ou `localhost`.      |
| `--ws <URL>`                    | Substitui o endpoint de WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Seleciona um ficheiro keypair, `ASK`, stdin (`-`) ou um URL de signatário suportado.          |
| `-C, --config <FILEPATH>`       | Utiliza um ficheiro de configuração da CLI diferente.                                        |
| `--commitment <LEVEL>`          | Lê com o nível de commitment `processed`, `confirmed` ou `finalized`.                   |
| `--output <FORMAT>`             | Devolve `json` ou `json-compact` quando suportado.                               |
| `--skip-preflight`              | Envia sem simulação de RPC. Utilize apenas quando compreender o compromisso associado a eventuais falhas. |
| `--use-tpu-client`              | Envia transações através do cliente TPU.                                      |
| `--no-address-labels`           | Apresenta os endereços sem etiquetas locais.                                          |
| `--skip-seed-phrase-validation` | Permite uma frase de recuperação fora da lista inglesa BIP39.                       |
| `-v, --verbose`                 | Mostra informação adicional na saída do comando.                                                |
| `-V, --version`                 | Apresenta a versão da CLI instalada.                                               |

## Configurar a CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

A configuração contém um URL de RPC, um URL de WebSocket, o signatário predefinido e o
commitment. Uma opção de linha de comandos substitui o valor guardado nessa invocação.

## Fluxos de trabalho comuns de contas e transações

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` aceita SOL por predefinição. Utilize `ALL` como montante para mover o saldo
disponível após as comissões. Para exemplos com tokens, consulte o
[guia de introdução aos tokens](/docs/tokens/quickstart).

## Fluxos de trabalho de programas

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Passe `--program-id <KEYPAIR_OR_ADDRESS>` quando uma implantação tiver de usar um
ID de programa conhecido. `--final` torna imutável uma nova implantação; leia atentamente a respetiva ajuda
antes de o utilizar, pois a autoridade de atualização não pode ser restaurada.

## Fluxos de trabalho de nonce durável

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Utilize `authorize-nonce-account` para alterar a autoridade do nonce e `nonce-account`
para inspecionar o estado completo da conta. As transações que utilizam um nonce também aceitam
`--nonce` e `--nonce-authority` nos comandos suportados.

## Fluxos de trabalho de stake

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

A desativação conclui-se no limite de um epoch e pode demorar mais do que um epoch.
Utilize `stakes`, `validators`, `stake-history` e `stake-minimum-delegation` para
inspecionar o estado do cluster e das delegações antes de submeter alterações.

## Utilitários de endereços

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

Os seeds de PDA usam `PREFIX:VALUE`. Os prefixos suportados incluem `string`, `pubkey`,
`hex`, `u8` e codificações de inteiros com largura fixa, com ou sem sinal, como
`u64le`.

## Mensagens off-chain e conclusão de shell

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Saída para scripts

Utilize `--output json` ou `--output json-compact` quando suportado, em vez de
analisar a saída legível por humanos:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Nem todos os comandos suportam saída estruturada. Consulte a ajuda do comando antes de
depender dela em automações e trate um estado de saída diferente de zero como falha.
