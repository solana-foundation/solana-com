A interface de linha de comando `solana` configura a conexão com um cluster, lê
o estado da rede, envia SOL, gerencia nonces duráveis, implanta programas e opera
contas de stake e de voto.

Esta referência segue o
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Execute
`solana --version` para verificar a versão instalada e use `--help` para ver as
opções exatas disponíveis nessa versão.

<Callout type="warn">
  Comandos que criam, transferem, autorizam, sacam ou implantam enviam
  transações. Confirme o cluster e o signatário configurados antes de executá-los.
  Os tokens da Devnet e da Testnet não têm valor; os comandos na Mainnet usam SOL real.
</Callout>

## Estrutura dos comandos

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Obtenha ajuda em qualquer nível:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Opções globais

As opções globais podem ser colocadas antes do comando. A ajuda específica de cada comando repete
as opções que se aplicam a ele.

| Opção                          | Finalidade                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Seleciona uma URL de RPC ou `mainnet-beta`, `testnet`, `devnet` ou `localhost`.      |
| `--ws <URL>`                    | Substitui o endpoint WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Seleciona um arquivo de keypair, `ASK`, stdin (`-`) ou uma URL de signatário compatível.          |
| `-C, --config <FILEPATH>`       | Usa um arquivo de configuração da CLI diferente.                                        |
| `--commitment <LEVEL>`          | Lê com o nível de commitment `processed`, `confirmed` ou `finalized`.                   |
| `--output <FORMAT>`             | Retorna `json` ou `json-compact` onde houver suporte.                               |
| `--skip-preflight`              | Envia sem simulação de RPC. Use apenas quando entender os riscos de falha. |
| `--use-tpu-client`              | Envia transações por meio do cliente TPU.                                      |
| `--no-address-labels`           | Imprime endereços sem rótulos locais.                                          |
| `--skip-seed-phrase-validation` | Permite uma frase de recuperação fora da lista em inglês do BIP39.                       |
| `-v, --verbose`                 | Mostra saída adicional do comando.                                                |
| `-V, --version`                 | Imprime a versão instalada da CLI.                                               |

## Configurar a CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

A configuração contém uma URL de RPC, uma URL de WebSocket, o signatário padrão e o
commitment. Uma opção de linha de comando substitui o valor salvo naquela invocação.

## Fluxos comuns de contas e transações

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` aceita SOL por padrão. Use `ALL` como valor para mover o saldo disponível
depois das taxas. Para exemplos com tokens, consulte o
[guia rápido de tokens](/docs/tokens/quickstart).

## Fluxos de programas

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Passe `--program-id <KEYPAIR_OR_ADDRESS>` quando uma implantação precisar usar um
ID de programa conhecido. `--final` torna uma nova implantação imutável; leia a ajuda com atenção
antes de usá-lo, pois a autoridade de atualização não pode ser restaurada.

## Fluxos de nonce durável

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Use `authorize-nonce-account` para alterar a autoridade do nonce e `nonce-account`
para inspecionar o estado completo da conta. As transações que usam um nonce também aceitam
`--nonce` e `--nonce-authority` nos comandos compatíveis.

## Fluxos de stake

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

A desativação é concluída no limite de um epoch e pode levar mais de um epoch.
Use `stakes`, `validators`, `stake-history` e `stake-minimum-delegation` para
inspecionar o estado do cluster e das delegações antes de enviar alterações.

## Utilitários de endereço

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

Os seeds de PDA usam `PREFIX:VALUE`. Os prefixos compatíveis incluem `string`, `pubkey`,
`hex`, `u8` e codificações de inteiros com largura fixa, com ou sem sinal, como
`u64le`.

## Mensagens off-chain e autocompletar do shell

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Saída para scripts

Use `--output json` ou `--output json-compact` onde houver suporte, em vez de
analisar a saída legível por humanos:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Nem todo comando oferece suporte a saída estruturada. Verifique a ajuda do comando antes de
depender dela em automações e trate um status de saída diferente de zero como falha.
