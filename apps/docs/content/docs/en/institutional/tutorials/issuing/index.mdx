These three tutorials build one token, in order. They end with a Token-2022 mint
on devnet whose accounts start frozen, whose holders are gated by an onchain
allowlist, and whose pause, forced-transfer, and metadata powers sit on separate
keys.

They use [Mosaic](https://github.com/solana-foundation/mosaic), the Solana
Foundation's open-source issuance toolkit. Mosaic encodes extension
configurations as templates, which keeps the tutorials focused on the decisions
involved rather than on assembling instructions by hand.

## Before you start

These tutorials need the Solana CLI, Node.js, and a funded devnet keypair.
Everything below runs on devnet.

```bash
# Solana CLI, if you do not already have it
sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"

solana-keygen new --outfile ~/.config/solana/institutional-demo.json
solana config set --url https://api.devnet.solana.com
solana airdrop 2 --keypair ~/.config/solana/institutional-demo.json
```

Install the Mosaic CLI:

```bash
npm install -g @solana/mosaic-cli@0.1.2
mosaic --help
```

<Callout type="warn">

Mosaic is pre-1.0 and under active development. These tutorials were written
against `@solana/mosaic-cli@0.1.2`, which the install above pins. Check the
[repository](https://github.com/solana-foundation/mosaic) for the current
command surface before adapting them beyond devnet, and keep the pin in any
pipeline that depends on it.

One pending change matters to this chain: at 0.1.2 the `tokenized-security`
template does not enable permissioned burn, and a later release adds it. If you
unpin, recheck what
[operate the token](/docs/institutional/tutorials/issuing/operate-the-token)
says about who can burn.

</Callout>

Every Mosaic command accepts two global flags:

| Flag               | Purpose                                                 |
| ------------------ | ------------------------------------------------------- |
| `--rpc-url <url>`  | The RPC endpoint to use. Defaults to devnet             |
| `--keypair <path>` | The signing keypair. Defaults to your Solana CLI config |

The tutorials pass both explicitly so each command runs on its own.

## If you cannot run a CLI in your pipeline

Mosaic exposes the same operations as a library, and all of them build ordinary
Token-2022 and Token ACL instructions. Three paths, in order of increasing
control:

1. **The Mosaic CLI** - these tutorials.
2. **The Mosaic SDK** - `@solana/mosaic-sdk`, the same templates as library
   calls.
3. **Direct instruction building** - see
   [launch a token](/docs/tokenization/quickstart) for the Kit, legacy
   TypeScript, and Rust equivalents, and
   [token extensions](/docs/tokens/extensions) for each extension's API.

Where a pre-1.0 CLI cannot be introduced into a build pipeline, these tutorials
still describe the sequence, which can be implemented with option 2 or 3.
