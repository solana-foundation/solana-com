[Anchor](https://www.anchor-lang.com/docs) is a Rust framework that simplifies
writing, testing, deploying, and interacting with Solana
<span className="sol-chip" data-concept="program"><Tooltip headline="Programs" tip="Programs are code deployed to the network that owns and updates accounts. Most apps call existing programs, such as the Token program, rather than writing their own." cta="Learn more" href="/developers/docs/core/programs">programs</Tooltip><span className="nojs-only"> ([Programs](/developers/docs/core/programs): Programs are code deployed to the network that owns and updates accounts. Most apps call existing programs, such as the Token program, rather than writing their own.)</span>.</span> The first-program tutorial in these docs uses it.

## What Anchor does for you

- **Account validation.** You declare the
  <span className="sol-chip" data-concept="account"><Tooltip headline="Accounts" tip="Everything on Solana (balances, tokens, programs, app data) lives in accounts: records at an address, each with an owner that is allowed to change it." cta="Learn more" href="/developers/docs/core/accounts">accounts</Tooltip><span className="nojs-only"> ([Accounts](/developers/docs/core/accounts): Everything on Solana (balances, tokens, programs, app data) lives in accounts: records at an address, each with an owner that is allowed to change it.)</span></span> each
  instruction expects, with constraints such as owner, signer, and
  <span className="sol-chip" data-concept="pda"><Tooltip headline="Program-derived addresses" tip="A PDA is an address derived from a program plus some seeds. It has no private key, so only that program can sign for it, which makes it handy for storing app state at predictable addresses." cta="Learn more" href="/developers/docs/core/pda">PDA</Tooltip><span className="nojs-only"> ([Program-derived addresses](/developers/docs/core/pda): A PDA is an address derived from a program plus some seeds. It has no private key, so only that program can sign for it, which makes it handy for storing app state at predictable addresses.)</span></span> seeds, and Anchor
  checks them before your code runs.
- **Serialization.** Instruction arguments and account data are encoded and
  decoded for you.
- **An IDL.** Anchor generates an
  [IDL](/developers/docs/programs/idls), a JSON description of your program's interface.
  Clients and tools such as [Codama](/developers/docs/programs/codama/clients) use it to
  generate typed clients.
- **A CLI and project template.** `anchor init`, `anchor build`, `anchor test`,
  and `anchor program deploy` cover the whole loop. A new project includes a Rust test
  template that uses [LiteSVM](/developers/docs/tools/litesvm).
