The Lisbon Solar Fund (LSF) is a demo asset whose token accounts start
**frozen**. An account can receive LSF only after the issuer approves it. Below,
the issuer approves two investors, then a holder sends LSF to an approved
investor and to an account nobody approved. Last, the issuer uses two more
controls: a pause and a clawback. Press **Run** to step through this tutorial's
code on a local test network (Surfpool). Nothing is sent from your browser, and
you need no code or wallet.

The holder, the token, and the instruction were the same both times, but only
one transfer settled. The rule lives in the token, so it applies in every
wallet and app.

## Why the transfer failed

Every new LSF token account opens in the `Frozen` state. The issuer approves an
investor after a KYC check by **thawing** their account, which is what "Approve
two investors" did. Nobody approved the third account, so the
<span className="sol-chip" data-concept="program"><Tooltip headline="Programs" tip="Programs are code deployed to the network that owns and updates accounts. Most apps call existing programs, such as the Token program, rather than writing their own." cta="Learn more" href="/developers/docs/core/programs">Token-2022 program</Tooltip><span className="nojs-only"> ([Programs](/developers/docs/core/programs): Programs are code deployed to the network that owns and updates accounts. Most apps call existing programs, such as the Token program, rather than writing their own.)</span></span>
refused to credit it. Here are the lines from step 2 (excerpt):

```text title="Failed transfer (excerpt of the output)"
Opened FecRDHyzRTLH3dfdz6ni5pnGq5j883zcSBToSe3PPdbP state: Frozen
Transfer 1 LSF: failed onchain
  err: {"InstructionError":[0,{"Custom":17}]}
  log: Program log: Error: Account is frozen
  fee paid anyway: 5000 lamports
Transfer 1 LSF: rejected: Custom program error: #17 (instruction #1)
  accountFrozen: true (no fee: it never landed)
```

How to read it:

- `{"InstructionError":[0,{"Custom":17}]}` means instruction 0 of the
  transaction failed with Token-2022 error 17, `AccountFrozen`. The program log
  says the same in words: `Account is frozen`.
- Transactions are all-or-nothing. The failed transfer moved no tokens: the
  unapproved account still holds 0 LSF.
- This transfer was sent with `skipPreflight`, so it landed onchain as a failed
  transaction and the sender still paid the 5000-lamport network fee.
- Sent the normal way, with preflight, the RPC node simulates the transaction
  first and rejects it before it lands. No fee is charged, and your code gets
  the same error 17 back (`accountFrozen: true`).

Step 3 of the run shows the other two controls. While the asset is paused,
every transfer fails with error 67 (`Transferring, minting, and burning is
paused on this mint`). After it resumes, the issuer, as **permanent delegate**,
moves 50 LSF out of an investor's account without their signature, the control
for carrying out a court order or recovering lost tokens.
