Put a price of 0.001 USDC on an HTTP endpoint and have a client pay it
automatically, request by request. You call a paid API, read the server, then
run both yourself.

The protocol is [x402](https://www.x402.org/). It uses the HTTP status code
`402 Payment Required`:

1. **Request.** The client calls `GET /api/forecast` as usual.
2. **Quote.** The server answers `402 Payment Required` with a price, the token
   it accepts (USDC), and the address to pay.
3. **Pay.** The client signs a USDC transfer for that price.
4. **Retry.** The client sends the same request again, with the signed
   transfer in a payment header.
5. **Return.** The server checks the transfer, sends it to the network, waits for
   it to confirm, and returns the data with the transaction signature as a
   receipt.

**Time:** about 30 minutes. **You need:** nothing for steps 1 and 2. For step
3, Node.js 24, pnpm, and git; the local test network runs from npm.

<Note>
  This tutorial implements x402 directly on `@solana/kit` so you can see every
  check. It uses the x402 version 1 message shapes (the `X-PAYMENT` header) and
  is not the x402 SDK. For production, use the x402 version 2 packages
  (`@x402/express`, `@x402/fetch`, `@x402/svm`) and a facilitator, as step 4
  describes.
</Note>

## Is this the right tool?

|                           | Card billing                 | Credits and API keys          | x402 on Solana            |
| ------------------------- | ---------------------------- | ----------------------------- | ------------------------- |
| Smallest charge           | Set by fixed per-charge fees | A prepaid top-up              | A fraction of a cent      |
| Client setup              | An account and a card        | A signup, a key, and a balance | A wallet with USDC        |
| Works for AI agents       | Needs a person-issued card   | After a person sets it up     | Yes, with its own wallet  |
| Billing code you maintain | Invoices, retries, disputes  | A balance ledger              | Receipts, refunds, and a used-payment store |

<Columns cols={2}>
<Card title="A good fit if" icon="check" color="#16a34a">
- You want to price per request, per page, or per unit of compute
- Your clients are programs or AI agents, not people at a checkout
- You don't want to run signups, API keys, and balances
</Card>
<Card title="Not the right fit if" icon="x" color="#dc2626">
- You charge one flat monthly fee: use your existing billing
- Your buyers need invoices and payment terms
- Every request must answer in a few milliseconds, including the first paid one: each paid request waits for its payment to confirm
</Card>
</Columns>
