Start as the client. The API below sells tomorrow's forecast for 0.001 USDC per
request. The client is a script with its own wallet of test USDC, so it pays
without a person approving each call. Press **Run** to step through this
tutorial's code on a local test network (Surfpool). Nothing is sent from your
browser, and no real money moves.

<Demo />

What happened:

- The first call got `402 Payment Required`. The body listed the price as
  `1000` base units of USDC (USDC has 6 decimals, so that is 0.001 USDC), the
  USDC mint address, the address to pay (`payTo`), and the network.
- The client signed a USDC transfer for exactly that amount and sent the same
  request again with the signed transfer in the `X-PAYMENT` header.
- The server sent the transfer to the network, waited for it to confirm, and
  answered `200` with the forecast. The network fee for that

  5,000 lamports (0.000005 SOL).

The addresses and signatures exist only on the local network. The `network`
field still shows the devnet ID (`solana:EtWT…xqa1`), the default `NETWORK` in
`x402.ts`.

## Requests that don't get the forecast

The server and the client both refuse payments that don't fit. The first
request resends the `X-PAYMENT` header from the paid request above. The second
comes from a client capped below the price.

## Why 402?

HTTP has reserved status code 402 "Payment Required" since 1997 without
defining how to pay. [x402](https://www.x402.org/) is an open protocol that fills that
gap: the 402 response lists the payments the server accepts, and the client
retries with a signed payment in a header. On Solana the network fee is a
fraction of a cent, so a price of a tenth of a cent still works.
