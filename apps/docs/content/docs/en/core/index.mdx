Solana is a public network of computers, called validators, that all keep the
same copy of one shared record. The record is made of accounts: some hold data,
such as token balances, and some hold code, called programs, that the network
runs. Apps and wallets make changes by sending the network transactions, which
usually settle in under a second and cost a fraction of a cent.

Seven concepts make up Solana's execution model. Start with Accounts and
Programs, then see how Instructions become Transactions. PDAs, CPIs, and Fees
build on those. The diagram below follows one transaction from your app,
through the network, to your program and back.

<Columns cols={2}>
  <Card title="Accounts" href="/developers/docs/core/accounts">
    All state lives in accounts, keyed by 32-byte addresses. Each has five
    fields: lamports, data, owner, executable, and rent_epoch.
  </Card>
  <Card title="Programs" href="/developers/docs/core/programs">
    Solana's smart contracts, compiled to sBPF. Programs are stateless: their
    data lives in separate accounts passed in by instructions.
  </Card>
  <Card title="Instructions" href="/developers/docs/core/instructions">
    A call to one program: its ID, the accounts it uses, and data bytes. One
    transaction can hold several.
  </Card>
  <Card title="Transactions" href="/developers/docs/core/transactions">
    Signatures plus a message (accounts, a recent blockhash, and
    instructions) that runs all or nothing. Max 1,232 bytes, or 4,096 with the
    v1 format.
  </Card>
  <Card title="Fees" href="/developers/docs/core/fees">
    5,000 lamports per signature, plus an optional priority fee per compute
    unit requested. Max 1.4M compute units per transaction.
  </Card>
  <Card title="Program-derived addresses (PDAs)" href="/developers/docs/core/pda">
    Addresses derived from a program ID and seeds. Only that program can sign
    for a PDA, via invoke_signed.
  </Card>
  <Card title="Cross-Program Invocations (CPIs)" href="/developers/docs/core/cpi">
    One program calling another via invoke or invoke_signed. Signer and writable
    privileges carry over. Max stack depth of 5, including the top-level
    instruction (9 with SIMD-0268).
  </Card>
</Columns>
