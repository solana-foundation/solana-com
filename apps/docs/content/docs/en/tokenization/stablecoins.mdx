A stablecoin is a token redeemable for a reference currency. The token is the
issuer's liability, and the reserve backing it is held separately;
[token design](/docs/tokenization/design) treats this as the model in which the
token is the asset.

## The sequence

1. **[Design the token](/docs/tokenization/design)** - confirm which register
   governs the liability and how the reserve is evidenced, then choose the token
   program and lay out the authorities that mint, freeze, and pause.
2. **[Choose transfer controls](/docs/tokenization/design/choosing-controls)** -
   which controls the asset needs, and which ones constrain the payment flows
   below.
3. **[Evidence compliance](/docs/tokenization/compliance)** - binding a KYC or
   sanctions decision to an address without publishing personal data.
4. **[Gate the holders](/docs/tokenization/compliance/token-acl)** - allowlists
   and blocklists, where holder eligibility is restricted.
5. **[Integrate custody](/docs/tokenization/custody)** - what a custodian needs
   from the mint before it can hold or distribute the token.
6. **[Operate it](/docs/tokenization/tutorials)** - build a gated, operable mint
   and run the supply operations against it.

## Where it gets used

A stablecoin is issued to be paid with. [Payments](/docs/payments) is the
integration surface for accepting, sending, and reconciling stablecoin flows,
and [choose the cash leg](/docs/tokenization/settlement/cash-leg) covers the
case where the stablecoin is the cash side of a settlement against another
asset.
