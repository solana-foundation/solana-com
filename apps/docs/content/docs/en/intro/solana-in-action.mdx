  <li>
    <p className="sol-inaction-step-t">
      Play opens a game account and a session key
    </p>
    <p>
      Your board and score live in a small account that the 2048 program owns.
      Play also creates a session key: a short-lived key, funded with a little
      devnet SOL, that the program accepts for moves, so you don't approve every
      one.
    </p>
  </li>
  <li>
    <p className="sol-inaction-step-t">Each arrow key sends a transaction</p>
    <p>
      The transaction holds one instruction, `push_in_direction`, with the
      direction you pressed. The session key signs it and pays the fee, a
      fraction of a cent.
    </p>
  </li>
  <li>
    <p className="sol-inaction-step-t">The program updates your board</p>
    <p>
      The 2048 program merges the tiles and writes the new board and score to
      your game account, and updates the high-score list. It all happens in one
      transaction: every change, or none.
    </p>
  </li>
  <li>
    <p className="sol-inaction-step-t">
      The game shows the move before it's final
    </p>
    <p>
      To feel instant, the game draws the result as soon as a validator
      processes the transaction, and rolls the move back if the network doesn't
      confirm it.
    </p>
  </li>
</ol>
