Do these steps in order. Run commands in the user's project folder. Ask before changing anything outside it.

In most agents, Claude Code included, an MCP server added during a session only loads in the next session. So this setup normally ends with the user restarting the agent. That's expected, not a failure.

1. **Add the Solana MCP server.** If `npx` isn't found, Node may be managed by a version manager that only loads in interactive shells; try loading it (nvm: `source ~/.nvm/nvm.sh`, fnm: `eval "$(fnm env)"`). If there's still no `npx`, don't install Node: the direct setup below doesn't need it.
   - With `npx`: run `npx add-mcp https://mcp.solana.com/mcp -n solana-mcp -g -y`. It finds the agents installed on this machine and adds the server to each, without prompting.
   - Without `npx`, or if `add-mcp` fails, add it to the agent you're running in:
     - Claude Code: `claude mcp add --transport http solana-mcp https://mcp.solana.com/mcp`
     - Codex: `codex mcp add solana-mcp --url https://mcp.solana.com/mcp`
     - Cursor: add `{"mcpServers": {"solana-mcp": {"url": "https://mcp.solana.com/mcp"}}}` to `.cursor/mcp.json`.
     - VS Code: add `{"servers": {"solana-mcp": {"type": "http", "url": "https://mcp.solana.com/mcp"}}}` to `.vscode/mcp.json`.
     - Windsurf: add `{"mcpServers": {"solana-mcp": {"serverUrl": "https://mcp.solana.com/mcp"}}}` to `~/.codeium/windsurf/mcp_config.json`.
2. **Install the Solana skill.** First check whether `solana-dev` is already installed: if you have `npx`, run `npx skills list` and `npx skills list -g`; either way, look for a `solana-dev` folder in your agent's skills directories (for example `.claude/skills/` or `~/.claude/skills/`).
   - Not installed, with `npx`: run `npx skills add https://github.com/solana-foundation/solana-dev-skill -y`.
   - Not installed, without `npx`: use the skill's install script, which only needs `git` and `bash`. From the project folder, run `git clone --depth 1 https://github.com/solana-foundation/solana-dev-skill /tmp/solana-dev-skill && bash /tmp/solana-dev-skill/install.sh --project`. It copies the skill into `.agents/skills/` and `.claude/skills/`.
   - Installed: compare `metadata.version` in its `SKILL.md` with the latest in [the upstream SKILL.md](https://raw.githubusercontent.com/solana-foundation/solana-dev-skill/main/skills/solana-dev/SKILL.md). If it's current, leave it.
   - Older, and listed by `npx skills list`: update it in place with `npx skills update solana-dev -y`.
   - Older, and not managed by the skills CLI (for example a symlink into a dotfiles repo): don't overwrite it or write through the link. Tell the user both versions and where the link points, and ask how they want to update it.
3. **Check it works.** If the Solana MCP tools are available to you, search the docs for "transaction fees" and summarise the answer in one sentence. If they aren't loaded yet, check that the server responds over HTTP instead:

   ```bash
   curl -s -X POST https://mcp.solana.com/mcp \
     -H 'Content-Type: application/json' \
     -H 'Accept: application/json, text/event-stream' \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"Solana_Documentation_Search","arguments":{"query":"transaction fees"}}}'
   ```

   If that returns results, the setup worked; tell the user to restart the agent so it loads the Solana MCP tools.
4. **Tell the user what you did** in two lines, including whether they need to restart. Then offer to start the Quickstart (`/developers/docs/quickstart`): check a devnet balance, send test dollars (USDC), create an asset, send it to someone, and freeze their account. Ask before running anything that spends SOL or USDC. The Quickstart only uses devnet.
