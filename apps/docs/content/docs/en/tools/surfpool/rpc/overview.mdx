Surfnet is Surfpool's local Solana network simulator, designed to provide
developers with a testing environment that mimics the behavior of the
Solana blockchain without the overhead of a full validator node.

## Getting Started

Start a Surfnet instance using the Surfpool CLI:

```bash
surfpool start
```

This will start a local Surfnet instance on `http://localhost:8899` with the RPC
endpoints available.

## Key Features

- **Broad RPC Compatibility**: Supports most of the Solana RPC API (see
  [Limitations](#limitations) for the methods that behave differently)
- **Fast Iteration**: No need to wait for block confirmations
- **State Manipulation**: Cheatcodes for directly modifying blockchain state
- **Mainnet Fork**: Fork from mainnet to test with real accounts and programs
- **Geyser Plugin Support**: Connect your Geyser plugins for real-time data
  streaming

## Limitations

Surfnet is a simulator, so a few standard methods return empty or default data
or are not supported:

- `getHighestSnapshotSlot` returns error `-32008` (`No snapshot`).
- `getLeaderSchedule` returns `{}`, and `getRecentPerformanceSamples` returns
  synthetic samples with zero transactions.
- `getBlocks` returns `[]` with `--offline` and the datasource's slots when
  forking.
- `getSlotLeaders` returns a single placeholder leader and fails only for epochs
  without a leader schedule.
- `getSupply` returns all zeros until you call `surfnet_setSupply`.
- `blockSubscribe`, `voteSubscribe`, and `slotUpdatesSubscribe` are not
  supported over WebSocket.
- Most Agave validator admin methods are not implemented (see
  [Admin](/developers/docs/tools/surfpool/rpc/admin)).
- Request samples assume a Surfnet that forks mainnet (the default). On a
  Surfnet started with `--offline`, methods that read accounts or token data
  from the datasource return empty results or `not found` errors.
