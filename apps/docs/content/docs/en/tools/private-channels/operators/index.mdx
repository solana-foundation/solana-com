## What is a Private Channels Operator?

An operator is a trusted, onchain-permissioned entity that bridges Solana
Mainnet and the private channel network. Operators are provisioned by the
instance admin via `AddOperator`, which creates an onchain `Operator` PDA;
without this, no party can call `ReleaseFunds`. In practice, an operator is an
organization or team running the services that watch for deposits, mint
channel-side tokens, detect withdrawals, and settle funds back to Mainnet.
Running an instance gives your users private, high-volume transfers that don't
appear on Solana Mainnet, instant zero-fee throughput beyond native Solana TPS,
and controlled access via RBAC.

<Info>
  If you're a developer integrating against an existing Private Channels
  instance rather than deploying one, start with the
  [Quickstart](/developers/docs/tools/private-channels/quickstart/installation) instead.
</Info>

## Before You Start

### Prerequisites

Pin these versions on the host to match the Docker images:

- Docker Engine 26+ (macOS Apple Silicon: enable "Docker VMM" in Settings ->
  Virtual Machine Options)
- Node.js **24** and pnpm **10.15.1**, the versions the repository's
  Dockerfile and `versions.env` use
- Solana CLI **3.1.13** (Agave; upstream `main` uses 4.2.2)
- Rust **1.91.0** (upstream `main` uses 1.96+)
- A Yellowstone gRPC endpoint for Devnet (available from Helius, Triton,
  QuickNode)

For network requirements and default port assignments, see
[`docs/TECHNICAL_REQUIREMENTS.md`](https://github.com/solana-foundation/solana-private-channels/blob/main/docs/TECHNICAL_REQUIREMENTS.md)
in the repository.

Install the pinned Solana toolchain and warm the SBF cache:

```bash
make install-toolchain
```

### Services

Running a Private Channels instance means owning five ongoing responsibilities,
each handled by dedicated containers in the Docker Compose stack:

1. **Index Mainnet for deposits** - `indexer-solana` watches Solana Mainnet for
   `Deposit` events via Yellowstone gRPC; `operator-solana` picks up confirmed
   deposits and mints the equivalent token balance on the channel network
2. **Index the channel for withdrawals** - `indexer-private-channel` polls the
   channel every second for `WithdrawFunds` burn events and writes pending
   withdrawal records to the database
3. **Release funds on Mainnet** - `operator-private-channel` picks up pending
   records and calls `ReleaseFunds` on the Escrow Program, which consumes the
   withdrawal's nonce in the instance's withdrawal bitmap
4. **Rotate the withdrawal bitmap** - `operator-private-channel` calls
   `RotateBitmap` to move the bitmap to the next generation of 65,536 nonces;
   the onchain bitmap check, which releases each nonce at most once and only
   within the current generation, is the last line of defense against replayed
   withdrawals
5. **Run the gateway and auth service** - the gateway is the single public
   endpoint for all client traffic; the auth service (optional) enforces
   JWT/RBAC when `JWT_SECRET` is set

For the full service inventory and port assignments, see the
[Configuration reference](/developers/docs/tools/private-channels/operators/configuration).

> **Security note:** Write-node and read-node ports are bound to loopback
> (`127.0.0.1`) only, as is Grafana, but several other services (gateway, auth,
> operator metrics, Prometheus, cAdvisor) are published to all network
> interfaces by default. See the
> [Configuration reference](/developers/docs/tools/private-channels/operators/configuration#service-port-reference)
> for the full port table and firewall these before any public-facing
> deployment. RBAC only covers the gateway's own JSON-RPC methods, not these
> other services.

### Access Control: Open vs. RBAC

By default the gateway accepts all connections; no tokens required. To enable
JWT-based RBAC, set `JWT_SECRET` and start the stack with `--profile auth`. See
**[Authentication & Roles](/developers/docs/tools/private-channels/concepts/auth)** for the
full configuration reference, including how to provision the `operator` role and
register user wallets.

If enabling auth, add these to your environment before starting the stack:

```bash
JWT_SECRET=<openssl rand -hex 32>   # must match on gateway and auth service
AUTH_PORT=8903
```

## Environment Setup

`.env.devnet` is already tracked in the repository with devnet-specific defaults
filled in; edit it directly rather than regenerating it from `.env.example`,
which would overwrite those defaults.

Fill in the remaining values as you work through the deploy steps below; some
are only available mid-deployment. Secrets go in the gitignored `.env` file;
non-secret variables go in `.env.devnet`.

**Secrets - set these immediately:**

```bash
POSTGRES_PASSWORD=<openssl rand -hex 32>
POSTGRES_REPLICATION_PASSWORD=<openssl rand -hex 32>
```

**Variables obtained during deployment:**

```bash
ESCROW_INSTANCE_ID=<instance address - from Step 3>
ADMIN_PRIVATE_KEY=<operator keypair as u8 array or base58 - from Step 4>
DEVNET_RPC_URL=https://api.devnet.solana.com
DEVNET_YELLOWSTONE_ENDPOINT=<your Yellowstone gRPC endpoint>
INDEXER_YELLOWSTONE_TOKEN=<your Yellowstone auth token>
```

<Warning>
  `ADMIN_PRIVATE_KEY` is the offchain services' own required fee-payer signer,
  unrelated to the onchain instance admin from Step 3. This guide puts the
  **operator** keypair generated in Step 4 below into `ADMIN_PRIVATE_KEY` and
  leaves the optional `OPERATOR_PRIVATE_KEY` unset, so the operator signer falls
  back to the same key. Never put the protocol-level instance admin keypair from
  Step 3 into either variable.
</Warning>

For the full environment variable reference, see
**[Configuration](/developers/docs/tools/private-channels/operators/configuration)**.

## Deploy

<Steps titleSize="h3">

<Step title="Build images">

```bash
make docker-devnet-build
```

This compiles all Rust services into a shared Docker image. The first build
takes 30 minutes to an hour.

</Step>

<Step title="Set up instance management tooling">

You create and configure the escrow instance (`CreateInstance`, `AllowMint`,
`AddOperator`) with the CLI binaries in
[`scripts/devnet`](https://github.com/solana-foundation/solana-private-channels/tree/main/scripts/devnet),
run from the repository root. They read their signers from keypair files, so
create those first:

```bash
mkdir -p keypairs
# Escrow admin (Instance.admin): signs create_instance, allow_mint, add_operator
solana-keygen new -o ./keypairs/escrow-admin.json -s --no-bip39-passphrase
# User: holds the whitelisted token, signs deposit and withdraw
solana-keygen new -o ./keypairs/user.json -s --no-bip39-passphrase
```

The binaries compile against the Codama-generated escrow and withdraw clients,
which are not checked in. Install the program dependencies and generate the
clients before the first `cargo run`:

```bash
make install
make generate-clients
```

The scripts build their instructions from the current program source, so the
escrow program they call must be built from the same source. Check when the
devnet program was last deployed:

```bash
solana program show 9tgHa1DcnaSSUtmMsst8ovKTe1Gfxzezn27KnH9xXYeU --url devnet   # note "Last Deployed In Slot"
solana block-time <LAST_DEPLOYED_SLOT> --url devnet
git log -1 --format="%ci %s" -- private-channel-escrow-program/program
```

If the source changed after the deploy, `create_instance` fails (for example
with `NotEnoughAccountKeys`). Redeploy the programs from your checkout as
described in
[Step 0 of the devnet quickstart](https://github.com/solana-foundation/solana-private-channels/blob/main/docs/DEVNET_QUICKSTART.md#step-0-check-the-on-chain-programs-are-current-upgrade-if-stale).

</Step>

<Step title="Create an escrow instance">

Ensure the escrow admin keypair has Devnet SOL for fees (use the
[Solana Faucet](https://faucet.solana.com/) if needed), then run the CLI script
from `scripts/devnet`, which creates the instance and prints its address
(`escrow_instance_id`). Set that address as `ESCROW_INSTANCE_ID` in
`.env.devnet`.

```bash
cargo run --bin create_instance -- \
  https://api.devnet.solana.com \
  ./keypairs/escrow-admin.json
```

</Step>

<Step title="Generate an operator keypair">

```bash
solana-keygen new -o operator-keypair.json -s --no-bip39-passphrase
solana-keygen pubkey operator-keypair.json
```

Set the keypair contents as `ADMIN_PRIVATE_KEY` in your environment. The public
key isn't an environment variable; you'll pass it directly as the operator
pubkey in the "Configure the instance" step below.

</Step>

<Step title="Finalize environment variables">

Update `.env.devnet` with `ESCROW_INSTANCE_ID`, `DEVNET_RPC_URL`,
`DEVNET_YELLOWSTONE_ENDPOINT`, and `INDEXER_YELLOWSTONE_TOKEN`. Put secrets
(`POSTGRES_PASSWORD`, `POSTGRES_REPLICATION_PASSWORD`, `ADMIN_PRIVATE_KEY`) in
the gitignored `.env` file.

If you decided to enable RBAC
([Access Control: Open vs. RBAC](#access-control-open-vs-rbac)), also add
`JWT_SECRET` and `AUTH_PORT` now.

</Step>

<Step title="Start all services">

Without auth:

```bash
make docker-devnet-up
```

With auth:

```bash
docker compose -f docker-compose.devnet.yml --env-file versions.env --env-file .env.devnet --env-file .env --profile auth up -d
```

Compose disables its automatic `.env` auto-load once any `--env-file` flag is
passed, so the trailing `--env-file .env` is required. Without it,
`POSTGRES_PASSWORD`, `ADMIN_PRIVATE_KEY`, and `JWT_SECRET` (which you put in
`.env` above) resolve empty and the stack fails to start correctly.

> Start services before configuring the instance. The indexer streams events in
> real time, so bringing the stack up first ensures `AllowMint` and your first
> deposit are indexed in order without needing a backfill.

</Step>

<Step title="Configure the instance">

With the stack running, whitelist a token mint and add your operator using the
`scripts/devnet` cargo binaries.

1. **Allow Mint**: whitelist the token mint you want to support (for example
   Devnet USDC, `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`):

   ```bash
   cargo run --bin allow_mint -- \
     https://api.devnet.solana.com \
     ./keypairs/escrow-admin.json \
     <INSTANCE_ID> \
     <MINT_ADDRESS>
   ```

2. **Add Operator**: register the operator public key from the "Generate an
   operator keypair" step:

   ```bash
   cargo run --bin add_operator -- \
     https://api.devnet.solana.com \
     ./keypairs/escrow-admin.json \
     <INSTANCE_ID> \
     <OPERATOR_PUBKEY>
   ```

</Step>

</Steps>

<Warning>

This guide targets Solana devnet. For Mainnet:

- Program IDs are compiled in via `declare_id!()`: verify you are using the
  correct Mainnet IDs from the repository
- Yellowstone gRPC endpoints require a Mainnet plan; devnet endpoints will not
  stream Mainnet events
- The operator wallet pays SOL fees for every `ReleaseFunds` call, so size the
  SOL balance for your expected withdrawal volume
- Change all default credentials (Grafana, PostgreSQL) before any public-facing
  deployment

</Warning>

## Operations

### Instance Administration

The escrow admin keypair manages the instance after setup. `scripts/devnet`
covers mint gating as well as the setup commands above. `block_mint` sets the
deposit and withdrawal gates for an allowed mint; both flags are absolute, so
passing `false` re-opens that gate, and blocking deposits leaves escrowed
balances withdrawable:

```bash
cargo run --bin block_mint -- \
  https://api.devnet.solana.com \
  ./keypairs/escrow-admin.json \
  <INSTANCE_ID> \
  <MINT_ADDRESS> \
  <BLOCK_DEPOSITS> \
  <BLOCK_WITHDRAWALS>
```

Revoking an operator and transferring the admin role have no CLI script; send
the [RemoveOperator](/developers/docs/tools/private-channels/instructions/remove-operator)
and [SetNewAdmin](/developers/docs/tools/private-channels/instructions/set-new-admin)
instructions with the generated
[escrow program clients](https://github.com/solana-foundation/solana-private-channels/tree/main/private-channel-escrow-program/clients).

### Useful Commands

```bash
# View logs (all services)
make docker-devnet-logs

# View logs (specific service)
docker compose -f docker-compose.devnet.yml --env-file versions.env --env-file .env.devnet logs -f indexer-solana

# Stop services
make docker-devnet-down

# Stop and wipe all state (volumes)
make docker-devnet-clean
```

### Observability

The stack includes Prometheus, Grafana, and cAdvisor for metrics and container
monitoring. Grafana is accessible on port `37429` (bound to `127.0.0.1` only).

<Warning>
  The default Grafana password is `admin`. Change it before exposing port 37429
  to any network beyond localhost.
</Warning>

## Troubleshooting

### Channel balance not updating after deposit

1. Confirm the Mainnet deposit transaction landed on a Mainnet explorer
2. Verify `indexer-solana` is running:
   `docker compose -f docker-compose.devnet.yml --env-file versions.env --env-file .env.devnet logs -f indexer-solana`
3. Verify `operator-solana` is running:
   `docker compose -f docker-compose.devnet.yml --env-file versions.env --env-file .env.devnet logs -f operator-solana`
4. Check that your Yellowstone gRPC endpoint is reachable and the token is valid
   (`DEVNET_YELLOWSTONE_ENDPOINT`, `INDEXER_YELLOWSTONE_TOKEN`)
5. Allow up to 30 seconds after onchain confirmation, since the indexer applies
   a finality safety delay before crediting

### Withdrawal not settling to Mainnet

1. Verify `indexer-private-channel` is running:
   `docker compose -f docker-compose.devnet.yml --env-file versions.env --env-file .env.devnet logs -f indexer-private-channel`
2. Verify `operator-private-channel` is running:
   `docker compose -f docker-compose.devnet.yml --env-file versions.env --env-file .env.devnet logs -f operator-private-channel`
3. Confirm the operator keypair in `ADMIN_PRIVATE_KEY` matches the key
   registered with `AddOperator` onchain
4. If `operator-private-channel` exits at startup with
   `Withdrawal bitmap divergence` in its logs, the database records a release
   that the onchain bitmap does not. Follow the upstream
   [withdrawal pipeline halt runbook](https://github.com/solana-foundation/solana-private-channels/blob/main/docs/runbooks/withdrawal_pipeline_halt_runbook.md)
   before restarting

### JWT authentication failures (401 on all requests)

1. Confirm `JWT_SECRET` is identical on both the gateway and auth service
   containers
2. Confirm the stack was started with `--profile auth`
3. Tokens expire after 24 hours; re-authenticate to get a fresh token

### First build takes too long

Expected. The first `make docker-devnet-build` compiles all Rust services and
can take 30-60 minutes on typical hardware. Subsequent builds use Docker layer
cache and are significantly faster.
