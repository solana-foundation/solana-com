## Programs Under Test

The test below loads two programs: a callee that logs a message, and a caller
that invokes the callee, whose program ID it receives as an account. Put both
in one Cargo workspace, so `cargo build-sbf` writes `caller.so` and
`callee.so` to the shared `target/deploy/` folder:

```
cpi-example/
├── Cargo.toml
├── callee/
│   ├── Cargo.toml
│   └── src/lib.rs
└── caller/
    ├── Cargo.toml
    ├── src/lib.rs
    └── tests/cpi_test.rs
```

The workspace `Cargo.toml` sets `resolver = "2"`. Without it, Cargo applies the
test dependencies' features to the program build, and `cargo build-sbf` fails
once LiteSVM is a dev-dependency:

```toml Cargo.toml
[workspace]
members = ["callee", "caller"]
resolver = "2"
```

Both programs have the same `Cargo.toml`, apart from the package name:

```toml caller/Cargo.toml
[package]
name = "caller"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib", "lib"]

[dependencies]
solana-program = "2.2.0"
```

```rust callee/src/lib.rs
use solana_program::{
    account_info::AccountInfo, entrypoint, entrypoint::ProgramResult, msg, pubkey::Pubkey,
};

entrypoint!(process_instruction);

pub fn process_instruction(
    _program_id: &Pubkey,
    _accounts: &[AccountInfo],
    _instruction_data: &[u8],
) -> ProgramResult {
    msg!("Callee invoked");
    Ok(())
}
```

```rust caller/src/lib.rs
use solana_program::{
    account_info::{next_account_info, AccountInfo},
    entrypoint,
    entrypoint::ProgramResult,
    instruction::Instruction,
    msg,
    program::invoke,
    pubkey::Pubkey,
};

entrypoint!(process_instruction);

pub fn process_instruction(
    _program_id: &Pubkey,
    accounts: &[AccountInfo],
    _instruction_data: &[u8],
) -> ProgramResult {
    let accounts_iter = &mut accounts.iter();
    let _payer = next_account_info(accounts_iter)?;
    let callee_program = next_account_info(accounts_iter)?;

    msg!("Caller invoking callee");
    // Invoke the callee program, whose ID arrives as the second account
    invoke(
        &Instruction::new_with_bytes(*callee_program.key, &[], vec![]),
        &[callee_program.clone()],
    )?;
    Ok(())
}
```

Add the test dependencies to the caller, then build both programs from the
workspace root. Adding them before the first build lets Cargo resolve the
program and test dependencies together:

```bash
cd caller
cargo add --dev litesvm solana-sdk@4
cargo add --dev solana-system-interface --features bincode
cd ..
cargo build-sbf
```

## Complete Test

```rust caller/tests/cpi_test.rs
use litesvm::LiteSVM;
use solana_sdk::{
    instruction::{AccountMeta, Instruction},
    pubkey::Pubkey,
    signature::{Keypair, Signer},
    transaction::Transaction,
};
use solana_system_interface::program as system_program;

#[test]
fn test_cross_program_invocation() {
    let mut svm = LiteSVM::new();

    // Deploy both programs
    let caller_program = Pubkey::new_unique();
    let callee_program = Pubkey::new_unique();

    svm.add_program(
        caller_program,
        include_bytes!("../../target/deploy/caller.so")
    ).unwrap();

    svm.add_program(
        callee_program,
        include_bytes!("../../target/deploy/callee.so")
    ).unwrap();

    // Setup accounts
    let payer = Keypair::new();
    svm.airdrop(&payer.pubkey(), 10_000_000_000).unwrap();

    // Create instruction that will trigger CPI
    let instruction = Instruction {
        program_id: caller_program,
        accounts: vec![
            AccountMeta::new(payer.pubkey(), true),
            AccountMeta::new_readonly(callee_program, false),
            AccountMeta::new_readonly(system_program::id(), false),
        ],
        data: vec![], // The caller ignores instruction data
    };

    let tx = Transaction::new_signed_with_payer(
        &[instruction],
        Some(&payer.pubkey()),
        &[&payer],
        svm.latest_blockhash(),
    );

    let result = svm.send_transaction(tx).unwrap();

    // Verify both programs were invoked
    assert!(result.logs.iter().any(|log|
        log.contains(&format!("Program {} invoke", caller_program))
    ));
    assert!(result.logs.iter().any(|log|
        log.contains(&format!("Program {} invoke", callee_program))
    ));

    println!("CPI successful!");
    println!("Logs showing both programs:");
    for log in &result.logs {
        if log.contains("invoke") {
            println!("   {}", log);
        }
    }
}
```

## Key Points

1. **Multiple Programs**: Deploy all programs involved in the CPI chain
2. **Program IDs**: Pass the callee program ID as an account in the instruction
3. **System Program**: Often needed for CPI operations (transfers, account
   creation, etc.)
4. **Log Verification**: Check logs to verify all programs in the call chain
   executed

For more detailed deployment information, read
[this section](/developers/docs/tools/litesvm/testing-your-program/deploy).

## Understanding CPI Logs

When a CPI occurs, you'll see logs like:

```
Program A invoke [1]
Program B invoke [2]
Program B success
Program A success
```

The numbers in brackets indicate the call depth.
