title: Railway Deployment
description: One-click deploy to Railway
---

[Railway](https://railway.com/) offers an easy deployment experience for Kora
nodes with automatic SSL, domain management, and built-in monitoring. This guide
will walk through setting up a Kora node on railway with a simple Docker image
and the Railway CLI.

## Prerequisites

- [Railway Account](https://railway.app)
- [Railway CLI](https://docs.railway.com/cli) installed
- [Solana CLI](/developers/docs/quickstart) for private key
  creation
- [Solana RPC Endpoint](https://solana.com/rpc)

## Step 1: Prepare Deployment Files

Create a new directory for your Kora node:

```bash
mkdir my-kora-node
cd my-kora-node
```

Add the sample configuration files to your directory:

- [kora.toml](https://github.com/solana-foundation/kora/blob/v2.0.5/examples/deploy/kora.toml)
- [signers.toml](https://github.com/solana-foundation/kora/blob/v2.0.5/examples/deploy/signers.toml)

Then create a `Dockerfile` that starts from the official Kora v2.0.5 image and
adds your configuration:

```dockerfile title="Dockerfile"
FROM ghcr.io/solana-foundation/kora:v2.0.5

WORKDIR /app
COPY kora.toml signers.toml ./

# kora reads RPC_URL and KORA_PRIVATE_KEY from the environment; Railway sets PORT
CMD kora --config kora.toml rpc start --signers-config signers.toml --port ${PORT:-8080}
```

> **Note:** Don't use the repository's
> [sample Dockerfile](https://github.com/solana-foundation/kora/blob/v2.0.5/examples/deploy/Dockerfile).
> It runs `cargo install kora-cli` on `rust:1.88`, and that build now fails
> because current dependency releases require Rust 1.89. If you want to compile
> Kora in your image instead, use `FROM rust:1.89` (or later) and
> `RUN cargo install kora-cli@2.0.5 --locked`.

Your directory should now look like:

```bash
my-kora-node/
├── kora.toml
├── signers.toml
└── Dockerfile
```

## Step 2: Deploy to Railway

From your project directory, login to Railway

```bash
# Login to Railway
railway login
```

Follow the on-screen instructions to log in with your account.

Initialize Railway project in your directory.

```bash
railway init
```

Railway will prompt you to:

1. Create a new project or select existing
2. Choose a project name (e.g., "my-kora-node")

### Deploy Your Application

```bash
# Deploy the application
railway up
```

This will:

- Upload your files to Railway
- Build the Docker image
- Deploy your application

**Expected output:**

```
Deploy complete
Starting Container
```

The container stops right away, and the deploy logs show
`Environment variable 'KORA_PRIVATE_KEY' required for signer 'main_signer' is not set`.
That's expected: the environment variables aren't configured yet. Set them
next.

## Step 3: Configure Environment Variables

Open your Railway dashboard at [railway.app](https://railway.app) and navigate
to your project. In your project, click "Settings" > "Variables"

<Frame caption="Railway Environment Variables for Kora">
  ![Railway Environment Variables for
  Kora](/docs-assets/assets/docs/tools/kora/deploy/railway-variables.jpg)
</Frame>

Add these environment variables:

| Variable           | Value                            | Description                                                                  |
| ------------------ | -------------------------------- | ---------------------------------------------------------------------------- |
| `RPC_URL`          | `https://api.mainnet.solana.com` | Solana RPC endpoint                                                          |
| `KORA_PRIVATE_KEY` | `[12,34,...]` or a base58 string | Your Solana private key: the byte array from a keypair file, or base58      |
| `RUST_LOG`         | `info`                           | Log level for debugging                                                      |

> **Security Warning**: Your private key has access to SOL for paying fees. Use
> a dedicated keypair for your Kora node and only fund it with the SOL you're
> willing to spend on transaction fees. For more information on signers, see the
> [Signers Guide](/developers/docs/tools/kora/operators/signers).

### Getting Your Private Key

If you need to create a new keypair:

```bash
# Generate new keypair
solana-keygen new --outfile ~/.config/solana/kora-keypair.json

# Print the private key as a byte array to paste into KORA_PRIVATE_KEY
cat ~/.config/solana/kora-keypair.json

# Print the public key (the fee payer address to fund)
solana-keygen pubkey ~/.config/solana/kora-keypair.json
```

`solana-keygen` writes the key as a JSON array of 64 numbers. Kora accepts that
array, a base58-encoded private key, or a path to a keypair file (see
[Signers](/developers/docs/tools/kora/operators/signers#private-key-signer)).
Fund the public key with enough SOL to pay the transaction fees your node will
sponsor.

## Step 4: Redeploy

After saving your variables, you will be prompted to redeploy your server--do
that.

## Step 5: Test Your Deployment

### Generate Public Endpoint

To send requests to your endpoint, you will need to generate a public Domain.
From your deployment, go to "Settings" > "Generate domain".

<Frame caption="Railway Domain Setup">
  ![Railway Domain
  Setup](/docs-assets/assets/docs/tools/kora/deploy/railway-domain.jpg)
</Frame>

Use the default port, "8080" and click "Generate Domain".

You should get a domain like `https://my-kora-node.railway.app/`

### Test Configuration Endpoint

```bash
curl -X POST https://my-kora-node.railway.app \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"getConfig","params":[]}' | jq
```

**Expected response:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "fee_payers": ["YourPublicKeyHere..."],
    "validation_config": {
      "max_allowed_lamports": 1000000,
      "allowed_programs": [...],
      "allowed_spl_paid_tokens": [...]
      // ...
    }
  }
}
```

Your Kora node is now live.
