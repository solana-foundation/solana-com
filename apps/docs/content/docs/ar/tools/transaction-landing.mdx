## البنية التحتية لـ RPC

[نقاط النهاية العامة](https://solana.com/docs/references/clusters#solana-public-rpc-endpoints)
(`api.mainnet.solana.com`) محدودة المعدل وبلا اتفاقية مستوى خدمة (SLA). لا بأس بها
للتطوير، لكنها ستفشل في مسارات الدفع الإنتاجية، تمامًا كمحاولة تشغيل معالج دفع
عبر واجهة API مشتركة دون أي ضمان لوقت التشغيل.

<Callout type="caution" title="لا تستخدم RPC العام في بيئة الإنتاج">
  استخدم [مزوّد RPC خاصًا](https://solana.com/rpc) للحصول على وصول موثوق
  ومنخفض زمن الاستجابة.
</Callout>

عند اختيار مزوّد RPC، ابحث عن:

- **الموثوقية**: اتفاقيات مستوى خدمة (SLA) مع ضمانات لوقت التشغيل (99.9%+)
- **زمن الاستجابة**: القرب الجغرافي من مستخدميك
- **الميزات**: ميزات هبوط المعاملات، والفهرسة، وواجهات API لرسوم الأولوية

للاطلاع على القائمة الكاملة لمزوّدي RPC، راجع دليل
[مزوّدي البنية التحتية لـ RPC](https://solana.com/rpc).

### إعداد RPC الاحتياطي (Redundant)

مثل أي مزوّد خدمة شبكة، قد يتعرض مزوّدو RPC لانقطاع الخدمة أو لفترات من تدهور
الأداء. ولضمان مرونة تطبيقك، يجب أن تهيّئه لاستخدام عدة مزوّدي RPC.

توفر [سولانا Kit](https://github.com/anza-xyz/kit/tree/main/packages/rpc-transport-http)
مكتبة لتخصيص وسائل نقل RPC، تتيح لك بناء عميل RPC احتياطي خاص بك. إليك مثالًا
على كيفية استخدامها لبناء عميل RPC احتياطي:

```ts
import { RpcTransport } from "@solana/rpc-spec";
import { RpcResponse } from "@solana/rpc-spec-types";
import { createHttpTransport } from "@solana/rpc-transport-http";

// Create a transport for each RPC server
const transports = [
  createHttpTransport({ url: "https://mainnet-beta.my-server-1.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-2.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-3.com" })
];

// Create a wrapper transport that distributes requests to them
let nextTransport = 0;
async function roundRobinTransport<TResponse>(
  ...args: Parameters<RpcTransport>
): Promise<RpcResponse<TResponse>> {
  const transport = transports[nextTransport];
  nextTransport = (nextTransport + 1) % transports.length;
  return await transport(...args);
}
```

إذا كنت تفضّل عدم بناء أدوات التوجيه بنفسك، فيمكنك الاستفادة من خدمة طرف ثالث
مثل [Iron Forge](https://www.ironforge.sanctum.so/) لتتولى التوجيه نيابةً عنك.

## هبوط المعاملات (Transaction Landing)

على Devnet، تهبط المعاملات بسهولة نسبيًا. أما على Mainnet، فأنت تتنافس على مساحة
الكتل. ولزيادة فرص تضمين معاملتك في كتلة، يجب أن تتأكد من أنك جمّعت معاملتك
بشكل صحيح. وهذا يعني:

- تضمين blockhash حديث قبل إرسال المعاملة
- تضمين تعليمة رسوم أولوية في المعاملة مع رسوم أولوية تنافسية
- تضمين تعليمة حد وحدات الحوسبة في المعاملة، بحد يستند إلى وحدات الحوسبة المقدّرة
  اللازمة للمعاملة

بالإضافة إلى ذلك، يجب أن تنظر في أدوات أخرى مثل Jito Bundles لزيادة فرص تضمين
معاملتك في كتلة. لنستكشف هذه الأدوات بمزيد من التفصيل.

### إعداد إرسال المعاملات

عند إرسال المعاملات على Mainnet، اضبط هذه المعلمات للحصول على أفضل معدلات الهبوط:

**إدارة Blockhash:**

- اجلبه باستخدام مستوى التأكيد `confirmed`
- خزّن قيمة `lastValidBlockHeight` التي تعيدها `getLatestBlockhash`، فهي تخبرك
  متى تنتهي صلاحية معاملتك
- تنتهي صلاحية Blockhash بعد مدة يحددها البروتوكول بحسب طول الـ slot.

**خيارات الإرسال:**

- `maxRetries: 0` — عطّل إعادة محاولات RPC التلقائية. تولَّ إعادة المحاولات بنفسك
  حتى تتمكن من تحديث blockhash عند الحاجة.
- `skipPreflight: true` — تجاوز المحاكاة قبل الإرسال. استخدمه عندما تكون قد تحققت
  من المعاملة بالفعل وتريد أقل زمن استجابة. أبقه على `false`
  أثناء التطوير لاكتشاف الأخطاء مبكرًا.

```typescript
import { createSolanaRpc } from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);

// 1. Get blockhash with confirmed commitment
const { value: latestBlockhash } = await rpc
  .getLatestBlockhash({ commitment: "confirmed" })
  .send();

// 2. Build and sign your transaction with the blockhash
// ... (transaction building code)

// 3. Send with production settings
const signature = await rpc
  .sendTransaction(encodedTransaction, {
    encoding: "base64",
    maxRetries: 0n, // Handle retries yourself
    skipPreflight: true, // Skip simulation for speed (use false during dev)
    preflightCommitment: "confirmed"
  })
  .send();

// 4. Track expiration using lastValidBlockHeight
const { lastValidBlockHeight } = latestBlockhash;
// Stop retrying when current block height exceeds lastValidBlockHeight
```

### استخدام رسوم الأولوية

تتطلب كل معاملة على سولانا رسم معاملة يُدفع بعملة SOL. تنقسم رسوم المعاملات إلى
جزأين: الرسم الأساسي ورسم الأولوية. يعوّض الرسم الأساسي الـ validators عن معالجة
المعاملة. أما رسم الأولوية فهو رسم اختياري يزيد من فرصة أن يعالج القائد الحالي
معاملتك. فكّر فيه كالشحن السريع: تدفع أكثر مقابل توصيل أسرع وأكثر موثوقية.

**كيف تعمل الرسوم:**

```
Total fee = Base fee (5,000 lamports per signature) + Priority fee
Priority fee (legacy/v0) = ceil(compute_unit_price * compute_unit_limit / 1,000,000) lamports
Priority fee (v1 only) = Absolute total in lamports set in the message config
```

**التكاليف في الواقع العملي:**

- تحويل USDC بسيط: ~0.001-0.005 دولار في الظروف العادية
- أثناء الازدحام: ~0.01-0.05 دولار
- ذروة الازدحام: قد ترتفع أكثر

**مثال على التنفيذ:**

توفر حزمة
[`@solana-program/compute-budget`](https://github.com/solana-program/compute-budget)
دالة مساعدة لتحديث تعليمة سعر وحدة الحوسبة (بالميكرو-لامبورت) أو إلحاقها بالمعاملة
بسهولة.

```typescript
import { updateOrAppendSetComputeUnitPriceInstruction } from "@solana-program/compute-budget";

const tx = pipe(
  createTransactionMessage({ version: 0 }),
  (m) => setTransactionMessageFeePayerSigner(payer, m),
  (m) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, m),
  (m) => appendTransactionMessageInstructions([myInstructions], m),
  (m) => updateOrAppendSetComputeUnitPriceInstruction(1000n as MicroLamports, m)
);
```

**الحصول على تقديرات الرسوم:** يوفر معظم مزوّدي RPC واجهات API لرسوم الأولوية:

- [Helius Priority Fee API](https://docs.helius.dev/solana-apis/priority-fee-api)
- [QuickNode Priority Fee Add-on](https://marketplace.quicknode.com/add-on/solana-priority-fee)
- [Triton Priority Fees API](https://docs.triton.one/chains/solana/improved-priority-fees-api)

للاطلاع على آليات الرسوم كاملة، راجع [رسوم المعاملات](/docs/core/fees) ودليلنا:
[كيفية إضافة رسوم الأولوية إلى معاملة](https://solana.com/developers/cookbook/transactions/add-priority-fees).

### تحسين وحدات الحوسبة

تُقاس الحوسبة على سولانا بوحدات الحوسبة (CUs)، وهي تقدير تقريبي لحجم العمل الذي
يؤديه البرنامج. حدود الحوسبة اليوم هي 50 مليون وحدة حوسبة لكل كتلة، و1.4 مليون
وحدة حوسبة لكل معاملة. عند إرسال معاملة، عليك تقدير كمية الحوسبة التي ستُستخدم،
وضبط حد وحدات الحوسبة وفقًا لذلك، وهذا في الواقع طلب لحجز جزء من السعة الإجمالية
لمعاملتك. عمليًا، يعني هذا أن التقدير الصحيح لوحدات الحوسبة اللازمة لمعاملتك أمر
حاسم لتضمينها في كتلة (ومهم أيضًا لإدارة رسوم الأولوية). ويحدد البروتوكول حدّي
الحوسبة للمعاملة وللكتلة.

تحتوي سولانا JSON RPC API على الطريقة
[`simulatetransaction`](/docs/rpc/http/simulatetransaction) التي يمكن
استخدامها لتقدير وحدات الحوسبة اللازمة لمعاملة ما، وهي تتضمن تقديرًا لوحدات الحوسبة
التي ستُستخدم.
وتوفر [`@solana/kit`](https://github.com/anza-xyz/kit) دوال مساعدة
تقدّر حدود موارد المعاملة وتضبطها على الرسالة في خطوة واحدة
(باستخدام الطريقة `simulatetransaction` في الخلفية). وبالنسبة إلى معاملات الإصدار 1،
تقدّر هذه الدوال المساعدة أيضًا حد حجم بيانات الحسابات المحمّلة.

```ts
import {
  estimateResourceLimitsFactory,
  estimateAndSetResourceLimitsFactory
} from "@solana/kit";

const estimateResourceLimits = estimateResourceLimitsFactory({ rpc });
const estimateAndSetResourceLimits = estimateAndSetResourceLimitsFactory(
  estimateResourceLimits
);
const txWithResourceLimits = await estimateAndSetResourceLimits(tx);
```

<Callout type="info">
  إذا كنت تبني المعاملات وترسلها باستخدام عميل kit plugin، فلن تحتاج عادةً إلى هذه
  الخطوة — إذ يضيف العميل تعليمات ميزانية الحوسبة نيابةً عنك
  عند الإرسال (`.sendTransaction()`). أما التدفق اليدوي أعلاه فهو للحالات التي
  تجمّع فيها المعاملات مباشرةً باستخدام `@solana/kit`.
</Callout>

في بيئة الإنتاج، إذا كنت تكرر النوع نفسه من المعاملات عدة مرات، ففكّر في تخزين
تقدير الحوسبة مؤقتًا لهذا النوع من المعاملات لتجنب عبء تقدير وحدات الحوسبة في كل مرة.

### Jito Bundles

Jito bundles أداة لإدارة التنفيذ الذري لعدة معاملات. ويتم ذلك بإرسال عدة معاملات
إلى شبكة Jito مع بقشيش (tip). ويمكن استخدام البقشيش لتحفيز شبكة Jito على تضمين
معاملاتك في كتلة.

### استراتيجيات إعادة المحاولة

قد تفشل المعاملات لأسباب عديدة. وعلى عكس واجهات API التقليدية للدفع التي تعيد
النجاح أو الفشل فورًا، تتطلب معاملات البلوكشين تتبّع التأكيد.

**المفاهيم الأساسية:**

- **انتهاء صلاحية Blockhash**: تظل blockhash الخاصة بالمعاملات
  صالحة لمدة 150 slot (نحو 30 ثانية عند 200 مللي ثانية لكل slot). وقد يختلف
  وقت انتهاء الصلاحية الفعلي بحسب سرعة إنتاج الكتل. استخدم
  lastValidBlockHeight لتحديد متى انتهت صلاحية blockhash.
- **خاصية Idempotency**: المعاملة الموقّعة نفسها تنتج دائمًا التوقيع نفسه،
  لذا فإعادة إرسالها آمنة
- **التراجع الأسي (Exponential backoff)**: تجنّب إغراق الشبكة بإعادة محاولات سريعة

```typescript
import {
  createSolanaRpc,
  createSolanaRpcSubscriptions,
  sendAndConfirmTransactionFactory,
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED
} from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);
const rpcSubscriptions = createSolanaRpcSubscriptions(process.env.RPC_WSS_URL!);

const sendAndConfirmTransaction = sendAndConfirmTransactionFactory({
  rpc,
  rpcSubscriptions
});

// Send with automatic confirmation tracking and block height monitoring
try {
  await sendAndConfirmTransaction(signedTransaction, {
    commitment: "confirmed",
    // Optional: abort after 75 seconds
    abortSignal: AbortSignal.timeout(75_000)
  });
} catch (e) {
  if (isSolanaError(e, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED)) {
    // Blockhash expired—rebuild transaction with fresh blockhash and retry
    rebuildAndRetryTransaction(); // implement your own logic for rebuilding and retrying the transaction
  }
  throw e;
}
```

تتولى الدالة `sendAndConfirmTransactionFactory` من `@solana/kit` استطلاع التأكيد
وتتبّع ارتفاع الكتلة تلقائيًا. وهي تطلق الخطأ
`SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED` عند انتهاء صلاحية blockhash الخاصة بالمعاملة،
مما يشير إلى أنك بحاجة إلى إعادة بناء المعاملة باستخدام blockhash حديثة.

## معالجة الأخطاء

توفر سولانا Kit أخطاءً مضبوطة الأنواع عبر `isSolanaError()`. استخدم رموز أخطاء محددة
بدلًا من مطابقة النصوص:

```typescript
import {
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED,
  SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE,
  SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND,
  SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS
} from "@solana/kit";

function handlePaymentError(error: unknown): {
  message: string;
  retryable: boolean;
} {
  // Blockhash expired—rebuild and retry
  if (
    isSolanaError(error, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED) ||
    isSolanaError(error, SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND)
  ) {
    return { message: "Transaction expired—rebuilding", retryable: true };
  }

  // Insufficient SOL for fees
  if (
    isSolanaError(
      error,
      SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE
    )
  ) {
    return { message: "Not enough SOL for fees", retryable: false };
  }

  // Insufficient token balance
  if (
    isSolanaError(error, SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS)
  ) {
    return { message: "Insufficient balance", retryable: false };
  }

  // Unknown error
  console.error("Payment error:", error);
  return { message: "Payment failed—please retry", retryable: true };
}
```

**رموز الأخطاء الشائعة:**

| رمز الخطأ                   | السبب                 | المعالجة                                                                                                 |
| ---------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------- |
| `BLOCK_HEIGHT_EXCEEDED`      | انتهت صلاحية Blockhash     | أعد البناء باستخدام blockhash حديثة                                                                             |
| `BLOCKHASH_NOT_FOUND`        | لم يتم العثور على Blockhash   | أعد البناء باستخدام blockhash حديثة                                                                             |
| `INSUFFICIENT_FUNDS_FOR_FEE` | رصيد SOL غير كافٍ        | موّل حساب دافع الرسوم أو استخدم [تجريد الرسوم](/docs/payments/send-payments/payment-processing/fee-abstraction) |
| `INSUFFICIENT_FUNDS`         | رصيد الرموز غير كافٍ     | يحتاج المستخدم إلى رصيد أكبر                                                                                  |
| `ACCOUNT_NOT_FOUND`          | token account مفقود | أنشئ ATA ضمن المعاملة                                                                                |

## المعاملات بدون رسوم غاز (Gasless)

يتوقع المستخدمون الدفع بالعملات المستقرة، لا الحصول على SOL لدفع رسوم الشبكة. وتحل
المعاملات بدون رسوم غاز هذه المشكلة، على غرار أن مستخدمي Venmo لا يفكرون في رسوم ACH.
راجع
[تجريد الرسوم](/docs/payments/send-payments/payment-processing/fee-abstraction)
للاطلاع على التنفيذ الكامل.
