## التثبيت

قم بتثبيت الحزمة الشاملة أو الموقعين الفرديين حسب الحاجة:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

يتطلب `@solana/kit` الإصدار 8.1 أو أحدث. معاملات v1
(`createTransactionMessage({ version: 1 })`) مدعومة، باستثناء Fireblocks
مع `useProgramCall: true`، الذي يقبل المعاملات القديمة (legacy) وv0 فقط.

## الاستخدام الأساسي

### المصنع الموحد (موصى به للتطبيقات التي ترغب في دعم موقعين متعددين)

استخدم `createKeychainSigner` مع تكوين مميز لإنشاء أي واجهة خلفية:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

أو قم بتثبيت حزمة موقع فردية للحصول على بصمة تبعيات أصغر:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### الاستخدام مع رسائل المعاملات

تُرجع كل واجهة خلفية، باستثناء Crossmint ووضع Fordefi الأصلي، كائن
`SolanaTransactionSigner`، وهو `TransactionPartialSigner` في Kit ويعمل
مع دوال المساعدة الخاصة بالموقّعين الجزئيين في `@solana/signers` الموضحة أدناه. تتناول [قدرات الموقّع](#signer-capabilities) الواجهات الخلفية ذات البث المُدار.

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### التوقيع والإرسال باستخدام أي موقّع

تتولى `signAndSendTransaction` من `@solana/keychain-core` إيصال المعاملة إلى
السلسلة أيًّا كان شكل الموقّع. تبثّ الموقّعات المرسِلة عبر مزوّدها؛ أما كل شكل آخر
فيستخدم دالة `sendTransaction` التي تمررها أنت (لا تعتمد النواة على أي
RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### الاستخدام مع عميل Kit (إضافة keychainSigner)

يقوم `@solana/keychain-kit-plugin` بتثبيت موقّع سلسلة المفاتيح مباشرةً على
[عميل Kit](https://github.com/anza-xyz/kit)، ويربطه بوصفه `payer` و `identity`،
مما يُغنيك عن الإعداد اليدوي لـ `pipe` الموضّح أعلاه:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

يقبل المكوّن الإضافي الإعداد نفسه الموسوم بالواجهة الخلفية كما في `createKeychainSigner`،
باستثناء Crossmint ووضع Fordefi الأصلي (عند ضبط `chain`). تعيد هذه الواجهات كتابة
المعاملة على جهة الخادم، لذا لا يمكنها العمل كـ`payer` أو
`identity` للعميل؛ ويرفضها المكوّن الإضافي عند التجميع وأثناء التشغيل. لا تُضمَّن إلا
الواجهة الخلفية التي يوجّه إليها (تُحمَّل حزم الواجهات الخلفية عبر
`import()` الديناميكي).

استخدم `keychainPayer` أو `keychainIdentity` لتعيين دور واحد فقط، ومزج الخلفيات
على عميل واحد:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

لديك بالفعل `SolanaTransactionSigner`؟ إنه `TransactionPartialSigner`
صالح في Kit، لذا يمكنك تثبيته باستخدام
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
بدلًا من ذلك (`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### الإلغاء والبث غير المؤكَّد

تقبل `signTransactions` و`modifyAndSignTransactions` و`signAndSendTransactions` و
`signMessages` جميعها `{ abortSignal }` كوسيط ثانٍ. يؤدي الإلغاء إلى
التوقف عن الانتظار، لكنه لا يتراجع عن عمل قبله المزوّد بالفعل.

في وضع Crossmint ووضع Fordefi الأصلي التلقائي، لا يعني الفشل أن شيئًا لم يصل إلى السلسلة. عندما قد يكون المزوّد قد قبل المعاملة، يكون رمز الخطأ
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
يُضبط `context.providerTransactionId` عند قبول الإنشاء، ويحمل
`context.idempotencyKey` المفتاح المشتق من الرسالة. إعادة إرسال
المعاملة المطابقة بايتًا ببايت آمنة؛ أما المعاملة المعاد بناؤها (مثلًا بـ blockhash جديد) فهي تحويل جديد. تساعد `providerMayHaveAccepted(error)` و
`providerStatus(error)` من `@solana/keychain-core` في تصنيف الخطأ.
تحقق من حالة المعاملة لدى المزوّد قبل إعادة المحاولة.

const signer = await createMemorySigner({
  privateKeyPath: "/path/to/id.json"
});

### Crossmint

```typescript

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmint للإرسال فقط. تنفّذ واجهته البرمجية دائمًا المعاملة المعتمدة
على جهة الخادم وتتكفل برسوم الغاز، لذا لا يعرض الموقّع سوى
`signAndSendTransactions()`: فلا توجد فيه `signTransactions()` ولا `signMessages()`،
ولا يمكن تثبيته باستخدام `@solana/keychain-kit-plugin`. يحدد التوقيع المُرجَع
المعاملة التي أتمّتها Crossmint على السلسلة.

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

لدى Fordefi ثلاثة أوضاع للتوقيع، تُحدَّد عند الإنشاء بواسطة `chain` و
`pushMode`. يعرض كل وضع دالة معاملات واحدة بالضبط، وتوقّع الأوضاع الثلاثة جميعها
الرسائل:

| الوضع          | الإعداد                                      | النوع                        | الدالة                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| الصندوق الأسود     | `chain` غير مضبوط                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| أصلي تلقائي   | `chain` مضبوط، و`pushMode` محذوف أو `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| أصلي يدوي | `chain` مضبوط، و`pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

تُوثَّق طلبات API بتوقيع طلب ECDSA P-256: قدّم
مفتاح التوقيع عبر `privateKeyPem`، أو أبقه في KMS/HSM بتمرير
`requestSigner`.

**الوضع الأصلي التلقائي** (موصى به للاستخدام على السلسلة): اضبط `chain`، وسيتولى Fordefi
توقيع المعاملة وبثّها بنفسه. ولأن Fordefi قد يستبدل
blockhash أو الرسوم قبل التوقيع، فإن الموقّع هو `TransactionSendingSigner` في Kit:
استخدمه مع
`signAndSendTransactionMessageWithSigners`، لا مع مسار الموقّع الجزئي الموضح
أعلاه. يقبل الوضع الأصلي التلقائي فقط معاملة غير موقّعة يكون الموقّع الوحيد المطلوب فيها
هو الخزنة، ولا يمكن استخدامه مع `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**الوضع الأصلي اليدوي**: اضبط `chain` و`pushMode: "manual"`. يعيد Fordefi كتابة
الرسالة (blockhash حديث، تعليمات رسوم Compute Budget) ويوقّعها،
لكنه لا يبثّها. تُرجع `modifyAndSignTransactions()` المعاملة التي
وقّعها Fordefi، وهي تحل محل التي أرسلتها: تابع دائمًا من
المعاملة المُرجَعة. يجب أن يكون Fordefi هو دافع الرسوم وأن يوقّع قبل أي
موقّع آخر مطلوب. لا تُعرض الفروقات في إعادة الكتابة، لذا افحص النتيجة قبل
البث.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**وضع الصندوق الأسود**: أغفِل `chain`. يوقِّع Fordefi البايتات الخام دون بثّها؛ وعليك أنت تجميع المعاملة وإرسالها. استخدم هذا الوضع مع خزنة الصندوق الأسود في Fordefi.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## قدرات الموقّع

تعرّف `@solana/keychain-core` واجهة واحدة لكل شكل من أشكال موقّعات Kit. تضيف كل منها
`isAvailable(): Promise<boolean>` إلى واجهة `@solana/signers` المطابقة:

- `SolanaTransactionSigner` (`TransactionPartialSigner` في Kit): يُرجع التوقيعات
  لمعاملة تملكها.
- `SolanaModifyingSigner` (`TransactionModifyingSigner` في Kit): يعيد كتابة
  المعاملة ويوقّعها ويُرجع المعاملة الجديدة دون بثّها.
- `SolanaSendingSigner` (`TransactionSendingSigner` في Kit): يوقّع ويبثّ
  عبر مزوّده.
- `SolanaMessageSigner` (`MessagePartialSigner` في Kit): يوقّع الرسائل خارج السلسلة.
  وهو منفصل عن أشكال المعاملات.

`SolanaSigner` هو اتحاد (union) أشكال المعاملات الثلاثة. يسمّي نوع الإرجاع لكل مصنع
الشكل الدقيق لواجهته الخلفية. وعندما لا يُعرف الإعداد إلا
أثناء التشغيل، استخدم التضييق عبر `isSolanaTransactionSigner` أو `isSolanaModifyingSigner` أو
`isSolanaSendingSigner` أو `isSolanaMessageSigner`. تُبلغ `signerCapabilities(signer)`
عن الأربعة جميعها دفعة واحدة.

| الواجهة الخلفية                                                                                                     | الشكل                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (الصندوق الأسود) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (دون توقيع الرسائل)  |
| fordefi (أصلي يدوي)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (أصلي تلقائي)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (دون توقيع الرسائل)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## بناء موقّعين مخصصين

نفّذ واجهات القدرات التي تدعمها واجهتك الخلفية:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

نفّذ فقط ما تدعمه واجهتك الخلفية. يصنّف Kit الموقّعين بحسب الدوال
الموجودة، لذا لا تضف أبدًا دالة تكتفي بإطلاق خطأ.

راجع [دليل إضافة الموقّعين](/docs/tools/keychain/adding-signers) لدمج خدمات
إدارة المفاتيح الإضافية.
