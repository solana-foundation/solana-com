## إدارة المفاتيح

- **لا تكشف المفاتيح الخاصة أبدًا في كود الواجهة الأمامية.** استخدم التوقيع عبر الواجهة الخلفية، أو
  المحافظ الصلبة، أو المحافظ متعددة التوقيعات، أو خدمات إدارة المفاتيح.
- **افصل بين المحافظ الساخنة والباردة.** استخدم المحفظة الساخنة للعمليات، والباردة
  للخزينة.
- **احتفظ بنسخ احتياطية لجميع مفاتيح الإنتاج.** خزّن النسخ الاحتياطية المشفّرة في عدة مواقع
  آمنة. فقدان المفتاح يعني فقدان الوصول بشكل دائم.
- **استخدم مفاتيح مختلفة لشبكة devnet وشبكة mainnet.** يجب ألا تكون مفاتيح devnet
  هي نفسها مفاتيح mainnet. استخدم إعدادات قائمة على البيئة لضمان تحميل المفاتيح الصحيحة
  لكل شبكة.

## بنية التوقيع التحتية

للتوقيع في الواجهة الخلفية على بيئة الإنتاج، استخدم [Keychain](/docs/tools/keychain)—وهي مكتبة
توقيع موحّدة تجرّد العديد من واجهات إدارة المفاتيح عبر واجهة
واحدة: Memory وVault وPrivy وTurnkey وAWS KMS وFireblocks وGCP KMS وCDP
وPara وDfns وCrossmint وOpenfort وUtila. يتيح لك ذلك التطوير محليًا باستخدام
مفاتيح في الذاكرة، ثم الانتقال إلى واجهات بمستوى الإنتاج دون تغيير
كود التطبيق.

لست متأكدًا من الواجهة المناسبة؟ راجع
[اختيار الواجهة الخلفية](/docs/tools/keychain/choosing-a-backend). تتوفر Keychain
لكل من [Rust](https://crates.io/crates/solana-keychain) و
[TypeScript](https://www.npmjs.com/package/@solana/keychain).

## أمان RPC

تعامل مع نقاط نهاية RPC كما تتعامل مع مفاتيح API—لا تكشفها في كود الواجهة الأمامية حيث
يمكن استخراجها وإساءة استخدامها. استخدم وسيطًا (proxy) في الواجهة الخلفية أو متغيرات بيئة
لا يتم تضمينها في كود العميل.

- [QuickNode: أفضل ممارسات أمان نقاط النهاية](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: احمِ مفاتيح API الخاصة بك على سولانا: أفضل ممارسات الأمان](https://www.helius.dev/docs/rpc/protect-your-keys)

## المراقبة

تتبّع هذه المقاييس في بيئة الإنتاج:

| المقياس                   | السبب                    |
| ------------------------ | ---------------------- |
| معدل نجاح المعاملات | اكتشاف المشكلات مبكرًا    |
| زمن التأكيد     | مراقبة سلامة الشبكة |
| إنفاق رسوم الأولوية       | إدارة التكلفة        |
| معدل أخطاء RPC           | سلامة المزوّد        |

أعدّ تنبيهات لما يلي:

- التحويلات التي تتجاوز الحد المحدد من الخزينة
- الارتفاعات المفاجئة في معدل فشل المعاملات
- أنماط غير معتادة للمستلمين
- زيادة معدل أخطاء RPC

لمراقبة المعاملات في الوقت الفعلي على نطاق واسع، راجع
[دليل الفهرسة](/docs/payments/accept-payments/indexing).

## التحقق من العناوين

لكل رمز ولكل برنامج عنوان صحيح واحد فقط على mainnet. الرموز المزيفة
التي تحاكي USDC أو العملات المستقرة الأخرى شائعة—فهي تحمل الاسم
والرمز نفسيهما لكن بعنوان mint مختلف. ينبغي لتطبيقك ترميز عناوين mint بشكل ثابت أو وضعها في قائمة سماح
(بحسب متطلباتك)، ولا يقبلها أبدًا بشكل ديناميكي
من مصادر غير موثوقة.

**الإعدادات القائمة على البيئة:** غالبًا ما تستخدم Devnet وMainnet عناوين mint للرموز مختلفة تمامًا.
أعدّ إعدادات تطبيقك لتحميل العناوين الصحيحة لكل بيئة—لا تكتب عناوين mainnet بشكل ثابت وتنسَ استبدالها
أثناء الاختبار، أو الأسوأ من ذلك، أن تنشر عناوين devnet في بيئة الإنتاج.

بعض عناوين mint الشائعة للعملات المستقرة:

| الرمز | الجهة المُصدِرة | عنوان Mint                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

عناوين البرامج مهمة أيضًا. إرسال التعليمات إلى البرنامج الخطأ سيفشل—أو الأسوأ، سيؤدي إلى
خسارة الأموال بشكل لا رجعة فيه. عناوين Token Program
هي:

| البرنامج            | العنوان                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Program | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

إدراج العناوين الصحيحة في قائمة السماح يحمي من الرموز المزيفة، لكنه
لا يحمي من الإرسال إلى _نوع_ خاطئ من الحسابات. يمكن أن يكون عنوان المستلم
محفظة، أو token account، أو mint، أو برنامجًا، ويتطلب كل منها
معالجة مختلفة. إن SOL الأصلي المُرسَل إلى أي شيء غير المحفظة يخرج
عن سيطرة المرسل — ويضيع تمامًا في حالة mint أو البرنامج، ولا يمكن استرداده إلا بواسطة
مالك الحساب في حالة token account — دون وجود معاملة فاشلة لتنبيه المستخدم.

<Callout type="warn" title="تحقق من المستلمين قبل الإرسال">
  صنّف كل عنوان مستلم قبل توقيع أي تحويل. راجع [التحقق من
  العنوان](/docs/payments/send-payments/verify-address) للاطلاع على شجرة القرار الكاملة
  والكود المرجعي الذي يميّز بين المحافظ وtoken accounts وعناوين mint
  والبرامج.
</Callout>
