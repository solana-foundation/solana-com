يوزّع برنامج Rewards الرموز من خزنة يملكها البرنامج على مجموعة من
المستلمين، ولكلٍّ منهم جدول استحقاق. تموّل الجهة المخوَّلة الخزنة وتحدد
من يحصل على ماذا. يطالب المستلمون برموزهم المستحقة بمرور الوقت، ويمكن
للجهة المخوَّلة إلغاء استحقاق المستلمين أو استرداد الرموز المتبقية عندما
يسمح التوزيع بذلك. بُني البرنامج باستخدام Pinocchio وتتولى صيانته مؤسسة
سولانا، ويعمل مع حسابات mint الخاصة بـ SPL Token وToken-2022، باستثناء
حسابات mint الخاصة بـ Token-2022 التي تستخدم امتداد transfer hook.

## اختر نوع التوزيع

يدعم البرنامج نوعين من التوزيع. يستخدم كلاهما جداول الاستحقاق نفسها
وأوضاع الإلغاء نفسها.

|                  | مباشر                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **آلية العمل** | ينشئ حسابًا على السلسلة لكل مستلم     | يخزّن جذر Merkle واحدًا على السلسلة؛ ويقدّم المستلمون إثباتات للمطالبة  |
| **التكلفة المسبقة** | يموّل الدافع rent لكل حساب مستلم | لا حسابات لكل مستلم إلى أن يطالب أحدهم                           |
| **النطاق**        | عملي حتى بضعة آلاف من المستلمين  | يتوسع إلى ملايين المستلمين؛ ولا ينمو التخزين إلا مع مطالبة المستلمين |
| **قابلية التعديل**   | يمكن إضافة مستلمين بعد الإنشاء       | مجموعة المستلمين ثابتة عند الإنشاء                                       |
| **مناسب لـ**   | التوزيعات الصغيرة التي تتغير بمرور الوقت    | التوزيعات الكبيرة الثابتة مثل airdrops                              |

## جداول الاستحقاق

يرتبط كل تخصيص بأحد أربعة جداول. الطوابع الزمنية بثواني Unix.

| الجدول      | السلوك                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | جميع الرموز قابلة للمطالبة فورًا                                                                                    |
| `Linear`      | تُفتح الرموز تناسبيًا بين `startTs` و`endTs`                                                             |
| `Cliff`       | لا يُفتح شيء حتى `cliffTs`، ثم تُفتح جميع الرموز دفعة واحدة                                                       |
| `CliffLinear` | استحقاق خطي من `startTs` إلى `endTs`، مع عدم إتاحة أي شيء للمطالبة حتى `cliffTs`؛ ويُفتح ما تراكم سابقًا عند الـ cliff |

## الحسابات

| الحساب              | PDA seeds                                        | المحتوى                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | الجهة المخوَّلة، وmint، وإجماليات التخصيص       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | تخصيص مستلم واحد واستحقاقه       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | الجهة المخوَّلة، وmint، والإجماليات، وجذر Merkle |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | المبلغ الذي طالب به مطالب واحد حتى الآن        |
| `Revocation`         | `["revocation", distribution, user]`             | علامة تمنع مطالبًا ضمن Merkle أُلغي استحقاقه |

`seed` هو عنوان موقّع إضافي يُمرَّر عند الإنشاء، بحيث يمكن لجهة مخوَّلة واحدة
تشغيل عدة توزيعات لنفس الـ mint. خزنة كل توزيع هي
associated token account الخاصة بـ PDA التوزيع لذلك الـ mint.

## التعليمات

### التوزيع المباشر

1. تستدعي الجهة المخوَّلة `CreateDirectDistribution` لإنشاء PDA التوزيع
   وخزنته.
2. تستدعي الجهة المخوَّلة `AddDirectRecipient` مرة لكل مستلم مع تحديد المبلغ
   وجدول الاستحقاق. ينقل كل استدعاء ذلك المبلغ من token account الخاص بالجهة
   المخوَّلة إلى الخزنة.
3. يستدعي المستلمون `ClaimDirect` لسحب الرموز المستحقة. مرّر `amount: 0` للمطالبة
   بكل ما استُحق حاليًا.
4. بمجرد أن يطالب المستلم بكل ما له، أو عند إغلاق التوزيع،
   يغلق `CloseDirectRecipient` حساب المستلم ويعيد rent إلى
   الحساب الذي دفعه.
5. تستدعي الجهة المخوَّلة `CloseDirectDistribution` لاسترداد الرصيد المتبقي في
   الخزنة وrent. إذا حُدد `clawbackTs`، فلا يُسمح بالإغلاق إلا بعد ذلك
   الوقت.

### توزيع Merkle

1. تبني الجهة المخوَّلة شجرة Merkle خارج السلسلة. تلتزم كل ورقة بمطالب،
   وبإجمالي مبلغ ذلك المطالب، وبجدول الاستحقاق.
2. تستدعي الجهة المخوَّلة `CreateMerkleDistribution` مع الجذر، وإجمالي المبلغ
   القابل للمطالبة، وقيمة `clawbackTs`، وتموّل الخزنة في التعليمة نفسها.
3. يستدعي المطالبون `ClaimMerkle` مع بيانات ورقتهم وإثباتها. تنشئ المطالبة الأولى
   حساب `MerkleClaim` الخاص بالمطالب. مرّر `amount: 0` للمطالبة
   بكل ما استُحق حاليًا.
4. بعد `clawbackTs`، تستدعي الجهة المخوَّلة `CloseMerkleDistribution` لاسترداد
   الرصيد المتبقي في الخزنة وrent.
5. بعد إغلاق التوزيع، يستدعي المطالبون `CloseMerkleClaim` لاسترداد
   rent حساب المطالبة الخاص بهم.

يجزّئ البرنامج الأوراق باستخدام Keccak-256 على النحو
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`، حيث
`totalAmount` هو `u64` بترتيب little-endian، ويستخدم `schedule` الترميز نفسه
المستخدم في وسيط `VestingSchedule` الخاص بالتعليمة. تُجزَّأ عقد الإثبات
كأزواج مرتبة، بحيث يأتي التجزئة الأصغر أولًا.

### الإلغاء

الإلغاء اختياري. يحدد القناع الثنائي `revocable` المضبوط عند الإنشاء الأوضاع
التي يجوز للجهة المخوَّلة استخدامها: يفعّل البت 0 الوضع `NonVested`، ويفعّل البت 1
الوضع `Full`، وتعطّل القيمة `0` الإلغاء.

| الوضع        | التعليمة                                    | النتيجة                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` أو `RevokeMerkleClaim` | تذهب الرموز المستحقة غير المطالَب بها إلى المستخدم؛ وتعود الرموز غير المستحقة إلى الجهة المخوَّلة |
| `Full`      | `RevokeDirectRecipient` أو `RevokeMerkleClaim` | تعود جميع الرموز غير المطالَب بها، المستحقة وغير المستحقة، إلى الجهة المخوَّلة               |

يؤدي إلغاء استحقاق مطالب ضمن Merkle إلى إنشاء علامة `Revocation` تمنع
المطالبات المستقبلية، حتى لو لم يطالب من قبل. أما إلغاء استحقاق مستلم مباشر فيغلق
حساب `DirectRecipient` الخاص به ويعيد rent الخاص بالحساب.
