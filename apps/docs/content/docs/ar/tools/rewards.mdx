يوزّع برنامج المكافآت الرموز من خزينة تملكها البرمجية إلى مجموعة من
المستلمين، ولكل منهم جدول استحقاق خاص. تموّل الجهة المسؤولة (authority) الخزينة وتحدد
من يحصل على ماذا. يطالب المستلمون برموزهم المستحقة بمرور الوقت، ويمكن
للجهة المسؤولة إلغاء استحقاق المستلمين أو استرداد الرموز المتبقية عندما يسمح
التوزيع بذلك. بُني البرنامج باستخدام Pinocchio، وتتولى صيانته مؤسسة سولانا
(Solana Foundation)، ويعمل مع كل من عملات SPL Token وToken-2022، باستثناء
عملات Token-2022 التي تستخدم إضافة transfer hook.

معرّف البرنامج (الشبكة الرئيسية وشبكة devnet):

```text

```

## اختر نوع التوزيع

يدعم البرنامج نوعين من التوزيع. يستخدم كلاهما جداول الاستحقاق
وأوضاع الإلغاء نفسها.

|                  | مباشر (Direct)                                       | Merkle                                                                   |
| ---------------- | -------------------------------------------- | ------------------------------------------------------------------------ |
| **آلية العمل** | ينشئ حسابًا على السلسلة لكل مستلم     | يخزّن جذر Merkle واحدًا على السلسلة؛ ويقدّم المستلمون إثباتات للمطالبة  |
| **التكلفة المبدئية** | يدفع الدافع rent لكل حساب مستلم | لا توجد حسابات لكل مستلم إلى أن يطالب أحدهم بحصته                           |
| **القابلية للتوسع**        | عملي حتى بضعة آلاف من المستلمين  | يتوسع إلى ملايين المستلمين؛ ولا يزداد التخزين إلا عند مطالبة المستلمين |
| **قابلية التعديل**   | يمكن إضافة مستلمين بعد الإنشاء       | مجموعة المستلمين ثابتة عند الإنشاء                                       |
| **مناسب لـ**   | التوزيعات الصغيرة التي تتغير بمرور الوقت    | التوزيعات الكبيرة الثابتة مثل airdrops                              |

## جداول الاستحقاق

يتبع كل تخصيص أحد أربعة جداول. الطوابع الزمنية بالثواني حسب نظام Unix.

| الجدول      | السلوك                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `Immediate`   | جميع الرموز قابلة للمطالبة فورًا                                                                                    |
| `Linear`      | تُفتح الرموز تناسبيًا بين `startTs` و`endTs`                                                             |
| `Cliff`       | لا يُفتح شيء حتى `cliffTs`، ثم تُفتح جميع الرموز دفعة واحدة                                                       |
| `CliffLinear` | استحقاق خطي من `startTs` إلى `endTs`، مع عدم إمكانية المطالبة بشيء حتى `cliffTs`؛ وتُفتح الكمية المتراكمة سابقًا عند الـ cliff |

## الحسابات

| الحساب              | seeds الخاصة بـ PDA                                        | يخزّن                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------- |
| `DirectDistribution` | `["direct_distribution", mint, authority, seed]` | الجهة المسؤولة والعملة وإجماليات التخصيص       |
| `DirectRecipient`    | `["direct_recipient", distribution, recipient]`  | تخصيص مستلم واحد واستحقاقه       |
| `MerkleDistribution` | `["merkle_distribution", mint, authority, seed]` | الجهة المسؤولة والعملة والإجماليات وجذر Merkle |
| `MerkleClaim`        | `["merkle_claim", distribution, claimant]`       | المبلغ الذي طالب به مطالب واحد حتى الآن        |
| `Revocation`         | `["revocation", distribution, user]`             | علامة تمنع مطالبًا ملغى استحقاقه في Merkle من المطالبة |

الـ `seed` هو عنوان موقّع إضافي يُمرَّر عند الإنشاء، بحيث يمكن لجهة
مسؤولة واحدة تشغيل عدة توزيعات لنفس العملة. خزينة كل توزيع
هي associated token account الخاص بـ PDA التوزيع لعملته.

## التعليمات

### التوزيع المباشر

1. تستدعي الجهة المسؤولة `CreateDirectDistribution` لإنشاء PDA التوزيع
   وخزينته.
2. تستدعي الجهة المسؤولة `AddDirectRecipient` مرة لكل مستلم مع تحديد المبلغ
   وجدول الاستحقاق. ينقل كل استدعاء ذلك المبلغ من token account
   الخاص بالجهة المسؤولة إلى الخزينة.
3. يستدعي المستلمون `ClaimDirect` لسحب الرموز المستحقة. مرّر `amount: 0` للمطالبة
   بكل ما استُحق حاليًا.
4. بمجرد مطالبة المستلم بكل ما له، أو إغلاق التوزيع،
   يغلق `CloseDirectRecipient` حساب المستلم ويعيد rent إلى
   الحساب الذي دفعه.
5. تستدعي الجهة المسؤولة `CloseDirectDistribution` لاسترداد رصيد الخزينة
   المتبقي وrent. إذا تم تعيين `clawbackTs`، فلا يُسمح بالإغلاق إلا بعد ذلك
   الوقت.

### توزيع Merkle

1. تبني الجهة المسؤولة شجرة Merkle خارج السلسلة. تلتزم كل ورقة بمطالب،
   ومجموع مبلغه، وجدول استحقاق.
2. تستدعي الجهة المسؤولة `CreateMerkleDistribution` مع الجذر، وإجمالي
   المبلغ القابل للمطالبة، و`clawbackTs`، وتموّل الخزينة ضمن التعليمة
   نفسها.
3. يستدعي المطالبون `ClaimMerkle` مع بيانات ورقتهم وإثباتها. تنشئ المطالبة الأولى
   حساب `MerkleClaim` الخاص بالمطالب. مرّر `amount: 0` للمطالبة
   بكل ما استُحق حاليًا.
4. بعد `clawbackTs`، تستدعي الجهة المسؤولة `CloseMerkleDistribution` لاسترداد
   رصيد الخزينة المتبقي وrent.
5. بعد إغلاق التوزيع، يستدعي المطالبون `CloseMerkleClaim` من أجل
   استرداد rent لحساب مطالبتهم.

يقوم البرنامج بحساب تجزئة الأوراق باستخدام Keccak-256 على النحو
`keccak256(0x00 || keccak256(claimant || totalAmount || schedule))`، حيث
إن `totalAmount` هو `u64` بترتيب little-endian، ويستخدم `schedule` الترميز نفسه
الخاص بوسيط `VestingSchedule` في التعليمة. تُجزَّأ عقد الإثبات
على شكل أزواج مرتبة، بحيث تأتي التجزئة الأصغر أولًا.

### الإلغاء

الإلغاء اختياري. تحدد القناع البتّي `revocable` المضبوط عند الإنشاء الأوضاع
التي يجوز للجهة المسؤولة استخدامها: يفعّل البت 0 وضع `NonVested`، ويفعّل البت 1 وضع `Full`،
وتعطّل القيمة `0` الإلغاء.

| الوضع        | التعليمة                                    | النتيجة                                                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- |
| `NonVested` | `RevokeDirectRecipient` أو `RevokeMerkleClaim` | تذهب الرموز المستحقة وغير المطالَب بها إلى المستخدم؛ وتعود الرموز غير المستحقة إلى الجهة المسؤولة |
| `Full`      | `RevokeDirectRecipient` أو `RevokeMerkleClaim` | تعود جميع الرموز غير المطالَب بها، المستحقة وغير المستحقة، إلى الجهة المسؤولة               |

يؤدي إلغاء استحقاق مطالب في Merkle إلى إنشاء علامة `Revocation` تمنع المطالبات
المستقبلية، حتى لو لم يطالب من قبل. أما إلغاء استحقاق مستلم مباشر فيغلق
حسابه `DirectRecipient` ويعيد rent الخاص به.
