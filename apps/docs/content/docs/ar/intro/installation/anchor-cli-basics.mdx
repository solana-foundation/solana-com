يوفر هذا القسم بعض الأوامر والأمثلة الشائعة لمساعدتك على البدء في استخدام
[Anchor CLI](https://www.anchor-lang.com/docs).

<Steps>
<Step>

### تهيئة المشروع

أنشئ مشروع Anchor جديدًا عبر تشغيل الأمر الموضح أدناه. سيؤدي هذا إلى إنشاء
مجلد جديد باسم المشروع واستخدامه لتهيئة مشروع Anchor
جديد.

```terminal
$ anchor init <project-name>
```

على سبيل المثال، سيُنشئ الأمر أدناه مشروعًا باسم `my-project`. سيحتوي المجلد
`my-project` على برنامج Rust معياري (modular) وقالب اختبار بلغة Rust
يستخدم LiteSVM.

```terminal
$ anchor init my-project
```

لإنشاء قالب اختبار بلغة TypeScript بدلًا من ذلك، اختر القالب صراحةً. على سبيل
المثال، استخدم قالب Mocha:

```terminal
$ anchor init my-project --test-template mocha
```

تتطلب قوالب اختبار TypeScript وجود Node.js ومدير حزم JavaScript.

ثم انتقل إلى مجلد المشروع:

```terminal
$ cd <project-name>
```

اطّلع على
[بنية ملفات المشروع](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) في Anchor.

</Step>
<Step>

### بناء البرنامج

لبناء مشروعك، قم بتشغيل الأمر التالي:

```terminal
$ anchor build
```

يمكنك العثور على البرنامج المترجم في دليل `/target/deploy`.

<Callout type="warn" title="فشل تثبيت أدوات المنصة">
  إذا أبلغت عملية البناء عن وجود مجلد platform-tools غير صالح، فأعد تثبيت أدوات بناء SBF
  ثم أعد محاولة البناء:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### نشر البرنامج

لنشر مشروعك، قم بتشغيل الأمر التالي:

```terminal
$ anchor deploy
```

ينشر هذا الأمر برنامجك إلى `cluster` المحدد في ملف
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml).

</Step>
<Step>

### اختبار البرنامج

لاختبار مشروعك، قم بتشغيل الأمر التالي:

```terminal
$ anchor test
```

يقوم هذا الأمر ببناء ونشر وتشغيل الاختبارات لمشروعك.

<Callout>
  عند استخدام مجموعة `localnet`، يقوم Anchor تلقائياً ببدء مدقق محلي، ونشر
  البرنامج، وتشغيل الاختبارات، ثم إيقاف المدقق.
</Callout>

<Callout type="warn" title="أخطاء مشغّل اختبارات JavaScript">

إذا اخترت قالب اختبار بلغة JavaScript أو TypeScript، فقد يشير أي من
الخطأين التاليين إلى أن Node.js أو مدير الحزم المهيّأ
غير مثبّت:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
