هناك أربع تعليمات تعيد الأموال دون إتمام التسوية: Reclaim وCancel وReject أثناء بقاء الصفقة مفتوحة، وRecover للإيداع الذي يصل بعد إغلاقها. لا تتحقق أي منها من انتهاء الصلاحية. وقد يظل أحد الجانبين محتجزًا بسبب حساب ضمان مجمَّد أو تغيّر في الـ mint، كما تصف الملاحظات في النهاية.

| التعليمة  | الموقِّع               | النطاق                         | حالة الصفقة بعد ذلك |
| ------------ | -------------------- | ----------------------------- | ---------------- |
| `ReclaimDvp` | `user_a` أو `user_b` | الجانب الخاص بالموقِّع          | ما تزال مفتوحة       |
| `CancelDvp`  | جهة التسوية | كلا الجانبين                     | مغلقة           |
| `RejectDvp`  | `user_a` أو `user_b` | كلا الجانبين                     | مغلقة           |
| `RecoverDvp` | `user_a` أو `user_b` | الجانب الخاص بالموقِّع، بعد الإغلاق | مغلقة سابقًا   |

في كل حالة يُفرَّغ حساب الضمان من كل ما يحتويه لصالح طرف ذلك الجانب: الضمان A إلى token account الخاص بـ `user_a` للـ `mint_a`، والضمان B إلى token account الخاص بـ `user_b` للـ `mint_b`، أيًّا كان من موّله. يُزوَّد memo program account لحسابات الاسترداد التي تتطلب memo.

تتابع هذه الصفحة الخطوات السابقة: ينتقل كلٌّ من العميل والموقِّعين من [إنشاء صفقة](/docs/defi/dvp-program/create-a-trade)، و`userAAtaA` و`userBAtaB` من [تمويل الجانبين](/docs/defi/dvp-program/fund-the-legs)، و`MEMO_PROGRAM_ID` و`authority` من [تسوية الصفقة](/docs/defi/dvp-program/settle-the-trade).

## استرجاع أحد الجانبين

تعيد Reclaim الجانب الخاص بالموقِّع وتُبقي الصفقة مفتوحة، بحيث يمكن تمويل ذلك الجانب مرة أخرى. استخدمها عندما تكون المشكلة في جانب الطرف المقابل؛ أما Cancel وReject فتغلقان الصفقة بأكملها.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getReclaimDvpInstruction } from "./dvp";

    // The asset-leg party takes its asset back.
    const reclaimInstruction = getReclaimDvpInstruction({
      signer: userASigner,
      swapDvp,
      mint: mintA,
      dvpSourceAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
    });

    await client.sendTransaction([reclaimInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::ReclaimDvpBuilder;

    // The asset-leg party takes its asset back.
    let reclaim_ix = ReclaimDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .mint(mint_a)
        .dvp_source_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .instruction();
    ```

  </Tab>
</Tabs>

## الإلغاء أو الرفض

توقّع جهةُ التسوية تعليمة Cancel، ويوقّع أيٌّ من الطرفين تعليمة Reject. تعيد كلتاهما ما يحتويه كل حساب ضمان إلى طرف جانبه، وتغلقان السجل وحسابَي الضمان معًا، ويذهب rent الحسابات المغلقة إلى الموقِّع. تأخذ التعليمتان الحسابات نفسها؛ والفرق الوحيد هو الموقِّع.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getCancelDvpInstruction, getRejectDvpInstruction } from "./dvp";

    const unwindAccounts = {
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    };

    // Signed by the settlement authority:
    const cancelInstruction = getCancelDvpInstruction({
      settlementAuthority: authoritySigner,
      ...unwindAccounts,
    });

    // Or signed by either party:
    const rejectInstruction = getRejectDvpInstruction({
      signer: userBSigner,
      ...unwindAccounts,
    });
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::{CancelDvpBuilder, RejectDvpBuilder};

    // Signed by the settlement authority:
    let cancel_ix = CancelDvpBuilder::new()
        .settlement_authority(authority)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();

    // Or signed by either party:
    let reject_ix = RejectDvpBuilder::new()
        .signer(user_b)
        .swap_dvp(swap_dvp)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .dvp_ata_a(escrow_a)
        .dvp_ata_b(escrow_b)
        .user_a_ata_a(user_a_ata_a)
        .user_b_ata_b(user_b_ata_b)
        .token_program_a(token_program_a)
        .token_program_b(token_program_b)
        .memo_program(MEMO_PROGRAM_ID)
        .leg_a_extras_count(0)
        .instruction();
    ```

  </Tab>
</Tabs>

يجب أن تكون حسابات الاسترداد (`userAAtaA` و`userBAtaB`) موجودة لأي جانب يحتوي على رصيد؛ فحساب الاسترداد غير المهيأ يجعل تحويل التوكن يفشل ويُلغي أثر التعليمة. أما الجانب الذي لم يُموَّل قط فلا يحتاج إلى تحويل ويتسامح مع غياب الحساب.

## استرداد إيداع متأخر

تغلق Settle وCancel وReject كلتا token accounts الخاصتين بالضمان، لذا يفشل أي تحويل عادي إلى حساب ضمان مغلق. لا يصل الإيداع بعد الإغلاق إلا إذا أعاد شيءٌ ما إنشاء حساب الضمان أولًا، مثل معاملة تمويل تتضمن تعليمة إنشاء associated token account بصيغة create-idempotent قبل التحويل، وكانت قيد التنفيذ عندما أرسل الطرف المقابل Reject. عندها تستقر التوكنات في حساب ضمان لم تعد صفقته موجودة: فالسجل اختفى، ولذلك لا تستطيع Reclaim العثور عليه، ويمنع الـ nonce tombstone إنشاء صفقة جديدة على العنوان نفسه والاستيلاء على الإيداع.

لاستخدام `RecoverDvp`، يزوّد طرف الجانب البرنامجَ بمدخلات الـ seed الأصلية (جهة التسوية، والطرفان، والـ mint ان، والـ nonce). يعيد البرنامج اشتقاق عنوان السجل، ويشترط وجود tombstone الخاص به كدليل على أن الصفقة كانت موجودة، ثم يُفرِّغ حساب الضمان إلى token account الخاص بالموقِّع ويغلقه، ويعيد rent حساب الضمان إلى الموقِّع. ويتحدد جانب الموقِّع بحسب الطرف الذي يوقّع: `mint_a` لـ `user_a`، و`mint_b` لـ `user_b`.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { getAddressEncoder, getProgramDerivedAddress } from "@solana/kit";
    import { DVP_SWAP_PROGRAM_PROGRAM_ADDRESS, getRecoverDvpInstruction } from "./dvp";

    const [nonceTombstone] = await getProgramDerivedAddress({
      programAddress: DVP_SWAP_PROGRAM_PROGRAM_ADDRESS,
      seeds: ["nonce", getAddressEncoder().encode(swapDvp)],
    });

    const recoverInstruction = getRecoverDvpInstruction({
      signer: userASigner,
      swapDvp,
      nonceTombstone,
      mint: mintA,
      dvpEscrowAta: escrowA,
      signerDestAta: userAAtaA,
      tokenProgram: tokenProgramA,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });

    await client.sendTransaction([recoverInstruction]);
    ```

  </Tab>

  <Tab value="Rust">
    ```rust
    use dvp_swap_program_client::instructions::RecoverDvpBuilder;

    let recover_ix = RecoverDvpBuilder::new()
        .signer(user_a)
        .swap_dvp(swap_dvp)
        .nonce_tombstone(nonce_tombstone)
        .mint(mint_a)
        .dvp_escrow_ata(escrow_a)
        .signer_dest_ata(user_a_ata_a)
        .token_program(token_program_a)
        .memo_program(MEMO_PROGRAM_ID)
        .settlement_authority(settlement_authority)
        .user_a(user_a)
        .user_b(user_b)
        .mint_a(mint_a)
        .mint_b(mint_b)
        .nonce(nonce)
        .instruction();
    ```

  </Tab>
</Tabs>

يعتمد الاسترداد على احتفاظ الطرف بمعاملات الإنشاء. فالنظام الذي يموّل الصفقات يخزّن مدخلات الـ seed مع كل أمر إلى أن تُغلق الصفقة ويتأكد من أن أرصدة حسابات الضمان فارغة.

## ملاحظات

- **الجوانب المجمَّدة.** في الـ mint المقيَّد بالصلاحيات، يمنع حساب الضمان المجمَّد تحويل التوكن الذي تنفّذه هذه التعليمات إلى أن تفك جهة التجميد التجميد. راجع [النظرة العامة](/docs/defi/dvp-program#mint-configuration-constraints).
- **تغيّر الـ mint بعد الإنشاء.** تتخطى مسارات التراجع فحوصات الامتدادات وصلاحية الـ mint حتى لا تعيق فحوصات البرنامج نفسه عملية الاسترداد. وتظل قواعد token program نفسه سارية. لا يمكن إغلاق الـ mint إلا عندما يكون المعروض صفرًا، لذا لا يمكن أن يتغير أثناء وجود رصيد في حساب الضمان، لكن إغلاق الـ mint وإعادة إنشائه بصفة NonTransferable أو برسوم تحويل قبل وصول إيداع متأخر قد يجعل ذلك الإيداع غير قابل للتحريك أو خاضعًا لرسوم. هذا هو الاعتماد على صلاحية الـ mint المذكور ضمن [التوكنات المدعومة](/docs/defi/dvp-program#supported-tokens).
