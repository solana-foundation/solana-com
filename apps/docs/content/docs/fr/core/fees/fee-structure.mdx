<Callout type="info" title="Résumé">
  Frais totaux = frais de base (5 000 lamports/signature, 50 % brûlés) + frais de priorité
  (CU_price * CU_limit / 1M lamports, 100 % au validator). Facturés que la
  transaction réussisse ou échoue.
</Callout>

## Algorithme de calcul des frais

Le montant total des frais d'une transaction est calculé par
[`calculate_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L53-L72) :

```text title="Total fee formula"
total_fee = base_fee + prioritization_fee
```

Les entrées sont le message de transaction, la valeur actuelle de `lamports_per_signature`
(actuellement 5 000) et les frais de priorité dérivés des instructions de budget de calcul.
Le montant total des frais est déduit du payeur de frais avant le début de l'exécution.
Si la transaction échoue, les frais sont tout de même prélevés.

## Frais de base

Les frais de base couvrent le coût de la vérification des signatures Ed25519 ainsi que
toute vérification de signature par précompilation. Chaque signature dans la transaction
est facturée, y compris les signatures vérifiées par les programmes de précompilation
Ed25519, Secp256k1 et Secp256r1.

La fonction
[`calculate_signature_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L75-L92)
calcule :

```text title="Base fee formula"
signature_count = num_transaction_signatures
                + num_ed25519_signatures
                + num_secp256k1_signatures
                + num_secp256r1_signatures   (if feature enabled)

base_fee = signature_count * lamports_per_signature
```

- `num_transaction_signatures` : le nombre de signatures Ed25519 sur la
  transaction (généralement une par signataire).
- `num_ed25519_signatures`, `num_secp256k1_signatures`,
  `num_secp256r1_signatures` : signatures vérifiées par les programmes de
  précompilation correspondants.
- `lamports_per_signature` : actuellement
  [5 000 lamports](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-structure/src/lib.rs#L210).

### Distribution des frais

Les frais de base et les frais de priorité sont distribués différemment. La fonction
[`calculate_reward_and_burn_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L85-L98)
dans le runtime calcule :

```text title="Fee distribution"
burn_amount     = transaction_fee * 50 / 100
validator_share = (transaction_fee - burn_amount) + priority_fee
```

- **Frais de base (transaction_fee)** : 50 % sont
  [brûlés](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L93)
  (retirés de la masse monétaire en circulation) et 50 % vont au
  validator qui produit le bloc. Le pourcentage brûlé est
  [`DEFAULT_BURN_PERCENT = 50`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-calculator/src/lib.rs#L70).
- **Frais de priorité** : 100 % vont au validator (rien n'est brûlé), conformément à
  [SIMD-0096](https://github.com/solana-foundation/solana-improvement-documents/blob/main/proposals/0096-reward-collected-priority-fee-in-entirety.md).

La récompense totale du validator pour une transaction est :

```text
validator_reward = (base_fee / 2) + prioritization_fee
```

## Frais de priorité

Les frais de priorité sont des frais optionnels qui augmentent la priorité d'ordonnancement
d'une transaction. Une unité de calcul (CU) est une unité de calcul que le runtime
mesurie lors de l'exécution de la transaction. Chaque opération (arithmétique, accès mémoire,
syscall) coûte un nombre fixe de CU. Vous pouvez définir les frais de priorité en
incluant des instructions de budget de calcul dans votre transaction. (Voir le
[guide d'utilisation des frais de priorité](/docs/core/fees) pour plus de détails.)

### Formule des frais de priorité

La fonction
[`get_prioritization_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L61-L69)
calcule :

```text title="Prioritization fee formula"
micro_lamport_fee = compute_unit_price * compute_unit_limit
prioritization_fee = ceil(micro_lamport_fee / 1,000,000)
```

| Variable             | Description                                                                                                                                                                       | Valeur par défaut                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `compute_unit_price` | Micro-lamports par CU, défini via `SetComputeUnitPrice`                                                                                                                              | 0 micro-lamport                |
| `compute_unit_limit` | Nombre maximum de CU que la transaction peut consommer, défini via `SetComputeUnitLimit`                                                                                                            | Somme des valeurs par défaut par instruction |
| `1 000 000`          | Facteur de conversion des micro-lamports en lamports ([`MICRO_LAMPORTS_PER_LAMPORT`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L17)) | --                              |

<Callout type="info" title="Les transactions v1 définissent les frais directement">
  Cette formule prix × limite s'applique aux transactions legacy et v0. Dans le
  [format v1](/docs/core/transactions/versioned-transactions#v1-format), les
  frais de priorité sont un total absolu en lamports défini directement dans la
  configuration du message — sans prix par CU, sans multiplication, sans arrondi.
</Callout>

### Limite d'unités de calcul

La limite d'unités de calcul est le nombre maximum de CU qu'une transaction peut consommer.
Si aucune instruction
[`SetComputeUnitLimit`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L32)
n'est incluse, la valeur par défaut est calculée à partir du nombre et du type
d'instructions (200 000 CU par instruction non intégrée, 3 000 par instruction intégrée). Voir
[Compute Budget](/docs/core/fees/compute-budget) pour plus de détails sur le calcul par défaut.

<Callout type="warn">
  Les frais de priorité sont basés sur la limite de CU demandée, et non sur l'utilisation réelle des CU.
  Définir une limite supérieure au nécessaire revient à payer pour des unités de calcul inutilisées.
</Callout>

### Prix de l'unité de calcul

Le prix de l'unité de calcul est un montant optionnel de micro-lamports payé pour chaque
CU demandé. Le prix des CU détermine directement les frais de priorité. Pour définir
le prix des CU, incluez une instruction
[`SetComputeUnitPrice`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L35)
dans votre transaction.

<Callout>
  Le prix des CU par défaut est 0, ce qui signifie que les frais de priorité par défaut sont également 0.
</Callout>

Pour des estimations du prix des CU en temps réel, consultez les fournisseurs d'API de frais de priorité ci-dessous.

| Fournisseur                                | API de frais de priorité                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| [Helius](https://www.helius.dev/)       | [Documentation](https://docs.helius.dev/solana-apis/priority-fee-api)             |
| [QuickNode](https://www.quicknode.com/) | [Documentation](https://marketplace.quicknode.com/add-on/solana-priority-fee)     |
| [Triton](https://triton.one/)           | [Documentation](https://docs.triton.one/chains/solana/improved-priority-fees-api) |

### Priorité d'ordonnancement des transactions

L'ordonnanceur classe les transactions à l'aide de la fonction
[`calculate_priority_and_cost`](https://github.com/anza-xyz/agave/blob/v3.1.8/core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs#L526-L546) :

```text title="Transaction priority formula"
Priority = reward * 1,000,000 / (cost + 1)
```

- **reward** : les revenus de frais du validator = frais de priorité + part non brûlée
  des frais de base. Calculé par
  [`calculate_reward_for_transaction`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L64-L83).
- **cost** : le
  [coût estimé en CU](https://github.com/anza-xyz/agave/blob/v3.1.8/cost-model/src/cost_model.rs#L37-L57)
  de l'ordonnanceur (coûts de signature + coûts de verrou en écriture + coûts d'instruction data + coûts
  d'exécution du programme + coût de la taille des données des comptes chargés). Voir
  [Compute Budget](/docs/core/fees/compute-budget#scheduler-cost-model) pour
  plus de détails.
- **1 000 000** : un multiplicateur pour préserver la précision, car le coût dépasse souvent
  la récompense en lamports bruts.
- **+1** : empêche la division par zéro.

La priorité détermine l'ordre dans lequel les transactions sont retirées de la file d'attente de
l'ordonnanceur pour être exécutées.

```ts !! title="Web3.js v3"
import {
  LAMPORTS_PER_SOL,
  SystemProgram,
  Transaction,
  Keypair,
  Connection,
  ComputeBudgetProgram,
  sendAndConfirmTransaction
} from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");

const sender = await Keypair.generate();
const recipient = await Keypair.generate();

const airdropSignature = await connection.requestAirdrop(
  sender.publicKey,
  LAMPORTS_PER_SOL
);
await connection.confirmTransaction(airdropSignature, "confirmed");

// Create compute budget instructions
const limitInstruction = ComputeBudgetProgram.setComputeUnitLimit({
  units: 300_000
});
const priceInstruction = ComputeBudgetProgram.setComputeUnitPrice({
  microLamports: 1
});

const transferInstruction = SystemProgram.transfer({
  fromPubkey: sender.publicKey,
  toPubkey: recipient.publicKey,
  lamports: 0.01 * LAMPORTS_PER_SOL
});

// Add the compute budget and transfer instructions to a new transaction
const transaction = new Transaction()
  .add(limitInstruction)
  .add(priceInstruction)
  .add(transferInstruction);

const signature = await sendAndConfirmTransaction(connection, transaction, [
  sender
]);

console.log("Transaction Signature:", signature);
```

```rust !! title="Rust"
use solana_client::nonblocking::rpc_client::RpcClient;
use solana_commitment_config::CommitmentConfig;
use solana_compute_budget_interface::ComputeBudgetInstruction;
use solana_sdk::{
    native_token::LAMPORTS_PER_SOL,
    signature::{Keypair, Signer},
    transaction::Transaction,
};
use solana_system_interface::instruction::transfer;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = RpcClient::new_with_commitment(
        String::from("http://localhost:8899"),
        CommitmentConfig::confirmed(),
    );

    let sender = Keypair::new();
    let recipient = Keypair::new();

    let airdrop_signature = client
        .request_airdrop(&sender.pubkey(), LAMPORTS_PER_SOL)
        .await?;

    loop {
        let confirmed = client.confirm_transaction(&airdrop_signature).await?;
        if confirmed {
            break;
        }
    }

    // Create compute budget instructions
    let limit_instruction = ComputeBudgetInstruction::set_compute_unit_limit(300_000);
    let price_instruction = ComputeBudgetInstruction::set_compute_unit_price(1);

    let transfer_amount = LAMPORTS_PER_SOL / 100;
    let transfer_instruction = transfer(&sender.pubkey(), &recipient.pubkey(), transfer_amount);

    let recent_blockhash = client.get_latest_blockhash().await?;

    let mut transaction = Transaction::new_with_payer(
        &[limit_instruction, price_instruction, transfer_instruction],
        Some(&sender.pubkey()),
    );
    transaction.sign(&[&sender], recent_blockhash);

    let signature = client.send_and_confirm_transaction(&transaction).await?;
    println!("Transaction Signature: {}", signature);

    Ok(())
}
```
