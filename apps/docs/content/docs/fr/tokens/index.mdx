Les tokens sont des actifs numériques qui représentent la propriété de diverses
catégories d'actifs. La tokenisation permet la numérisation des droits de
propriété. Les tokens sur Solana sont appelés tokens SPL
([Solana Program Library](https://github.com/solana-program)).

Cette section couvre les concepts de base de la représentation des tokens sur
Solana. Consultez la section [Bases des tokens SPL](/docs/tokens/basics) pour
des exemples de code.

## Points clés

- Les [Token Programs](#token-programs) contiennent toute la logique d'instruction pour
  interagir avec les tokens du réseau (fongibles et non fongibles).

- Un [mint account](#mint-account) représente un token spécifique et stocke les
  métadonnées globales du token telles que l'offre totale et l'autorité de
  frappe (adresse autorisée à créer de nouvelles unités d'un token).

- Un [token account](#token-account) suit la propriété individuelle des tokens
  pour un mint account spécifique et un propriétaire spécifique.

- Un [associated token account](#associated-token-account) est un token account
  créé avec une adresse dérivée des adresses du propriétaire et du mint account.

## Token Programs

Le Token Program contient toute la logique d'instruction pour interagir avec les tokens du
réseau (fongibles et non fongibles). Tous les tokens sur Solana sont effectivement
des [comptes de données](/docs/core/accounts/account-types#data-accounts) appartenant à un
Token Program.

![Token Program](/assets/docs/core/tokens/token-program.svg)

### Mint account

Les tokens sur Solana sont identifiés de manière unique par l'adresse d'un
[mint account](https://github.com/solana-program/token/blob/6d18ff73b1dd30703a30b1ca941cb0f1d18c2b2a/program/src/state.rs#L16-L30)
appartenant au Token Program. Ce compte agit comme un compteur global pour un
token spécifique et stocke des données telles que :

- **Supply** : offre totale du token
- **Decimals** : précision décimale du token
- **Mint authority** : le compte autorisé à créer de nouvelles unités du token,
  augmentant ainsi l'offre
- **Freeze authority** : le compte autorisé à geler les tokens dans un token
  account, les empêchant d'être transférés ou brûlés

L'autorité de frappe est configurée lors de l'initialisation du mint. Elle autorise
les frappes futures, mais il n'est pas nécessaire que ce soit le compte qui a créé ou financé
le mint account.

![Mint Account](/assets/docs/core/tokens/mint-account.svg)

Les détails complets stockés sur chaque mint account incluent les éléments
suivants :

```rust title="Mint Account State"
pub struct Mint {
    /// Optional authority used to mint new tokens. The mint authority may only
    /// be provided during mint creation. If no mint authority is present
    /// then the mint has a fixed supply and no further tokens may be
    /// minted.
    pub mint_authority: COption<Pubkey>,
    /// Total supply of tokens.
    pub supply: u64,
    /// Number of base 10 digits to the right of the decimal place.
    pub decimals: u8,
    /// Is `true` if this structure has been initialized
    pub is_initialized: bool,
    /// Optional authority to freeze token accounts.
    pub freeze_authority: COption<Pubkey>,
}
```

Pour référence, voici un lien Solana Explorer vers le
[mint account USDC](https://explorer.solana.com/address/EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v).

### Token Account

Le Token Program crée des
[token accounts](https://github.com/solana-program/token/blob/6d18ff73b1dd30703a30b1ca941cb0f1d18c2b2a/program/src/state.rs#L87-L108)
pour suivre la propriété individuelle de chaque unité de token. Un token account
stocke des données telles que :

- **Mint** : le token dont le token account détient des unités
- **Owner** : le compte autorisé à transférer des tokens depuis le token account
- **Amount** : nombre de tokens que le token account détient actuellement

![Token Account](/assets/docs/core/tokens/token-account.svg)

Les détails complets stockés sur chaque token account incluent les éléments
suivants :

```rust title="Token Account State"
pub struct Account {
    /// The mint associated with this account
    pub mint: Pubkey,
    /// The owner of this account.
    pub owner: Pubkey,
    /// The amount of tokens this account holds.
    pub amount: u64,
    /// If `delegate` is `Some` then `delegated_amount` represents
    /// the amount authorized by the delegate
    pub delegate: COption<Pubkey>,
    /// The account's state
    pub state: AccountState,
    /// If is_native.is_some, this is a native token, and the value logs the
    /// rent-exempt reserve. An Account is required to be rent-exempt, so
    /// the value is used by the Processor to ensure that wrapped SOL
    /// accounts do not drop below this threshold.
    pub is_native: COption<u64>,
    /// The amount delegated
    pub delegated_amount: u64,
    /// Optional authority to close the account.
    pub close_authority: COption<Pubkey>,
}
```

Un portefeuille a besoin d'un token account pour chaque token (mint) qu'il
souhaite détenir, avec l'adresse du portefeuille définie comme propriétaire du
token account. Chaque portefeuille peut posséder plusieurs token accounts pour
le même token (mint), mais un token account ne peut avoir qu'un seul
propriétaire et détenir des unités d'un seul token (mint).

![Relation des comptes](/assets/docs/core/tokens/token-account-relationship.svg)

<Callout type="info">

Notez que les données de chaque token account incluent un champ `owner` identifiant qui
détient l'autorité sur le token account. Cela diffère du propriétaire du programme
spécifié dans le type de base
[Account](/docs/core/accounts/account-structure#account-fields), qui est
le Token Program pour tous les token accounts.

</Callout>

### Associated Token Account

Les Associated Token Accounts simplifient le processus de recherche de l'adresse
d'un token account pour un mint et un propriétaire spécifiques. Considérez
l'Associated Token Account comme le token account « par défaut » pour un mint et
un propriétaire spécifiques.

Un Associated Token Account est créé avec une adresse dérivée de l'adresse du
propriétaire et de l'adresse du mint account. Il est important de comprendre
qu'un Associated Token Account est simplement un token account avec une adresse
spécifique.

La création d'un ATA nécessite un solde minimum remboursable pour le stockage de son compte.
Le payeur de l'instruction finance ce solde, même lorsqu'un autre portefeuille est propriétaire de
l'ATA. Voir
[Coût et payeur de l'ATA](/docs/tokens/basics/create-token-account#cost-and-payer)
pour les coûts actuels et les différences de dimensionnement avec Token-2022.

Cela introduit un concept clé du développement Solana :
[Program Derived Address (PDA)](/docs/core/pda). Un PDA dérive une adresse de
manière déterministe en utilisant des entrées prédéfinies, ce qui facilite la
recherche de l'adresse d'un compte.

![Associated Token Account](/assets/docs/core/tokens/associated-token-account.svg)

Notez que chaque portefeuille a besoin de son propre token account pour détenir
des tokens provenant du même mint.

![Relations des Comptes Étendue](/assets/docs/core/tokens/token-account-relationship-ata.svg)
