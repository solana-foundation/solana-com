L'interface en ligne de commande `spl-token` permet de créer et de gérer des mints, des token
accounts, des autorités, des transferts et des extensions Token-2022.

Cette référence correspond à
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
la version fournie avec Agave v4.2.1. Exécutez `spl-token --version` et utilisez
`<command> --help` pour connaître les options exactes disponibles dans votre version installée.

<Callout type="warn">
  La création de mints, les transferts, les changements d'autorité, les burns, les gels et la fermeture de comptes
  soumettent des transactions. Confirmez le cluster, le Token Program, le signataire et
  les adresses avant d'exécuter une commande. Les modifications sur le mainnet utilisent de vrais actifs.
</Callout>

## Installer et obtenir de l'aide

Le bundle de la CLI Agave inclut `spl-token`. S'il n'est pas installé, utilisez
le crate Rust publié :

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Consultez l'aide à la racine ou au niveau d'une commande :

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Options globales

Placez les options globales avant la commande.

| Option                                       | Objectif                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Sélectionne une URL RPC ou `mainnet-beta`, `testnet`, `devnet` ou `localhost`. |
| `-C, --config <PATH>`                        | Utilise un autre fichier de configuration de la CLI Solana.                            |
| `--fee-payer <KEYPAIR>`                      | Sélectionne le compte qui paie les frais de transaction.                            |
| `-p, --program-id <ADDRESS>`                 | Utilise un ID de Token Program explicite.                                         |
| `--program-2022`                             | Utilise Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Renvoie `json` ou `json-compact` lorsque c'est pris en charge.                          |
| `--with-compute-unit-limit <UNITS>`          | Définit la limite d'unités de calcul de la transaction.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Définit le prix de priorité par unité de calcul.                                  |
| `-v, --verbose`                              | Affiche une sortie supplémentaire.                                                   |
| `-V, --version`                              | Affiche la version installée de la CLI.                                          |

Le programme par défaut est le Token Program d'origine. Utilisez `--program-2022` pour un
mint ou un compte Token-2022, y compris pour le lire. Une commande échoue si le
programme sélectionné n'est pas propriétaire de l'adresse fournie.

## Créer et utiliser un token

Les commandes affichent les adresses créées. Conservez l'adresse du mint renvoyée par
`create-token` pour les commandes suivantes.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Les montants sont des montants de tokens en unités d'interface (UI), ajustés en fonction des décimales du mint. Des commandes comme
`transfer`, `burn` et `unwrap-sol` acceptent `ALL` lorsque cela est indiqué dans leur aide.

## Créer un mint Token-2022

Les extensions allouent un état supplémentaire au mint ou au compte et doivent généralement être choisies lors de
la création du mint. Cet exemple crée un mint à six décimales avec prise en charge des
métadonnées intégrées :

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Les options d'extension courantes de `create-token` incluent :

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` et `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` ou `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` avec
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Ne combinez que les extensions que le programme Token-2022 autorise ensemble. Consultez le
[guide des extensions Token-2022](/docs/tokens/extensions) pertinent avant de créer
une configuration de mint irréversible.

## Gérer les autorités et les délégués

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` prend en charge les types d'autorité mint, freeze, owner, close et ceux propres
aux extensions. Supprimer une autorité avec `--disable` est définitif si aucun
autre mécanisme du programme ne peut la rétablir.

## Geler, brûler et fermer

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` réduit à la fois le solde du compte et l'offre totale. `close` renvoie les
lamports restants du compte au destinataire configuré ; il ne récupère pas les
tokens brûlés.

## Wrapper et unwrapper des SOL

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Utilisez `sync-native` après avoir transféré des lamports directement vers un token
account de SOL wrappés afin que son montant de tokens corresponde aux lamports sous-jacents.

## Signature multisig

Créez un multisig Token Program M-sur-N comptant jusqu'à 11 membres :

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

Pour une transaction contrôlée par ce multisig, transmettez l'adresse du multisig comme
autorité concernée et fournissez les keypairs des membres via des valeurs
`--multisig-signer` répétées. Consultez l'aide de la commande ciblée, car son indicateur
d'autorité principale varie selon l'opération.

## Soldes confidentiels

Les commandes de solde confidentiel nécessitent un mint Token-2022 configuré pour
les transferts confidentiels et un compte destinataire configuré.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Pour `configure-confidential-transfer-account` et `apply-pending-balance`, transmettez
soit `--address <TOKEN_ACCOUNT_ADDRESS>`, soit un `<MINT_ADDRESS>` positionnel, mais pas
les deux. La forme positionnelle utilise l'associated token account du propriétaire. Le dépôt et
le retrait prennent toujours le mint et acceptent `--address` pour remplacer ce compte par défaut.

Utilisez `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits` et `disable-non-confidential-credits` pour
contrôler les dépôts que le compte accepte. Ces paramètres affectent la
confidentialité du compte et la compatibilité des paiements ; inspectez le compte avant de les modifier.

## Signature structurée et hors ligne

Utilisez la sortie structurée plutôt que d'analyser le texte affiché :

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Les commandes qui produisent des transactions prennent généralement en charge `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce` et `--nonce-authority`. Les entrées
hors ligne exactes dépendent de la commande, des décimales du mint et de la configuration des autorités ;
générez donc le message non signé en suivant les instructions `--help` de cette commande et
vérifiez chaque adresse avant de collecter les signatures.
