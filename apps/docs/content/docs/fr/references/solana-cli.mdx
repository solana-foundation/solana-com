L'interface en ligne de commande `solana` permet de configurer la connexion à un cluster, de lire
l'état du réseau, d'envoyer des SOL, de gérer les nonces durables, de déployer des programmes et de gérer
des comptes de stake et de vote.

Cette référence correspond à
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Exécutez
`solana --version` pour vérifier la version installée et utilisez `--help` pour connaître les
options exactes disponibles dans cette version.

<Callout type="warn">
  Les commandes qui créent, transfèrent, autorisent, retirent ou déploient soumettent des
  transactions. Vérifiez le cluster configuré et le signataire avant de les exécuter.
  Les tokens de Devnet et de Testnet n'ont aucune valeur ; les commandes sur Mainnet utilisent de vrais SOL.
</Callout>

## Structure des commandes

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Obtenir de l'aide à n'importe quel niveau :

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Options globales

Les options globales peuvent être placées avant la commande. L'aide propre à chaque commande reprend
les options qui s'appliquent à celle-ci.

| Option                          | Objectif                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Sélectionne une URL RPC ou `mainnet-beta`, `testnet`, `devnet` ou `localhost`.      |
| `--ws <URL>`                    | Remplace le point de terminaison WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Sélectionne un fichier keypair, `ASK`, l'entrée standard (`-`) ou une URL de signataire prise en charge.          |
| `-C, --config <FILEPATH>`       | Utilise un autre fichier de configuration de la CLI.                                        |
| `--commitment <LEVEL>`          | Lit avec un niveau de commitment `processed`, `confirmed` ou `finalized`.                   |
| `--output <FORMAT>`             | Renvoie `json` ou `json-compact` lorsque c'est pris en charge.                               |
| `--skip-preflight`              | Envoie sans simulation RPC. À utiliser uniquement si vous mesurez les risques d'échec. |
| `--use-tpu-client`              | Envoie les transactions via le client TPU.                                      |
| `--no-address-labels`           | Affiche les adresses sans les libellés locaux.                                          |
| `--skip-seed-phrase-validation` | Autorise une phrase de récupération ne figurant pas dans la liste anglaise BIP39.                       |
| `-v, --verbose`                 | Affiche des informations supplémentaires en sortie de la commande.                                                |
| `-V, --version`                 | Affiche la version installée de la CLI.                                               |

## Configurer la CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

La configuration contient une URL RPC, une URL WebSocket, le signataire par défaut et le
commitment. Une option de ligne de commande remplace la valeur enregistrée pour cette invocation.

## Workflows courants pour les comptes et les transactions

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` accepte des SOL par défaut. Utilisez `ALL` comme montant pour transférer le solde
disponible après déduction des frais. Pour des exemples avec des tokens, consultez le
[guide de démarrage rapide des tokens](/docs/tokens/quickstart).

## Workflows des programmes

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Passez `--program-id <KEYPAIR_OR_ADDRESS>` lorsqu'un déploiement doit utiliser un
identifiant de programme connu. `--final` rend un nouveau déploiement immuable ; lisez attentivement son aide
avant de l'utiliser, car l'autorité de mise à niveau ne peut pas être restaurée.

## Workflows des nonces durables

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Utilisez `authorize-nonce-account` pour changer l'autorité du nonce et `nonce-account`
pour inspecter l'état complet du compte. Les transactions utilisant un nonce acceptent également
`--nonce` et `--nonce-authority` sur les commandes qui les prennent en charge.

## Workflows de staking

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

La désactivation se termine à la limite d'un epoch et peut prendre plus d'un epoch.
Utilisez `stakes`, `validators`, `stake-history` et `stake-minimum-delegation` pour
inspecter l'état du cluster et des délégations avant de soumettre des modifications.

## Utilitaires d'adresses

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

Les seeds de PDA utilisent le format `PREFIX:VALUE`. Les préfixes pris en charge incluent `string`, `pubkey`,
`hex`, `u8`, ainsi que des encodages d'entiers signés ou non signés de largeur fixe, tels que
`u64le`.

## Messages hors chaîne et complétion du shell

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Sortie pour les scripts

Utilisez `--output json` ou `--output json-compact` lorsque c'est pris en charge, plutôt que
d'analyser une sortie lisible par un humain :

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Toutes les commandes ne prennent pas en charge la sortie structurée. Consultez l'aide de la commande avant
de vous y fier dans une automatisation, et considérez un code de sortie non nul comme un échec.
