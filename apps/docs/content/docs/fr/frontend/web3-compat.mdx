Si vous venez de `@solana/web3.js` (legacy), de `@solana/wallet-adapter-*`,
ou des anciens packages framework-kit (`@solana/client`, `@solana/react-hooks`,
`@solana/web3-compat`), nous vous encourageons à migrer vers les plugins `@solana/kit` ou
vers `@solana/web3.js` v3 (ou une version ultérieure).

Cette page met en correspondance les concepts que vous connaissez déjà avec leurs équivalents dans Kit.

## Correspondance des concepts

| web3.js (legacy) / wallet-adapter      | Kit                                                                  |
| -------------------------------------- | -------------------------------------------------------------------- |
| `new Connection(url)`                  | `createSolanaRpc(url)`, ou `.use(solanaRpc({ rpcUrl }))` sur un client |
| `PublicKey`                            | `Address` — convertir une chaîne avec `address("...")`                    |
| `Keypair`                              | `generateKeyPairSigner()` ou les plugins `@solana/kit-plugin-signer` |
| `SystemProgram.transfer(...)`          | `getTransferSolInstruction(...)` de `@solana-program/system`       |
| `LAMPORTS_PER_SOL` math                | `lamports(...)` de `@solana/kit`                                   |
| `Transaction` / `VersionedTransaction` | Messages de transaction construits et empaquetés par le planificateur de transactions     |
| `sendAndConfirmTransaction(...)`       | `client.sendTransaction([...])` (le planificateur signe, envoie et confirme) |
| `@solana/wallet-adapter-*`             | `@solana/kit-plugin-wallet` + découverte via Wallet Standard              |

web3.js v3 conserve les noms basés sur des classes ci-dessus — `Connection`, `Keypair`,
`Transaction`, `PublicKey` — sous forme de wrappers légers autour des composants internes de Kit, de sorte que la
colonne Kit décrit également ce que ces classes font en coulisses dans la v3.

## Vous venez de web3.js ?

Si vous maintenez une grande base de code `@solana/web3.js` (legacy) et qu'une réécriture complète
vers Kit n'est pas envisageable, web3.js v3 fait office de passerelle. Installez-le avec
`@solana/web3.js@3`. Il reconstruit l'API classique basée sur des classes — `Connection`,
`Keypair`, `Transaction`, `PublicKey` — au-dessus des composants internes de `@solana/kit`.
Comme il repose sur Kit, l'interopérabilité est étroite : `PublicKey` est le type d'adresse principal
et sa méthode `.toBase58()` renvoie la chaîne `Address` typée (branded) de Kit, et un `Keypair` v3
implémente le `KeyPairSigner` de Kit, ce qui vous permet de le passer directement aux API de Kit,
aux plugins et aux clients générés par Codama.

<Callout type="warn" title="Transactions v1 et web3.js (legacy)">
  Si vous envoyez des transactions v1 avec web3.js, vous devez utiliser la v3 ou une version ultérieure.
</Callout>

Pour la migration elle-même, consultez le
[guide de migration de web3.js v1 vers v3](https://github.com/solana-foundation/solana-web3.js/blob/main/docs/web3js-v1-to-v3-migration.md) officiel.

## Portefeuilles

Kit n'utilise pas wallet-adapter. `@solana/kit-plugin-wallet` découvre les
portefeuilles compatibles Wallet Standard et les expose via `client.wallet` et
les [hooks React](/docs/frontend/react-hooks). Les portefeuilles modernes
(Phantom, Solflare, Backpack, et autres) s'annoncent via Wallet Standard, donc
aucun package adaptateur par portefeuille n'est requis.

Vous pouvez également utiliser des outils prêts à l'emploi comme
[@solana/connector](https://www.npmjs.com/package/@solana/connector), qui
utilise directement les primitives de Kit pour se connecter aux portefeuilles.

<Callout type="info" title="Vous utilisez encore wallet-adapter ?">
  Si vous maintenez une application construite sur `@solana/wallet-adapter-*` et
  que vous n'êtes pas prêt à migrer, le [dépôt wallet-adapter
](https://github.com/anza-xyz/wallet-adapter) reste la référence pour cette
  stack. Pour tout nouveau projet, privilégiez le plugin de portefeuille Kit.
</Callout>
