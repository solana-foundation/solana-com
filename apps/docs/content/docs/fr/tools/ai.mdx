# Travailler avec les LLM et les agents sur Solana

Avant de plonger dans les outils spécifiques, comprenons les composants clés de la
pile de développement IA :

## Comprendre la pile IA

1. **Grands modèles de langage (LLM)**
   - Les modèles d'IA fondamentaux (comme GPT-4, Claude ou Llama)
   - Traitent et génèrent du langage naturel
   - Fournissent des capacités brutes d'intelligence et de raisonnement
   - Exemples : GPT-4 d'OpenAI, Claude d'Anthropic, Llama de Meta

2. **Frameworks d'agents (comme Eliza)**
   - Construits au-dessus des LLM pour créer des agents autonomes
   - Gèrent les personnalités et comportements des agents
   - Gèrent la mémoire et le contexte
   - Offrent une intégration multi-plateformes
   - Exemples : Eliza, LangChain, AutoGPT, Vercel AI

3. **Kits d'agents spécialisés (comme Solana Agent Kit)**
   - Conçus pour des cas d'usage spécifiques (p. ex. opérations blockchain)
   - Fournissent des outils et intégrations prêts à l'emploi
   - Abstraient la complexité technique
   - Fonctions blockchain prêtes à l'emploi
   - Exemples : Solana Agent Kit, GOAT Toolkit

Voyez les choses ainsi :

- Les LLM sont le « cerveau » capable de comprendre et de générer du langage
- Les frameworks d'agents sont le « système d'exploitation » qui gère le comportement de l'IA
- Les kits spécialisés sont les « applications » qui confèrent à l'IA des capacités spécifiques

# Développer des agents IA pour Solana

Ce guide vous montrera comment :

- Créer un agent IA de base avec le Solana Agent Kit de SendAI
- Créer un bot Twitter avec le framework Eliza
- Comprendre les options d'intégration de l'IA onchain
- Options pour créer des bots de trading avancés

## Introduction aux agents IA sur Solana

Les agents IA sur Solana sont des programmes autonomes capables d'interagir avec la
blockchain grâce au traitement du langage naturel et à l'apprentissage automatique. Ils peuvent :

- Exécuter des transactions
- Surveiller l'activité de la blockchain
- Interagir avec des contrats intelligents
- Fournir une assistance aux utilisateurs
- Automatiser des flux de travail complexes

## Frameworks disponibles

Plusieurs frameworks sont disponibles pour créer des agents IA sur Solana :

1. **Solana Agent Kit de SendAI**

- Une collection d'outils pour créer des agents sur Solana
- Compatible avec Eliza, Langchain et Vercel AI SDK
- Outils et utilitaires Solana intégrés
- Capacités de traitement du langage naturel
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Documentation](https://docs.solanaagentkit.xyz/)

2. **Framework Eliza**

- Combine couche de données, LLM et agents, et dispose d'un plugin Solana dédié
- Architecture d'agents extensible
- Intégration facile avec des projets existants et peut être utilisé par exemple pour
  des bots Twitter (X), Telegram ou Discord
- [Dépôt GitHub](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Kit de développement complet
- Compatibilité multi-chaînes
- [Dépôt GitHub](https://github.com/goat-sdk/goat)

4. **Framework Rig**

- Implémentation native en Rust
- Idéal pour les bots de trading haute performance
- Peut être combiné avec le toolkit Listen.rs pour l'intégration Solana, la surveillance des transactions
  et l'envoi de transactions via des bundles Jito par exemple
- [Dépôt GitHub](https://github.com/0xPlaygrounds/rig)
- [Dépôt Listen.rs](https://github.com/piotrostr/listen)

Si vous développez un framework IA, n'hésitez pas à ouvrir une PR pour l'ajouter à la liste

### Créer le script de l'agent

Créez un nouveau fichier appelé `agent.ts` avec le contenu suivant :

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

## Développer avec le framework Eliza

[ElizaOS](https://github.com/elizaOS/eliza) (anciennement connu sous le nom d'Ai16z) est un
framework IA. Il combine plusieurs applications en une seule et
organise leurs interactions. Il regroupe :

1. Différents LLM pour comprendre l'utilisateur
2. Des agents blockchain avec différentes actions (comme la frappe d'un NFT par exemple)
3. Des couches de données pour stocker l'état des personnages entre les actions, en utilisant par exemple
   Redis, PostgreSQL DB ou le stockage local
4. Différents clients comme X, Telegram, Discord, etc.

Il rassemble tous ces éléments et les articule de façon à vous permettre de créer un
« Personnage » capable d'interagir avec des utilisateurs ou de manière autonome. Ces personnages sont
définis dans un fichier JSON, qui précise quelles actions il peut effectuer, quel LLM il
doit utiliser et différents prompts qui définissent le comportement du personnage.

## Intégration d'agents dans des programmes onchain

Si vous souhaitez utiliser la réponse d'un agent dans un programme Solana, vous devez utiliser un
oracle qui écrit les données de réponse dans un compte que votre programme peut lire.
Vous pouvez trouver un exemple de LLM qui transfère des tokens à tout utilisateur qui
répond correctement aux questions ici :

[Interaction LLM avec un programme on-chain](https://github.com/GabrielePicco/super-smart-contracts)

Voici un exemple de programme on-chain qui s'intègre avec un oracle LLM (IA)
pour créer un agent interactif de distribution de tokens nommé "Mar1o".

### Fonctionnalités clés

1. **Interaction avec l'agent IA**
   - Les utilisateurs peuvent discuter avec Mar1o pour tenter de gagner des tokens
   - L'agent évalue les connaissances Solana de l'utilisateur pour déterminer les montants de tokens
   - Les réponses sont au format JSON avec le texte de réponse et le montant de tokens

2. **Gestion des tokens**
   - Crée des tokens MAR1O avec métadonnées
   - Peut émettre entre 0 et 10 000 tokens en fonction de la réponse de l'IA
   - Utilise des PDAs pour la gestion des tokens

### Fonctionnement du programme

Voici comment fonctionne ce programme :

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Cela démontre comment combiner les capacités de l'IA avec la mécanique de tokens on-chain pour
créer des expériences blockchain interactives. Voici un
[exemple en direct](https://mar1o.xyz/) où vous pouvez essayer de convaincre l'Agent de
vous transférer des tokens.

## Agents Rust avancés pour le trading algorithmique

Si vous souhaitez écrire vos agents en Rust, vous pouvez utiliser le
[framework Rig](https://github.com/0xPlaygrounds/rig) et la
bibliothèque [Listen.rs](https://github.com/piotrostr/listen).

Ces deux outils fonctionnent très bien ensemble. Tandis que le framework Rig vous offre un moyen simple de
vous connecter aux LLMs, la boîte à outils Listen.rs vous fournit l'intégration Solana,
notamment la surveillance des transactions et l'envoi de transactions via des bundles Jito
par exemple.

## Bonnes pratiques

- Sachez que votre agent possède une clé privée et peut donc accéder aux fonds de votre
  portefeuille. Si quelqu'un peut discuter avec votre agent et que celui-ci dispose d'une action de transfert,
  les utilisateurs pourront probablement le pousser à leur transférer vos fonds.
- Utilisez des [points de terminaison RPC](https://solana.com/rpc) payants. Les points de terminaison publics
  sont généralement soumis à des limitations de débit
- Surveillez les activités de l'agent et assurez-vous qu'il n'effectue rien de malveillant
  ou qu'il ne se laisse pas manipuler par des utilisateurs interagissant avec lui
- Implémentez des frais de priorité et des tentatives de retransmission dans les actions de votre agent afin
  qu'elles aboutissent même en cas de congestion du réseau
- Si possible, testez d'abord sur le devnet avant de déployer sur le mainnet. La plupart des agents
  prennent simplement l'URL RPC en entrée et vous pouvez utiliser une URL devnet jusqu'à ce que vous soyez
  prêt pour le mainnet. Toutes les actions ne sont cependant pas nécessairement réalisables sur le devnet.
- Lorsque vous écrivez vos propres actions, ajoutez des tests d'intégration afin que les
  frameworks puissent surveiller quelles actions échouent en raison de modifications de programmes ou d'APIs
