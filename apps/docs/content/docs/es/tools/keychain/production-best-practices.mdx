Keychain abstrae el backend de firma, pero operar un firmante en producción es
todavía tu responsabilidad. Estas prácticas se aplican a todos los backends; consulta
[Elegir un backend](/docs/tools/keychain/choosing-a-backend) para seleccionar uno.

## Separar firmantes activos y en frío

Usa un firmante operativo de bajo saldo («activo» o "hot") para transacciones
frecuentes y automatizadas, y un firmante separado de alto valor («en frío" o "cold") para
movimientos de tesorería. Respalda el firmante en frío con custodia MPC o un HSM
en la nube, y exige políticas de aprobación antes de que firme. Dado que la interfaz es
idéntica, cada rol puede usar un backend distinto sin modificar los puntos de llamada.

## Rotar claves de forma deliberada

En Solana, la clave de firma _es_ la dirección de la cuenta, por lo que rotar una clave
produce una nueva dirección. Planifica la rotación como una migración: provisiona una
nueva clave, reasigna las autoridades correspondientes (o transfiere fondos) a la nueva
dirección y, luego, retira la antigua. Usa claves distintas por entorno para que las claves
de devnet nunca se reutilicen en mainnet.

## Conceder acceso de mínimos privilegios

Limita las credenciales de cada backend al mínimo necesario para firmar. Para AWS KMS,
eso implica `kms:Sign` y `kms:DescribeKey` sobre la clave específica; prefiere roles IAM
a credenciales estáticas. Aplica el mismo principio a las políticas de Vault y a las claves
de API de carteras gestionadas.

## Planificar la disponibilidad

Los backends remotos dependen de un servicio de red. Llama a `isAvailable()` antes de
confiar en un firmante, aplica reintentos con retroceso exponencial ante fallos transitorios
y define una ruta de contingencia para interrupciones del servicio. Keychain impone HTTPS
para backends remotos y aplica un tiempo de espera de solicitud predeterminado.

## Proteger secretos y el transporte

- Todos los backends remotos se comunican mediante HTTPS; los endpoints que no usen HTTPS son rechazados.
- Suministra claves de API, tokens y credenciales desde un gestor de secretos o variables
  de entorno — nunca los codifiques en el código fuente ni los incluyas en el control de versiones.
- Keychain sanea las respuestas de error para evitar que los secretos se filtren en los registros; mantén
  tus propios registros libres de credenciales en bruto y material de claves.

## Monitorizar y auditar la firma

Realiza un seguimiento de la tasa de éxito de firma, la latencia y el recuento de fallos, y configura alertas ante picos —
consulta las métricas en
[Preparación para producción](/docs/tools/production-readiness#monitoring). Activa los registros de auditoría del
proveedor (KMS, Vault o custodio) y reconcílialos con las transacciones que envía tu aplicación.
