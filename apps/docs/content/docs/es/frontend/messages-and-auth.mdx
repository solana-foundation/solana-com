h1: Firma mensajes y autentica usuarios
description:
  Firma mensajes con una billetera de Solana para autenticar usuarios, registrar el consentimiento o autorizar acciones off-chain, mediante la firma de mensajes off-chain con una alternativa para las billeteras que aún no la admiten.
---

Firmar un mensaje demuestra que un usuario controla una billetera, sin transacción,
sin comisión y sin llamadas a la red. Las apps usan mensajes firmados para iniciar
la sesión de los usuarios, registrar que un usuario aceptó los términos, vincular una
billetera a una cuenta existente o autorizar una acción que ocurre off-chain, como
realizar un pedido.

Las billeteras de Solana firman mensajes de dos maneras:

- Los **mensajes off-chain** (`solana:signOffchainMessage`) envuelven tu texto en un
  formato estándar, definido por la [especificación](https://docs.anza.xyz/proposals/off-chain-message-signing) de firma de mensajes
  off-chain (OCMS).
  El formato nunca puede confundirse con una transacción, indica las cuentas que
  deben firmarlo y es el formato que firman las billeteras de hardware.
- Los **mensajes sin procesar** (`solana:signMessage`) firman exactamente los bytes que
  tu app les pasa, sin prefijo ni firmantes declarados. La mayoría de las billeteras
  de software los admiten, pero nada en los bytes los distingue como un mensaje en
  lugar de una transacción.

Usa mensajes off-chain cuando la billetera los admita y recurre a los mensajes sin
procesar cuando no. El resto de esta guía usa el inicio de sesión como ejemplo
práctico, pero los mismos pasos de firma y verificación se aplican a cualquier mensaje.

## Elige un formato de mensaje

|                           | Mensaje off-chain     | Mensaje sin procesar   | Transacción                   |
| ------------------------- | --------------------- | ------------- | ----------------------------- |
| Función de la billetera            | `signOffchainMessage` | `signMessage` | `signTransaction`             |
| Compatibilidad con billeteras de hardware   | Depende del dispositivo     | No            | Sí                           |
| Legible para el usuario      | Sí                   | Solo en software | Depende del dispositivo             |
| Declara los firmantes requeridos | Sí                   | No            | Sí                           |
| Llamadas RPC y comisiones        | Ninguna                  | Ninguna          | Blockhash, envío, comisión, confirmación |

### ¿Por qué no una transacción?

Antes, las billeteras de hardware no tenían forma de firmar un mensaje legible. Muchas
apps recurrían a pedir a estos usuarios que firmaran una transacción sin efecto
(no-op). Funciona, pero añade latencia, costo y riesgo:

- **Comisiones de red.** Una transacción paga una comisión, incluso cuando no hace nada.
- **Múltiples llamadas RPC.** Tu app obtiene un blockhash, simula, envía y después
  consulta periódicamente la confirmación.
- **Latencia adicional.** Cada una de esas llamadas es un viaje de ida y vuelta antes
  de que el usuario inicie sesión.
- **Nada legible.** El usuario aprueba los bytes de una transacción, no una declaración
  de lo que está aceptando.
- **Riesgo de comportamiento.** Pedir a los usuarios que firmen una transacción solo
  para iniciar sesión facilita engañarlos para que firmen una dañina.

Un mensaje off-chain evita todo eso. El único viaje de ida y vuelta es a tu propio
servidor.

## Qué firma la billetera

Un mensaje off-chain comienza con un dominio de firma fijo, `\xffsolana offchain`.
Ninguna transacción válida comienza con esos bytes, por lo que un mensaje firmado
nunca puede usarse como transacción. La versión 1 del formato enumera a continuación
los firmantes requeridos y transporta el mensaje como texto UTF-8, sin límite de longitud.

La billetera construye estos bytes, los firma y los devuelve junto con la
firma. La
[especificación](https://docs.anza.xyz/proposals/off-chain-message-signing)
cubre el formato completo, incluida la versión 0 heredada.

<DocsDiagram
  src="/assets/docs/frontend/offchain-message-layout.svg"
  alt="A version 1 off-chain message is a 16-byte signing domain, a version byte, a signer count, each signer's 32-byte public key in sorted order, and the UTF-8 content. The envelope prefixes it with a signature count and one 64-byte signature per signer."
/>

## Elige un método de inicio de sesión

No todas las billeteras admiten aún mensajes off-chain. Comprueba las funciones de la
cuenta conectada antes de solicitar una firma y recurre a una alternativa cuando falte
la función:

1. Si la cuenta admite `solana:signOffchainMessage` con la versión de mensaje 1,
   firma un mensaje off-chain.
2. De lo contrario, firma el mismo desafío con `solana:signMessage`. La mayoría de las
   billeteras de software lo admiten.
3. Ofrece a los usuarios de billeteras de hardware sin compatibilidad con mensajes una
   opción explícita, como un interruptor "Estoy usando una billetera de hardware", que
   firme en su lugar una transacción de inicio de sesión. No los dirijas por este
   camino de forma predeterminada.

## Firma un mensaje en el navegador

<Tabs items={["Wallet Standard (Kit)", "Wallet Adapter"]}>
  <Tab value="Wallet Standard (Kit)">
    Instala los paquetes de Wallet Standard junto con Kit:

    ```terminal
    $ npm install @solana/kit @solana/wallet-standard-features @wallet-standard/ui @wallet-standard/ui-features @wallet-standard/ui-registry
    ```

    Estos helpers reciben una `UiWalletAccount`, como la `account` que devuelve
    `useConnectedWallet` en la [guía de React](/docs/frontend/react-hooks):

    ```ts title="offchain-message.ts"
    import {
      SolanaSignOffchainMessage,
      type SolanaSignOffchainMessageFeature
    } from "@solana/wallet-standard-features";
    import type { UiWalletAccount } from "@wallet-standard/ui";
    import { getWalletAccountFeature } from "@wallet-standard/ui-features";
    import { getWalletAccountForUiWalletAccount } from "@wallet-standard/ui-registry";

    type OffchainMessageFeature =
      SolanaSignOffchainMessageFeature[typeof SolanaSignOffchainMessage];

    export function supportsOffchainMessages(account: UiWalletAccount) {
      if (!account.features.includes(SolanaSignOffchainMessage)) return false;
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      return feature.supportedMessageVersions.includes(1);
    }

    export async function signOffchainMessage(
      account: UiWalletAccount,
      message: string
    ) {
      const feature = getWalletAccountFeature(
        account,
        SolanaSignOffchainMessage
      ) as OffchainMessageFeature;
      const [output] = await feature.signOffchainMessage({
        messageVersion: 1,
        account: getWalletAccountForUiWalletAccount(account),
        message,
        requiredSigners: [account.publicKey]
      });
      return output;
    }
    ```

  </Tab>

  <Tab value="Wallet Adapter">
    `useWallet` de `@solana/wallet-adapter` expone `signOffchainMessage` solo
    cuando la cuenta conectada admite `solana:signOffchainMessage`. Firma un
    mensaje de versión 1 con la cuenta conectada como firmante requerido y
    se rechaza con `WalletNotReadyError` si la billetera no puede firmar la versión 1:

    ```terminal
    $ npm install @solana/web3.js@3 @solana/wallet-adapter
    ```

    ```tsx title="SignOffchainMessage.tsx"
    "use client";

    import { useWallet } from "@solana/wallet-adapter";

    export function SignOffchainMessage({ challenge }: { challenge: string }) {
      const { publicKey, signOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!publicKey || !signOffchainMessage) return;
        const { signature, signedOffchainMessage } =
          await signOffchainMessage(challenge);
        const valid = await publicKey.verifySignature(
          signature,
          signedOffchainMessage
        );
        // Server logic
      };

      return (
        <button onClick={onClick} disabled={!signOffchainMessage}>
          Sign in
        </button>
      );
    }
    ```

    `publicKey.verifySignature` comprueba la firma frente a los bytes firmados
    en el navegador. Tu servidor todavía necesita confirmar que esos bytes son el
    desafío que emitió. Cuando `signOffchainMessage` es `undefined`, recurre
    a `signMessage` del mismo hook.

  </Tab>
</Tabs>

`signOffchainMessage` devuelve `signedOffchainMessage`, los bytes completos que firmó
la billetera, y `signature`. Codifica ambos en Base64 y envíalos a tu servidor junto con
la dirección de la billetera.

Redacta el desafío para que se lea bien en una pantalla pequeña. Indica el nombre de tu
app y dominio, explica qué hace la firma e incluye un nonce de un solo uso y una hora
de emisión generados por tu servidor:

```text
swap.app wants you to sign in with your Solana account.

Signing in costs nothing and does not submit a transaction.

Nonce: 8f3a1c9e
Issued at: 2026-09-29T17:04:00Z
```

## Verifica la firma en tu servidor

La verificación es una comprobación local de la firma y no necesita conexión RPC.
Decodifica los bytes que firmó la billetera, confirma que coinciden con el desafío que
emitiste y después comprueba la firma:

```ts title="verify-sign-in.ts"
import {
  address,
  assertOffchainMessageV1Equal,
  getBase64Encoder,
  getOffchainMessageDecoder,
  verifyOffchainMessageEnvelope,
  type OffchainMessageBytes,
  type SignatureBytes
} from "@solana/kit";

export async function verifySignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signedOffchainMessage: string;
  signature: string;
}) {
  const signer = address(input.walletAddress);
  const base64 = getBase64Encoder();
  const content = base64.encode(
    input.signedOffchainMessage
  ) as OffchainMessageBytes;
  const signature = base64.encode(input.signature) as SignatureBytes;

  const received = getOffchainMessageDecoder().decode(content);
  if (received.version !== 1) {
    throw new Error(`Expected a v1 message, got v${received.version}`);
  }
  assertOffchainMessageV1Equal(received, {
    version: 1,
    requiredSignatories: [{ address: signer }],
    content: input.expectedMessage
  });

  await verifyOffchainMessageEnvelope({
    content,
    signatures: { [signer]: signature }
  });
}
```

`assertOffchainMessageV1Equal` lanza un error si el contenido o los firmantes difieren
de lo esperado. `verifyOffchainMessageEnvelope` lanza un error si la firma falta o no
es válida. Busca `expectedMessage` por nonce en tu servidor en lugar de confiar en la
copia que devuelve el cliente. Consume el nonce una vez que se verifique, para que la
misma firma no pueda iniciar sesión dos veces.

### Verifica un mensaje sin procesar

Una firma de `signMessage` cubre directamente los bytes del desafío, por lo que el cliente
solo necesita enviar la firma y la dirección de la billetera. Compruébala con el
desafío que emitiste:

```ts title="verify-raw-sign-in.ts"
import {
  address,
  getBase64Encoder,
  getPublicKeyFromAddress,
  getUtf8Encoder,
  signatureBytes,
  verifySignature
} from "@solana/kit";

export async function verifyRawSignIn(input: {
  walletAddress: string;
  expectedMessage: string;
  signature: string;
}) {
  const publicKey = await getPublicKeyFromAddress(address(input.walletAddress));
  const signature = signatureBytes(getBase64Encoder().encode(input.signature));
  const message = getUtf8Encoder().encode(input.expectedMessage);
  if (!(await verifySignature(publicKey, signature, message))) {
    throw new Error("Invalid signature");
  }
}
```

Se aplican las mismas reglas del nonce: busca `expectedMessage` por nonce y consúmelo
una vez que se verifique.

<Callout type="info">
  `@solana/kit` reexporta estos helpers desde `@solana/offchain-messages`. Usa
  el paquete independiente si tu servidor no depende de Kit.
</Callout>

## Sign In With Solana

[Sign In With Solana](https://github.com/phantom/sign-in-with-solana) (SIWS)
estandariza el propio desafío. Tu app pasa campos estructurados, como
`domain`, `statement`, `nonce` e `issuedAt`, a la función `solana:signIn` de la
billetera. La billetera los formatea en un mensaje estándar, se conecta si es necesario
y lo firma en un solo paso.

La versión `1.1.0` de `solana:signIn` añade la opción `useOffchainMessage`. Cuando
pasas `useOffchainMessage: { messageVersion: 1 }`, la billetera envuelve el texto de SIWS
en un mensaje off-chain de versión 1 con la cuenta firmante como único firmante
requerido. Las billeteras de hardware pueden mostrarlo y firmarlo, y la salida informa
`signedMessageFormat: { kind: "offchainMessage", messageVersion: 1 }`. Las billeteras
que anuncian la versión `1.0.0` no conocen la opción, así que comprueba primero la
versión de la función y omítela en caso contrario.

  <Tab value="Wallet Standard">
    `solana:signIn` es una función de la billetera, no de la cuenta, por lo que estos
    helpers reciben una `UiWallet`:

    ```ts title="sign-in.ts"
    import {
      SolanaSignIn,
      type SolanaSignInFeature,
      type SolanaSignInInput
    } from "@solana/wallet-standard-features";
    import type { UiWallet } from "@wallet-standard/ui";
    import { getWalletFeature } from "@wallet-standard/ui-features";

    type SignInFeature = SolanaSignInFeature[typeof SolanaSignIn];

    export function supportsOffchainSignIn(wallet: UiWallet) {
      if (!wallet.features.includes(SolanaSignIn)) return false;
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      return feature.version === "1.1.0";
    }

    export async function signIn(wallet: UiWallet, input: SolanaSignInInput) {
      const feature = getWalletFeature(wallet, SolanaSignIn) as SignInFeature;
      const [output] = await feature.signIn({
        ...input,
        ...(supportsOffchainSignIn(wallet) && {
          useOffchainMessage: { messageVersion: 1 }
        })
      });
      return output;
    }
    ```

  <Tab value="Wallet Adapter">
    `useWallet` expone `signIn` cuando la billetera seleccionada admite
    `solana:signIn`, y `supportsSignInWithOffchainMessage` cuando anuncia la
    versión `1.1.0`. Pasar `useOffchainMessage` a una billetera que no lo
    admite se rechaza con `WalletSignInError`:

    ```tsx title="SignIn.tsx"
    "use client";

    import {
      useWallet,
      verifySignIn,
      type SolanaSignInInput
    } from "@solana/wallet-adapter";

    export function SignIn({ input }: { input: SolanaSignInInput }) {
      const { signIn, supportsSignInWithOffchainMessage } = useWallet();

      const onClick = async () => {
        if (!signIn) return;
        const output = await signIn({
          ...input,
          ...(supportsSignInWithOffchainMessage && {
            useOffchainMessage: { messageVersion: 1 }
          })
        });
        const valid = await verifySignIn(input, output);
      };

      return (
        <button onClick={onClick} disabled={!signIn}>
          Sign in with Solana
        </button>
      );
    }
    ```

    `verifySignIn` comprueba que el mensaje firmado reproduce cada campo de la
    entrada y lleva una firma válida de la cuenta firmante, ya sea que la
    billetera haya firmado texto SIWS simple o un mensaje off-chain. Ejecuta la misma
    comprobación en tu servidor importándola desde `@solana/wallet-adapter/core`, que
    no tiene dependencia de React.

  </Tab>
</Tabs>

Construye la entrada en tu servidor, con un `nonce` de un solo uso y una hora
`issuedAt`, y conserva una copia indexada por el nonce. Consume el nonce una vez que
se verifique el inicio de sesión.

Sin Wallet Adapter, `verifySignIn` de `@solana/wallet-standard-util`
comprueba únicamente la salida SIWS simple. Cuando `signedMessageFormat` indica un mensaje
off-chain, `signedMessage` es un mensaje off-chain cuyo contenido es el texto SIWS.
Reconstruye el texto esperado a partir de la entrada almacenada y la dirección firmante
con `createSignInMessageText` de `@solana/wallet-standard-util`, y luego verifícalo
como cualquier otro mensaje off-chain, como se explica en
[Verifica la firma en tu servidor](#verify-the-signature-on-your-server). El
[README de `@solana/offchain-messages`](https://github.com/anza-xyz/kit/tree/main/packages/offchain-messages#verifying-a-signed-offchain-message)
cubre este flujo en Kit.

## Para billeteras

Las billeteras añaden compatibilidad implementando la función `solana:signOffchainMessage`
de Wallet Standard desde `@solana/wallet-standard-features`:

- Informa `version: "1.0.0"` y enumera las versiones de mensaje que puedes firmar en
  `supportedMessageVersions`. Hoy, eso es `[1]`.
- Crea el preámbulo de la versión 1 a partir de `requiredSigners`, que debes ordenar y comprobar
  para detectar duplicados. Rechaza la solicitud si la cuenta no es uno de los firmantes
  requeridos.
- Muestra el texto del mensaje completo al usuario antes de firmar, incluso en
  dispositivos de hardware.
- Devuelve los bytes exactos que firmaste como `signedOffchainMessage`, junto con la
  `signature` Ed25519.
- Para admitir Sign In With Solana fuera de la cadena, indica `version: "1.1.0"` para
  `solana:signIn`. Cuando la entrada incluya `useOffchainMessage`, firma el texto de SIWS
  como un mensaje fuera de la cadena de la versión 1, devuelve sus bytes como `signedMessage`
  y establece `signedMessageFormat`.
- Sigue admitiendo `solana:signMessage`. No ha cambiado, y las aplicaciones aún lo usan
  como alternativa.
