<Callout type="info" title="Resumen">
  Comisión total = comisión base (5.000 lamports/firma, 50% quemado) + comisión de priorización
  (CU_price * CU_limit / 1M lamports, 100% al validator). Se cobra tanto si la
  transacción tiene éxito como si falla.
</Callout>

## Algoritmo de cálculo de comisiones

La comisión total de una transacción es calculada por
[`calculate_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L53-L72):

```text title="Total fee formula"
total_fee = base_fee + prioritization_fee
```

Las entradas son el mensaje de la transacción, el valor actual de `lamports_per_signature`
(actualmente 5.000) y la comisión de priorización derivada de las instrucciones de presupuesto de cómputo. La comisión total se deduce del pagador de comisiones antes de que comience la ejecución.
Si la transacción falla, la comisión se cobra igualmente.

## Comisión base

La comisión base cubre el coste de la verificación de firmas Ed25519, además de cualquier
verificación de firmas de precompilados. Se cobra cada firma de la transacción,
incluidas las verificadas por los programas precompilados Ed25519, Secp256k1 y Secp256r1.

La función
[`calculate_signature_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L75-L92)
calcula:

```text title="Base fee formula"
signature_count = num_transaction_signatures
                + num_ed25519_signatures
                + num_secp256k1_signatures
                + num_secp256r1_signatures   (if feature enabled)

base_fee = signature_count * lamports_per_signature
```

- `num_transaction_signatures`: el número de firmas Ed25519 en la
  transacción (normalmente una por firmante).
- `num_ed25519_signatures`, `num_secp256k1_signatures`,
  `num_secp256r1_signatures`: firmas verificadas por los programas
  precompilados correspondientes.
- `lamports_per_signature`: actualmente
  [5.000 lamports](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-structure/src/lib.rs#L210).

### Distribución de comisiones

La comisión base y la comisión de priorización se distribuyen de forma diferente. La función
[`calculate_reward_and_burn_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L85-L98)
del entorno de ejecución calcula:

```text title="Fee distribution"
burn_amount     = transaction_fee * 50 / 100
validator_share = (transaction_fee - burn_amount) + priority_fee
```

- **Comisión base (transaction_fee)**: el 50% se
  [quema](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L93)
  (se retira de la oferta circulante) y el 50% va al validator que produce el bloque. El porcentaje quemado es
  [`DEFAULT_BURN_PERCENT = 50`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-calculator/src/lib.rs#L70).
- **Comisión de priorización**: el 100% va al validator (nada se quema), según
  [SIMD-0096](https://github.com/solana-foundation/solana-improvement-documents/blob/main/proposals/0096-reward-collected-priority-fee-in-entirety.md).

La recompensa total del validator por una transacción es:

```text
validator_reward = (base_fee / 2) + prioritization_fee
```

## Comisión de priorización

La comisión de priorización es una comisión opcional que aumenta la prioridad de programación
de una transacción. Una unidad de cómputo (CU) es una unidad de cálculo que el entorno de ejecución
mide durante la ejecución de la transacción. Cada operación (aritmética, acceso a memoria,
syscall) tiene un coste fijo en CUs. Puedes establecer la comisión de priorización incluyendo instrucciones de presupuesto de cómputo en tu transacción. (Consulta la
[guía Cómo usar comisiones de prioridad](/docs/core/fees) para más detalles.)

### Fórmula de la comisión de priorización

La función
[`get_prioritization_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L61-L69)
calcula:

```text title="Prioritization fee formula"
micro_lamport_fee = compute_unit_price * compute_unit_limit
prioritization_fee = ceil(micro_lamport_fee / 1,000,000)
```

| Variable             | Descripción                                                                                                                                                                       | Valor predeterminado                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `compute_unit_price` | Micro-lamports por CU, establecido mediante `SetComputeUnitPrice`                                                                                                                              | 0 micro-lamports                |
| `compute_unit_limit` | CUs máximos que puede consumir la transacción, establecido mediante `SetComputeUnitLimit`                                                                                                            | Suma de los valores predeterminados por instrucción |
| `1.000.000`          | Factor de conversión de micro-lamports a lamports ([`MICRO_LAMPORTS_PER_LAMPORT`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L17)) | --                              |

<Callout type="info" title="Las transacciones v1 establecen la comisión directamente">
  Esta fórmula de precio por límite se aplica a las transacciones legacy y v0. En el
  [formato v1](/docs/core/transactions/versioned-transactions#v1-format), la
  comisión de priorización es un total absoluto en lamports establecido directamente en la configuración del mensaje
  — sin precio por CU, sin multiplicación ni redondeo.
</Callout>

### Límite de unidades de cómputo

El límite de unidades de cómputo es el número máximo de CUs que puede consumir una transacción.
Si no se incluye ninguna instrucción
[`SetComputeUnitLimit`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L32),
el valor predeterminado se calcula a partir del número y tipo de instrucciones (200.000 CUs por instrucción no integrada, 3.000 por instrucción integrada). Consulta
[Compute Budget](/docs/core/fees/compute-budget) para más detalles sobre el cálculo predeterminado.

<Callout type="warn">
  La comisión de priorización se basa en el límite de CUs solicitado, no en el uso real de CUs.
  Establecer un límite mayor del necesario implica pagar por unidades de cómputo no utilizadas.
</Callout>

### Precio de la unidad de cómputo

El precio de la unidad de cómputo es una cantidad opcional de micro-lamports que se paga por cada
CU solicitado. El precio de CU determina directamente la comisión de priorización. Para establecer
el precio de CU, incluye una instrucción
[`SetComputeUnitPrice`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L35)
en tu transacción.

<Callout>
  El precio de CU predeterminado es 0, lo que significa que la comisión de priorización predeterminada también es 0.
</Callout>

Para estimaciones del precio de CU en tiempo real, consulta los proveedores de la API de comisiones de prioridad a continuación.

| Proveedor                                | API de comisión de prioridad                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| [Helius](https://www.helius.dev/)       | [Documentación](https://docs.helius.dev/solana-apis/priority-fee-api)             |
| [QuickNode](https://www.quicknode.com/) | [Documentación](https://marketplace.quicknode.com/add-on/solana-priority-fee)     |
| [Triton](https://triton.one/)           | [Documentación](https://docs.triton.one/chains/solana/improved-priority-fees-api) |

### Prioridad de programación de transacciones

El programador clasifica las transacciones mediante la función
[`calculate_priority_and_cost`](https://github.com/anza-xyz/agave/blob/v3.1.8/core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs#L526-L546):

```text title="Transaction priority formula"
Priority = reward * 1,000,000 / (cost + 1)
```

- **reward**: los ingresos del validator por comisiones = comisión de priorización + porción no quemada
  de la comisión base. Calculado por
  [`calculate_reward_for_transaction`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L64-L83).
- **cost**: el
  [coste estimado en CUs](https://github.com/anza-xyz/agave/blob/v3.1.8/cost-model/src/cost_model.rs#L37-L57)
  del programador (costes de firmas + costes de bloqueo de escritura + costes de instruction data + costes de ejecución del programa + coste del tamaño de datos de cuentas cargadas). Consulta
  [Compute Budget](/docs/core/fees/compute-budget#scheduler-cost-model) para más detalles.
- **1.000.000**: un multiplicador para preservar la precisión, ya que el coste suele superar
  la recompensa en lamports brutos.
- **+1**: evita la división por cero.

La prioridad determina el orden en que las transacciones se retiran del
búfer del programador para su ejecución.

```ts !! title="Web3.js v3"
import {
  LAMPORTS_PER_SOL,
  SystemProgram,
  Transaction,
  Keypair,
  Connection,
  ComputeBudgetProgram,
  sendAndConfirmTransaction
} from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");

const sender = await Keypair.generate();
const recipient = await Keypair.generate();

const airdropSignature = await connection.requestAirdrop(
  sender.publicKey,
  LAMPORTS_PER_SOL
);
await connection.confirmTransaction(airdropSignature, "confirmed");

// Create compute budget instructions
const limitInstruction = ComputeBudgetProgram.setComputeUnitLimit({
  units: 300_000
});
const priceInstruction = ComputeBudgetProgram.setComputeUnitPrice({
  microLamports: 1
});

const transferInstruction = SystemProgram.transfer({
  fromPubkey: sender.publicKey,
  toPubkey: recipient.publicKey,
  lamports: 0.01 * LAMPORTS_PER_SOL
});

// Add the compute budget and transfer instructions to a new transaction
const transaction = new Transaction()
  .add(limitInstruction)
  .add(priceInstruction)
  .add(transferInstruction);

const signature = await sendAndConfirmTransaction(connection, transaction, [
  sender
]);

console.log("Transaction Signature:", signature);
```

```rust !! title="Rust"
use solana_client::nonblocking::rpc_client::RpcClient;
use solana_commitment_config::CommitmentConfig;
use solana_compute_budget_interface::ComputeBudgetInstruction;
use solana_sdk::{
    native_token::LAMPORTS_PER_SOL,
    signature::{Keypair, Signer},
    transaction::Transaction,
};
use solana_system_interface::instruction::transfer;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = RpcClient::new_with_commitment(
        String::from("http://localhost:8899"),
        CommitmentConfig::confirmed(),
    );

    let sender = Keypair::new();
    let recipient = Keypair::new();

    let airdrop_signature = client
        .request_airdrop(&sender.pubkey(), LAMPORTS_PER_SOL)
        .await?;

    loop {
        let confirmed = client.confirm_transaction(&airdrop_signature).await?;
        if confirmed {
            break;
        }
    }

    // Create compute budget instructions
    let limit_instruction = ComputeBudgetInstruction::set_compute_unit_limit(300_000);
    let price_instruction = ComputeBudgetInstruction::set_compute_unit_price(1);

    let transfer_amount = LAMPORTS_PER_SOL / 100;
    let transfer_instruction = transfer(&sender.pubkey(), &recipient.pubkey(), transfer_amount);

    let recent_blockhash = client.get_latest_blockhash().await?;

    let mut transaction = Transaction::new_with_payer(
        &[limit_instruction, price_instruction, transfer_instruction],
        Some(&sender.pubkey()),
    );
    transaction.sign(&[&sender], recent_blockhash);

    let signature = client.send_and_confirm_transaction(&transaction).await?;
    println!("Transaction Signature: {}", signature);

    Ok(())
}
```
