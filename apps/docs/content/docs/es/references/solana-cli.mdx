La interfaz de línea de comandos `solana` configura la conexión a un clúster, lee el
estado de la red, envía SOL, gestiona nonces duraderos, despliega programas y opera
cuentas de stake y de voto.

Esta referencia corresponde a
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Ejecuta
`solana --version` para comprobar la versión instalada y usa `--help` para ver las
opciones exactas disponibles en esa versión.

<Callout type="warn">
  Los comandos que crean, transfieren, autorizan, retiran o despliegan envían
  transacciones. Confirma el clúster configurado y el firmante antes de ejecutarlos.
  Los tokens de Devnet y Testnet no tienen valor; los comandos de Mainnet usan SOL reales.
</Callout>

## Estructura de los comandos

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Obtén ayuda en cualquier nivel:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Opciones globales

Las opciones globales pueden colocarse antes del comando. La ayuda específica de cada comando repite
las opciones que se aplican a ese comando.

| Opción                          | Finalidad                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Selecciona una URL de RPC o `mainnet-beta`, `testnet`, `devnet` o `localhost`.      |
| `--ws <URL>`                    | Sustituye el endpoint de WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Selecciona un archivo de keypair, `ASK`, la entrada estándar (`-`) o una URL de firmante compatible.          |
| `-C, --config <FILEPATH>`       | Usa un archivo de configuración de la CLI diferente.                                        |
| `--commitment <LEVEL>`          | Lee con nivel de commitment `processed`, `confirmed` o `finalized`.                   |
| `--output <FORMAT>`             | Devuelve `json` o `json-compact` donde sea compatible.                               |
| `--skip-preflight`              | Envía sin simulación de RPC. Úsalo solo si entiendes los riesgos de un posible fallo. |
| `--use-tpu-client`              | Envía las transacciones a través del cliente TPU.                                      |
| `--no-address-labels`           | Muestra las direcciones sin etiquetas locales.                                          |
| `--skip-seed-phrase-validation` | Permite una frase de recuperación que no esté en la lista en inglés de BIP39.                       |
| `-v, --verbose`                 | Muestra una salida adicional del comando.                                                |
| `-V, --version`                 | Muestra la versión instalada de la CLI.                                               |

## Configurar la CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

La configuración contiene una URL de RPC, una URL de WebSocket, el firmante predeterminado y el
nivel de commitment. Una opción de línea de comandos sustituye el valor guardado en esa invocación.

## Flujos de trabajo habituales de cuentas y transacciones

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` acepta SOL de forma predeterminada. Usa `ALL` como importe para mover el saldo
disponible después de las comisiones. Para ver ejemplos con tokens, consulta la
[guía de inicio rápido de tokens](/docs/tokens/quickstart).

## Flujos de trabajo de programas

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Pasa `--program-id <KEYPAIR_OR_ADDRESS>` cuando un despliegue deba usar un ID de
programa conocido. `--final` hace inmutable un nuevo despliegue; lee su ayuda con atención
antes de usarlo, porque la autoridad de actualización no puede restaurarse.

## Flujos de trabajo de nonces duraderos

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Usa `authorize-nonce-account` para cambiar la autoridad del nonce y `nonce-account`
para inspeccionar el estado completo de la cuenta. Las transacciones que usan un nonce también aceptan
`--nonce` y `--nonce-authority` en los comandos compatibles.

## Flujos de trabajo de stake

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

La desactivación se completa en el límite de un epoch y puede tardar más de un epoch.
Usa `stakes`, `validators`, `stake-history` y `stake-minimum-delegation` para
inspeccionar el estado del clúster y de las delegaciones antes de enviar cambios.

## Utilidades de direcciones

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

Los seeds de PDA usan `PREFIX:VALUE`. Los prefijos compatibles incluyen `string`, `pubkey`,
`hex`, `u8` y codificaciones de enteros con signo o sin signo de ancho fijo, como
`u64le`.

## Mensajes fuera de la cadena y autocompletado del shell

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Salida para scripts

Usa `--output json` o `--output json-compact` donde sea compatible en lugar de
analizar la salida legible para personas:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

No todos los comandos admiten salida estructurada. Consulta la ayuda del comando antes de
depender de ella en automatizaciones, y trata un estado de salida distinto de cero como un fallo.
