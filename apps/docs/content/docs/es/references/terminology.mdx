Los siguientes términos se utilizan en toda la documentación y el ecosistema de desarrollo de Solana.

## cuenta

Un registro en el libro contable de Solana que almacena datos o es un programa ejecutable.

Al igual que una cuenta en un banco tradicional, una cuenta de Solana puede contener fondos llamados
[lamports](#lamport). Cada cuenta en un [clúster](#cluster) tiene una
[dirección](#address) única.

## app

Una aplicación de front-end que interactúa con un clúster de Solana.

## dirección

La ubicación en Solana que puede usarse para encontrar una cuenta. Cada dirección es
única en el [clúster](#cluster) de Solana.

Las direcciones en Solana pueden ser una [clave pública](#public-key-pubkey) Ed25519 o
una [dirección derivada de programa](#program-derived-address-pda).

## tabla de búsqueda de direcciones (ALT)

Una estructura de datos que almacena una lista de direcciones de cuenta, lo que permite que las
[transacciones versionadas](#versioned-transaction) referencien cuentas utilizando índices compactos de 1 byte en lugar de claves públicas completas de 32 bytes. Las tablas de búsqueda de direcciones permiten que una sola transacción referencie más cuentas de las que el formato de transacción original permite. Solo las transacciones de versión 0 (`v0`) admiten tablas de búsqueda de direcciones; la versión 1 (`v1`) las elimina en favor de un tamaño de transacción mayor que incluye las mismas direcciones de forma directa.

## Anchor

Un framework para construir [programas onchain](#onchain-program) de Solana en Rust.
Anchor proporciona macros que reducen el código repetitivo, un sistema estandarizado de validación de cuentas y genera un [IDL](#idl) que describe la interfaz del programa. Es el framework más utilizado para el desarrollo de programas en Solana.

## associated token account (ATA)

Un [token account](#token-account) cuya dirección se deriva de forma determinista
a partir de una dirección de billetera y un [token mint](#token-mint). El programa de associated token account garantiza que cada billetera tenga un token account canónico por tipo de token.

## autoridad

La dirección de un usuario que tiene algún tipo de permiso sobre una cuenta.

Por ejemplo:

- La capacidad de acuñar nuevos tokens se otorga a la cuenta que es la 'autoridad de acuñación' del token mint.
- La capacidad de actualizar un programa se otorga a la cuenta que es la 'autoridad de actualización' del programa.

## creador de mercado automatizado (AMM)

Un modelo de intercambio onchain en el que los usuarios operan contra un grupo de reservas de tokens gobernado por una fórmula de precios, en lugar de contra una orden en reposo de una contraparte. Los precios se mueven en función de las reservas, por lo que las operaciones incurren en un [deslizamiento](#slippage) proporcional al tamaño.

## estado del banco

El resultado de interpretar todos los programas del libro contable en una
[altura de tick](#tick-height) determinada. Incluye al menos el conjunto de todas las
[cuentas](#account) que tienen [tokens nativos](#native-token) distintos de cero.

## bloque

Un conjunto contiguo de [entradas](#entry) en el libro contable cubierto por un
[voto](#ledger-vote). Un [líder](#leader) produce como máximo un bloque por
[slot](#slot).

## hash de bloque

Un valor único ([hash](#hash)) que identifica un registro (bloque). Solana calcula
un hash de bloque a partir del último [ID de entrada](#entry-id) del bloque.

## altura de bloque

El número de [bloques](#block) por debajo del bloque actual. El primer bloque tras
el [bloque génesis](#genesis-block) tiene altura uno.

## validador de arranque

El [validador](#validator) que produce el [bloque](#block) génesis (primero) de
una cadena de bloques.

## BPF loader

El programa de Solana que es propietario y carga [programas](/docs/core/programs)
[onchain](#onchain-program) de [BPF](/docs/core/programs), permitiendo que el programa interactúe con el entorno de ejecución.

## bump

Un byte único (0–255) que se añade a las [semillas](#seed) al derivar una
[dirección derivada de programa](#program-derived-address-pda) para garantizar que la dirección resultante quede fuera de la curva ed25519 y sea, por tanto, un PDA válido. El bump canónico es el valor más alto que produce un PDA válido y normalmente se guarda en los datos de la cuenta para evitar recalcularlo.

## libro de órdenes de límite central (CLOB)

Un modelo de intercambio que mantiene una lista ordenada de ofertas y solicitudes en reposo; una operación ocurre cuando una orden entrante cruza una orden del lado opuesto. Contrasta con el [creador de mercado automatizado](#automated-market-maker-amm).

## cliente

Un programa informático que accede a la red de servidores del [clúster](#cluster) de Solana.

## confirmación

Una medida de la confirmación de la red para el [bloque](#block).

## formato de array compacto

Un array compacto es un array serializado en el siguiente formato:

- La longitud del array (codificada como
  [compact-u16](https://github.com/anza-xyz/agave/blob/v2.1.13/short-vec/src/lib.rs))
- Los elementos del array enumerados uno tras otro

![Formato de array compacto](/assets/docs/core/transactions/compact_array_format.png)

El formato de array compacto se usa para codificar tanto el array de
[direcciones de cuenta](/docs/core/transactions/transaction-structure#account-addresses)
como el array de
[instrucciones](/docs/core/transactions/transaction-structure#instructions)
en los mensajes de transacción.

## clúster

Un conjunto de [validadores](#validator) que mantienen un único [libro contable](#ledger).

## presupuesto de cómputo

El número máximo de [unidades de cómputo](#compute-units) consumidas por transacción.

## unidades de cómputo

La unidad de medida más pequeña para el consumo de recursos computacionales de la blockchain. Las unidades de cómputo se utilizan para medir los recursos computacionales empleados en el procesamiento de una transacción.

## tiempo de confirmación

La duración en reloj de pared entre que un [líder](#leader) crea una
[entrada de tick](#tick) y crea un [bloque confirmado](#confirmed-block).

## bloque confirmado

Un [bloque](#block) que ha recibido una [supermayoría](#supermajority) de
[votos del libro contable](#ledger-vote).

## plano de control

Una red de gossip que conecta todos los [nodos](#node) de un [clúster](#cluster).

## período de enfriamiento

Cierto número de [epochs](#epoch) tras la desactivación del [stake](#stake), durante el cual este se va haciendo progresivamente disponible para su retiro. Durante este período, el stake se considera "en desactivación". Más información en:
[calentamiento y enfriamiento](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)

## unidades de costo

También denominado `costo de transacción`, es una estimación integral de todos los recursos necesarios para procesar una transacción, medida en [unidades de cómputo](#compute-units). Más información
[aquí](https://www.anza.xyz/blog/why-solana-transaction-costs-and-compute-units-matter-for-developers).

## crédito

Ver [crédito de voto](#vote-credit).

## cross-program invocation (CPI)

Una llamada de un [programa onchain](#onchain-program) a otro. Para más
información, consulta [llamadas entre programas](/docs/core/cpi).

## plano de datos

Una red multicast utilizada para validar eficientemente [entradas](#entry) y alcanzar consenso.

## drone

Un servicio offchain que actúa como custodio de la clave privada de un usuario. Normalmente sirve para validar y firmar transacciones.

## entrada

Una entrada en el [libro contable](#ledger), ya sea un [tick](#tick) o una
[entrada de transacción](#transactions-entry).

## ID de entrada

Un [hash](#hash) resistente a preimagen sobre el contenido final de una entrada, que
actúa como identificador único global de la [entrada](#entry). El hash sirve como evidencia de:

- Que la entrada fue generada tras una duración de tiempo
- Que las [transacciones](#transaction) especificadas son las incluidas en la entrada
- La posición de la entrada con respecto a otras entradas en el [libro contable](#ledger)

Ver [prueba de historia](#proof-of-history-poh).

## epoch

El tiempo, es decir, el número de [slots](#slot), durante el cual es válido un
[calendario de líderes](#leader-schedule).

## depósito en garantía

Un patrón en el que un [programa onchain](#onchain-program) mantiene tokens en una
[bóveda](#vault) en nombre de dos o más partes hasta que se cumplan las condiciones definidas por el programa, momento en que los libera. Se usa para eliminar la necesidad de que las partes confíen directamente entre sí.

## cuenta de comisiones

La cuenta de comisiones en la transacción es la cuenta que paga el costo de incluir la transacción en el libro contable. Es la primera cuenta de la transacción. Esta cuenta debe declararse como de lectura-escritura (modificable) en la transacción, ya que el pago de la transacción reduce el saldo de la cuenta.

## finalidad

Cuando los nodos que representan 2/3 del [stake](#stake) tienen una
[raíz](#root) común.

## bifurcación

Un [libro contable](#ledger) derivado de entradas comunes que luego divergen.

## bloque génesis

El primer [bloque](#block) de la cadena.

## configuración génesis

El archivo de configuración que prepara el [libro contable](#ledger) para el
[bloque génesis](#genesis-block).

## hash

Una huella digital de una secuencia de bytes.

## inflación

Un aumento en el suministro de tokens a lo largo del tiempo utilizado para financiar recompensas por validación y para financiar el desarrollo continuo de Solana.

## instrucción interna

Ver [cross-program invocation](#cross-program-invocation-cpi).

## instrucción

Una llamada para invocar un [manejador de instrucción](#instruction-handler) específico en un
[programa](#program). Una instrucción también especifica qué cuentas desea leer o modificar, así como datos adicionales que sirven como entrada auxiliar al
[manejador de instrucción](#instruction-handler). Un [cliente](#client) debe incluir al
menos una instrucción en una [transacción](#transaction), y todas las instrucciones deben completarse para que la transacción se considere exitosa.

## manejador de instrucción

Los manejadores de instrucción son funciones de [programa](#program) que procesan
[instrucciones](#instruction) de [transacciones](#transaction). Un manejador de instrucción puede contener una o más
[cross-program invocations](#cross-program-invocation-cpi).

## IDL

Lenguaje de Definición de Interfaz. Un archivo JSON generado por [Anchor](#anchor) que describe los [manejadores de instrucción](#instruction-handler), cuentas y tipos de un programa. El IDL permite que las bibliotecas cliente generen automáticamente interfaces tipadas para interactuar con un [programa onchain](#onchain-program).

## keypair

Una [clave pública](#public-key-pubkey) y la [clave privada](#private-key) correspondiente
para acceder a una cuenta.

## lamport

Un [token nativo](#native-token) fraccionario con un valor de 0.000000001
[sol](#sol).

> Dentro del presupuesto de cómputo, una cantidad de
> _[micro-lamports](https://github.com/solana-labs/solana/blob/ced8f6a512c61e0dd5308095ae8457add4a39e94/program-runtime/src/prioritization_fee.rs#L1-L2)_
> se utiliza en el cálculo de las [tarifas de priorización](#prioritization-fee).

## líder

El rol de un [validador](#validator) cuando está añadiendo [entradas](#entry) al
[libro contable](#ledger).

## calendario de líderes

Una secuencia de [claves públicas](#validator) de [validadores](#public-key-pubkey) mapeadas
a [slots](#slot). El clúster utiliza el calendario de líderes para determinar qué validador es el [líder](#leader) en cada momento.

## libro contable

Una lista de [entradas](#entry) que contienen [transacciones](#transaction) firmadas por
[clientes](#client). Conceptualmente, esto puede rastrearse hasta el
[bloque génesis](#genesis-block), pero el libro contable de un [validador](#validator) real puede contener solo [bloques](#block) más recientes para reducir el almacenamiento, ya que los más antiguos no son necesarios para la validación de bloques futuros por diseño.

## voto del libro contable

Un [hash](#hash) del [estado del validador](#bank-state) en una
[altura de tick](#tick-height) determinada. Comprende la afirmación de un [validador](#validator) de que un [bloque](#block) que ha recibido ha sido verificado, así como un compromiso de no votar por un [bloque](#block) en conflicto \(es decir, una [bifurcación](#fork)\) durante un tiempo específico, el período de [bloqueo](#lockout).

## cliente ligero

Un tipo de [cliente](#client) que puede verificar que apunta a un
[clúster](#cluster) válido. Realiza más verificación del libro mayor que un
[cliente ligero](#thin-client) y menos que un [validator](#validator).

## liquidez

La profundidad de órdenes o reservas agrupadas disponibles para operar a un precio cercano al
actual. Una mayor liquidez reduce el [deslizamiento](#slippage). En un
[CLOB](#central-limit-order-book-clob), la liquidez es suministrada por
[órdenes maker](#maker); en un [AMM](#automated-market-maker-amm), es suministrada
por proveedores de liquidez que depositan pares de tokens en el pool.

## cargador

Un [programa](#program) con la capacidad de interpretar la codificación binaria de otros
[programas onchain](#onchain-program).

## período de bloqueo

La duración de tiempo durante la cual un [validator](#validator) no puede
[votar](#ledger-vote) en otro [fork](#fork).

## maker

Un operador cuya orden añade [liquidez](#liquidity) a un
[CLOB](#central-limit-order-book-clob) al quedar en espera en el libro en lugar de
cruzar inmediatamente el lado opuesto. Dicha orden se denomina orden maker.
Los makers generalmente no pagan comisión o reciben un reembolso por parte del mercado.

## creador de mercado

Una entidad que suministra [liquidez](#liquidity) publicando continuamente tanto
órdenes de compra como de venta. En Solana, los creadores de mercado son ya sea programas (como
[AMMs](#automated-market-maker-amm)) o firmas externas que ejecutan bots para publicar
[órdenes maker](#maker) en [CLOBs](#central-limit-order-book-clob).

## mensaje

El contenido estructurado de una [transacción](#transaction). Generalmente contiene una
cabecera, un array de direcciones de cuentas, un [blockhash](#blockhash) reciente y un array
de [instrucciones](#instruction).

Obtén más información sobre el
[formato de mensajes dentro de las transacciones](/docs/core/transactions/transaction-structure#header)
aquí.

## micro-lamport

1.000.000 de micro-lamports = 1 [lamport](#lamport)

## coeficiente de Nakamoto

Una medida de descentralización, el Coeficiente de Nakamoto es el menor número
de entidades independientes que pueden actuar colectivamente para interrumpir una blockchain. El
término fue acuñado por Balaji S. Srinivasan y Leland Lee en
[Quantifying Decentralization](https://news.earn.com/quantifying-decentralization-e39db233c28e).

## token nativo

El [token](#token) utilizado para registrar el trabajo realizado por los [nodos](#node) en un clúster.

## nodo

Un equipo que participa en un [clúster](#cluster).

## conteo de nodos

El número de [validators](#validator) que participan en un [clúster](#cluster).

## offchain

Describe datos, procesos o servicios que existen o se ejecutan fuera de la blockchain de
Solana, como clientes RPC, indexadores, frontends y creadores de libros de órdenes offchain.
Complemento de [onchain](#onchain). "Offchain" (sin guion) es la
orthografía preferida.

## onchain

Describe datos o programas que existen o se ejecutan en una blockchain. "Onchain" (sin
guion) es la ortografía preferida.

## programa onchain

El código ejecutable en la blockchain de Solana que interpreta las
[instrucciones](#instruction) enviadas dentro de cada [transacción](#transaction) para
leer y modificar las cuentas sobre las que tiene control. Estos programas suelen
denominarse "[_contratos inteligentes_](/docs/core/programs)" en otras blockchains.

## oráculo

Un [programa onchain](#onchain-program) que publica datos provenientes de fuera de la
cadena —más frecuentemente precios de activos del mundo real— para que otros programas los lean.

## propietario

Puede referirse al [programa propietario](#owning-program) o a la
[cartera propietaria](#owning-wallet). Por ejemplo,
[getTokenAccountsByOwner](https://solana.com/docs/rpc/http/gettokenaccountsbyowner)
obtiene token accounts de una cartera específica; sin embargo, el programa propietario de
esas token accounts es el [token program](#token-program).

Para evitar confusiones, es preferible usar
[programa propietario](#owning-program) o [cartera propietaria](#owning-wallet) en lugar del
término genérico 'propietario'.

## programa propietario

La [dirección](#address) del [programa](#onchain-program) que es propietario de la
cuenta. Solo el programa propietario puede modificar la cuenta.

Véase también [autoridad](#authority).

## cartera propietaria

La cartera asociada a una cuenta. Por ejemplo, el token program se
utiliza para almacenar token accounts asociadas a una cartera y mint específicas, usando
una dirección formada a partir de esa [cartera](#wallet) y ese [mint](#token-mint).

## PoH

Véase [Proof of History](#proof-of-history-poh).

## punto

Un [crédito](#credit) ponderado en un sistema de recompensas. En el
[validator](#validator) [régimen de recompensas](https://docs.anza.xyz/consensus/stake-delegation-and-rewards),
el número de puntos correspondientes a un [stake](#stake) durante el canje es el producto
de los [créditos de voto](#vote-credit) obtenidos y el número de
[lamports](#lamport) en stake.

## clave privada

La clave privada de un [keypair](#keypair).

## programa

Véase [programa onchain](#onchain-program).

## dirección derivada de programa (PDA)

Una cuenta cuya dirección se crea a partir de un
[programa onchain](#onchain-program) y uno o más [seeds](#seed) creados por
el autor del programa. Las direcciones PDA no son claves públicas, y las PDAs no
cuentan con claves privadas.

La autoridad de firma de una PDA es el [programa onchain](#onchain-program) que
es su [programa propietario](#owning-program).

## id de programa

La clave pública de la [cuenta](#account) que contiene un
[programa](#onchain-program).

## proof of history (PoH)

Una cadena de pruebas, cada una de las cuales demuestra que ciertos datos existían antes de que la prueba
fuera creada y que transcurrió una duración exacta de tiempo desde la prueba anterior.
Al igual que un [VDF](#verifiable-delay-function-vdf), un Proof of History puede
verificarse en menos tiempo del que tardó en producirse.

## tarifa de priorización

Una tarifa adicional que el usuario puede especificar en la
[instrucción](#instruction) del presupuesto de cómputo para priorizar sus [transacciones](#transaction).

La tarifa de priorización se calcula multiplicando las unidades de cómputo máximas solicitadas
por el precio por unidad de cómputo (especificado en incrementos de 0,000001
[lamports](#lamport) por unidad de cómputo) redondeado hacia arriba al
[lamport](#lamport) más cercano.

Las transacciones deben solicitar la cantidad mínima de unidades de cómputo necesarias para
su ejecución a fin de minimizar las tarifas.

## clave pública (pubkey)

La clave pública de un [keypair](#keypair). Una clave pública es uno de los distintos
tipos de [dirección](#address) que una cuenta puede usar en Solana.

## rent

Tarifa pagada por [cuentas](#account) y [programas](#program) para almacenar datos en la
blockchain. Cuando las cuentas no tienen saldo suficiente para pagar el rent, pueden ser
eliminadas por el recolector de basura.

Véase también [exención de rent](#rent-exempt) a continuación. Más información sobre el rent aquí:
[¿Qué es el rent?](/docs/core/accounts/account-structure).

## exención de rent

Las cuentas que mantienen un saldo mínimo de lamports proporcional a la
cantidad de datos almacenados en la cuenta. Todas las cuentas recién creadas se almacenan
onchain de forma permanente hasta que la cuenta se cierra. No es posible crear una
cuenta que caiga por debajo del umbral de exención de rent.

## raíz

Un [bloque](#block) o [slot](#slot) que ha alcanzado el máximo [período de bloqueo](#lockout)
en un [validator](#validator). La raíz es el bloque más alto que es ancestro
de todos los forks activos en un validator. Todos los bloques ancestros de una raíz son también
transitivamente una raíz. Los bloques que no son ancestros ni descendientes de la
raíz quedan excluidos de la consideración para el consenso y pueden descartarse.

## runtime

El componente de un [validator](#validator) responsable de la ejecución de
[programas](#program).

## Sealevel

El entorno de ejecución en paralelo de Solana para [programas onchain](#onchain-program).

## seed

Un valor de byte o array de valores de byte utilizado como entrada al derivar una
[dirección derivada de programa](#program-derived-address-pda). Un programa puede usar cualquier
combinación de cadenas estáticas, claves públicas u otros datos como seeds. Los seeds se
combinen con el ID del programa y un [bump](#bump) para producir una dirección PDA única.

## shred

Una fracción de un [bloque](#block); la unidad más pequeña enviada entre
[validators](#validator).

## firma

Una firma ed25519 de 64 bytes compuesta por R (32 bytes) y S (32 bytes). Con el
requisito de que R sea un punto de Edwards comprimido que no sea de orden pequeño y S sea un
escalar en el rango `0 <= S < L`. Este requisito garantiza que no haya maleabilidad de la firma.
Cada transacción debe tener al menos una firma para la
[cuenta de tarifa](#fee-account). Por lo tanto, la primera firma en una transacción puede
tratarse como el [id de transacción](#transaction-id).

## firmante

Una [cuenta](#account) que ha autorizado una [instrucción](#instruction) o
[transacción](#transaction). Para un [keypair](#keypair) normal, esto implica una
[firma](#signature) criptográfica sobre la transacción. Para una
[dirección derivada de programa](#program-derived-address-pda), la autorización es
otorgada por el [programa propietario](#owning-program) cuando realiza una
[invocación entre programas](#cross-program-invocation-cpi), ya que una PDA no tiene
clave privada.

## tasa de omisión

El porcentaje de [slots omitidos](#skipped-slot) sobre el total de slots de liderazgo
en el epoch actual. Esta métrica puede ser engañosa, ya que presenta alta varianza
tras el límite del epoch cuando el tamaño de la muestra es pequeño, así como para
validators con un número reducido de slots de liderazgo; sin embargo, también puede ser útil para
identificar configuraciones incorrectas de nodos en ciertos momentos.

## slot omitido

Un [slot](#slot) pasado que no produjo un [bloque](#block), porque el líder
estaba fuera de línea o el [fork](#fork) que contenía el slot fue abandonado en favor de una
mejor alternativa por consenso del clúster. Un slot omitido no aparecerá como ancestro
de bloques en slots posteriores, ni incrementará la [altura del bloque](#block-height),
ni expirará el `recent_blockhash` más antiguo.

Si un slot ha sido omitido solo puede determinarse cuando se vuelve más antiguo
que el último slot con [raíz](#root) (y por lo tanto no omitido).

## deslizamiento

La diferencia entre el precio que esperaba un operador y el precio al que se
ejecutó realmente su operación. En los [AMMs](#automated-market-maker-amm), surge del
movimiento de la curva de precios a medida que cambian las reservas; en los
[CLOBs](#central-limit-order-book-clob), surge de una sola orden que consume
varias órdenes en espera a precios sucesivamente peores.

## slot

El período de tiempo durante el cual cada [líder](#leader) procesa transacciones y
produce un [bloque](#block).

En conjunto, los slots crean un reloj lógico. Los slots están ordenados secuencialmente y
no se superponen, comprendiendo un tiempo real aproximadamente igual según
[PoH](#proof-of-history-poh).

## contrato inteligente

Véase [programa onchain](#onchain-program).

## SOL

El [token nativo](#native-token) de un [clúster](#cluster) de Solana.

## Solana Program Library (SPL)

Una [biblioteca de programas](https://www.solana-program.com/docs/) en Solana, como
spl-token, que facilita tareas como la creación y el uso de tokens.

## stake

Tokens confiscados al [clúster](#cluster) si se puede probar un comportamiento
malicioso de un [validator](#validator).

## calidad de servicio ponderada por stake (SWQoS)

SWQoS permite
[un tratamiento preferencial para las transacciones provenientes de validators con stake](/docs/defi/stake-weighted-qos).

## supermayoría

2/3 de un [clúster](#cluster).

## system program

Un programa nativo de Solana (ID de programa `11111111111111111111111111111111`)
responsable de crear nuevas [cuentas](#account), asignar datos de cuenta,
atribuir cuentas a programas y transferir [SOL](#sol) entre cuentas.
Todas las cuentas nuevas en Solana son propiedad del System Program hasta que se reasignan.

## sysvar

Una [cuenta](#account) del sistema. Las [Sysvars](https://docs.anza.xyz/runtime/sysvars)
proporcionan información sobre el estado del clúster, como la altura de tick actual, los valores de
[puntos](#point) de recompensas, etc. Los programas pueden acceder a las Sysvars a través de una cuenta Sysvar
(pubkey) o consultando mediante una syscall.

## taker

Un operador cuya orden elimina [liquidez](#liquidity) de un
[CLOB](#central-limit-order-book-clob) cruzando el lado opuesto del libro
y emparejándose con una o más órdenes en reposo. Dicha orden se denomina orden taker,
y el taker generalmente paga la comisión de negociación de la plataforma.

## cliente ligero

Un tipo de [cliente](#client) que confía en que se está comunicando con un
[clúster](#cluster) válido.

## tick

Una [entrada](#entry) del libro de contabilidad que estima la duración en tiempo real.

## altura de tick

El N-ésimo [tick](#tick) en el [libro de contabilidad](#ledger).

## token

Un activo transferible digitalmente.

## token account

Una [cuenta](#account) que almacena el saldo de un [token](#token) específico. Las
token accounts son propiedad del [Token Program](#token-program) o del
[Token Extensions Program](#token-extensions-program) y almacenan el saldo del token,
el [token mint](#token-mint) asociado y la dirección de la billetera propietaria.

## Token Extensions Program

El [Token Extensions Program](https://www.solana-program.com/docs/token-2022)
tiene el ID de programa `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` e incluye
las mismas funcionalidades que el [Token Program](#token-program), pero incorpora
extensiones como Saldos Confidenciales, lógica de transferencia personalizada, metadatos
extendidos y mucho más.

## token mint

Una cuenta que puede producir (o "acuñar") tokens. Los distintos tokens se
diferencian por las direcciones únicas de su token mint.

## Token Program

El [Token Program](https://www.solana-program.com/docs/token) tiene el ID de programa
`TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` y proporciona las capacidades
básicas de transferir, congelar y acuñar tokens.

## tps

[Transacciones](#transaction) por segundo.

## tpu

[Unidad de procesamiento de transacciones](https://docs.anza.xyz/validator/tpu).

## transacción

Una o más [instrucciones](#instruction) firmadas por un [cliente](#client) mediante uno
o más [keypairs](#keypair) y ejecutadas de forma atómica con solo dos resultados posibles:
éxito o fracaso.

## id de transacción

La primera [firma](#signature) en una [transacción](#transaction), que puede usarse
para identificar de forma única la transacción en todo el [libro de contabilidad](#ledger).

## confirmaciones de transacción

El número de [bloques confirmados](#confirmed-block) desde que la transacción fue
aceptada en el [libro de contabilidad](#ledger). Una transacción queda finalizada cuando su bloque
se convierte en una [raíz](#root).

## entrada de transacciones

Un conjunto de [transacciones](#transaction) que pueden ejecutarse en paralelo.

## tvu

[Unidad de validación de transacciones](https://docs.anza.xyz/validator/tvu).

## validator

Un participante completo en un [clúster](#cluster) de red Solana que produce nuevos
[bloques](#block). Un validator valida las transacciones añadidas al
[libro de contabilidad](#ledger).

## vault

Una [token account](#token-account) propiedad de un
[programa onchain](#onchain-program) que custodia activos agrupados en nombre de los usuarios
— por ejemplo, las reservas base y de cotización de un
[AMM](#automated-market-maker-amm), los tokens bloqueados en un [escrow](#escrow),
o los saldos en reposo y las comisiones acumuladas de un
[CLOB](#central-limit-order-book-clob). Solo el programa propietario puede mover tokens
fuera del vault, normalmente hacia la [token account](#token-account) propia del usuario
una vez que se cumple una condición de intercambio o liberación.

## VDF

Ver [función de retraso verificable](#verifiable-delay-function-vdf).

## función de retraso verificable (VDF)

Una función que tarda una cantidad fija de tiempo en ejecutarse y produce una prueba
de que se ejecutó, la cual puede verificarse en menos tiempo del que tardó en generarse.

## transacción versionada

Un formato de transacción que admite funcionalidades adicionales más allá del formato de
[transacción](#transaction) original. La versión 0 (`v0`) es el primer formato versionado
y añade soporte para [tablas de búsqueda de direcciones](#address-lookup-table-alt),
permitiendo que las transacciones referencien más cuentas de las que permite el formato original.
La versión 1 (`v1`), activa en todos los clústeres, aumenta el tamaño máximo de transacción
a 4.096 bytes, incorpora límites de recursos en una sección de configuración del mensaje
en lugar de instrucciones ComputeBudget, y elimina el soporte para tablas de búsqueda de direcciones.
Ver [transacciones versionadas](/docs/core/transactions/versioned-transactions).

## voto

Ver [voto del libro de contabilidad](#ledger-vote).

## crédito de voto

Un registro de recompensas para los [validators](#validator). Se otorga un crédito de voto a un
validator en su cuenta de voto cuando el validator alcanza una [raíz](#root).

## billetera

Una colección de [keypairs](#keypair) que permite a los usuarios gestionar sus fondos.

## período de activación

Un número determinado de [epochs](#epoch) tras la delegación del [stake](#stake) durante
el cual este se vuelve progresivamente efectivo. Durante este período, el stake se considera
en estado de "activación". Más información sobre:
[activación y desactivación](https://docs.anza.xyz/consensus/stake-delegation-and-rewards#stake-warmup-cooldown-withdrawal)
