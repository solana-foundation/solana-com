La interfaz de línea de comandos `spl-token` crea y administra mints, token
accounts, autoridades, transferencias y extensiones de Token-2022.

Esta referencia sigue
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
la versión incluida con Agave v4.2.1. Ejecuta `spl-token --version` y usa
`<command> --help` para consultar las opciones exactas disponibles en tu versión instalada.

<Callout type="warn">
  La creación de mints, las transferencias, los cambios de autoridad, las quemas, los congelamientos y el cierre de
  cuentas envían transacciones. Confirma el clúster, el Token Program, el firmante y las
  direcciones antes de ejecutar un comando. Los cambios en mainnet usan activos reales.
</Callout>

## Instalación y obtención de ayuda

El paquete de versión de Agave CLI incluye `spl-token`. Si no está instalado, usa
el crate de Rust publicado:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Consulta la ayuda a nivel raíz o de comando:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Opciones globales

Coloca las opciones globales antes del comando.

| Opción                                       | Finalidad                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Selecciona una URL de RPC o `mainnet-beta`, `testnet`, `devnet` o `localhost`. |
| `-C, --config <PATH>`                        | Usa un archivo de configuración de Solana CLI diferente.                            |
| `--fee-payer <KEYPAIR>`                      | Selecciona la cuenta que paga las comisiones de transacción.                            |
| `-p, --program-id <ADDRESS>`                 | Usa un ID de Token Program explícito.                                         |
| `--program-2022`                             | Usa Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Devuelve `json` o `json-compact` donde sea compatible.                          |
| `--with-compute-unit-limit <UNITS>`          | Establece el límite de unidades de cómputo de la transacción.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Establece el precio de prioridad por unidad de cómputo.                                  |
| `-v, --verbose`                              | Muestra salida adicional.                                                   |
| `-V, --version`                              | Imprime la versión instalada de la CLI.                                          |

El programa predeterminado es el Token Program original. Usa `--program-2022` para un
mint o una cuenta de Token-2022, incluso al leerlos. Un comando falla si el
programa seleccionado no es propietario de la dirección proporcionada.

## Crear y usar un token

Los comandos imprimen las direcciones creadas. Guarda la dirección del mint devuelta por
`create-token` para los comandos siguientes.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Las cantidades son cantidades de token en formato de interfaz, ajustadas a los decimales del mint. Comandos como
`transfer`, `burn` y `unwrap-sol` aceptan `ALL` donde se indica en su ayuda.

## Crear un mint de Token-2022

Las extensiones asignan estado adicional al mint o a la cuenta y, por lo general, deben elegirse cuando
se crea el mint. Este ejemplo crea un mint de seis decimales con compatibilidad con
metadatos integrados:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Las opciones de extensión habituales de `create-token` incluyen:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` y `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` o `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` junto con
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Combina únicamente las extensiones que el programa Token-2022 permita usar juntas. Revisa la
[guía de extensiones de Token-2022](/docs/tokens/extensions) correspondiente antes de crear
una configuración de mint irreversible.

## Administrar autoridades y delegados

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` admite los tipos de autoridad mint, freeze, owner, close y los específicos de cada extensión.
Eliminar una autoridad con `--disable` es permanente cuando ningún
otro mecanismo del programa puede restaurarla.

## Congelar, quemar y cerrar

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` reduce tanto el saldo de la cuenta como el suministro total. `close` devuelve los
lamports restantes de la cuenta al destinatario configurado; no recupera los
tokens quemados.

## Envolver y desenvolver SOL

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Usa `sync-native` después de transferir lamports directamente a una token
account de SOL envuelto para que su cantidad de tokens coincida con los lamports subyacentes.

## Firma multisig

Crea un multisig de Token Program M-de-N con hasta 11 miembros:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

Para una transacción controlada por ese multisig, pasa la dirección del multisig como la
autoridad correspondiente y proporciona los keypairs de los miembros mediante valores
`--multisig-signer` repetidos. Consulta la ayuda del comando de destino, ya que su indicador de
autoridad principal varía según la operación.

## Saldos confidenciales

Los comandos de saldo confidencial requieren un mint de Token-2022 configurado para
transferencias confidenciales y una cuenta de destino configurada.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Para `configure-confidential-transfer-account` y `apply-pending-balance`, pasa
`--address <TOKEN_ACCOUNT_ADDRESS>` o una `<MINT_ADDRESS>` posicional, pero no
ambas. La forma posicional usa la associated token account del propietario. Los depósitos y
retiros siempre toman el mint y aceptan `--address` para reemplazar esa cuenta
predeterminada.

Usa `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits` y `disable-non-confidential-credits` para
controlar qué depósitos acepta la cuenta. Estos ajustes afectan la
privacidad de la cuenta y la compatibilidad de pagos; inspecciona la cuenta antes de cambiarlos.

## Firma estructurada y sin conexión

Usa la salida estructurada en lugar de analizar el texto mostrado:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Los comandos que producen transacciones suelen admitir `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce` y `--nonce-authority`. Las entradas exactas
para la firma sin conexión dependen del comando, los decimales del mint y la configuración de autoridades,
por lo que debes generar el mensaje sin firmar siguiendo las instrucciones de `--help` de ese comando y
verificar cada dirección antes de recopilar las firmas.
