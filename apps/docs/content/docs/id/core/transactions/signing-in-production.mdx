Sebuah transaksi hanya akan dieksekusi jika memiliki
[tanda tangan](/docs/core/transactions/transaction-structure#signatures) yang valid dari setiap
penandatangan yang diperlukan. Selama pengembangan lokal, kamu biasanya menyimpan kunci tersebut sebagai
[`Keypair`](/developers/cookbook/wallets/create-keypair) dan menandatangani secara langsung. Di
lingkungan produksi, pertanyaan pentingnya berbeda: **di mana private key
disimpan, dan siapa yang diizinkan untuk mengotorisasi tanda tangan dengannya?**

<Callout type="warn">
  Jangan pernah menyematkan private key dalam kode sisi klien, membundel ke dalam frontend, atau
  melakukan commit ke source control. Siapa pun yang mendapatkan kunci tersebut akan memperoleh kendali penuh atas
  dana akun tersebut.
</Callout>

## Pendekatan penandatanganan

| Pendekatan                  | Lokasi penyimpanan kunci                                     | Yang menandatangani                                          | Paling cocok untuk                                                      |
| ------------------------- | ------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **keypair lokal**         | Sebuah file atau variabel lingkungan pada mesin           | Kode kamu, secara langsung                                | Pengembangan lokal, pengujian, CI                                  |
| **Dompet browser**        | Dompet pengguna akhir (misalnya Phantom, Solflare)          | Pengguna akhir, per transaksi                      | dApps frontend di mana pengguna menandatangani transaksi mereka sendiri        |
| **Cloud KMS / HSM**       | Layanan kunci berbasis perangkat keras (AWS KMS, GCP KMS, Vault) | Backend kamu meminta tanda tangan dari layanan | Layanan backend, operasi treasury, lingkungan yang diregulasi |
| **Dompet Terkelola / MPC** | Dibagi atau dikustodikan di seluruh infrastruktur penyedia   | Penyedia ikut menandatangani sesuai kebijakan kamu     | Dompet tertanam, alur persetujuan, kustodi institusional   |

keypair lokal adalah satu-satunya pendekatan yang menempatkan material kunci mentah di dalam
aplikasi kamu. Setiap pendekatan produksi menyimpan kunci dalam infrastruktur khusus
dan meminta infrastruktur tersebut untuk menandatangani atas nama kamu.

## Penandatanganan backend

Ketika server perlu menandatangani — membayar biaya, mengirim transaksi program, atau
mengelola treasury — gunakan backend manajemen kunci khusus daripada
keypair mentah. Solana Foundation mengelola [Keychain](/docs/tools/keychain), sebuah
library penandatanganan terpadu (Rust dan TypeScript) yang mengekspos satu antarmuka `SolanaSigner`
di seluruh backend dalam tabel di atas: Memory, HashiCorp Vault, AWS
KMS, GCP KMS, Fireblocks, Privy, Turnkey, CDP, Crossmint, Dfns, Para, Openfort,
dan Utila.

Karena antarmukanya identik di semua backend, kamu dapat mengembangkan secara lokal dengan
kunci dalam memori dan beralih ke backend produksi melalui konfigurasi,
tanpa menulis ulang kode aplikasi. Keychain kompatibel dengan
[`@solana/kit`](/docs/clients/official/javascript) dan
[Rust SDK](/docs/clients/official/rust).
