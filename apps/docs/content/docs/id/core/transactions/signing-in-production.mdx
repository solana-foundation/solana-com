Sebuah transaksi hanya akan dieksekusi jika membawa
[tanda tangan](/docs/core/transactions/transaction-structure#signatures) yang valid dari setiap
penandatangan yang diperlukan. Selama pengembangan lokal, Anda biasanya menyimpan kunci tersebut sebagai
[`Keypair`](/developers/cookbook/wallets/create-keypair) dan menandatangani secara langsung. Di
lingkungan produksi, pertanyaan pentingnya berbeda: **di mana kunci privat
disimpan, dan siapa yang berhak mengotorisasi tanda tangan dengan kunci tersebut?**

<Callout type="warn">
  Jangan pernah menyematkan kunci privat di kode sisi klien, menyertakannya ke dalam frontend, atau
  meng-commit-nya ke source control. Siapa pun yang memperoleh kunci tersebut akan mendapatkan kendali penuh atas
  dana di akun itu.
</Callout>

## Pendekatan penandatanganan

| Pendekatan                  | Lokasi penyimpanan kunci                                     | Siapa yang menandatangani                                          | Paling cocok untuk                                                      |
| ------------------------- | ------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| **Keypair lokal**         | File atau variabel lingkungan pada mesin           | Kode Anda, secara langsung                                | Pengembangan lokal, pengujian, CI                                  |
| **Dompet browser**        | Dompet pengguna akhir (misalnya Phantom, Solflare)          | Pengguna akhir, untuk setiap transaksi                      | dApp frontend tempat pengguna menandatangani transaksinya sendiri        |
| **KMS / HSM cloud**       | Layanan kunci berbasis perangkat keras (AWS KMS, GCP KMS, Vault) | Backend Anda meminta tanda tangan dari layanan tersebut | Layanan backend, operasi treasury, lingkungan yang diatur regulasi |
| **Dompet terkelola / MPC** | Dipecah atau dikustodi di seluruh infrastruktur penyedia   | Penyedia ikut menandatangani sesuai kebijakan Anda     | Dompet tersemat, alur kerja persetujuan, kustodian institusional   |

Keypair lokal adalah satu-satunya pendekatan yang menempatkan materi kunci mentah di dalam
aplikasi Anda. Setiap pendekatan produksi menyimpan kunci di infrastruktur khusus
dan meminta infrastruktur tersebut menandatangani atas nama Anda.

## Penandatanganan backend

Ketika server perlu menandatangani (membayar biaya, mengirim transaksi program, atau
mengoperasikan treasury), gunakan backend manajemen kunci khusus alih-alih
keypair mentah. Solana Foundation memelihara [Keychain](/docs/tools/keychain), sebuah
library penandatanganan terpadu (Rust, TypeScript, Python, dan Go) yang menyediakan satu antarmuka
`SolanaSigner` untuk seluruh backend dalam tabel di atas: Memory,
HashiCorp Vault, AWS KMS, GCP KMS, Fireblocks, Privy, Turnkey, CDP, Crossmint,
Dfns, Para, Openfort, Utila, dan Fordefi.

Karena antarmukanya sama di seluruh backend, Anda dapat mengembangkan secara lokal dengan
kunci in-memory dan beralih ke backend produksi melalui konfigurasi, tanpa
menulis ulang kode aplikasi (backend yang melakukan broadcast untuk Anda, seperti Crossmint,
dipanggil melalui jalur sign-and-send). Keychain kompatibel dengan
[`@solana/kit`](/docs/clients/official/javascript),
[Rust SDK](/docs/clients/official/rust), `solders` (Python), dan `solana-go` v2
(Go).
