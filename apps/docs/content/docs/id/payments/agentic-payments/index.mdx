Pembayaran agentic memungkinkan perangkat lunak menemukan harga, mengotorisasi pembayaran, dan menerima
sumber daya dalam alur kerja HTTP yang sama. Agen dapat membayar kueri data, inferensi model,
atau pemanggilan tool tanpa harus membuat akun penagihan atau menyalin
kunci API terlebih dahulu.

## Alur pembayaran umum

MPP dan x402 menggunakan header dan model data yang berbeda, tetapi alur HTTP dasarnya
serupa:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP dan x402

Kedua protokol dapat menyelesaikan pembayaran stablecoin di Solana. Pilihlah berdasarkan
model pembayaran dan interoperabilitas yang dibutuhkan layanan Anda, bukan hanya berdasarkan kode status `402`
yang sama.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Tantangan (challenge)               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| Otorisasi klien    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Tanda terima                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Model pembayaran Solana   | Intent `charge` sekali bayar dan intent `session` berbasis pengukuran dengan batas           | Skema seperti `exact` dan `upto`; dukungan bervariasi menurut jaringan dan klien |
| Arsitektur penyelesaian | Validasi server, atau relay atau gateway opsional                | Server sumber daya dengan verifikasi lokal atau facilitator                 |
| Titik awal yang baik     | API yang memerlukan semantik autentikasi HTTP atau pengukuran berulang | Sumber daya bayar per permintaan dan klien x402 yang sudah ada                      |

MPP adalah **Machine Payments Protocol**. Jangan bingung dengan **Model
Context Protocol (MCP)**. MCP mengekspos tool dan sumber daya kepada agen; MPP atau x402
dapat mewajibkan pembayaran saat agen memanggil salah satu tool tersebut.

<Callout type="info">
  Sebuah layanan dapat mengiklankan lebih dari satu protokol. Klien memilih opsi
  pembayaran yang didukungnya, lalu menggunakan header tantangan, otorisasi, dan
  tanda terima yang sesuai selama seluruh pertukaran.
</Callout>
