## Infrastruktur RPC

[Endpoint publik](https://solana.com/docs/references/clusters#solana-public-rpc-endpoints)
(`api.mainnet.solana.com`) dibatasi lajunya dan tanpa SLA. Endpoint ini cukup
untuk pengembangan, tetapi akan gagal pada alur pembayaran produksi—seperti mencoba menjalankan
prosesor pembayaran melalui API bersama tanpa jaminan uptime.

<Callout type="caution" title="Jangan pernah menggunakan RPC publik untuk produksi">
  Gunakan [penyedia RPC privat](https://solana.com/rpc) untuk akses yang andal dan
  berlatensi rendah.
</Callout>

Saat memilih penyedia RPC, perhatikan hal berikut:

- **Keandalan**: SLA dengan jaminan uptime (99,9%+)
- **Latensi**: Kedekatan geografis dengan pengguna Anda
- **Fitur**: Fitur pendaratan transaksi, pengindeksan, API biaya prioritas

Untuk daftar lengkap penyedia RPC, lihat panduan
[Penyedia Infrastruktur RPC](https://solana.com/rpc).

### Konfigurasi RPC Redundan

Seperti penyedia layanan jaringan lainnya, penyedia RPC dapat mengalami downtime atau
periode penurunan performa. Agar aplikasi Anda tangguh, sebaiknya
konfigurasikan aplikasi Anda untuk menggunakan beberapa penyedia RPC.

[Solana Kit](https://github.com/anza-xyz/kit/tree/main/packages/rpc-transport-http)
menyediakan pustaka untuk menyesuaikan transport RPC yang memungkinkan Anda membangun
klien RPC redundan sendiri. Berikut contoh cara menggunakannya untuk membangun
klien RPC redundan:

```ts
import { RpcTransport } from "@solana/rpc-spec";
import { RpcResponse } from "@solana/rpc-spec-types";
import { createHttpTransport } from "@solana/rpc-transport-http";

// Create a transport for each RPC server
const transports = [
  createHttpTransport({ url: "https://mainnet-beta.my-server-1.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-2.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-3.com" })
];

// Create a wrapper transport that distributes requests to them
let nextTransport = 0;
async function roundRobinTransport<TResponse>(
  ...args: Parameters<RpcTransport>
): Promise<RpcResponse<TResponse>> {
  const transport = transports[nextTransport];
  nextTransport = (nextTransport + 1) % transports.length;
  return await transport(...args);
}
```

Jika Anda tidak ingin membangun alat perutean sendiri, Anda dapat memanfaatkan layanan
pihak ketiga seperti [Iron Forge](https://www.ironforge.sanctum.so/) untuk menangani
perutean bagi Anda.

## Pendaratan Transaksi

Di Devnet, transaksi cukup mudah mendarat. Di Mainnet, Anda bersaing untuk mendapatkan
ruang blok. Untuk meningkatkan peluang transaksi Anda dimasukkan ke dalam
blok, pastikan Anda telah menyusun transaksi dengan benar. Artinya:

- menyertakan blockhash baru sebelum mengirim transaksi
- menyertakan instruksi biaya prioritas dalam transaksi dengan biaya
  prioritas yang kompetitif
- menyertakan instruksi batas compute unit dalam transaksi dengan batas compute
  unit berdasarkan perkiraan compute unit yang dibutuhkan untuk transaksi tersebut

Selain itu, pertimbangkan alat lain seperti Jito Bundles untuk meningkatkan
peluang transaksi Anda dimasukkan ke dalam blok. Mari kita jelajahi alat-alat ini
lebih rinci.

### Konfigurasi Pengiriman Transaksi

Saat mengirim transaksi di Mainnet, konfigurasikan parameter berikut untuk tingkat
pendaratan yang optimal:

**Manajemen blockhash:**

- Ambil dengan commitment `confirmed`
- Simpan `lastValidBlockHeight` yang dikembalikan oleh `getLatestBlockhash`—ini memberi tahu
  Anda kapan transaksi Anda kedaluwarsa
- Blockhash kedaluwarsa setelah waktu yang ditetapkan oleh protokol tergantung pada durasi
  slot.

**Opsi pengiriman:**

- `maxRetries: 0` — Menonaktifkan percobaan ulang RPC otomatis. Tangani percobaan ulang sendiri agar
  Anda dapat menyegarkan blockhash bila diperlukan.
- `skipPreflight: true` — Melewati simulasi sebelum pengiriman. Gunakan ini saat Anda sudah
  memvalidasi transaksi dan menginginkan latensi terendah. Biarkan `false`
  selama pengembangan untuk menangkap error lebih awal.

```typescript
import { createSolanaRpc } from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);

// 1. Get blockhash with confirmed commitment
const { value: latestBlockhash } = await rpc
  .getLatestBlockhash({ commitment: "confirmed" })
  .send();

// 2. Build and sign your transaction with the blockhash
// ... (transaction building code)

// 3. Send with production settings
const signature = await rpc
  .sendTransaction(encodedTransaction, {
    encoding: "base64",
    maxRetries: 0n, // Handle retries yourself
    skipPreflight: true, // Skip simulation for speed (use false during dev)
    preflightCommitment: "confirmed"
  })
  .send();

// 4. Track expiration using lastValidBlockHeight
const { lastValidBlockHeight } = latestBlockhash;
// Stop retrying when current block height exceeds lastValidBlockHeight
```

### Gunakan Biaya Prioritas

Setiap transaksi Solana memerlukan biaya transaksi, yang dibayar dalam SOL. Biaya
transaksi dibagi menjadi dua bagian: biaya dasar dan biaya prioritas. Biaya dasar
mengompensasi validator untuk memproses transaksi. Biaya prioritas adalah biaya
opsional untuk meningkatkan peluang leader saat ini memproses
transaksi Anda. Anggap seperti pengiriman ekspres: Anda membayar lebih untuk pengiriman yang lebih cepat dan
lebih andal.

**Cara kerja biaya:**

```
Total fee = Base fee (5,000 lamports per signature) + Priority fee
Priority fee (legacy/v0) = ceil(compute_unit_price * compute_unit_limit / 1,000,000) lamports
Priority fee (v1 only) = Absolute total in lamports set in the message config
```

**Biaya di dunia nyata:**

- Transfer USDC sederhana: ~$0,001-0,005 pada kondisi normal
- Saat terjadi kemacetan: ~$0,01-0,05
- Kemacetan puncak: Bisa melonjak lebih tinggi

**Contoh Implementasi:**

Paket
[`@solana-program/compute-budget`](https://github.com/solana-program/compute-budget)
menyediakan fungsi helper untuk memperbarui atau menambahkan instruksi harga compute unit
(dalam micro-lamport) ke transaksi dengan mudah.

```typescript
import { updateOrAppendSetComputeUnitPriceInstruction } from "@solana-program/compute-budget";

const tx = pipe(
  createTransactionMessage({ version: 0 }),
  (m) => setTransactionMessageFeePayerSigner(payer, m),
  (m) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, m),
  (m) => appendTransactionMessageInstructions([myInstructions], m),
  (m) => updateOrAppendSetComputeUnitPriceInstruction(1000n as MicroLamports, m)
);
```

**Mendapatkan perkiraan biaya:** Sebagian besar penyedia RPC menawarkan API biaya prioritas:

- [Helius Priority Fee API](https://docs.helius.dev/solana-apis/priority-fee-api)
- [QuickNode Priority Fee Add-on](https://marketplace.quicknode.com/add-on/solana-priority-fee)
- [Triton Priority Fees API](https://docs.triton.one/chains/solana/improved-priority-fees-api)

Untuk mekanisme biaya selengkapnya, lihat [Biaya Transaksi](/docs/core/fees) dan
panduan kami:
[Cara Menambahkan Biaya Prioritas ke Transaksi](https://solana.com/developers/cookbook/transactions/add-priority-fees).

### Optimalkan Compute Unit

Komputasi di Solana diukur dalam compute unit (CU), yaitu perkiraan kasar
dari jumlah pekerjaan yang dilakukan program. Batas komputasi saat ini adalah 50 juta
CU per blok, dan 1,4 juta CU per transaksi. Saat Anda mengirimkan
transaksi, Anda perlu memperkirakan jumlah komputasi yang akan digunakan, dan
menetapkan batas compute unit yang sesuai - ini pada dasarnya adalah permintaan untuk berapa
banyak dari total kapasitas yang harus dicadangkan untuk transaksi Anda. Dalam
praktiknya, ini berarti memperkirakan compute unit yang dibutuhkan dengan tepat untuk
transaksi Anda sangat penting agar transaksi Anda dimasukkan ke dalam blok (dan
penting untuk mengelola biaya prioritas Anda). Batas komputasi transaksi dan blok
ditentukan oleh protokol.

Solana JSON RPC API memiliki metode
[`simulatetransaction`](/docs/rpc/http/simulatetransaction) yang dapat
digunakan untuk memperkirakan compute unit yang dibutuhkan untuk suatu transaksi, termasuk
perkiraan compute unit yang akan digunakan.
[`@solana/kit`](https://github.com/anza-xyz/kit) menyediakan fungsi helper yang
memperkirakan batas sumber daya transaksi dan menetapkannya pada pesan dalam satu langkah
(menggunakan metode `simulatetransaction` di balik layar). Untuk transaksi
versi 1, helper ini juga memperkirakan batas ukuran data akun yang dimuat.

```ts
import {
  estimateResourceLimitsFactory,
  estimateAndSetResourceLimitsFactory
} from "@solana/kit";

const estimateResourceLimits = estimateResourceLimitsFactory({ rpc });
const estimateAndSetResourceLimits = estimateAndSetResourceLimitsFactory(
  estimateResourceLimits
);
const txWithResourceLimits = await estimateAndSetResourceLimits(tx);
```

<Callout type="info">
  Jika Anda membangun dan mengirim transaksi dengan klien plugin kit, Anda biasanya
  tidak memerlukan langkah ini — klien akan menambahkan instruksi compute budget untuk Anda
  saat mengirim (`.sendTransaction()`). Alur manual di atas ditujukan untuk saat Anda
  menyusun transaksi secara langsung dengan `@solana/kit`.
</Callout>

Di produksi, jika Anda mengulang jenis transaksi yang sama berkali-kali,
sebaiknya pertimbangkan untuk menyimpan cache perkiraan komputasi untuk jenis transaksi tersebut guna
menghindari overhead memperkirakan compute unit setiap kali.

### Jito Bundles

Jito bundles adalah alat untuk mengelola eksekusi atomik dari beberapa transaksi.
Ini dicapai dengan mengirim beberapa transaksi ke jaringan Jito dengan
tip. Tip dapat digunakan untuk memberi insentif kepada jaringan Jito agar memasukkan
transaksi Anda ke dalam blok.

### Strategi Percobaan Ulang

Transaksi dapat gagal karena berbagai alasan. Tidak seperti API pembayaran tradisional yang
langsung mengembalikan sukses/gagal, transaksi blockchain memerlukan pelacakan
konfirmasi.

**Konsep utama:**

- **Kedaluwarsa blockhash**: Kedaluwarsa blockhash: Blockhash transaksi tetap
  valid selama 150 slot (sekitar 30 detik pada waktu slot 200 md). Waktu
  kedaluwarsa sebenarnya dapat bervariasi tergantung kecepatan produksi blok. Gunakan
  lastValidBlockHeight untuk menentukan kapan blockhash telah kedaluwarsa.
- **Idempotensi**: Transaksi bertanda tangan yang sama selalu menghasilkan
  tanda tangan yang sama—mengirim ulang aman dilakukan
- **Exponential backoff**: Hindari membebani jaringan dengan percobaan ulang yang cepat

```typescript
import {
  createSolanaRpc,
  createSolanaRpcSubscriptions,
  sendAndConfirmTransactionFactory,
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED
} from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);
const rpcSubscriptions = createSolanaRpcSubscriptions(process.env.RPC_WSS_URL!);

const sendAndConfirmTransaction = sendAndConfirmTransactionFactory({
  rpc,
  rpcSubscriptions
});

// Send with automatic confirmation tracking and block height monitoring
try {
  await sendAndConfirmTransaction(signedTransaction, {
    commitment: "confirmed",
    // Optional: abort after 75 seconds
    abortSignal: AbortSignal.timeout(75_000)
  });
} catch (e) {
  if (isSolanaError(e, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED)) {
    // Blockhash expired—rebuild transaction with fresh blockhash and retry
    rebuildAndRetryTransaction(); // implement your own logic for rebuilding and retrying the transaction
  }
  throw e;
}
```

`sendAndConfirmTransactionFactory` dari `@solana/kit` menangani polling konfirmasi
dan pelacakan tinggi blok secara otomatis. Fungsi ini melempar
`SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED` saat blockhash transaksi kedaluwarsa,
yang menandakan Anda perlu membangun ulang transaksi dengan blockhash baru.

## Penanganan Error

Solana Kit menyediakan error bertipe melalui `isSolanaError()`. Gunakan kode error spesifik
alih-alih pencocokan string:

```typescript
import {
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED,
  SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE,
  SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND,
  SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS
} from "@solana/kit";

function handlePaymentError(error: unknown): {
  message: string;
  retryable: boolean;
} {
  // Blockhash expired—rebuild and retry
  if (
    isSolanaError(error, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED) ||
    isSolanaError(error, SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND)
  ) {
    return { message: "Transaction expired—rebuilding", retryable: true };
  }

  // Insufficient SOL for fees
  if (
    isSolanaError(
      error,
      SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE
    )
  ) {
    return { message: "Not enough SOL for fees", retryable: false };
  }

  // Insufficient token balance
  if (
    isSolanaError(error, SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS)
  ) {
    return { message: "Insufficient balance", retryable: false };
  }

  // Unknown error
  console.error("Payment error:", error);
  return { message: "Payment failed—please retry", retryable: true };
}
```

**Kode Error Umum:**

| Kode Error                   | Penyebab                 | Pemulihan                                                                                                 |
| ---------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------- |
| `BLOCK_HEIGHT_EXCEEDED`      | Blockhash kedaluwarsa     | Bangun ulang dengan blockhash baru                                                                             |
| `BLOCKHASH_NOT_FOUND`        | Blockhash tidak ditemukan   | Bangun ulang dengan blockhash baru                                                                             |
| `INSUFFICIENT_FUNDS_FOR_FEE` | SOL tidak cukup        | Danai pembayar biaya atau gunakan [abstraksi biaya](/docs/payments/send-payments/payment-processing/fee-abstraction) |
| `INSUFFICIENT_FUNDS`         | Token tidak cukup     | Pengguna perlu menambah saldo                                                                                  |
| `ACCOUNT_NOT_FOUND`          | token account tidak ada | Buat ATA dalam transaksi                                                                                |

## Transaksi Tanpa Gas

Pengguna berharap membayar dengan stablecoin, bukan memperoleh SOL untuk biaya jaringan. Transaksi
tanpa gas menyelesaikan masalah ini—mirip dengan pengguna Venmo yang tidak memikirkan biaya ACH.
Lihat
[Abstraksi Biaya](/docs/payments/send-payments/payment-processing/fee-abstraction)
untuk implementasi lengkap.
