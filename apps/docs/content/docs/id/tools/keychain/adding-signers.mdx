Panduan ini ditujukan untuk penyedia layanan dompet dan pengembang yang ingin
mengintegrasikan solusi manajemen kunci baru ke dalam pustaka `solana-keychain`.
Dengan menambahkan implementasi penanda tangan Anda, Anda akan memungkinkan
pengembang menggunakan layanan Anda untuk penandatanganan transaksi Solana yang
aman melalui antarmuka terpadu.

Keychain menjaga implementasi Rust, TypeScript, Python, dan Go-nya tetap setara.
PR yang mencakup keempatnya sangat diutamakan. Jika Anda hanya dapat berkontribusi
pada satu, tidak masalah, tetapi harap ketahui bahwa implementasi lainnya akan diwajibkan sebelum signer dirilis
dalam sebuah rilis.

_Menggunakan Claude Code? [skill `add-signer-ci`](https://github.com/solana-foundation/solana-keychain/tree/main/.claude/skills/add-signer-ci)
di repo ini
menyiapkan workflow CI untuk signer baru yang dikontribusikan melalui PR fork._

## Ikhtisar Arsitektur

Library ini menggunakan arsitektur berbasis trait yang didefinisikan di `src/traits.rs`. Setiap
signer mengimplementasikan trait dasar `SolanaSigner` (`pubkey`, `sign_message`,
`is_available`) ditambah tepat satu trait kapabilitas yang sesuai dengan bentuk provider:

- `TransactionSigner` (`sign_transaction`): provider menandatangani byte
  dari pemanggil dan pemanggil yang melakukan broadcast. Sebagian besar backend.
- `ModifyingSigner` (`modify_and_sign_transaction`): provider menulis ulang
  transaksi, lalu menandatanganinya tanpa melakukan broadcast.
- `SendingSigner` (`sign_and_send_transaction`): provider menandatangani dan
  melakukan broadcast di sisi server.

Library ini juga menyediakan enum `Signer` terpadu yang membungkus semua
implementasi, sehingga memungkinkan pemilihan backend penandatanganan saat runtime. Enum ini hanya
mengimplementasikan trait dasar; kapabilitas diakses melalui `as_transaction_signer()`,
`as_modifying_signer()`, dan `as_sending_signer()`.

## Daftar Periksa Integrasi Cepat

- Buat modul penanda tangan Anda dengan implementasi
- Implementasikan trait dasar `SolanaSigner` (`pubkey`, `sign_message`,
  `is_available`) ditambah satu trait kapabilitas yang sesuai dengan bentuk provider Anda
  (biasanya `TransactionSigner`)
- Tambahkan feature flag di `Cargo.toml`, termasuk penanda internal `_remote` jika
  signer Anda menggunakan reqwest
- Perbarui enum `Signer` di `src/lib.rs` (varian, arm `dispatch_signer!`, dan
  arm di accessor kapabilitas yang sesuai dengan bentuk Anda)
- Terapkan HTTPS dan konfigurasi timeout pada klien HTTP
- Tandatangani byte pesan dan verifikasi signature yang dikembalikan sebelum melampirkannya
- Tambahkan unit test yang komprehensif (berbasis wiremock, di modul Anda)
- Tambahkan file integration test dan perbarui `.env.example`
- Tambahkan implementasi TypeScript, Python, dan Go
- Perbarui dokumentasi
- Pembaruan workflow CI (koordinasikan dengan maintainer, lihat
  [Pembaruan Workflow CI](#ci-workflow-updates-fork-prs))
- Kirim PR

## Langkah 3: Implementasikan Constructor dan Metode Helper

Penanda tangan jarak jauh **wajib** menerapkan HTTPS dan mengkonfigurasi timeout
HTTP. Gunakan struct `HttpClientConfig` bersama untuk pengaturan timeout.

```rust
use crate::http_client_config::HttpClientConfig;

impl YourServiceSigner {
    pub fn new(
        api_key: String,
        api_secret: String,
        wallet_id: String,
        public_key: String,
        http_config: Option<HttpClientConfig>,
    ) -> Result<Self, SignerError> {
        let pubkey = Pubkey::from_str(&public_key)
            .map_err(|e| SignerError::InvalidPublicKey(format!("Invalid public key: {e}")))?;

        let http = http_config.unwrap_or_default();
        let builder = reqwest::Client::builder()
            .timeout(http.resolved_request_timeout())
            .connect_timeout(http.resolved_connect_timeout());

        // Enforce HTTPS in production; wiremock uses HTTP in tests
        #[cfg(not(test))]
        let builder = builder.https_only(true);

        let client = builder.build().map_err(|e| {
            SignerError::ConfigError(format!("Failed to build HTTP client: {e}"))
        })?;

        Ok(Self {
            api_key,
            api_secret,
            wallet_id,
            api_base_url: "https://api.yourservice.com/v1".to_string(),
            client,
            public_key: pubkey,
        })
    }

    /// Sign raw bytes using your service's API
    async fn sign(&self, message: &[u8]) -> Result<Signature, SignerError> {
        let encoded_message = base64::engine::general_purpose::STANDARD.encode(message);

        let url = format!("{}/sign", self.api_base_url);
        let response = self
            .client
            .post(&url)
            .header("Authorization", format!("Bearer {}", self.api_key))
            .json(&serde_json::json!({
                "wallet_id": self.wallet_id,
                "message": encoded_message,
            }))
            .send()
            .await?;

        // Use generic error messages: never expose raw API response text
        if !response.status().is_success() {
            let status = response.status().as_u16();
            return Err(SignerError::remote_api(format!(
                "YourService API returned status {status}"
            )));
        }

        // Parse response: always use map_err, never .expect() or .unwrap()
        let response_data: SignResponse = response
            .json()
            .await
            .map_err(|e| SignerError::SerializationError(format!("Failed to parse response: {e}")))?;
        let sig_bytes = base64::engine::general_purpose::STANDARD
            .decode(&response_data.signature)
            .map_err(|e| SignerError::SerializationError(format!("Failed to decode signature: {e}")))?;

        let sig_array: [u8; 64] = sig_bytes
            .try_into()
            .map_err(|_| SignerError::SigningFailed("Invalid signature length".to_string()))?;

        Ok(Signature::from(sig_array))
    }
}
```

## Langkah 4: Implementasikan Trait Signer

Trait dasar `SolanaSigner` memiliki 2 metode async (`sign_message`,
`is_available`) ditambah `pubkey()`. Penandatanganan transaksi ditempatkan di trait kapabilitas;
sebagian besar provider mengimplementasikan `TransactionSigner`, yang `sign_transaction`-nya mengembalikan
`SignTransactionResult` (enum bertag yang menandai transaksi telah ditandatangani sepenuhnya atau
sebagian).

Tandatangani byte pesan, jangan seluruh transaksi wire, dan verifikasi
signature provider terhadap byte tersebut sebelum melampirkannya. Gunakan helper
`TransactionUtil` bersama untuk penandatanganan dan serialisasi.

```rust
use crate::signature_util::verify_or_reject;
use crate::traits::{SignTransactionResult, TransactionSigner};
use crate::transaction_util::TransactionUtil;

#[async_trait::async_trait]
impl SolanaSigner for YourServiceSigner {
    fn pubkey(&self) -> Pubkey {
        self.public_key
    }

    async fn sign_message(&self, message: &[u8]) -> Result<Signature, SignerError> {
        let signature = self.sign(message).await?;
        verify_or_reject(&signature, &self.public_key, message)?;
        Ok(signature)
    }

    async fn is_available(&self) -> bool {
        let url = format!("{}/health", self.api_base_url);
        self.client
            .get(&url)
            .send()
            .await
            .map(|r| r.status().is_success())
            .unwrap_or(false)
    }
}

#[async_trait::async_trait]
impl TransactionSigner for YourServiceSigner {
    async fn sign_transaction(
        &self,
        tx: &mut VersionedTransaction,
    ) -> Result<SignTransactionResult, SignerError> {
        let message = tx.message.serialize();
        let signature = self.sign(&message).await?;
        verify_or_reject(&signature, &self.public_key, &message)?;

        TransactionUtil::add_signature_to_transaction(tx, &self.public_key, signature)?;
        let serialized = TransactionUtil::serialize_transaction(tx)?;
        Ok(TransactionUtil::classify_signed_transaction(
            tx,
            (serialized, signature),
        ))
    }
}
```

Jika provider Anda menulis ulang transaksi sebelum menandatangani, implementasikan
`ModifyingSigner` sebagai gantinya dan ganti transaksi pemanggil secara menyeluruh dengan
byte dari provider. Jika provider melakukan broadcast di sisi server, implementasikan `SendingSigner`
dan biarkan transaksi pemanggil tidak tersentuh. Jangan pernah mengimplementasikan kapabilitas yang tidak dapat
dilayani oleh provider Anda.

## Langkah 7: Perbarui Enum Signer

Tambahkan signer Anda ke `src/lib.rs`. Impl dasar `SolanaSigner` melakukan dispatch melalui
makro `dispatch_signer!`, jadi tambahkan satu arm di sana. Akses kapabilitas berada di
accessor `as_transaction_signer()`, `as_modifying_signer()`, dan `as_sending_signer()`:
tambahkan arm `Some(s)` ke accessor yang sesuai dengan trait kapabilitas Anda (dan,
untuk backend sending atau modifying, arm `None` di `as_transaction_signer()`).

```rust
// Add feature-gated module
#[cfg(feature = "your_service")]
pub mod your_service;

// Re-export your signer type
#[cfg(feature = "your_service")]
pub use your_service::YourServiceSigner;

// Add to Signer enum
#[derive(Debug)]
pub enum Signer {
    #[cfg(feature = "memory")]
    Memory(MemorySigner),

    // ... existing variants

    #[cfg(feature = "your_service")]
    YourService(YourServiceSigner),  // Add your variant
}

// Add constructor method
impl Signer {
    #[cfg(feature = "your_service")]
    pub fn from_your_service(
        api_key: String,
        api_secret: String,
        wallet_id: String,
        public_key: String,
    ) -> Result<Self, SignerError> {
        Ok(Self::YourService(YourServiceSigner::new(
            api_key,
            api_secret,
            wallet_id,
            public_key,
            None, // uses default HttpClientConfig
        )?))
    }
}

// Update the dispatch macro: the base SolanaSigner impl uses it for
// pubkey, sign_message and is_available
macro_rules! dispatch_signer {
    ($self:ident, $signer:pat => $body:expr) => {
        match $self {
            // ... existing variants
            #[cfg(feature = "your_service")]
            Signer::YourService($signer) => $body,
        }
    };
}

// Add your arm to the capability accessor matching your shape
impl Signer {
    pub fn as_transaction_signer(&self) -> Option<&dyn TransactionSigner> {
        match self {
            // ... existing variants
            #[cfg(feature = "your_service")]
            Signer::YourService(s) => Some(s),
        }
    }
}
```

## Langkah 8: Tambahkan Pengujian Komprehensif

Tambahkan pengujian ke modul Anda (di bagian bawah `src/your_service/mod.rs`):

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use solana_sdk::{signature::Keypair, signer::Signer};
    use wiremock::{
        matchers::{header, method, path},
        Mock, MockServer, ResponseTemplate,
    };

    #[tokio::test]
    async fn test_new() {
        let keypair = Keypair::new();
        let signer = YourServiceSigner::new(
            "test-key".to_string(),
            "test-secret".to_string(),
            "test-wallet".to_string(),
            keypair.pubkey().to_string(),
            None,
        );
        assert!(signer.is_ok());
    }

    #[tokio::test]
    async fn test_sign_message() {
        let mock_server = MockServer::start().await;
        let keypair = Keypair::new();
        let message = b"test message";
        let signature = keypair.sign_message(message);

        Mock::given(method("POST"))
            .and(path("/sign"))
            .respond_with(ResponseTemplate::new(200).set_body_json(serde_json::json!({
                "signature": base64::engine::general_purpose::STANDARD.encode(signature.as_ref())
            })))
            .expect(1)
            .mount(&mock_server)
            .await;

        let mut signer = YourServiceSigner::new(
            "test-key".to_string(),
            "test-secret".to_string(),
            "test-wallet".to_string(),
            keypair.pubkey().to_string(),
            None,
        ).unwrap();
        signer.api_base_url = mock_server.uri();

        let result = signer.sign_message(message).await;
        assert!(result.is_ok());
    }

    #[tokio::test]
    async fn test_sign_unauthorized() {
        let mock_server = MockServer::start().await;
        let keypair = Keypair::new();

        Mock::given(method("POST"))
            .and(path("/sign"))
            .respond_with(ResponseTemplate::new(401))
            .expect(1)
            .mount(&mock_server)
            .await;

        let mut signer = YourServiceSigner::new(
            "bad-key".to_string(),
            "bad-secret".to_string(),
            "test-wallet".to_string(),
            keypair.pubkey().to_string(),
            None,
        ).unwrap();
        signer.api_base_url = mock_server.uri();

        let result = signer.sign_message(b"test").await;
        assert!(result.is_err());
    }
}
```

Cakup juga kegagalan verifikasi signature: respons mock yang signature-nya
tidak lolos verifikasi harus mengembalikan error.

Lihat `rust/src/tests/test_para_integration.rs` untuk referensi lengkap, dan

## Pembaruan Workflow CI (PR Fork)

CI adalah proses dua fase. Koordinasikan dengan maintainer untuk menyiapkan `main` sebelum
PR Anda dapat diuji: mereka memperbarui `fork-external-live-manual.yml`, menambahkan variabel env
ke `ci.yml`, dan mengonfigurasi GitHub Secrets.

PR Anda harus menyertakan perubahan Fase 2 berikut bersama kode signer Anda:

- **`ci.yml`**: tambahkan fitur Rust Anda ke matriks `backend` (sebelum `all`) dan
  fungsi integration test Anda ke matriks `test`
- **`typescript-ci.yml`**: tambahkan paket Anda ke matriks unit dan integration test,
  lalu tambahkan variabel env ke langkah integration test
- **`typescript-publish.yml`**: tambahkan paket Anda ke `PUBLISH_PACKAGES`, array
  `packages` GitHub Release, dan tabel ringkasan
- **`python-ci.yml`**: tambahkan backend ke gating `CI_SIGNER_*` di
  `resolve-signers` dan ke matriks integrasi
- **`go-ci.yml`**: tambahkan backend ke gating `CI_SIGNER_*` dan ke
  `moduleBySigner`

## Signer TypeScript

Jika Anda juga menambahkan paket signer TypeScript, buat di
`typescript/packages/your-signer/`. Pola kunci:

- Fungsi factory `createYourSigner()` mengembalikan
  `SolanaTransactionSigner<TAddress> & SolanaMessageSigner<TAddress>`; jadikan
  kelas signer bersifat internal dan ekspor hanya factory beserta tipe konfigurasinya
- Ekspor interface config (`YourSignerConfig`)
- Jika backend Anda tidak dapat menandatangani pesan, hilangkan `SolanaMessageSigner` dan jangan ekspos metode
  `signMessages` sama sekali: Kit mengklasifikasikan signer berdasarkan keberadaan metode, sehingga
  stub yang melempar error akan salah mengklasifikasikan signer
- Terapkan HTTPS pada field konfigurasi `apiBaseUrl` dengan `assertHttpsUrl()` dari
  `@solana/keychain-core`
- Lakukan panggilan remote melalui `fetchSignerJson()` dari `@solana/keychain-core`,
  yang menangani pemetaan error, sanitasi respons, penolakan redirect, dan
  timeout default
- Sanitasi teks error API remote lainnya dengan `sanitizeRemoteErrorResponse()`
  dari `@solana/keychain-core`
- Gunakan `throwSignerError(SignerErrorCode.*, { cause, message })` dari
  `@solana/keychain-core`
- Hormati `config?.abortSignal` di setiap metode penandatanganan, dengan meneruskannya ke
  `fetchSignerJson()` dan `signBatchStaggered()`
- Validasi `requestDelayMs` dengan `validateRequestDelayMs()` dan lakukan batch dengan
  `signBatchStaggered()`
- Tambahkan JSDoc `@throws` ke fungsi factory yang mencantumkan kode error
- Deklarasikan paket `@solana/*` sebagai peer dependency pada `>=8.1.0`
- Unit test dengan vitest dan `fetch` yang di-mock; integration test dengan
  `runSignerIntegrationTest` dari `@solana/keychain-test-utils`

### Sending Signer

Jika provider Anda menulis ulang transaksi atau melakukan broadcast di sisi server,
signature-nya tidak dapat diterapkan pada transaksi pemanggil, sehingga harus berupa
`SolanaSendingSigner` dan bukan `SolanaTransactionSigner`:

- Implementasikan `signAndSendTransactions()` dan **jangan** ekspos `signTransactions`
  (maupun `signMessages`, kecuali backend benar-benar menandatangani pesan)
- Hormati `config?.abortSignal`. Setelah provider menerima permintaan create, laporkan
  setiap kegagalan (termasuk abort) sebagai `BROADCAST_UNCONFIRMED` dengan menyertakan
  id transaksi provider, dengan alasan abort disimpan sebagai `cause`
- Tambahkan overload `createKeychainSigner` bertipe yang mengembalikan tipe sending-signer Anda
- Kecualikan backend Anda dari `KeychainKitPluginConfig` di
  `typescript/packages/kit-plugin/src/keychain-plugin.ts`, karena sending
  signer tidak dapat berfungsi sebagai `payer` atau `identity` klien Kit
- Pastikan dalam unit test bahwa `isTransactionPartialSigner()` bernilai false dan
  `isTransactionSendingSigner()` bernilai true untuk instance Anda

### Perbarui Paket Umbrella

Perbarui `typescript/packages/keychain/` (7 file yang perlu diubah):

1. `src/types.ts`: Tambahkan `YourSignerConfig` ke union terdiskriminasi
   `KeychainSignerConfig`
2. `src/create-keychain-signer.ts`: Tambahkan switch case (setiap paket backend
   dimuat dengan `import()` dinamis)
3. `src/resolve-address.ts`: Tambahkan ke switch case fast-path atau fetch-path
4. `src/index.ts`: Tambahkan ekspor tipe konfigurasi, namespace, dan fungsi factory
5. `package.json`: Tambahkan dependensi `@solana/keychain-your-signer: "workspace:*"`
6. `tsconfig.json`: Tambahkan referensi `{ "path": "../your-signer" }`
7. `typescript/scripts/test-treeshake-umbrella.mjs`: Tambahkan paket Anda ke
   `SIGNER_MARKERS` dan factory Anda ke `FACTORIES`

Pernyataan switch memiliki pemeriksaan `never` yang menyeluruh, sehingga TypeScript akan menampilkan error
jika Anda menambahkan ke union tetapi melewatkan sebuah case. Jalankan `just ts-treeshake` setelahnya:
setiap paket dan umbrella harus tetap dapat di-tree-shake.

## Signer Python

Buat modul di `python/src/solana_keychain/your_signer/` (`__init__.py`
ditambah `signer.py`). Pola utama:

- Buat subclass `SolanaSigner` dari `solana_keychain.core` (properti `pubkey`,
  `async sign_message()`, `async is_available()`) ditambah tepat satu class
  kapabilitas: `TransactionSigner` (`async sign_transaction()`), `ModifyingSigner`
  (`async modify_and_sign_transaction()`) atau `SendingSigner`
  (`async sign_and_send_transaction()`)
- Ekspor factory `async create_your_signer()` yang meng-await `init()` ketika
  backend me-resolve alamatnya secara remote; sebelum init, penandatanganan memunculkan
  `SignerErrorCode.NOT_INITIALIZED`
- Ekspor dataclass konfigurasi (`YourSignerConfig`) dengan secret yang ditandai
  `field(repr=False)`
- Terapkan HTTPS pada field base-URL dengan `assert_https_url()`, dan arahkan setiap
  permintaan melalui `fetch_signer_json()`
- Verifikasi signature provider sebelum mengembalikannya; gunakan
  `signed_message_bytes()` untuk byte yang dicakup signature, jangan pernah menggunakan prefiks
  versi buatan sendiri
- Daftarkan backend di `_BACKENDS` pada
  `python/src/solana_keychain/keychain.py`
- Jika backend memerlukan SDK provider, lindungi impor tersebut dengan guard, munculkan `ImportError`
  yang menyebutkan `pip install 'solana-keychain[your-signer]'`, deklarasikan extra di
  `python/pyproject.toml`, dan jangan pernah mengimpor backend secara eager dari root
  paket
- Unit test dengan pytest: `respx` untuk backend HTTP, stub client untuk backend
  SDK, serta pemeriksaan bahwa tidak ada secret yang muncul di `str()` atau `repr()` dari
  error yang di-raise
- Tambahkan factory `make_your_signer()` ke
  `python/tests/integration/test_live_signers.py` dan daftarkan di
  `_MESSAGE_CAPABLE` (atau `_TRANSACTION_ONLY` untuk backend tanpa
  `sign_message`)

## Go Signer

Setiap backend Go adalah modulnya sendiri, di `go/signers/yoursigner/` dengan path modul
`github.com/solana-foundation/solana-keychain/go/signers/yoursigner/v2`. Lihat
`go/signers/para/` sebagai referensi. Pola utama:

- Implementasikan `core.SolanaSigner` (`Pubkey()`, `SignMessage(ctx, message)`,
  `IsAvailable(ctx)`) ditambah tepat satu interface capability:
  `core.TransactionSigner`, `core.ModifyingSigner`, atau `core.SendingSigner`.
  Capability dideteksi melalui type assertion, sehingga backend yang tidak dapat menandatangani
  transaksi tidak boleh memiliki method `SignTransaction` sama sekali
- Ekspor struct `Config` dan constructor `New` (`New(ctx, cfg)` ketika
  backend menyelesaikan alamatnya secara remote; sebelum itu, kembalikan
  `core.NewNotInitializedError`)
- Bangun HTTP client dengan `core.NewHTTPClient` atau `core.ResolveHTTPClient`, dan
  validasi base URL dengan `core.NormalizeHTTPSBaseURL`
- Tandatangani transaksi dengan `core.SignTransactionWith`, yang menandatangani byte
  pesan dan melampirkan tanda tangan; verifikasi tanda tangan provider dengan
  `core.VerifySignature`
- Kembalikan error dengan `core.NewSignerError` / `core.WrapSignerError` dan kode
  yang stabil seperti `core.CodeSigningFailed`
- Unit test dengan `httptest`; integration test di `integration_test.go` di balik
  tag `//go:build integration`

## Tips Implementasi

### Penanganan Error

Selalu gunakan varian `SignerError` yang sudah ada. Baik `Display` maupun `Debug` pada
`SignerError` di-redact, jadi jaga pesan tetap generik dan jangan pernah menyertakan data mentah
respons API. Jangan pernah menggunakan `.expect()` atau `.unwrap()` pada respons API yang tidak tepercaya:

```rust
// Good: uses the constructor with a generic message
return Err(SignerError::remote_api(format!(
    "YourService API returned status {status}"
)));

// Good: converts from standard errors
let bytes = base64::decode(data)
    .map_err(|e| SignerError::SerializationError(format!("Failed to decode: {e}")))?;
```

### Persyaratan Keamanan

Ini bukan sekadar saran: konsumen memilih backend berdasarkan hal-hal ini. Jika
provider Anda membuat salah satunya mustahil dipenuhi, sampaikan hal itu di PR dan di
`docs/SECURITY_MODEL.md` milik repositori.

- **Verifikasi apa yang ditandatangani provider.** Hitung byte pesan secara lokal dan
  verifikasi tanda tangan yang dikembalikan terhadap byte tersebut pada posisi yang diwajibkan signer Anda
  sebelum melampirkannya. Tanda tangan yang tidak lolos verifikasi harus gagal, jangan pernah
  dilampirkan.
- **Nyatakan apakah provider melakukan broadcast.** Jika provider mengeksekusi di sisi server,
  implementasikan bentuk sending dan kembalikan tanda tangan yang mengidentifikasi
  transaksi yang sudah masuk. Jika provider tidak memiliki endpoint khusus sign, jadikan
  backend hanya-sending daripada mengirim secara diam-diam di belakang pemanggil.
- **Jangan pernah membiarkan pemanggil memegang transaksi yang tidak dicakup oleh tanda tangan.**
  Provider yang menulis ulang transaksi menandatangani byte miliknya sendiri: biarkan
  transaksi pemanggil tidak tersentuh (kasus broadcast-managed), atau gunakan
  bentuk modifying dan ganti seluruhnya dengan byte dari provider.
- **Laporkan ketidakpastian broadcast apa adanya.** Kegagalan setelah pengiriman mungkin tetap
  berhasil masuk. Tampilkan `BROADCAST_UNCONFIRMED` alih-alih error generik,
  sertakan ID transaksi provider setiap kali Anda memilikinya, dan kirim
  idempotency key yang diturunkan dari pesan pada setiap create agar pengiriman ulang dengan byte identik
  aman.
- **Jangan pernah menandatangani sebelum init.** Gunakan `Option<Pubkey>` (bukan `Pubkey::default()`) untuk
  kunci publik sebelum `init()`, dan gagalkan dengan error konfigurasi jika penandatanganan
  dicoba lebih dulu.
- Jangan pernah mencatat log data sensitif (kunci privat, secret API, respons API mentah), dan
  gunakan impl `Debug` yang menyembunyikan field sensitif
- Terapkan HTTPS (`https_only(true)`, dibatasi dengan `#[cfg(not(test))]` untuk
  wiremock) dan konfigurasikan timeout request dan koneksi melalui `HttpClientConfig`
  (default: 30s/5s)
- Zeroize material kunci perantara dengan `zeroize::Zeroizing<Vec<u8>>`

### Pengujian dengan Mock

Gunakan `wiremock` untuk melakukan mocking API HTTP. Lakukan assertion pada tipe
error saja, bukan teks pesan error:

```rust
#[cfg(test)]
mod tests {
    use wiremock::{MockServer, Mock, ResponseTemplate};

    #[tokio::test]
    async fn test_api_call() {
        let mock_server = MockServer::start().await;

        Mock::given(method("POST"))
            .respond_with(ResponseTemplate::new(200))
            .mount(&mock_server)
            .await;

        // Use mock_server.uri() as your api_base_url
    }
}
```
