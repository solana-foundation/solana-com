## Instalasi

Instal paket lengkap atau penanda tangan individual sesuai kebutuhan:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Memerlukan `@solana/kit` 8.1 atau yang lebih baru. Transaksi v1
(`createTransactionMessage({ version: 1 })`) didukung, kecuali oleh Fireblocks
dengan `useProgramCall: true`, yang hanya menerima legacy dan v0.

## Penggunaan Dasar

### Factory Terpadu (Direkomendasikan untuk aplikasi yang ingin mendukung beberapa penanda tangan)

Gunakan `createKeychainSigner` dengan konfigurasi diskriminan untuk membuat
backend apa pun:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Atau instal paket penanda tangan individual untuk jejak dependensi yang lebih
kecil:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Menggunakan dengan Pesan Transaksi

Setiap backend kecuali Crossmint dan mode native Fordefi mengembalikan
`SolanaTransactionSigner`, yaitu `TransactionPartialSigner` Kit dan dapat digunakan
dengan helper partial-signer `@solana/signers` di bawah ini. Backend dengan
managed-broadcast dibahas di [Kemampuan Signer](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Tandatangani dan Kirim dengan Signer Apa Pun

`signAndSendTransaction` dari `@solana/keychain-core` mengirimkan transaksi ke
onchain apa pun bentuk signer-nya. Sending signer melakukan broadcast melalui
provider-nya; bentuk lainnya menggunakan `sendTransaction` yang Anda berikan (core tidak memiliki
dependensi RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Menggunakan dengan Kit Client (plugin keychainSigner)

`@solana/keychain-kit-plugin` menginstal keychain signer langsung pada
[Kit client](https://github.com/anza-xyz/kit), menghubungkannya sebagai `payer`
dan `identity` sehingga Anda melewati pengaturan `pipe` manual seperti yang
ditunjukkan di atas:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Plugin menerima konfigurasi bertag backend yang sama seperti `createKeychainSigner`,
kecuali Crossmint dan mode native Fordefi (`chain` diatur). Backend tersebut menulis ulang
transaksi di sisi server, sehingga tidak dapat berperan sebagai `payer` atau
`identity` klien; plugin menolaknya saat kompilasi maupun saat runtime. Hanya
backend yang dituju yang dibundel (paket backend dimuat melalui
`import()` dinamis).

Gunakan `keychainPayer` atau `keychainIdentity` untuk menetapkan satu peran
saja, dan gabungkan backend pada satu client:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Sudah memiliki `SolanaTransactionSigner`? Itu adalah `TransactionPartialSigner`
Kit yang valid, sehingga Anda dapat memasangnya dengan
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
sebagai gantinya (`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Pembatalan dan Broadcast yang Belum Terkonfirmasi

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions`, dan
`signMessages` semuanya menerima `{ abortSignal }` sebagai argumen kedua. Membatalkan
hanya menghentikan penantian; ini tidak membatalkan pekerjaan yang sudah diterima provider.

Pada mode auto native Crossmint dan Fordefi, kegagalan tidak berarti tidak ada
yang masuk. Jika provider mungkin sudah menerima transaksi, kode errornya adalah
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` diatur ketika permintaan pembuatan diterima, dan
`context.idempotencyKey` membawa kunci yang diturunkan dari pesan. Mengirim ulang
transaksi yang identik byte demi byte aman dilakukan; transaksi yang dibangun ulang (misalnya dengan
blockhash baru) adalah transfer baru. `providerMayHaveAccepted(error)` dan
`providerStatus(error)` dari `@solana/keychain-core` membantu mengklasifikasikan error.
Lakukan rekonsiliasi dengan provider sebelum mencoba lagi.

});

### Crossmint

```typescript
import { createCrossmintSigner } from "@solana/keychain-crossmint";

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmint hanya mendukung pengiriman. API-nya selalu mengeksekusi transaksi yang disetujui
di sisi server dan menanggung gas, sehingga signer hanya menyediakan
`signAndSendTransactions()`: tidak ada `signTransactions()` atau `signMessages()`,
dan tidak dapat dipasang dengan `@solana/keychain-kit-plugin`. Signature yang
dikembalikan mengidentifikasi transaksi yang didaratkan Crossmint.

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

Fordefi memiliki tiga mode penandatanganan, yang ditetapkan saat konstruksi oleh `chain` dan
`pushMode`. Setiap mode menyediakan tepat satu metode transaksi, dan ketiganya menandatangani
pesan:

| Mode          | Konfigurasi                                      | Tipe                        | Metode                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Black box     | `chain` tidak diatur                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Native auto   | `chain` diatur, `pushMode` dihilangkan atau `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Native manual | `chain` diatur, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

Permintaan API diautentikasi dengan tanda tangan permintaan ECDSA P-256: berikan
kunci penandatanganan sebagai `privateKeyPem`, atau simpan di KMS/HSM dengan memberikan
`requestSigner`.

**Mode native auto** (direkomendasikan untuk penggunaan onchain): atur `chain`, dan Fordefi
menandatangani serta melakukan broadcast transaksi sendiri. Karena Fordefi dapat mengganti
blockhash atau biaya sebelum menandatangani, signer-nya adalah `TransactionSendingSigner`
Kit: gunakan dengan
`signAndSendTransactionMessageWithSigners`, bukan alur partial-signer yang ditampilkan
di atas. Mode native auto hanya menerima transaksi yang belum ditandatangani dan satu-satunya
signer yang diperlukan adalah vault, dan tidak dapat digunakan dengan `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Mode native manual**: atur `chain` dan `pushMode: "manual"`. Fordefi menulis ulang
pesan (blockhash terbaru, instruksi biaya Compute Budget) dan menandatanganinya,
tetapi tidak melakukan broadcast. `modifyAndSignTransactions()` mengembalikan transaksi yang
ditandatangani Fordefi, yang menggantikan transaksi yang Anda kirimkan: selalu lanjutkan dari
transaksi yang dikembalikan. Fordefi harus menjadi pembayar biaya dan harus menandatangani sebelum
signer lain yang diperlukan. Penulisan ulang tidak di-diff, jadi periksa hasilnya sebelum
melakukan broadcast.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Mode black box**: hilangkan `chain`. Fordefi menandatangani byte mentah dan tidak menyiarkan; Anda merakit dan mengirimkan transaksi sendiri. Gunakan ini dengan vault black box Fordefi.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Kemampuan Signer

`@solana/keychain-core` mendefinisikan satu interface untuk setiap bentuk signer Kit. Masing-masing menambahkan
`isAvailable(): Promise<boolean>` ke interface `@solana/signers` yang sesuai:

- `SolanaTransactionSigner` (`TransactionPartialSigner` Kit): mengembalikan signature
  untuk transaksi yang Anda miliki.
- `SolanaModifyingSigner` (`TransactionModifyingSigner` Kit): menulis ulang
  transaksi, menandatanganinya, dan mengembalikan transaksi baru tanpa melakukan broadcast.
- `SolanaSendingSigner` (`TransactionSendingSigner` Kit): menandatangani dan melakukan broadcast
  melalui provider-nya.
- `SolanaMessageSigner` (`MessagePartialSigner` Kit): menandatangani pesan offchain.
  Ini terpisah dari bentuk-bentuk transaksi.

`SolanaSigner` adalah gabungan (union) dari ketiga bentuk transaksi. Tipe kembalian setiap factory
menyebutkan bentuk persis dari backend-nya. Ketika konfigurasi baru diketahui saat
runtime, persempit dengan `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner`, atau `isSolanaMessageSigner`. `signerCapabilities(signer)`
melaporkan keempatnya sekaligus.

| Backend                                                                                                     | Bentuk                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (black box) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (tanpa penandatanganan pesan)  |
| fordefi (native manual)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (native auto)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (tanpa penandatanganan pesan)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Membangun Signer Kustom

Implementasikan interface kemampuan yang didukung backend Anda:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Implementasikan hanya yang didukung backend Anda. Kit mengklasifikasikan signer berdasarkan metode
yang ada, jadi jangan pernah menambahkan metode yang hanya melempar error.

Lihat [panduan Menambahkan Signer](/docs/tools/keychain/adding-signers) untuk
mengintegrasikan layanan manajemen kunci tambahan.
