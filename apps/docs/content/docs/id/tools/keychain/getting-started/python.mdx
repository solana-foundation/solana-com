Versi 2.0 adalah rilis stabil pertama dari paket Python ini. [Panduan migrasi 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)
membahas bentuk penandatanganan yang sama dengan Rust dan TypeScript.

## Instalasi

Instal paket dasar, ditambah satu extra untuk setiap backend yang membutuhkan
dependensi provider:

```shell
pip install solana-keychain                # memory, vault and para
pip install 'solana-keychain[aws-kms]'     # AWS KMS (boto3)
pip install 'solana-keychain[gcp-kms]'     # GCP KMS (google-cloud-kms)
pip install 'solana-keychain[privy]'       # Privy
pip install 'solana-keychain[turnkey]'     # Turnkey
pip install 'solana-keychain[fireblocks]'  # Fireblocks
pip install 'solana-keychain[cdp]'         # Coinbase Developer Platform
pip install 'solana-keychain[crossmint]'   # Crossmint
pip install 'solana-keychain[dfns]'        # Dfns
pip install 'solana-keychain[openfort]'    # Openfort
pip install 'solana-keychain[utila]'       # Utila
pip install 'solana-keychain[fordefi]'     # Fordefi

# Several at once
pip install 'solana-keychain[aws-kms,privy]'
```

Membutuhkan Python 3.10 atau yang lebih baru. Transaksi adalah objek
[`solders`](https://pypi.org/project/solders/) `VersionedTransaction`;
pesan legacy, v0, dan v1 semuanya diterima, kecuali oleh Fireblocks dengan
`use_program_call=True`, yang hanya menerima legacy dan v0.

Memory, Vault, dan Para dapat diimpor dari root paket. Setiap backend lainnya
diimpor dari submodulnya sendiri (misalnya `solana_keychain.aws_kms`), dan
mengimpor salah satunya tanpa extra-nya akan memunculkan `ImportError` yang menyebutkan extra
yang harus diinstal. Ledger hanya tersedia untuk Rust.

## Penggunaan Dasar

Setiap backend memiliki dataclass konfigurasi dan factory async `create_<backend>_signer`
yang mengembalikan signer yang siap digunakan. Semua metode penandatanganan adalah coroutine:

```python
import asyncio

from solana_keychain import MemorySigner
from solders.transaction import VersionedTransaction


async def sign(transaction: VersionedTransaction) -> str:
    signer = MemorySigner.from_private_key_file("/path/to/id.json")
    print("Signing with:", signer.pubkey)

    # Check availability (useful for remote signers)
    if not await signer.is_available():
        raise RuntimeError("Signer offline")

    result = await signer.sign_transaction(transaction)
    print("Signature:", result.signature)
    print("Fully signed:", result.is_complete)
    return result.encoded_transaction  # base64 wire transaction
```

`sign_transaction` mengembalikan `SignedTransaction` dengan `encoded_transaction`,
`signature`, `is_complete`, dan `transaction`. `transaction` adalah transaksi
yang telah ditandatangani dan menjadi acuan utama: lanjutkan dari objek ini, terutama dengan modifying signer, yang
hasilnya adalah objek yang berbeda dari objek yang Anda berikan.

### Factory Terpadu

`create_keychain_signer` menerima nama backend dan dataclass konfigurasi backend tersebut,
lalu mengimpor backend secara lazy, sehingga hanya extra yang Anda gunakan yang perlu
diinstal:

```python
from solana_keychain import create_keychain_signer
from solana_keychain.privy import PrivySignerConfig

signer = await create_keychain_signer(
    "privy",
    PrivySignerConfig(
        app_id="your-app-id",
        app_secret="your-app-secret",
        wallet_id="your-wallet-id",
    ),
)
```

Nama-nama tersebut tercantum di `SUPPORTED_BACKENDS`: `aws-kms`, `cdp`, `crossmint`,
`dfns`, `fireblocks`, `fordefi`, `gcp-kms`, `memory`, `openfort`, `para`,
`privy`, `turnkey`, `utila`, dan `vault`. Nama yang tidak dikenal, atau konfigurasi dengan
kelas yang salah, akan memunculkan `SignerError` dengan `SignerErrorCode.CONFIG_ERROR`. Factory
ini bertipe pengembalian `SolanaSigner` dasar, jadi persempit dengan
`isinstance` sebelum menandatangani (lihat [Kemampuan Signer](#signer-capabilities)).

### Klien HTTP Jarak Jauh

Backend HTTP jarak jauh menerima `http_client` opsional (sebuah `httpx.AsyncClient`)
untuk TLS atau proxy kustom. Jika tidak diatur, setiap permintaan menggunakan klien sekali pakai
dengan batas waktu 60 detik, HTTPS diwajibkan pada URL dasar, dan pengalihan
(redirect) ditolak.

## Kemampuan Signer

Setiap backend merupakan subkelas dari ABC `SolanaSigner` (`pubkey`, `sign_message`,
`is_available`) ditambah tepat satu kelas kemampuan:

- `TransactionSigner`: `sign_transaction(tx)` menandatangani transaksi Anda di tempat
  dan mengembalikan `SignedTransaction`. Anda yang menyiarkannya.
- `ModifyingSigner`: `modify_and_sign_transaction(tx)` memungkinkan provider menulis ulang
  transaksi, lalu menandatanganinya tanpa menyiarkannya. Objek Anda dibiarkan
  tidak berubah; lanjutkan dari `SignedTransaction.transaction` yang dikembalikan.
- `SendingSigner`: `sign_and_send_transaction(tx)` menandatangani dan menyiarkan melalui
  provider, lalu mengembalikan `Signature` dari transaksi yang berhasil masuk. Transaksi
  Anda tidak pernah diubah.

| Backend                                                                           | Kelas kemampuan    | `sign_message`                                  |
| --------------------------------------------------------------------------------- | ------------------- | ----------------------------------------------- |
| memory, vault, privy, turnkey, aws-kms, fireblocks, gcp-kms, dfns, para, openfort | `TransactionSigner` | Ya                                             |
| cdp                                                                               | `TransactionSigner` | Hanya payload UTF-8, selain itu `SERIALIZATION_ERROR` |
| utila                                                                             | `TransactionSigner` | Memunculkan `SIGNING_FAILED`                         |
| fordefi black box (`FordefiBlackBoxSigner`)                                       | `TransactionSigner` | Ya                                             |
| fordefi native manual (`FordefiNativeManualSigner`)                               | `ModifyingSigner`   | Ya                                             |
| fordefi native auto (`FordefiNativeAutoSigner`)                                   | `SendingSigner`     | Ya                                             |
| crossmint                                                                         | `SendingSigner`     | Memunculkan `SIGNING_FAILED`                         |

Persempit dengan `isinstance`. Semua kelas kemampuan diekspor dari root
paket:

```python
from solana_keychain import ModifyingSigner, SendingSigner, TransactionSigner

if isinstance(signer, SendingSigner):
    signature = await signer.sign_and_send_transaction(transaction)
elif isinstance(signer, ModifyingSigner):
    result = await signer.modify_and_sign_transaction(transaction)
elif isinstance(signer, TransactionSigner):
    result = await signer.sign_transaction(transaction)
```

### Inisialisasi

Factory `create_*` dan `create_keychain_signer` melakukan semua penyiapan yang diperlukan
untuk Anda. Jika Anda membuat kelas signer Privy, Fireblocks, Dfns, Crossmint, Para, Openfort, atau
Utila secara langsung, panggil `await signer.init()` sebelum digunakan. Sebelum itu,
`pubkey` dan setiap pemanggilan penandatanganan akan memunculkan `SignerErrorCode.NOT_INITIALIZED`.

## Konfigurasi Backend

### Memory

Buat dari file keypair Solana CLI, string base58 atau `"[1,2,...]"`, byte
mentah, atau `Keypair` dari `solders`:

```python
from solana_keychain import MemorySigner, MemorySignerConfig, create_memory_signer
from solders.keypair import Keypair

signer = MemorySigner.from_private_key_file("/path/to/id.json")
signer = MemorySigner.from_private_key_string("base58_private_key")
signer = MemorySigner.from_bytes(secret_key_bytes)  # 64 or 32 bytes
signer = await create_memory_signer(MemorySignerConfig(keypair=Keypair()))
```

Kunci berada di memori proses, dan Python tidak dapat menghapusnya dengan nol (zeroize). Gunakan backend ini
untuk pengembangan dan pengujian.

### HashiCorp Vault

Kunci harus berupa kunci ed25519 di mesin transit. HTTP biasa hanya diterima
untuk alamat loopback, untuk `vault server -dev`:

```python
from solana_keychain import VaultSignerConfig, create_vault_signer

signer = await create_vault_signer(
    VaultSignerConfig(
        api_base_url="https://vault.example.com:8200",
        token="hvs.xxxxx",
        key_name="my-solana-key",
        public_key="base58_public_key",
    )
)
```

### AWS KMS

`key_id` adalah ID kunci, ARN, atau alias untuk kunci `ECC_NIST_EDWARDS25519`. Berikan
`client` KMS boto3 yang sudah dibuat untuk kredensial atau endpoint kustom; `region`
lalu diabaikan:

```python
from solana_keychain.aws_kms import AwsKmsSignerConfig, create_aws_kms_signer

signer = await create_aws_kms_signer(
    AwsKmsSignerConfig(
        key_id="alias/my-solana-key",
        public_key="base58_public_key",
        region="us-east-1",  # optional, defaults to the AWS config chain
    )
)
```

### GCP KMS

### Crossmint

```python
from solana_keychain.crossmint import CrossmintSignerConfig, create_crossmint_signer

signer = await create_crossmint_signer(
    CrossmintSignerConfig(
        api_key="api_key",
        wallet_locator="wallet_locator",
    )
)

signature = await signer.sign_and_send_transaction(transaction)
```

Crossmint hanya untuk pengiriman. API-nya selalu mengeksekusi transaksi yang disetujui
di sisi server dan menanggung gas, sehingga `CrossmintSigner` adalah `SendingSigner` dan
`sign_message` memunculkan `SIGNING_FAILED`. Signature yang dikembalikan mengidentifikasi
transaksi yang diproses Crossmint, yang mungkin berbeda dari transaksi Anda. Mengatur
`signer_secret` (secret delegated-signer `xmsk1_...`) akan menyetujui transaksi
secara otomatis, yang berarti menyerahkan pilihan tentang apa yang disetujui kepada Crossmint.

### Fordefi

Fordefi memiliki tiga mode penandatanganan, yang ditetapkan saat konstruksi oleh `chain` dan
`push_mode`. `create_fordefi_signer` memilih kelasnya, setiap kelas menolak
konfigurasi yang ditujukan untuk kelas lain, dan ketiganya menandatangani pesan:

| Mode          | Konfigurasi                                     | Kelas                       | Metode                        |
| ------------- | ------------------------------------------ | --------------------------- | ----------------------------- |
| Black box     | `chain` tidak diatur                              | `FordefiBlackBoxSigner`     | `sign_transaction`            |
| Native auto   | `chain` diatur, `push_mode` tidak diatur atau `"auto"` | `FordefiNativeAutoSigner`   | `sign_and_send_transaction`   |
| Native manual | `chain` diatur, `push_mode="manual"`          | `FordefiNativeManualSigner` | `modify_and_sign_transaction` |

Permintaan API diautentikasi dengan tanda tangan permintaan ECDSA P-256: berikan
kunci sebagai `private_key_pem`, atau simpan di KMS/HSM dengan meneruskan subkelas
`FordefiRequestSigner` sebagai `request_signer`.

**Mode native auto**: atur `chain` (`"solana_devnet"` atau `"solana_mainnet"`), dan
Fordefi dapat mengganti blockhash dan biaya, lalu menandatangani dan menyiarkan
transaksi itu sendiri. Mode ini hanya menerima transaksi yang belum ditandatangani dengan satu-satunya
penandatangan yang diperlukan adalah vault. `fee` diteruskan apa adanya ke Fordefi:

```python
import os

from solana_keychain.fordefi import FordefiSignerConfig, create_fordefi_signer

signer = await create_fordefi_signer(
    FordefiSignerConfig(
        access_token=os.environ["FORDEFI_ACCESS_TOKEN"],
        vault_id=os.environ["FORDEFI_VAULT_ID"],
        public_key=os.environ["FORDEFI_PUBLIC_KEY"],  # vault address (base58)
        private_key_pem=open("./secret/private.pem").read(),
        chain="solana_devnet",
        fee={"type": "custom", "priority_fee": "1000"},  # optional
    )
)

signature = await signer.sign_and_send_transaction(transaction)
```

**Mode native manual**: atur `chain` dan `push_mode="manual"`. Fordefi menulis ulang
pesan (recent blockhash, instruksi biaya Compute Budget) dan menandatanganinya,
tetapi tidak menyiarkannya. Transaksi yang dikembalikan menggantikan transaksi yang Anda kirim,
jadi selalu lanjutkan dari `result.transaction`. Fordefi harus menjadi fee payer dan
harus menandatangani sebelum penandatangan lain yang diperlukan: transaksi yang sudah memuat
tanda tangan tetap diterima, tetapi penulisan ulang membatalkannya. Penulisan ulang tidak di-diff,
jadi periksa hasilnya sebelum menyiarkan, dan siarkan dengan segera, karena Fordefi
tidak mengembalikan tinggi kedaluwarsa blockhash yang baru.

```python
signer = await create_fordefi_signer(
    FordefiSignerConfig(
        access_token=os.environ["FORDEFI_ACCESS_TOKEN"],
        vault_id=os.environ["FORDEFI_VAULT_ID"],
        public_key=os.environ["FORDEFI_PUBLIC_KEY"],
        private_key_pem=open("./secret/private.pem").read(),
        chain="solana_devnet",
        push_mode="manual",
    )
)

result = await signer.modify_and_sign_transaction(transaction)
...  # inspect result.transaction, then add any remaining signatures
```

Siarkan transaksi yang telah diperiksa seperti pada [Tanda Tangan dan Kirim](#sign-and-send), dan
lakukan rekonsiliasi sebelum mencoba ulang jika pengiriman gagal.

**Mode black box**: hilangkan `chain`. Fordefi menandatangani byte pesan Anda persis apa adanya dan
tidak menyiarkannya. Gunakan ini dengan vault black box Fordefi.

```python
signer = await create_fordefi_signer(
    FordefiSignerConfig(
        access_token=os.environ["FORDEFI_ACCESS_TOKEN"],
        vault_id=os.environ["FORDEFI_BB_VAULT_ID"],
        public_key=os.environ["FORDEFI_BB_PUBLIC_KEY"],
        private_key_pem=open("./secret/private.pem").read(),
    )
)
```

## Tanda Tangan dan Kirim

`sign_and_send_transaction` memasukkan transaksi ke chain apa pun bentuk signer-nya.
`SendingSigner` menyiarkan melalui providernya dan fungsi kirim Anda
tidak pernah dipanggil. `TransactionSigner` atau `ModifyingSigner` menandatangani, dan fungsi kirim Anda
menyiarkan hasil yang dienkode base64 (paket ini tidak memiliki klien RPC):

```python
import httpx
from solana_keychain import sign_and_send_transaction
from solders.signature import Signature


async def send(encoded: str) -> Signature:
    async with httpx.AsyncClient() as client:
        response = await client.post(
            "https://api.devnet.solana.com",
            json={
                "jsonrpc": "2.0",
                "id": 1,
                "method": "sendTransaction",
                "params": [encoded, {"encoding": "base64"}],
            },
        )
    return Signature.from_string(response.json()["result"])


signature = await sign_and_send_transaction(signer, transaction, send)
```

Signer yang hanya menandatangani tanpa fungsi kirim akan memunculkan `CONFIG_ERROR`, dan
transaksi yang masih kekurangan tanda tangan setelah penandatanganan akan memunculkan `SIGNING_FAILED`.

## Penanganan Error

Setiap kegagalan adalah `SignerError` dengan `code` yang stabil dari `SignerErrorCode`:
`BROADCAST_UNCONFIRMED`, `CONFIG_ERROR`, `EXPECTED_SOLANA_SIGNER`, `HTTP_ERROR`,
`INVALID_PRIVATE_KEY`, `INVALID_PUBLIC_KEY`, `IO_ERROR`, `NOT_AVAILABLE`,
`NOT_INITIALIZED`, `OTHER`, `PARSING_ERROR`, `REMOTE_API_ERROR`,
`SERIALIZATION_ERROR`, dan `SIGNING_FAILED`. Cocokkan berdasarkan `code`, bukan pesannya:
`str()` dan `repr()` hanya memuat pesan generik tetap, tidak pernah materi kunci atau
respons mentah provider. `status_code` dan `provider_error_code` diatur ketika
kegagalan berasal dari respons provider.

`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`) berarti
transaksi mungkin sudah masuk:

- Pada Crossmint dan Fordefi native auto, `provider_transaction_id` diatur ketika
  pembuatan transaksi diterima, dan `idempotency_key` membawa kunci yang diturunkan dari
  pesan yang digunakan saat pembuatan dikirim. Mengirim ulang transaksi yang identik byte demi byte
  aman dilakukan; transaksi yang dibangun ulang (misalnya dengan blockhash baru) merupakan transfer
  baru.
- Dari `sign_and_send_transaction`, fungsi kirim yang gagal memunculkannya dengan
  `transaction_signature` diatur ke tanda tangan transaksi yang telah selesai.
- Fireblocks memunculkannya hanya jika polling menunjukkan Fireblocks menyiarkan
  transaksi `use_program_call` meskipun dikirim hanya untuk penandatanganan.

```python
from solana_keychain import SignerError, SignerErrorCode

try:
    signature = await sign_and_send_transaction(signer, transaction, send)
except SignerError as error:
    if error.code is SignerErrorCode.BROADCAST_UNCONFIRMED:
        reconcile(
            error.provider_transaction_id,
            error.idempotency_key,
            error.transaction_signature,
        )
    raise
```

Panggilan yang dibatalkan memunculkan kembali `asyncio.CancelledError`, yang tidak membawa field apa pun. Untuk
memulihkan id yang diterima provider sebelum pembatalan, teruskan
`PendingTransactionId()` (dari `solana_keychain.core`) sebagai `pending_transaction_id` pada konfigurasi native auto Crossmint atau
Fordefi, lalu baca `.get()` setelah
pembatalan. Lakukan rekonsiliasi dengan provider sebelum mencoba ulang.

Keychain memvalidasi tahap penandatanganan, bukan apa yang dilakukan transaksi: tanda tangan
yang dikembalikan provider diverifikasi ed25519 terhadap pesan yang dihitung secara lokal
sebelum dilampirkan. Python tidak dapat menghapus buffer kunci dengan nol, jadi dengan
backend kunci lokal (Memory, serta API key dan PEM yang disimpan dalam konfigurasi backend jarak jauh),
anggap seluruh memori proses bersifat sensitif. Lihat
[model keamanan](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md)
untuk jaminan yang diberikan setiap bentuk penandatanganan.

## Menambahkan Signer Kustom

Buat subclass dari satu kelas kapabilitas yang sesuai dengan backend Anda (`TransactionSigner`,
`ModifyingSigner`, atau `SendingSigner`) dari `solana_keychain.core`. Lihat
[panduan Adding Signers](/docs/tools/keychain/adding-signers) untuk mengintegrasikan
layanan manajemen kunci tambahan.
