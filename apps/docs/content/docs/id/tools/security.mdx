## Manajemen Kunci

- **Jangan pernah mengekspos private key di kode frontend.** Gunakan penandatanganan di backend, hardware
  wallet, wallet multisignature, atau layanan manajemen kunci.
- **Pisahkan hot wallet dan cold wallet.** Hot wallet untuk operasional, cold wallet untuk
  treasury.
- **Cadangkan semua kunci produksi.** Simpan cadangan terenkripsi di beberapa lokasi
  yang aman. Kehilangan kunci berarti kehilangan akses secara permanen.
- **Gunakan kunci yang berbeda untuk devnet dan mainnet.** Kunci devnet Anda tidak boleh
  menjadi kunci mainnet Anda. Gunakan konfigurasi berbasis environment untuk memastikan kunci yang tepat
  dimuat untuk setiap jaringan.

## Infrastruktur Penandatanganan

Untuk penandatanganan backend di lingkungan produksi, gunakan [Keychain](/docs/tools/keychain)—library
penandatanganan terpadu yang mengabstraksikan berbagai backend manajemen kunci melalui satu
antarmuka: Memory, Vault, Privy, Turnkey, AWS KMS, Fireblocks, GCP KMS, CDP,
Para, Dfns, Crossmint, Openfort, dan Utila. Dengan begitu, Anda dapat mengembangkan secara lokal dengan
kunci in-memory, lalu beralih ke backend tingkat produksi tanpa mengubah
kode aplikasi.

Tidak yakin backend mana yang cocok? Lihat
[Memilih backend](/docs/tools/keychain/choosing-a-backend). Keychain tersedia
untuk [Rust](https://crates.io/crates/solana-keychain) dan
[TypeScript](https://www.npmjs.com/package/@solana/keychain).

## Keamanan RPC

Perlakukan endpoint RPC seperti API key—jangan mengeksposnya di kode frontend karena
dapat diekstrak dan disalahgunakan. Gunakan proxy backend atau environment variable yang
tidak dibundel ke dalam kode klien.

- [QuickNode: Praktik Terbaik Keamanan Endpoint](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: Lindungi API Key Solana Anda: Praktik Terbaik Keamanan](https://www.helius.dev/docs/rpc/protect-your-keys)

## Pemantauan

Lacak metrik berikut di lingkungan produksi:

| Metrik                   | Alasan                    |
| ------------------------ | ---------------------- |
| Tingkat keberhasilan transaksi | Mendeteksi masalah sejak dini    |
| Latensi konfirmasi     | Memantau kesehatan jaringan |
| Pengeluaran priority fee       | Manajemen biaya        |
| Tingkat error RPC           | Kesehatan provider        |

Siapkan peringatan untuk:

- Transfer di atas ambang batas dari treasury
- Lonjakan tingkat transaksi yang gagal
- Pola penerima yang tidak biasa
- Peningkatan tingkat error RPC

Untuk pemantauan transaksi real-time dalam skala besar, lihat
[Panduan Indexing](/docs/payments/accept-payments/indexing) kami.

## Verifikasi Alamat

Setiap token dan program hanya memiliki satu alamat yang benar di mainnet. Token palsu
yang meniru USDC atau stablecoin lainnya sering ditemukan—token tersebut memiliki nama
dan simbol yang sama, tetapi mint yang berbeda. Aplikasi Anda sebaiknya melakukan hardcode atau allowlist
pada alamat mint (sesuai kebutuhan Anda), dan jangan pernah menerimanya secara dinamis
dari sumber yang tidak tepercaya.

**Konfigurasi berbasis environment:** Devnet dan Mainnet sering kali menggunakan mint token
yang sama sekali berbeda. Siapkan konfigurasi aplikasi Anda untuk memuat alamat yang benar
untuk setiap environment—jangan melakukan hardcode alamat mainnet lalu lupa menggantinya
saat pengujian, atau lebih buruk lagi, mengirimkan alamat devnet ke produksi.

Beberapa mint stablecoin yang umum adalah:

| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

Alamat program juga penting. Mengirim instruksi ke program yang salah akan
gagal—atau lebih buruk lagi, mengakibatkan kehilangan dana yang tidak dapat dipulihkan. Alamat Token Program
adalah:

| Program            | Alamat                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Program | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

Menambahkan alamat yang tepat ke allowlist melindungi dari token palsu, tetapi tidak
melindungi dari pengiriman ke _jenis_ akun yang salah. Alamat penerima
dapat berupa wallet, token account, mint, atau program, dan masing-masing memerlukan
penanganan yang berbeda. SOL native yang dikirim ke selain wallet akan lepas dari kendali
pengirim — hilang sepenuhnya jika dikirim ke mint atau program, dan hanya dapat dipulihkan oleh
pemilik akun jika dikirim ke token account — tanpa ada transaksi gagal yang memperingatkan pengguna.

<Callout type="warn" title="Validasi penerima sebelum mengirim">
  Klasifikasikan setiap alamat penerima sebelum menandatangani transfer. Lihat [Verify
  Address](/docs/payments/send-payments/verify-address) untuk pohon keputusan lengkap
  dan kode referensi yang membedakan wallet, token account, mint, dan
  program.
</Callout>
