Antarmuka baris perintah `spl-token` digunakan untuk membuat dan mengelola mint, token
account, authority, transfer, dan ekstensi Token-2022.

Referensi ini mengikuti
[`spl-token-cli` v5.6.1](https://github.com/solana-program/token-2022/releases/tag/cli%40v5.6.1),
yaitu versi yang dibundel dengan Agave v4.2.1. Jalankan `spl-token --version` dan gunakan
`<command> --help` untuk melihat opsi yang tersedia di versi yang Anda instal.

<Callout type="warn">
  Pembuatan mint, transfer, perubahan authority, burn, freeze, dan penutupan
  akun akan mengirimkan transaksi. Pastikan cluster, token program, penanda tangan, dan
  alamat sudah benar sebelum menjalankan perintah. Perubahan di Mainnet menggunakan aset sungguhan.
</Callout>

## Instal dan dapatkan bantuan

Paket rilis Agave CLI sudah menyertakan `spl-token`. Jika belum terinstal, gunakan
crate Rust yang dipublikasikan:

```shell
cargo install spl-token-cli --version 5.6.1
spl-token --version
```

Lihat bantuan di tingkat root atau tingkat perintah:

```shell
spl-token --help
spl-token create-token --help
spl-token transfer --help
```

## Opsi global

Letakkan opsi global sebelum perintah.

| Opsi                                       | Fungsi                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `-u, --url <URL_OR_MONIKER>`                 | Pilih URL RPC atau `mainnet-beta`, `testnet`, `devnet`, atau `localhost`. |
| `-C, --config <PATH>`                        | Gunakan file konfigurasi Solana CLI yang berbeda.                            |
| `--fee-payer <KEYPAIR>`                      | Pilih akun yang membayar biaya transaksi.                            |
| `-p, --program-id <ADDRESS>`                 | Gunakan ID Token Program secara eksplisit.                                         |
| `--program-2022`                             | Gunakan Token-2022 (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`).           |
| `--output <FORMAT>`                          | Menampilkan `json` atau `json-compact` jika didukung.                          |
| `--with-compute-unit-limit <UNITS>`          | Atur batas compute unit transaksi.                                   |
| `--with-compute-unit-price <MICRO_LAMPORTS>` | Atur harga prioritas per compute unit.                                  |
| `-v, --verbose`                              | Tampilkan output tambahan.                                                   |
| `-V, --version`                              | Cetak versi CLI yang terinstal.                                          |

Program default adalah Token Program asli. Gunakan `--program-2022` untuk
mint atau akun Token-2022, termasuk saat membacanya. Perintah akan gagal jika
program yang dipilih bukan pemilik alamat yang diberikan.

## Membuat dan menggunakan token

Perintah-perintah ini mencetak alamat yang dibuat. Simpan alamat mint yang dikembalikan oleh
`create-token` untuk perintah-perintah berikutnya.

```shell
# Create a six-decimal mint under the original Token Program.
spl-token --url devnet create-token --decimals 6

# Create the default signer's associated token account for the mint.
spl-token --url devnet create-account <MINT_ADDRESS>

# Mint 100 tokens to that associated token account.
spl-token --url devnet mint <MINT_ADDRESS> 100

# Read supply, balance, and complete mint or account details.
spl-token --url devnet supply <MINT_ADDRESS>
spl-token --url devnet balance <MINT_ADDRESS>
spl-token --url devnet display <MINT_OR_TOKEN_ACCOUNT_ADDRESS>

# Transfer tokens to a wallet and create its associated account if needed.
spl-token --url devnet transfer \
  <MINT_ADDRESS> \
  10 \
  <RECIPIENT_WALLET_ADDRESS> \
  --fund-recipient
```

Jumlah yang digunakan adalah jumlah token UI, yang disesuaikan dengan desimal mint. Perintah seperti
`transfer`, `burn`, dan `unwrap-sol` menerima `ALL` jika ditampilkan dalam bantuannya.

## Membuat mint Token-2022

Ekstensi mengalokasikan state mint atau akun tambahan dan biasanya harus dipilih saat
mint dibuat. Contoh ini membuat mint dengan enam desimal dan dukungan
metadata tertanam:

```shell
spl-token --program-2022 create-token \
  --decimals 6 \
  --enable-metadata

spl-token --program-2022 initialize-metadata \
  <MINT_ADDRESS> \
  "Example Token" \
  EXAMPLE \
  https://example.com/token.json
```

Opsi ekstensi `create-token` yang umum meliputi:

- `--enable-close`
- `--enable-confidential-transfers auto|manual`
- `--enable-freeze`
- `--enable-group` dan `--enable-member`
- `--enable-metadata`
- `--enable-non-transferable`
- `--enable-pause`
- `--enable-permanent-delegate`
- `--enable-permissioned-burn`
- `--enable-transfer-hook` atau `--transfer-hook <PROGRAM_ID>`
- `--interest-rate <BASIS_POINTS>`
- `--transfer-fee-basis-points <BASIS_POINTS>` bersama
  `--transfer-fee-maximum-fee <AMOUNT>`
- `--ui-amount-multiplier <MULTIPLIER>`

Hanya gabungkan ekstensi yang diizinkan digunakan bersamaan oleh program Token-2022. Tinjau
[panduan ekstensi Token-2022](/docs/tokens/extensions) yang relevan sebelum membuat
konfigurasi mint yang tidak dapat dibatalkan.

## Mengelola authority dan delegate

```shell
# Change the mint authority.
spl-token authorize <MINT_ADDRESS> mint <NEW_AUTHORITY_ADDRESS>

# Permanently remove the mint authority.
spl-token authorize <MINT_ADDRESS> mint --disable

# Let a delegate spend up to 25 tokens from one token account.
spl-token approve \
  <TOKEN_ACCOUNT_ADDRESS> \
  25 \
  <DELEGATE_ADDRESS>

# Remove the current delegate.
spl-token revoke <TOKEN_ACCOUNT_ADDRESS>
```

`authorize` mendukung tipe authority mint, freeze, owner, close, dan yang khusus ekstensi.
Menghapus authority dengan `--disable` bersifat permanen jika tidak ada
mekanisme program lain yang dapat memulihkannya.

## Freeze, burn, dan close

```shell
spl-token freeze <TOKEN_ACCOUNT_ADDRESS>
spl-token thaw <TOKEN_ACCOUNT_ADDRESS>

spl-token burn <TOKEN_ACCOUNT_ADDRESS> 5

# A token account must normally have a zero token balance before closing.
spl-token close --address <TOKEN_ACCOUNT_ADDRESS>
```

`burn` mengurangi saldo akun sekaligus total suplai. `close` mengembalikan
lamport yang tersisa di akun ke penerima yang dikonfigurasi; perintah ini tidak memulihkan
token yang telah di-burn.

## Wrap dan unwrap SOL

```shell
# Create or fund the owner's wrapped SOL token account.
spl-token wrap 1

# Unwrap part of the wrapped SOL balance.
spl-token unwrap-sol 0.25

# Close the wrapped SOL account and return its full lamport balance.
spl-token unwrap
```

Gunakan `sync-native` setelah mentransfer lamport langsung ke wrapped SOL token
account agar jumlah token-nya sesuai dengan lamport yang mendasarinya.

## Penandatanganan multisig

Buat multisig Token Program M-of-N dengan hingga 11 anggota:

```shell
spl-token create-multisig \
  2 \
  <MEMBER_1_ADDRESS> \
  <MEMBER_2_ADDRESS> \
  <MEMBER_3_ADDRESS>
```

Untuk transaksi yang dikendalikan oleh multisig tersebut, berikan alamat multisig sebagai
authority yang relevan dan sediakan keypair anggota melalui nilai
`--multisig-signer` yang diulang. Periksa bantuan perintah yang dituju karena flag
authority utamanya berbeda-beda tergantung operasinya.

## Saldo rahasia

Perintah saldo rahasia memerlukan mint Token-2022 yang dikonfigurasi untuk
transfer rahasia dan akun penerima yang sudah dikonfigurasi.

```shell
spl-token --program-2022 configure-confidential-transfer-account \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 deposit-confidential-tokens \
  <MINT_ADDRESS> \
  10 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 apply-pending-balance \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 withdraw-confidential-tokens \
  <MINT_ADDRESS> \
  5 \
  --address <TOKEN_ACCOUNT_ADDRESS>

spl-token --program-2022 transfer \
  <MINT_ADDRESS> \
  1 \
  <RECIPIENT_ADDRESS> \
  --confidential
```

Untuk `configure-confidential-transfer-account` dan `apply-pending-balance`, berikan
salah satu dari `--address <TOKEN_ACCOUNT_ADDRESS>` atau `<MINT_ADDRESS>` posisional, jangan
keduanya. Bentuk posisional menggunakan associated token account milik pemilik. Deposit dan
penarikan selalu menggunakan mint dan menerima `--address` untuk mengganti akun
default tersebut.

Gunakan `enable-confidential-credits`, `disable-confidential-credits`,
`enable-non-confidential-credits`, dan `disable-non-confidential-credits` untuk
mengatur deposit mana yang diterima akun. Pengaturan ini memengaruhi privasi akun
dan kompatibilitas pembayaran; periksa akun sebelum mengubahnya.

| `bench`                                   | Jalankan perintah benchmark token.                                              |
| `burn`                                    | Hancurkan token dari sebuah akun dan kurangi suplai mint.                        |
| `close`                                   | Tutup token account yang memenuhi syarat dan pulihkan lamport-nya.                     |
| `close-mint`                              | Tutup mint Token-2022 yang dikonfigurasi dengan ekstensi close-mint.             |
| `configure-confidential-transfer-account` | Konfigurasikan akun untuk menggunakan transfer rahasia.                           |
| `create-account`                          | Buat token account asosiasi atau tambahan.                              |
| `create-multisig`                         | Buat multisig Token Program M-of-N.                                      |

## Penandatanganan terstruktur dan offline

Gunakan output terstruktur daripada mengurai teks tampilan:

```shell
spl-token accounts --output json
spl-token display <MINT_ADDRESS> --output json-compact
```

Perintah yang menghasilkan transaksi umumnya mendukung `--sign-only`, `--blockhash`,
`--signer <PUBKEY=SIGNATURE>`, `--nonce`, dan `--nonce-authority`. Input
offline yang tepat bergantung pada perintah, desimal mint, dan susunan authority,
jadi hasilkan pesan yang belum ditandatangani sesuai petunjuk `--help` perintah tersebut dan
verifikasi setiap alamat sebelum mengumpulkan tanda tangan.
