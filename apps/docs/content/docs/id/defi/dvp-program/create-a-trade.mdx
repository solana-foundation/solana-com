`CreateDvp` mencatat ketentuan sebuah trade dan membuat dua akun escrow yang
akan didanai oleh para pihak. Instruksi ini tidak memindahkan token. Siapa pun dapat mengirimnya, sehingga catatan tersebut
bisa berasal dari counterparty, operator otoritas penyelesaian, atau pihak ketiga,
dan setiap peserta lain memverifikasi ketentuan yang tersimpan sebelum bertindak berdasarkan ketentuan itu (lihat
[mendanai leg](/docs/defi/dvp-program/fund-the-legs)).

Cuplikan kode menggunakan klien yang dihasilkan secara langsung, dengan alamat placeholder, sehingga
akun dan penanda tangan yang terlibat terlihat jelas. Cuplikan ini menargetkan devnet, tempat
program di-deploy pada alamat yang sama dengan mainnet-beta.

## Instalasi

Per 2 Oktober 2026, belum ada paket yang dipublikasikan untuk klien DvP. Keduanya
dihasilkan dari IDL program di repositori dan digunakan dari source.

Halaman-halaman ini ditulis berdasarkan commit `df9919e`, dengan `@solana/kit` 8 di
TypeScript dan crate `solana-*` 2.x di Rust.

Cuplikan kode di setiap halaman langkah saling berlanjut: setiap halaman menggunakan klien, penanda tangan,
dan alamat yang didefinisikan di halaman sebelumnya. `payerSigner`, `userASigner`,
`userBSigner`, dan `authoritySigner` adalah `TransactionSigner` untuk pembayar
rent, kedua pihak, dan otoritas penyelesaian, misalnya dari
`createKeyPairSignerFromBytes`. Cuplikan Rust membangun instruksi dan menyerahkan
penandatanganan serta pengiriman kepada pemanggil.

## Menurunkan alamat

Catatan trade adalah Program Derived Address yang diturunkan dari otoritas penyelesaian,
kedua pihak, kedua mint, dan sebuah nonce. Setiap escrow adalah associated token account
milik catatan tersebut untuk salah satu mint. Kedua penurunan ini tidak memerlukan akses jaringan.

Gunakan nonce 64-bit acak untuk setiap trade. Karena pembuatan bersifat permissionless, nonce yang
dapat ditebak memungkinkan pihak ketiga menempati alamat yang seharusnya
digunakan oleh trade. Berikan nonce dan jumlahnya sebagai `bigint` di TypeScript; klien
yang dihasilkan akan menolak `number`.

Ganti setiap placeholder `..._HERE` dengan alamat asli sebelum menjalankan kode.
`address()` memvalidasi base58 dan melempar error pada placeholder, sedangkan `pubkey!` gagal
dikompilasi.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

  </Tab>

## Mencatat ketentuan

`CreateDvp` menerima dua jumlah dalam satuan dasar, waktu kedaluwarsa, nonce, dan empat
bidang opsional: referensi opak hingga 64 byte, tujuan penyelesaian
untuk masing-masing pihak, dan waktu penyelesaian paling awal (lihat Catatan). Tujuan tersebut adalah
tempat hasil milik pihak itu diterima saat penyelesaian, misalnya dompet deposit
kustodian; secara default tujuannya adalah alamat pihak itu sendiri dan tidak dapat diubah setelah
catatan dibuat. Pengembalian dana dan klaim ulang selalu masuk ke token account milik pihak tersebut
untuk mint leg itu, tidak pernah ke tujuan penyelesaian, siapa pun yang mendanai escrow.

Pembayar mendanai rent untuk catatan, tombstone nonce, dan kedua escrow.
Saat penutupan, rent tersebut diberikan kepada siapa pun yang menandatangani instruksi penutupan, bukan dikembalikan ke
pembayar. Tombstone tidak pernah ditutup, sehingga setiap trade meninggalkan saldo permanen
yang kecil. Saat menganggarkan SOL pembayar, turunkan jumlah rent dengan metode RPC
`getMinimumBalanceForRentExemption` alih-alih menuliskannya secara hardcode.

Cuplikan TypeScript memerlukan `getProgramDerivedAddress` dan `getAddressEncoder`
dari `@solana/kit`, serta `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS` dari klien, dalam
scope. Builder Rust membiarkan system program dan associated token program
pada nilai defaultnya.

## Catatan

- **Kedaluwarsa.** Hanya Settle yang memeriksa waktu kedaluwarsa. Reclaim, Cancel, dan Reject tetap berfungsi
  setelahnya, dan deposit yang masuk setelah kedaluwarsa dapat dipulihkan oleh
  pihak pemilik leg tersebut. Waktu kedaluwarsa paling lama satu tahun setelah pembuatan.
- **Waktu adalah waktu jaringan.** Program membaca jam onchain, yang dapat
  berbeda dari waktu jam dinding, kadang hingga puluhan detik, dan dapat melompat
  maju. Sisakan jarak antara waktu kedaluwarsa dan waktu penyelesaian yang dituju,
  hindari mendanai atau menyelesaikan mendekati salah satu batas, dan jangan mengandalkan waktu kedaluwarsa
  untuk menegakkan tenggat hingga hitungan detik. README program menyarankan menganggarkan
  sekitar satu menit untuk selisih waktu.
- **Penyelesaian paling awal.** Opsional. Jika diatur, Settle akan ditolak sebelum waktu tersebut, dan
  waktunya tidak boleh lebih lambat dari waktu kedaluwarsa.
- **Pemeriksaan saat pembuatan.** Create gagal dengan `PartyNotSignerCapable` jika salah satu pihak
  bukan akun milik system program (ini mengecualikan multisig SPL Token),
  `SettlementDestinationIsSwapDvp`, `SelfDvp`, `SameMint`, `ZeroAmount`,
  `SettlementAuthorityIsParty`, atau `ExpiryNotInFuture`. Daftar lengkapnya ada di
  [tabel error](/docs/defi/dvp-program#errors).
