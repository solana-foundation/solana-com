`CreateDvp` mencatat ketentuan sebuah trade dan membuat dua akun escrow yang
akan didanai oleh para pihak. Instruksi ini tidak memindahkan token apa pun.
Siapa pun dapat mengirimnya, sehingga record bisa berasal dari counterparty,
operator settlement authority, atau pihak ketiga, dan setiap peserta lainnya
memverifikasi ketentuan yang tersimpan sebelum bertindak berdasarkan ketentuan
tersebut (lihat [danai leg](/docs/defi/dvp-program/fund-the-legs)).

Cuplikan kode menggunakan klien yang dihasilkan secara langsung, dengan alamat
placeholder, sehingga akun dan signer yang terlibat terlihat jelas. Cuplikan ini
menargetkan devnet, tempat program di-deploy pada alamat yang sama dengan
mainnet-beta.

## Instalasi

Per 2 Oktober 2026, belum ada paket yang dipublikasikan untuk klien DvP. Kedua
klien dihasilkan dari IDL program di repositori dan digunakan langsung dari
source.

Cuplikan kode di setiap halaman langkah saling berkelanjutan: setiap halaman
menggunakan klien, signer, dan alamat yang didefinisikan di halaman sebelumnya.
`payerSigner`, `userASigner`, `userBSigner`, dan `authoritySigner` adalah
`TransactionSigner` untuk pembayar rent, kedua pihak, dan settlement authority,
misalnya dari `createKeyPairSignerFromBytes`. Cuplikan Rust membangun instruksi
dan menyerahkan proses penandatanganan serta pengiriman kepada pemanggil.

## Menurunkan alamat

Record trade adalah program-derived address yang diturunkan dari settlement
authority, kedua pihak, kedua mint, dan sebuah nonce. Setiap escrow adalah
associated token account milik record untuk salah satu mint. Kedua penurunan
tersebut tidak memerlukan akses jaringan.

Gunakan nonce acak 64-bit untuk setiap trade. Karena pembuatan trade tidak
memerlukan izin, nonce yang dapat ditebak memungkinkan pihak ketiga menempati
alamat yang seharusnya digunakan sebuah trade. Teruskan nonce dan jumlah sebagai
`bigint` di TypeScript; klien yang dihasilkan akan menolak `number`.

Ganti setiap placeholder `..._HERE` dengan alamat yang sebenarnya sebelum
menjalankan kode. `address()` memvalidasi base58 dan melempar error pada
placeholder, sedangkan `pubkey!` gagal dikompilasi.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { address, createClient } from "@solana/kit";
    import { solanaRpc } from "@solana/kit-plugin-rpc";
    import { signer } from "@solana/kit-plugin-signer";
    import { TOKEN_2022_PROGRAM_ADDRESS } from "@solana-program/token-2022";
    import { findSwapDvpEscrowAta, findSwapDvpPda } from "./dvp";

    const client = createClient()
      .use(signer(payerSigner))
      .use(
        solanaRpc({
          rpcUrl: "https://api.devnet.solana.com",
          rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
        }),
      );

    const settlementAuthority = address("SETTLEMENT_AUTHORITY_ADDRESS_HERE");
    const userA = address("ASSET_LEG_PARTY_ADDRESS_HERE");
    const userB = address("CASH_LEG_PARTY_ADDRESS_HERE");
    const mintA = address("ASSET_MINT_ADDRESS_HERE");
    const mintB = address("CASH_MINT_ADDRESS_HERE");
    const tokenProgramA = TOKEN_2022_PROGRAM_ADDRESS;
    const tokenProgramB = TOKEN_2022_PROGRAM_ADDRESS;

    // A fresh random nonce per trade, as a bigint.
    const nonce = new DataView(
      crypto.getRandomValues(new Uint8Array(8)).buffer,
    ).getBigUint64(0);

    const [swapDvp] = await findSwapDvpPda({
      settlementAuthority,
      userA,
      userB,
      mintA,
      mintB,
      nonce,
    });
    const [escrowA] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintA,
      tokenProgram: tokenProgramA,
    });
    const [escrowB] = await findSwapDvpEscrowAta({
      swapDvp,
      mint: mintB,
      tokenProgram: tokenProgramB,
    });
    ```

## Mencatat ketentuan

`CreateDvp` menerima dua jumlah dalam satuan dasar, sebuah expiry, nonce, dan
empat field opsional: referensi buram (opaque) hingga 64 byte, tujuan settlement
untuk masing-masing sisi, dan waktu settlement paling awal (lihat Catatan).
Tujuan settlement adalah tempat hasil milik pihak tersebut diterima saat
settlement, misalnya dompet deposit milik custodian; nilai defaultnya adalah
alamat pihak itu sendiri dan tidak dapat diubah setelah record dibuat. Refund
dan reclaim selalu masuk ke token account milik pihak tersebut untuk mint leg
itu, tidak pernah ke tujuan settlement, siapa pun yang mendanai escrow.

Payer mendanai rent untuk record, tombstone nonce, dan kedua escrow. Saat
close, rent tersebut diberikan kepada siapa pun yang menandatangani instruksi
penutupan, bukan dikembalikan ke payer. Tombstone tidak pernah ditutup, sehingga
setiap trade meninggalkan saldo permanen yang kecil. Saat menganggarkan SOL
untuk payer, turunkan jumlah rent dengan metode RPC
`getMinimumBalanceForRentExemption` alih-alih menuliskannya secara hardcode.

Cuplikan TypeScript memerlukan `getProgramDerivedAddress` dan
`getAddressEncoder` dari `@solana/kit`, serta `DVP_SWAP_PROGRAM_PROGRAM_ADDRESS`
dari klien, yang harus tersedia dalam scope. Builder Rust membiarkan system
program dan associated token program pada nilai defaultnya.

## Catatan

- **Expiry.** Hanya Settle yang memeriksa expiry. Reclaim, Cancel, dan Reject
  tetap berfungsi setelahnya, dan deposit yang masuk setelah expiry dapat
  dipulihkan oleh pihak pemilik leg tersebut. Expiry paling lama satu tahun
  setelah pembuatan.
- **Waktu adalah waktu jaringan.** Program membaca jam onchain, yang bisa berbeda
  dari waktu jam dinding, terkadang hingga puluhan detik, dan bisa melompat
  maju. Sisakan margin antara expiry dan waktu settlement yang dimaksud,
  hindari pendanaan atau settlement mendekati salah satu batas tersebut, dan
  jangan mengandalkan expiry untuk menegakkan tenggat hingga hitungan detik.
  README program menyarankan untuk menganggarkan sekitar satu menit untuk
  drift.
- **Settlement paling awal.** Opsional. Jika diatur, Settle ditolak sebelum
  waktu tersebut, dan waktunya tidak boleh lebih lambat dari expiry.
- **Pemeriksaan saat pembuatan.** Create gagal dengan `PartyNotSignerCapable`
  jika salah satu pihak bukan akun milik system (ini mengecualikan multisig SPL
  Token), `SettlementDestinationIsSwapDvp`, `SelfDvp`, `SameMint`, `ZeroAmount`,
  `SettlementAuthorityIsParty`, atau `ExpiryNotInFuture`. Daftar lengkapnya ada
  di [tabel error](/docs/defi/dvp-program#errors).
