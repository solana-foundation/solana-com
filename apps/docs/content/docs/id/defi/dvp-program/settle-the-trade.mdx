`SettleDvp` ditandatangani oleh otoritas settlement yang tercantum dalam catatan trade. Dalam
satu transaksi, instruksi ini memindahkan `amount_a` dari sisi aset ke tujuan pihak sisi kas
dan `amount_b` dari sisi kas ke tujuan pihak sisi aset,
mengembalikan kelebihan di escrow mana pun kepada pihak sisi tersebut, serta menutup catatan
dan kedua escrow. Jika salah satu transfer tersebut tidak dapat diselesaikan, instruksi
gagal dan tidak ada yang berpindah.

Halaman ini melanjutkan dari [membuat trade](/docs/defi/dvp-program/create-a-trade)
dan [mendanai kedua sisi](/docs/defi/dvp-program/fund-the-legs); client, signer,
`trade`, dan token account para pihak tetap digunakan.

## Validasi ulang sebelum menandatangani

Otoritas settlement menandatangani transaksi yang memindahkan kedua sisi, sehingga ia
melakukan pembacaan yang sama seperti tiap pihak sebelum menandatangani: owner, ukuran, pihak,
mint, jumlah, masa berlaku, dan kedua tujuan (lihat
[mendanai kedua sisi](/docs/defi/dvp-program/fund-the-legs#verify-the-terms)). Program itu sendiri memeriksa ulang saat settlement bahwa setiap mint masih milik token
program yang dicatat saat pembuatan, tidak memiliki ekstensi yang diblokir, dan memiliki
mint authority yang sama seperti saat trade dibuat, sehingga mint yang dibuat ulang dengan ekstensi
yang diblokir, token program yang berbeda, atau mint authority yang berbeda tidak dapat
di-settle.

## Membuat account penerima

Settle menulis ke empat token account yang tidak dibuat oleh program:

| Account                | Menerima                     | Owner                           |
| ---------------------- | ---------------------------- | ------------------------------- |
| `userADestinationAtaB` | Sisi kas (`amount_b`)    | `user_a_settlement_destination` |
| `userBDestinationAtaA` | Sisi aset (`amount_a`)   | `user_b_settlement_destination` |
| `userAAtaA`            | Kelebihan apa pun pada sisi aset | `user_a`                        |
| `userBAtaB`            | Kelebihan apa pun pada sisi kas  | `user_b`                        |

Account kelebihan hanya digunakan ketika sebuah escrow menyimpan lebih dari jumlah
yang disepakati, tetapi siapa pun yang memegang mint dapat menciptakan kelebihan dengan mengirim beberapa base
unit ke dalam escrow. Jika account pengembalian tidak ada, seluruh Settle
gagal, jadi buat keempatnya secara idempoten dalam transaksi yang sama.

    import {
      findAssociatedTokenPda,
      getCreateAssociatedTokenIdempotentInstruction,

    const destinationA = t.userASettlementDestination; // defaults to userA
    const destinationB = t.userBSettlementDestination; // defaults to userB

    const [userADestinationAtaB] = await findAssociatedTokenPda({
      mint: mintB,
      owner: destinationA,
      tokenProgram: tokenProgramB,
    });
    const [userBDestinationAtaA] = await findAssociatedTokenPda({
      mint: mintA,
      owner: destinationB,
      tokenProgram: tokenProgramA,
    });
    // userAAtaA and userBAtaB are from fund the legs.

    const createRecipientAccounts = [
      { ata: userADestinationAtaB, owner: destinationA, mint: mintB, tokenProgram: tokenProgramB },
      { ata: userBDestinationAtaA, owner: destinationB, mint: mintA, tokenProgram: tokenProgramA },
      { ata: userAAtaA, owner: userA, mint: mintA, tokenProgram: tokenProgramA },
      { ata: userBAtaB, owner: userB, mint: mintB, tokenProgram: tokenProgramB },
    ].map(({ ata, owner, mint, tokenProgram }) =>
      getCreateAssociatedTokenIdempotentInstruction({
        payer: authoritySigner,
        ata,
        owner,
        mint,
        tokenProgram,
      }),
    );

## Settle

`legAExtrasCount` memberi tahu program berapa banyak account yang ditambahkan setelah
daftar tetap yang termasuk dalam transfer hook sisi aset; sisanya untuk transfer
sisi kas. Untuk mint tanpa transfer hook, berikan nol dan jangan tambahkan apa pun. Program
account memo diwajibkan oleh instruksi dan hanya digunakan untuk tujuan
yang memerlukan memo.

<Tabs items={["TypeScript", "Rust"]}>
  <Tab value="TypeScript">
    ```ts
    import { MEMO_PROGRAM_ADDRESS } from "@solana-program/memo";
    import { getSettleDvpInstruction } from "./dvp";

    const settleInstruction = getSettleDvpInstruction({
      settlementAuthority: authoritySigner,
      swapDvp,
      mintA,
      mintB,
      dvpAtaA: escrowA,
      dvpAtaB: escrowB,
      userADestinationAtaB,
      userBDestinationAtaA,
      userAAtaA,
      userBAtaB,
      tokenProgramA,
      tokenProgramB,
      memoProgram: MEMO_PROGRAM_ADDRESS,
      legAExtrasCount: 0,
    });

    const { context: settleContext } = await client.sendTransaction([
      ...createRecipientAccounts,
      settleInstruction,
    ]);
    const settleSignature = settleContext.signature;
    console.log("Submitted:", settleSignature);

    // sendTransaction returns at the client's commitment (confirmed by default).
    // Wait for finalized before recording the trade as settled.
    let finalized = false;
    for (let attempt = 0; attempt < 30 && !finalized; attempt++) {
      const {
        value: [status],
      } = await client.rpc.getSignatureStatuses([settleSignature]).send();
      if (status?.err) {
        throw new Error("Settle transaction failed");
      }
      finalized = status?.confirmationStatus === "finalized";
      if (!finalized) {
        await new Promise((resolve) => setTimeout(resolve, 2_000));
      }
    }
    if (!finalized) {
      // A closed record means it settled; an open one is safe to settle again.
      throw new Error("Settle not finalized after 60s; read the trade record");
    }
    console.log("Settled:", settleSignature);
    ```

### Transfer hook

IDL yang dihasilkan hanya mencantumkan account tetap, sehingga builder yang dihasilkan
tidak mengetahui account hook. Selesaikan extra account meta dari setiap hook mint dengan
cara yang sama seperti untuk transfer langsung token tersebut, lalu tambahkan ke
instruksi: account sisi aset terlebih dahulu, kemudian sisi kas, dengan
`legAExtrasCount` diatur ke jumlah pada kelompok pertama. Di TypeScript, sebarkan
meta yang sudah diselesaikan ke array `accounts` instruksi; di Rust, gunakan
`add_remaining_accounts` pada builder. Batasnya adalah 32 account per sisi,
termasuk program hook dan account validasi; batas account transaksi
dapat tercapai lebih dulu ketika kedua sisi memiliki hook. Program menghapus flag signer
dari setiap account yang diteruskan, sehingga sebuah hook tidak dapat memperoleh tanda tangan
otoritas settlement melalui jalur ini.

## Mencatat hasilnya

Anggap trade telah selesai ketika transaksi Settle mencapai `finalized`. Catatan
dan kedua escrow tidak ada lagi setelah settlement, sehingga sistem yang memerlukan
ketentuannya di kemudian hari menyimpannya dari pembacaan sebelum settlement atau dari
transaksi pembuatan. Dana rent dari account yang ditutup telah diberikan kepada otoritas
settlement.

## Error pada Settle

`LegNotFunded` berarti sebuah escrow menyimpan kurang dari jumlah yang disepakati; `DvpExpired`
dan `SettlementTooEarly` berarti jendela waktu terlewat; `MintAuthorityChanged`
dan `BlockedMintExtension` berarti sebuah mint berubah setelah pembuatan;
`RecipientAtaMismatch` berarti token account tujuan atau pengembalian tidak ada atau
tidak lagi dimiliki oleh owner dan mint yang diharapkan, biasanya karena langkah
pembuatan account di atas dilewati. Dalam setiap kasus, tidak ada yang berpindah, dan
para pihak dapat membatalkannya (unwind), sesuai dengan otoritas mint (lihat
[membatalkan trade](/docs/defi/dvp-program/unwind-a-trade)).

## Langkah berikutnya

- [Membatalkan trade](/docs/defi/dvp-program/unwind-a-trade): memulihkan sisi yang sudah
  didanai ketika trade tidak ter-settle
