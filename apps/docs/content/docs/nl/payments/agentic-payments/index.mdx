Met agentic-betalingen kan software in dezelfde HTTP-workflow een prijs ontdekken, een betaling autoriseren en een resource ontvangen. Een agent kan betalen voor een dataquery, modelinferentie of tool-aanroep zonder eerst een factureringsaccount aan te maken of een API-sleutel te kopiëren.

## De gemeenschappelijke betaalflow

MPP en x402 gebruiken verschillende headers en datamodellen, maar hun basis-HTTP-flow is vergelijkbaar:

```mermaid title="Agentic HTTP Payment Flow"
sequenceDiagram
    participant Agent
    participant Payer as Payment-aware client
    participant API as Resource server
    participant Solana
    Agent->>Payer: Request a paid resource
    Payer->>API: HTTP request
    API-->>Payer: 402 Payment Required + terms
    Note over Payer: Check price, asset, recipient, and policy
    Payer->>Payer: Ask the wallet to authorize and sign
    Payer->>API: Retry with payment authorization
    API->>Solana: Verify and settle, directly or through a facilitator
    Solana-->>API: Confirmed transaction
    API-->>Payer: Resource + payment receipt
    Payer-->>Agent: Return the result
```

## MPP en x402

Beide protocollen kunnen stablecoinbetalingen op Solana afwikkelen. Kies op basis van het betaalmodel en de interoperabiliteit die je service nodig heeft, en niet alleen op basis van de gedeelde statuscode `402`.

|                         | MPP                                                               | x402                                                                     |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Challenge               | `WWW-Authenticate: Payment`                                       | `PAYMENT-REQUIRED`                                                       |
| Autorisatie door de client    | `Authorization: Payment`                                          | `PAYMENT-SIGNATURE`                                                      |
| Ontvangstbewijs                 | `Payment-Receipt`                                                 | `PAYMENT-RESPONSE`                                                       |
| Solana-betaalmodellen   | Eenmalige `charge`-intents en `session`-intents met limiet en meting           | Schema's zoals `exact` en `upto`; ondersteuning verschilt per netwerk en client |
| Afwikkelingsarchitectuur | Servervalidatie, of een optionele relay of gateway                | Resourceserver met lokale verificatie of een facilitator                 |
| Goed startpunt     | API's die HTTP-authenticatiesemantiek of herhaalde metering nodig hebben | Resources met betaling per verzoek en bestaande x402-clients                      |

MPP staat voor **Machine Payments Protocol**. Verwar het niet met het **Model Context Protocol (MCP)**. MCP stelt tools en resources beschikbaar aan agents; MPP of x402 kan betaling vereisen wanneer een agent een van die tools aanroept.

<Callout type="info">
  Een service kan meer dan één protocol aanbieden. De client kiest een betaaloptie die hij ondersteunt en gebruikt vervolgens de bijbehorende challenge-, autorisatie- en receipt-headers voor de hele uitwisseling.
</Callout>
