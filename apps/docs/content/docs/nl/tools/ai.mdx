# Werken met LLM's en agents op Solana

Voordat we ingaan op specifieke tools, laten we de belangrijkste componenten in de AI-ontwikkelingsstack begrijpen:

## De AI-stack begrijpen

1. **Grote taalmodellen (LLM's)**
   - De fundamentele AI-modellen (zoals GPT-4, Claude of Llama)
   - Verwerken en genereren van natuurlijke taal
   - Bieden ruwe intelligentie en redeneervermogens
   - Voorbeelden: OpenAI's GPT-4, Anthropic's Claude, Meta's Llama

2. **Agentframeworks (zoals Eliza)**
   - Gebouwd bovenop LLM's om autonome agents te creëren
   - Beheren van agentpersoonlijkheden en -gedragingen
   - Geheugen en context beheren
   - Bieden integratie met meerdere platforms
   - Voorbeelden: Eliza, LangChain, AutoGPT, Vercel AI

3. **Domeinspecifieke agentkits (zoals Solana Agent Kit)**
   - Gebouwd voor specifieke gebruikssituaties (bijv. blockchain-operaties)
   - Bieden kant-en-klare tools en integraties
   - Abstractie van technische complexiteit
   - Gebruiksklare blockchain-functies
   - Voorbeelden: Solana Agent Kit, GOAT Toolkit

Zie het zo:

- LLM's zijn het "brein" dat taal kan begrijpen en genereren
- Agentframeworks zijn het "besturingssysteem" dat het gedrag van de AI beheert
- Domeinspecifieke kits zijn de "apps" die de AI specifieke mogelijkheden geven

# AI-agents bouwen voor Solana

Deze gids laat je zien hoe je:

- Een basis AI-agent bouwt met behulp van SendAI's Solana Agent Kit
- Een Twitter-bot maakt met het Eliza Framework
- Onchain AI-integratieopties begrijpt
- Opties voor het bouwen van geavanceerde handelsbots

## Inleiding tot AI-agents op Solana

AI-agents op Solana zijn autonome programma's die met de blockchain kunnen communiceren via natuurlijke taalverwerking en machine learning. Ze kunnen:

- Transacties uitvoeren
- Blockchain-activiteit monitoren
- Interactie met smart contracts
- Gebruikersondersteuning bieden
- Complexe workflows automatiseren

## Beschikbare frameworks

Er zijn verschillende frameworks beschikbaar voor het bouwen van AI-agents op Solana:

1. **SendAI's Solana Agent Kit**

- Een verzameling tools voor het bouwen van agents op Solana
- Compatibel met Eliza, Langchain en Vercel AI SDK
- Ingebouwde Solana-tools en -hulpprogramma's
- Mogelijkheden voor natuurlijke taalverwerking
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Documentatie](https://docs.solanaagentkit.xyz/)

2. **Eliza Framework**

- Combineert datalaag, LLM en agents en heeft een toegewijde Solana-plugin
- Uitbreidbare agentarchitectuur
- Eenvoudige integratie met bestaande projecten en kan bijvoorbeeld worden gebruikt voor
  Twitter (X)-, Telegram- of Discord-bots
- [GitHub-repository](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Uitgebreide ontwikkelingstoolkit
- Cross-chain compatibiliteit
- [GitHub-repository](https://github.com/goat-sdk/goat)

4. **Rig Framework**

- Ingebouwde Rust-implementatie
- Geschikt voor high-performance handelsbots
- Kan worden gecombineerd met de Listen.rs-toolkit voor Solana-integratietransactiemonitoring en het versturen van transacties met behulp van Jito-bundels
  bijvoorbeeld
- [GitHub-repository](https://github.com/0xPlaygrounds/rig)
- [Listen.rs-repository](https://github.com/piotrostr/listen)

Als je een AI-framework bouwt, kun je gerust een PR openen om je framework
aan de lijst toe te voegen

### Het agentscript aanmaken

Maak een nieuw bestand aan genaamd `agent.ts` met de volgende inhoud:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

</Step>

## Bouwen met het Eliza Framework

Het [ElizaOS](https://github.com/elizaOS/eliza) (voorheen bekend als Ai16z) is een
AI-framework. Dat betekent dat het meerdere applicaties combineert in één en
hun interacties organiseert. Het combineert:

1. Verschillende LLM's om de gebruiker te begrijpen
2. Blockchain-agents met verschillende acties (zoals het minten van een NFT bijvoorbeeld)
3. Datalaag om de toestand van de karakters tussen acties op te slaan via bijvoorbeeld
   Redis, PostgreSQL-database of lokale opslag
4. Verschillende clients zoals X, Telegram, Discord, enz.

Het brengt al deze zaken samen op een manier waarmee je een
"Karakter" kunt creëren dat met gebruikers kan communiceren of autonoom kan handelen. Deze karakters worden
gedefinieerd in een JSON-bestand, dat bepaalt welke acties het kan uitvoeren, welke LLM het
moet gebruiken en verschillende prompts die het gedrag van het karakter bepalen.

### Karakterconfiguratie aanmaken

Om een nieuw karakter aan te maken, moeten we een character.json-bestand aanmaken. Je kunt de
vooringestelde karakters vinden in de map characters van het Eliza-project. Om een
nieuw karakter aan te maken, kun je een van de al bestaande karakters kopiëren en aanpassen, of
je kunt de
[Composer-functie in Cursor](https://docs.cursor.com/composer/overview) gebruiken en aangeven
wat voor soort karakter je wilt aanmaken.

```json filename=characters/sol.character.json
{
    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },
        ...
```

Het belangrijke onderdeel hier zijn de clients en de modelProvider. In ons geval willen we
twitter gebruiken als client en openai als modelprovider, omdat dit ook
is waarvoor we onze geheimen hebben ingesteld in het `.env`-bestand.

Nu de configuratie is voltooid, kunnen we ons karakter uitvoeren:


Dit start de agent en je kunt er nu mee communiceren op Twitter. Het

Als je client geen verbinding maakt, zorg er dan voor dat je je agent uitvoert met de `--host`-

## Onchain programma-agentintegratie

Als je de reactie van een agent wilt gebruiken binnen een Solana-programma, moet je een
oracle gebruiken die de antwoorddata in een account schrijft dat jouw programma kan lezen.
Je kunt hier een voorbeeld vinden van een LLM dat tokens overdraagt aan elke gebruiker die
vragen correct beantwoordt:

[On-chain programma LLM-interactie](https://github.com/GabrielePicco/super-smart-contracts)

Dit is een voorbeeld van een onchain-programma dat integreert met een LLM (AI) oracle
om een interactieve token-uitdeler te maken, genaamd "Mar1o".

### Belangrijkste functies

1. **AI-agentinteractie**
   - Gebruikers kunnen chatten met Mar1o om tokens te verdienen
   - De agent beoordeelt de Solana-kennis van de gebruiker om de tokenhoeveelheid te bepalen
   - Antwoorden zijn in JSON-formaat met antwoordtekst en tokenhoeveelheid

2. **Tokenbeheer**
   - Maakt MAR1O-tokens aan met metadata
   - Kan tussen 0 en 10.000 tokens minten op basis van de AI-respons
   - Gebruikt PDA's voor tokenbeheer

### Programmaverloop toegelicht

Zo werkt dit programma:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Dit laat zien hoe je AI-mogelijkheden kunt combineren met onchain tokenmechanismen om
interactieve blockchain-ervaringen te creëren. Hier is een
[live voorbeeld](https://mar1o.xyz/) waar je kunt proberen de agent te overtuigen
om je wat tokens over te maken.

## Geavanceerde Rust-agents voor algoritmische handel

Als je je agents in Rust wilt schrijven, kun je het
[Rig-framework](https://github.com/0xPlaygrounds/rig) en de
[Listen.rs](https://github.com/piotrostr/listen)-bibliotheek gebruiken.

Deze twee werken goed samen. Terwijl het Rig-framework je een eenvoudige manier biedt om
verbinding te maken met LLM's, biedt de Listen.rs-toolkit de Solana-integratie,
inclusief transactiemonitoring en het verzenden van transacties via Jito-bundels,
bijvoorbeeld.

## Beste praktijken

- Houd er rekening mee dat je agent een privésleutel heeft en daarmee toegang heeft tot de fondsen in je
  portemonnee. Als iemand met je agent kan chatten en deze heeft bijvoorbeeld een overdrachtactie,
  kunnen gebruikers hem waarschijnlijk overtuigen om jouw fondsen over te maken.
- Gebruik betaalde [RPC-eindpunten](https://solana.com/rpc). De openbare eindpunten
  worden doorgaans snelheidslimitering opgelegd
- Monitor agentactiviteiten en zorg ervoor dat ze niets kwaadaardigs doen
  of daartoe worden verleid door gebruikers die ermee communiceren
- Implementeer prioriteitsvergoedingen en transactiepogingen voor je agentacties, zodat
  ze ook landen wanneer er congestie is op het netwerk
- Test indien mogelijk eerst op devnet voordat je naar mainnet deployt. De meeste agents
  nemen de RPC-URL als invoer en je kunt een devnet-URL gebruiken totdat je klaar bent
  voor mainnet. Niet alle acties zijn mogelijk op devnet.
- Voeg bij het schrijven van je eigen acties integratietests toe, zodat
  de frameworks kunnen monitoren welke acties mislukken door gewijzigde programma's of
  API's

## Conclusie

AI-agents op Solana openen nieuwe mogelijkheden voor automatisering en interactie
met de blockchain. Hoewel nog niet alle integraties perfect zijn, worden ze
snel ontwikkeld en bieden ze veel kansen voor bijdragen en zijn ze zeer
flexibel voor het toevoegen van je eigen integraties.
