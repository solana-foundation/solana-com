## RPC-infrastructuur

[Publieke endpoints](https://solana.com/docs/references/clusters#solana-public-rpc-endpoints)
(`api.mainnet.solana.com`) hebben een rate limit en geen SLA. Ze zijn prima voor
ontwikkeling, maar laten betalingsstromen in productie vastlopen—alsof je een
betalingsverwerker draait via een gedeelde API zonder uptimegarantie.

<Callout type="caution" title="Gebruik nooit publieke RPC in productie">
  Gebruik een [private RPC-provider](https://solana.com/rpc) voor betrouwbare toegang met lage
  latency.
</Callout>

Let bij het kiezen van een RPC-provider op:

- **Betrouwbaarheid**: SLA's met uptimegaranties (99,9%+)
- **Latency**: Geografische nabijheid tot je gebruikers
- **Functies**: Functies voor transactielanding, indexering, API's voor priority fees

Voor een volledige lijst met RPC-providers, zie de gids
[RPC-infrastructuurproviders](https://solana.com/rpc).

### Redundante RPC-configuratie

Net als elke andere netwerkdienstverlener kunnen RPC-providers downtime of
periodes met verminderde prestaties hebben. Om ervoor te zorgen dat je applicatie
veerkrachtig is, moet je deze zo configureren dat ze meerdere RPC-providers gebruikt.

[Solana Kit](https://github.com/anza-xyz/kit/tree/main/packages/rpc-transport-http)
biedt een bibliotheek voor het aanpassen van RPC-transports, waarmee je je
eigen redundante RPC-client kunt bouwen. Hier is een voorbeeld van hoe je dit
kunt gebruiken om een redundante RPC-client te bouwen:

```ts
import { RpcTransport } from "@solana/rpc-spec";
import { RpcResponse } from "@solana/rpc-spec-types";
import { createHttpTransport } from "@solana/rpc-transport-http";

// Create a transport for each RPC server
const transports = [
  createHttpTransport({ url: "https://mainnet-beta.my-server-1.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-2.com" }),
  createHttpTransport({ url: "https://mainnet-beta.my-server-3.com" })
];

// Create a wrapper transport that distributes requests to them
let nextTransport = 0;
async function roundRobinTransport<TResponse>(
  ...args: Parameters<RpcTransport>
): Promise<RpcResponse<TResponse>> {
  const transport = transports[nextTransport];
  nextTransport = (nextTransport + 1) % transports.length;
  return await transport(...args);
}
```

Als je liever geen eigen routeringstools bouwt, kun je een externe
dienst zoals [Iron Forge](https://www.ironforge.sanctum.so/) gebruiken om de
routering voor je te verzorgen.

## Transactielanding

Op Devnet landen transacties vrij gemakkelijk. Op Mainnet concurreer je om
blokruimte. Om de kans te vergroten dat je transactie in een
blok wordt opgenomen, moet je ervoor zorgen dat je transactie correct is samengesteld. Dit
betekent:

- een verse blockhash opnemen voordat je de transactie verzendt
- een priority fee-instructie met een concurrerende
  priority fee opnemen in de transactie
- een instructie voor de compute unit-limiet opnemen in de transactie, met een compute
  unit-limiet op basis van het geschatte aantal compute units dat de transactie nodig heeft

Daarnaast kun je andere tools overwegen, zoals Jito Bundles, om de
kans te vergroten dat je transactie in een blok wordt opgenomen. Laten we deze tools
nader bekijken.

### Configuratie voor het verzenden van transacties

Configureer bij het verzenden van transacties op Mainnet deze parameters voor optimale
landingspercentages:

**Blockhash-beheer:**

- Haal op met `confirmed` commitment
- Sla de `lastValidBlockHeight` op die `getLatestBlockhash` retourneert—deze geeft
  aan wanneer je transactie verloopt
- Blockhashes verlopen na een tijd die door het protocol wordt bepaald en afhangt van de lengte
  van een slot.

**Verzendopties:**

- `maxRetries: 0` — Schakel automatische RPC-retries uit. Handel retries zelf af,
  zodat je de blockhash kunt vernieuwen wanneer nodig.
- `skipPreflight: true` — Sla de simulatie vóór het verzenden over. Gebruik dit als je de
  transactie al hebt gevalideerd en de laagste latency wilt. Houd het op `false`
  tijdens de ontwikkeling om fouten vroeg te ontdekken.

```typescript
import { createSolanaRpc } from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);

// 1. Get blockhash with confirmed commitment
const { value: latestBlockhash } = await rpc
  .getLatestBlockhash({ commitment: "confirmed" })
  .send();

// 2. Build and sign your transaction with the blockhash
// ... (transaction building code)

// 3. Send with production settings
const signature = await rpc
  .sendTransaction(encodedTransaction, {
    encoding: "base64",
    maxRetries: 0n, // Handle retries yourself
    skipPreflight: true, // Skip simulation for speed (use false during dev)
    preflightCommitment: "confirmed"
  })
  .send();

// 4. Track expiration using lastValidBlockHeight
const { lastValidBlockHeight } = latestBlockhash;
// Stop retrying when current block height exceeds lastValidBlockHeight
```

### Gebruik priority fees

Elke Solana-transactie vereist transactiekosten, betaald in SOL. De transactiekosten
bestaan uit twee delen: de basisvergoeding en de priority fee. De basisvergoeding
compenseert validators voor het verwerken van de transactie. De priority fee is een
optionele vergoeding om de kans te vergroten dat de huidige leader je
transactie verwerkt. Zie het als expresverzending: je betaalt meer voor snellere,
betrouwbaardere levering.

**Hoe kosten werken:**

```
Total fee = Base fee (5,000 lamports per signature) + Priority fee
Priority fee (legacy/v0) = ceil(compute_unit_price * compute_unit_limit / 1,000,000) lamports
Priority fee (v1 only) = Absolute total in lamports set in the message config
```

**Kosten in de praktijk:**

- Eenvoudige USDC-overdracht: ~$0,001-0,005 onder normale omstandigheden
- Tijdens congestie: ~$0,01-0,05
- Piekcongestie: kan nog hoger oplopen

**Voorbeeldimplementatie:**

Het pakket
[`@solana-program/compute-budget`](https://github.com/solana-program/compute-budget)
biedt een hulpfunctie om eenvoudig de instructie voor de compute unit-prijs
(in micro-lamports) aan een transactie toe te voegen of bij te werken.

```typescript
import { updateOrAppendSetComputeUnitPriceInstruction } from "@solana-program/compute-budget";

const tx = pipe(
  createTransactionMessage({ version: 0 }),
  (m) => setTransactionMessageFeePayerSigner(payer, m),
  (m) => setTransactionMessageLifetimeUsingBlockhash(latestBlockhash, m),
  (m) => appendTransactionMessageInstructions([myInstructions], m),
  (m) => updateOrAppendSetComputeUnitPriceInstruction(1000n as MicroLamports, m)
);
```

**Feeschattingen ophalen:** De meeste RPC-providers bieden API's voor priority fees:

- [Helius Priority Fee API](https://docs.helius.dev/solana-apis/priority-fee-api)
- [QuickNode Priority Fee Add-on](https://marketplace.quicknode.com/add-on/solana-priority-fee)
- [Triton Priority Fees API](https://docs.triton.one/chains/solana/improved-priority-fees-api)

Voor de volledige werking van kosten, zie [Transactiekosten](/docs/core/fees) en onze
gids:
[Priority fees toevoegen aan een transactie](https://solana.com/developers/cookbook/transactions/add-priority-fees).

### Compute units optimaliseren

Compute op Solana wordt gemeten in compute units (CU's), een grove schatting
van hoeveel werk het programma verricht. De huidige compute-limieten zijn 50 miljoen
CU's per blok en 1,4 miljoen CU's per transactie. Wanneer je een
transactie indient, moet je schatten hoeveel compute er wordt gebruikt en
de compute unit-limiet dienovereenkomstig instellen. Dit is in feite een verzoek om te bepalen hoeveel
van de totale capaciteit voor jouw transactie moet worden gereserveerd. In de
praktijk betekent dit dat het correct schatten van de compute units die je
transactie nodig heeft cruciaal is om je transactie in een blok te laten opnemen (en
belangrijk voor het beheren van je priority fees). De compute-limieten voor transacties en blokken
worden bepaald door het protocol.

De Solana JSON RPC API heeft een
[`simulatetransaction`](/docs/rpc/http/simulatetransaction)-methode die gebruikt kan
worden om de compute units te schatten die een transactie nodig heeft, inclusief een
schatting van de compute units die daadwerkelijk worden gebruikt.
[`@solana/kit`](https://github.com/anza-xyz/kit) biedt hulpfuncties die de resourcelimieten van een transactie
schatten en in één stap op het bericht instellen
(met de `simulatetransaction`-methode onder de motorkap). Voor versie 1-
transacties schatten deze hulpfuncties ook de limiet voor de grootte van geladen accountdata.

```ts
import {
  estimateResourceLimitsFactory,
  estimateAndSetResourceLimitsFactory
} from "@solana/kit";

const estimateResourceLimits = estimateResourceLimitsFactory({ rpc });
const estimateAndSetResourceLimits = estimateAndSetResourceLimitsFactory(
  estimateResourceLimits
);
const txWithResourceLimits = await estimateAndSetResourceLimits(tx);
```

<Callout type="info">
  Als je transacties bouwt en verzendt met een kit-pluginclient, heb je deze stap meestal
  niet nodig — de client voegt compute budget-instructies voor je toe
  wanneer hij verzendt (`.sendTransaction()`). De handmatige flow hierboven is voor als je
  transacties rechtstreeks samenstelt met `@solana/kit`.
</Callout>

Als je in productie hetzelfde type transactie meerdere keren herhaalt,
overweeg dan om de compute-schatting voor dat transactietype te cachen om
de overhead van het schatten van de compute units telkens te vermijden.

### Jito Bundles

Jito bundles zijn een tool voor het atomair uitvoeren van meerdere transacties.
Dit wordt bereikt door meerdere transacties met een
tip naar het Jito-netwerk te sturen. Tips kunnen worden gebruikt om het Jito-netwerk te stimuleren je
transacties in een blok op te nemen.

### Retrystrategieën

Transacties kunnen om vele redenen mislukken. In tegenstelling tot traditionele betaal-API's die
direct succes of mislukking retourneren, vereisen blockchaintransacties het bijhouden
van bevestigingen.

**Belangrijkste concepten:**

- **Verlopen van blockhash**: Verlopen van blockhash: blockhashes van transacties blijven
  150 slots geldig (ongeveer 30 seconden bij 200 ms per slot). De daadwerkelijke
  verlooptijd kan variëren afhankelijk van de snelheid van blokproductie. Gebruik
  lastValidBlockHeight om te bepalen wanneer een blockhash is verlopen.
- **Idempotentie**: Dezelfde ondertekende transactie levert altijd dezelfde
  handtekening op—opnieuw indienen is veilig
- **Exponentiële backoff**: Voorkom dat je het netwerk overbelast met snelle retries

```typescript
import {
  createSolanaRpc,
  createSolanaRpcSubscriptions,
  sendAndConfirmTransactionFactory,
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED
} from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL!);
const rpcSubscriptions = createSolanaRpcSubscriptions(process.env.RPC_WSS_URL!);

const sendAndConfirmTransaction = sendAndConfirmTransactionFactory({
  rpc,
  rpcSubscriptions
});

// Send with automatic confirmation tracking and block height monitoring
try {
  await sendAndConfirmTransaction(signedTransaction, {
    commitment: "confirmed",
    // Optional: abort after 75 seconds
    abortSignal: AbortSignal.timeout(75_000)
  });
} catch (e) {
  if (isSolanaError(e, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED)) {
    // Blockhash expired—rebuild transaction with fresh blockhash and retry
    rebuildAndRetryTransaction(); // implement your own logic for rebuilding and retrying the transaction
  }
  throw e;
}
```

De `sendAndConfirmTransactionFactory` uit `@solana/kit` regelt automatisch het pollen van
bevestigingen en het bijhouden van de blokhoogte. Hij geeft
`SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED` als de blockhash van de transactie verloopt,
wat aangeeft dat je de transactie opnieuw moet opbouwen met een verse blockhash.

## Foutafhandeling

Solana Kit biedt getypeerde fouten via `isSolanaError()`. Gebruik specifieke foutcodes
in plaats van het matchen van strings:

```typescript
import {
  isSolanaError,
  SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED,
  SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE,
  SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND,
  SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS
} from "@solana/kit";

function handlePaymentError(error: unknown): {
  message: string;
  retryable: boolean;
} {
  // Blockhash expired—rebuild and retry
  if (
    isSolanaError(error, SOLANA_ERROR__BLOCK_HEIGHT_EXCEEDED) ||
    isSolanaError(error, SOLANA_ERROR__TRANSACTION_ERROR__BLOCKHASH_NOT_FOUND)
  ) {
    return { message: "Transaction expired—rebuilding", retryable: true };
  }

  // Insufficient SOL for fees
  if (
    isSolanaError(
      error,
      SOLANA_ERROR__TRANSACTION_ERROR__INSUFFICIENT_FUNDS_FOR_FEE
    )
  ) {
    return { message: "Not enough SOL for fees", retryable: false };
  }

  // Insufficient token balance
  if (
    isSolanaError(error, SOLANA_ERROR__INSTRUCTION_ERROR__INSUFFICIENT_FUNDS)
  ) {
    return { message: "Insufficient balance", retryable: false };
  }

  // Unknown error
  console.error("Payment error:", error);
  return { message: "Payment failed—please retry", retryable: true };
}
```

**Veelvoorkomende foutcodes:**

| Foutcode                   | Oorzaak                 | Herstel                                                                                                 |
| ---------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------- |
| `BLOCK_HEIGHT_EXCEEDED`      | Blockhash verlopen     | Opnieuw opbouwen met verse blockhash                                                                             |
| `BLOCKHASH_NOT_FOUND`        | Blockhash niet gevonden   | Opnieuw opbouwen met verse blockhash                                                                             |
| `INSUFFICIENT_FUNDS_FOR_FEE` | Onvoldoende SOL        | Stort tegoed op de fee payer of gebruik [fee abstraction](/docs/payments/send-payments/payment-processing/fee-abstraction) |
| `INSUFFICIENT_FUNDS`         | Onvoldoende tokens     | Gebruiker heeft meer saldo nodig                                                                                  |
| `ACCOUNT_NOT_FOUND`          | token account ontbreekt | Maak ATA aan in transactie                                                                                |
