De opdrachtregelinterface `solana` configureert een clusterverbinding, leest
de netwerkstatus, verstuurt SOL, beheert durable nonces, deployt programma's en beheert
stake- en vote-accounts.

Deze referentie volgt
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Voer
`solana --version` uit om de geïnstalleerde release te controleren en gebruik `--help` voor de exacte
opties die in die versie beschikbaar zijn.

<Callout type="warn">
  Commando's die aanmaken, overmaken, autoriseren, opnemen of deployen, dienen
  transacties in. Controleer het geconfigureerde cluster en de ondertekenaar voordat je ze uitvoert.
  Devnet- en Testnet-tokens hebben geen waarde; Mainnet-commando's gebruiken echte SOL.
</Callout>

## Commandostructuur

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Hulp opvragen op elk niveau:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Globale opties

Globale opties kunnen vóór het commando worden geplaatst. De commandospecifieke help herhaalt
de opties die voor dat commando gelden.

| Optie                          | Doel                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Selecteer een RPC-URL of `mainnet-beta`, `testnet`, `devnet` of `localhost`.      |
| `--ws <URL>`                    | Overschrijf het WebSocket-eindpunt.                                               |
| `-k, --keypair <KEYPAIR>`       | Selecteer een keypair-bestand, `ASK`, stdin (`-`) of een ondersteunde signer-URL.          |
| `-C, --config <FILEPATH>`       | Gebruik een ander CLI-configuratiebestand.                                        |
| `--commitment <LEVEL>`          | Lees met de commitment `processed`, `confirmed` of `finalized`.                   |
| `--output <FORMAT>`             | Geef `json` of `json-compact` terug waar dit wordt ondersteund.                               |
| `--skip-preflight`              | Verzend zonder RPC-simulatie. Gebruik dit alleen als je de afweging met betrekking tot mogelijke fouten begrijpt. |
| `--use-tpu-client`              | Verstuur transacties via de TPU-client.                                      |
| `--no-address-labels`           | Toon adressen zonder lokale labels.                                          |
| `--skip-seed-phrase-validation` | Sta een herstelzin toe die niet in de Engelse BIP39-lijst staat.                       |
| `-v, --verbose`                 | Toon aanvullende commando-uitvoer.                                                |
| `-V, --version`                 | Toon de geïnstalleerde CLI-versie.                                               |

## De CLI configureren

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

De configuratie bevat een RPC-URL, WebSocket-URL, standaard ondertekenaar en
commitment. Een opdrachtregeloptie overschrijft de opgeslagen waarde voor die aanroep.

## Veelgebruikte account- en transactieworkflows

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` accepteert standaard SOL. Gebruik `ALL` als bedrag om het beschikbare
saldo na aftrek van kosten over te maken. Voor tokenvoorbeelden, zie de
[token-quickstart](/docs/tokens/quickstart).

## Programma-workflows

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Geef `--program-id <KEYPAIR_OR_ADDRESS>` mee wanneer een deployment een bekende
programma-ID moet gebruiken. `--final` maakt een nieuwe deployment onveranderlijk; lees de help hiervan zorgvuldig
voordat je het gebruikt, omdat de upgrade-autoriteit niet kan worden hersteld.

## Durable nonce-workflows

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Gebruik `authorize-nonce-account` om de nonce-autoriteit te wijzigen en `nonce-account`
om de volledige accountstatus te inspecteren. Transacties die een nonce gebruiken accepteren ook
`--nonce` en `--nonce-authority` bij ondersteunde commando's.

## Stake-workflows

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

Deactivering wordt voltooid bij een epoch-grens en kan meer dan één epoch duren.
Gebruik `stakes`, `validators`, `stake-history` en `stake-minimum-delegation` om
de cluster- en delegatiestatus te inspecteren voordat je wijzigingen indient.

## Adreshulpmiddelen

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

PDA-seeds gebruiken `PREFIX:VALUE`. Ondersteunde prefixen zijn onder meer `string`, `pubkey`,
`hex`, `u8` en integercoderingen met vaste breedte, met of zonder teken, zoals
`u64le`.

## Off-chain-berichten en shell-completion

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Scriptuitvoer

Gebruik `--output json` of `--output json-compact` waar dit wordt ondersteund, in plaats van
menselijk leesbare uitvoer te parsen:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Niet elk commando ondersteunt gestructureerde uitvoer. Controleer de help van het commando voordat je
in automatisering ervan afhankelijk bent, en beschouw een afsluitstatus ongelijk aan nul als een fout.
