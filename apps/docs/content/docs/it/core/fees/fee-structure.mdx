<Callout type="info" title="Riepilogo">
  Commissione totale = commissione base (5.000 lamports/firma, 50% bruciato) + commissione di priorità
  (CU_price * CU_limit / 1M lamports, 100% al validator). Addebitata sia che la
  transazione abbia successo o meno.
</Callout>

## Algoritmo di calcolo delle commissioni

La commissione totale per una transazione viene calcolata da
[`calculate_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L53-L72):

```text title="Total fee formula"
total_fee = base_fee + prioritization_fee
```

Gli input sono il messaggio della transazione, il valore attuale di `lamports_per_signature`
(attualmente 5.000) e la commissione di priorità derivata dalle istruzioni del budget di calcolo.
La commissione totale viene dedotta dal pagante prima dell'esecuzione.
Se la transazione fallisce, la commissione viene comunque addebitata.

## Commissione base

La commissione base copre il costo della verifica della firma Ed25519 e
le verifiche delle firme precompilate. Ogni firma nella transazione viene
addebita, incluse le firme verificate dai programmi precompilati Ed25519, Secp256k1 e Secp256r1.

La funzione
[`calculate_signature_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/fee/src/lib.rs#L75-L92)
calcola:

```text title="Base fee formula"
signature_count = num_transaction_signatures
                + num_ed25519_signatures
                + num_secp256k1_signatures
                + num_secp256r1_signatures   (if feature enabled)

base_fee = signature_count * lamports_per_signature
```

- `num_transaction_signatures`: il numero di firme Ed25519 nella
  transazione (in genere una per firmatario).
- `num_ed25519_signatures`, `num_secp256k1_signatures`,
  `num_secp256r1_signatures`: firme verificate dai rispettivi
  programmi precompilati.
- `lamports_per_signature`: attualmente
  [5.000 lamports](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-structure/src/lib.rs#L210).

### Distribuzione delle commissioni

La commissione base e la commissione di priorità vengono distribuite in modo diverso. La funzione
[`calculate_reward_and_burn_fee_details`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L85-L98)
nel runtime calcola:

```text title="Fee distribution"
burn_amount     = transaction_fee * 50 / 100
validator_share = (transaction_fee - burn_amount) + priority_fee
```

- **Commissione base (transaction_fee)**: il 50% viene
  [bruciato](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L93)
  (rimosso dalla circolazione) e il 50% va al validator che produce il blocco.
  La percentuale bruciata è
  [`DEFAULT_BURN_PERCENT = 50`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/fee-calculator/src/lib.rs#L70).
- **Commissione di priorità**: il 100% va al validator (nessuna quota viene bruciata), secondo
  [SIMD-0096](https://github.com/solana-foundation/solana-improvement-documents/blob/main/proposals/0096-reward-collected-priority-fee-in-entirety.md).

La ricompensa totale del validator per una transazione è:

```text
validator_reward = (base_fee / 2) + prioritization_fee
```

## Commissione di priorità

La commissione di priorità è una commissione opzionale che aumenta la priorità di schedulazione
di una transazione. Un'unità di calcolo (CU) è un'unità di elaborazione misurata dal runtime
durante l'esecuzione della transazione. Ogni operazione (aritmetica, accesso alla memoria,
syscall) ha un costo fisso in CU. È possibile impostare la commissione di priorità includendo
istruzioni del budget di calcolo nella transazione. (Consulta la
[guida Come utilizzare le commissioni di priorità](/docs/core/fees) per i dettagli.)

### Formula della commissione di priorità

La funzione
[`get_prioritization_fee`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L61-L69)
calcola:

```text title="Prioritization fee formula"
micro_lamport_fee = compute_unit_price * compute_unit_limit
prioritization_fee = ceil(micro_lamport_fee / 1,000,000)
```

| Variabile             | Descrizione                                                                                                                                                                       | Predefinito                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `compute_unit_price` | Micro-lamports per CU, impostato tramite `SetComputeUnitPrice`                                                                                                                              | 0 micro-lamports                |
| `compute_unit_limit` | CU massime che la transazione può consumare, impostate tramite `SetComputeUnitLimit`                                                                                                            | Somma dei valori predefiniti per istruzione |
| `1.000.000`          | Fattore di conversione da micro-lamports a lamports ([`MICRO_LAMPORTS_PER_LAMPORT`](https://github.com/anza-xyz/agave/blob/v3.1.8/compute-budget/src/compute_budget_limits.rs#L17)) | --                              |

<Callout type="info" title="Le transazioni v1 impostano la commissione direttamente">
  Questa formula prezzo per limite si applica alle transazioni legacy e v0. Nel
  [formato v1](/docs/core/transactions/versioned-transactions#v1-format), la
  commissione di priorità è un totale assoluto in lamports impostato direttamente nella
  configurazione del messaggio — nessun prezzo per CU, nessuna moltiplicazione, nessun arrotondamento.
</Callout>

### Limite di unità di calcolo

Il limite di unità di calcolo è il numero massimo di CU che una transazione può consumare.
Se non viene inclusa alcuna istruzione
[`SetComputeUnitLimit`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L32),
il valore predefinito viene calcolato in base al numero e al tipo di istruzioni
(200.000 CU per istruzione non integrata, 3.000 per quelle integrate). Consulta
[Compute Budget](/docs/core/fees/compute-budget) per i dettagli sul calcolo predefinito.

<Callout type="warn">
  La commissione di priorità è basata sul limite di CU richiesto, non sull'utilizzo effettivo delle CU.
  Impostare un limite più alto del necessario significa pagare per unità di calcolo non utilizzate.
</Callout>

### Prezzo dell'unità di calcolo

Il prezzo dell'unità di calcolo è un importo opzionale in micro-lamports pagato per ogni
CU richiesta. Il prezzo CU determina direttamente la commissione di priorità. Per impostare
il prezzo CU, includi un'istruzione
[`SetComputeUnitPrice`](https://github.com/anza-xyz/solana-sdk/blob/clock%40v2.2.3/compute-budget-interface/src/lib.rs#L35)
nella tua transazione.

<Callout>
  Il prezzo CU predefinito è 0, il che significa che anche la commissione di priorità predefinita è 0.
</Callout>

Per stime in tempo reale del prezzo CU, consulta i provider di API per le commissioni di priorità di seguito.

| Provider                                | API per le commissioni di priorità                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| [Helius](https://www.helius.dev/)       | [Documentazione](https://docs.helius.dev/solana-apis/priority-fee-api)             |
| [QuickNode](https://www.quicknode.com/) | [Documentazione](https://marketplace.quicknode.com/add-on/solana-priority-fee)     |
| [Triton](https://triton.one/)           | [Documentazione](https://docs.triton.one/chains/solana/improved-priority-fees-api) |

### Priorità di schedulazione delle transazioni

Lo scheduler classifica le transazioni utilizzando la funzione
[`calculate_priority_and_cost`](https://github.com/anza-xyz/agave/blob/v3.1.8/core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs#L526-L546):

```text title="Transaction priority formula"
Priority = reward * 1,000,000 / (cost + 1)
```

- **reward**: il reddito da commissioni del validator = commissione di priorità + quota non bruciata
  della commissione base. Calcolato da
  [`calculate_reward_for_transaction`](https://github.com/anza-xyz/agave/blob/v3.1.8/runtime/src/bank/fee_distribution.rs#L64-L83).
- **cost**: il
  [costo CU stimato](https://github.com/anza-xyz/agave/blob/v3.1.8/cost-model/src/cost_model.rs#L37-L57)
  dallo scheduler (costi delle firme + costi di blocco in scrittura + costi di instruction data + costi di
  esecuzione del programma + costo della dimensione dei dati degli account caricati). Consulta
  [Compute Budget](/docs/core/fees/compute-budget#scheduler-cost-model) per i dettagli.
- **1.000.000**: un moltiplicatore per preservare la precisione, poiché il costo spesso supera
  la ricompensa in lamports grezzi.
- **+1**: previene la divisione per zero.

La priorità determina l'ordine in cui le transazioni vengono estratte dal buffer dello
scheduler per l'esecuzione.

```ts !! title="Web3.js v3"
import {
  LAMPORTS_PER_SOL,
  SystemProgram,
  Transaction,
  Keypair,
  Connection,
  ComputeBudgetProgram,
  sendAndConfirmTransaction
} from "@solana/web3.js";

const connection = new Connection("http://localhost:8899", "confirmed");

const sender = await Keypair.generate();
const recipient = await Keypair.generate();

const airdropSignature = await connection.requestAirdrop(
  sender.publicKey,
  LAMPORTS_PER_SOL
);
await connection.confirmTransaction(airdropSignature, "confirmed");

// Create compute budget instructions
const limitInstruction = ComputeBudgetProgram.setComputeUnitLimit({
  units: 300_000
});
const priceInstruction = ComputeBudgetProgram.setComputeUnitPrice({
  microLamports: 1
});

const transferInstruction = SystemProgram.transfer({
  fromPubkey: sender.publicKey,
  toPubkey: recipient.publicKey,
  lamports: 0.01 * LAMPORTS_PER_SOL
});

// Add the compute budget and transfer instructions to a new transaction
const transaction = new Transaction()
  .add(limitInstruction)
  .add(priceInstruction)
  .add(transferInstruction);

const signature = await sendAndConfirmTransaction(connection, transaction, [
  sender
]);

console.log("Transaction Signature:", signature);
```

```rust !! title="Rust"
use solana_client::nonblocking::rpc_client::RpcClient;
use solana_commitment_config::CommitmentConfig;
use solana_compute_budget_interface::ComputeBudgetInstruction;
use solana_sdk::{
    native_token::LAMPORTS_PER_SOL,
    signature::{Keypair, Signer},
    transaction::Transaction,
};
use solana_system_interface::instruction::transfer;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = RpcClient::new_with_commitment(
        String::from("http://localhost:8899"),
        CommitmentConfig::confirmed(),
    );

    let sender = Keypair::new();
    let recipient = Keypair::new();

    let airdrop_signature = client
        .request_airdrop(&sender.pubkey(), LAMPORTS_PER_SOL)
        .await?;

    loop {
        let confirmed = client.confirm_transaction(&airdrop_signature).await?;
        if confirmed {
            break;
        }
    }

    // Create compute budget instructions
    let limit_instruction = ComputeBudgetInstruction::set_compute_unit_limit(300_000);
    let price_instruction = ComputeBudgetInstruction::set_compute_unit_price(1);

    let transfer_amount = LAMPORTS_PER_SOL / 100;
    let transfer_instruction = transfer(&sender.pubkey(), &recipient.pubkey(), transfer_amount);

    let recent_blockhash = client.get_latest_blockhash().await?;

    let mut transaction = Transaction::new_with_payer(
        &[limit_instruction, price_instruction, transfer_instruction],
        Some(&sender.pubkey()),
    );
    transaction.sign(&[&sender], recent_blockhash);

    let signature = client.send_and_confirm_transaction(&transaction).await?;
    println!("Transaction Signature: {}", signature);

    Ok(())
}
```
