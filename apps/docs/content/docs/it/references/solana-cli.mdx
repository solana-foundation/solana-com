L'interfaccia a riga di comando `solana` configura la connessione a un cluster, legge
lo stato della rete, invia SOL, gestisce i durable nonce, esegue il deploy dei programmi e gestisce
account di stake e di voto.

Questo riferimento segue
[Agave v4.2.1](https://github.com/anza-xyz/agave/releases/tag/v4.2.1). Esegui
`solana --version` per verificare la release installata e usa `--help` per vedere le
opzioni esatte disponibili in quella versione.

<Callout type="warn">
  I comandi che creano, trasferiscono, autorizzano, prelevano o eseguono il deploy inviano
  transazioni. Conferma il cluster configurato e il firmatario prima di eseguirli.
  I token di Devnet e Testnet non hanno alcun valore; i comandi su Mainnet usano SOL reali.
</Callout>

## Struttura dei comandi

```text
solana [GLOBAL_OPTIONS] <COMMAND> [COMMAND_OPTIONS]
```

Ottieni aiuto a qualsiasi livello:

```shell
solana --help
solana transfer --help
solana address-lookup-table extend --help
```

## Opzioni globali

Le opzioni globali possono essere inserite prima del comando. La guida specifica di un comando ripete
le opzioni che si applicano a quel comando.

| Opzione                          | Scopo                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `-u, --url <URL_OR_MONIKER>`    | Seleziona un URL RPC oppure `mainnet-beta`, `testnet`, `devnet` o `localhost`.      |
| `--ws <URL>`                    | Sostituisce l'endpoint WebSocket.                                               |
| `-k, --keypair <KEYPAIR>`       | Seleziona un file keypair, `ASK`, stdin (`-`) o un URL di firmatario supportato.          |
| `-C, --config <FILEPATH>`       | Usa un file di configurazione della CLI diverso.                                        |
| `--commitment <LEVEL>`          | Legge con livello di commitment `processed`, `confirmed` o `finalized`.                   |
| `--output <FORMAT>`             | Restituisce `json` o `json-compact` dove supportato.                               |
| `--skip-preflight`              | Invia senza la simulazione RPC. Usalo solo se comprendi i compromessi in caso di errore. |
| `--use-tpu-client`              | Invia le transazioni tramite il client TPU.                                      |
| `--no-address-labels`           | Stampa gli indirizzi senza etichette locali.                                          |
| `--skip-seed-phrase-validation` | Consente una frase di recupero non presente nell'elenco inglese BIP39.                       |
| `-v, --verbose`                 | Mostra un output aggiuntivo del comando.                                                |
| `-V, --version`                 | Stampa la versione installata della CLI.                                               |

## Configurare la CLI

```shell
# Inspect the effective configuration.
solana config get

# Use Devnet and a specific signer by default.
solana config set --url devnet
solana config set --keypair ./devnet-keypair.json

# Override defaults for one command.
solana --url mainnet-beta --keypair usb://ledger address
```

La configurazione contiene un URL RPC, un URL WebSocket, il firmatario predefinito e il
commitment. Un'opzione da riga di comando sostituisce il valore salvato per quella specifica invocazione.

## Flussi di lavoro comuni per account e transazioni

```shell
# Print the default signer's address and balance.
solana address
solana balance

# Read an account as JSON.
solana account <ACCOUNT_ADDRESS> --output json

# Request Devnet SOL.
solana airdrop 1 --url devnet

# Send SOL and then confirm the returned signature.
solana transfer <RECIPIENT_ADDRESS> 0.1 --allow-unfunded-recipient
solana confirm <TRANSACTION_SIGNATURE>

# Inspect recent activity and stream logs mentioning an address.
solana transaction-history <ADDRESS> --limit 20
solana logs <ADDRESS>
```

`transfer` accetta SOL per impostazione predefinita. Usa `ALL` come importo per trasferire il saldo
disponibile al netto delle commissioni. Per esempi sui token, consulta la
[guida rapida ai token](/docs/tokens/quickstart).

## Flussi di lavoro dei programmi

```shell
# Deploy or upgrade an SBF program.
solana program deploy ./target/deploy/my_program.so

# Inspect the deployed program and list programs controlled by the signer.
solana program show <PROGRAM_ID>
solana program show --programs

# Close a program buffer and recover its lamports.
solana program close <BUFFER_ADDRESS>
```

Passa `--program-id <KEYPAIR_OR_ADDRESS>` quando un deploy deve usare un program ID
noto. `--final` rende immutabile un nuovo deploy; leggi con attenzione la relativa guida
prima di usarlo, perché l'upgrade authority non può essere ripristinata.

## Flussi di lavoro dei durable nonce

```shell
solana-keygen new --outfile nonce-account.json
solana create-nonce-account nonce-account.json 0.1
solana nonce nonce-account.json
solana new-nonce nonce-account.json
solana withdraw-from-nonce-account nonce-account.json <RECIPIENT_ADDRESS> ALL
```

Usa `authorize-nonce-account` per cambiare la nonce authority e `nonce-account`
per ispezionare lo stato completo dell'account. Le transazioni che usano un nonce accettano anche
`--nonce` e `--nonce-authority` sui comandi supportati.

## Flussi di lavoro di staking

```shell
solana-keygen new --outfile stake-account.json
solana create-stake-account stake-account.json 1
solana delegate-stake stake-account.json <VOTE_ACCOUNT_ADDRESS>
solana stake-account stake-account.json

solana deactivate-stake stake-account.json
solana withdraw-stake stake-account.json <RECIPIENT_ADDRESS> ALL
```

La disattivazione si completa al limite di un epoch e può richiedere più di un epoch.
Usa `stakes`, `validators`, `stake-history` e `stake-minimum-delegation` per
ispezionare lo stato del cluster e delle deleghe prima di inviare modifiche.

## Utilità per gli indirizzi

```shell
# Derive a PDA from typed seeds.
solana find-program-derived-address \
  <PROGRAM_ID> \
  string:profile \
  pubkey:<OWNER_ADDRESS>

# Create and extend an address lookup table.
solana address-lookup-table create
solana address-lookup-table extend \
  <LOOKUP_TABLE_ADDRESS> \
  --addresses <ADDRESS_1>,<ADDRESS_2>
```

I seed PDA usano `PREFIX:VALUE`. I prefissi supportati includono `string`, `pubkey`,
`hex`, `u8` e codifiche di interi con segno o senza segno a larghezza fissa, come
`u64le`.

## Messaggi off-chain e completamento della shell

```shell
solana sign-offchain-message "terms accepted"
solana verify-offchain-signature \
  "terms accepted" \
  <SIGNATURE> \
  --signer <SIGNER_ADDRESS>

# Print a completion script for the current shell.
solana completion --shell zsh
```

## Output per gli script

Usa `--output json` o `--output json-compact` dove supportato, invece di
eseguire il parsing dell'output leggibile dall'uomo:

```shell
solana epoch-info --output json
solana account <ACCOUNT_ADDRESS> --output json-compact
solana validators --output json > validators.json
```

Non tutti i comandi supportano l'output strutturato. Controlla la guida del comando prima di
farvi affidamento nell'automazione e considera uno stato di uscita diverso da zero come un errore.
