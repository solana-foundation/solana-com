**Solana Keychain offre un'interfaccia unificata per firmare le transazioni Solana
su più backend di gestione delle chiavi.** Sviluppa in locale con una chiave
in memoria, poi passa in produzione alla gestione delle chiavi enterprise, agli HSM cloud o ai servizi
di wallet gestiti, senza riscrivere il tuo codice di firma.

### Perché Keychain?

- **Interfaccia unica**: un'unica interfaccia di base `SolanaSigner` per tutti i backend,
  più una capability per ciascun backend: firma, riscrittura e firma, oppure firma e broadcast
- **Backend intercambiabili**: cambia provider di gestione delle chiavi tramite configurazione; i
  punti di chiamata cambiano solo quando il nuovo backend ha una capability diversa (modalità native di Crossmint
  e Fordefi)
- **Paghi solo ciò che usi**: i feature flag di Rust, i pacchetti npm per singolo backend, gli extra di Python
  e i moduli Go per singolo backend includono solo i backend di cui hai bisogno
- **Sottoposto ad audit**: Rust, TypeScript, Python e Go sono stati sottoposti ad audit da
  [OtterSec](https://osec.io) (il backend Ledger, opzionale, era fuori ambito); un
  precedente audit di [Accretion](https://accretion.xyz) ha coperto Rust e TypeScript.
  Consulta lo
  [stato degli audit](https://github.com/solana-foundation/solana-keychain/blob/main/audits/AUDIT_STATUS.md).

### Architettura

- **Linguaggi**: Rust, TypeScript, Python e Go, con parità di funzionalità (il backend Ledger
  è disponibile solo per Rust)
- **Interfaccia**: base `SolanaSigner` (`pubkey`, `sign_message`, `is_available`)
  più esattamente una capability per backend: `TransactionSigner`,
  `ModifyingSigner` o `SendingSigner`
- **Backend**: Memory, Vault, AWS KMS, GCP KMS, Privy, Turnkey, Fireblocks,
  CDP, Crossmint, Dfns, Openfort, Para, Utila, Fordefi, Ledger (solo Rust,
  opzionale, non sottoposto ad audit)
- **Compatibilità**: `@solana/kit` e `@solana/signers` 8.1+ (TypeScript) |
  `solana-sdk` 2.x, 3.x o 4.x tramite le feature `sdk-v2` / `sdk-v3` / `sdk-v4`
  (Rust; le transazioni v1 richiedono `sdk-v4`) | `solders` (Python) | `solana-go` v2
  (Go)

### Backend Supportati

I backend coprono lo sviluppo locale, la gestione delle chiavi self-hosted e
cloud, e servizi di wallet gestiti o MPC. Consulta
[Scegliere un backend](/docs/tools/keychain/choosing-a-backend) per confrontare
i modelli di custodia e scegliere quello più adatto.

## Avvio rapido

### Rust

Installa il crate Rust:

```bash
cargo add solana-keychain
```

Utilizzo di base:

```rust
use solana_keychain::{Signer, SolanaSigner};

// Create a signer from any backend
let signer = Signer::from_memory("base58_private_key")?;
let pubkey = signer.pubkey();

// Transaction signing is a capability; `tx` is a VersionedTransaction
if let Some(tx_signer) = signer.as_transaction_signer() {
    let result = tx_signer.sign_transaction(&mut tx).await?;
}

// Or let the umbrella route any backend shape and supply the RPC hop yourself
let signature = signer
    .sign_and_send(&mut tx, |encoded| async move { broadcast(encoded).await })
    .await?;
```

- [Guida Rust](/docs/tools/keychain/getting-started/rust) - Installazione
  completa e configurazione del backend
- [Crates.io](https://crates.io/crates/solana-keychain) - Crate Rust

### TypeScript

Installa il pacchetto TypeScript:

```bash
pnpm add @solana/keychain
```

Utilizzo di base:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers";

// Create any signer via the unified factory
const signer = await createKeychainSigner({
  backend: "vault",
  vaultAddr: "https://vault.example.com:8200",
  vaultToken: "hvs.xxxxx",
  keyName: "my-solana-key",
  publicKey: "base58_public_key"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

- [Guida TypeScript](/docs/tools/keychain/getting-started/typescript) -
  Pacchetti `@solana/keychain`
- [Pacchetto npm](https://www.npmjs.com/package/@solana/keychain) - Pacchetto
  npm

Per installare un signer Keychain su un client [Kit](https://github.com/anza-xyz/kit)
come `payer` o `identity`, usa `@solana/keychain-kit-plugin` (le modalità native di Crossmint e
Fordefi sono escluse, poiché riscrivono le transazioni).

### Python

Installa il pacchetto (i backend più pesanti sono distribuiti come extra, ad esempio
`solana-keychain[aws-kms]`):

```bash
pip install solana-keychain
```

Utilizzo di base:

```python
import os

from solana_keychain import VaultSignerConfig, create_vault_signer

signer = await create_vault_signer(
    VaultSignerConfig(
        api_base_url="https://vault.example.com:8200",
        token=os.environ["VAULT_TOKEN"],
        key_name="my-solana-key",
        public_key="base58_public_key",
    )
)

# tx is a solders VersionedTransaction
result = await signer.sign_transaction(tx)
```

- [Guida Python](/docs/tools/keychain/getting-started/python) - Installazione
  completa, extra e configurazione dei backend
- [PyPI](https://pypi.org/project/solana-keychain/) - Pacchetto Python

### Go

Ogni backend è un modulo Go a sé stante, così scarichi solo i backend che importi:

```bash
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2@latest
```

Utilizzo di base:

```go
import "github.com/solana-foundation/solana-keychain/go/signers/vault/v2"

signer, err := vault.New(vault.Config{
	VaultAddr: "https://vault.example.com:8200",
	Token:     os.Getenv("VAULT_TOKEN"),
	KeyName:   "my-solana-key",
	Pubkey:    "base58_public_key",
})
if err != nil {
	return err
}

// tx is a *solana.Transaction from solana-go v2
res, err := signer.SignTransaction(ctx, tx)
```

- [Guida Go](/docs/tools/keychain/getting-started/go) - Moduli, capability
  e configurazione dei backend
- [pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2) -
  Riferimento Go
