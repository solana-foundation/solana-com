## Installazione

Installa il pacchetto principale o i singoli signer secondo necessità:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Richiede `@solana/kit` 8.1 o versioni successive. Le transazioni v1
(`createTransactionMessage({ version: 1 })`) sono supportate, tranne da Fireblocks
con `useProgramCall: true`, che accetta solo transazioni legacy e v0.

## Utilizzo di base

### Factory unificata (Consigliata per le app che desiderano supportare più signer)

Utilizza `createKeychainSigner` con una configurazione discriminata per creare
qualsiasi backend:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Oppure installa un singolo pacchetto signer per un footprint di dipendenze
ridotto:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Utilizzo con i messaggi di transazione

Ogni backend, eccetto Crossmint e la modalità nativa di Fordefi, restituisce un
`SolanaTransactionSigner`, che è un `TransactionPartialSigner` di Kit e funziona
con gli helper per partial signer di `@solana/signers` riportati di seguito. I backend
con broadcast gestito sono trattati in [Signer Capabilities](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Firmare e inviare con qualsiasi signer

`signAndSendTransaction` di `@solana/keychain-core` porta una transazione on-chain
qualunque sia la forma del signer. I signer di tipo sending effettuano il broadcast tramite il
proprio provider; ogni altra forma usa la funzione `sendTransaction` che
passi come argomento (il core non ha dipendenze RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Utilizzo con un Kit Client (plugin keychainSigner)

`@solana/keychain-kit-plugin` installa un keychain signer direttamente su un
[Kit client](https://github.com/anza-xyz/kit), collegandolo come `payer` e
`identity` così da evitare la configurazione manuale di `pipe` mostrata in
precedenza:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Il plugin accetta la stessa configurazione con tag del backend di `createKeychainSigner`,
tranne Crossmint e la modalità nativa di Fordefi (con `chain` impostato). Questi backend riscrivono
la transazione lato server, quindi non possono fungere da `payer` o
`identity` del client; il plugin li rifiuta sia in fase di compilazione sia in fase di esecuzione. Viene incluso nel bundle solo il
backend a cui viene delegata la richiesta (i pacchetti dei backend vengono caricati tramite
`import()` dinamico).

Usa `keychainPayer` o `keychainIdentity` per impostare un solo ruolo e combinare
backend su un singolo client:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Hai già un `SolanaTransactionSigner`? È un `TransactionPartialSigner`
di Kit valido, quindi puoi installarlo con
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
(`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Annullamento e broadcast non confermati

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` e
`signMessages` accettano tutti `{ abortSignal }` come secondo argomento. L'annullamento
interrompe l'attesa, ma non annulla il lavoro che un provider ha già accettato.

Nella modalità nativa automatica di Crossmint e Fordefi, un errore non significa che nulla
sia stato registrato. Quando il provider potrebbe aver accettato la transazione, il codice di errore è
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` viene impostato quando la creazione è stata accettata, e
`context.idempotencyKey` contiene la chiave derivata dal messaggio. Reinviare la
transazione identica byte per byte è sicuro; una transazione ricostruita (ad esempio con un nuovo
blockhash) è un nuovo trasferimento. `providerMayHaveAccepted(error)` e
`providerStatus(error)` di `@solana/keychain-core` aiutano a classificare l'errore.
Verifica lo stato con il provider prima di riprovare.

`privateKeyPath`:

```typescript

  privateKeyPath: "/path/to/id.json"
});
```

### Crossmint

```typescript
import { createCrossmintSigner } from "@solana/keychain-crossmint";

const signer = await createCrossmintSigner({
  apiKey: "api_key",
  walletLocator: "wallet_locator"
});
```

Crossmint supporta solo l'invio. La sua API esegue sempre una transazione approvata
lato server e sponsorizza il gas, quindi il signer espone solo
`signAndSendTransactions()`: non ha `signTransactions()` né `signMessages()`
ed è impossibile installarlo con `@solana/keychain-kit-plugin`. La firma restituita
identifica la transazione registrata da Crossmint.

```typescript
const [signature] = await signer.signAndSendTransactions([transaction]);
// or: await signAndSendTransactionMessageWithSigners(transactionMessage);
```

### Fordefi

Fordefi prevede tre modalità di firma, definite alla creazione tramite `chain` e
`pushMode`. Ogni modalità espone esattamente un metodo per le transazioni, e tutte e tre firmano
i messaggi:

| Modalità          | Configurazione                                      | Tipo                        | Metodo                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Black box     | `chain` non impostato                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Native auto   | `chain` impostato, `pushMode` omesso o `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Native manual | `chain` impostato, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

Le richieste API sono autenticate con una firma della richiesta ECDSA P-256: fornisci la
chiave di firma come `privateKeyPem`, oppure conservala in un KMS/HSM passando un
`requestSigner`.

**Modalità native auto** (consigliata per l'uso on-chain): imposta `chain` e Fordefi
firma ed effettua il broadcast della transazione autonomamente. Poiché Fordefi può sostituire il
blockhash o le commissioni prima della firma, il signer è un `TransactionSendingSigner`
di Kit: usalo con
`signAndSendTransactionMessageWithSigners`, non con il flusso dei partial signer mostrato
sopra. La modalità native auto accetta solo una transazione non firmata il cui unico
firmatario richiesto è il vault, e non può essere usata con `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Modalità native manual**: imposta `chain` e `pushMode: "manual"`. Fordefi riscrive
il messaggio (blockhash recente, istruzioni di commissione del Compute Budget) e lo firma,
ma non effettua il broadcast. `modifyAndSignTransactions()` restituisce la transazione
firmata da Fordefi, che sostituisce quella che hai inviato: prosegui sempre dalla
transazione restituita. Fordefi deve essere il fee payer e deve firmare prima di qualsiasi
altro firmatario richiesto. La riscrittura non viene confrontata con l'originale (nessun diff), quindi controlla il risultato prima di
fare il broadcast.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Modalità black box**: ometti `chain`. Fordefi firma i byte grezzi e non trasmette la transazione; sei tu ad assemblare e inviare la transazione. Utilizzala con un vault black box di Fordefi.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Signer Capabilities

`@solana/keychain-core` definisce un'interfaccia per ciascuna forma di signer di Kit. Ognuna aggiunge
`isAvailable(): Promise<boolean>` all'interfaccia corrispondente di `@solana/signers`:

- `SolanaTransactionSigner` (`TransactionPartialSigner` di Kit): restituisce le firme
  per una transazione di cui sei in possesso.
- `SolanaModifyingSigner` (`TransactionModifyingSigner` di Kit): riscrive la
  transazione, la firma e restituisce la nuova transazione senza effettuare il broadcast.
- `SolanaSendingSigner` (`TransactionSendingSigner` di Kit): firma ed effettua il broadcast
  tramite il proprio provider.
- `SolanaMessageSigner` (`MessagePartialSigner` di Kit): firma messaggi off-chain.
  È distinto dalle forme per le transazioni.

`SolanaSigner` è l'unione delle tre forme per le transazioni. Il tipo di ritorno di ogni factory
indica la forma esatta del suo backend. Quando la configurazione è nota solo in
fase di esecuzione, restringi il tipo con `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` o `isSolanaMessageSigner`. `signerCapabilities(signer)`
restituisce tutte e quattro le informazioni in una volta.

| Backend                                                                                                     | Forma                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (black box) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (senza firma di messaggi)  |
| fordefi (native manual)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (native auto)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (senza firma di messaggi)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Creazione di Signer Personalizzati

Implementa le interfacce di capability supportate dal tuo backend:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Implementa solo ciò che il tuo backend supporta. Kit classifica i signer in base ai
metodi presenti, quindi non aggiungere mai un metodo che si limita a generare un errore.

Consulta la [guida all'aggiunta di Signer](/docs/tools/keychain/adding-signers)
per integrare servizi aggiuntivi di gestione delle chiavi.
