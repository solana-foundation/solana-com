2.0.0 è la prima release stabile dei moduli Go, quindi non c'è nulla da
migrare. La
[guida alla migrazione 2.0](https://github.com/solana-foundation/solana-keychain/blob/main/docs/MIGRATING_V2.md)
descrive la stessa suddivisione delle capacità per Rust e TypeScript.

## Installazione

Ogni backend è un modulo Go a sé stante, così la tua build e il tuo grafo dei moduli contengono
solo i backend che importi:

```shell
go get github.com/solana-foundation/solana-keychain/go/core/v2                # Interfaces, errors, helpers
go get github.com/solana-foundation/solana-keychain/go/signers/memory/v2      # Local keypair signer
go get github.com/solana-foundation/solana-keychain/go/signers/vault/v2       # HashiCorp Vault
go get github.com/solana-foundation/solana-keychain/go/signers/awskms/v2      # AWS KMS
go get github.com/solana-foundation/solana-keychain/go/signers/gcpkms/v2      # GCP KMS
go get github.com/solana-foundation/solana-keychain/go/signers/privy/v2       # Privy
go get github.com/solana-foundation/solana-keychain/go/signers/turnkey/v2     # Turnkey
go get github.com/solana-foundation/solana-keychain/go/signers/fireblocks/v2  # Fireblocks
go get github.com/solana-foundation/solana-keychain/go/signers/cdp/v2         # Coinbase Developer Platform
go get github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2   # Crossmint
go get github.com/solana-foundation/solana-keychain/go/signers/dfns/v2        # Dfns
go get github.com/solana-foundation/solana-keychain/go/signers/openfort/v2    # Openfort
go get github.com/solana-foundation/solana-keychain/go/signers/para/v2        # Para
go get github.com/solana-foundation/solana-keychain/go/signers/utila/v2       # Utila
go get github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2     # Fordefi
```

I moduli sono taggati `go/<module>/v2.0.0` (ad esempio
`go/signers/memory/v2.0.0`). Ogni modulo richiede Go 1.25.0, tranne `gcpkms`,
che richiede Go 1.25.8 a causa del requisito minimo imposto da `google.golang.org/api`.
Ledger è solo Rust e non ha un modulo Go.

### Transazioni solana-go v2 e v1

I moduli sono basati su
[`github.com/solana-foundation/solana-go/v2`](https://github.com/solana-foundation/solana-go)
v2.0.0 e accettano il suo `*solana.Transaction`. Sono supportate le transazioni legacy, v0 e v1
(`solana.MessageVersionV1`), fatta eccezione per Fireblocks
con `UseProgramCall: true`, che accetta solo legacy e v0.

## Utilizzo di base

Ogni signer implementa la
[`core.SolanaSigner` interface](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2#SolanaSigner)
di base (`Pubkey`, `SignMessage`, `IsAvailable`). I metodi accettano un `context.Context` e
sono bloccanti. Inoltre, ogni backend implementa esattamente una interfaccia di capacità:

- `core.TransactionSigner`: `SignTransaction` firma la transazione così com'è.
- `core.ModifyingSigner`: `ModifyAndSignTransaction` consente al provider di riscrivere
  la transazione, quindi la firma.
- `core.SendingSigner`: `SignAndSendTransaction` fa sì che il provider la firmi e la
  trasmetta.

Ogni pacchetto backend espone una struct `Config` e un costruttore `New`:

```go
import (
	"context"
	"fmt"

	"github.com/solana-foundation/solana-go/v2"
	"github.com/solana-foundation/solana-keychain/go/core/v2"
	"github.com/solana-foundation/solana-keychain/go/signers/memory/v2"
)

func signWithKeychain(ctx context.Context, tx *solana.Transaction) error {
	signer, err := memory.New(memory.Config{PrivateKeyPath: "/path/to/id.json"})
	if err != nil {
		return err
	}

	if !signer.IsAvailable(ctx) {
		return core.NewSignerError(core.CodeNotAvailable, "signer offline")
	}

	result, err := signer.SignTransaction(ctx, tx)
	if err != nil {
		return err
	}
	fmt.Println("signature:", result.Signature)
	fmt.Println("complete:", result.IsComplete())
	// result.EncodedTransaction is the base64 wire transaction
	return nil
}
```

`SignTransaction` e `ModifyAndSignTransaction` restituiscono un
`core.SignedTransaction` (`EncodedTransaction`, `Signature`, `Completeness`).
I backend HTTP remoti accettano un `HTTPClient` e un `HTTPClientConfig` opzionali
(timeout). Il client predefinito impone HTTPS; fornendo il tuo client si aggira questo vincolo
e sei tu a rispondere della sua sicurezza.

### Capacità dei signer

Un backend che non può firmare una transazione non ha alcun metodo `SignTransaction`,
quindi la capacità è un dato noto in fase di compilazione per i tipi concreti e una type
assertion per un `core.SolanaSigner`:

| Backend                                                                         | Capacità          | `SignMessage`                  |
| ------------------------------------------------------------------------------- | ------------------- | ------------------------------ |
| memory, vault, privy, turnkey, awskms, gcpkms, fireblocks, dfns, para, openfort | `TransactionSigner` | Sì                            |
| cdp                                                                             | `TransactionSigner` | Solo payload UTF-8            |
| utila                                                                           | `TransactionSigner` | Fallisce con `CodeSigningFailed` |
| fordefi black box (`fordefi.BlackBoxSigner`)                                    | `TransactionSigner` | Sì                            |
| fordefi native manual (`fordefi.NativeManualSigner`)                            | `ModifyingSigner`   | Sì                            |
| fordefi native auto (`fordefi.NativeAutoSigner`)                                | `SendingSigner`     | Sì                            |
| crossmint                                                                       | `SendingSigner`     | Fallisce con `CodeSigningFailed` |

```go
switch s := signer.(type) {
case core.SendingSigner:
	sig, err := s.SignAndSendTransaction(ctx, tx)
case core.ModifyingSigner:
	signed, err := s.ModifyAndSignTransaction(ctx, tx)
case core.TransactionSigner:
	signed, err := s.SignTransaction(ctx, tx)
}
```

### Inizializzazione

Non esiste un passaggio `Init` separato. Privy, Fireblocks, Dfns, Crossmint, Para,
Openfort e Utila risolvono l'indirizzo del wallet all'interno di `New`, motivo per cui i loro
costruttori accettano un `context.Context`. Crea sempre i signer tramite `New`: un
signer Crossmint, Para o Utila a valore zero fallisce con `CodeNotInitialized`
anziché firmare per l'indirizzo zero.

### Firmare e inviare con qualsiasi signer

`core.SignAndSendTransaction` porta una transazione on-chain indipendentemente dalla
forma del signer. Un `SendingSigner` trasmette tramite il proprio provider e ignora la funzione
di invio; ogni altra forma firma e la tua funzione trasmette il risultato
in base64, che per un `ModifyingSigner` è la transazione riscritta dal suo provider.
Core non ha dipendenze RPC:

```go
import "github.com/solana-foundation/solana-go/v2/rpc"

client := rpc.New("https://api.devnet.solana.com")

sig, err := core.SignAndSendTransaction(ctx, signer, tx,
	func(ctx context.Context, encoded string) (solana.Signature, error) {
		return client.SendEncodedTransaction(ctx, encoded)
	})
```

### Firma in batch

La firma in batch è fornita come helper liberi, concorrenti, con un
scaglionamento opzionale per richiesta per le API con limiti di frequenza:

```go
sigs, err := core.SignMessages(ctx, signer, [][]byte{msg1, msg2}, core.BatchOptions{
	MaxConcurrency: 4, // 0 = unbounded
	RequestDelay:   50 * time.Millisecond,
})

signed, err := core.SignTransactions(ctx, signer, txs, core.BatchOptions{})
```

`core.SignTransactions` accetta un `core.TransactionSigner`, quindi i
signer che gestiscono il broadcast (Crossmint, Fordefi native auto) e Fordefi native
manual non possono essere processati in batch; chiamali una transazione alla volta. Un
signer le cui chiamate creano lavoro lato provider (Fireblocks con `UseProgramCall`)
lo segnala tramite `core.BatchServerSideEffects`, e il batch viene quindi eseguito
in sequenza.

## Configurazione del backend

### Memory

Fornisci esattamente uno tra `PrivateKey` (byte grezzi), `PrivateKeyString` (base58 o un
array di byte `[1,2,...]`) o `PrivateKeyPath` (file keypair della Solana CLI):

```go
import "github.com/solana-foundation/solana-keychain/go/signers/memory/v2"

signer, err := memory.New(memory.Config{
	PrivateKeyPath: "/path/to/id.json",
})
```

Go non offre un modo affidabile per azzerare la memoria: il garbage collector può copiare e
conservare i byte delle chiavi (i keypair in memoria e le chiavi che Crossmint e Openfort derivano
localmente) fino alla raccolta. Considera l'intera memoria del processo come sensibile quando
usi backend con chiavi locali.

import "github.com/solana-foundation/solana-keychain/go/signers/vault/v2"

signer, err := vault.New(vault.Config{

	Token:     "hvs.xxxxx",

### Crossmint

Crossmint è solo per l'invio: la sua API esegue ogni transazione approvata
lato server, quindi `*crossmint.Signer` ha `SignAndSendTransaction` ma non
`SignTransaction`. La tua transazione non viene mai modificata; la firma restituita
identifica la transazione che Crossmint ha portato on-chain, che può differire dalla tua se
Crossmint sponsorizza il gas.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/crossmint/v2"

signer, err := crossmint.New(ctx, crossmint.Config{
	APIKey:        "api_key",
	WalletLocator: "wallet_locator",
	SignerSecret:  "", // optional xmsk1_ secret: auto-approves what Crossmint presents
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

### Fordefi

Fordefi è disponibile in tre tipi di signer, determinati alla costruzione da `Config.Chain` e
`Config.PushMode`. Tutti e tre firmano messaggi:

| Config                                          | Tipo                          | Entry point                |
| ----------------------------------------------- | ----------------------------- | -------------------------- |
| `Chain` non impostato                                   | `*fordefi.BlackBoxSigner`     | `SignTransaction`          |
| `Chain` impostato, `PushMode` non impostato o `PushModeAuto` | `*fordefi.NativeAutoSigner`   | `SignAndSendTransaction`   |
| `Chain` impostato, `PushMode: PushModeManual`         | `*fordefi.NativeManualSigner` | `ModifyAndSignTransaction` |

`fordefi.New` smista in base alla configurazione e restituisce un `core.SolanaSigner`;
`fordefi.NewBlackBox`, `fordefi.NewNativeAuto` e `fordefi.NewNativeManual`
restituiscono il tipo concreto e rifiutano le configurazioni delle altre modalità. Le richieste API sono
autenticate con una firma della richiesta ECDSA P-256: fornisci esattamente uno tra
`PrivateKeyPEM` oppure un `RequestSigner` per mantenere quella chiave in un KMS/HSM.

**Modalità native auto**: Fordefi può sostituire il blockhash e le commissioni, quindi firma e
trasmette. Accetta solo una transazione non firmata il cui unico firmatario richiesto
è il vault.

```go
import "github.com/solana-foundation/solana-keychain/go/signers/fordefi/v2"

signer, err := fordefi.NewNativeAuto(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"), // Solana vault address (base58)
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet, // or fordefi.ChainSolanaMainnet
	Fee: &fordefi.Fee{
		Type:          fordefi.FeeTypePriority,
		PriorityLevel: fordefi.PriorityMedium,
	},
})

sig, err := signer.SignAndSendTransaction(ctx, tx)
```

**Modalità native manual**: imposta `PushMode: fordefi.PushModeManual`. Fordefi riscrive
il messaggio (recent blockhash, istruzioni di commissione del Compute Budget) e lo firma
senza trasmetterlo. `ModifyAndSignTransaction` sostituisce `tx` con la
transazione firmata da Fordefi: prosegui sempre da quella. Fordefi deve essere il
fee payer e deve firmare prima di qualsiasi altro firmatario richiesto, poiché la riscrittura invalida
le firme esistenti. La riscrittura non viene confrontata con l'originale, quindi controlla il risultato prima di
trasmettere.

```go
signer, err := fordefi.NewNativeManual(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
	Chain:         fordefi.ChainSolanaDevnet,
	PushMode:      fordefi.PushModeManual,
})

signed, err := signer.ModifyAndSignTransaction(ctx, tx)
```

**Modalità black box**: lascia `Chain` non impostato. Fordefi firma esattamente i byte del tuo messaggio
e non trasmette. Usala con un vault Fordefi black box.

```go
signer, err := fordefi.NewBlackBox(ctx, fordefi.Config{
	AccessToken:   os.Getenv("FORDEFI_ACCESS_TOKEN"),
	VaultID:       os.Getenv("FORDEFI_BB_VAULT_ID"),
	PublicKey:     os.Getenv("FORDEFI_BB_PUBLIC_KEY"),
	PrivateKeyPEM: string(pemBytes),
})
```

## Perché non esiste un pacchetto ombrello

Rust ha un enum `Signer` e TypeScript ha `createKeychainSigner`; Go
volutamente non ha né l'uno né l'altro. Go non elimina il dead code attraverso uno switch di
dispatch a runtime, quindi un pacchetto ombrello forzerebbe l'SDK del fornitore di ogni backend (AWS, GCP
e gli altri) nella build di ogni consumatore. Importare il pacchetto backend di cui hai
bisogno è il selettore. Per scegliere un backend a runtime, scrivi lo switch nel tuo
codice solo per i backend che supporti e conserva il risultato come
`core.SolanaSigner`.

## Gestione degli errori

Ogni errore è un `*core.SignerError` con un `Code` stabile (`CodeConfigError`,
`CodeHTTPError`, `CodeRemoteAPIError`, `CodeSigningFailed`,
`CodeNotInitialized`, `CodeBroadcastUnconfirmed` e altri). `Error()` restituisce
solo un messaggio fisso per codice, mai materiale di chiave o risposte grezze del provider.
Effettua il confronto con `errors.As`, `errors.Is(err, &core.SignerError{Code: ...})` o
`core.CodeOf(err)`.

Con Crossmint e Fordefi native auto mode, un errore non significa che nulla sia
andato a buon fine. Quando il provider potrebbe aver accettato la transazione, il codice è
`core.CodeBroadcastUnconfirmed` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`ProviderTxID` viene impostato quando la creazione è stata accettata, e `IdempotencyKey` contiene
la chiave derivata dal messaggio. Reinviare la transazione identica byte per byte è
sicuro; una transazione ricostruita (ad esempio con un nuovo blockhash) è un nuovo trasferimento.
`core.SignAndSendTransaction` segnala questo codice anche quando la tua funzione di invio
fallisce, con la firma del fee payer in `TransactionSignature`. Fireblocks
PROGRAM_CALL è solo firma e non invia alcuna chiave; segnala questo codice solo quando un
polling mostra che Fireblocks ha comunque trasmesso.

```go
sig, err := core.SignAndSendTransaction(ctx, signer, tx, send)
var se *core.SignerError
if errors.As(err, &se) && se.Code == core.CodeBroadcastUnconfirmed {
	// Reconcile se.ProviderTxID, se.IdempotencyKey or se.TransactionSignature
	// with the provider before retrying.
}
```

Consulta il
[modello di sicurezza](https://github.com/solana-foundation/solana-keychain/blob/main/docs/SECURITY_MODEL.md)
per le garanzie offerte da ciascuna forma di firma, il
[README di Go](https://github.com/solana-foundation/solana-keychain/blob/main/go/README.md)
per l'elenco completo dei moduli e
[pkg.go.dev](https://pkg.go.dev/github.com/solana-foundation/solana-keychain/go/core/v2)
per il riferimento API.

## Aggiungere signer personalizzati

Implementa `core.SolanaSigner` più esattamente una interfaccia di capacità, e non aggiungere alcun
metodo che il tuo backend non possa onorare: i chiamanti rilevano la capacità tramite type assertion.
Consulta la [guida Adding Signers](/docs/tools/keychain/adding-signers) per integrare
ulteriori servizi di gestione delle chiavi.
