## Gestione delle chiavi

- **Non esporre mai le chiavi private nel codice frontend.** Usa la firma lato backend, hardware
  wallet, wallet multifirma o servizi di gestione delle chiavi.
- **Separa hot wallet e cold wallet.** Hot wallet per le operazioni, cold wallet per la
  tesoreria.
- **Esegui il backup di tutte le chiavi di produzione.** Conserva backup cifrati in più
  luoghi sicuri. Perdere una chiave significa perdere l'accesso in modo permanente.
- **Usa chiavi diverse per devnet e mainnet.** Le chiavi di devnet non dovrebbero essere
  le stesse di mainnet. Usa una configurazione basata sull'ambiente per assicurarti che vengano
  caricate le chiavi giuste per ciascuna rete.

## Infrastruttura di firma

Per la firma backend in produzione, usa [Keychain](/docs/tools/keychain), una libreria di
firma unificata che astrae più backend di gestione delle chiavi attraverso un'unica
interfaccia: Memory, Vault, Privy, Turnkey, AWS KMS, Fireblocks, GCP KMS, CDP,
Para, Dfns, Crossmint, Openfort e Utila. Ti consente di sviluppare in locale con
chiavi in memoria, per poi passare a backend di livello produttivo senza modificare il
codice dell'applicazione.

Non sai quale backend faccia al caso tuo? Consulta
[Scegliere un backend](/docs/tools/keychain/choosing-a-backend). Keychain è
disponibile sia per [Rust](https://crates.io/crates/solana-keychain) che per
[TypeScript](https://www.npmjs.com/package/@solana/keychain).

## Sicurezza RPC

Tratta gli endpoint RPC come chiavi API: non esporli nel codice frontend, dove
possono essere estratti e usati in modo improprio. Usa un proxy backend o variabili d'ambiente che
non vengano incluse nel bundle del codice client.

- [QuickNode: Endpoint Security Best Practices](https://www.quicknode.com/guides/quicknode-products/endpoint-security/endpoint-security-best-practices)
- [Helius: Protect Your Solana API Keys: Security Best Practices](https://www.helius.dev/docs/rpc/protect-your-keys)

## Monitoraggio

Monitora queste metriche in produzione:

| Metrica                   | Perché                    |
| ------------------------ | ---------------------- |
| Tasso di successo delle transazioni | Individua i problemi in anticipo    |
| Latenza di conferma     | Monitora lo stato di salute della rete |
| Spesa per le priority fee       | Gestione dei costi        |
| Tasso di errori RPC           | Stato di salute del provider        |

Configura degli avvisi per:

- Trasferimenti dalla tesoreria superiori a una soglia
- Picchi nel tasso di transazioni fallite
- Schemi anomali dei destinatari
- Aumenti del tasso di errori RPC

Per il monitoraggio delle transazioni in tempo reale su larga scala, consulta la nostra
[Guida all'indicizzazione](/docs/payments/accept-payments/indexing).

## Verifica degli indirizzi

Ogni token e ogni programma ha esattamente un indirizzo corretto su mainnet. I token
contraffatti che imitano USDC o altre stablecoin sono comuni: hanno lo stesso nome
e simbolo, ma un mint diverso. La tua applicazione dovrebbe codificare in modo fisso o inserire in una allowlist
gli indirizzi dei mint (in base alle tue esigenze), senza mai accettarli dinamicamente
da fonti non attendibili.

**Configurazione basata sull'ambiente:** Devnet e Mainnet usano spesso mint di token
completamente diversi. Configura l'applicazione in modo che carichi gli indirizzi corretti
per ogni ambiente: non codificare in modo fisso gli indirizzi di mainnet dimenticando di sostituirli
durante i test e, peggio ancora, non rilasciare in produzione indirizzi di devnet.

Alcuni mint comuni di stablecoin sono:

| Token | Emittente | Indirizzo del mint                                   |
| ----- | ------ | ---------------------------------------------- |
| USDC  | Circle | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` |
| USDT  | Tether | `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB` |
| PYUSD | PayPal | `2b1kV6DkPAnxd5ixfnxCpjxmKwqjjaYmCZfHsFu24GXo` |
| USDG  | Paxos  | `2u1tszSeqZ3qBWF3uNGPFc8TzMk2tdiwknnRMWGWjGWH` |

Anche gli indirizzi dei programmi sono importanti. Inviare istruzioni al programma sbagliato
fallirà oppure, peggio, comporterà la perdita irreversibile dei fondi. Gli indirizzi del Token Program
sono:

| Programma            | Indirizzo                                       |
| ------------------ | --------------------------------------------- |
| Token Program      | `TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA` |
| Token-2022 Program | `TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb` |

Inserire in una allowlist gli indirizzi giusti protegge dai token contraffatti, ma
non protegge dall'invio a un _tipo_ di account sbagliato. L'indirizzo di un destinatario
può essere un wallet, un token account, un mint o un programma, e ciascuno richiede una
gestione diversa. I SOL nativi inviati a qualsiasi cosa diversa da un wallet escono dal controllo del
mittente — persi definitivamente se inviati a un mint o a un programma, recuperabili solo dal
proprietario dell'account se inviati a un token account — senza alcuna transazione fallita che avvisi l'utente.

<Callout type="warn" title="Convalida i destinatari prima dell'invio">
  Classifica ogni indirizzo destinatario prima di firmare un trasferimento. Consulta [Verifica
  dell'indirizzo](/docs/payments/send-payments/verify-address) per l'albero decisionale completo
  e il codice di riferimento che distingue wallet, token account, mint e
  programmi.
</Callout>
