# Lavorare con LLM e Agenti su Solana

Prima di esaminare gli strumenti specifici, vediamo i componenti chiave dello
stack di sviluppo AI:

## Comprendere lo Stack AI

1. **Large Language Model (LLM)**
   - I modelli AI fondamentali (come GPT-4, Claude o Llama)
   - Elaborano e generano linguaggio naturale
   - Forniscono intelligenza grezza e capacità di ragionamento
   - Esempi: GPT-4 di OpenAI, Claude di Anthropic, Llama di Meta

2. **Framework per Agenti (come Eliza)**
   - Costruiti sopra gli LLM per creare agenti autonomi
   - Gestiscono le personalità e i comportamenti degli agenti
   - Gestiscono memoria e contesto
   - Forniscono integrazione multi-piattaforma
   - Esempi: Eliza, LangChain, AutoGPT, Vercel AI

3. **Kit per Agenti Specifici del Dominio (come Solana Agent Kit)**
   - Costruiti per casi d'uso specifici (es. operazioni blockchain)
   - Forniscono strumenti e integrazioni predefiniti
   - Astraggono la complessità tecnica
   - Funzioni blockchain pronte all'uso
   - Esempi: Solana Agent Kit, GOAT Toolkit

Pensa a come se fosse così:

- Gli LLM sono il "cervello" che può comprendere e generare linguaggio
- I framework per agenti sono il "sistema operativo" che gestisce il comportamento dell'AI
- I kit specifici del dominio sono le "app" che conferiscono all'AI capacità specifiche

# Costruire Agenti AI per Solana

Questa guida ti mostrerà come:

- Costruire un agente AI di base usando Solana Agent Kit di SendAI
- Creare un bot Twitter con il Framework Eliza
- Comprendere le opzioni di integrazione AI onchain
- Opzioni su come costruire bot di trading avanzati

## Introduzione agli Agenti AI su Solana

Gli agenti AI su Solana sono programmi autonomi in grado di interagire con la
blockchain utilizzando l'elaborazione del linguaggio naturale e il machine learning. Possono:

- Eseguire transazioni
- Monitorare l'attività della blockchain
- Interagire con gli smart contract
- Fornire assistenza agli utenti
- Automatizzare flussi di lavoro complessi

## Framework Disponibili

Sono disponibili diversi framework per la costruzione di agenti AI su Solana:

1. **Solana Agent Kit di SendAI**

- Una raccolta di strumenti per costruire agenti su Solana
- Compatibile con Eliza, Langchain e Vercel AI SDK
- Strumenti e utility Solana integrati
- Capacità di elaborazione del linguaggio naturale
- [Solana Agent Kit](https://github.com/sendaifun/solana-agent-kit)
- [Documentazione](https://docs.solanaagentkit.xyz/)

2. **Eliza Framework**

- Combina datalayer, LLM e agenti e dispone di un plugin Solana dedicato
- Architettura degli agenti estensibile
- Facile integrazione con progetti esistenti e può essere utilizzato ad esempio per
  bot su Twitter (X), Telegram o Discord
- [Repository GitHub](https://github.com/elizaOS/eliza)

3. **GOAT Toolkit**

- Toolkit di sviluppo completo
- Compatibilità cross-chain
- [Repository GitHub](https://github.com/goat-sdk/goat)

4. **Rig Framework**

- Implementazione nativa in Rust
- Ottimo per bot di trading ad alte prestazioni
- Può essere combinato con il toolkit Listen.rs per l'integrazione con Solana, il monitoraggio delle transazioni
  e l'invio di transazioni tramite bundle Jito, ad esempio
- [Repository GitHub](https://github.com/0xPlaygrounds/rig)
- [Repository Listen.rs](https://github.com/piotrostr/listen)

Se stai costruendo un framework AI, sentiti libero di aprire una PR per aggiungere il tuo framework
all'elenco

### Crea lo script dell'agente

Crea un nuovo file chiamato `agent.ts` con il seguente contenuto:

```typescript filename=agent.ts
import { SolanaAgentKit, createSolanaTools } from "solana-agent-kit";
import { HumanMessage } from "@langchain/core/messages";
import { ChatOpenAI } from "@langchain/openai";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { MemorySaver } from "@langchain/langgraph";
import * as dotenv from "dotenv";
import bs58 from "bs58";
import * as readline from "readline";

dotenv.config();

async function initializeAgent() {
  const llm = new ChatOpenAI({
    modelName: "gpt-4-turbo-preview",
    temperature: 0.7
  });

  // Convert array string to actual array, then to Uint8Array, then to base58
  const privateKeyArray = JSON.parse(process.env.SOLANA_PRIVATE_KEY!);
  const privateKeyUint8 = new Uint8Array(privateKeyArray);
  const privateKeyBase58 = bs58.encode(privateKeyUint8);

  const solanaKit = new SolanaAgentKit(privateKeyBase58, process.env.RPC_URL!, {
    OPENAI_API_KEY: process.env.OPENAI_API_KEY!
  });

  const tools = createSolanaTools(solanaKit);
  const memory = new MemorySaver();

  return createReactAgent({
    llm,
    tools,
    checkpointSaver: memory
  });
}

async function runInteractiveChat() {
  const agent = await initializeAgent();
  const config = { configurable: { thread_id: "Solana Agent Kit!" } };
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout
  });

  // Clear console and start chat with a small delay
  setTimeout(() => {
    console.clear(); // Clear any initialization messages
    console.log("Chat with Solana Agent (type 'exit' to quit)");
    console.log("--------------------------------------------");
    askQuestion();
  }, 100);

  const askQuestion = () => {
    rl.question("You: ", async (input) => {
      if (input.toLowerCase() === "exit") {
        rl.close();
        return;
      }

      const stream = await agent.stream(
        {
          messages: [new HumanMessage(input)]
        },
        config
      );

      process.stdout.write("Agent: ");
      for await (const chunk of stream) {
        if ("agent" in chunk) {
          process.stdout.write(chunk.agent.messages[0].content);
        } else if ("tools" in chunk) {
          process.stdout.write(chunk.tools.messages[0].content);
        }
      }
      console.log("\n--------------------------------------------");

      askQuestion(); // Continue the conversation
    });
  };
}

runInteractiveChat().catch(console.error);
```

## Costruire con il Framework Eliza

[ElizaOS](https://github.com/elizaOS/eliza) (precedentemente noto come Ai16z) è un
framework AI. Significa che combina più applicazioni in una sola e
organizza le loro interazioni. Combina:

1. Diversi LLM per comprendere l'utente
2. Agenti blockchain con diverse azioni (come ad esempio il conio di un NFT)
3. Datalayer per memorizzare lo stato dei personaggi tra le azioni usando ad esempio
   Redis, PostgreSQL DB o storage locale
4. Diversi client come X, Telegram, Discord, ecc.

Prende tutte queste cose e le mette insieme in modo tale da poter creare un
"Personaggio" che può interagire con gli utenti o operare autonomamente. Questi Personaggi sono
definiti in un file JSON, che definisce quali azioni può eseguire, quale LLM
dovrebbe usare e i diversi prompt che definiscono il comportamento del personaggio.

### Crea la configurazione del personaggio

Per creare un nuovo personaggio dobbiamo creare un file character.json. Puoi trovare
i personaggi preimpostati nella cartella characters del progetto Eliza. Per creare un
nuovo personaggio puoi copiare e modificare uno dei personaggi già esistenti, oppure
puoi usare la
[funzionalità composer in Cursor](https://docs.cursor.com/composer/overview) e indicargli
che tipo di personaggio vuoi creare.

```json filename=characters/sol.character.json
{
    "name": "Sol",
    "clients": ["twitter"],
    "modelProvider": "openai",
    "settings": {
        "voice": {
            "model": "en_US-neural"
        },
        ...
```

La parte importante qui sono i client e il modelProvider. Nel nostro caso
vogliamo usare Twitter come client e OpenAI come provider del modello, poiché è
ciò per cui abbiamo anche impostato i nostri segreti nel file `.env`.

Ora che la configurazione è completata, possiamo avviare il nostro personaggio:

```bash

```

Questo avvierà l'agente e potrai ora interagire con esso su Twitter. Il
personaggio inizierà automaticamente a pubblicare tweet ogni poche ore e quando
interagiamo con lui sarà in grado di eseguire azioni Solana come il conio di NFT
ad esempio.

Qui puoi vedere il
[personaggio in azione](https://x.com/solanadevhelper/status/1882222232656847143).

Puoi anche interagire con il personaggio localmente usando il seguente comando:
Potresti dover liberare la porta 3000 e avviare il tuo personaggio con il flag `--host`.

```bash

pnpm start:client
```

Se il tuo client non si connette, assicurati di eseguire l'agente con il flag `--host`
e che la porta 3000 non sia in uso quando avvii il client.

Per ulteriori informazioni segui la

## Integrazione di agenti con programmi onchain

Se vuoi utilizzare la risposta di un agente all'interno di un programma Solana, devi usare un
oracle che scriva i dati della risposta in un account che il tuo programma possa leggere.
Puoi trovare un esempio di LLM che trasferirà token a qualsiasi utente che
risponde correttamente alle domande qui:

[Interazione LLM con programma on-chain](https://github.com/GabrielePicco/super-smart-contracts)

Questo è un esempio di programma onchain che si integra con un oracle LLM (AI)
per creare un agente interattivo di distribuzione token chiamato "Mar1o".

### Funzionalità principali

1. **Interazione con l'agente AI**
   - Gli utenti possono chattare con Mar1o per cercare di guadagnare token
   - L'agente valuta la conoscenza di Solana dell'utente per decidere la quantità di token
   - Le risposte sono in formato JSON con testo di risposta e quantità di token

2. **Gestione dei token**
   - Crea token MAR1O con metadati
   - Può coniare tra 0 e 10.000 token in base alla risposta dell'AI
   - Utilizza PDA per la gestione dei token

### Flusso del programma spiegato

Ecco come funziona questo programma:

```rust
// Initialize the AI agent with personality
const AGENT_DESC: &str = "You are an AI agent called Mar1o which can dispense MAR1O tokens...";

// User interaction flow:
// 1. User sends message to agent
// 2. Oracle processes with LLM
// 3. Agent responds with JSON containing reply and amount
// 4. If amount > 0, tokens are minted to user

// Example response:
{
    "reply": "Great answer! Here's a reward.",
    "amount": 1000
}
```

Questo dimostra come combinare le capacità dell'AI con la meccanica dei token onchain per
creare esperienze blockchain interattive. Ecco un
[esempio live](https://mar1o.xyz/) dove puoi provare a convincere l'Agente a
trasferire alcuni token.

## Agenti Rust avanzati per il trading algoritmico

Se vuoi scrivere i tuoi agenti in Rust puoi utilizzare il
[framework Rig](https://github.com/0xPlaygrounds/rig) e la
libreria [Listen.rs](https://github.com/piotrostr/listen).

Questi due strumenti funzionano molto bene insieme. Mentre il framework Rig ti offre un modo semplice per
collegerti agli LLM, il toolkit Listen.rs ti fornisce l'integrazione con Solana,
includendo il monitoraggio delle transazioni e l'invio di transazioni tramite Jito bundle,
ad esempio.

## Best practice

- Tieni presente che il tuo agente possiede una chiave privata e può quindi accedere ai fondi nel tuo
  wallet. Se qualcuno può chattare con il tuo agente e questo dispone di un'azione di trasferimento,
  ad esempio, gli utenti potrebbero riuscire a fargli trasferire i tuoi fondi.
- Usa [endpoint RPC](https://solana.com/rpc) a pagamento. Gli endpoint pubblici
  vengono solitamente soggetti a limitazioni di frequenza
- Monitora le attività dell'agente e assicurati che non stia compiendo azioni dannose
  o che non venga ingannato dagli utenti che interagiscono con esso
- Implementa fee di priorità e nuovi tentativi di transazione nelle azioni del tuo agente, in modo che
  vengano eseguite anche in caso di congestione sulla rete
- Se possibile, testa prima sulla devnet prima di effettuare il deployment sulla mainnet. La maggior parte degli agenti
  accetta semplicemente l'URL RPC come input e puoi utilizzarne uno della devnet finché non sei
  pronto per la mainnet. Tuttavia, non tutte le azioni potrebbero essere realizzabili sulla devnet.
- Quando scrivi le tue azioni personalizzate, aggiungi test di integrazione per esse, in modo che i
  framework possano monitorare quali azioni falliscono a causa di programmi o API modificati
