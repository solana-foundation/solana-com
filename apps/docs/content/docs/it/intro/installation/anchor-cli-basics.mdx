  Questa sezione illustra alcuni comandi comuni della CLI di Anchor per

---

Questa sezione fornisce alcuni comandi ed esempi comuni per aiutarti a iniziare
ad usare la [CLI di Anchor](https://www.anchor-lang.com/docs).

<Steps>
<Step>

### Inizializzare il progetto

Crea un nuovo progetto Anchor eseguendo il comando mostrato di seguito. Verrà creata una
nuova directory con il nome del progetto e verrà usata per inizializzare un nuovo progetto
Anchor.

```terminal
$ anchor init <project-name>
```

Ad esempio, il comando seguente creerà un progetto chiamato `my-project`. La
directory `my-project` conterrà un programma Rust modulare e un template di test
Rust che utilizza LiteSVM.

```terminal
$ anchor init my-project
```

Per generare invece un template di test TypeScript, sceglilo esplicitamente. Ad
esempio, usa il template Mocha:

```terminal
$ anchor init my-project --test-template mocha
```

I template di test TypeScript richiedono Node.js e un package manager JavaScript.

Poi vai alla directory del progetto:

```terminal
$ cd <project-name>
```

Consulta la
[struttura dei file del progetto](https://www.anchor-lang.com/docs/quickstart/local#project-file-structure) di Anchor.

</Step>
<Step>

### Compila il programma

Per compilare il tuo progetto, esegui il seguente comando:

```terminal
$ anchor build
```

Puoi trovare il programma compilato nella directory `/target/deploy`.

<Callout type="warn" title="Installazione dei platform tools non riuscita">
  Se la build segnala una directory platform-tools non valida, reinstalla i tool di
  build SBF, quindi riprova la build:

```terminal
$ cargo build-sbf --force-tools-install
$ anchor build
```

</Callout>

</Step>
<Step>

### Distribuisci il programma

Per distribuire il tuo progetto, esegui il seguente comando:

```terminal
$ anchor deploy
```

Questo comando distribuisce il tuo programma sul `cluster` specificato nel file
[`Anchor.toml`](https://www.anchor-lang.com/docs/references/anchor-toml).

</Step>
<Step>

### Testa il programma

Per testare il tuo progetto, esegui il seguente comando:

```terminal
$ anchor test
```

Questo comando compila, distribuisce ed esegue i test per il tuo progetto.

<Callout>
  Quando si utilizza il cluster `localnet`, Anchor avvia automaticamente un
  validator locale, distribuisce il programma, esegue i test e poi arresta il
  validator.
</Callout>

<Callout type="warn" title="Errori del test runner JavaScript">

Se hai selezionato un template di test JavaScript o TypeScript, uno dei
seguenti errori potrebbe indicare che Node.js o il package manager configurato non
è installato:

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

</Callout>

</Step>
</Steps>
