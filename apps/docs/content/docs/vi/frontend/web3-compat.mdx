---

Nếu bạn đang chuyển từ `@solana/web3.js` (legacy), `@solana/wallet-adapter-*`,
hoặc các gói framework-kit trước đây (`@solana/client`, `@solana/react-hooks`,
`@solana/web3-compat`), chúng tôi khuyến khích bạn chuyển sang các plugin `@solana/kit` hoặc
`@solana/web3.js` v3 (hoặc cao hơn).

Trang này ánh xạ các khái niệm bạn đã biết sang các khái niệm tương đương trong Kit.

## Ánh xạ khái niệm

| web3.js (legacy) / wallet-adapter      | Kit                                                                  |
| -------------------------------------- | -------------------------------------------------------------------- |
| `new Connection(url)`                  | `createSolanaRpc(url)`, hoặc `.use(solanaRpc({ rpcUrl }))` trên client |
| `PublicKey`                            | `Address` — ép kiểu chuỗi bằng `address("...")`                    |
| `Keypair`                              | `generateKeyPairSigner()` hoặc các plugin `@solana/kit-plugin-signer` |
| `SystemProgram.transfer(...)`          | `getTransferSolInstruction(...)` từ `@solana-program/system`       |
| `LAMPORTS_PER_SOL` math                | `lamports(...)` từ `@solana/kit`                                   |
| `Transaction` / `VersionedTransaction` | Transaction message được xây dựng và đóng gói bởi transaction planner     |
| `sendAndConfirmTransaction(...)`       | `client.sendTransaction([...])` (planner ký, gửi và xác nhận) |
| `@solana/wallet-adapter-*`             | `@solana/kit-plugin-wallet` + khám phá Wallet Standard              |

web3.js v3 giữ nguyên các tên theo kiểu class ở trên — `Connection`, `Keypair`,
`Transaction`, `PublicKey` — dưới dạng các lớp bao mỏng (thin wrapper) bên trên phần lõi của Kit, vì vậy cột
Kit cũng mô tả những gì các class này thực hiện bên trong ở v3.

## Bạn đến từ web3.js?

Nếu bạn đang duy trì một codebase `@solana/web3.js` (legacy) lớn và việc viết lại hoàn toàn
sang Kit không khả thi, thì web3.js v3 chính là cầu nối. Hãy cài đặt bằng
`@solana/web3.js@3`. Nó xây dựng lại API kiểu class cổ điển — `Connection`,
`Keypair`, `Transaction`, `PublicKey` — trên nền phần lõi của `@solana/kit`.
Vì được xây dựng trên Kit nên khả năng tương tác rất chặt chẽ: `PublicKey` là kiểu
địa chỉ chính và phương thức `.toBase58()` của nó trả về chuỗi `Address` có gắn nhãn (branded) của Kit, còn `Keypair` ở v3
triển khai `KeyPairSigner` của Kit, nên bạn có thể truyền trực tiếp vào các API của Kit,
plugin và các client do Codama tạo ra.

<Callout type="warn" title="Giao dịch v1 và web3.js (legacy)">
  Nếu bạn gửi giao dịch v1 bằng web3.js, bạn phải sử dụng v3 trở lên.
</Callout>

Về quá trình migration, hãy xem
[hướng dẫn migration web3.js v1 → v3](https://github.com/solana-foundation/solana-web3.js/blob/main/docs/web3js-v1-to-v3-migration.md) chính thức.

## Ví

Kit không sử dụng wallet-adapter. `@solana/kit-plugin-wallet` tự động phát hiện
các ví theo chuẩn Wallet Standard và hiển thị chúng thông qua `client.wallet` và
các [React hook](/docs/frontend/react-hooks). Các ví hiện đại (Phantom,
Solflare, Backpack và nhiều ví khác) tự quảng bá thông qua Wallet Standard, do
đó không cần gói adapter riêng cho từng ví.

Bạn cũng có thể sử dụng các công cụ có sẵn như
[@solana/connector](https://www.npmjs.com/package/@solana/connector), vốn sử
dụng các thành phần nguyên thủy của Kit để kết nối trực tiếp với ví.

<Callout type="info" title="Vẫn đang dùng wallet-adapter?">
  Nếu bạn đang duy trì một ứng dụng được xây dựng trên
  `@solana/wallet-adapter-*` và chưa sẵn sàng để chuyển đổi, [kho lưu trữ
  wallet-adapter ](https://github.com/anza-xyz/wallet-adapter) vẫn là tài liệu
  tham khảo cho stack đó. Đối với bất kỳ dự án mới nào, hãy ưu tiên sử dụng
  plugin ví của Kit.
</Callout>
