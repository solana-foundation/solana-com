## Cài đặt

Cài đặt gói tổng hợp (umbrella package) hoặc từng signer riêng lẻ tùy nhu cầu:

```shell
# Umbrella package (includes all signers)
pnpm add @solana/keychain

# Or install individual packages
pnpm add @solana/keychain-core        # Core interfaces (required for custom signers)
pnpm add @solana/keychain-memory      # Local keypair signer
pnpm add @solana/keychain-vault       # HashiCorp Vault
pnpm add @solana/keychain-aws-kms     # AWS KMS
pnpm add @solana/keychain-gcp-kms     # GCP KMS
pnpm add @solana/keychain-privy       # Privy
pnpm add @solana/keychain-turnkey     # Turnkey
pnpm add @solana/keychain-fireblocks  # Fireblocks
pnpm add @solana/keychain-cdp         # Coinbase Developer Platform
pnpm add @solana/keychain-crossmint   # Crossmint
pnpm add @solana/keychain-dfns        # Dfns
pnpm add @solana/keychain-openfort    # Openfort
pnpm add @solana/keychain-para        # Para
pnpm add @solana/keychain-utila       # Utila
pnpm add @solana/keychain-fordefi     # Fordefi

# Kit client plugins (keychainSigner / keychainPayer / keychainIdentity)
pnpm add @solana/keychain-kit-plugin
```

Yêu cầu `@solana/kit` 8.1 trở lên. Các giao dịch v1
(`createTransactionMessage({ version: 1 })`) được hỗ trợ, ngoại trừ Fireblocks
với `useProgramCall: true`, chỉ chấp nhận giao dịch legacy và v0.

## Cách sử dụng cơ bản

### Factory hợp nhất (Khuyến nghị cho các ứng dụng muốn hỗ trợ nhiều signer)

Sử dụng `createKeychainSigner` với một cấu hình phân biệt (discriminated config) để tạo bất kỳ backend nào:

```typescript
import { createKeychainSigner } from "@solana/keychain";
import { signTransactionWithSigners } from "@solana/signers"; // requires @solana/signers >= 8.1

const signer = await createKeychainSigner({
  backend: "privy",
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});

// Sign an already-compiled transaction
const signedTx = await signTransactionWithSigners(
  [signer],
  compiledTransaction
);
```

Hoặc cài đặt từng gói signer riêng lẻ để giảm dung lượng phụ thuộc:

```typescript
import { createPrivySigner } from "@solana/keychain-privy";

const signer = await createPrivySigner({
  appId: "your-app-id",
  appSecret: "your-app-secret",
  walletId: "your-wallet-id"
});
```

### Sử dụng với Transaction Message

Mọi backend, trừ Crossmint và chế độ native của Fordefi, đều trả về một
`SolanaTransactionSigner`, vốn là một `TransactionPartialSigner` của Kit và hoạt động
cùng các hàm hỗ trợ partial-signer của `@solana/signers` bên dưới. Các backend
tự động broadcast được đề cập trong [Signer Capabilities](#signer-capabilities).

```typescript
import type { SolanaTransactionSigner } from "@solana/keychain-core";
import { signTransactionMessageWithSigners } from "@solana/signers";
import {
  createTransactionMessage,
  setTransactionMessageFeePayerSigner,
  pipe
} from "@solana/kit";

async function signWithKeychain(signer: SolanaTransactionSigner) {
  // Check availability (useful for remote signers)
  if (!(await signer.isAvailable())) {
    throw new Error("Signer offline");
  }

  // Use with @solana/kit transaction builder
  const transaction = pipe(
    createTransactionMessage({ version: 0 }),
    (tx) => setTransactionMessageFeePayerSigner(signer, tx)
    // ... set a lifetime and add instructions
  );

  // Sign with the standard signers API
  const signedTx = await signTransactionMessageWithSigners(transaction);
  return signedTx;
}
```

### Ký và gửi với bất kỳ Signer nào

`signAndSendTransaction` từ `@solana/keychain-core` đưa giao dịch lên
chain bất kể signer có dạng nào. Các sending signer broadcast thông qua
provider của chúng; mọi dạng khác sẽ dùng hàm `sendTransaction` mà bạn truyền vào (core không
phụ thuộc vào RPC):

```typescript
import { signAndSendTransaction } from "@solana/keychain-core";

const signature = await signAndSendTransaction(signer, transaction, {
  sendTransaction: (tx) =>
    sendAndConfirmTransaction(tx, { commitment: "confirmed" })
});
```

### Sử dụng với Kit Client (plugin keychainSigner)

`@solana/keychain-kit-plugin` cài đặt trực tiếp một keychain signer vào
[Kit client](https://github.com/anza-xyz/kit), thiết lập nó làm `payer` và
`identity` để bạn bỏ qua bước thiết lập `pipe` thủ công như đã trình bày ở trên:

```typescript
import { createClient } from "@solana/kit";
import { keychainSigner } from "@solana/keychain-kit-plugin";

const client = await createClient().use(
  keychainSigner({
    backend: "privy",
    appId: process.env.PRIVY_APP_ID!,
    appSecret: process.env.PRIVY_APP_SECRET!,
    walletId: process.env.PRIVY_WALLET_ID!
  })
);

client.payer; // SolanaTransactionSigner, also a Kit TransactionPartialSigner
client.identity; // same signer instance
```

Plugin chấp nhận cùng cấu hình gắn thẻ backend như `createKeychainSigner`,
trừ Crossmint và chế độ native của Fordefi (đã đặt `chain`). Các backend đó viết lại
giao dịch ở phía máy chủ, nên không thể đóng vai trò `payer` hoặc
`identity` của client; plugin sẽ từ chối chúng ở cả thời điểm biên dịch lẫn thời gian chạy. Chỉ
backend được điều phối tới mới được đóng gói (các gói backend được tải qua
`import()` động).

Dùng `keychainPayer` hoặc `keychainIdentity` để chỉ thiết lập một vai trò, và kết hợp các backend
trên cùng một client:

```typescript
import { createClient } from "@solana/kit";
import { keychainIdentity, keychainPayer } from "@solana/keychain-kit-plugin";

const client = await createClient()
  .use(
    keychainPayer({
      backend: "memory",
      privateKeyPath: `${process.env.HOME}/.config/solana/id.json`
    })
  )
  .use(keychainIdentity({ backend: "turnkey", ...turnkeyConfig }));
```

Đã có sẵn một `SolanaTransactionSigner`? Nó là một `TransactionPartialSigner`
hợp lệ của Kit, nên bạn có thể cài đặt nó bằng
[`@solana/kit-plugin-signer`](https://github.com/anza-xyz/kit-plugins/tree/main/packages/kit-plugin-signer)
thay thế (`pnpm add @solana/kit-plugin-signer`):

```typescript
import { createClient } from "@solana/kit";
import { signer } from "@solana/kit-plugin-signer";
import { createKeychainSigner } from "@solana/keychain";

const mySigner = await createKeychainSigner({
  backend: "vault",
  ...vaultConfig
});
const client = createClient().use(signer(mySigner));
```

### Hủy bỏ và các Broadcast chưa được xác nhận

`signTransactions`, `modifyAndSignTransactions`, `signAndSendTransactions` và
`signMessages` đều nhận `{ abortSignal }` làm đối số thứ hai. Việc hủy bỏ
chỉ dừng việc chờ đợi; nó không hoàn tác công việc mà provider đã chấp nhận.

Với chế độ native auto của Crossmint và Fordefi, lỗi không có nghĩa là chưa có gì
được ghi nhận. Khi provider có thể đã chấp nhận giao dịch, mã lỗi là
`SignerErrorCode.BROADCAST_UNCONFIRMED` (`"SIGNER_BROADCAST_UNCONFIRMED"`).
`context.providerTransactionId` được đặt khi yêu cầu tạo đã được chấp nhận, và
`context.idempotencyKey` mang khóa được sinh ra từ message. Gửi lại giao dịch
giống hệt từng byte là an toàn; một giao dịch được dựng lại (ví dụ với blockhash
mới) sẽ là một lần chuyển mới. `providerMayHaveAccepted(error)` và
`providerStatus(error)` từ `@solana/keychain-core` giúp phân loại lỗi.
Hãy đối chiếu với provider trước khi thử lại.

### Fordefi

Fordefi có ba chế độ ký, được cố định khi khởi tạo bởi `chain` và
`pushMode`. Mỗi chế độ cung cấp đúng một phương thức giao dịch, và cả ba đều ký
message:

| Chế độ          | Cấu hình                                      | Kiểu                        | Phương thức                        |
| ------------- | ------------------------------------------- | --------------------------- | ----------------------------- |
| Black box     | `chain` không được đặt                               | `FordefiBlackBoxSigner`     | `signTransactions()`          |
| Native auto   | `chain` được đặt, `pushMode` bị bỏ qua hoặc là `"auto"` | `FordefiNativeSigner`       | `signAndSendTransactions()`   |
| Native manual | `chain` được đặt, `pushMode: "manual"`           | `FordefiNativeManualSigner` | `modifyAndSignTransactions()` |

Các yêu cầu API được xác thực bằng chữ ký yêu cầu ECDSA P-256: cung cấp
khóa ký dưới dạng `privateKeyPem`, hoặc lưu nó trong KMS/HSM bằng cách truyền
`requestSigner`.

**Chế độ native auto** (khuyến nghị cho việc sử dụng on-chain): đặt `chain`, và Fordefi
sẽ tự ký và broadcast giao dịch. Vì Fordefi có thể thay thế
blockhash hoặc phí trước khi ký, signer là một `TransactionSendingSigner` của Kit:
hãy dùng nó với
`signAndSendTransactionMessageWithSigners`, không dùng luồng partial-signer đã trình bày
ở trên. Chế độ native auto chỉ chấp nhận giao dịch chưa ký mà signer bắt buộc duy nhất
là vault, và không thể dùng với `@solana/keychain-kit-plugin`.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { signAndSendTransactionMessageWithSigners } from "@solana/signers";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!, // Solana vault address (base58)
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet", // or "solana_mainnet"
  fee: { type: "custom", priority_fee: "1000" } // optional
});

const signature =
  await signAndSendTransactionMessageWithSigners(transactionMessage);
```

**Chế độ native manual**: đặt `chain` và `pushMode: "manual"`. Fordefi viết lại
message (blockhash gần nhất, các instruction phí Compute Budget) và ký nó,
nhưng không broadcast. `modifyAndSignTransactions()` trả về giao dịch
mà Fordefi đã ký, giao dịch này thay thế giao dịch bạn đã gửi: luôn tiếp tục từ
giao dịch được trả về. Fordefi phải là bên trả phí (fee payer) và phải ký trước mọi
signer bắt buộc khác. Phần được viết lại không có diff, vì vậy hãy kiểm tra kết quả trước khi
broadcast.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_VAULT_ID!,
  publicKey: process.env.FORDEFI_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8"),
  chain: "solana_devnet",
  pushMode: "manual"
});

const [signedTransaction] = await signer.modifyAndSignTransactions([
  transaction
]);
```

**Chế độ black box**: bỏ qua `chain`. Fordefi ký các byte thô và không
broadcast; bạn tự lắp ráp và gửi giao dịch. Hãy dùng chế độ này với
vault black box của Fordefi.

```typescript
import { createFordefiSigner } from "@solana/keychain-fordefi";
import { readFileSync } from "node:fs";

const signer = await createFordefiSigner({
  accessToken: process.env.FORDEFI_ACCESS_TOKEN!,
  vaultId: process.env.FORDEFI_BB_VAULT_ID!,
  publicKey: process.env.FORDEFI_BB_PUBLIC_KEY!,
  privateKeyPem: readFileSync("./secret/private.pem", "utf8")
});
```

## Signer Capabilities

`@solana/keychain-core` định nghĩa một interface cho mỗi dạng signer của Kit. Mỗi interface bổ sung
`isAvailable(): Promise<boolean>` vào interface `@solana/signers` tương ứng:

- `SolanaTransactionSigner` (`TransactionPartialSigner` của Kit): trả về các chữ ký
  cho một giao dịch mà bạn sở hữu.
- `SolanaModifyingSigner` (`TransactionModifyingSigner` của Kit): viết lại
  giao dịch, ký nó, và trả về giao dịch mới mà không broadcast.
- `SolanaSendingSigner` (`TransactionSendingSigner` của Kit): ký và broadcast
  thông qua provider của nó.
- `SolanaMessageSigner` (`MessagePartialSigner` của Kit): ký các message off-chain.
  Dạng này tách biệt với các dạng giao dịch.

`SolanaSigner` là union của ba dạng giao dịch. Kiểu trả về của mỗi factory
chỉ rõ dạng chính xác của backend tương ứng. Khi cấu hình chỉ được biết tại
thời gian chạy, hãy thu hẹp kiểu bằng `isSolanaTransactionSigner`, `isSolanaModifyingSigner`,
`isSolanaSendingSigner` hoặc `isSolanaMessageSigner`. `signerCapabilities(signer)`
trả về cả bốn cùng lúc.

| Backend                                                                                                     | Dạng                                           |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| memory, vault, aws-kms, gcp-kms, privy, turnkey, fireblocks, cdp, dfns, para, openfort, fordefi (black box) | `SolanaTransactionSigner & SolanaMessageSigner` |
| utila                                                                                                       | `SolanaTransactionSigner` (không ký message)  |
| fordefi (native manual)                                                                                     | `SolanaModifyingSigner & SolanaMessageSigner`   |
| fordefi (native auto)                                                                                       | `SolanaSendingSigner & SolanaMessageSigner`     |
| crossmint                                                                                                   | `SolanaSendingSigner` (không ký message)      |

```typescript
import {
  isSolanaSendingSigner,
  isSolanaTransactionSigner
} from "@solana/keychain-core";

if (isSolanaSendingSigner(signer)) {
  await signer.signAndSendTransactions([transaction]);
} else if (isSolanaTransactionSigner(signer)) {
  await signer.signTransactions([transaction]);
}
```

## Xây dựng Signer tùy chỉnh

Triển khai các interface capability mà backend của bạn hỗ trợ:

```typescript
import type {
  SolanaMessageSigner,
  SolanaTransactionSigner
} from "@solana/keychain-core";
import type { Address } from "@solana/addresses";
import type {
  MessagePartialSignerConfig,
  SignableMessage,
  TransactionPartialSignerConfig
} from "@solana/signers";
import type { Transaction } from "@solana/transactions";

class MyCustomSigner implements SolanaTransactionSigner, SolanaMessageSigner {
  constructor(readonly address: Address) {}

  async isAvailable(): Promise<boolean> {
    return await myBackend.healthCheck();
  }

  async signMessages(
    messages: readonly SignableMessage[],
    config?: MessagePartialSignerConfig
  ) {
    return await myBackend.signMessages(messages, config?.abortSignal);
  }

  async signTransactions(
    transactions: readonly Transaction[],
    config?: TransactionPartialSignerConfig
  ) {
    return await myBackend.signTransactions(transactions, config?.abortSignal);
  }
}
```

Chỉ triển khai những gì backend của bạn hỗ trợ. Kit phân loại signer dựa trên các
phương thức hiện có, vì vậy đừng bao giờ thêm một phương thức chỉ để ném lỗi.

Xem [hướng dẫn Thêm Signer](/docs/tools/keychain/adding-signers) để tích hợp
các dịch vụ quản lý khóa khác.
