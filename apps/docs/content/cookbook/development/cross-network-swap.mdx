Solana users often want to trade for assets that live on another network. An EVM
stablecoin, a Sui token, BTC. The usual path (bridge out, wait, swap on the
other side, bridge back) is slow and asks the user to hold three balances.

This guide shows how to run the whole flow as a single intent from a Solana
wallet: the user signs one transaction, and the output settles on whichever
destination network you specify. No new programs on Solana, no token approvals,
no relayer bookkeeping in your app.

## The Pattern

An intent-based cross-network SDK abstracts three moving parts behind one call:

1. **Source-side lock.** The user signs a transaction on Solana that locks the
   input token and declares what they want on the destination network.
2. **Solver competition.** A network of solvers picks up the intent and competes
   to fill it against native liquidity on the destination network.
3. **Destination settlement.** Output arrives at the recipient address on the
   destination network. Nothing else is sent back to Solana.

If nothing fills before the deadline, the intent can be cancelled and funds
returned.

Several projects offer this pattern for Solana today. This guide uses
[SODAX](https://docs.sodax.com/solana) as its example. Other options that let
you build a similar flow include
[deBridge DLN](https://docs.debridge.com/dln-details/overview/introduction),
[Wormhole SDK](https://wormhole.com/docs/build/), and
[LayerZero OFT](https://docs.layerzero.network/v2/developers/solana/oft/overview).
Pick based on which networks and assets you need to reach and how the fee and
solver model fits your app.

## Wrap the User's Wallet

Any wallet adapter that exposes `publicKey` and `signTransaction` works. In a
browser app, use whatever your wallet adapter surfaces (Phantom, Solflare,
Backpack, or any other Standard-Wallet-compatible provider). In a script or bot,
pass raw keypair bytes instead. Use one of the two.

In a browser, from your wallet adapter:

```typescript
import { SolanaWalletProvider } from "@sodax/wallet-sdk-core";

const walletProvider = new SolanaWalletProvider({
  wallet: walletContextState,
  endpoint: "https://api.mainnet-beta.solana.com"
});
```

In a script or bot:

```typescript
import { SolanaWalletProvider } from "@sodax/wallet-sdk-core";

const walletProvider = new SolanaWalletProvider({
  privateKey: keypairBytes, // Uint8Array
  endpoint: "https://api.mainnet-beta.solana.com"
});
```

## Look Up Tokens

Read supported assets from the SDK config at runtime rather than hard-coding
mints. The list on Solana is smaller than the total reach across networks: the
recipient can be on any supported destination even if the input starts as SPL.

```typescript
import { Sodax, ChainKeys, SolverIntentStatusCode } from "@sodax/sdk";

const sodax = new Sodax();
await sodax.initialize();

const sol = sodax.swaps
  .getSupportedSwapTokensByChainId(ChainKeys.SOLANA_MAINNET)
  .find((t) => t.symbol === "SOL");

const usdcArb = sodax.swaps
  .getSupportedSwapTokensByChainId(ChainKeys.ARBITRUM_MAINNET)
  .find((t) => t.symbol === "USDC");

if (!sol || !usdcArb) {
  throw new Error("Token not supported for swaps");
}
```

## Get a Quote

Quotes reflect what the user actually receives. Any configured platform fee is
already deducted from `quoted_amount`.

```typescript
const quote = await sodax.swaps.getQuote({
  token_src: sol.address,
  token_dst: usdcArb.address,
  token_src_blockchain_id: ChainKeys.SOLANA_MAINNET,
  token_dst_blockchain_id: ChainKeys.ARBITRUM_MAINNET,
  amount: 100_000_000n, // 0.1 SOL (9 decimals)
  quote_type: "exact_input"
});

if (!quote.ok) {
  throw new Error(`Quote failed: ${quote.error.detail.code}`);
}

const minOut = (quote.value.quoted_amount * 99n) / 100n; // 1% slippage
```

SDK operations such as quotes, swaps, and status lookups return a `Result<T>`
rather than throwing. Branch on `result.ok` and use the typed error instead of
catching exceptions.

## Execute the Swap

`swap()` runs the full lifecycle from a single call: it creates the intent on
Solana, verifies the transaction landed, submits it to the relay, waits for the
packet on the hub, and notifies solvers. There is one user signature.

```typescript
// `deadline` is an absolute Unix timestamp; getSwapDeadline turns an offset
// in seconds into one.
const deadline = await sodax.swaps.getSwapDeadline(300n); // 5 minutes
if (!deadline.ok) {
  throw new Error("Could not compute a swap deadline");
}

// Replace with the Arbitrum address that should receive the USDC before
// running. In an app this is usually the user's connected EVM wallet.
const recipientEvmAddress = "REPLACE_WITH_RECIPIENT_ARBITRUM_ADDRESS";

const result = await sodax.swaps.swap({
  params: {
    inputToken: sol.address,
    outputToken: usdcArb.address,
    inputAmount: 100_000_000n,
    minOutputAmount: minOut,
    deadline: deadline.value,
    allowPartialFill: false,
    srcChainKey: ChainKeys.SOLANA_MAINNET,
    dstChainKey: ChainKeys.ARBITRUM_MAINNET,
    srcAddress: await walletProvider.getWalletAddress(),
    dstAddress: recipientEvmAddress,
    solver: "0x0000000000000000000000000000000000000000",
    data: "0x"
  },
  walletProvider,
  timeout: 120_000
});

if (!result.ok) {
  throw new Error(`Swap failed: ${result.error.code}`);
}
```

## Wait for the Fill

A successful `swap()` means the intent was created, relayed to the hub, and
handed to solvers. It does not mean it was filled. Poll the status until it
reports `SOLVED`, which is the only success signal:

```typescript
const intentTxHash = result.value.intentDeliveryInfo.dstTxHash as `0x${string}`;

let solved = false;
let notFound = 0;
for (let i = 0; i < 60 && !solved; i++) {
  const status = await sodax.swaps.getStatus({ intent_tx_hash: intentTxHash });
  if (status.ok) {
    const code = status.value.status;
    if (code === SolverIntentStatusCode.SOLVED) {
      console.log("Filled on the destination:", status.value.fill_tx_hash);
      solved = true;
    } else if (code === SolverIntentStatusCode.FAILED) {
      throw new Error("Intent failed");
    } else if (code === SolverIntentStatusCode.NOT_FOUND) {
      // Not terminal: the solver can report NOT_FOUND for the first polls.
      if (++notFound >= 3) throw new Error("Intent not found");
    } else {
      notFound = 0;
    }
  }
  if (!solved) await new Promise((r) => setTimeout(r, 5000));
}

// Running out of polls is not settlement: the intent is still pending.
if (!solved) {
  throw new Error(
    "Swap fill not confirmed; check the intent status before cancelling"
  );
}
```

If nothing fills before the deadline, `sodax.swaps.cancelIntent(...)` cancels
the intent and returns the locked input.

## What You Did Not Have to Do

A few Solana-specific properties of this flow are worth calling out:

- **No approval step.** SPL allowances are not used. On Solana,
  `isAllowanceValid` passes without an on-chain transaction, so the flow goes
  straight from quote to swap.
- **No relay bookkeeping.** Manually orchestrated Solana intents
  (`createIntent` + `submitIntent`) must pass the `relayData` that
  `createIntent` returns. `swap()` handles this behind the scenes.
- **No approvals to revoke.** The intent locks only the input amount for this
  swap.

Wrap the app once, with Solana enabled for both the SDK and the wallet layer:

```tsx
import type { ReactNode } from "react";
import { QueryClientProvider } from "@tanstack/react-query";
import { SodaxProvider, createSodaxQueryClient } from "@sodax/dapp-kit";
import {
  SodaxWalletProvider,
  type SodaxWalletConfig
} from "@sodax/wallet-sdk-react";
import { ChainKeys, type SodaxOptions } from "@sodax/sdk";

const queryClient = createSodaxQueryClient();
const rpcUrl = "https://api.mainnet-beta.solana.com";

const sodaxConfig: SodaxOptions = {
  chains: { [ChainKeys.SOLANA_MAINNET]: { rpcUrl } }
};

const walletConfig: SodaxWalletConfig = {
  SOLANA: { chains: { [ChainKeys.SOLANA_MAINNET]: { rpcUrl } } }
};

export function Providers({ children }: { children: ReactNode }) {
  return (
    <SodaxProvider config={sodaxConfig}>
      <QueryClientProvider client={queryClient}>
        <SodaxWalletProvider config={walletConfig}>
          {children}
        </SodaxWalletProvider>
      </QueryClientProvider>
    </SodaxProvider>
  );
}
```

Then take the connected wallet from `useWalletProvider` and submit through
`useSwap`, with the same params as the `swap()` call above:

```tsx
import { useSwap } from "@sodax/dapp-kit";
import { useWalletProvider } from "@sodax/wallet-sdk-react";
import { ChainKeys, type CreateIntentParams } from "@sodax/sdk";

export function SwapButton({ params }: { params: CreateIntentParams }) {
  // undefined until a Solana wallet is connected
  const walletProvider = useWalletProvider({
    xChainId: ChainKeys.SOLANA_MAINNET
  });
  const { mutateAsyncSafe: swap, isPending } = useSwap();

  const onSwap = async () => {
    if (!walletProvider) return;
    const result = await swap({ params, walletProvider });
    if (!result.ok) {
      console.error("Swap failed", result.error);
      return;
    }
    // Then track the fill as shown above (dapp-kit also exports useStatus).
  };

  return (
    <button onClick={onSwap} disabled={isPending || !walletProvider}>
      {isPending ? "Swapping..." : "Swap"}
    </button>
  );
}
```

## Without the SDK

The same flow (tokens, quote, create intent, submit, status) is also exposed as
a plain HTTP API at `https://api.sodax.com/v1/swaps`, for backends that do not
run TypeScript. See the
[Swaps API reference](https://docs.sodax.com/developers/http-api/swaps). SODAX
is rolling out [API keys](https://docs.sodax.com/developers/how-to/api-keys) for
its write endpoints; they are not enforced yet, but integrations that will run
in production should plan to send one from a server they control.
