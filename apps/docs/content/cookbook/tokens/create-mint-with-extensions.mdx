This example creates a Token-2022 mint with onchain metadata, pausable
transfers, a permanent delegate, and token accounts that start frozen. It is the
same set of extensions the [Issue an asset](/developers/docs/assets/issue-asset) path
uses, written in Kit, web3.js v3, Rust, and legacy web3.js. Pick a tab, then
run it on the isolated test network:

<CreateMintWithExtensionsCreate />

You should see the transaction signature and the mint address. The Kit, web3.js
v3, and Rust tabs also print the list of enabled extensions.

## Point it at devnet

Each tab generates a new payer and funds it with an airdrop, which only works on
a local network: the public devnet endpoint no longer serves airdrops. On
devnet, pay with a keypair you funded yourself. Get devnet SOL for your Solana
CLI keypair (`solana address` prints its address) from the
[Solana Faucet](https://faucet.solana.com) or another
[faucet](/developers/cookbook/development/airdrops-and-faucets), then, in your
tab, replace the lines that create the payer, the mint keypair and the RPC
connection, and the airdrop that follows them, with:

<CodeGroup>

```ts Kit
// These imports replace the tab's @solana/kit and Kit plugin imports
import { readFileSync } from "node:fs";
import { homedir } from "node:os";
import {
  createClient,
  createKeyPairSignerFromBytes,
  generateKeyPairSigner,
} from "@solana/kit";
import { solanaRpc } from "@solana/kit-plugin-rpc";
import { payer as kitPayer } from "@solana/kit-plugin-signer";

// A keypair you funded with devnet SOL from https://faucet.solana.com
const payer = await createKeyPairSignerFromBytes(
  new Uint8Array(
    JSON.parse(readFileSync(`${homedir()}/.config/solana/id.json`, "utf8")),
  ),
);
const mint = await generateKeyPairSigner();

// No rpcAirdrop() or airdropPayer(): the payer is already funded
const client = await createClient()
  .use(kitPayer(payer))
  .use(
    solanaRpc({
      rpcUrl: "https://api.devnet.solana.com",
      rpcSubscriptionsUrl: "wss://api.devnet.solana.com",
    }),
  );
```

```ts title="Web3.js v3"
import { readFileSync } from "node:fs";
import { homedir } from "node:os";

// A keypair you funded with devnet SOL from https://faucet.solana.com
const payer = await Keypair.fromSecretKey(
  Uint8Array.from(
    JSON.parse(readFileSync(`${homedir()}/.config/solana/id.json`, "utf8")),
  ),
);
const mint = await Keypair.generate();

// No requestAirdrop(): the payer is already funded
const connection = new Connection("https://api.devnet.solana.com", "confirmed");
```

```rust Rust
// Import read_keypair_file (LAMPORTS_PER_SOL is no longer needed)
use solana_sdk::{
    signature::{read_keypair_file, Keypair},
    signer::Signer,
    transaction::Transaction,
};

// In main():
let client = RpcClient::new_with_commitment(
    String::from("https://api.devnet.solana.com"),
    CommitmentConfig::confirmed(),
);

// A keypair you funded with devnet SOL from https://faucet.solana.com
let payer = read_keypair_file(format!("{}/.config/solana/id.json", std::env::var("HOME")?))
    .map_err(|e| anyhow::anyhow!("failed to read keypair: {e}"))?;
let mint = Keypair::new();
let token_program = spl_token_2022_interface::id();

// No request_airdrop(): the payer is already funded
```

Everything after the setup is unchanged. Before using the same configuration on
mainnet, plan authority management, compliance operations, and monitoring for
the asset: the [go-live checklist](/developers/docs/assets/issue-asset/go-live)
of the Issue an asset tutorial covers them.
