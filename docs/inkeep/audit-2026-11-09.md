# Solana Inkeep integration review

The integration answers core developer questions, but community retrieval,
source selection, and citation consistency need work. Alex's Superteam example
exposes two separate issues: a reported challenge failure that did not recur in
a fresh desktop session, and a reproducible failure to retrieve the official
website. A frustrated wording variant stayed polite but missed the same link.
The observed answer problem is relevance and completeness; changing the
assistant's personality alone would not address it.

This is the review phase of
[ECO-670](https://linear.app/solana-fndn/issue/ECO-670/restore-and-modernize-the-solanacom-inkeep-integration)
and the baseline for
[ECO-673](https://linear.app/solana-fndn/issue/ECO-673/audit-and-upgrade-solana-content-using-inkeep-mcp-and-rag).
No website behavior, public content, credentials, prompts, or indexes were
changed. The parent remains incomplete until fixes are deployed, reindexed, and
measured again.

## Evidence and scope

- Initialized a local stdio MCP server, discovered its tools, and made 40
  `tools/call` requests: retrieval and QA for each of 20 questions. The server
  follows Inkeep's [RAG MCP pattern](https://inkeep.com/blog/mcp-server).
- Used the existing `solana-com/dev` server credential in memory. All 40 calls
  returned HTTP 200. The [baseline JSON](baseline-2026-11-09.json) preserves
  answers and ordered source metadata, including duplicate records.
- A separate `solana-com/prd` credential probe to `inkeep-rag`, with the
  production Origin/Referer, returned HTTP 403, “Not authenticated for
  integration type.” That does **not** prove production widget authentication is
  broken: its web credential has a different challenge flow. The project ID and
  assistant settings behind these credentials were not independently verified in
  the Inkeep portal.
- A fresh Chromium session on `https://solana.com/` completed the challenge,
  sent a solution header, and received a successful chat response for Alex's
  exact question. `?search=superteam` also opened search and returned results.
  The search results visibly repeated regional Superteam podcast entries.
- Existing proxy tests passed: 26/26. They exercise validation, challenge
  forwarding, streaming/citation pass-through, rate limits, upstream errors,
  disconnects, and missing configuration with mocked upstream responses.
- The baseline latency median was 13.12 seconds and maximum 34.55 seconds for
  completed tool calls with concurrency three. These are local audit timings,
  not production time-to-first-token or a service SLA.

The audit returned 154 document records, 113 distinct URLs across all questions,
and 22 records pointing to `llms.txt` or `llms-full.txt`. Counts of repeated
URLs across different questions are not themselves a defect; the per-question
duplicates and localized results below are the relevant evidence.

This is a sampled retrieval and integration review, not a complete inventory of
the Inkeep project. Analytics, query frequency, prompt rules, crawl exclusions,
source sync status, key revocation, preview environments, and reindex controls
were not available through the local retrieval tools. These require the Inkeep
project owner. A mobile browser attempt and automated citation fetches later
encountered access/rate-limit restrictions; mobile behavior and every citation's
reachability are not certified by this run.

## Citation checks

[Automated fetch results](citation-check-2026-11-09.json) cover 33 distinct
answer links. Most `solana.com` fetches returned 429 in this environment, so
these results cannot classify them as broken. The faucet returned 403, also
inconclusive. In contrast, the earlier interactive production session and
selected documentation checks worked. The Superteam website and its calendar
were reachable; the calendar redirected to `luma.com`. The grants URL redirected
to `/grants-funding`.

Follow up `gen3.network` and `metacamp.so` before recommending them; a single
failed fetch does not establish that either service is permanently unavailable.
Citation presence, destination reachability, and whether the cited text actually
supports an answer are separate checks.

## Implementation and reindex sequence

1. Inkeep owner confirms project/assistant identity, crawl configuration, source
   inventory, analytics, and audit credential ownership. Use frequency data to
   refine the priorities above; none was available for this baseline.
2. Under ECO-673, improve evergreen community/support content in its canonical
   source and review staking accuracy. Preserve historical Media copy; avoid
   adding query-specific special cases to the shared proxy.
3. Tune canonicalization, locale selection, source relevance, citation rules,
   and retired-source handling in Inkeep. Diagnose the challenge failure under
   ECO-670 using an affected-session trace before selecting a repair.
4. Publish approved content, reindex affected sources, and rerun
   [the MCP benchmark](../../scripts/inkeep/README.md) using the same verified
   assistant. Compare each answer and ordered source list against this baseline.
5. Verify desktop/mobile search and chat, multiple turns, stale challenge/retry
   recovery, working citations, dark/light themes, keyboard shortcuts,
   deep-linked queries, approved previews/local setup, and upstream degradation.
   Do not mark ECO-670 complete until these deployment checks and the measured
   post-reindex results exist.
